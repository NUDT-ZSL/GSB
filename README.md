迁移方案定稿后，团队拿到的不是旧工程而是目标说明：Windows 工作区尚无任何代码与样本，需按新方案独立实现软件供应链完整性审计的首个可运行版本。业务目标是对本地确定性生成的构件完整性清单做跨版本归并，判定依赖闭包中哪些构件因上游摘要变化或吊销而失效，并以可集成库加完整示例交付。全部输入由随题交付的固定种子脚本生成，不依赖网络、账号或外部服务：构件清单声明构件标识、版本、内容摘要与摘要算法、签名状态与发布时刻；依赖声明给出构件之间的依赖边与版本约束；两代清单快照并存，v1 为单文件 JSON，记录相对发布秒与以扁平十六进制串书写的摘要，v2 为分片 JSON 加 SQLite 元数据库，记录规范构件标识、绝对毫秒发布时间、摘要代数、摘要算法与墓碑标记。版本演进后同一构件在两代口径下的发布时间、摘要代数与摘要算法表示方式不一致，且摘要计算量随构件数与共享依赖深度增长，需要同时处理口径换算精度、摘要位宽分派与依赖失效闭包的一致性。

任务环境与准备：
安装 Python 3.11 及以上版本，并在 Windows 命令行确认 python --version 可用。
创建全新工作目录作为项目根目录，仅放入随题交付的固定种子样本生成脚本，不预置任何实现代码。
安装依赖：pip install numpy pytest；SQLite 使用 Python 标准库 sqlite3，无需额外安装。
运行样本生成脚本，在本地产出 v1 单文件快照、v2 分片 JSON 与 SQLite 元数据库、依赖声明与观测时钟声明，确认生成过程不访问网络。
准备本地临时目录用于检查点、快照与报告的原子写出验证，并确认测试用例可在该目录下重复执行。

业务要求：
1. 实现 v1 单文件快照与 v2 分片快照加 SQLite 元数据库的统一解析层：校验规范构件键唯一性、版本表达式语法、摘要串为合法十六进制且长度与所声明算法位宽一致、签名状态取值白名单、发布时间与摘要代次为非负整数，对非法记录输出含快照标识、构件规范键与稳定业务码的拒绝记录并继续处理其余构件。
2. 把 v1 相对发布秒以样本声明的观测时钟为唯一基准换算为绝对毫秒，禁止使用系统当前时间；换算后须为每个构件给出秒到毫秒端点换算的量化误差界，并在两代快照对同一构件发布时间、摘要代数或摘要算法结论不一致时输出显式冲突记录而非静默择一。
3. 实现跨摘要算法的摘要一致性判定：按算法白名单把 sha256 与 hmac-sha256 声明归一，校验声明算法与实际摘要位宽、十六进制大小写规范化口径一致，位宽不符与摘要值不一致分别返回 E_HASH_ALGO 与 E_HASH_MISMATCH，并给出不一致时的摘要前缀证据与出现代数。
4. 实现依赖图构建与失效闭包计算：以依赖声明为有向边建图，检测自引用与任意长度环并返回 E_DEP_CYCLE 且列出环中构件规范键序列；某构件摘要变化或带吊销标记时，沿依赖边反向计算直接与传递依赖它的构件集合，闭包内构件须标注失效来源构件键与传播层级。
5. 实现增量批次到达时仅重判受影响部分：新快照或吊销批次到达后只重判失效闭包内构件及其入边，重判后的完整性视图、冲突条目与闭包集合必须与从零全量重算逐字段一致，不一致须返回 E_RECOMPUTE_DIVERGE 并给出首个分歧构件键与字段名。
6. 实现受控并行与真实资源预算：支持以可配置并发度对多个快照批次并发导入，并设置单批次真实耗时上限、待处理批次队列上限与单批次摘要计算次数上限；耗时以真实墙钟测量判定而非人为延迟常量，超时返回 E_TIMEOUT 并终止该批次后续处理并计入报告，队列超限须拒绝入队且不破坏已入队批次。
7. 实现检查点演进与强制终止后的恢复边界：按已应用批次水位与完整性视图摘要把检查点持久化到 SQLite 与本地快照文件，进程被强制终止后只允许从最后一个完整检查点恢复且不承诺生成退出报告；检测到检查点结构版本、算法白名单版本或合并口径版本变化时须整体重建而非增量续接，不得把旧版完整性结论与新视图混合。
8. 交付可交互命令行与确定性本地验证：提供导入快照、查询完整性视图、导出失效闭包报告、校验检查点四类子命令，报告为可解析 JSON 并含构件级结论、业务码、误差界与失效闭包链，报告与快照均先写临时文件再整体重命名替换；单份快照解析失败不得中断同批其他快照，附固定种子样本生成器与测试集覆盖摘要冲突、循环依赖、增量等值与终止恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证跨版本归并、摘要冲突分派与依赖失效闭包结论，并核对增量重判与全量重算一致及中断恢复后的账本状态。

## 交付实现

本仓库已按上述目标说明交付首个可运行版本：核心包为 `supply_chain_audit/`，固定种子生成器为 `generate_seed_samples.py`，测试位于 `tests/`。运行时核心仅依赖 Python 标准库；`numpy` 与 `pytest` 按题目要求作为本地验证依赖安装。

### Windows 快速开始

```powershell
python --version
python -m pip install numpy pytest
python .\generate_seed_samples.py .\samples\seed
python -m pytest -q

python -m supply_chain_audit import-snapshots `
  --sample-dir .\samples\seed `
  --workspace .\.audit-workspace `
  --concurrency 4 --timeout-seconds 10 --queue-limit 32 `
  --max-hash-operations 10000 --apply-seed-updates

python -m supply_chain_audit query-view --workspace .\.audit-workspace --status revoked
python -m supply_chain_audit export-closure --workspace .\.audit-workspace --out .\closure-report.json
python -m supply_chain_audit verify-checkpoint --workspace .\.audit-workspace
```

也可使用别名：`import`、`query`、`export`、`checkpoint`/`verify`。PowerShell 一键验证脚本为 `scripts/validate.ps1`。

### 主要能力

- v1 单文件 JSON、v2 分片 JSON + SQLite 元数据的统一解析与拒绝记录。
- 固定观测时钟换算、秒/毫秒端点区间和 `999ms`/`499.5ms` 误差界。
- `sha256`、`hmac-sha256`、`sha512`、`hmac-sha512` 的位宽分派和大小写归一比较。
- 自引用、任意长度环检测，以及带来源、层级和依赖链的反向失效闭包。
- 受影响集合增量重判、关联边记录和 `E_RECOMPUTE_DIVERGE` 逐字段分歧定位。
- 并发导入、真实 `time.monotonic()` 超时、队列上限和摘要计算次数预算。
- SQLite + 原子 JSON 双检查点；策略版本变化时只允许整体重建。
- JSON CLI 报告、临时文件 + `os.replace` 原子替换和确定性测试。

详见 `docs/IMPLEMENTATION.md` 与 `docs/VALIDATION.md`。
