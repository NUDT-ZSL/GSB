在空白工作区构建一个面向表格数据特征工程的交互式专业应用，用于在有限交互延迟预算下完成特征编码与特征选择的反复试验。输入为本地确定性合成数据集（数值列、类别列、缺失值、高基数类别列与若干冗余列），以及一份实验配置（目标列、编码方式集合、选择器参数、交互延迟预算、并发数）。应用需要支持用户通过交互命令反复调整编码与选择方案，后台执行编码、评估、选择的确定性流水线，前端在交互延迟预算内返回当前最优方案的评估指标，且在用户连续修改后最终报告必须与从零串行执行完整方案得到的结果一致。核心冲突在于：增量复用已算特征可压低交互延迟，但缓存键、选择器状态与评估切分之间的不一致会造成指标漂移；同时多线程并发评估与延迟预算调度会改变任务完成顺序，必须在结果顺序与有效性上保持与串行执行完全等价。

任务环境与准备：
确认 Windows 上可用 Python 3.10 及以上，并安装 numpy 与 pyyaml 的兼容版本。
在空白工作区创建项目目录，准备本地 YAML 配置样例与确定性合成数据集描述文件，不依赖网络与外部数据集。
准备一个本地演示脚本入口，用于按固定交互序列驱动应用并收集报告，运行前无需任何外部账号或服务。

业务要求：
1. 实现数据与配置加载层：读取本地 YAML 配置与合成数据描述（列名、类型、缺失标记、生成种子），按配置确定性生成表格数据，并对未知列、类型不符、目标列缺失、预算非正等输入输出 E_CONFIG_INVALID 业务码；所有数值列与类别列在加载后形成不可变列快照，快照带内容指纹，供后续阶段引用。
2. 实现特征编码器集合：至少覆盖独热编码、目标编码与频率编码，按配置为每列指定编码方式；独热编码需处理高基数类别列并受最大基数约束限制，超限列按配置回退或报 E_CARDINALITY_EXCEEDED；目标编码须以基于行号的确定性切分计算，禁止使用评估行自身标签造成泄漏，并对缺失值给出固定替代编码。
3. 实现特征选择器：依据配置在方差过滤、相关性过滤与基于权重的逐步消除之间执行选择流程，逐步消除每轮剔除权重绝对值最小的特征，同权重按特征名字典序剔除；选择器输出被保留与被剔除特征清单及剔除轮次，且选择器状态必须可从输入特征清单与参数完整重建，不允许依赖内部历史的隐式状态。
4. 实现增量复用与失效判定：为每个特征编码结果计算由列快照指纹、编码方式与参数、选择器配置共同派生的缓存键；用户修改编码方式或参数时仅使受影响特征及其下游选择与评估阶段失效，未失效特征必须直接复用且不得重新计算；缓存键与选择器状态不一致时必须判定失效而非静默复用。
5. 实现交互延迟预算调度：交互命令触达后，调度器在配置的延迟预算内优先返回可用的当前最优方案指标，超预算部分转入后台继续计算并以 E_BUDGET_EXHAUSTED 标记未完成方案的中间状态；预算耗尽不得通过伪造指标或返回过期缓存充当结果，必须区分已确认指标与待定指标并在响应中标注其依据。
6. 保证并发评估与串行执行结果一致：使用线程池并发计算候选方案的交叉验证指标，最大并发数取自配置；每个候选任务携带由方案标识与折号派生的稳定排序键，无论完成顺序如何，最终指标表顺序、选择器剔除顺序与报告中方案排名必须与单线程串行执行逐字段一致。
7. 实现中断恢复与强制终止后的状态判定：交互过程中收到可处理的退出信号时，完成当前已算特征与选择器状态的原子快照写盘后以整数退出码 0 退出；进程被强制终止后重启时，仅依据已完整替换的快照恢复，恢复后继续交互得到的最终报告必须与不中断会话一致，对损坏或不完整快照输出 E_SNAPSHOT_CORRUPT 并回退到上一完整版本。
8. 实现评估报告与可重复演示：输出 JSON 报告，包含各方案交叉验证指标、被选特征清单与剔除轮次、缓存命中与失效特征数、各交互命令响应耗时与是否超预算、快照版本号与失败清单；报告字段名与业务码须与前文一致，以临时文件加原子替换写盘，并提供确定性的本地演示脚本复现同一组交互序列得到逐字段相同报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本执行一组交互编辑序列，验证增量报告与从零串行执行逐字段一致、延迟预算与恢复语义正确。
