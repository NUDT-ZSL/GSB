需要在一个空白工作区中实现一个面向本地单机场景的「键值存储索引与过期管理引擎」，用于模拟真实 KV 存储中索引、过期与存储格式版本化的核心机制。引擎维护键值数据，并为每个键维护过期时间戳；索引采用磁盘上的有序段文件（segment）与内存态映射相结合，段文件具有自描述的格式头（魔数、格式版本、键区间、校验和）。引擎需支持对同一数据目录在不同格式版本间的读写互操作：旧版本段必须能以只读兼容方式打开与查询，新写入必须以当前格式版本落盘，并支持显式迁移把旧版本段升级为新格式。过期键采用惰性删除与后台回收相结合的真实机制，过期判定依赖单调递增的逻辑时钟而非单纯读取；同时维护过期索引以支持按时间范围扫描待回收键。全程无外部服务依赖，数据目录与格式头校验均由本地确定性样本驱动。

任务环境与准备：
安装 Python 3.10 或以上版本，确认 python 与 python -m pytest 可在 Windows 命令行使用。
安装 pytest（如 python -m pip install pytest），无需网络即可运行既有依赖版本。
在空白工作区创建项目目录与样本数据目录，样本段文件、元数据与固定逻辑时钟推进序列需由任务实现自身生成并落盘。
确认数据目录为本地可写路径，测试运行前清空历史数据以保证可重复。

业务要求：
1. 实现段文件的自描述二进制格式与读写：段文件头部必须包含魔数、格式版本号、键区间下界与上界、条目数量与 CRC32 校验和；条目按键字典序存放键、值与过期时间戳。写入须保证原子性，写入中途失败不得留下半截可见段文件；头部损坏或校验和不匹配的段必须返回业务码 E_CORRUPT_SEGMENT，且不得部分载入其内容。
2. 实现多版本格式互操作：当前支持的格式版本集合须显式声明，打开数据目录时按段头版本分派读取器；已知旧版本段必须能以只读兼容方式载入并可参与查询与扫描，不支持的过高或过低版本须返回 E_UNSUPPORTED_VERSION 并在错误信息中给出段名与版本号；新旧版本段共存的目录在只读查询中必须给出一致视图。
3. 实现显式格式迁移流程：提供迁移接口把指定段从旧版本升级为当前版本，迁移须先写临时新段并校验 CRC 后再原子替换，替换前旧段保持可读；迁移中断后重启时须依据持久化的迁移标记识别未完成迁移并回滚到迁移前状态，不得同时存在两个有效同键段造成读放大歧义。
4. 实现基于逻辑时钟的过期判定：每个写操作推进逻辑时钟，过期时间戳为绝对逻辑刻度；读路径惰性删除过期键并返回 E_KEY_EXPIRED 业务码语义；逻辑时钟与段内过期时间戳必须落在同一刻度体系，重启后逻辑时钟须从持久化元数据恢复且不得回退，避免过期键被重新视为有效。
5. 实现过期索引与后台回收：维护按过期时间排序的过期索引，支持按逻辑时间范围扫描待回收键；后台回收按批推进，每批只回收已过期且已无活跃引用的键，回收过程中新写入的同名键不得被误删；回收批次的进度须可查询且可从中断处继续，不得整体重扫。
6. 实现版本兼容的元数据与快照替换：数据目录维护一份元数据文件记录格式版本、逻辑时钟、段清单与过期索引根；元数据整体替换时必须携带递增的元数据版本号，启动时若发现版本号未变化但内容摘要变化须判定为损坏并返回 E_METADATA_TAMPERED；元数据与段清单必须保持一致，孤立段须被识别并隔离。
7. 实现对外操作接口与异常链路：通过命令行的 JSON 请求文件与标准输出提供写入、读取、按版本范围扫描、触发迁移、查询回收进度与查询段清单的操作；所有错误须以业务码在 JSON 响应中返回且错误码集合固定；读请求命中损坏段时须返回对应业务码而非抛出未处理异常，且引擎整体仍可对其他健康段提供查询。
8. 提供本地确定性样本与可重复测试：样本须包含至少一个旧版本段、一个当前版本段与一个损坏段，覆盖版本兼容读、迁移回滚、逻辑时钟恢复、过期惰性删除与后台回收中断续跑；pytest 用例须在 Windows 离线运行，使用固定键集与固定逻辑时钟推进序列，保证结果可重复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证多版本段互操作、迁移回滚、逻辑时钟过期与回收续跑及损坏段隔离。
