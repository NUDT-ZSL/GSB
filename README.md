一项协调中间件的独立验证工作由新成员接手，本地 Linux（WSL Ubuntu）工作区还没有任何代码与样本，需要从第一行开始构建一个协调选举与故障转移场景的领域可视化与诊断工作台。系统围绕选主拓扑归并、租约世代推进与故障转移决策展开，全部输入由随工程交付的固定种子脚本确定性生成。输入包括：节点清单（节点名、协调角色、回环候选地址、租约世代号、优先级、健康状态）、选举事件流（事件序号、节点名、注入逻辑时钟毫秒、候选代数、投票摘要、是否撤销）、订阅声明（服务名、订阅节点、回调地址）以及两代拓扑策略快照（v1为单文件JSON，记录扁平拓扑视图与相对发布秒数；v2为分片JSON加SQLite元数据，记录拓扑代数、绝对发布毫秒与作用域墓碑）。关键业务约束是：选举拓扑归并必须在每轮候选并发上限与总逻辑时间预算内完成，强制终止后的恢复必须基于持久化选举账本裁决半提交投票，任何节点在第 N 轮看到的领导者视图必须与一次性重放相同，不得出现双主或租约代数回退。

任务环境与准备：
在 Linux（WSL Ubuntu）上安装 Python 3.10 或更高版本以及 pip，并安装依赖 `pip install fastapi uvicorn`。
从空工作目录开始，使用随题交付的固定种子脚本生成本地节点清单、选举事件流、订阅声明与两代拓扑策略快照样本，不依赖外部网络或真实服务。
确保本地可写目录用于 SQLite 数据库和输出文件，并通过 `python -m uvicorn` 启动诊断接口。

业务要求：
1. 实现节点清单、选举事件流、订阅声明与两代拓扑策略快照的解析校验，确保节点名全局唯一、角色字段为合法枚举、候选代数单调且候选地址为回环格式、事件序号严格递增、v1相对秒数为非负整数、v2分片哈希与SQLite元数据中拓扑代数一致，任何字段缺失或跨代代际冲突必须返回独立业务错误码并保留可诊断字段。
2. 实现两代拓扑策略快照的跨版本合并与统一拓扑索引构建，同一节点在两代快照中同时出现时依据声明的逻辑时钟与拓扑代数裁决最新条目，逻辑时钟相同则按来源格式优先级裁决，v1相对秒数在注入逻辑时钟下换算为绝对毫秒并记录换算标度与舍入方向，合并后的每节点视图须保留来源版本、原始时间表示和裁决依据，任一分片哈希不匹配必须终止合并且不得产生半合并视图。
3. 实现可注入逻辑时钟驱动的选举事件分批归并，将事件按节点与候选代数分组到拓扑批次，每批只包含已提交事件，同一节点同一候选代数在同一批内最多出现一次，乱序到达事件先进入待裁决缓冲并按序号与逻辑时钟稳定排序，归并结果必须与一次性全量重放同一事件流得到的拓扑状态逐项一致，且逻辑时钟回拨超过容差返回业务错误码。
4. 实现并行选举拓扑归并与合并调度器，在每轮候选并发上限与总逻辑时间预算双重约束下选择可归并批次，预算或并发上限耗尽须放弃剩余未启动批次并记录放弃原因，区分预算内未启动、启动后失败与主动放弃三类结局，已启动批次不得被截断，同一批次在同一拓扑代数下只被提交一次并由SQLite事务与文件锁保证。
5. 实现节点租约世代与领导者指针状态机演进，依据归并后的投票摘要与优先级裁决每个拓扑域内的领导者，租约世代只增不减且领导者切换必须记录新领导者的世代号、生效逻辑时钟与旧领导者失效墓碑，任一节点在强制终止后恢复时不得直接恢复到内存残留状态，而须从持久化选举账本中恢复并校验状态链完整性。
6. 实现拓扑策略版本化持久化与增量失效闭包裁决，每次新策略包提交产生新版本号并以临时表加版本号整体替换当前指针而非逐条覆盖，版本回退被拒绝，策略变更时沿依赖边计算受影响拓扑域及订阅节点闭包，精确标记哪些缓存视图需重算、哪些可安全复用，未受影响订阅不得重复触发回调。
7. 实现强制终止后的恢复一致性，把每个拓扑域账本管理水位、已提交投票序号、领导者指针版本、租约世代、待裁决缓冲与逻辑时钟水位以单事务原子写入SQLite，进程在归并或策略提交中途被SIGKILL后，恢复路径依据持久化状态识别半提交批次并只重放缺失事件，校验页对齐且不得重复累计投票计数。
8. 实现多进程并发一致性与可重复可视化诊断接口，允许多个归并实例并行处理不同拓扑域，通过SQLite事务与文件锁保证同一节点同一候选代数只被计入一次、同一策略快照指针只被整体替换一次，提供FastAPI端点或等价命令进行状态查询、恢复与验证，输出稳定排序JSON包含各领导者、租约世代、字段统计与缓冲状态。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
通过本地确定性样本验证拓扑归并结果与一次性重放一致，且在强制终止后能从持久化账本正确恢复领导者视图与租约世代。
