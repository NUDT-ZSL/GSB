当前是空白工作区，需要从零构建一个面向内部审计档案的增量采集工作台，供团队周期性抓取本地授权档案站点并核对跨会话的版本关联。本地目标站点由同一进程内的确定性 HTTP 服务提供：列表页分页且条目容器由前端脚本二次渲染后才出现，详情页按页面内声明的 schemaVersion 采用不同字段结构；条目内容带修订号，新会话再次采集同一业务标识时可能只返回部分字段的增量。服务端可配置注入交互延迟（响应间隔随请求序号变化）、503 与会话过期。采集端需把原始响应、规范化记录与跨会话版本关联写入 SQLite，并在交互延迟波动下保持计算结果一致：同一份固定样本无论并发度与延迟参数如何变化，最终规范化记录与版本关联链必须一致。工作台以 FastAPI 提供服务，页面可创建任务、查看进度、差异与版本关联图，并触发恢复。

任务环境与准备：
安装 Python 3.10 及以上版本，并在虚拟环境中安装 fastapi、uvicorn、httpx、beautifulsoup4 或 lxml 等依赖（版本自选）。
本地站点服务与采集器在同一进程或本机端口协作，不依赖外网、真实账号或付费资源，样本数据由脚本在本地生成。
准备 SQLite 数据库文件路径与演示配置项（端口、并发度上限、延迟参数、异常注入开关），演示脚本与手动启动方式均在题面说明范围内可重复执行。

业务要求：
1. 实现列表页就绪判定与分页游标推进：必须以条目容器出现且条目计数连续两次观测稳定作为渲染完成标记，不得以固定等待替代；分页游标由页面声明的总页数与下一页标识共同推进，超时返回 E_RENDER_TIMEOUT 并保留可复核的观测快照。
2. 实现按 schemaVersion 选择的详情解析，至少兼容两个结构版本，未声明或未知版本降级为保留原始字段并标记 unresolved，不得静默丢弃；解析结果须携带所用版本证据，供增量字段比较与关联链引用。
3. 实现跨会话增量采集的字段级版本关联：同一业务标识的多次采集按修订号构成关联链，仅在新会话中出现的字段记为增量字段，消失字段记为待确认缺失，关联链须能按业务标识追溯到每次采集所依据的原始响应。
4. 设计幂等键与冲突裁决：以业务标识加 schemaVersion 加修订号构成唯一键，重复采集同一修订不得产生重复记录；同一修订出现字段内容不一致时写入冲突记录并返回业务码 E_CONFLICT，不得以先到先得方式静默覆盖关联链。
5. 实现交互延迟波动下的结果一致性：在允许的最大并发度范围内，无论延迟参数与并发度如何配置，最终规范化记录集合、增量字段集合与关联链边集合必须逐项相同；需给出证明一致性的对账输出，逐业务标识比对两次不同配置运行的摘要并报告差异。
6. 实现并发调度与延迟感知退避：并发度可配置且有硬上限，遇 503 与高延迟按有界指数退避重试，重试耗尽记为条目级失败而非任务级失败；汇总须区分条目级失败与任务级失败，且退避等待不得无序扩张在途请求数。
7. 实现会话过期识别与重放：检测到会话过期响应时重新获取会话并重放当前请求，重放次数有上限；超过上限返回 E_SESSION 且任务保持可恢复，过期响应体不得作为正常数据入库，重放不得破坏已建立的关联链顺序。
8. 实现持久化检查点与强制终止后的恢复：以检查点记录已完成条目键集合、当前分页游标与已完成会话标识，进程被强制终止后仅依据库中状态续跑；恢复前后已确认条目计数、修订号序列与关联链边数须一致，不承诺补写退出报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本以不同并发与延迟配置各跑一遍，核验规范化记录、增量字段与关联链逐项一致，并验证恢复与异常业务码。
