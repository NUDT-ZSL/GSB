域名注册与解析托管平台的权威解析集群每天承载大量区数据查询，值班工程师要根据各解析节点的探测表现决定它是否继续对外应答。探测结果里偶发一次超时、连续多次 SERVFAIL、以及节点返回的区数据序列号落后于主控，这三种情况的含义并不相同：前两者是应答可用性问题，后者是数据陈旧问题，处置方式也不同。更麻烦的是节点摘除与恢复若只用单点阈值，会在抖动时反复摘除又恢复，造成解析流量震荡。摘除之后还要把该节点原有查询权重转给其余健康节点，而各节点有承接上界，分配不能超限，也不能让总权重不守恒。值班工程师需要一套在本机可重复运行的判定组件，逐探测时刻给出每个节点的健康分级、摘除与恢复时间点及依据、负载转移方案，并在探测参数或节点权重调整后只重判受影响的节点，与全量重判逐节点比对。

任务环境与准备：
准备 Linux（WSL Ubuntu）上的 Python 运行环境，仅使用语言标准库，不安装第三方包。
在工作目录下创建项目入口与模块目录，运行命令统一为 python3 加模块名。
确定性生成器与人工构造边界样本均作为仓库内文件提供，运行时不访问外部网络或真实解析节点。

业务要求：
1. 读取题内确定性生成器按固定种子产出的解析运维工程：节点清单（节点标识、所承载域名区、权重、承接上界、最近一次区数据序列号与刷新时刻）、逐逻辑时刻的探测记录（探测类型、NOERROR/SERVFAIL/REFUSED/超时响应码、应答时延、返回序列号是否与主控一致），以及探测周期、超时预算声明和权重调整事件。生成器必须可复现，并在样本中附上人工构造的边界工况。
2. 把探测记录按节点标识与逻辑时刻组织成健康观测序列，逐条保留来源追溯（节点、时刻、探测类型、原始响应码），对重复或乱序的探测记录按时刻排序后去重并标记冲突，遇到未知响应码要归入明确的未识别类别并计入统计，不能静默丢弃。
3. 按声明的超时预算与探测周期划分每个节点的时间滑动探测窗口，统计窗内连续失败次数、超时占比与各响应码分布，输出逐探测时刻每个节点的窗口统计值及所用窗口边界，窗口跨过探测参数变更时刻时要按变更前后的参数分段处理。
4. 结合窗内统计与节点返回的区数据序列号是否与主控一致，判定节点在每个探测时刻的健康分级为健康、降级或摘除；序列号落后且网络应答正常的节点单独归因为数据陈旧，输出陈旧节点清单与其最后同步时刻，并判定陈旧是否应独立触发摘除。
5. 采用摘除阈值与恢复阈值不对称的滞回规则判定节点摘除与恢复的时间点，输出每次切换的时刻、方向与依据（触发统计量、阈值与持续时间），并核对在临近阈值的抖动序列下不出现短时间内的反复摘除与恢复。
6. 对被摘除节点，按其余健康节点的权重与承接上界重新归一分配其查询权重，输出负载转移方案、各健康节点承接后负载占比与总权重守恒情况，标记承接超出上界的节点并给出需要追加转移的部分。
7. 在探测周期、超时预算或节点权重调整后，依据节点与滑动窗口的依赖关系推导受影响节点集合做增量重判，其余节点沿用上次结果；输出增量重判结果，并与全量重判逐节点逐探测时刻比对，差异必须可解释或为空。
8. 在每一次探测时刻推进后持久化节点健康状态、切换记录与负载转移快照，支持从快照续算；当同一时刻到达的摘除与恢复判定冲突时按声明的优先级裁定并记账，全部节点处于摘除状态时输出整体不可用结论而不产生空方案。

验收：
以确定性生成的解析运维工程与人工构造边界样本核对逐时刻分级、摘除恢复时间点、负载转移守恒与增量重判一致性。
