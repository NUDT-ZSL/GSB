当前是空白工作区，需要从零构建一个面向 Windows 本地环境的对象存储分片上传与元数据一致性工作台。用户通过 Tkinter 界面或脚本，把本地确定性样本文件按可配置分片大小切分为多个分片上传到本地回环 TCP 上的存储服务模拟进程；服务端以本地文件持久化分片数据，以 SQLite 持久化对象元数据（对象键、分片清单、分片摘要、对象元数据版本、上传会话状态与完成标记）。核心业务是：一次上传会话从创建、分片上传、分片校验、合并完成到对象可见，全过程须维持元数据与分片数据的跨模块一致；分片可在中断后续传，已完成对象可用不同元数据版本重新合并；界面须展示分片进度、分片摘要校验结果、对象元数据版本与操作结论，并在输入异常或注入故障时给出确定业务码。

任务环境与准备：
确认 Windows 上可用 Python 3.11 及以上版本，Tkinter 随官方 Python 安装提供，无需额外第三方包。
在工作区创建项目目录，准备本地确定性样本文件生成脚本与样本数据，样本规模固定以便摘要与耗时观测可复现。
准备本地回环 TCP 存储服务模拟进程的启动脚本与端口约定，端口范围 1 至 65535 且可被参数覆盖。
准备本地 SQLite 数据库文件所在目录与分片数据目录，确认具备读写权限；准备结构化日志输出目录。
运行命令与说明放在任务执行前可直接使用的本地脚本中，不依赖任何线上服务、真实账号或容器环境。

业务要求：
1. 实现样本文件的分片切分与确定性摘要：按命令行或界面给定的整数分片大小把本地文件切分为有序分片，每片计算确定性摘要并与分片序号、对象键一起登记；相同文件与分片大小多次切分必须得到逐字节相同的分片内容与摘要序列，分片大小为非法值（非正、超过文件长度上限）时以 E_CHUNK 业务码报告且不产生任何持久化写入。
2. 实现上传会话状态机与断点续传：会话在 created、uploading、verifying、committed、aborted 间迁移，每个迁移写入 SQLite 元数据表并记录会话标识、对象键、分片总数与已完成分片序号集合；进程中断后重新打开工作台须依据持久化状态恢复会话，已登记分片不得重复上传，续传完成后的对象内容摘要须与一次性完成上传的对象内容摘要一致。
3. 实现分片上传、摘要校验与合并：上传分片写入本地分片数据文件并回写元数据，合并前逐片比较持久化分片数据摘要与元数据登记摘要，任何不一致以 E_INTEGRITY 拒绝合并并保留会话供续传；合并生成对象可见文件后写入对象元数据版本与完成标记，完成标记与对象内容须同时可见，不允许出现元数据已提交而对象内容缺失的中间态。
4. 实现并发分片上传与资源控制：支持多个分片在受全局并发上限与单会话并发配额约束下并行上传，配额耗尽时分片排队且不得绕过配额；同一分片被并发重复上传时必须收敛为唯一持久化结果且摘要一致；调度过程须输出每个分片的开始时间、结束时间与尝试序号，用时以本地单调计数毫秒为观测基准。
5. 实现对象元数据多版本与整体替换：同一对象键可因元数据变更（分片大小重算、标签或摘要算法口径变化）产生新元数据版本，版本号单调递增；提交新版本时对象元数据须整体替换而非与旧版本增量合并，旧版本保留为只读并可查询差异，差异须稳定列出变化字段与分片清单变化项。
6. 实现分片与元数据一致性审计：提供审计命令，逐对象校验元数据分片清单、分片数据摘要、对象内容摘要与元数据版本号之间的对应关系，并校验当前版本引用的分片集合与实际分片数据文件集合完全一致；不一致须以 E_AUDIT 业务码报告并列出对象键、首个差异分片序号与差异类型，审计输出顺序稳定且每次全量比较，可定位注入的首个差异分片。
7. 实现会话快照与版本识别恢复：把上传会话、对象元数据、分片清单与审计结论快照持久化，重新打开快照时先比较快照中的元数据版本与分片数据集合摘要是否与当前一致，不一致须整体替换当前工作台状态而非增量合并；恢复后对快照内已完成对象重新审计须得到相同结论，不可复现时以 E_REPLAY 业务码报告。
8. 实现故障注入与结构化日志：支持以命令行参数分别注入分片数据文件截断、元数据中分片摘要损坏、上传过程中对象元数据版本冲突三类异常，分别以 E_CHUNK、E_INTEGRITY、E_VERSION 业务码报告并写入结构化日志；注入仅改变输入文件或参数，不得修改工作台源码制造失败。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
