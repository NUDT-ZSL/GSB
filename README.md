当前为空白工作区，需要从零构建一个面向多标签图像分类的算法实现与可复现实验环境，核心业务问题是可复现验证与异常注入。业务对象是本地确定性生成的图像样本：由固定种子生成的固定尺寸 RGB 像素数组，每张图携带多标签真值集合（标签来自受控标签集，允许一张图对应多个标签，个别标签可在样本中被标记为不确定）。分类链路为：像素预处理→确定性特征提取（分块统计与固定权重投影）→按标签独立打分（线性打分加固定偏置）→多标签判决（每标签独立门限）→指标汇总（micro/macro F1、逐标签 precision/recall 与 hamming loss）。实验环境需对外证明同一配置逐字节可复现，并能按输入或参数注入异常，观察异常沿链路如何被归因与降级，而不是靠修改源码制造失败。

任务环境与准备：
准备 Windows 本地工作区与 Python 3.10 及以上解释器，确认可执行 python 命令。
安装 NumPy 与 pytest（pip install numpy pytest），无需 GPU、外部数据集或网络服务。
在项目内约定本地样本与快照目录，样本由题目要求的固定种子在运行时生成，不依赖任何附件。
运行命令行示例与测试时使用虚拟环境或独立目录，避免与系统环境中的其他包产生版本冲突。

业务要求：
1. 实现确定性的多标签分类链路：按固定种子生成固定尺寸 RGB 样本与真值标签集合，完成像素预处理、确定性特征提取和按标签独立线性打分；同一输入、同一配置与固定种子下，各阶段中间特征、逐标签分数与最终标签集合必须逐字节一致，禁止依赖系统时间、字典遍历顺序或未声明状态。
2. 实现多标签判决与不确定标签语义：每个标签按可配置门限独立判决，允许同一样本命中多个标签；被标记为不确定的标签须按配置策略（忽略、计入正例或单独统计）处理，且策略显式记录在结果中；须校验每个样本的判决标签集合与分数向量按标签顺序一一对应，违反返回 E_INCONSISTENT 并指出样本与标签。
3. 实现逐标签与整体指标汇总：由判决结果与真值计算 micro/macro F1、逐标签 precision/recall 与 hamming loss，指标须可由逐样本逐标签明细独立重算一致；当某标签在真值与预测中均无样本时须按声明口径处理而非产生除零结果，口径缺失或非法返回 E_METRIC_UNDEFINED 并指明标签。
4. 实现四阶段异常注入框架：在预处理、特征提取、打分、判决阶段分别提供由输入或参数触发的注入点（如像素值越界、投影权重形状不符、标签索引越界、门限非正），注入不得修改源码；每次注入须产生带阶段名、业务码、样本标识与注入参数的记录，未命中任何注入点的运行不得产生注入记录。
5. 实现异常归因与降级链路：某阶段产出业务码时下游须按明确策略降级（如跳过特征投影回退到原始分块统计、回退到默认门限判决），降级结果必须携带降级类别与触发它的上游业务码；禁止静默吞掉异常，未被任何阶段归因的异常须汇总到结果并返回 E_UNATTRIBUTED，且降级后的指标须标记来自降级路径。
6. 实现实验配置与样本快照的版本化及整体替换：配置、特征投影参数与真值标注各携带单调递增版本号与内容校验和，提交时整体替换旧快照而非增量修补；加载时识别版本号或校验和变化并整体替换，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明快照类别与版本，禁止使用部分可解析的损坏数据推进实验。
7. 实现可复现验证器与跨阶段一致性自检：验证器用固定种子重跑两次并比对完整输出哈希一致，同时校验各阶段处理的样本标识集合一致、逐标签分数可重算出判决、注入与降级记录可追溯到具体样本；检测到偏差返回 E_VERIFY_FAIL 并给出首个偏差位置；为样本数、特征维度与驻留矩阵内存设可配置上限，超限返回 E_RESOURCE_LIMIT 或降级并标记降级类别。
8. 实现算法组件接口与可复现实验环境：暴露分类、指标、注入与验证四个入口，命令行示例读取本地确定性样本，输出含逐标签分数、判决结果、指标、四阶段注入记录、降级链路、业务码与重跑哈希的 JSON 报告；须附一次正常运行、一次多点注入与一次资源超限降级的演示，全部仅依赖本地生成样本与本地进程。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证分类指标、异常注入记录、降级链路与固定种子重跑的哈希一致性。
