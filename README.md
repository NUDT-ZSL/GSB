在游戏引擎与影视后期交付中，同一段素材需要在 SDR、HLG、PQ 三种传递函数之间做色彩转换，并把宽色域素材映射到目标色域与目标亮度范围。转换过程涉及传递函数的分段定义、色域矩阵、白点适应、逐通道与亮度域色调映射，任何一步的浮点处理次序差异都会让结果在暗部与高光处产生可见偏差。当前为空白工作区，需从零开发一个本地色彩转换与 HDR 映射组件，输入为一个 JSON 任务描述：源与目标传递函数、源与目标色域及白点、参考白亮度与峰值亮度、色调映射曲线参数、逐帧统计窗口参数，以及一段由程序按确定性规则生成的本地浮点帧数据（每帧给出 HDR 线性光三通道浮点值）。组件需输出转换后的帧数据、逐帧与逐窗口的亮度统计报告，并支持异常注入清单验证错误链路。所有样本本地生成，不依赖真实素材或外部库。

任务环境与准备：
准备 Windows 本机 Python 3.11 与 NumPy（安装说明由任务执行方自行完成，不预先验证）。
在工作区创建项目目录与本地样本生成脚本，按确定性种子生成浮点帧数据 JSON 与任务描述 JSON。
确认输出目录可写并准备中断信号测试方式（进程级可处理终止信号），不依赖任何网络或外部素材。

业务要求：
1. 实现任务描述解析与输入校验：读取 JSON 任务描述与帧数据，校验传递函数与色域属于允许集合、参考白亮度与峰值亮度为有限正数且峰值不小于参考白、色调映射参数在定义域内、帧数据三通道长度一致且不含 NaN 或 Inf，非法输入返回带 E_xxx 业务码的 JSON 错误且不产生任何输出文件。
2. 实现传递函数的正向与逆向变换：按规格实现 SDR gamma、HLG 与 PQ 三条曲线的编码与解码，HLG 与 PQ 的解码须给出绝对亮度（cd/m2），逆变换须与正向在数值容差内往返一致，分段点两侧连续且不得出现跳变；三条曲线的常数须与规格表逐项一致并在报告中标明所用曲线。
3. 实现色域矩阵与白点适应：按源与目标色域的三基色色度坐标构造 RGB 到 XYZ 矩阵及其逆矩阵，并按源与目标白点做 Bradford 色适应；矩阵须由色度坐标数值计算而非硬编码，往返转换误差在容差内，超出目标色域的像素须记录色域外占比供后续映射使用。
4. 实现亮度域色调映射与逐通道回压：按色调映射曲线把绝对亮度压到目标峰值内，映射须保持单调且不产生色相偏移，逐通道回压后若任一通道仍超出目标范围须按确定规则处理并计数，映射前后亮度守恒程度须写入统计报告，全黑帧与超高峰值帧均须有确定结果。
5. 实现逐帧与逐窗口亮度统计：按统计窗口参数在帧序列上切分窗口，逐帧与逐窗口计算亮度均值、峰值与超目标峰值像素比例，窗口起止帧与报告字段严格对应，末尾不足一窗的帧按规格规则处理；统计值只依据转换后的最终帧数据，不得使用映射前的中间量。
6. 实现异常注入驱动的错误链路验证：按任务描述中的异常注入清单在指定帧注入 NaN、负亮度、超峰值溢出、错误传递函数声明等情形，组件须对受影响帧或整帧给出可区分的业务码并继续处理其余合法帧，报告须汇总注入位置与首错帧序号，注入不得修改源码或样本源文件。
7. 处理可处理终止信号与原子写出：外部可发送可处理终止信号使任务在帧块边界写入中断标记并以约定整数退出码退出，未完成帧块不得留下可被误认为完成的中间结果；输出帧数据与统计报告须先写同目录临时文件再整体替换，替换前读取已有输出文件的帧数与参数摘要版本信息，仅版本不同才替换，强制终止后仅依赖已持久化状态恢复。
8. 实现并发帧块处理与资源上限：按任务描述中的并发数使用有界线程池处理帧块，同时处于计算中的帧数据与矩阵中间量总量受内存预算限制，转换矩阵与曲线查表须在并发间只读共享，最终拼装结果须与并发度为 1 时逐元素相同，任一帧块失败时取消其余待处理块并返回首个错误。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
