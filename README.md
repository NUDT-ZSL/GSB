电子合同签署高峰期，同一客户批次的合同编号前缀集中爆发，签约平台某几个存储分片读写过载，其他分片却大量空闲。运维工程师需要依据实时访问计数与容量水位认定热点分片及热点合同号子范围，把热点范围内的合同文档元数据、印章使用记录与签署事件迁往空闲分片，迁移期间签署流程不能中断，合同归属不能错乱，迁移意外中断后必须从断点续迁，最终分片分布与一次性全量迁移等价。

任务环境与准备：
在 Linux（WSL Ubuntu）下准备 Python 3 运行环境，仅使用标准库，无需安装第三方包。
工作区从空目录开始，题内确定性生成器、参考区间路由器所需的样本与固定种子参数都由实现自身产出，程序通过命令行入口在本地离线运行。

业务要求：
1. 按固定种子从确定性生成器装载合同文档元数据、印章使用记录、签署事件流、分片拓扑声明与访问请求序列，将三者按合同编号关联为统一合同事件模型，输出每个字段的来源路径与按合同号范围建立的区间路由表初始归属，并校验合同文档字节汇总与分片已用字节声明互相对账。
2. 以滑动热点检测窗口逐分片统计窗口内访问请求次数，同时按承载合同的文档字节汇总计算各分片容量水位，叠加分片容量上限与迁移阈值参数认定热点分片及其热点合同号子范围，输出热点评分、各因子取值和认定依据；当热点合同号子范围恰跨两个分片路由边界时，拆分归属并分别标记。
3. 对每个热点合同号子范围按待迁字节量与迁移批次容量生成从源分片到目标分片的迁移计划，目标分片须保证承接后容量不超上限、且优先选择低水位分片，输出待迁合同清单、字节数、批次划分与目标分片选择理由；容量不足以承接时给出拒绝结论与缺口字节。
4. 迁移执行期间逐请求裁决路由：读请求仍由源分片服务，写请求先在源分片落地再同步到目标分片，迁入的合同键在源分片置为迁移中状态，输出逐请求路由记录，并核对窗口内每次写后在源与目标两侧可见的合同逻辑版本一致。
5. 某个迁移批次内全部合同完成两侧同步后，以区间路由表的原子替换将热点合同号范围指向目标分片，输出切换前后路由表差异、各分片负载与容量分布，并给出热点是否消除的判定；切换后源分片上该范围的合同键须标记为待回收而不误服务。
6. 迁移在批次中途被强制中断时，依据已迁移批次清单与迁移中键状态持久化快照从断点续迁，禁止重复迁移已完成合同，输出续迁后的路由表与逐合同分片归属，并与不走中断的全量迁移结果逐合同号范围比对一致性。
7. 对由人工构造的边界样本——热点区间恰跨分片边界、迁移中同一合同被并发读改写、批次切换完成后立刻断开、目标分片正好承接至容量上限——逐一给出可观察的路由与状态结论，异常输入以参数注入方式触发并以整数符号码标识。
8. 将迁移计划、逐请求路由记录、切换前后路由表与续迁结果写入结构化报告文件并按固定键序输出，使同一工程重复运行结果逐字节一致，运维人员能据报告回看任一合同的事件关联与分片归属变化。

验收：
以构造热点真值核对热点认定与迁移计划，用独立区间路由参考器逐请求核对路由与合同状态，并验证中断续迁路由表与全量迁移逐合同范围一致。
