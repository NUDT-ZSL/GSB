当前是空白工作区，需要从零构建一个面向本地 Windows 环境的推理批处理调度与数值精度诊断工作台，属于 ML 训练与推理系统方向下的推理批处理与调度场景。系统使用固定随机种子的本地确定性样本，构造一个小型多层前馈推理模型与一组待推理样本；用户以本地 JSON 文件声明批处理配置：批大小上限、批内样本排序策略、数值精度模式（float32 与定点量化两种）以及量化缩放因子。工作台须把样本按声明策略分批，在每条批内以 NumPy 完成前向推理，并对每条输出记录数值精度诊断信息，包括逐层中间量的定点化误差界、与浮点参考输出的偏差以及偏差沿层传播的归因链。核心业务是：当批大小、批内排序或精度模式发生变化时，推理结果与诊断结论须整体按新参数版本替换而非增量合并，且同一配置组合多次运行必须得到逐位一致的输出与诊断结果；中断后只能依据持久化快照恢复已完成批次的结论。

任务环境与准备：
安装 Python 3.10 或以上，并在任务开始前用 pip 安装 numpy；tkinter 使用 Windows 官方安装包自带组件。
在空白工作区创建项目目录，预置确定性样本配置与模型参数文件，均使用受控随机种子生成本地数据。
准备演示脚本与样本快照目录，确认可在无网络、无外部服务的本地环境重复运行。
运行前确认工作区中不存在旧的快照与缓存文件，以免干扰版本识别与重放校验。

业务要求：
1. 实现本地确定性样本与模型参数的构造：以命令行参数指定的整数随机种子、样本数、输入维度与隐藏层维度生成固定数据集与各层权重偏置，相同参数组合多次运行必须得到逐位一致的输入矩阵与参数矩阵；须把数据摘要与参数摘要写入推理报告，摘要不一致时以 E_DATA 业务码整体拒绝本次推理。
2. 实现批处理配置与批划分：从本地 JSON 读取批大小上限、批内排序策略（按样本标识、按输入范数或保持输入顺序）与精度模式，校验批大小为正整数、排序策略属于受支持集合、量化缩放因子为 10 的整数幂；按声明策略对样本稳定排序后划分批次，相同配置必须产生相同的批边界与批内样本顺序，非法配置以 E_CONFIG 拒绝。
3. 实现 float32 与定点量化两条前向推理路径：浮点路径以 NumPy 前向计算作为参考输出；定点路径把权重、激活与累加按声明的缩放因子量化为整数并显式处理舍入方向与溢出饱和；两条路径须逐批产出输出矩阵，定点路径须同时输出每层中间量的量化误差界与累计误差界，量化误差界须以整数格表示并说明其推导依据。
4. 实现逐层数值偏差归因链：对每条样本逐层比较定点中间量与浮点中间量的偏差，按层归因并计算输出端的相对偏差分数，输出偏差最大的层与累计误差占比；归因须与批边界无关，同一批内不同位置的同一样本必须得到相同归因结果，偏差超出阈值时以 E_DRIFT 标记该批次并记录首个超限的层与样本标识。
5. 实现精度模式与批参数变更后的整体替换刷新：当批大小、排序策略或精度模式版本号变化时，已有批次的输出与诊断结论须被标记为陈旧且不得参与当前报告，新参数版本下的全部批次结果须整体替换旧结果；报告须稳定列出新旧版本的差异批次、差异层与偏差变化方向。
6. 实现推理会话快照与版本识别的整体替换恢复：快照持久化数据摘要、参数摘要、批处理配置版本、已完成批次输出摘要与逐层误差界；重新打开快照时须先比较快照中的数据摘要与配置版本同当前会话是否一致，不一致须整体替换当前批次状态与结果缓存而非增量合并，并保留旧快照为只读备份；恢复后须能继续未完成批次。
7. 实现恢复后的重放校验与逐位一致性验证：从快照恢复后按快照记录的配置版本与批划分重新执行已完成批次，将每条样本的输出、逐层误差界与归因结果与快照记录逐位比较，差异须定位到首个不一致的批次序号、样本标识与层名并输出 E_REPLAY；因配置版本或量化缩放因子不一致导致不可复现时须在报告中说明具体不可复现项。
8. 提供 Tkinter 诊断界面与可重复演示脚本：界面展示批列表与批内样本标识、精度模式、逐层误差界热力、偏差归因链、当前配置版本与快照列表，渲染顺序稳定；附带确定性样本配置与演示脚本，顺序执行浮点与定点各一次推理、变更量化缩放因子后重推理、快照恢复后重放三个场景，输出稳定顺序的诊断总结。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
