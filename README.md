当前是空白工作区，需要从零构建一个面向本地 Windows 环境的变更风险与回滚运维应用，交付形式为领域数据编辑与操作应用。变更单以本地 JSON 文件录入，包含一组配置变更项（键、旧值、新值、类别、影响服务与来源系统），变更单本身存在三种历史格式版本：v1 只含变更项键与值，v2 增加类别与影响服务，v3 再增加来源系统与整数风险权重。回滚计划描述每个变更项的回滚动作与依赖顺序，回滚依赖之间可形成图。核心业务是：把变更单统一归一为内部模型，按风险权重与影响面计算变更风险分数，生成可按依赖顺序执行的回滚计划，并在执行过程中维护回滚账本；当变更单格式版本或依赖关系演进时，须准确推导受影响的回滚步骤并整体替换旧结论。应用以 Tkinter 界面编辑与本地 SQLite 持久化账本，所有数据来自本地确定性样本。

任务环境与准备：
安装 Python 3.11 及以上版本，确认标准库 sqlite3 与 tkinter 可用（Windows 官方安装包默认包含 Tk）。
在空工作区创建项目目录与本地样本目录，准备三版本变更单 JSON 样本、回滚计划样本与账本 SQLite 目标路径，样本由本任务提供内容自行编写，不依赖外部下载。
准备一个本地演示脚本入口，按顺序驱动加载、风险计算、回滚执行与恢复重放；无需网络、外部账号或容器环境。

业务要求：
1. 实现三版本变更单的加载与归一：v1 项含键与值，v2 增加类别与影响服务，v3 再增加来源系统与整数风险权重；加载时检测格式版本，未知版本、字段缺失或类别不在受支持集合须以 E_FORMAT 整体拒绝并输出出错字段路径，同时把各版本统一归一为带版本来源标记的内部模型，归一结果须稳定可比较。
2. 实现回滚依赖图构建与强校验：从回滚计划读取每步的回滚动作与其依赖的回滚步骤，校验回滚步骤标识唯一、依赖引用存在、图中无环；依赖成环须以 E_DEPEND 整体拒绝并输出环上步骤序列，删除仍被依赖的回滚步骤须拒绝并列出依赖者，图的遍历输出顺序不得依赖字典或哈希顺序。
3. 实现风险分数计算与定点误差界：对每个变更项按风险权重、影响服务数与类别系数以整数定点方式计算风险贡献并聚合为变更单风险分数，给出单值量化误差与聚合误差上界；当两个变更单风险分数之差落在误差界内时须按显式决胜规则排序，并在诊断输出中标注该判定由误差界主导。
4. 实现格式版本升级与回滚计划的增量重算：变更单从低版本升级到当前版本时，仅对新增或变化的变更项重算风险贡献，未变化项的贡献须保持不变且可校验；升级后须识别受影响的回滚步骤集合并重新生成回滚顺序，受影响集合的推导须与全量重算在顺序与风险贡献上逐项一致，不一致以 E_INCR 报告首个差异步骤。
5. 实现回滚执行账本与幂等重放：按回滚顺序逐步执行回滚动作并把每步的结果、所用变更单版本、风险分数快照与时刻写入本地 SQLite 账本；重复执行同一回滚步骤须幂等返回已记录结果而不重复写入，账本记录须能逐项对应回滚计划步骤，缺失或多余步骤须以 E_LEDGER 报告并列出偏差步骤标识。
6. 实现变更单版本演进后的整体替换恢复：账本与界面中的风险结论、回滚计划与执行状态须带变更单版本与回滚计划版本；变更单被修改后版本号单调递增，当前视图须整体替换而非增量合并，替换时须稳定列出发生变化的变更项、受影响回滚步骤与被清空的重算缓存条目数，旧版本结论保留为只读历史。
7. 实现强制终止后的恢复与一致性重放校验：进程被强制终止后重启只能依据账本中已完整写入的回滚步骤恢复，未完成步骤须标记为未知并要求重跑，不得声称生成退出报告；恢复后按账本记录的变更单版本与回滚计划重新计算风险分数与回滚顺序，与账本逐项比较，不可复现须以 E_REPLAY 报明具体步骤与依据。
8. 实现 Tkinter 编辑界面与异常注入：界面须展示变更项列表与来源版本、风险贡献与误差界、回滚依赖图、受影响步骤集合、账本执行状态与版本列表，渲染顺序稳定；支持以命令行参数注入变更单文件损坏、回滚依赖成环、账本版本冲突三类异常并分别以 E_FORMAT、E_DEPEND、E_VERSION 报告，注入仅改变输入文件或参数，附带确定性样本与顺序演示脚本。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
