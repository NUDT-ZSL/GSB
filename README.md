当前是空白工作区，需要从零实现一个本地异构加速卡算力切分与租赁裁决组件，以数据处理管线加结果验证工具形式交付。与按整卡分配的调度不同，本场景把每张卡视为可被切分为若干算力份额与显存份额的租赁单元：训练作业按声明的算力份额需求与显存份额需求申请一份或多个切分租约，租约在逻辑时钟下被授予、续租、到期回收与抢占回收，回收后的算力份额与显存份额须能重新组合成满足后续作业需求的切分。本地 JSON 样本给出：加速卡清单（卡 ID、总算力份额单位、总显存份额单位、支持的切分粒度、健康状态、拓扑域）、作业清单（作业 ID、所需算力份额、所需显存份额、租约时长逻辑毫秒、优先级、配额组、是否可被抢占、是否容忍跨卡拼接）、租赁配置（配额组算力份额上限、切分对齐粒度、续租宽限逻辑毫秒、碎片阈值、逻辑时钟步进表）。组件需产出逐轮可复现的租约账本与回收报告。

任务环境与准备：
安装 Python 3.11 或以上版本，并确认标准库 sqlite3 可用。
安装 NumPy（用于切分区间对齐与碎片组合的向量化计算），版本以本地离线可用的稳定版为准。
在空工作区下准备本地样本目录：加速卡清单、作业清单、租赁配置与异常注入清单各一份 JSON，样本由本地确定性生成脚本产出，不依赖任何外部集群或真实加速卡。
确认工作区目录可写，用于生成 SQLite 账本库、账本指针文件与分阶段回收报告；无需启动任何网络服务。

业务要求：
1. 实现加速卡清单、作业清单与租赁配置的解析校验：卡 ID 与作业 ID 唯一、总算力与总显存份额为正整数且能被切分粒度整除、作业需求份额为正整数、租约时长为正整数逻辑毫秒、优先级与配额组枚举闭合、不支持跨卡拼接的作业其需求份额不得超过单卡剩余、续租宽限小于租约时长；非法条目返回独立业务错误码且不写入任何持久化状态。
2. 实现算力份额与显存份额双重维度下的切分租约授予：在配额组算力份额上限、每卡剩余算力份额与剩余显存份额三重约束下决定作业落在哪张卡的哪个切分区间，算力与显存任一不足即拒绝并给出首个触发约束与相关份额数值；同一卡的切分区间不得重叠，授予须记录起始份额、长度与对齐位置。
3. 实现基于注入逻辑时钟的租约续租与到期回收：续租判定只依赖注入逻辑时钟毫秒值与续租宽限，续租须校验作业身份与租约代数，过期未续的租约进入回收态并释放其切分区间；同一逻辑时钟序列下重复运行必须得到逐位一致的续租与回收序列，逻辑时钟回拨超过容差返回业务错误码。
4. 实现碎片感知的回收后重组裁决：被回收的算力份额与显存份额碎片须按切分对齐粒度重新组合成候选区间，并判定某等待作业能否被这些碎片满足；必须区分真无剩余资源与碎片导致不可满足，输出导致失败的关键碎片分布，并说明重组所依赖的碎片拼接顺序与对齐假设。
5. 实现高优先级作业的可抢占回收推演：当高优先级作业无法授予时，按优先级与租约剩余时长推演可被抢占回收的租约集合，输出完整回收链与回收后能否授予的判定依据；被抢占作业须保留已消耗份额的退还未结记录，回收不得使同一卡已授出份额超过总份额。
6. 实现租约账本与切分占用映射的持久化及强制终止后的恢复：租约代数、切分区间占用、配额组已消耗份额、退还未结记录与逻辑时钟水位以事务原子写入 SQLite，每轮提交识别版本变化并整体替换账本指针；进程被强制终止后只重放未提交轮次，不得重复扣减份额或重复登记退还。
7. 实现异常注入与异常链路隔离：按本地注入清单在授予、续租、回收、重组四个阶段注入切分区间重叠、账本份额不守恒、续租代数回退、碎片重组摘要不匹配等受控异常，每种异常映射到不同业务错误码并保留轮次号与卡 ID；注入不得修改样本源文件，单个异常不得中断其他卡的租赁裁决。
8. 实现多进程并发一致性与可重复命令行验证工具：多个裁决实例并行处理同一批作业时通过 SQLite 事务与文件锁保证同一卡同一切分区间的授予只提交一次、配额组已消耗份额不被并发超扣，重复提交相同轮次结果幂等；提供 load、lease、preempt、resume、status、verify 子命令，verify 校验切分区间不重叠、份额守恒与退还未结账目。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
