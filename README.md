当前是空白工作区，需要从零构建一个面向对话级语音情感分析的本地领域数据编辑与操作应用。业务对象是本地确定性合成的单声道 16kHz PCM 对话音频：用固定种子生成若干说话人的基频、共振峰与能量包络参数，按给定对话时间轴与增益叠加为混合信号，并附逐帧真值文件（帧长 20ms，字段含 frame_index、speaker_id、valence、arousal、is_speech）与对话清单（JSONL，字段含 dialog_id、sample_rate、duration_ms、seed、speaker_count、frame_ms），另有一份注册样本清单（JSONL，字段含 speaker_id、clip_seed、clip_ms、registry_version）。分析流程被建模为四个阶段：重采样与分帧（帧级能量与过零率）→ 说话人分段（基于注册样本的嵌入统计量做确定性指派）→ 段级情感维度回归（valence 与 arousal）→ 对话级聚合与报告。核心业务问题是状态演进与恢复一致性：一次长对话分析可能被分成多批推进，每批结束后必须留下可持久化的阶段快照；进程在任意批之间被强制终止后，重启必须从最后一个已提交阶段继续，不得把未提交的中间分段当作已完成结果使用，也不得对已提交阶段的对话重复计分。同时，说话人注册样本追加会使嵌入统计量版本升级，已提交的阶段快照与缓存必须识别版本变化并整体替换。

任务环境与准备：
安装 Python 3.11 并使用标准库加 NumPy，版本在依赖清单中固定。
无需外部服务、GPU 或网络，音频、注册片段与真值样本全部由脚本用固定种子在本地合成。
在工作区创建空项目目录并初始化可运行的命令行入口，确保 Windows 下可执行。

业务要求：
1. 实现确定性特征与分帧阶段：按 frame_ms 与帧移切分 PCM，帧边界以样本索引精确确定，计算短时能量与过零率，输出逐帧特征与帧数；同一 dialog_id、同一 seed 与同一配置下必须逐字节产出相同的特征序列，且帧数须与逐帧真值文件完全对齐，采样率非 16000 或帧移超过帧长返回 E_CONFIG_INVALID 并指明字段。
2. 实现说话人分段阶段：由注册样本清单中的固定种子与时长确定性合成注册片段，估计每个说话人的嵌入统计量，对每帧按确定性相似度打分指派说话人编号，同分按 speaker_id 升序打破平局，输出连续段与切换时间轴；须校验逐帧标签与真值的说话人编号属于同一受控集合，越界返回 E_SPEAKER_INVALID 并指出 dialog_id 与帧号。
3. 实现段级情感回归与对话级聚合：按说话人连续段对 valence 与 arousal 做确定性回归并给出每段置信区间，对话级按段时长加权聚合并显式记录权重口径；同一输入与配置重跑得到相同分数与相同排序，聚合分数须可由分段明细与权重独立重算一致。
4. 实现四阶段状态机：分帧、分段、回归、聚合各阶段产生带单调递增版本号与内容校验和的阶段快照，只有当该阶段全部对话处理完成才提交；提交顺序、阶段状态与版本号必须在持久化存储中原子可见，部分完成的阶段不得提交。
5. 实现强制终止后的恢复逻辑：重启时读取已提交快照，从最后已提交阶段继续推进，已提交阶段的对话不得重算或重复计分；未提交的中间分段与回归状态必须丢弃并从该阶段起点重建，恢复后的完整报告须与不间断完整运行结果逐字节一致。
6. 实现说话人注册样本追加引起的版本演进：注册样本、嵌入统计量与缓存条目各携带版本号与内容校验和，检测到版本变化时必须整体替换旧快照而非增量修补；版本不变的快照必须复用，不损坏的快照在加载时返回 E_SNAPSHOT_CORRUPT 并指明阶段名与版本号。
7. 实现并发提交控制与资源上限：同一时刻只允许一个阶段提交生效，并发冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待，已提交阶段不得被旧版本回退覆盖，回退尝试返回 E_SNAPSHOT_ROLLBACK；为单阶段对话数、驻留特征与分段内存估算设可配置上限，超限返回 E_RESOURCE_LIMIT 并标记降级类别。
8. 提供本地可交互应用与跨模块一致性自检：展示当前阶段、快照版本、各阶段对话计数、恢复报告与最近业务错误码，允许触发一次演示——执行分析、在指定阶段后强制终止、重启从已提交快照恢复并对比恢复结果与完整运行结果；自检校验各阶段 dialog_id 集合一致、分段标签首尾相接无重叠、恢复与完整运行报告哈希一致，不一致返回 E_INCONSISTENT。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
