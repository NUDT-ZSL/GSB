当前为空白工作区。需开发一个面向回合制卡牌对战的规则回放验证工具。本地提供可确定性生成的战斗事件流样本（JSON 行格式，每行含 seq、actor、action、target、cost、rng_seed_delta 等字段）以及规则配置（卡牌费用、资源上限、触发链深度）。工具需按事件顺序重放对局，校验费用扣除、资源预算上限、随机数派生链与触发链嵌套深度，检出违规事件并定位首个分歧点。回放需支持多份对局并行验证，而每份对局内部的触发链必须串行执行以保持事件因果；并行度受线程数预算和内存预算双重约束，超预算时须降级而非崩溃。输出为结构化校验报告与可复核摘要。

任务环境与准备：
确认 Windows 上可用 Python 3.11 或以上，并能通过 pip 安装 NumPy 与 pytest（仅本地包，不联网拉取样本）。
在工作区创建项目目录并初始化虚拟环境，安装 NumPy 与 pytest 后运行 pip list 确认版本。
准备本地合成事件流生成脚本或直接由入口命令内置生成，样本不得依赖任何真实游戏资产或远程服务。
确认 CPU 核心数与可用内存，用于设置线程数预算与单对局内存预算的默认值。

业务要求：
1. 实现事件流解析与规则重放引擎：按 seq 严格递增校验输入，若出现序号跳变或重复则判定为 E_SEQ_GAP 并终止该对局重放；每步执行费用扣除、目标合法性检查与状态转移，产出逐步状态快照供后续比对。
2. 实现随机数派生链：每个事件按 rng_seed_delta 从对局种子派生独立随机流，派生结果只依赖 (种子, seq, delta)，不依赖执行顺序或线程调度；同一事件流两次重放的随机流序列必须逐值相同，派生偏差记录为 E_RNG_DRIFT。
3. 实现触发链的串行执行与深度限制：单事件触发的连锁效果在同一对局内严格按因果顺序展开，最大嵌套深度由配置给出，超出时中止该链并记录 E_TRIGGER_DEPTH，已产生的部分状态需回滚到链开始前的快照。
4. 实现并行调度器：将多份对局分配给工作线程池并发验证，单对局内部保持串行；调度器须支持线程数预算与单对局内存预算，资源不足时按队列降级为更低并行度并记录降级原因，不得因预算紧张导致结果缺失或顺序错乱。
5. 实现资源预算校验：按事件统计累计费用消耗与瞬时资源上限，任何事件使资源为负或超过上限时返回 E_RESOURCE_OVERFLOW 并标记该事件；预算报告须列出每对局峰值使用、越界次数与首个越界事件序号。
6. 实现首个分歧点定位：对比两份重放报告（如修复前后或不同规则配置），按 (对局ID, seq) 定位首个状态哈希不一致的事件，输出分歧上下文快照；无分歧时须给出全量一致的显式结论，不得仅凭条数相等即判一致。
7. 定义业务错误码并覆盖异常链路：E_SEQ_GAP、E_RNG_DRIFT、E_TRIGGER_DEPTH、E_RESOURCE_OVERFLOW、E_BUDGET_DENIED、E_MALFORMED_EVENT 等，非法字段类型、缺失必填字段与未知动作须返回明确业务码而非通用异常，且单对局失败不得中断其他对局。
8. 提供确定性验证入口：一条命令生成合成事件流样本（含正常局、序号断裂局、预算越界局、深层触发链局），在固定线程与内存预算下运行验证，输出结构化报告与内容哈希；两次相同输入与预算的运行必须产生逐字节相同的报告正文。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地合成事件流在预算约束下运行验证，检查业务码、报告哈希确定性与首个分歧定位。
