港口生产调度数据库的管理员与泊位计划员每天要看一批靠泊作业记录：船舶标识、泊位编号、计划靠泊与离泊时刻、作业吨位、货种，按写入顺序逐条进入作业记录表。随着船期不断追加，按键顺序写入的索引频繁发生页分裂，同一组“泊位占用区间重叠”和“靠泊时刻闭区间”查询在不同索引定义下的返回结果与访问代价差别很大。计划员无法判断某次查询结果是索引口径变了还是页链表在分裂后断了，因此需要一个本地可反复运行的内核：从固定种子生成港口作业样本与查询请求，构造可观测的 B+Tree 页结构，执行插入、页内有序分裂、中位键上移与叶子链表维护，再用全表扫描结果作为独立基准逐条核对范围扫描，并对候选索引给出选择结论。

任务环境与准备：
使用 Linux（WSL Ubuntu）本机 Python 3 运行环境，只使用标准库，不安装第三方包。
在空工作区中创建项目目录与入口脚本，样本生成、索引构建、查询核对与报告输出均从该入口按固定种子执行。
运行前确认当前目录可写，以便写入索引快照与查询报告的 JSON 文件。

业务要求：
1. 实现确定性港口作业记录生成器：给定固定种子与写入批次数，产出船舶标识、泊位编号、靠泊时刻与离泊时刻、作业吨位、货种以及记录写入顺序；样本须覆盖同一靠泊时刻多条记录、键恰好落在页容量边界、离泊时刻等于靠泊时刻的零长区间与连续重复泊位编号等边界形态，并按批次序列输出。
2. 实现带页容量与分裂填充因子参数的 B+Tree 插入：按键顺序在叶页内有序插入，页满时按分裂填充因子切成两页并将中位键上移父页，父页满时按同一规则递归上移；每发生一次分裂须记录页号、所在层级、被上移的分裂键、分裂前后两页的键数与填充率。
3. 维护叶子页双向链表，每批写入完成后输出索引结构快照，包含总页数、各层页数与层级深度、每页键数与容量占用，并检查链表连通性，能报告断裂、重复链接或指向不存在页的具体页号。
4. 对泊位占用区间重叠查询与靠泊时刻闭区间查询，从根页逐层比较键定位起始叶页，沿叶链表扫描至终止边界后停止，输出起始落点页号、终止落点页号、逐页访问顺序、命中记录集合与访问页数，并保证命中顺序为键序稳定顺序。
5. 以同一批样本的全表扫描过滤结果作为独立基准，对每个查询逐条比对索引扫描与全表扫描的命中记录集合、重复条目与顺序，一旦不一致须指出具体查询、缺失或多余记录以及首次分歧位置，并在全部一致时明确报告一致。
6. 对至少三种候选索引定义（如泊位编号与靠泊时刻组合、靠泊时刻与离泊时刻组合、单一靠泊时刻）分别构建并执行同一组查询，比较页分裂次数、叶子平均填充率、扫描页数与落点正确性，给出面向泊位区间查询的索引选择结论并说明取舍依据。
7. 支持在已有索引上仅对新批次键执行增量插入并更新结构快照，验证增量插入后全部既有查询的结果与在同一全量数据上重新构建索引再查询的结果逐查询一致，不一致时须定位到查询与页。
8. 将索引结构快照与查询结果报告持久化为本地 JSON 文件，中断后可从最近快照恢复索引继续追加写入，恢复后的分裂计数、页结构与链表连通性须与连续写入路径得到的结果一致。

验收：
用全表扫描基准核对索引范围扫描结果，并核实增量插入、快照恢复与全量重建三种路径的查询结果一致。
