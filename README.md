游戏动捕配音的现场录制会用多台采集设备同时记录不同通道：设备之间采样率与位深不一致（44.1kHz 16bit、48kHz 24bit、96kHz 24bit 混用），各自的本地时钟在启动时刻和运行速率上都有偏差，长时间录制还会缓慢漂移。录制结束后必须把各通道统一到一条参考时间轴上，才能在同一工程里做对齐审阅与后续混音。眼下目录里还没有任何代码和样本，能用的只有一台装好 Python 的 Windows 开发机；全部 WAV、采集元数据与两代工程描述都由随题交付的固定种子脚本确定性生成，不依赖真实设备、驱动或网络。业务对象是本地采集会话：会话 JSON 声明设备标称参数、参考设备、各设备样本中的脉冲同步标记理论位置；两代工程快照并存——v1 为单文件 JSON，以相对起始秒数与整数采样点记录设备偏移与通道启用状态；v2 为分片 JSON 加 SQLite 元数据库，记录规范通道标识、绝对逻辑毫秒起点、漂移率与代数、墓碑标记。工程需要在工作台里被编辑（调整偏移微调、启用禁用通道、改变参考设备），编辑后只重算受影响的通道与时间区间，并在中断后继续得到与不中断一次跑完相同的对齐结果。

任务环境与准备：
Windows 10/11 本地工作区，安装 Python 3.11 或 3.12，并执行 pip install numpy==1.26.4 与自带 sqlite3 模块（Python 标准库，无额外安装）。
准备固定种子样本生成脚本，确定性生成各设备 WAV、采集会话 JSON、脉冲同步标记声明与 v1/v2 两代工程快照，样本随工程交付，不依赖外部数据。
创建空的项目目录与状态目录，确认可写；运行前无需网络、真实音频设备或外部服务。

业务要求：
1. 实现采集会话、各设备 WAV 文件头与两代工程快照的解析校验：采样率属于允许集合、位深为 16 或 24、声道数与元数据声明一致、脉冲同步标记理论位置落在文件范围内、v1 相对秒可换算为绝对逻辑毫秒、v2 漂移率为有限小数且代数与墓碑标记自洽；非法输入按会话或通道返回可区分业务码且不产生任何输出文件。
2. 实现同步脉冲检测与起始偏移、漂移率估计：在各设备样本中按会话给出的搜索窗检测确定性脉冲峰值采样点，把峰值与理论位置之差作为观测，按工程声明的漂移模型阶数做最小二乘估计，输出整数采样点起始偏移与漂移率；可用脉冲数不足以确定模型阶数时按降级规则返回 E_SYNC 并在报告中标注该设备，而不是静默给出零漂移。
3. 实现参考时间轴映射与整数采样点一致性：以参考设备采样率为统一时间轴，按估计偏移与漂移率把每个通道映射到参考时间轴，漂移按线性模型逐采样插值补偿，映射误差不超过 1 个参考采样点；参考设备通道被禁用或剔除时按确定规则重选参考，任意两通道在同一参考时刻的相对误差不超过声明容差，且映射结果不随并发调度改变。
4. 实现两代快照的字段互操作归一与冲突裁决：按版本适配规则处理时间单位由毫秒改微秒、声道标签由整数改名称、增益单位变化等字段差异，未声明适配且语义不一致的字段判为不可自动兼容并返回 E_COMPAT 指向具体通道与字段；同代同规范标识按代数取新、墓碑优先，两代冲突按代数与逻辑时刻裁决并逐条产出可定位到分片与通道的冲突项。
5. 实现按通道与时间区间的依赖记录与增量重算：为每个通道的每个时间块记录其对偏移微调量、漂移率、增益、启用状态与参考设备选择的依赖，编辑脚本任一步发生后只把受影响的通道与时间块标记失效并重算，其余块复用已持久化结果；增量结果与同输入从头全量处理在逐通道逐采样点上一致，报告须逐条列出失效理由与受影响区间。
6. 实现分块级持久化、版本识别与中断恢复：按通道与时间块把对齐中间量与块摘要及由全部输入内容规范化摘要构成的版本标识原子写入状态目录（先写临时文件再整体替换），替换前识别旧版本标识变化；可处理终止信号只在块边界生效并写入中断标记后以约定整数退出码退出，强制终止后重启仅依据摘要有效的持久化块恢复且不承诺生成退出报告。
7. 实现并发通道加载与双资源上限：按会话并发上限使用有界线程池并行解码、检测脉冲与映射各通道，同时在途解码缓冲与映射中间量总量不得超过声明的内存预算，超出时按设备标识确定顺序让后续通道等待而非降低检测精度或截短搜索窗；任一通道失败时取消其余待处理通道并以首个错误终止，报告保留已完成合法通道的结果。
8. 实现桌面诊断视图与产物原子导出：视图展示统一时间轴上的各通道波形缩略、脉冲观测点与拟合偏移漂移线、冲突项与失效区间列表，并可从异常业务码或冲突项跳转到对应通道与时间块；导出的多通道拼接结果与 JSON 报告先写同目录临时文件再整体替换正式文件，视图只读取已持久化且摘要有效的块结果。
