当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向 LLM 偏好对齐与奖励建模数据准备的本地工作台。业务对象是本地确定性生成的偏好对样本（JSONL，字段含 pair_id、prompt、chosen、rejected、annotator_group、quality_flag），以及一份构造配置：质量打分各分项权重、近重复相似度门限、标注者一致性平滑系数、每标注者组与每质量档的采样配额、并行 worker 数与每批 pair 数、乘加运算预算与驻留内存预算、数值精度档。构造链路被建模为多级流水：质量打分→近重复检测与分组→对级一致性判定→配比采样→数据集清单导出。核心业务问题有两层耦合：一是多标注者组并行构造时必须在乘加预算、驻留内存预算与 worker 槽位三重约束下决定准入集合与分批规模，批规模放大能减少归约开销但逼近内存上限，worker 增多能缩短整体耗时但分摊预算；二是修正某个标注者组的样本或调整质量权重、相似度门限后，必须按内容寻址缓存键精确计算受影响的层级与 pair 集合，只重算受影响后缀，并保证局部修正后的结果与全量重算逐字节一致，同时拒绝继续使用旧版本配置产出的过期清单。

任务环境与准备：
确认可用的 Python 3.10 及以上版本，并安装 NumPy（版本在项目依赖声明中固定），全程使用本地虚拟环境。
在空白工作区初始化项目目录，创建样本生成脚本，用固定随机种子确定性生成偏好对 JSONL、构造配置与调度预算参数，不依赖任何外部网络或真实账号。
准备本地进程池可用的运行环境，确认并行 worker 数与内存上限在开发机上可按预算参数声明进行配置。
准备运行与验证脚本的执行入口说明，使诊断报告可写入本地文件，便于比对两次运行的输出哈希与业务码。

业务要求：
1. 实现确定性的质量打分级：质量分由回复长度、重复率与噪声字符比例按配置权重加权得到，每个分项贡献须显式记录，同分 pair 按 pair_id 升序打破平局；同一输入与同一配置下必须逐字节产出相同的分项分数、加权总分与 pass 标记，禁止依赖系统时间或未声明随机源。
2. 实现近重复检测与分组级：按文档给出的分块签名口径计算相似度，相似度不低于门限的 pair 归入同一簇，簇内按质量分降序、再按 pair_id 升序保留代表；须保证每个 pair 恰属一个簇、簇代表不重复，且门限比较采用可配置的严格或容差带策略。
3. 实现对级一致性判定级：同一 prompt 下 chosen 与 rejected 不得交叉矛盾，同一标注者组内标签方向须一致，违反时按显式规则标记冲突 pair 并返回结构化业务码；须输出冲突 pair 对、冲突类型与其参与判定的分项证据，使冲突判定可由证据独立复核。
4. 实现配比采样与欠配归因级：在每标注者组与每质量档的采样配额下做确定性采样，优先满足总量并允许受限欠配；清单须记录每个配额目标的实际达成量、欠配原因与采样种子，使同一快照同一配置重跑得到相同清单与相同采样序列。
5. 实现面向并行槽位、乘加预算与驻留内存预算三重约束的调度计划器与批量执行：按 pair 数、近重复候选比较次数与批次规模估算代价，在预算内决定准入 pair 集合、分批规模与并行度，并按计划分派到本地进程池执行；同一观测下决策必须逐字节一致，worker 内异常须以结构化业务码与阶段名归因到具体 pair_id 与批次。
6. 实现预算冲突的显式裁决规则：当并行度提高缩短整体耗时但放大驻留内存、批规模扩大减少归约开销但逼近预算、降低近重复比较预算损失分组质量时，须按声明的优先级顺序在进度、内存、并行度与分组质量之间裁决，被拒或降级 pair 返回结构化业务码或标记降级类别，并在调度报告中记录裁决依据与各 pair 所走路径。
7. 实现全链路内容寻址缓存与增量失效传播：每级产物附带内容哈希落盘，缓存键须纳入该级输入摘要、上游产物哈希、配置版本与采样种子；修正某标注者组的样本、调整质量权重或相似度门限时，计算受影响级与受影响 pair_id 集合，复用未受影响上游产物，仅重算受影响后缀，并输出重算级清单与复用级清单，保证局部修正结果与全量重算逐字节一致。
8. 实现配置与清单快照的版本化整体替换、过期结果拒绝与跨模块一致性自检：快照携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换而非增量修补，旧版本不得覆盖新版本且回退尝试返回业务码，键所依赖版本已变而清单仍来自旧键时返回 E_STALE_RESULT；自检校验重算集合与复用集合无交集且并集覆盖全部受影响 pair、清单中每条 pair 恰出现一次、采样明细可重算出配比统计。
