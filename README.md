在空白工作区构建一个本地确定性的文生视频与图生视频渲染工作台，用于在有限交互延迟预算下反复调整生成参数并逐帧查看结果。渲染管线由提示词编码（受限词表加哈希词袋嵌入）、初始潜变量生成（由提示词、种子与图生视频初始图编码派生）、若干去噪步（每步读取上一步潜变量，叠加预置噪声表与条件引导）、逐帧解码（线性投影加逐像素裁剪到 0-255，并合成输出多帧预览序列）组成；图生视频路径以初始图编码潜变量替代部分早期去噪步。用户通过交互命令修改提示词、种子、步数、引导强度、帧数、初始图或对某一步的局部矩形区域施加潜变量补丁。核心矛盾在于：交互命令要求尽快返回可用的首帧预览与生成进度摘要，而后台多帧渲染必须最终收敛到与从零串行渲染完全一致的逐帧像素结果；同时进程可能被可处理退出信号或强制终止打断，恢复必须依赖已持久化的阶段快照。所有输入为本地程序生成的确定性样本，禁用容器化环境。

任务环境与准备：
安装 Python 3.11 与 NumPy、Pillow，使用本地虚拟环境，不安装容器相关工具。
在工作区创建输入样本目录，用固定种子脚本生成受限词表、预置噪声表、初始图 PNG 与文生视频及图生视频配置文件。
准备本地交互命令流 JSON 与异常注入配置样例，包含种子越界、补丁坐标越界与噪声表长度不符条目。
确认输出目录可写，测试运行不依赖网络、真实账号或任何外部服务。

业务要求：
1. 实现阶段化视频渲染管线：将提示词编码、潜变量初始化、逐去噪步、逐帧解码划分为独立阶段，每阶段产物以临时文件加原子替换方式持久化为带版本号的产物文件，产物含阶段名、内容指纹、依赖指纹清单与潜变量或像素帧数据；任一阶段产物缺失或指纹不符时必须判定为不可复用并重算该阶段及其下游。
2. 实现图生视频路径与文生视频路径的显式分支：图生视频以初始图编码潜变量替代指定数量的早期去噪步，替代步数由图生视频配置给出；同一提示词与种子下两条路径在替代步之后必须共享相同的去噪计算语义；初始图缺失或尺寸与配置不符时输出 E_INITIMAGE_INVALID，且不得静默回退为文生视频路径。
3. 实现交互延迟预算内的首帧响应：交互命令触达后先复用最近一次已完成的低分辨率首帧预览与当前进度摘要，在配置的首帧预算内返回；预算内无法得到最新参数下的首帧时返回带 E_PREVIEW_BUDGET_PENDING 业务码的中间态摘要，后台继续渲染。预算耗尽不得被表述为渲染已终止，也不得丢弃后台任务。
4. 实现局部潜变量补丁的精确失效传播：配置可指定对某一步去噪输出施加局部矩形区域的潜变量替换，补丁以坐标与数值数组给出；该补丁只能使该步及其下游去噪步与解码阶段失效，其上游阶段必须保持命中；补丁内容指纹纳入缓存键，坐标越界输出 E_PATCH_OUT_OF_RANGE，噪声表长度与配置步数不符输出 E_NOISE_MISMATCH。
5. 保证增量渲染与全量渲染的逐帧一致性：从任意初始状态执行包含提示词、种子、步数、引导强度、帧数、初始图与补丁变更的编辑序列，每次编辑后增量运行得到的最终多帧像素与各中间潜变量，必须与从空白工作区按相同最终输入全量串行渲染的结果逐像素一致；比较须覆盖文生视频与图生视频两条路径及至少一次步数变化。
6. 实现阶段快照与中断恢复的状态判定：渲染过程中收到可处理的退出信号时，完成当前阶段产物落盘与进度记录后以整数退出码 0 退出；进程被强制终止后重启时仅依据清单中已完整替换的产物与进度记录恢复，恢复点须可识别并输出；强制终止后不得承诺生成退出报告，也不得以快照版本号相同为由混用旧帧数据。
7. 实现并发渲染与串行结果一致性：使用线程池并发执行去噪步与逐帧解码，最大并发数取自配置；每个任务携带由阶段名、步序号与帧序号派生的稳定排序键，无论线程调度顺序如何，最终帧顺序、中间潜变量清单顺序、失败清单顺序与诊断摘要内容必须与单线程串行执行逐字段一致。
8. 实现参数注入校验、失败隔离与诊断报告：配置缺字段、类型错误、种子越界、引导强度非有限数分别输出 E_CONFIG_INVALID，单阶段异常时记录阶段名、步序号或帧序号与异常类型到失败清单并继续其余可恢复工作；每次完整运行生成 JSON 诊断报告，含失效与复用阶段、各阶段重算耗时、快照版本号、业务码与最终帧差异摘要，并以临时文件加原子替换写盘。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证两条生成路径、增量与全量逐帧一致、首帧预算响应与恢复点判定，并附诊断报告。
