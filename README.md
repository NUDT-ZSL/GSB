在空白工作区从零实现一个本地数据库日志与崩溃恢复组件，用于在确定性样本上复现增量日志应用、检查点演进与依赖失效恢复。本地样本以目录形式给出：一组按序列号递增的日志段文件（JSON 行格式，每行含逻辑事务号、操作类型、表名、行键、变更前后镜像、依赖的检查点代数与操作摘要哈希），以及若干检查点文件（记录检查点代数、已应用的日志序列号水位、各表行版本摘要与脏页映射）。组件需加载检查点与增量日志，按事务序验证日志链连续性，把日志增量应用到本地 SQLite 表上，维护每行的版本号与来源事务，支持从任意检查点重放、识别依赖检查点失效的日志段并拒绝越过失效点继续应用。进程可能在应用中途被强制终止，恢复时必须依据持久化的已应用水位与事务提交标记判定哪些增量已提交、哪些需重放。所有文件均在本地，运行结果需稳定可复现。

任务环境与准备：
确认 Windows 本机已安装 Python 3.10 及以上版本，并可使用标准库 sqlite3；创建全新工作目录作为项目根目录。
在工作目录内准备 samples 目录，放置若干 JSON 行格式日志段文件与检查点 JSON 文件，日志与检查点均为本地确定性生成的小规模样本。
准备一个用于存放 SQLite 状态库与运行输出的运行目录，确保当前用户具备读写权限；不依赖任何外部服务、账号或网络资源。
在项目根目录编写并运行本地自检脚本以确认 sqlite3 可用，随后按交付要求实现命令行子命令与演示脚本。

业务要求：
1. 实现日志段与检查点解析校验：校验逻辑事务号严格递增、操作类型枚举、变更前后镜像与操作类型匹配、依赖检查点代数存在、操作摘要哈希与行内容一致，构建有序日志链与检查点代数模型；非法行、断链或摘要不匹配必须返回明确业务错误码（如 E_BROKEN_CHAIN、E_BAD_DIGEST）并保持已加载状态不变。
2. 实现检查点驱动的增量日志应用：从指定检查点代数与水位开始，按事务序把插入、更新、删除增量应用到 SQLite 表，维护每行版本号、来源事务号与删除墓碑，应用结果须与从空库全量重放同一日志链得到的结果逐行一致，并为每个已应用事务记录来源日志序列号与摘要。
3. 实现依赖检查点失效识别与拒绝越过：当日志行声明的依赖检查点代数在当前检查点链中不存在、已被新代数整体替换或水位回退时，判定该日志段失效，必须停在失效点之前并返回业务错误码，不得部分应用该段中越过失效点的后续事务，也不得静默跳过。
4. 实现检查点创建与整体替换：在应用若干事务后按当前已应用水位生成新检查点，记录各表行版本摘要与脏页映射，提交时以整体替换方式切换当前检查点指针并识别版本变化，版本回退必须被拒绝；新检查点生成后旧日志段仅在水位之前可被裁剪，裁剪不得影响从剩余检查点开始的正确重放。
5. 实现强制终止后的恢复与重放裁决：把已应用水位、已提交事务标记、检查点指针与未完成事务记录以事务原子写入 SQLite；进程被强制终止后，恢复路径依据持久化状态识别已提交但未更新水位的事务与半应用事务，只重放未提交部分，恢复后表内容与逐事务结果必须与不中断执行完全一致。
6. 实现并发一致性与幂等应用：允许多个恢复或应用实例并行处理同一日志链，通过 SQLite 事务与文件锁保证同一事务号同一版本只被应用一次，重复应用同一日志段必须幂等；读取方只能看到完整已提交事务的可见结果，不得观察到半应用行版本。
7. 实现异常链路与业务错误码：日志段缺失、JSON 行畸形、事务号重复或回退、表结构不匹配、摘要不匹配、检查点代数不存在分别映射到不同业务错误码并在输出中保留可诊断字段；单个事务异常不得中断其他已加载事务的重新应用或污染已提交行状态。
8. 提供可重复的命令行接口与演示：支持 load、apply、checkpoint、resume、status、verify 子命令，status 以稳定排序 JSON 输出当前水位、检查点代数、已应用事务数与失效日志段，verify 校验表内容与检查点摘要一致；使用固定本地样本执行两次应用与一次中断恢复，输出结果须完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定日志与检查点样本，验证增量应用、检查点失效拒绝、强制终止后恢复结果与不中断一致，并输出业务错误码。
