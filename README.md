团队刚敲定首个可运行版本，本地 Linux（WSL Ubuntu）工作区里还没有代码或样本，需要从零交付一个面向顺序消息追平的数据处理管线与结果验证工具，核心不是网关投递本身，而是两代顺序投递描述格式在合并、追平裁决与中断恢复时能否保持账本互操作。业务输入由随工程交付的固定种子脚本确定性生成：主题分区清单声明主题名、分区数、分区键规范范式；生产者事务事件流逐条给出事件序号、分区键、载荷摘要、注入逻辑时钟毫秒戳、期望投递代数；消费者订阅声明给出订阅者 ID、主题、每次拉取条数、本地回环回调端点、消费速率上限；两代投递语义快照并存——v1 为单文件 JSON，记录相对生效秒数与扁平投递别名字段；v2 为分片 JSON 加 SQLite 元数据库，记录绝对生效毫秒、投递语义代数、依赖上游偏移水位与失效墓碑。系统需把两代描述合并为统一投递视图，在可注入逻辑时钟下追平积压，并输出可复现的账本与格式迁移结论。

任务环境与准备：
在 Linux（WSL Ubuntu）环境中安装 Python 3.9 或以上版本，确保 sqlite3 模块可用。
创建空工作目录，使用固定种子脚本在本地生成主题分区清单 JSON、生产者事务事件流 JSONL、消费者订阅声明 JSON 以及 v1、v2 两代投递语义快照文件。
无需安装额外第三方库，仅使用 Python 标准库完成实现。

业务要求：
1. 实现主题分区清单、生产者事件流、订阅声明与两代投递语义快照的解析校验，确保主题名与事件序号唯一、分区数为正整数、分区键规则可解析且覆盖全部事件键、注入逻辑时钟为非负整数、v1 相对秒数为非负整数、v2 分片哈希与语义代数单调且失效墓碑引用闭合，任何非法输入须返回独立业务错误码且不写入账本。
2. 实现两代投递语义的跨版本合并与统一投递视图构建，同一消息键在 v1 与 v2 同时存在时依据快照声明的逻辑时钟与语义代数裁决最新版本，逻辑时钟相同则按来源格式优先级裁决，v1 相对生效秒数在注入逻辑时钟下换算为绝对毫秒并记录换算标度、舍入方向与被舍弃余量，合并后每个条目须保留来源版本、原始时间表示与裁决依据。
3. 实现分区键到分区的确定性路由与单调偏移分配，同一分区键在任意运行次数下必须落到同一分区，事件偏移按分区内追加顺序单调递增且不跳号，每次追加在同一事务内写入偏移、载荷摘要、期望投递代数与逻辑时钟戳，并输出分区水位摘要以便后续追平校验与格式迁移核对。
4. 实现基于注入逻辑时钟的顺序追平裁决，按分区推进投递，同一分区任一时刻最多一个投递在途，后偏移事件不得越过前偏移未确认事件，追平决策只依赖注入逻辑时钟与已提交的语义代数，不读取系统墙钟，须输出每分区可投递偏移与积压深度并保证同一事件序列重复运行得到逐位一致的水位。
5. 实现语义补丁驱动的依赖失效闭包与结论复用，以补丁形式提交投递语义代数变更、上游偏移水位依赖或失效墓碑修改，沿消息对上游水位的引用边精确标记受影响分区与投递结论，只重算受影响闭包内的追平结果，未受影响分区的既有结论与账本条目不得被改变，并输出可追溯的失效来源链。
6. 实现账本与追平状态的持久化及强制终止后的恢复，把分区已提交偏移水位、投递代数、在途投递登记、确认标记、死信墓碑、格式迁移决策与逻辑时钟水位以单事务原子写入 SQLite，每轮提交以临时表加版本号整体替换当前账本指针并识别版本回退，进程在追平或语义合并中途被 SIGKILL 后恢复路径只重放未提交事件且不重复计入投递代数。
7. 实现多进程并发一致性与业务错误码隔离，允许多个追平实例并行处理不同分区，通过 SQLite 事务与文件锁保证同一分区同一偏移只被追加一次、同一事件同一语义代数只被投递一次、跨版本合并后的语义指针只被整体替换一次，重复提交相同事件或确认必须幂等，事件乱序、分区缺失、语义代数回退分别映射到不同业务错误码并保留可诊断字段。
8. 实现格式互操作与可重复命令行验证，支持 load、merge、replay、patch、resume、status、verify 子命令，merge 输出两代快照合并的时间换算、优先级裁决与条目级继承证据，status 以稳定排序 JSON 输出每分区水位、投递代数和积压深度，verify 对照串行逐事件处理结果逐位校验追平账本。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
运行固定种子样本完成两代顺序消息快照合并、追平与中断恢复，输出分区水位、格式迁移证据和一致性校验结论。
