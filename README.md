需要在一个空白工作区中从零实现一个面向本地计算引擎的 SQL 解析与逻辑计划构建组件，用于在离线环境下可复现地验证 SQL 语义与计划结构。组件接收受限 SQL 子集（SELECT 投影、WHERE 谓词、JOIN、GROUP BY、ORDER BY、LIMIT），解析为抽象语法树并归一化为逻辑计划树（扫描、过滤、连接、聚合、排序、限制节点），计划节点带稳定节点编号与列引用绑定信息。组件需维护本地 SQLite 目录元数据（表名、列名、列类型、可空性、索引），用于语义校验与列解析。核心挑战在于：每个解析或语义错误都必须以固定业务码返回并附带出错位置（行、列、字节偏移），同时组件要提供可复现的异常注入机制，按预置注入点（词法、语法、绑定、规划、元数据载入）在指定第 N 次触发时抛出指定异常，用于验证错误链路与部分失败后不留半成品计划。位置信息以 UTF-8 字节偏移与 1 起始的行列号共同表示，真值来源为样本 SQL 文件中人工标注的标注表。

任务环境与准备：
安装 Python 3.11 与 pytest，使用标准库 sqlite3 与 json，无需网络。
在空白工作区建立项目目录与本地样本 SQL、元数据 JSON 文件。
确认 Windows 本地文件读写与临时目录可用，测试不依赖外网、账号或 GPU。

业务要求：
1. 实现受限 SQL 子集的词法分析与语法分析，产出带行号、列号与字节偏移的抽象语法树；不支持的关键字、未闭合字符串、非法数值字面量必须返回固定业务码 E_LEX 或 E_SYNTAX，且位置信息必须指向首个出错字符，不得吞掉后续错误造成位置漂移。
2. 实现基于本地 SQLite 目录元数据的语义绑定：解析表名与列名、校验列类型兼容性、展开 SELECT * 与别名，未知名返回 E_UNKNOWN_COLUMN、类型不匹配返回 E_TYPE_MISMATCH，错误中必须包含涉及的表名与列名，绑定结果以稳定的列引用编号表示。
3. 实现逻辑计划构建与归一化：将绑定后的语法树转换为扫描、过滤、连接、聚合、排序、限制节点组成的树，节点编号须按确定性遍历顺序分配，谓词下推仅允许在语义等价的前提下进行，输出计划须能规范化序列化为逐字段可比较的结构。
4. 实现可复现的异常注入机制：按注入点名称（lex、parse、bind、plan、meta）与触发计数配置注入，仅在指定注入点第 N 次被调用时抛出指定异常，其余调用正常执行；注入配置须来自输入参数或配置文件，不得通过修改源码实现，且同一配置重复运行结果完全一致。
5. 实现异常链路与业务码映射：词法、语法、绑定、规划各阶段抛出的内部异常必须在边界处映射为固定业务码集合，注入的通用异常须映射为 E_INJECTED 并保留原始注入点与计数；错误响应 JSON 字段固定，包含业务码、阶段、消息、位置（可为空）与根因链。
6. 实现失败原子性：任一阶段失败时不得留下部分构建的计划、部分写入的元数据缓存或残留的临时绑定上下文；失败后再次以相同输入（关闭注入）请求必须成功，且成功结果与从未失败过时的规范化计划完全一致。
7. 实现计划与元数据的缓存一致性：以 SQL 文本摘要与元数据版本号作为缓存键，元数据版本变化时旧计划缓存必须失效；在注入导致规划阶段失败时不得写入缓存，缓存命中与未命中的规范化输出必须逐字段一致。
8. 提供本地样本与可重复测试：样本包含至少五个表定义与二十条覆盖成功与各类失败的 SQL 用例，提供 pytest 用例覆盖词法、语法、绑定、规划错误、注入触发计数、失败原子性与缓存失效，全部在 Windows 离线可重复运行。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证解析、计划归一化、固定业务码与注入触发计数，失败后重跑结果一致。
