在空白工作区从零实现一个本地查询计划与索引选择诊断引擎，用于分析给定 SQL 子集在本地样本数据上的计划稳定性与数值精度问题。输入包括：本地 SQLite 样本数据库（含表结构、索引与数据）、待分析的查询模板集合、以及用户指定的数值容差参数。引擎需基于 SQLite EXPLAIN QUERY PLAN 与自研代价模型，评估每个查询在现有索引下的计划、扫描行数估计、选择率估计及代价估计，并输出 JSON 格式诊断报告。同时需模拟索引变更（增删索引、调整统计信息）对查询计划与代价估计的影响，并检测估计过程中因浮点运算、累计误差或统计信息陈旧导致的精度偏差。引擎应支持断点续算与状态恢复，保证在中断后能从持久化快照继续分析。所有输入与输出均为本地文件，不依赖外部数据库服务或网络。

任务环境与准备：
安装 Python 3.10 及以上版本，并安装 NumPy 与 SQLite3（Python 标准库自带）。
准备本地样本 SQLite 数据库文件，包含至少两张表、若干索引与固定行数的确定性数据，以及查询模板 JSON 文件。
确保工作目录可读写，运行演示脚本前无需网络或外部数据库服务。

业务要求：
1. 解析本地 SQLite 样本库中的表结构与索引定义，构建表、列、索引的元数据模型，并支持从 EXPLAIN QUERY PLAN 获取实际查询计划；元数据模型需记录索引的列顺序、唯一性约束及统计信息（行数、NDV 估计）的采集时间与来源版本，供后续精度分析使用。
2. 实现基于均匀分布与等深直方图的基数估计器：根据样本数据采集列直方图与 NDV，估计等值、范围、IN 谓词的选择率；估计器需记录中间浮点运算的二进制表示，以便在精度异常时回溯误差来源。
3. 实现代价模型并输出查询计划诊断报告：结合选择率估计、索引扫描代价、随机 I/O 与顺序 I/O 权重，计算候选访问路径的代价，选择最小代价路径；报告以 JSON 输出每个查询的选定索引、估计行数、估计代价及估计置信区间。
4. 实现数值精度与误差传播检测：对同一查询在同一统计信息下多次估计时，若因浮点累计误差导致选择率或代价出现非确定性差异（超过给定容差），或估计值与真实执行扫描行数偏差超过阈值，则标记为精度异常，并输出误差来源链（直方图桶选择、NDV 除法、代价加权等）。
5. 实现索引变更模拟与计划稳定性评估：给定索引增删操作，重新估计查询计划与代价，输出计划是否翻转、翻转的临界条件（如行数阈值或选择率阈值）；若两次模拟结果因浮点误差或统计信息快照版本不同导致不一致，需记录版本差异并标记为不可比。
6. 实现断点续算与状态恢复：将每个查询的分析进度、已采集统计信息、直方图快照与误差记录持久化到 SQLite；在中断后从快照恢复时需校验快照版本与样本数据是否一致，只补算缺失部分，不得重复已完成的估计或改变已输出的结果。
7. 实现异常输入链路与业务错误码：当查询模板引用不存在的表或列、SQL 语法不合法、统计信息缺失或容差参数非法时，返回明确的 JSON 业务错误码（如 E_NO_TABLE、E_BAD_TOLERANCE）并保持状态一致可用，不得遗留半写入的中间记录。
8. 提供可重复的命令行接口与演示脚本：支持 analyze、simulate、resume、report 子命令；report 子命令以稳定排序输出 JSON 诊断报告；演示脚本使用固定本地样本执行两次 analyze 并产生完全一致的输出，用于验证确定性与精度检测的稳定性。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地 SQLite 样本执行 analyze 与 simulate，检查计划诊断报告、精度异常标记与中断恢复后结果的一致性。
