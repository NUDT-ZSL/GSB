在空白工作区构建一个面向本地确定性样本的全景分割结果数据处理管线与结果验证工具，核心解决像素掩码在多种交换格式之间的互操作与版本兼容问题。输入为一个本地样本目录：若干程序生成的 PNG 全景分割标注图（固定分辨率，像素值为实例 ID 与语义类别编码）、一份实例元数据 JSON（实例 ID、语义类别、置信度、是否 crowd 区域）、一份 v1 格式的掩码包（每实例以行程编码存储在单个二进制文件中，仅含实例 ID 与语义类别）、一份 v2 格式的掩码包（JSON，每实例以 base64 编码的逐像素 0/1 数组存储，含置信度与 crowd 标记并带命名调色板），以及一份管线配置 JSON（并发数、行程压缩档位、像素保留策略、融合 IoU 阈值、快照提交间隔）。两种格式在实例粒度、置信度表达、crowd 语义与压缩方式上均不等价，管线需解析为统一中间表示，支持双向转换、跨格式全景结果融合、版本化快照与恢复、以及一致性验证报告输出。

任务环境与准备：
准备 Windows 本地工作区，确认已安装 Python 3.10 或以上，并安装 NumPy 与 Pillow（用于读取与写出 PNG）。
生成确定性样本：多张固定分辨率的全景分割 PNG 标注图、v1 行程编码二进制掩码包、v2 base64 JSON 掩码包、实例元数据 JSON 与管线配置 JSON，全部由固定种子本地生成，不依赖网络。
准备一份可处理退出信号的运行入口说明与整数退出码约定，异常注入通过独立配置注入，不修改源码制造失败。

业务要求：
1. 实现双格式解析器与统一中间表示：分别读取 v1 二进制行程编码掩码包（含实例 ID 与语义类别）与 v2 base64 逐像素掩码包（含置信度、crowd 标记与调色板），解析为统一的实例掩码位图、语义类别、置信度与来源版本元数据；对行程越界、base64 长度与像素总数不符、调色板索引缺失分别输出 E_RLE_OUT_OF_RANGE、E_MASK_LENGTH_MISMATCH、E_PALETTE_MISSING 并进入失败清单。
2. 实现格式双向转换器与信息保留策略：v1 升 v2 时为每实例生成置信度推定值（缺失时取配置默认值）、crowd 标记默认值与调色板条目；v2 降 v1 时丢弃置信度与 crowd 语义但把其汇总写入旁路迁移报告，压缩档位切换须能无损还原实例 ID 与行程；无法表达的字段必须记录到降级损失清单，不得静默丢弃。
3. 实现跨格式全景结果融合：按配置的 IoU 阈值对来源不同版本的同类别实例做匹配，匹配成功按置信度加权合并掩码与元数据，匹配冲突时按 IoU 降序、置信度降序、实例 ID 字典序依次决断；crowd 区域参与掩码覆盖但不参与匹配竞争；融合后的像素归属须唯一且覆盖全域，输出融合实例清单与冲突裁决记录。
4. 实现版本指纹与失效识别：为每个实例掩码计算由行程内容指纹、语义类别、元数据指纹与格式版本号派生的缓存键，为融合结果计算由参与实例缓存键与 IoU 阈值派生的依赖指纹；当单个实例元数据被替换或像素保留策略变更时，仅使受影响实例及其下游融合区域失效并纳入重算集合，未失效实例必须直接复用且不重复解码。
5. 实现版本化快照整体替换与强制终止恢复：以 manifest 记录全局版本号、格式版本号、配置哈希、各实例结果版本与融合结果版本，先写临时目录再整体替换；读取时以 manifest 版本号与配置哈希判定命中或重建；收到可处理退出信号时完成当前实例产物与 manifest 原子提交后以整数退出码 0 退出，强制终止后仅依据已完整替换的快照恢复且不得承诺一定生成退出报告。
6. 实现增量运行与全量重建的一致性：从任意初始状态施加包含实例元数据修改、单实例掩码替换、格式版本切换与融合阈值调整的编辑序列，每次增量运行得到的全景掩码像素、实例清单顺序与冲突裁决记录，必须与从空白工作区按相同最终输入与配置全量运行的结果逐字段一致；比较须覆盖两种压缩档位与两种格式来源。
7. 实现并发调度、异常隔离与结果验证报告：使用线程池并发执行解码、转换与融合，最大并发数取自配置，每个实例任务携带由实例 ID 与阶段名派生的稳定排序键，最终掩码顺序、融合投票顺序与失败清单顺序须与单线程按实例 ID 顺序执行一致；单实例在任一阶段抛异常时记录实例 ID、阶段名、业务码与异常类型并继续其余实例；报告以 JSON 原子写盘，含实例数、降级损失清单、失效与复用计数、快照版本号与失败清单。
8. 实现融合阈值与像素保留策略的边界诊断：对每个 IoU 恰好落在匹配阈值附近或像素覆盖率恰好等于策略下限的实例，输出其双精度参考值与实际判定差异，当两者判定不一致时记 E_BOUNDARY_SENSITIVE 并在报告中区分阈值敏感实例与策略敏感实例；边界诊断不得改变主融合结果，只作为旁路诊断输出且须可复现。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地双版本掩码样本验证解析转换、融合、增量与全量一致性及异常业务码，并输出验证报告。
