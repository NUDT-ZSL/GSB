在空白工作区从零实现一个本地数据库锁等待与索引命中的联合诊断工具，用于分析并发事务脚本在共享锁表与索引访问路径交错时产生的等待时长误差传播问题。本地样本由确定性脚本生成：SQLite 样本库（表结构、索引与固定数据）、并发事务脚本集合（每个事务由有序读、写、范围扫描与锁声明操作组成）、以及诊断配置（锁等待预算毫秒、并发事务上限、逻辑时钟步进、等待时长容差与定点标度）。工具需以多个本地工作进程并行执行事务，通过自建锁表登记共享与排他锁、维护先进先出等待队列，并在注入逻辑时钟下累计每个事务的锁等待时长；同时记录每个操作实际命中的索引路径，把等待时长按'持锁事务—等锁事务—索引路径'三元组归因。核心难点是等待时长由多次逻辑时钟采样相减得到，采样点与锁表状态推进之间存在换算与舍入误差，误差会沿等待链传播并使两个事务的等待排序在容差带内翻转；工具须给出可追溯的误差来源与精度敏感标记，并保证中断后账目一致。

任务环境与准备：
确认 Windows 环境下已安装 Python 3.10 及以上版本，并可在命令行调用 python。
仅使用 Python 标准库 sqlite3、json 与 multiprocessing；无需 NumPy、外部数据库服务或网络访问。
准备本地确定性生成脚本，按固定种子生成样本库、表结构、索引、固定数据、并发事务脚本、诊断配置与逻辑时钟序列。

业务要求：
1. 实现样本库、事务脚本与诊断配置的解析校验：校验表名与索引名唯一、操作序列合法、隔离级别与锁模式枚举闭合、锁等待预算与并发事务上限为正整数、定点标度与容差为正；引用不存在的表列、循环事务依赖或非法配置须返回不同业务错误码（如 E_NO_TABLE、E_BAD_BUDGET）且不写入任何锁记录。
2. 实现锁表与先进先出等待队列：以 SQLite 锁表持久化每行与每表区段的持有者、锁模式与等待次序，读操作申请共享锁、写操作申请排他锁、范围扫描按区段登记；冲突申请进入等待队列且顺序稳定可复现，同一事务重复申请同一资源须按重入规则裁决并记录原因。
3. 实现基于可注入逻辑时钟的等待时长计量：所有持锁开始、等锁入队、获得锁与放弃等待的时刻只依据注入的逻辑时钟毫秒值，不读取系统墙钟；等待时长由获得或放弃时刻减去入队时刻得到，每次相减须记录两端采样点编号、换算标度、舍入方向与换算前原始值，使同一逻辑时钟序列下重复执行得到逐位一致的时长记录。
4. 实现等待时长误差上界累计与传播链记录：对每个事务累计其各次等待时长换算与求和的误差上界，输出误差来源链（含入队与出队采样点编号、参与换算的锁资源与持锁事务）；当两个事务等待时长差小于容差且等待排序或放弃裁决依赖该差值时标记为精度敏感，并给出首个分歧采样点与两事务的中间值。
5. 实现锁等待预算与全局并发上限下的调度裁决：在每事务锁等待预算与全局并发事务上限双重约束下决定事务启动与放弃等待，预算耗尽须给出放弃原因并释放已持有锁；须区分预算内未启动、入队后等待超时放弃与主动回滚三类结局，已启动事务不得被简单截断为超时。
6. 实现索引命中归因与死锁牺牲裁决：记录每个读操作实际使用的索引路径（或全表扫描）并与锁等待记录关联，按三元组汇总等待时长；按检测周期遍历等待图识别环路并选择确定性牺牲事务回滚，输出完整死锁环、牺牲依据与其余事务的继续推进结果，解除后等待队列次序与锁归属须被重新校验。
7. 实现强制终止后的恢复一致性：把事务阶段、锁持有与等待队列内容摘要、等待时长账目、误差上界、死锁牺牲决策与逻辑时钟水位以单事务原子写入 SQLite；进程在入队、获得锁或放弃等待中途被强制终止后，恢复路径须识别已提交等待记录与半提交锁登记，只清理未提交登记并重建等待队列，恢复后账目须与未中断运行逐项一致。
8. 实现多进程并发一致性与可重复命令行演示：允许多个诊断实例并行推进不同事务，通过 SQLite 事务与文件锁保证同一事务同一操作版本只提交一次、同一锁资源不被并发超授，重复提交相同等待记录必须幂等；提供 run、resume、status、verify、report 子命令，report 以稳定排序 JSON 输出等待时长、索引归因、精度敏感清单与误差上界，演示脚本用固定样本运行两次得到一致输出。
