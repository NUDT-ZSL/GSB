电商平台在扩充新品类前，商品数据运营与买手团队需要判断：由生成器模拟出的购买兴趣样本能否替代新品类冷启动阶段的真实数据，用于离线推荐策略试验。已有输入包括确定性生成器按固定种子产出的商品目录（标识、类目、价格区间、属性标签）、脱敏购买兴趣日志（用户—商品点击与购买事件、类目偏好）以及一份小规模真实评估集与类目兴趣基线。真实数据里长尾类目稀疏但必须保留，价格敏感度分层明显；合成样本若把长尾压平、价格区间拉偏或交互密度过高，准入结论就会失真。团队要一个本地可运行的评估组件：既从真实日志中建模兴趣分布、条件采样生成合成交互，也要逐维度给出与真实评估集的对齐评分、漂移标记和准入结论，让生产者与使用者对同一份合成数据有一致判断依据。

任务环境与准备：
在 Linux（WSL Ubuntu）下准备 Python 3 运行环境，并安装 NumPy 作为数值计算依赖。
在仓库内提供确定性数据生成器脚本，按固定种子产出商品目录、购买兴趣日志、真实评估集与类目兴趣基线，输出为本地文件。
提供组件入口脚本与运行示例，示例涵盖正常样本、长尾缺失样本、价格偏移样本与脏数据样本，结果写入本地文件供核对。

业务要求：
1. 读取商品目录与购买兴趣日志，按类目与属性标签做分层建组：每个商品映射到唯一的类目—属性组合，统计各组内真实交互次数与活跃用户数；对样本量低于声明阈值的层标记为稀疏层并单列，不得因稀疏而直接并入父层，为后续采样与对齐提供分组依据。
2. 对每个非稀疏层建模用户兴趣分布参数：以用户在该层内购买事件的相对频率刻画类目偏好强度，以购买价格的中位与四分位距刻画该层价格敏感度，以用户的交互商品数刻画交互广度；参数按用户去重后聚合，输出各层参数快照，并保留参与统计的用户计数，供条件采样与对齐评分共同引用。
3. 实现条件采样结合保序重加权的合成交互生成：先按层的用户计数与兴趣强度抽样层与用户，再在层内按价格敏感度分布抽取商品；对稀疏层采用从父层按属性相似度回补的方式补足样本，并用保序重加权修正合成样本相对真实样本的层权重偏差；为每条合成交互记录采样层、来源依据与权重，结果在固定种子下可重复。
4. 计算类目兴趣分布的KL散度与长尾覆盖率差异：以真实评估集的类目购买占比作为参照分布，对合成样本做平滑后求KL散度；同时统计合成样本覆盖的真实长尾类目（基线占比低于长尾阈值的类目）占真实长尾类目的比例，逐类目输出对齐评分与偏离方向，长尾缺失需明确标记到具体类目。
5. 计算价格敏感度分位数差与交互稀疏度分布差异：在类目与全局两个层面比较合成与真实样本的购买价格分位差（如10/50/90分位），并对用户交互度分布做差异度量；当某项差距超出声明容差即标记漂移，输出包含维度名、受影响类目或用户群体与差值的漂移标记清单。
6. 以留出的真实评估集做两样本统计检验来判定准入：对类目兴趣分布采用基于分层频数的卡方或等价检验，对价格与交互度采用非参数检验；综合各维度漂移标记与检验结果给出准入、有条件准入、拒绝三档结论，以及拒绝时导致不合格的主要类目或用户群说明，结论须可追溯到具体维度评分。
7. 对同一种子重复生成合成样本并重算全部评分与结论：验证两次运行的类目对齐评分、漂移标记与准入结论完全一致；若两次结果不一致，应输出指出哪一维度或哪一类目出现分歧的诊断信息，而不是仅给出通过或失败。
8. 组件需能处理异常输入：遇到类目或属性标签缺失、价格区间非法（负值或下限大于上限）、日志中商品标识无法在目录中匹配时，按声明的业务错误码在结果中记录并跳过对应记录，同时汇总被跳过数量与原因，不得因单条脏数据中断整体评估。

验收：
用留出真实评估集核对合成样本的对齐评分、漂移标记与准入结论；用人工构造的长尾缺失、价格偏移、交互过密样本检查判定；验证固定种子重复可复现。
