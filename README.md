本地空白工作区需要从零构建一个面向目标检测后处理的数据处理管线与结果验证工具。输入为本地确定性生成的检测结果 JSONL：每行含 image_id、每类的候选框集合（x1,y1,x2,y2 浮点坐标、score、class_id）以及真值框集合（含 label、框坐标、difficulty 标记）。管线核心任务是把候选框按类别与真值框做 IoU 匹配，计算匹配指派、TP/FP/FN 与精度召回类统计，并在此基础上按资源预算做并行调度：可配置的 worker 数量、单图最大候选数、总匹配比较次数预算与内存上限共同决定执行方式。业务要求同一输入在相同配置下结果完全可复现，同时预算收紧时必须以明确定义的降级或拒绝语义返回业务码，不允许静默改变最终匹配结果；匹配、统计与验证三阶段之间要保持集合级一致，任何候选框不得同时被判为 TP 和 FP。

任务环境与准备：
安装 Python 3.10 或以上，并通过 pip 安装 numpy（建议 1.24 及以上），无需 GPU 与网络服务。
在空白工作区创建项目目录，按题面字段语义自行生成确定性本地检测结果样本与真值样本，样本规模可控且可复现。
确认本地进程池可启动多个 worker 进程，并预留可观测的内存与预算参数用于演示降级与拒绝路径。
运行命令行入口验证输出 JSON 结构、业务码与降级标记；演示注入输入由本地脚本生成，不修改管线源码制造失败。

业务要求：
1. 实现确定性候选框匹配：对每张图按 class_id 分组，用可配置 IoU 阈值做贪心指派（score 降序、同分按坐标字典序打破平局），输出每个候选的匹配真值框索引或未匹配标记；同一输入同一配置重跑必须逐字节一致，坐标非法或框面积为零分别返回 E_BOX_INVALID 与 E_BOX_DEGENERATE。
2. 实现并行调度层：按可配置 worker 数与单图最大候选数把图像分块分配给多个本地进程池任务，分块边界与归并顺序必须确定性可复现；worker 内异常须以结构化业务码回传主进程并归因到具体 image_id，不得吞掉或让整个批次无限等待。
3. 实现匹配比较次数预算：按候选数×真值框数估算每图匹配代价，在总预算内做准入裁决；超出总预算时按明确策略拒绝返回 E_MATCH_BUDGET 或降级到仅评估低难度真值的受限模式，受限模式必须在结果中标记降级类别且不得改变已评估图的匹配结果。
4. 实现内存上限控制：为同时驻留的结果分片与候选数组设置可配置内存上限，超限时按明确的分片淘汰策略回收已归并数据或返回 E_MEMORY_LIMIT；淘汰策略不得丢失最终统计所需的计数，且上限触发必须在验证工具中可观测。
5. 实现 TP/FP/FN 统计与集合一致性：由匹配指派计算整体与分类别统计，并校验任一候选不得同时计入 TP 与 FP、任一真值框不得同时计入 TP 与 FN，违反时返回 E_INCONSISTENT 并指明不一致类别与 image_id。
6. 实现结果验证工具：对管线输出做独立复核，检查每图候选覆盖完整、匹配索引在真值范围内、统计数值与逐图明细可重算一致，检测到偏差返回 E_VERIFY_FAIL 并输出首个偏差位置；验证须能处理降级模式输出并区分其业务码。
7. 实现配置与输入校验链路：worker 数、IoU 阈值范围、预算与内存参数非法分别返回 E_CONFIG_INVALID；重复 image_id、候选引用不存在的 class_id 集合、真值 label 不在受控标签集内分别返回 E_DUP_IMAGE、E_CLASS_UNKNOWN、E_LABEL_UNKNOWN，且错误须在调度开始前或对应图处理时准确暴露。
8. 提供命令行入口与本地演示：读取本地样本执行完整管线、输出含匹配明细、统计、业务码与降级标记的 JSON，并附一次注入异常输入（非法框、超预算、损坏行）的演示；演示只依赖本地生成样本与本地进程池，不依赖外部服务或 GPU。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证匹配指派、预算与内存降级、统计一致性、验证工具及异常业务码的确定性输出。
