推理服务平台的容量规划工程师要在正式线上流量接入前，离线核对混合专家模型的专家路由与通信均衡策略。服务工程中，若干专家分片声明所属副本、领域标签、单样本计算成本与每轮跨副本通信量；副本声明容量上限、支持精度与所属机架；按逻辑时刻到达的推理请求带领域标签、样本数与序列长度，另有副本扩缩容与专家迁移事件序列。同一工程以三个 schema 版本描述，字段命名、负载与通信量单位、专家表表达各不相同。工程师需要一套可逐请求核对、能随事件重算分派并在跨版本间保持一致判定结果的本地组件与演示。

任务环境与准备：
在 Linux（WSL Ubuntu）上创建工作目录，使用系统自带的 Python 3 运行环境，不安装任何第三方包。
从零编写确定性样本生成器、三个 schema 版本样例文件、参考分配器与命令行演示入口，所有文件均放在该工作目录内。
运行演示命令时指定固定随机种子与样本规模参数，在本机即可复现相同路由结果与均衡指标。

业务要求：
1. 将同一工程的三个 schema 版本归一为统一的专家分片—副本—请求内部模型：版本间的字段命名差异、专家表扁平列表与按副本分组嵌套树的表达差异、样本数与等价字节的负载单位差异、MB 与 MiB 的通信量单位差异都必须在归一阶段对齐，并输出归一后的模型供后续路由与均衡使用。
2. 按请求的领域标签筛选候选专家分片，结合副本剩余容量与跨副本通信代价，为每个请求确定专家路由归属与目标副本分派，分配结果须逐请求可追溯，并能说明每个请求的候选筛选依据与副本选择依据。
3. 逐轮核算各副本承担的计算负载与跨副本通信量，输出每副本每专家的负载账目与瓶颈副本标记；同一副本上承载多个专家分片时，要正确合并其样本负载与通信量，不得把共享机架内的通信按跨机架重复计费。
4. 以最小最大不均衡为目标做副本间负载再均衡，在容量上限与通信代价约束下输出均衡前后各副本负载与通信不均衡度指标，并能说明每次再均衡调整了哪些请求的专家路由归属或目标副本。
5. 当副本扩缩容或专家迁移事件在请求流中发生时，按专家—副本依赖关系推算受影响的已分派请求与需迁移的专家集合，输出重新路由结果；容量缩小导致已分派请求无法维持时需给出明确的重新选择依据。
6. 提供独立的加权均衡参考分配器，对同一工程产出逐请求路由归属、副本负载账目与不均衡度，并与主路由均衡结果逐请求比对，报告首个不一致的请求编号及其分配依据差异；参考分配器不得复用主路由的实现代码。
7. 对三个 schema 版本归一后分别执行路由与均衡，输出逐请求路由与均衡统计的一致性结论及跨版本差异清单；差异清单要指明是归一阶段还是路由阶段造成的可观察差异，并给出对应证据。
8. 内置确定性样本生成器按固定种子产出专家通信量悬殊、副本容量接近饱和、请求领域标签分布倾斜及插入扩缩容事件的样本，并提供命令行演示入口展示逐请求路由归属、负载账目、不均衡度指标与受影响请求重算结果。

验收：
用内嵌参考分配器逐请求核对三版本归一后的路由归属、负载账目与不均衡度，并验证事件重算与跨版本一致性。
