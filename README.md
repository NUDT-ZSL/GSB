需要在新工作区从零构建一个面向分析型场景的本地列式存储引擎与查询执行器，并附带一个桌面诊断工作台，用于核对增量更新后的数据正确性与依赖失效范围。数据以列块（column chunk）组织，每个列块按行组分区并持久化为本地文件，元数据记录每个列块的统计信息、版本号与依赖图（例如物化视图、聚合索引、缓存查询结果对其依赖的列块集合）。增量更新以批为单位到来：更新可以只影响部分行组中的部分列块，引擎需为该批生成新版本列块而不是整体重写所有数据，并据此判定哪些下游依赖对象失效。查询执行器支持对单列做过滤、对多列做投影与分组聚合，需能在列块统计信息上做裁剪以减少读取。工作台要把依赖图、列块版本分布、失效传播范围与实际查询结果差异以可视化方式呈现，帮助定位“更新后结果为何变化”或“为何没有变化”。

全部数据与更新批次由本地确定性生成器产出，使用固定随机种子，不依赖任何外部账号或网络服务；工作台直接读取引擎持久化目录，所有诊断结论必须能在同一目录上重复复现。

任务环境与准备：
确认 Windows 环境已安装 Python 3.10 或以上版本，并可在命令行调用 python。
创建全新工作区目录，使用虚拟环境安装依赖：pip install numpy pyqt5 pytest，版本以安装时解析到的稳定版为准。
使用本地确定性样本生成器产出列式数据与更新批次，固定随机种子，样本与批次文件写入工作区 data 子目录。
准备引擎持久化目录与 SQLite 元数据库文件，工作台与命令行执行器均指向同一目录，确保演示可重复执行。

业务要求：
1. 实现列块持久化格式与元数据中心：按行组与列拆分列块并写入磁盘，元数据以 SQLite 记录每个列块的路径、行数、统计信息（最小值/最大值/空值数）、版本号与所属行组，读取时须校验元数据与实际文件一致，不一致返回业务码 E_META_MISMATCH。
2. 实现批量增量更新与版本化替换：每个更新批只对受影响的列块生成新版本文件，未受影响的列块保持原版本且不得重写；整体替换须依据列块版本号识别变化，版本号相同的列块必须复用而非重建，并在元数据中记录批次标识与旧新版本映射。
3. 实现依赖图与失效传播：维护列块到下游对象（物化视图、聚合索引、缓存查询结果）的依赖边，更新完成后只将受影响列块可达的下游对象标记为失效，未受影响对象的有效位不得被翻转；失效状态随元数据持久化，重启后传播结果逐条一致。
4. 实现基于统计信息的查询裁剪与投影分组执行：查询可按列范围过滤并做分组聚合，执行器须利用行组统计信息跳过不可能命中的列块，并只读取被投影或过滤涉及的列，跳过读取的列块须在诊断输出中可枚举。
5. 解决增量更新与查询正确性之间的冲突：查询在新批次更新后必须看到一致的列块版本组合，不得出现同一行组混用新旧版本；需在执行前校验所选列块版本集合的完整性，不完整返回业务码 E_SNAPSHOT 并给出缺失的列块标识。
6. 实现失效对象的按需重建与结果差异诊断：对被标记失效的对象可触发重建，重建只读取有效列块并刷新有效位；同时输出重建前后查询结果差异（新增/删除/改动的分组键与聚合值），差异必须可追溯到导致失效的更新批次与列块。
7. 提供依赖失效可视化与诊断工作台：以图或矩阵方式展示列块、行组与下游依赖关系及失效状态，支持按批次查看版本分布与裁剪命中情况，并可从某个失效对象反查其可达的更新来源；界面操作不改变引擎状态除非显式触发重建。
8. 实现异常注入与恢复边界：通过配置参数注入元数据损坏、列块文件缺失、批次重复提交、依赖环与非法版本回退等异常，分别返回 E_META_MISMATCH、E_CHUNK_MISSING、E_DUPLICATE_BATCH、E_DEP_CYCLE、E_VERSION_REGRESS；强制终止后重启仅依赖持久化元数据恢复列块版本视图与失效位，不承诺补写退出报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
