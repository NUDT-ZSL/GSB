需要为内部运维团队构建一个本地运行的动态页面采集控制台。模拟目标站点是一个本地启动的工单系统（提供静态 HTML 与 JSON 接口，含分页、延迟渲染、偶发 503 响应与会话过期的模拟开关），其列表页由前端脚本二次渲染后才出现条目，详情页的字段结构随版本号小幅演进。采集器要按可配置的并发度抓取工单列表与详情，将原始与规范化数据写入 SQLite，并支持在中断后从持久化状态恢复，且恢复后不得重复入库、不得遗漏已确认的条目。控制台通过 FastAPI 提供任务创建、状态查询和恢复入口，前端用简单页面触发展示，整个演示须可重复运行且结果确定。

任务环境与准备：
Windows 10/11，Python 3.11 及以上，使用 venv 创建虚拟环境并安装 playwright、fastapi、uvicorn、httpx、pytest 与 sqlite3 标准库依赖
执行 playwright install chromium 安装本地浏览器内核，仅访问本机回环地址的模拟站点
启动随任务提供的本地模拟工单服务（同一 Python 进程或独立端口），该服务支持分页、延迟渲染、503 与会话过期开关，数据为内置确定性样本
为演示脚本与测试准备独立临时数据库路径，确保每次运行前可清空重来

业务要求：
1. 实现采集任务配置与状态机：任务从 pending 经 running 到 succeeded/failed/paused，暂停与失败均可进入恢复流程，状态迁移必须落库且非法迁移被拒绝并返回业务码 E_STATE。
2. 针对列表页的延迟渲染实现就绪判定：必须以显式同步标记（条目容器出现且计数稳定）确认渲染完成，不得以固定 sleep 代替；超时返回 E_RENDER_TIMEOUT 并记录观测快照。
3. 详情页解析需兼容至少两个版本号的结构差异，按页面内声明的版本选择解析规则，未知版本降级为原始字段保留并标记，不得静默丢弃数据。
4. 设计去重与幂等键：以工单业务标识加版本号构成唯一键，恢复重跑与并发重复抓取均不得产生重复行，冲突时保留最新完整字段并记录来源标识。
5. 实现并发抓取与资源控制：并发度可配置但有上限，遇到模拟 503 需按有界的指数退避重试，重试耗尽记为条目级失败而非任务级失败，并在汇总中区分两类失败。
6. 实现断点恢复的一致性：以持久化检查点记录已完成条目与当前分页游标，恢复时未确认条目重抓、已确认条目跳过；强制终止进程后重启只能依赖库中状态续跑，不承诺补写退出报告。
7. 会话过期需被识别并触发重新获取会话后重放当前请求，重放次数有上限；超过上限返回 E_SESSION 并保持任务可恢复，不得将过期响应当作正常数据入库。
8. 提供可交互控制台与确定性演示：创建任务、查看进度与失败明细、触发恢复；演示脚本可重复执行得到相同的条目计数与最终状态汇总，异常注入通过配置参数完成而非修改源码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
在本地模拟站点重复运行演示，验证并发采集、去重、会话恢复与强制终止后续跑结果一致且异常码正确。
