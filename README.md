这项需求没有既有代码，需要在空白工作区从零实现一个本地 TLS 握手证书链校验与信任时刻精度诊断引擎。本地样本目录提供：两代信任库快照——v1 为单文件 JSON，记录别名、PEM 证书、指纹、相对信任秒数与启用标记；v2 为分片 JSON 加 SQLite 元数据库，记录规范别名、绝对生效毫秒时间戳、信任代数、告警墓碑与吊销标记；由本地脚本确定性生成的根与中间 CA 证书 PEM、叶子证书集合及期望主机名与用途、CRL 与 OCSP 响应记录文件。引擎需加载并合并两代信任库为统一信任视图，对每个叶子证书构建并校验证书链，并专项处理信任时刻换算中的数值精度与误差传播。

任务环境与准备：
安装 Python 3.11 或以上，并执行 pip install cryptography 与 pytest，确认 cryptography 可导入。
在 Windows 上创建空白工作目录，准备本地样本脚本：使用 cryptography 确定性生成根 CA、中间 CA 与叶子证书 PEM，并写出 v1 单文件 JSON、v2 分片 JSON 与 SQLite 元数据库及 CRL/OCSP 占位记录。
确认样本中的指纹、分片哈希与内容摘要可在本地复算，逻辑时钟步进表与精度配置随样本一同提供，全部路径为工作区内相对路径。
无需网络、真实证书颁发机构或外部站点；SQLite 使用 Python 标准库 sqlite3。

业务要求：
1. 实现两代信任库快照的解析与校验：v1 校验别名唯一、指纹与 PEM 证书实际摘要一致、相对信任秒数为非负整数；v2 校验分片文件哈希、SQLite 元数据中信任代数单调、绝对生效毫秒时间戳为整数、告警墓碑与吊销标记类型合法；非法条目须返回明确业务错误码且不写入任何持久状态。
2. 实现跨版本信任库合并与统一信任视图构建：同一别名在两代快照中同时存在时，依据快照声明的逻辑时钟与信任代数裁决最新版本，逻辑时钟相同则按来源格式优先级；合并后每个信任锚须保留来源版本、原始时间表示与裁决依据，v1 相对信任秒数在注入逻辑时钟下换算为绝对信任时刻并记录换算标度与舍入方向。
3. 实现基于 cryptography 的证书链构建与校验语义：从信任锚出发按签发者与主体匹配构建到叶子的链路，校验签名、基本约束、路径长度、密钥用途、有效期与主机名（支持通配符规则），每一步判定记录为可追溯节点；有效期比较只依赖注入逻辑时钟毫秒值，不得读取系统墙钟。
4. 实现吊销检查与信任代数联动：按样本中的 CRL 与 OCSP 响应记录判定叶子与中间证书的吊销状态，未提供可用吊销证据时必须认定为未知并与已吊销严格区分；信任库代数变化或吊销墓碑新增后，相关链的吊销结论必须失效重算而非复用旧结论。
5. 实现信任时刻换算的定点与高精度双通路账本：每次相对秒数到绝对毫秒的换算同时计算受控定点通路值，并以基于 decimal 的高精度全量重算作为真值通路值，记录两通路数值、绝对偏差与相对偏差；累计每次换算与比较的误差上界，输出误差来源链（含别名、快照版本、换算步骤与舍入方向）。
6. 实现有效期边界上的精度敏感标记与结论翻转追溯：当两个信任锚或两级证书的有效期剩余时长之差小于给定容差且“是否过期”或“是否需回源验链”的判定依赖该差值时标记为精度敏感，输出参与比较的证书、各自偏差、误差上界与若改用更高标度是否翻转结论；该标记必须可重算且结论稳定。
7. 实现信任库版本化持久化与强制终止后的恢复：把信任库版本指针、链结论缓存、失效清单、吊销结论、精度账本与逻辑时钟水位以事务原子写入 SQLite，每次快照提交以临时表加版本号整体替换当前指针并识别版本回退；进程在合并或校验中途被强制终止后，恢复路径依据持久化状态识别未提交步骤并只重放未完成部分。
8. 实现多进程并发一致性与可重复诊断命令行：允许多个校验进程与信任库更新进程并行，通过 SQLite 事务与文件锁保证同一快照版本只提交一次、同一（主机名，用途，代数）链结论只提交一次，重复提交相同补丁或相同校验请求必须幂等；提供 load、chain、verify、apply、resume、status、verify-audit 子命令，status 以稳定排序 JSON 输出信任库版本指针、链结论摘要、精度敏感记录与逻辑时钟水位。
