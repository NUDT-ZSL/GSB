这个仓库还空着，需要从零搭建一个本地GPU调度与配额引擎，以可集成算法库和可复现实验形式交付。业务围绕异构GPU节点上训练作业的算力份额与显存份额切分、配额组约束、租约生命周期与抢占回收展开。全部输入由随工程交付的固定种子脚本在WSL Ubuntu本地确定性生成：加速卡清单声明卡ID、总算力份额、总显存份额、切分粒度、健康状态；作业清单声明作业ID、所需算力份额、所需显存份额、优先级、配额组、租约时长；租赁配置给出每轮逻辑时间预算、并发授予上限、续租宽限、抢占推演参数；另有异常注入清单在授予、续租、回收和重组阶段注入受控异常。引擎需在可注入逻辑时钟下实现切分租约授予、续租、到期回收、碎片重组和高优先级抢占推演，并将账本与日志持久化到SQLite支持中断恢复。本任务核心难点在于状态演进与恢复一致性：租约账本、切分区间占用和碎片重组结果必须在强制终止后通过持久化状态准确恢复，且多进程并发下不出现份额超卖或重复授予。

任务环境与准备：
在WSL Ubuntu环境中安装Python 3.10或更高版本，确保pip可用。
安装所需的Python依赖：numpy和标准库sqlite3、json、os、math等，无需额外第三方包。
在项目根目录下创建data/samples目录存放由固定种子脚本生成的JSON样本文件，包括cards.json、jobs.json、config.json和inject.json。
运行样本生成脚本generator.py，该脚本使用固定种子并输出上述JSON文件；生成后检查文件存在且格式合法。
创建results目录用于存放输出的状态文件、日志和恢复验证证据，确保进程有写权限。

业务要求：
1. 实现加速卡清单、作业清单、租赁配置和异常注入清单的解析校验：卡ID和作业ID唯一、总算力与总显存份额为正整数且能被切分粒度整除、作业需求份额为正整数、租约时长为正整数逻辑毫秒、优先级与配额组枚举合法、不支持切分的卡必须拒绝任何授予、异常注入引用的阶段和对象合法，非法输入须返回明确业务错误码且不产生任何持久化变更。
2. 在可注入逻辑时钟下实现切分租约授予：对每个作业在配额组算力份额上限、每卡剩余算力份额和剩余显存份额三重约束下裁决授予哪张卡的哪个切分区间，算力或显存任一不足即拒绝并给出首个触发约束与相关份额数值，授予成功必须原子更新租约代数、切分区间占用和配额组已消耗份额，同一逻辑时钟序列重复运行得到逐位一致的授予序列。
3. 实现租约续租和到期回收：续租必须校验作业身份与租约代数且只依据注入逻辑时钟，过期未续的租约进入回收态并真实释放其算力份额与显存份额，回收后更新配额组已消耗份额，并区分正常到期回收、配额收缩回收和抢占回收三类原因，每次回收记录包含回收时刻、释放的份额碎片区间和影响范围。
4. 实现碎片感知的回收后重组裁决：被回收的算力份额与显存份额碎片按切分对齐粒度重新组合成候选区间，判定等待队列中的作业能否被这些碎片满足，必须区分真无剩余资源与碎片导致不可满足，输出导致失败的关键碎片分布以及若进行最少次数迁移后能否满足该作业的结论。
5. 实现高优先级作业的可抢占回收推演：当高优先级作业无法授予时，按优先级与租约剩余时长推演可被抢占回收的租约集合，输出完整回收链、回收后能否授予的判定依据以及被抢占作业的退还未结记录，且推演过程不得改变当前已提交账本，实际执行抢占时必须与推演结果一致。
6. 实现租约账本与切分占用映射的持久化及强制终止后的恢复一致性：把租约代数、切分区间占用、配额组已消耗份额、退还未结记录、逻辑时钟水位和异常注入消费标记以事务原子写入SQLite，每轮提交识别版本变化并整体替换账本指针，进程在授予、续租、回收或重组中途被强制终止后，恢复路径依据持久化状态识别半提交操作并只重放未完成部分，保证恢复后的账本满足份额守恒且无重复授予。
7. 实现多进程并发一致性与异常注入隔离：多个调度实例并行处理同一批作业时，通过SQLite事务与文件锁保证同一卡同一切分区间的授予只提交一次、配额组已消耗份额不被并发超扣、重复提交相同轮次结果幂等，异常注入清单按阶段精确触发切分区间重叠、账本份额不守恒、续租代数回退和碎片重组摘要不匹配，每种异常映射到不同业务错误码并保留轮次号、卡ID和作业ID等可诊断字段。
8. 提供可复现实验命令行接口：支持 load、grant、renew、recover、preempt、resume、status、verify 子命令，status 以稳定排序 JSON 输出每张卡的剩余份额与碎片区间、每个租约的代数与到期时刻、每个配额组的已消耗份额，verify 通过重新执行持久化账本全链并比对摘要校验份额守恒、授予幂等与异常隔离结果。
