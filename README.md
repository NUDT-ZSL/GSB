# 播客片段音轨合成器

按 JSON 编辑清单把多个单声道播客片段合成一条音轨，并生成处理报告。
仅使用 Python 标准库（`wave`、`json`、`array`），无 Docker、无第三方依赖、不访问网络。

## 环境

- Python 3.10 或更高（本机以 3.10 / 3.13 验证）
- 标准库 `wave`、`json` 即可，无需 pip 安装

```powershell
python --version
```

## 快速开始

```powershell
# 1. 生成样本、清单并跑完所有演示场景（产物在 demo/ 下）
python demo.py

# 2. 运行验收测试（24 项）
python -m unittest discover -s tests -v

# 3. 手动合成单个场景
python compose_audio.py demo\input\01_full.json demo\output\manual
```

`compose_audio.py` 的调用约定：

```
python compose_audio.py <清单路径> <输出目录>
```

输出目录中生成 `output.wav`（单声道 16 位 8 kHz PCM）与 `report.json`。

## 清单格式

顶层必须是 JSON 数组，每项含 `path`（字符串）与 `start`、`fade_in`、`fade_out`
（非负有限数值，单位秒）：

```json
[
  {"path": "intro.wav", "start": 0.0, "fade_in": 0.1, "fade_out": 0.2},
  {"path": "guest.wav", "start": 1.2, "fade_in": 0.2, "fade_out": 0.2}
]
```

- 相对路径按**清单文件所在目录**解析（绝对路径原样使用），因此从任意工作目录运行结果一致。
- 任何一项不合规（非数组、缺 `path`、负值、非数值、NaN/Infinity、`start` 超过
  3600 秒上限）都会拒绝处理，退出码 2，标准错误输出 `清单格式错误: ...`，
  且不写出任何输出文件。
- 清单不存在 / 不可读 / 不是合法 JSON 时退出码 2，标准错误输出 `无法读取清单: ...`。

## 合成规则

| 规则 | 实现 |
| --- | --- |
| 片段格式 | 必须是单声道、16 位、8 kHz、PCM；否则报告 `格式不支持`，跳过该片段 |
| 缺失文件 | 报告 `缺失` / `文件不存在`，跳过，其余片段继续合成 |
| 损坏或不可读 | 报告 `读取失败` / `文件无法读取`，跳过，不中断流程 |
| 时间轴 | 按 `start` 秒插入；`start` 相同按清单顺序叠加 |
| 防过载 | 浮点累加后统一峰值缩放，只在峰值超 int16 时线性压回满幅，不做硬削波 |
| 淡入淡出 | 线性包络；淡入从片段第 0 采样开始，淡出在片段末尾归零；时长超过片段时按片段长度截断 |
| 总时长 | 覆盖所有有效片段在时间轴上的范围；无有效片段时为 0 采样（44 字节 WAV） |
| 确定性 | 无随机数、无时间戳；报告固定键顺序与缩进、LF 换行，重复执行字节级一致 |

报告结构：

```json
{
  "完整": true,
  "总时长": 5.5,
  "片段": [
    {"path": "intro.wav", "状态": "完整", "错误信息": null}
  ]
}
```

- `完整`：所有片段状态均为 `完整` 时为 `true`；空清单为 `true`。
- `总时长`：秒，最多 6 位小数。
- `片段`：严格按清单顺序；`错误信息` 在有效片段上为 `null`，否则为简短中文说明。
- 状态取值：`完整`、`缺失`、`格式不支持`、`读取失败`。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 处理完成（即使存在缺失/不支持/读取失败的片段） |
| 2 | 清单无法读取或格式错误，未生成输出 |
| 3 | 输出目录不可写 |

## 演示场景

`python demo.py` 会先在 `demo/input/` 生成确定性样本与清单，再逐个场景运行，
最后对同一场景连续执行两次并比较哈希。场景与预期：

| 场景 | 说明 | 预期 |
| --- | --- | --- |
| `01_full` | 三个片段，含淡入淡出 | 完整=true，总时长 5.5s |
| `02_missing` | 中间片段不存在 | 该项“缺失”，其余正常，完整=false |
| `03_unsupported` | 立体声与 16 kHz 片段 | 两项“格式不支持”，其余正常 |
| `04_overlap` | 两个 start=0 片段叠加 | 完整=true，输出无削波 |
| `05_longfade` | 2s 片段设 fade_in=5 | 完整=true，起点增益约为 0 |
| `06_delayed` | 3s 片段 start=2 | 总时长 5.0s |
| `07_corrupt` | 头部损坏的 WAV | 该项“读取失败”，另一项正常 |
| `08_empty` | 空清单 | 完整=true，44 字节 WAV，片段=[] |
| `09_invalid_manifest` | start=-1 | 退出码 2，`清单格式错误` |
| `10_invalid_json` | 截断的 JSON | 退出码 2，`无法读取清单` |

## 验收测试

`tests/test_compose_audio.py` 用 `unittest` 覆盖全部 14 条要求（含边界补充），共 24 项：

- 清单校验：负 start、缺 path、非数组、布尔冒充数值、超大 start
- 缺失片段跳过且其余音频逐采样一致
- 立体声 / 16 kHz 片段判定为格式不支持
- 同 start 混合：与线性缩放期望值逐点比对（误差 ≤ 1），并检测无削波平台
- 淡入长度超过片段时增益从 0 线性升至 1；淡出末点接近静音
- 时间轴总长、无有效片段时 44 字节
- 报告结构、键集合、片段顺序、错误信息 null/中文
- 头部损坏、截断、目录冒充文件三种读取失败
- 两次执行 SHA-256 一致
- 输出 WAV 的 RIFF 头与 `wave` 参数
- 空清单
- 相对路径按清单目录解析
