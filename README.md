当前是空白工作区，需要从零实现一个本地分布式副本修复引擎，用于在确定性样本上复现副本缺失检测、修复来源选择与修复任务调度的完整链路，并处理数据规模变化导致的策略取舍。本地 JSON 样本给出：集群拓扑（节点名、机架与拓扑域、容量上限、健康状态、网络成本权重）、分片清单（分片 ID、副本数要求、各副本所在节点、每副本字节量与内容摘要、最近校验逻辑时钟）以及修复配置（每轮最大并发修复数、单节点修复出口带宽预算、带宽单位换算规则、小分片阈值、抽样校验比例、容差参数、逻辑时钟步进）。引擎需按注入的逻辑时钟检测副本缺口，按拓扑距离、负载与摘要可信度选择修复来源，在并发与带宽预算下调度修复任务并记录每个分片的修复状态与校验证据。核心难点是：数据规模从小分片为主变为大分片为主时，修复来源选择、抽样校验与带宽分配之间必须做明确取舍，且进程被强制终止后恢复结果必须与未中断运行一致。

任务环境与准备：
安装 Python 3.11 及以上版本，并确保 sqlite3 与 NumPy 可用（pip install numpy）。
在工作区创建 samples 目录，放入固定的集群拓扑、分片清单与修复配置 JSON 样本，以及一份包含固定种子的测试运行脚本。
确认运行环境不需要网络、容器或外部存储服务，所有节点与分片数据由本地样本与回环地址模拟。
首次运行前删除 samples 下历史状态数据库与输出目录，保证基线可复现。

业务要求：
1. 实现集群拓扑、分片清单与修复配置的解析校验：校验节点名与分片 ID 唯一、副本所在节点存在且不重复、副本字节量为正整数、内容摘要与声明算法匹配、副本数要求不超过合法范围、并发与带宽字段为正整数，构建分片到副本的映射模型；非法输入返回明确业务错误码且不写入任何持久化状态。
2. 实现注入逻辑时钟下的副本缺口检测：按最近校验逻辑时钟计算每个分片的健康副本数与缺口数，判定副本为缺失、摘要可疑或正常，可疑判定依据抽样校验比例与内容摘要一致性；检测结果只依赖注入的逻辑时钟，不读取系统墙钟，同一逻辑时钟序列重复检测必须得到逐位一致的缺口清单。
3. 实现修复来源选择与规模自适应裁决：候选来源按拓扑距离、节点当前修复负载、摘要可信度与网络成本权重打分，并对小分片与大分片分别采用不同的候选裁剪与带宽分配策略；裁决须输出选定来源、被否决候选与首个否决理由，以及本次触发的规模区间与切换依据，使相同输入复现相同来源选择。
4. 实现并发与带宽预算下的修复任务调度：同一轮次内按节点分组并发启动修复任务，同时受每轮最大并发修复数与单节点出口带宽预算约束；预算耗尽时放弃剩余任务并记录放弃原因，区分预算内未启动、启动后失败与主动放弃三类结局，并给出每任务的带宽份额与预计逻辑耗时。
5. 实现修复轮次状态机与持久化推进：分片在待修复、修复中、已校验、校验失败、已放弃之间按规则迁移，迁移须依据本轮完整结果与持久化状态裁决，重启后不得凭内存残留决定分片状态；已校验分片必须记录来源节点、内容摘要与校验证据链。
6. 实现强制终止后的恢复一致性：把轮次水位、分片阶段、已提交修复结果摘要、带宽消耗与逻辑时钟水位以事务原子写入 SQLite；进程在调度或修复中途被强制终止后，恢复路径识别已提交与半提交修复结果，只重做未完成分片且不得重复扣减带宽预算，恢复后缺口清单与未中断运行逐字段一致。
7. 实现多进程并发一致性与幂等提交：允许多个修复实例并行处理不同分片，通过 SQLite 事务与文件锁保证同一分片同一轮次同一来源只提交一次、单节点带宽预算不被并发超扣，重复提交相同修复结果必须幂等；读取方只能看到完整已提交轮次状态而非中间态。
8. 实现异常链路与可重复命令行验证：来源节点连接拒绝、传输超单次修复预算、摘要校验失败、分片清单缺失、逻辑时钟回拨超阈值分别映射到不同业务错误码并在输出中保留可诊断字段，单个分片异常不得中断其他分片修复；提供 detect、repair、resume、status、verify 子命令，status 以稳定排序 JSON 输出每分片缺口、来源与阶段，verify 校验持久化状态与缺口清单一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
