在空白工作区从零实现一个本地 GPU 训练任务的配额调度与显存装箱诊断工作台，用于在确定性样本上分析训练作业在有限 GPU 资源池上的准入、分片与显存装箱决策。本地样本以 JSON 给出：GPU 节点清单（节点名、每卡显存容量、卡数、健康状态、拓扑域）、训练作业清单（作业 ID、请求卡数与每卡显存需求、训练阶段、优先级、配额组、是否允许分片与抢占）以及调度配置（配额组卡时上限、装箱策略参数、显存换算单位与容差参数）。工作台需实现作业准入、配额扣减、卡级显存装箱、碎片诊断与抢占推演，数据规模从数十作业到数千作业变化时，装箱算法需在首次适应与最佳适应之间按策略取舍并输出可比的诊断结果。

任务环境与准备：
安装 Python 3.11 及以上，确认 python 与 pip 可用，无需 GPU 或 CUDA。
安装 NumPy：pip install numpy；SQLite 使用 Python 标准库 sqlite3。
在空白工作区创建项目目录，准备本地节点、作业与调度配置 JSON 样本及固定随机种子，不连接任何外部服务或线上资源。
确认可在 Windows 命令行多次运行本地脚本并获得一致输出。

业务要求：
1. 实现 GPU 节点与训练作业清单的解析校验：校验节点名唯一、显存容量为正整数 MiB、卡数为正、作业请求卡数与每卡显存需求合法、优先级与配额组枚举闭合、不允许分片作业的卡数不超过单节点卡数，把所有显存换算为整数 MiB 并记录每项换算误差上界；非法条目必须返回明确业务错误码且不写入任何持久化状态。
2. 实现配额组卡时准入：按配额组已消耗卡时与配置上限判定作业是否准入，准入时以事务方式预扣该作业本轮所需卡时，作业完成后按实际占用回补差额；同一配额组内准入必须尊重优先级且同优先级按稳定顺序排队，配额耗尽时返回可诊断的拒绝原因而非静默丢弃作业。
3. 实现卡级显存装箱与分片决策：在节点卡数与每卡显存容量约束下，按配置在首次适应与最佳适应策略间选择装箱算法，决定每作业落在哪些卡上以及多卡作业是否分片；装箱结果须记录每卡剩余显存、碎片量与被淘汰的候选放置，同输入多次运行逐位一致。
4. 实现数据规模变化下的装箱算法取舍评估：对同一批作业分别以两种装箱策略与不同作业规模采样运行，输出可比较指标（准入数、卡利用率、平均碎片、拒绝数）与策略选择依据；指标必须说明估计所依赖的观测与真值来源（以全量重算结果为基准），不得以缺失信息推断。
5. 实现抢占推演与碎片诊断：当高优先级作业因显存碎片无法装箱时，按配置推演可抢占的低优先级作业集合，输出完整抢占链与释放后能否装箱的判定依据；诊断必须区分真无可用资源与碎片导致的不可装箱，并给出导致失败的关键卡与剩余显存区间。
6. 实现持久化状态与强制终止后的恢复：把调度轮次、作业阶段、配额预扣、卡占用映射、抢占决策与诊断摘要以事务原子写入 SQLite，每轮提交识别版本变化并整体替换当前快照指针；进程被强制终止后依据持久化状态识别未提交轮次与半写入占用，只清理未提交记录并从已提交状态重建，不得承诺对被强杀进程生成退出报告。
7. 实现多进程并发一致性与幂等提交：允许多个调度实例并行处理同一批作业，通过 SQLite 事务与文件锁保证同一作业同一轮次只被准入或抢占一次，重复提交相同轮次结果必须幂等；读取方只能看到完整已提交轮次快照，并需在配额回补与抢占释放并发时保证卡占用与配额计数不出现负值或重复释放。
8. 提供命令行工作台与可重复演示：支持 load、schedule、explain、compare、resume、status、verify 子命令，explain 以稳定排序输出指定作业的准入与装箱决策链及碎片诊断，compare 输出两种装箱策略在固定采样规模下的指标对照，verify 校验持久化状态与诊断摘要一致性，演示脚本用固定本地样本两次运行产生完全一致的输出。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证准入、装箱、抢占、策略对照和恢复后的结果及错误码，附运行输出。
