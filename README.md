# 帧序列动画合成命令行工具

本地命令行工具：读取帧清单 JSON 与逐帧 PNG，合成预览 GIF、导出逐帧透明通道预览，
并输出区分各类未完成原因的处理报告。纯本地运行，不使用容器、不访问任何网络目标。

## 1. 环境要求

| 依赖 | 要求 | 本机实测 |
|---|---|---|
| Python | ≥ 3.10 | 3.14.7 |
| Pillow | 已安装即可（无其他第三方依赖） | 12.3.0 |

安装 Pillow（如尚未安装）：

```powershell
python -m pip install Pillow
```

## 2. 文件说明

| 文件 | 作用 |
|---|---|
| `frame_anim_tool.py` | 主工具（清单校验、逐帧处理、GIF 合成、透明通道预览、报告） |
| `make_samples.py` | 生成可复现样例：12 条帧条目，覆盖正常/小图/半透明边缘/全透明/超尺寸/损坏/延时非法/延时越界/缺文件 |
| `verify_all.py` | 15 条验收项的自动化验证（临时目录自建夹具，子进程调用 CLI 并读回产物断言） |
| `samples/` | 样例清单与 PNG（由 `make_samples.py` 生成，`f11_missing.png` 故意不生成） |
| `samples_output/` | 样例运行产物：`preview.gif`、`report.json`、`alpha_preview/` |

## 3. 本地启动方式

所有命令均在项目根目录执行，统一使用 `python -I`（隔离模式，忽略当前目录可植入的
同名模块如假 `json.py`，符合不可信数据目录的安全要求）。

```powershell
# 步骤一：生成样例帧与清单（重复执行结果一致）
python -I make_samples.py

# 步骤二：合成（输出目录不存在时自动创建）
python -I frame_anim_tool.py --manifest samples\manifest.json --output-dir samples_output

# 步骤三：跑全部 15 条验收（通过则退出码 0，任一失败退出码 1）
python -I verify_all.py
```

命令行参数：

```
--manifest    帧清单 JSON 路径（必填）
--output-dir  产物输出目录（必填，不存在时递归自动创建）
```

退出码：`0` 成功（允许存在无效帧，原因写入报告）；`2` 清单字段校验失败
（stderr 指出具体字段名，如 `字段 'canvas.width' 缺失`）；`1` 其他 I/O 错误。

## 4. 清单格式

```json
{
  "canvas": { "width": 64, "height": 64 },
  "loop_count": 2,
  "background_color": "#0066cc",
  "frames": [
    { "file": "frames/f01.png", "delay_ms": 100 }
  ]
}
```

- `canvas.width` / `canvas.height`：必填整数像素。范围 **[1, 4096]**，缺失/类型错/越界均为清单级错误（退出码 2）。
- `loop_count`：可选，非负整数，范围 **[0, 1000]**，`0` 表示无限循环。缺省时写为无限循环，
  报告中 `loop_count_source` 标为 `default_infinite` 并附中文说明。
- `background_color`：可选，`#RRGGBB` 或 `[r,g,b]`，缺省白色 `#ffffff`。
- `frames[].delay_ms`：毫秒整数，范围 **[10, 60000]**。GIF 时基为厘秒（10ms），
  低于 10ms 无法无损表示，故 0、5 等均判延时非法（越界）；超过 60000 判越界上界。
- 帧文件路径相对于清单所在目录解析。

## 5. 产物

| 产物 | 说明 |
|---|---|
| `preview.gif` | 仅含有效帧，帧序与清单中有效帧顺序一致；每帧延时按声明毫秒写入；`loop` 写循环次数；`disposal=2` 无残影 |
| `report.json` | 汇总（总条目/有效/无效/总时长/GIF 帧数）+ 每帧结果（序号、文件、有效性、原因码、中文原因、细节、延时、居里边距、透明预览路径）+ 上下界与循环取值来源 |
| `alpha_preview/frame_NNN_alpha.png` | 逐帧透明通道预览（L 灰阶）：**白=全透明、黑=不透明、灰=半透明**；半透明像素映射值恒在 1..254，边缘不出现纯黑，杜绝黑边渗色观感 |

### 无效帧原因码（报告中分类区分，互不混淆）

| reason_code | 中文原因 | 触发条件 |
|---|---|---|
| `missing_file` | 缺失 | 文件不存在 |
| `corrupt_image` | 损坏 | PNG 无法解码 |
| `oversized` | 超尺寸 | 帧宽或高超过画布 |
| `delay_invalid` | 延时非法 | 延时缺失/类型错误 |
| `delay_out_of_range` | 延时非法 | 延时超出 [10, 60000]ms（含 0） |
| `fully_transparent` | 全透明 | alpha 通道最大值为 0（空帧，不计总时长） |
| `missing_field` / `malformed_entry` | 字段缺失 / 条目格式错误 | 帧条目本身结构异常 |

处理顺序保证：任一单帧失败只记录该帧原因，不中断后续帧，已成功帧不受影响。

## 6. 黑边问题的处理方式

美术素材常见的“透明边缘黑边”源于半透明像素直接转 GIF 调色板时 RGB 被按不透明处理。
本工具在合成阶段用不透明背景色对每帧做 `alpha_composite` 合成，半透明边缘与背景
正确混合（红+蓝底→紫环），GIF 本身不含任何透明像素，因此不存在黑边渗色；
独立的透明通道预览只表达 alpha 信息，半透明区域恒为灰阶而非纯黑。

## 7. 确定性（重复运行逐字节一致）

- 固定 256 色调色板（6×6×6 网页安全色 + 灰阶），量化关闭抖动；
- GIF 关闭 `optimize`，帧参数固定；报告 JSON 键排序、固定缩进与 `\n` 换行；
- 报告仅记录清单文件名与相对路径，不含绝对路径或时间戳。

## 8. 验收结果（本机实测）

`python -I verify_all.py` 输出 **通过 16/16**（15 条需求 + 1 个全套样例集成用例）。
样例清单 12 条目：有效 6、无效 6（全透明/超尺寸/损坏/延时 0/延时越界/缺文件各一），
GIF 6 帧、逐帧延时 `[100,200,300,100,100,100]`、总时长 900ms、循环 2 次可读回；
两次运行的 GIF、报告、透明预览 SHA-256 完全相同。
