物流分拨中心的值班运维工程师与路径信息平台发布协调员，在双十一与春节前的分拨高峰窗口，需要依据分拨线自动化设备、路径规划服务、运单轨迹回传链路的维护窗口与变更申请，排布变更窗口并冻结冲突时段，再按业务影响与回滚就绪度裁定每个变更的执行或推迟。分拨高峰期间变更窗口与业务高峰重叠时，多个变更挤占同一服务或分拨线容量，服务依赖链上的并发变更会叠加影响运单轨迹回传；仅凭人工登记无法判断某条变更应推迟还是拆分，也难核对窗口容量与依赖链约束是否同时满足，导致变更后故障难以追溯到具体排布决策。本任务从零搭建一个本地可复现的排布与裁定工作台，输入由实现自带的确定性生成器按固定种子产出，输出逐窗口排布方案、冲突时段清单、变更裁定及依据、容量占用账目、候选窗口建议与时间线诊断视图。

任务环境与准备：
准备 Linux（WSL Ubuntu）上的 Python 3 运行环境，项目从空工作区开始创建，不依赖已有源码、样本或外部服务。
安装 Flask 第三方包用于本地诊断服务，其余仅使用 Python 标准库（含 sqlite3、json、random 等），SQLite 以 Python 标准库 sqlite3 直接嵌入文件数据库使用，无需独立数据库服务。
启动命令写入项目说明：运行内核入口生成固定种子样本并输出排布与裁定结果，另起 Flask 进程在 127.0.0.1 本地端口提供只读诊断视图。
所有输入由实现自带的确定性生成器按固定种子产出，不依赖真实分拨中心、线上服务或外部账号。

业务要求：
1. 实现确定性样本生成器，按固定种子产出分拨变更工程：服务清单（服务标识、所属系统、承载业务、服务等级、上下游依赖边）、维护窗口声明（起止逻辑时刻、允许变更类型、分拨线容量上界、最大并发变更数）、按逻辑时刻提交的变更申请（目标服务、变更类型、预计时长、回滚剧本就绪标记、业务影响等级）以及交错的业务高峰与设备维保占用事件；装载时校验窗口起止时刻有序、依赖边无自环、申请引用的服务与窗口存在，校验失败按业务错误码输出归一后的工程摘要。
2. 按逻辑时刻将变更申请归入所属维护窗口，逐窗口以定点整数核算分拨线容量占用与并发变更数，输出每个窗口的容量账目（已占用、剩余、峰值并发）以及超限窗口清单；容量核算须与申请预计时长和并发峰值一致，超限判定同时依据分拨线容量与最大并发变更数两个约束。
3. 沿服务依赖关系检查同一依赖链上并发变更与上下游同时变更的约束：对每个窗口内落在同一依赖链上的变更对，判定其执行时段是否重叠、是否违反上下游串行约束，输出违反约束的变更对及依赖链路径；依赖关系存在传递闭包，须识别间接上下游的并发冲突。
4. 对容量或依赖链约束不满足的变更，依据业务影响等级与回滚剧本就绪度进行确定性排序裁定执行或推迟，输出裁定结论及可复核的排序依据（影响等级权重、回滚就绪标记、同分时的稳定次序），同一工程重放两次裁定序列逐字段相同。
5. 为被推迟的变更匹配满足容量余量与依赖链约束的候选窗口，输出候选窗口建议与理由；候选匹配须在逻辑时刻晚于当前窗口且允许该变更类型的窗口中按容量余量降序、窗口起始时刻升序选取，无可行候选时显式标记无建议。
6. 在业务高峰或设备维保占用事件插入、或窗口声明局部调整后，仅重算受影响窗口的容量占用与变更裁定，未受影响窗口的排布与裁定逐字段保持不变；受影响窗口集合依据占用事件覆盖的窗口与变更引用关系推导，重算结果须与全量重算一致。
7. 将已提交窗口的容量账目与裁定序列持久化到本地 SQLite，支持中断后从持久化状态续算；续算时须识别工程版本变化，版本不一致的窗口重新排布，版本一致的窗口直接复用持久化结果，重放后整体排布与裁定可复现。
8. 提供本地 Flask 诊断服务，以只读接口展示逐窗口容量占用账目、依赖链冲突定位、变更裁定排序依据与候选窗口建议，并在插入高峰占用事件后仅刷新受影响窗口的视图数据，接口返回的账目与裁定须与内核计算结果一致。

验收：
以独立参考排期器逐窗口重算容量账目、依赖冲突与裁定序列一致；局部插入高峰事件后仅受影响窗口变化，重放两次结果完全相同。
