工作目录目前是空的，团队要先把一条能通过验收的最简链路跑通：为自研本地二进制封装格式 BSL（Binary Segment Log）构建离线解析与安全诊断工作台。样本由本地确定性脚本按固定种子生成，不依赖网络、账号或外部数据。BSL 文件由 32 字节固定头（魔数 b'BSL1'、格式版本 uint16 小端、段数量 uint32 小端、段表偏移 uint64 小端、声明总长 uint64 小端、保留区 8 字节）与若干段记录组成，段记录含段名长度 uint16、段类型 uint8、压缩方式 uint8、载荷偏移 uint64、声明载荷长度 uint64、内容摘要 32 字节。段类型 0x10 表示载荷为完整嵌套 BSL 文件。工作台把一次解析建模为状态演进过程：按段逐条推进解析状态，检测越界、重叠、摘要不符、嵌套过深与环状引用，并把每轮解析的状态代与水位移入 SQLite 账本；样本修订批次到达时判定哪些已解析结论失效，进程被强制终止后只允许从最后一个完整检查点恢复，最终输出可复现的 JSON 诊断报告与段依赖图。

任务环境与准备：
确认 Windows 本地 Python 3.11 可用，执行 python -m venv .venv 并激活虚拟环境。
在虚拟环境内执行 pip install pytest==8.2.0 numpy==1.26.4，SQLite 使用 Python 标准库 sqlite3，无需额外安装。
工作区为空目录，样本与快照均由待实现的固定种子生成脚本产出，测试前先运行生成脚本，不依赖网络、真实账号或外部数据。

业务要求：
1. 实现 BSL 文件头与段表的严格解析：校验魔数、格式版本白名单（仅 1 与 2）、段数量与段表偏移及声明总长自洽、段名 UTF-8 合法性、段类型与压缩方式取值，任一越界、偏移加长度溢出 64 位整型或超出文件实际长度须返回带出错偏移的 E_HEADER 或 E_BOUNDS 并终止该文件解析。
2. 实现段载荷的区间冲突检测：识别任意两段载荷区间的部分交叉与完全包含并返回 E_OVERLAP 且给出冲突段名对，识别载荷引用段表自身区段的自引用返回 E_SELFREF，重复段名须返回 E_DUP_NAME 并以首次出现为真值报告冲突位置，全部结论须与段记录在文件中的排列顺序无关。
3. 实现内容摘要与压缩方式的分派校验：按压缩方式 0 不校验、1 校验 SHA-256、2 校验 HMAC-SHA256 对实际载荷计算摘要，摘要不符返回 E_CHECKSUM，压缩方式与声明摘要位宽不匹配单独返回 E_DIGEST_WIDTH，未知压缩方式须作为可报告错误返回 E_COMPRESSION 而非静默跳过。
4. 实现嵌套 BSL 的递归解析与环引用检测：压缩方式 0x10 时其载荷为完整 BSL 文件须递归解析，最大递归深度为 4 层，超过返回 E_DEPTH；遇到段载荷引用祖先段构成环时返回 E_CYCLE 并列出环中段名序列；递归累计展开字节数须受可配置配额约束，超出返回 E_EXPAND_LIMIT。
5. 在 SQLite 中维护解析状态账本：以文件标识与段规范键为主键记录每段状态、状态代、已处理字节水位与累计摘要结论，每轮解析在单事务内推进账本，前置校验失败不得改动任何账本状态；账本格局版本（段类型白名单或校验策略版本）变化时须整体重建而非增量续接。
6. 实现样本修订批次的失效判定：当同一文件的新修订批次到达时，按段规范键与内容摘要比对找出内容变化的段，并沿段引用依赖边计算传递失效闭包，输出需重算的段集合与失效来源；失效判定须与修订批次到达顺序无关，报告中的段与失效项须按稳定键排序保证可复现。
7. 实现检查点与强制终止后的恢复边界：按已完成文件标识与账本摘要持久化检查点到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放校验账本一致性以识别半写残留；检查点与快照均先写临时文件再整体重命名替换，同一工作目录并发写入以文件锁串行化，锁冲突返回 E_LOCK。
8. 交付可交互命令行与确定性本地验证：提供解析、查询段状态、导出诊断报告、校验检查点四类子命令，单文件解析失败不得中断同批其他文件，退出码区分全部成功、部分失败与参数错误；附固定种子样本生成器与 pytest 测试集，覆盖畸形头、越界、重叠、摘要不符、深层嵌套、环引用、配额超限、修订失效与强制终止恢复。
