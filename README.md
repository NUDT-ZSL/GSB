远程教学与考试平台的发布值班工程师在学期考试周前要推进监考与答题服务的新版本：同一份发布工程被拆成按流量放量的若干步骤，每一步都带观察窗口与错误率、延迟分位、会话掉线率阈值，工程师需要依据逐步放量过程中采集到的指标序列决定继续放量、暂停还是回滚。考试周流量起伏大，瞬时尖峰与持续劣化混在一起，探针也可能缺失上报，而历史工程又分布在三个 schema 版本上，流量单位、阈值表达与步骤结构各不相同。若沿用固定节拍放量与单点阈值比较，异常版本可能被推给大批考生，或正当版本被瞬时抖动误回滚。平台要求把归一、逐步推进、指标判定、回退核算与跨版本一致性做成可在本地离线复核的内核。

任务环境与准备：
在 Linux（WSL Ubuntu）上使用 Python 3 解释器运行，仅使用标准库，不安装第三方包。
在工作区建立源码目录与测试样本目录，确定性生成器按固定种子产出三个 schema 版本的发布工程与观测指标序列，样本与账目输出写入工作目录下的文件。
提供命令行入口运行一次完整推演，输出逐步裁决、回退动作、放量账目与跨版本差异清单，并留下可供人工复核的结果文件。

业务要求：
1. 读入三个 schema 版本的同一份渐进发布工程，把服务版本声明、按流量放量的步骤声明、观察窗口与三类指标阈值归一为统一步骤序列、同一流量刻度与统一阈值口径，使同一放量比例与同一阈值在各版本下映射到相同判定口径，并保留逐字段的来源版本记录。
2. 按逻辑时刻逐步推进发布步骤，在每个观察窗口内对错误率、响应延迟分位与会话掉线率计算滑动统计，输出每一步的指标轨迹，轨迹点包含窗口边界、样本数、当前值与所用滑动样本区间。
3. 以滑动分位数与连续超阈次数判定每一步是否异常：连续超阈达到步骤声明的次数才算持续劣化，单点越界后回到阈值内只记一次尖峰事件，并输出放量、暂停或回滚的裁决与触发该裁决的阈值、观测值与连续超阈计数。
4. 裁决为回滚时确定回退目标：在已通过判定的步骤中选出最近的已知稳定步骤，计算需要回收的流量比例、回退后重新计入观察的窗口与受影响会话处置清单，并输出回滚动作序列。
5. 处理探针缺失与上报中断：某个指标在观察窗口内样本缺失超过步骤声明的比例时暂停放量并记录降级依据，缺失的滑动统计不得用前一窗口值顶替；指标恢复后从恢复时刻起重新累计连续超阈次数再作判定。
6. 汇总全程放量账目，逐步骤给出放量比例、实际放量时长、暂停与回滚次数、三类指标各自的超阈计数与尖峰计数，并要求账目与逐步裁决记录逐步骤可对应。
7. 保证同一工程在三个 schema 版本归一后产出相同的逐步裁决、回退目标与放量账目，同时输出跨版本差异清单，逐项标明字段命名、流量单位或阈值表达上的差异及归一后的取值。
8. 提供独立的指标判定参考推进器，以同一份归一工程逐步核对裁决、触发依据与回退目标，报告首个不一致的发布步骤及该步骤的指标依据，参考推进器与主流程分别独立实现。

验收：
用内嵌参考推进器逐步核对裁决、触发依据与回退目标；检查尖峰区分、探针缺失降级与三版本归一后的账目一致。
