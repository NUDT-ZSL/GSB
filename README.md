在空白工作区从零实现一个本地数据处理管线的并行调度与结果验证工具，用于在确定性样本上复现资源预算约束下的并行调度决策。本地 JSON 管线描述文件给出：算子节点清单（节点名、阶段序号、依赖的父节点列表、计算成本估计、内存需求 MiB、可并行度）、每阶段资源预算（最大并发执行数、单阶段总内存预算 MiB、单阶段逻辑时间窗口毫秒）以及逻辑时钟步进配置。每个算子的实际计算结果由固定本地输入样本（JSON 记录集合）经确定性计算得到，不依赖外部服务。工具需按依赖关系做拓扑调度：同一阶段内按内存预算与并发上限决定启动顺序与放弃策略，预算不足时必须显式放弃剩余算子并记录原因；已启动算子必须执行到完成或明确失败，不得被静默截断。管线中断后须依据持久化状态恢复，只补算未完成算子，最终产出确定性结果文件与验证报告。

任务环境与准备：
安装 Python 3.11 及以上版本，确认 python 与 pip 可用。
安装 NumPy 与 pytest：pip install numpy pytest。
在空白工作区创建项目目录，并准备本地 JSON 管线描述文件与输入记录样本作为固定测试数据。
确认 SQLite 由 Python 标准库 sqlite3 提供，无需额外安装；所有路径使用 Windows 本地路径。

业务要求：
1. 实现管线描述解析与校验：读取本地 JSON，校验节点名唯一、依赖父节点存在且无环、阶段序号与依赖方向一致（父节点阶段序号必须小于子节点）、成本与内存为正整数、可并行度为非负整数且不超过阶段最大并发数，构建节点依赖图与阶段分组；非法输入必须返回明确业务错误码 E_BAD_PIPELINE 并保持不写入任何持久化状态。
2. 实现拓扑调度器：按阶段顺序推进，在每阶段最大并发数与总内存预算双重约束下决定节点启动顺序；预算不足时显式放弃剩余节点并记录放弃原因，区分预算内未启动、已启动后失败与主动放弃三类结局，已启动节点必须执行到完成或明确失败，不得以线程超时替代终止。
3. 实现确定性算子计算：对通过调度的节点在其输入记录集合上执行固定计算（过滤、整数聚合与浮点聚合），浮点聚合顺序与运算顺序固定，使相同输入在任意运行次数下产生逐位一致的结果，并记录每个输出记录到来源节点与输入记录的追溯映射。
4. 实现算子状态与阶段水位持久化：把每个节点的执行状态、已提交输出摘要、阶段水位与内存占用以事务原子写入 SQLite；推进前校验节点输入摘要，摘要不匹配时拒绝推进并返回业务错误码，状态只能依据已提交的完整结果演进。
5. 实现强制终止后的恢复一致性：进程在阶段执行中被强制终止后，恢复路径依据 SQLite 识别已提交节点结果、半提交节点与未启动节点，只重放未完成节点且不得重复累加已完成节点的输出；恢复后结果文件与账本必须描述同一组已提交节点，不得出现账本已提交而结果缺失。
6. 实现并发一致性与幂等提交：允许多个调度实例并行推进不同阶段，通过 SQLite 事务与文件锁保证同一节点同一版本结果只提交一次，重复提交相同节点结果必须幂等；读取方只能看到完整已提交节点结果而非中间态，不得出现输出写入一半被读取。
7. 实现异常链路与业务错误码：输入文件缺失、JSON 畸形、依赖成环、内存预算非法、摘要不匹配、逻辑时钟回拨超过容差分别映射到不同业务错误码并在输出中保留可诊断字段；单个节点异常不得中断其他节点的已提交状态或污染结果文件。
8. 提供命令行接口与结果验证工具：支持 run、resume、status、verify 子命令，status 以稳定排序 JSON 输出每节点状态、所属阶段与内存占用，verify 校验持久化状态、结果文件与追溯映射的一致性；使用固定本地样本执行两次运行并恢复一次，输出一致报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地样本验证并行调度、预算放弃、强制终止恢复与结果一致性，附运行输出。
