当前是空白工作区，需要从零实现一个面向本地列式数据处理的向量化执行引擎，核心职责是在多表等值连接查询上完成连接顺序选择、向量化聚合计算与结果一致性验证。查询由若干本地列式数据块（每列以 NumPy 数组存储，列类型为整数或定长字符串编码）构成，逻辑计划为多个基表的等值连接加分组聚合与结果排序。引擎须维护表级统计元数据（行数、列基数、值域哈希摘要、空值比例），据此用代价模型枚举连接顺序并选优；随后以批量向量化方式执行扫描、哈希连接与聚合，产出确定性的结果集与执行报告。真实场景的难点在于代价模型（基于统计估计）与实际执行（基于真实中间行数）之间存在偏差：估计偏差会导致选出的连接顺序在交互延迟预算内反而更慢，而结果又必须与从零全量重算逐值一致。引擎须在估计与实测之间进行反馈校正，同时处理大表溢出落盘、批量大小自适应、查询中断与结果摘要校验等耦合问题，全部在 Windows 本地离线运行。

任务环境与准备：
安装 Python 3.11 与 NumPy，确保 pip 可离线安装本地已备好的 wheels 或包源访问可用。
确认 Python 标准库中 numpy、json、hashlib、time 可用，无需任何外部服务或数据库。
在空白工作区创建项目目录，准备固定随机种子生成样本数据块的脚本入口与 pytest 运行环境。
允许使用 Windows 本地临时目录作为溢出落盘位置，执行前清理残留文件。

业务要求：
1. 实现列式数据块与统计元数据的载入：每个数据块含列名、类型、NumPy 数组与行数，元数据含行数、列基数、值域哈希摘要与空值比例，以 JSON 加 NPZ 文件载入并做结构校验；列类型非法或摘要不匹配须返回 E_BAD_STATS 且不进入规划流程。
2. 实现基于代价模型的连接顺序枚举：对给定的多表等值连接查询枚举左深连接顺序（按确定性次序生成），对每个顺序按估计中间行数与列基数推算哈希表构建与探测代价，选出估计代价最小的顺序；枚举上限须显式配置，超限须返回 E_PLAN_LIMIT 而非静默截断。
3. 实现向量化哈希连接与批量聚合执行：连接与聚合须按配置的向量批量推进，单批内不产生逐行 Python 对象；分组聚合的输出键序须按最终排序键与分组键的确定性次序归一化，使相同输入在任意连接顺序下产出逐值一致的结果集。
4. 实现估计与实测的反馈校正：每完成一个连接阶段须记录实测中间行数与估计值的偏差；当累计偏差超过配置阈值时，后续阶段须按实测行数重新评估剩余连接顺序并允许改道，改道决策须写入执行报告，包含触发阶段、原顺序与新顺序及校正依据。
5. 实现交互延迟预算与中断语义：查询可声明单阶段与整查询的延迟预算，按真实单调时钟计时；预算耗尽须以 E_BUDGET_EXHAUSTED 中断并保留已产出的完整批次，不得返回半批数据；被中断查询的部分结果须可通过会话标识续读或明确标记为不可续读。
6. 实现大表溢出落盘与结果摘要校验：当某阶段中间结果超出内存上限时须按分区溢出到本地临时目录并在后续阶段合并读取，溢出与内存路径的结果须逐值一致；最终结果集须计算确定性摘要（按键序逐值哈希），摘要不一致须返回 E_DIGEST_MISMATCH 并输出首个不一致位置。
7. 实现并发查询与统计快照隔离：多个查询可并发执行，每个查询在开始时固定统计元数据版本与数据块版本，中途版本变化须判定为 E_SNAPSHOT_STALE；并发查询共用临时目录与内存额度时须互不干扰，额度超限须排队而非失败。
8. 提供本地样本与结果验证工具：内置固定随机种子的数据块生成器，产出至少四表、每表万行级、含倾斜键与空值的数据块；提供验证工具对同一查询在估计顺序与强制全排列顺序下执行并比对摘要，pytest 用例须在 Windows 离线覆盖选优、改道、预算中断、溢出、摘要校验与快照失效。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证连接顺序选优、反馈改道、预算中断与溢出路径，并确认结果摘要一致。
