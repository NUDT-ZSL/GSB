当前是空白工作区，需要从零构建一个面向本地 Windows 环境的分布式数据并行训练通信仿真台。系统以本地 TCP 回环端口模拟 4 至 8 个训练工作进程，每个工作进程持有按确定性随机种子生成的本地梯度分片；核心业务是：各工作进程按环形拓扑执行 all-reduce，将梯度分片切块后沿环转发并累加，最终每块在环形归约完成后广播给所有工作进程，使每个工作进程得到一致的全局梯度，并用该全局梯度做一步参数更新。系统须支持可配置的块大小、消息交错深度与人工注入的节点延迟，在界面中展示每个工作进程的发送/接收进度、通信阶段与当前参数版本，并允许用户在一次训练步内观察交互延迟对收敛一致性的影响。关键难点在于：环形通信的分块与阶段推进必须保证所有工作进程最终得到逐位一致的归约结果，归约顺序、浮点累加顺序与注入延迟下的消息交错会直接影响一致性；同时系统须区分可处理的退出信号与强制终止后的恢复，且快照整体替换须识别参数版本变化。

任务环境与准备：
安装 Python 3.10 或更高版本，并确认标准库 tkinter 可用；安装 NumPy 与 pytest。
在空白工作区创建项目目录，准备本地回环端口范围说明与样本随机种子配置文件，无需外部数据集或网络服务。
确认本机允许程序监听 127.0.0.1 上多个自定义端口，演示前清理占用端口。

业务要求：
1. 实现训练工作进程的本地梯度生成与参数初始化：以命令行参数指定的随机种子、工作进程数与模型维度生成确定性的初始参数向量与每步本地梯度分片，相同参数组合在多次运行中必须生成逐位相同的分片内容；分片内容摘要须写入日志，种子或维度非法时返回 E_INIT 业务码并拒绝启动。
2. 实现基于 TCP 回环的环形 all-reduce 通信：每个工作进程作为独立进程启动并监听本地端口，按环拓扑把梯度分片切块后依次转发并累加，块大小与消息交错深度可配置；通信阶段须明确划分 reduce-scatter 与 all-gather 两个阶段，且每个块的归约完成才允许进入广播阶段，违规推进须返回 E_PHASE 业务码。
3. 保证全局梯度的一致性：所有工作进程最终持有的全局梯度必须在字节级完全一致，归约采用固定的累加顺序规则而非依赖网络到达顺序；系统须提供一致性校验命令，比较各进程全局梯度的字节摘要，不一致时返回 E_DIVERGE 并列出首个分叉分片与各进程对应的累加顺序。
4. 实现人工延迟注入与消息交错观测：用户可按工作进程对配置固定毫秒的发送延迟，注入仅改变本地端口上的消息调度时序；系统须记录每个块在每个工作进程的发送时间、接收时间与当前阶段，并在界面中展示进度，要求延迟注入不改变最终归约结果的字节摘要。
5. 实现参数更新与版本识别：每完成一次 all-reduce 后各工作进程用全局梯度按固定学习率更新参数，参数版本号单调递增；系统须在每次更新后输出参数版本号、全局梯度摘要与参数摘要，当检测到某进程参数版本落后或超前时返回 E_VERSION 业务码并报告具体进程。
6. 实现训练快照的整体替换与恢复：快照持久化参数向量、参数版本号、随机种子、模型维度与已完成的训练步数，恢复时须先校验快照中的版本号与当前会话记录的版本差异，若版本不一致须整体替换当前状态而非增量合并；强制终止后重启须依赖已持久化快照恢复，且不允许承诺为每个进程都生成退出报告。
7. 实现可交互的 Tkinter 界面与可重复演示：界面展示每个工作进程的通信阶段、已收发块数、已用时间、当前参数版本与最终梯度一致性状态，并提供按钮触发一次完整训练步、保存快照与恢复快照；附带演示脚本顺序执行一次正常训练步、一次带人工延迟的训练步与一次快照保存后强制终止再恢复，三种场景的输出顺序与摘要须稳定可复现。
8. 实现异常链路与业务码报告：支持以命令行参数注入端口占用、块大小超过分片维度、快照文件损坏三类异常，系统须分别以 E_PORT、E_BLOCK、E_SNAPSHOT 业务码报告并写入结构化日志；异常注入仅改变输入或参数，不得修改源码制造失败，且注入延迟不得被用来替代真实超时判定。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
