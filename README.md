# 游戏配音 PCM WAV 片段拼接工具

把多段录音批次不同、参数可能不一致、个别损坏或失效的 PCM WAV 角色语音，
按剧本章节顺序拼成一条统一参数的完整音轨，并生成逐片段文本报告
（哪些成功、哪些被跳过及具体原因），方便素材师据此补录。

## 1. 环境要求

- Python **3.10 或更高版本**（开发与验收环境：Python 3.10.20，Windows 11）
- **仅使用 Python 标准库**（`wave` / `struct` / `json` / `argparse` 等），无需 pip 安装任何第三方包
- 不使用 Docker 或其他容器；不访问任何网络目标
- 建议用 `python -I`（隔离模式）运行，避免当前目录中被植入的同名模块（如 `json.py`）被解释器加载

## 2. 文件说明

| 文件 | 作用 |
| --- | --- |
| `wav_joiner.py` | 主工具（命令行入口）：RIFF/WAVE 头部解析、损坏判定、参数一致性校验、浮点限幅转换、顺序拼接、报告生成 |
| `make_samples.py` | 确定性生成演示素材：多种参数的合法 WAV、32 位浮点 WAV、损坏 WAV、假 WAV、非 PCM WAV、文本文件与 7 份 JSON 清单 |
| `verify_all.py` | 端到端验收脚本，覆盖任务全部 10 条验收标准（共 45 项检查），含独立 RIFF 解析做交叉验证 |

## 3. 可复现的本地启动方式

在项目根目录依次执行（PowerShell 与 Git Bash 命令相同）：

```bash
# 步骤 1：生成确定性样本与清单（输出到 ./demo，重复运行字节级一致）
python -I make_samples.py demo

# 步骤 2：运行全量自动验收（退出码 0 表示 45 项检查全部通过）
python -I verify_all.py

# 步骤 3：业务操作 —— 按清单拼接
python -I wav_joiner.py demo/manifest_main.json demo/out
# 成功后 demo/out 下生成 joined.wav（结果音轨）与 report.txt（逐片段报告）
```

退出码约定：

| 退出码 | 含义 |
| --- | --- |
| `0` | 正常结束（即使部分或全部片段被跳过；报告仍会生成） |
| `2` | 清单本身不可用（JSON 无法解析 / 缺少 `segments` / 条目非法），**不产出任何音频** |
| `3` | 结果 WAV 写入失败 |

## 4. 清单格式

顶层为含 `segments` 数组的 JSON 对象；条目按数组顺序即剧本章节顺序处理。
条目支持两种写法，可混用：

```json
{
  "description": "第一章角色语音（示例）",
  "segments": [
    "materials/a_int32_16k_mono.wav",
    { "path": "materials/b_int32_16k_mono.wav", "chapter": "ch02" }
  ]
}
```

- 相对路径相对于**清单文件所在目录**解析；也支持绝对路径
- 同一路径重复出现会按出现次数分别拼接、分别记录，不去重（对应章节重复播报语义）

## 5. 处理规则（与验收标准对应）

1. **支持的编码**：PCM 整数 WAV 的 8/16/24/32 位，以及 32 位 IEEE 浮点 WAV；
   其他编码（如 μ-law）直接跳过并在报告注明。
2. **参数一致性**：以第一个成功片段为基准（采样率 / 声道数 / 位深），
   后续片段任一参数不一致即跳过并逐条说明差异，其余片段照常拼接。
3. **损坏判定**：RIFF 总长度、任一子块声明长度与实际字节数不符、文件截断、
   `fmt`/`data` 块缺失、块对齐或字节率不自洽、data 长度不是帧大小整数倍，
   均视为损坏；损坏片段的采样数据绝不写入结果，也不影响其他片段。
4. **结果文件**：由标准库 `wave` 写出，保证为可播放的有效 PCM WAV；
   参数与首个成功片段一致；成功片段按清单顺序连续写入，**不插入任何静音或间隙**；
   总采样帧数严格等于各成功片段帧数之和。
5. **浮点转换**：32 位浮点片段写出时逐样本转为 32 位有符号整数，
   按 [-1.0, 1.0] 线性缩放，`|x| ≥ 1` 限幅到 int32 边界、NaN 归零，
   报告中明确标注该片段“已做浮点->整数转换”，输出样本不会越界。
6. **不可用条目**：路径不存在、扩展名非 `.wav`、内容无法解析为 WAV，
   一律跳过并记录原因，其他片段继续处理。
7. **全部不可用**：不生成结果 WAV（并清理同名陈旧文件），但报告照常生成，
   逐片段列出问题，供素材师逐一补齐。
8. **清单非法**：JSON 无法解析或缺少片段列表时直接返回非 0、输出可读错误，
   且不创建任何音频文件。

## 6. 业务操作样例

### 样例 A：综合清单（成功 + 各类跳过 + 重复条目）

```bash
python -I wav_joiner.py demo/manifest_main.json demo/out
```

`manifest_main.json` 共 13 个条目，实际结果（见 `report.txt`）：

- 成功 4 条：`a`（1000 帧）→ `b`（1000 帧）→ `c` 浮点片段（1000 帧，限幅转 int32）→ `a` 重复（1000 帧）
- 跳过 9 条：采样率不同、声道不同、位深不同、声明长度损坏、文件截断、
  假 WAV、μ-law 非 PCM、扩展名不符、路径不存在，各带具体原因
- `joined.wav`：16000 Hz / 单声道 / 32 位整数 PCM，共 **4000 帧**（0.25 秒）

### 样例 B：全部片段不可用（只出报告，不出音频）

```bash
python -I wav_joiner.py demo/manifest_all_bad.json demo/out_all_bad
# 退出码 0；目录中只有 report.txt，没有任何 WAV
```

### 样例 C：损坏的清单 JSON（非 0 退出，无音频产出）

```bash
python -I wav_joiner.py demo/manifest_broken_json.json demo/out_broken
# 退出码 2，stderr 输出：错误: 清单 JSON 无法解析: ...
```

### 样例 D：8 位 / 24 位同构素材（验证各整数位深均可作为基准）

```bash
python -I wav_joiner.py demo/manifest_u8.json  demo/out_u8    # 8000Hz/单声道/8bit，1100 帧
python -I wav_joiner.py demo/manifest_s24.json demo/out_s24   # 48000Hz/立体声/24bit，750 帧
```

### 自定义输出文件名

```bash
python -I wav_joiner.py demo/manifest_main.json demo/out \
    --output-name chapter1_full.wav --report-name chapter1_report.txt
```

## 7. 实际验证结果

在 Windows 11 + Python 3.10.20 上执行 `python -I verify_all.py` 的结果：

```
验收汇总: 通过 45 项, 失败 0 项
全部验收通过。
```

覆盖情况（括号内为任务验收条目编号）：

- 合法清单退出码 0、音频与报告双产物（1、6）
- 采样率/声道/位深不一致逐条跳过、其余正常拼接（2）
- 声明长度错误与截断文件标记损坏、采样不入结果（3）
- 输出为标准库可打开的有效 PCM，帧数等于成功片段之和，
  并逐字节比对确认片段边界直接相连、无静音间隙（4）
- 浮点片段限幅转 int32、报告注明转换、样本全部落在 int32 区间，
  锚点 `1.0/-1.0/1.5/-1.5` 限幅为 `[MAX,MIN,MAX,MIN]`（5）
- 报告行序与清单完全一致、文件名/结论/原因/帧数齐全，重复条目分别记录（6、9）
- 全损清单无 WAV 但有逐条原因报告，且会清理同名陈旧 WAV（7）
- 缺失路径、文本文件、假 WAV、非 PCM 编码均跳过且不影响其他片段（8）
- 损坏 JSON / 缺 `segments` 字段返回非 0、无音频、错误可读（10）
- 附加：8 位与 24 位同构拼接、空清单行为、陈旧文件清理
