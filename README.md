当前是空白工作区，需要从零构建一个面向中文文本意图识别的可集成领域组件与完整示例，核心业务问题是意图配置与标签体系的跨版本互操作及可复现的异常注入验证。业务对象是本地确定性生成的查询样本（JSONL，字段含 query_id、query_text、locale、label_raw）与三套并存的意图配置书写形式：v1 为扁平行式（每行为“意图标签|关键词串|优先级”三个以竖线分隔的字段，无字段名、无置信门限），v2 为带字段名的行式（每行含 intent、keywords、threshold、fallback_intent 四个键值对），v3 为结构化 JSON（在 v2 基础上引入标签层级路径、槽位占位符与权重向量）。组件需把样本按配置匹配关键词并做确定性意图判定，输出意图、命中关键词与码点偏移、置信度；同一查询在三套配置下的判定必须可核对。配置版本差异、标签体系收缩与脏样本会让判定结果分叉，组件必须能识别版本变化、整体替换配置快照，并通过输入或参数注入异常来验证各阶段的错误码与降级链路，最终以命令行示例与结构化报告交付。

任务环境与准备：
安装 Python 3.10 及以上与 NumPy，确认 python 与 pip 在 PATH 中可用。
在空白工作区创建项目目录与虚拟环境并安装依赖，无需外部服务或网络账号。
用固定脚本生成本地确定性中文查询样本 JSONL 与三套意图配置样本（含一份超过关键词上限与一份行字段数错误的样本用于异常演示）。
准备一份运行说明，列出执行基线与注入演示的命令行参数及其预期生成的报告文件名。

业务要求：
1. 实现 v1、v2、v3 三种意图配置的读取器：v1 按竖线分列解析、v2 按键值对解析、v3 按结构化 JSON 解析，并按版本头或字段集分派解析路径；未知版本返回 E_VERSION_UNSUPPORTED，行字段数不符与键名缺失返回 E_FORMAT_CORRUPT 并指明行号，标签重复返回 E_DUP_INTENT 并指明重复标签与行号。
2. 实现 v1 到 v2、v2 到 v3 的双向迁移器：升级时补全缺失的置信门限与回退意图并记录补全项，降级时对 v3 中 v1、v2 无法表达的层级路径与权重向量按显式声明的丢弃或展平规则处理并输出丢弃明细；迁移不得静默改变已有意图标签的匹配语义。
3. 实现确定性意图判定：对每条查询按配置关键词做最长优先匹配，输出意图、命中关键词及其在查询文本中的码点起止偏移、置信度；同分时按关键词长度降序、再按意图标签字典序打破平局；同一输入与同一配置版本下必须逐字节可复现，且偏移须落在查询码点长度内。
4. 实现跨版本判定结果裁决：同一查询在 v1、v2、v3 三种书写形式经加载与迁移后必须产出相同意图与相同码点偏移；当因 v1 或 v2 表达能力不足导致语义不可完全还原时，须返回 E_SEMANTIC_LOSS 并列出不可还原字段与涉及的 query_id，禁止以任一版本结果充当全部结论。
5. 实现标签体系收缩与回退链路：当配置版本提升导致受控意图集合收缩且已有查询命中的标签不再合法时，按回退意图或显式拒绝策略处理，分别返回 E_LABEL_RETIRED 或以回退结果代替并在结果中标记回退类别与触发它的旧标签；回退不得改变未受影响查询的判定结果。
6. 实现三阶段异常注入框架：在配置读取、迁移、判定三个阶段分别提供由输入或参数触发的注入点（如行字段数错误、键名缺失、关键词为空、偏移表长度不符），注入不得通过修改源码制造；每次注入须产生带阶段名、业务码、query_id 或行号的记录，并汇总到报告，未被任何阶段归因的异常须单独列出。
7. 实现配置快照的版本化管理与整体替换：每份意图配置连同受控标签集合携带单调递增版本号与内容校验和，加载时检测到版本号或校验和变化必须整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK；损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明版本与字段偏移。
8. 实现输入校验、资源上限与一致性自检：配置与样本参数非法分别返回 E_CONFIG_INVALID、E_DUP_QUERY 并指明字段；为关键词总数、单条查询码点长度与驻留匹配中间表设可配置上限，超限返回 E_RESOURCE_LIMIT 或降级为仅前缀匹配并标记降级类别；自检校验命中关键词偏移互不重叠、回退集合与直接命中集合无交集且并集覆盖全部判定记录，不一致返回 E_INCONSISTENT 并指出类别。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
