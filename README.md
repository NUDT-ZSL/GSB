当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个多源配置生效顺序冲突诊断与确定性收敛台，核心技术问题是同一逻辑服务在不同部署环境下，多条配置来源（本地基线源、文件覆盖源、运行时注入源）对同一键给出不同取值，系统的任务是判定每条键最终生效值与生效顺序链，并把顺序规则本身当作可诊断对象暴露出来。每个环境由一个本地确定性环境描述文件表示，描述其层级、可用来源集合与来源优先级偏置；每条配置键在来源之间可声明绑定约束（某键必须来自某来源或禁止来自某来源）。系统须按生效顺序规则逐键裁决，识别无法裁决的顺序环、绑定冲突与偏置导致的非单调结果，并把一次诊断会话（来源集合、顺序规则版本、逐键裁决轨迹与收敛结论）持久化到本地 SQLite；会话中断后须能恢复并重算。相同输入与相同诊断参数必须得到逐项一致的诊断报告与业务码，结论须可追溯到具体来源与规则。

任务环境与准备：
安装 Python 3.11 或以上版本，确认 python 与 pip 可在命令行直接调用。
创建空工作目录并初始化项目结构，使用 venv 建立本地虚拟环境；NumPy 从本机已缓存 wheel 安装，无需访问网络。
准备任务自带的本地样本环境描述、来源定义与偏置文件及演示脚本所需目录，所有输入均为本地文件，不访问外部服务。
确认本地 SQLite 可用（Python 标准库 sqlite3 即可），并预留在工作目录写入会话数据库与日志的权限。

业务要求：
1. 实现环境描述与来源集合的加载及强校验：从本地 JSON 读取环境层级、可用来源标识、来源优先级偏置与逐键绑定约束，校验环境标识唯一、来源标识属于受支持集合、偏置为整数、绑定目标来源存在且同键约束不自相矛盾；任一不合法须以 E_ENV 整体拒绝加载并输出出错字段路径。
2. 实现逐键生效顺序链的构建：对每个键按来源偏置与显式顺序规则生成有序来源链，链上每步记录来源标识、该来源的取值与参与排序的依据；顺序规则须显式声明且稳定，不得依赖字典或哈希遍历顺序，同一键多次构建必须得到逐字节一致的链结构摘要。
3. 实现自相矛盾顺序的识别与报码：当顺序规则与绑定约束共同导致某键无可裁决来源或顺序成环时，须分别以 E_CONFLICT 与 E_CYCLE 报告并输出涉及的键、来源与规则依据；识别不得因来源集合遍历顺序不同而漏报，且同一会话内同一键只报一次主因。
4. 实现逐键收敛裁决与依据回溯：按链上首个满足绑定约束的来源确定最终生效值，输出生效值、所选来源与其余被覆盖来源及各自被覆盖原因；被覆盖原因须区分优先级偏低与绑定禁止两类，最终结论须能由顺序链逐项回溯，不得出现链上无法解释的裁决。
5. 实现偏置变化后的整体替换收敛：来源优先级偏置或绑定约束变化后规则版本号单调递增，旧版本裁决结论须标记陈旧且不得参与当前统计；当前视图须整体替换而非增量合并，替换时须稳定列出发生变化的键、旧所选来源与新所选来源集合。
6. 实现诊断会话快照与恢复后重算校验：快照持久化环境集合版本、顺序规则版本、逐键顺序链、裁决结论与覆盖原因；恢复时先比较快照规则版本与当前规则版本，不一致须整体替换而非增量合并；恢复后按快照记录重算逐键裁决并与保存结果逐项比较，不可复现须以 E_REPLAY 报告具体环境、键与来源。
7. 实现异常注入与业务码链路：支持以命令行参数分别注入环境描述损坏、绑定约束引用缺失来源、顺序链摘要不一致三类异常，分别以 E_ENV、E_BIND、E_CHAIN 业务码报告并写入结构化日志；注入仅改变输入文件或参数，不得修改实现来触发失败。
8. 提供诊断工具与可重复演示：验证工具独立读取会话数据库，校验每个环境每个键的顺序链、所选来源与覆盖原因三者对应关系并输出结构化总结；附带确定性样本环境、来源与偏置及演示脚本，顺序执行首次全量裁决、偏置变更后重裁决、快照恢复后重算三个场景，输出顺序稳定。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
运行本地样本与演示脚本，校验逐键顺序链裁决、偏置变更整体替换重算及三类注入业务码均符合预期。
