某安全团队需要在离线 Windows 空白工作区从零开发一个本地证书链与信任管理工具。输入是一批本地确定性构造的证书描述文件（每条声明一个证书的标识、签发者标识、公钥指纹、有效期起止与吊销状态）与一组信任锚版本快照（每次快照声明受信根证书标识集合、策略版本与吊销条目），以及多份证书链声明文件（每条声明给出从叶到根的有序证书标识序列）。工具需在信任锚多次增删改的过程中，为每条声明计算可验证的信任路径结论（受信、不受信、部分可信），识别吊销与过期导致的失效传播，并输出可复现的 JSON 报告与人工可读的路径说明。核心难点是：信任锚快照会整体替换，路径校验结论必须与快照版本严格对应，乱序到达的锚更新不得与旧结论混合，同时吊销条目的传播与并发校验下的结论一致性和中断恢复相互耦合。全部处理在本地完成，不依赖网络、账号或真实证书基础设施。

任务环境与准备：
在 Windows 上准备 Python 3.11 及以上解释器并创建空白工作目录作为项目根。
仅使用 Python 标准库与 pytest（pip install pytest），全程离线使用本地生成样本，不访问网络。
确认工作目录可读写临时文件与目录，用于原子写入与文件锁验证。
准备本地确定性证书与快照样本生成脚本所需的随机种子设定，保证样本可重复构造。

业务要求：
1. 实现证书描述与链声明的解析规范化层：逐条解析本地 JSON 证书描述，校验标识唯一性、签发者引用是否存在、有效期起止为整数毫秒且起小于止、公钥指纹格式合法；解析链声明中的标识序列并校验其从叶到根的方向性、是否存在重复标识与引用缺失，对非法条目输出含文件序号与业务错误码的拒绝记录并继续处理其余声明。
2. 实现信任锚版本快照管理：每次快照整体声明受信根标识集合、策略版本与吊销条目，加载时校验快照结构版本与策略版本格式，并识别快照整体替换（受信集合任一增删或策略版本变化均视为新版本）；任意合法到达顺序的快照序列最终生效版本须由版本号与稳定键决定，不得依赖文件到达顺序或目录遍历顺序。
3. 实现信任路径校验与结论分级：依据当前生效快照判定链声明是受信、不受信还是部分可信，链中途出现不在受信集合的根、根标识不匹配受信集合、链长度为零或缺失中间证书须给出各自的业务错误码与出错位置；结论必须记录其所依据的锚版本标识，禁止将不同版本快照下的路径结论混合复用。
4. 实现吊销与过期的失效传播：依据快照中吊销条目与证书有效期计算沿链的失效传播，叶被吊销与中间证书被吊销须区分报告并标明传播到哪些声明；有效期判定须以快照声明的观测时间为唯一真值来源，不得使用系统当前时间，观测时间缺失时返回明确业务错误码。
5. 实现乱序锚更新下的一致性：支持锚快照与链声明任意交错导入，最终每条链声明的结论必须与该链最终排序位置所对应生效锚版本完全一致；若某链声明引用了在其导入时尚未出现的吊销条目，须在吊销条目到达后重新计算并覆盖旧结论，覆盖行为须在报告中体现观测一致计数。
6. 实现检查点与状态演进：以已应用快照版本水位与链结论状态持久化检查点，恢复时只从最后一个完整检查点继续；检测到检查点结构版本或策略版本与当前不一致时须整体重建而非增量续接，不得把旧策略版本的信任结论与新吊销条目混合。
7. 实现原子快照写入与强制终止后的恢复边界：检查点与最终报告均先写临时文件再整体重命名替换，替换前校验内容完整性；同一工作目录并发写入须以文件锁串行化，锁冲突返回 E_LOCK；进程被强制终止后只允许恢复到最后一个完整检查点，不承诺生成退出报告，且不得出现半写文件被当作有效状态加载。
8. 实现可交互命令行、确定性样本生成与 pytest 测试集：提供导入快照、校验链、查询结论、校验检查点四类子命令，并发校验时结论须与串行校验完全一致，退出码区分全部成功、部分失败与参数错误；样本生成器覆盖锚增删改、吊销传播、过期、乱序交错到达、未知策略版本与检查点中断恢复，测试断言业务错误码、结论对应锚版本及恢复后状态正确性。
