客户提出新能力，需要独立完成首个版本。当前工作区没有任何既有代码或样本，需在 Linux（WSL Ubuntu）上从零实现面向句法与依存解析的本地可集成领域组件，核心业务是规则版本互操作与格式迁移兼容。全部输入由本地固定种子脚本确定性生成：解析任务清单为 JSONL，每行含 sentence_id、raw_text、token_list、pos_tag_list、lang，另有规则快照以 v1 单文件 JSON、v2 分片 JSON 加 SQLite 元数据库、v3 嵌套带校验和声明三种格式并存，分别声明句法标签集、依存关系方向与根节点判定参数。解析链路建模为有向无环计算图：文本规范化与分词校验、句子结构预分析、依赖弧解析与标签指派、根节点回归与交叉校验、解析结果导出。系统需要把三种规则快照统一迁移为内部表示，并在规则版本演进时精确识别受影响句子与计算节点，复用未受影响结果，避免全量重算；同时要求跨格式语义等价裁决、解析结果追溯重放以及中断后的阶段恢复一致性。

任务环境与准备：
在 Linux（WSL Ubuntu）环境下准备 Python 3.10+，仅使用标准库 sqlite3、json、hashlib、argparse，无需 pip 安装额外依赖。
工作目录初始为空，所有输入由本地固定种子脚本在运行时生成，不得依赖外部网络、数据集或附件。
准备一个命令行入口，用于读取本地确定性生成的解析任务 JSONL 和三种规则快照文件，并输出解析结果、增量失效账本和业务码。

业务要求：
1. 实现 v1、v2、v3 三种句法与依存规则快照的读取器，按版本头或字段集分派解析路径：未知版本返回 E_VERSION_UNSUPPORTED，字段缺失、竖线字段数不符、零值无法解析或标签集非字符串数组返回 E_FORMAT_CORRUPT，并输出首个失败字段位置。
2. 实现三套规则快照到统一内部表示的双向迁移器：v1 升级到 v2 或 v3 时补全依存方向幂等约束、根节点回退规则、标签集合校验和默认值并逐项记录补全来源，v3 降级到 v1 时对 v1 无法表达的嵌套方向映射与回退规则按显式丢弃或展平规则处理；迁移后内部表示不一致返回 E_SEMANTIC_DRIFT 并指出首个差异字段。
3. 实现确定性的解析流水线核心，依次完成文本规范化与分词校验、句子结构预分析、依赖弧解析与标签指派、根节点回归与交叉校验四阶段；同一 sentence_id、同一规则快照与同一配置下必须逐字节产出相同的依存弧集合、解析标签、根节点列表与各阶段校验和，禁止使用系统随机数或时钟。
4. 实现基于内容寻址的缓存与规则版本变更后的定向依赖失效传播：依赖弧、解析标签、根节点与阶段校验和各自以内容哈希落盘，缓存键须纳入原始 token 序列哈希、规则快照内容哈希、标签集版本、根节点判定版本与上游节点哈希；当某条规则变更时计算受影响句子与受影响节点集合，复用未受影响上游产物，仅重算受影响后缀，并输出本次重算节点清单与复用集合。
5. 实现跨格式语义等价裁决，同一句法与依存规则以 v1、v2、v3 三种形式书写时，迁移并解析后必须产出相同的句法树集合、相同的依存弧集合、相同的解析约束与相同的根节点集合；任何格式迁移差异导致的解析结果偏离返回 E_SEMANTIC_DRIFT 并定位到具体弧或节点差异类别。
6. 实现解析导出的可追溯重放，每条依存弧须记录来源句法标签、路径节点版本、缓存键与根节点判定依据，可按这些记录重放出相同弧、标签与根节点；当缓存键任一依赖版本已变化而结果仍来自旧键时返回 E_STALE_RESULT 并输出受影响句子的句子 ID 与版本链。
7. 实现解析流水线的阶段检查点与强制终止恢复，四阶段各产生带单调递增版本号、已完成句子集合与内容校验和的持久化快照，检查点写入须以临时文件后原子替换；重启时从最近已提交阶段继续推进，已提交阶段句子不得重算，未提交中间产物必须丢弃并从阶段起点重建。
8. 实现规则快照与解析结果账本的版本化整体替换及并发提交控制，快照和账本均携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK；同一时刻只允许一个规则快照提交生效，并发冲突后到者立即获得 E_STAGE_BUSY 且不阻塞等待，并提供本地命令行示例验证完整链路。
