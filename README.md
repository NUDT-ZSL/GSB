这个交付项目着手于一个为风控模型提供后续治理的本地诊断管线，当前工作区除了一份设计说明外没有任何代码或数据，全部输入由随题固定种子脚本在 Linux（WSL Ubuntu）上确定性生成。业务需要联合处理三部分数据：来自多个监控周期的批量样本 JSONL（每行含 batch_id、cycle_id、特征列键值对、决策分数和真实标签）、一份决策边界校准配置（声明校准项、目标分位、阈值带、代价权重）以及可注入变更校准事件的日志（JSONL，每行含 event_seq、batch_id、变更维度、旧配置摘要与新配置摘要）。系统要完成跨批统计校验、分段分位校准、类别边界稳定性诊断和决策结果追溯；不仅要逐批次建立统计量账本，还需在配置变化后精确重算受影响批次，并用两代快照（v1 单文件、v2 分片加 SQLite）管理批次统计与校准结果。

任务环境与准备：
在 WSL Ubuntu 上准备 Python 3.10+，仅安装 NumPy，其余使用标准库 json、hashlib、sqlite3、argparse。
提供 generate_sample.py 固定种子脚本，用于生成样本 JSONL、校准配置与变更事件日志 JSONL。

业务要求：
1. 实现确定性的批次统计量累积与校验节点：按 batch_id 与 cycle_id 升序读取批量样本 JSONL，对数值特征和类别特征分别维护均数、方差、分位数或占比统计，并对每个批次的样本数与特征值域进行校验；同一输入、同一配置和固定种子下必须产生逐字节一致的批次摘要、异常计数与批次指纹，且输出必须显式区分参考窗口统计量和全量统计量。
2. 实现分段分位校准节点：按配置中的校准项和分段边界对每个批次的分位数做单调性检查与线性插值校准，不能把缺失分位视为可接受零值，发现跨段倒挂或零分母时返回 E_QUANTILE_ORDER 或 E_ZERO_DENOM 并记录该批次与分段索引。
3. 将批次统计量、校准结果和变更摘要以内容寻址方式缓存，缓存键必须包括上游批次样本内容哈希、算法与分段参数版本、校准事件序号和从属快照版本，键相同复用缓存产物，键不同强制重算，任何变更都记录在缓存引用链中。
4. 根据变更校准事件日志定向重算受影响批次：配置变化、特征重定义或分段边界改变时逐条解析变更维度并计算受影响批次闭包，禁止整批全量重算；要输出重算批次集合、复用批次集合以及二者之间的差异覆盖检查。
5. 检测并修复类别边界稳定性问题：对每个类别判定目标计算最近邻边界点距离和边界翻转次数，当翻转次数超过配置阈值或边界点距离统计量缺失时返回 E_BOUNDARY_FLIP 或 E_BOUNDARY_STATS 并附回放证据。
6. 实现强制终止后的恢复逻辑：处理中途可处理信号或外部中断时，必须退出前持久化已提交阶段索引；重启后从最近提交点继续，已提交批次不得重算或重复写入，未完成批次的中间统计与缓存指向必须被清除，并输出恢复说明。
7. 实现版本化快照与原子替换：两代配置与统计快照各携带单调递增版本号、绝对毫秒时间戳和内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，旧版本回退尝试返回 E_SNAPSHOT_ROLLBACK，应用快照切换不得被并发请求撕裂读。
8. 提供执行状态报告与可重放观测：每次执行完毕后写出含批次统计量摘要、校准变化账本、重算与复用批次清单、业务错误码和校验和的 JSON 报告，且报告内容可用本地样本和记录参数在重复运行中一致还原。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
以本地确定性样本验证统计累积、分段校准、定向重算与中断恢复；重复执行得到一致结果。
