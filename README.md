在空白工作区从零实现一个本地 Kubernetes 调度框架的仿真计算引擎，用于在确定性样本上复现调度插件链中过滤、打分与绑定阶段的并行调度与资源预算裁决。本地 JSON 样本给出：节点清单（节点名、可分配 CPU 毫核与内存 MiB、GPU 卡数、污点、拓扑域标签）、Pod 清单（Pod 名、请求资源、优先级、亲和与反亲和规则、拓扑散布约束、容忍声明）、以及调度配置（过滤插件启用列表、打分插件权重、每轮调度总逻辑时间预算毫秒、每工作负载并发调度上限、重试预算、逻辑时钟步进）。引擎需为每个待调度 Pod 依次执行过滤插件、打分插件与绑定决策，所有时间推进基于可注入逻辑时钟，不得读取系统墙钟；节点资源与拓扑域状态在调度轮次间必须持久化并可恢复。核心矛盾在于：多个过滤插件可能给出不同淘汰原因，打分插件权重归一化与资源装箱评分存在浮点精度取舍，而并行调度与总时间预算又要求部分 Pod 在预算内被放弃且放弃原因可追溯，同时进程被强制终止后资源占用与决策链不得出现半提交状态。

任务环境与准备：
安装 Python 3.10 或更高版本，并确保 pip 可用。
安装 NumPy 与 pytest：在命令行执行 pip install numpy pytest。
确认 Python 标准库 sqlite3 可用（通常随 Python 发行版提供）。
准备本地确定性样本目录，包含 nodes.json、pods.json、schedule_config.json 与注入清单，所有样本文件由任务执行者按题面语义生成，不依赖网络。
在 Windows 命令行中确认工作目录可写，用于创建 SQLite 数据库文件与临时对象目录。

业务要求：
1. 实现节点清单、Pod 清单与调度配置的解析校验：节点名与 Pod 名唯一、可分配 CPU 毫核与内存 MiB 为正整数、GPU 卡数非负、容忍声明与污点键值格式合法、过滤插件启用列表与打分插件权重覆盖已知插件、每轮总预算与并发上限为正整数；非法条目必须返回明确业务错误码（如 E_BAD_NODE、E_BAD_POD、E_BAD_CONFIG）且不写入任何持久化状态。
2. 实现并行过滤插件链：依次执行资源可行性、污点容忍、节点亲和、Pod 间反亲和与拓扑散布过滤，每个插件对每个节点返回通过或淘汰并记录首个淘汰原因；资源可行性判定必须在整数毫核与 MiB 换算后比较，不得以未换算浮点比较；过滤结果按节点名稳定排序输出，同时输出每节点五个插件的逐个判定与首个淘汰插件的顺序号。
3. 实现打分插件链与权重归一化：按资源装箱、节点亲和匹配度与拓扑散布均衡度计算原始分，再按配置权重归一化为总分，输出每节点每插件的原始分、权重、归一化中间值与最终总分；归一化必须对权重和为浮点非整数的配置给出确定性舍入规则并记录舍入方向，并显式计算归一化中间值的累计误差上界，当两节点总分差小于给定容差且绑定结论依赖该差值时标记为精度敏感并输出误差来源链。
4. 实现每次调度轮次的全局并行调度器：同一轮次内对多个待调度 Pod 并发执行过滤与打分，同时受每轮总逻辑时间预算与每工作负载并发调度上限双重约束；预算耗尽时必须放弃剩余未启动 Pod 并记录放弃原因，区分预算内未启动、启动后过滤失败与主动放弃三类结局，已启动 Pod 必须执行到明确结论，不得被简单截断为超时；时间推进全部使用注入的逻辑时钟毫秒值，不得读取系统墙钟。
5. 实现节点资源与拓扑域状态的持久化演进：每次绑定决策后原子扣减目标节点的可分配 CPU 毫核、内存 MiB 与 GPU 卡数，并更新拓扑域内 Pod 计数；状态只能依据已提交绑定结果推进，推进前校验轮次内容摘要，摘要不匹配时拒绝推进并返回业务错误码，重启后不得凭内存残留决定资源占用；同一 Pod 的绑定额定资源必须与实际扣减量一致。
6. 实现强制终止后的恢复一致性：把调度轮次水位、每节点已提交资源占用、每 Pod 调度阶段与决策链摘要以事务原子写入 SQLite；进程在过滤、打分或绑定中途被强制终止后，恢复路径依据持久化状态识别已提交绑定与半提交决策，只重放未完成 Pod 且不得重复扣减资源，不得承诺一定生成退出报告。
7. 实现多进程并发一致性与幂等提交：允许多个调度实例并行处理同一批 Pod，通过 SQLite 事务与文件锁保证同一 Pod 同一轮次同一版本只被绑定一次、节点资源不被并发超卖，重复提交相同 Pod 绑定结果必须幂等；读取方只能看到完整已提交轮次快照而非并发中间态，并需识别节点资源快照的版本变化以拒绝过期写入。
8. 实现调度决策解释与可重复命令行演示：支持 load、schedule、explain、resume、status、verify 子命令；explain 以稳定排序 JSON 输出指定 Pod 的过滤淘汰链、打分明细、精度敏感标记与最终绑定节点，status 输出各节点剩余资源与逻辑时钟水位；使用固定本地样本执行两次 schedule 必须产生逐字节一致的决策报告，verify 校验持久化状态与决策报告一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地样本验证过滤淘汰链、打分归一化与精度标记、预算放弃原因、中断恢复与并发幂等，两次运行输出逐字节一致。
