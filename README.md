当前是空白工作区，需要从零实现一个本地配置中心热更新引擎及其数值诊断能力，交付可交互的专业应用与可重复演示。配置中心以本地 JSON 提供初始配置快照，含命名空间、配置键、值、版本号与逻辑时钟毫秒戳；配置值中包含大量数值参数（超时毫秒、重试倍率、采样率、限流阈值、容量上限、权重），订阅配置的本地数据处理客户端依据这些参数执行确定性计算任务（过滤阈值、聚合权重、批大小与输出比例），任务结果直接受数值参数换算影响。业务痛点在于：配置热更新需要把 JSON 中的十进制小数换算为内部定点整数供计算内核使用，换算的舍入方向与累计余量会沿派生量计算链传播，使两个配置版本产生本不应有的结果差异，且差异难以归因到具体配置键。引擎需维护配置版本链，把每次热更新对客户端计算派生量的影响记录为可追溯的误差账本，并提供验证工具复现结论。

任务环境与准备：
安装 Python 3.11 及以上，确认 Python 可执行文件在 PATH 中。
安装依赖：pip install flask numpy；SQLite 使用 Python 标准库 sqlite3，无需额外安装。
在工作区根目录创建 data 目录并准备本地 JSON 样本：配置快照文件、配置补丁序列、客户端计算输入样本与逻辑时钟步进表，全部由本地脚本或手工编写，不依赖线上配置中心。
确认工作区可写，SQLite 数据库文件与临时指针表放在工作区内的 state 目录，无需容器或外部服务。
准备崩溃注入脚本的可选路径：以本地命令行启动计算后在指定阶段强制结束进程，用于验证恢复路径，不使用容器。

业务要求：
1. 实现配置快照与补丁解析校验：命名空间与配置键唯一、值类型与声明一致、版本号严格递增、逻辑时钟戳非负、补丁声明目标版本号与内容摘要且摘要与内容一致；非法输入返回明确业务错误码（如 E_BAD_CONFIG、E_BAD_CLOCK）且不写入任何持久化状态。
2. 实现数值配置键的受控定点换算与余量保留：把超时、倍率、采样率、容量与权重按各自的定点标度换算为整数，登记每次换算的标度、舍入方向与被舍弃余量，未满一个定点单位的余量按配置键分别保留并在后续换算中参与，同一配置版本重复换算必须逐位一致。
3. 实现配置版本链与原子热更新：每次补丁提交产生新版本并在 SQLite 事务中整体替换当前快照指针，保留父版本号与内容摘要；订阅客户端读取时必须看到完整的新版本或完整的旧版本，禁止读到新旧混合参数；版本回退必须被拒绝并返回独立业务错误码。
4. 实现数据处理客户端的确定性派生量计算：按配置参数执行过滤、加权聚合与批大小缩减，派生量（阈值、有效权重、期望批大小）的运算顺序固定，定点通路结果可复现；同时保留基于 decimal 的高精度通路作为真值对照，两通路数值与偏差须逐项输出。
5. 实现沿派生量依赖链的误差上界累计与来源链输出：每个派生量累计其换算与乘加的误差上界，输出包含配置键、版本号、换算登记序号与该登记余量的来源链；当两版本或两客户端派生量差小于容差且结论依赖该差值时标记为精度敏感，并说明若改用更高标度是否翻转结论。
6. 实现热更新期间客户端计算结果一致性保障与强制终止恢复：客户端在计算中途收到新版本时必须完成当前版本计算并记录结果所绑定版本，新版本仅在下一次计算开始时生效；把版本指针、客户端结果摘要、误差账本与逻辑时钟水位以事务写入 SQLite，进程被强制终止后只重放未提交计算，不得重复计入派生量。
7. 实现配置版本整体替换的版本变化识别与读取隔离：提交新快照包时比较版本号、内容摘要与键集合，判定完整替换、增量追加或无需操作；完整替换以临时表加版本号切换指针而非逐条覆盖，进行中计算按绑定版本完成，读者不得观察到替换中间态。
8. 实现多进程并发一致性与幂等提交：多个客户端进程与更新进程并行时，通过 SQLite 事务与文件锁保证同一版本号只提交一次、同一客户端同一计算轮次结果只提交一次，重复提交相同补丁或结果幂等；提供 load、apply、compute、resume、status、verify 子命令，status 以稳定排序 JSON 输出当前版本、逻辑时钟水位与各客户端结果摘要及精度敏感标记。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证热更新原子性、定点与高精度两通路对照及强制终止后恢复一致性，并输出误差来源链与业务错误码。
