团队拿到的是一个刚装好 Python 的 Windows 空目录，除随题交付的固定种子样本生成脚本外没有任何代码，需要先把首版做成能验收的形态：面向自研本地 HTTP 中间件的离线请求走私判定与模糊测试工作台。工作台不做静态字符串匹配，而是把本地确定性生成的原始报文流按连接重建为一台可执行的 HTTP 协议状态机，用两代检测规则快照对状态机迁移施加约束，再以变异报文作为模糊测试输入驱动状态机重演，观察内容长度与传输编码并存、同名头重复、块长度畸变与尾部夹带等变异是否让状态机与真实回显服务产生解读分歧，从而把走私判定从命中升级为状态迁移证据。报文流为 JSONL，每行含连接标识、方向、报文序号、逻辑毫秒戳与原始字节十六进制载荷；规则快照 v1 为单文件 JSON 记录规则名、相对生效秒、扁平匹配串与启用标记，v2 为分片 JSON 加 SQLite 元数据库记录规范规则名、绝对毫秒生效窗口、规则代数、状态机迁移约束与墓碑标记。本地还有一个随题启动的本机回环 HTTP 回显服务作为真实对端，模糊测试注入的报文会实际发送并观测回显，交互延迟与状态机结论必须一致。

任务环境与准备：
在 Windows 开发机安装 Python 3.11 或以上，并用 pip 安装 numpy 与 pytest，SQLite 使用 Python 标准库 sqlite3 无需额外安装。
确认本机回环网络可用并允许绑定 127.0.0.1 的临时端口，回显服务随工作台在本机启动，不使用外部站点或账号。
运行随题交付的固定种子样本生成脚本生成报文流、两代规则快照与变异清单，生成物写入工作区本地目录并保持只读。
准备一个用于存放检查点、快照与诊断报告的本地工作目录，确保可写并能创建临时文件与文件锁。

业务要求：
1. 实现原始报文流、两代规则快照与变异清单的严格解析规范化层，校验连接标识与方向取值、报文序号在连接内单调唯一、十六进制载荷为偶数长度可解码、逻辑毫秒戳为非负整数；v1 的相对生效秒须以样本声明的观测时钟为唯一基准换算为绝对毫秒，禁止使用系统当前时间；同一规范规则名按规则代数与生效时刻裁决权威来源，墓碑标记必须覆盖较早的非墓碑记录；对非法记录输出含来源文件与记录序号的拒绝清单并继续处理其余记录。
2. 按连接与方向把报文载荷重组为字节流并切分为请求边界，构建每台连接的 HTTP 协议状态机，状态至少覆盖起始行、头字段区、实体区、块传输区与报文结束，迁移由实际字节驱动而非规则匹配；处理乱序到达、重复投递、缺口与跨连接混入，缺口返回 E_MSG_GAP 并给出缺失序号区间，跨连接混入返回 E_MIX_CONN，重复按首次出现为真值并在报告中记录重复次数与位置。
3. 实现状态机迁移约束的规则化表达与应用：把合并后规则视图中的每条规则编译为一组状态迁移前置条件与违规动作，规则命中须给出触发时的状态名、字节偏移与命中规则代数；当多条规则在同一状态同时命中且动作冲突时按规则代数、生效时刻与规范键稳定排序裁决并列出被压制规则，禁止依赖字典遍历顺序。
4. 实现变异驱动的模糊测试与真实回显观测：按变异清单对请求边界、内容长度头、传输编码头、同名头与块长度字段执行确定性变异，把变异报文通过本机回环 HTTP 回显服务实际发送并观测回显字节，回显确认的往返时延须以真实墙钟测量；状态机对变异报文的解读与回显服务实际解读不一致时按分歧类型给出稳定业务码，并保证同一变异在相同种子下重复执行产生同一分歧集合。
5. 保证交互延迟采集与计算结果的一致性：每条变异请求从提交时刻计到回显结论可见时刻的延迟须真实测量并写入报告；当状态机判定结论在延迟观测完成前已得出或被延迟到达的回显推翻时，须以最终可见结论为准并记录推翻次数，不得以固定延迟常量或线程超时冒充真实测量；在任意并发度、任意回显延迟档位与任意到达顺序下，每条变异的判定结论、分歧集合与延迟观测记录必须与串行执行按稳定键排序的结果完全一致。
6. 实现规则补丁增量到达后的失效闭包与重判：补丁使某规则的迁移约束、启用标记或墓碑状态变化时，沿规则键到状态机迁移到变异命中的依赖关系计算需重判的连接与变异集合，仅重判受影响部分且要求与从零全量重演逐字节一致，不一致返回 E_RECOMPUTE_DIVERGE；遇到规则依赖环返回 E_RULE_CYCLE 并列出环中规范规则名；变异集合边界与重启回显服务的行为不得让闭包漏判。
7. 实现真实资源预算与异常链路的可复现注入：并发度、单连接实测耗时上限、单连接报文数上限与在途发送字节上限均可配置，耗时以真实墙钟测量判定而非人为延迟，超时返回 E_TIMEOUT 并以真实机制终止该连接后续变异发送，超限返回 E_BUDGET 并计入报告；回显服务不可达、连接被对端提前关闭与非预期响应码须作为独立业务码进入异常链路报告，且不得中断同批其他连接。
8. 实现检查点演进、原子快照整体替换与强制终止后的恢复边界：按已完成连接标识与聚合判定状态把检查点持久化到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放校验以识别半写残留；检查点结构版本或规则代数口径变化时须整体重建而非增量续接；检查点与诊断报告均先写临时文件并在校验内容可解析后整体重命名替换，同一工作目录并发写入以文件锁串行化且锁冲突返回 E_LOCK；进程被强制终止后不承诺生成退出报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本与本机回显服务验证状态机重演、变异分歧、延迟观测及断点恢复的一致性。
