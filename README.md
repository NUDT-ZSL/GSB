当前是空白工作区，需要从零实现一个面向本地多进程场景的分布式锁与租约中间件。服务管理锁资源（锁名、持有者、租约截止时间、租约代数 epoch），客户端通过本地 HTTP 申请、续期、释放锁，并可为锁注册依赖对象（如某个缓存键或配置块），当锁被新持有者接管时依赖必须级联失效。核心难点有三：其一，续期请求可能在租约已过期之后到达，此时旧持有者的续期必须被拒绝而不能复活已失效的租约；其二，锁被接管会使依赖闭包失效，但失效计算必须基于已持久化的锁状态快照，不能在并发续期与接管之间产生中间态；其三，进程重启后租约到期判定必须依据绝对时间戳恢复，且正在进行的依赖失效必须能够重放而不重复触发下游通知。

任务环境与准备：
安装 Python 3.11 或以上版本，并确保 pip 可用。
在工作区创建虚拟环境并安装 pytest 与 requests（或使用标准库 urllib 构造 HTTP 请求）。
确认 Windows 防火墙允许本地回环端口的 HTTP 服务与多进程客户端连接，无需外网。
准备本地样本目录用于存放锁与依赖描述 JSON、时钟偏置配置与测试桩参数，全部为离线确定性数据。
运行前清理工作区内的 SQLite 数据库文件与临时目录，确保每次实验从相同初始状态开始。

业务要求：
1. 实现锁资源的租约模型与申请协议：锁记录包含锁名、持有者标识、租约时长、租约截止绝对时间戳与单调递增的租约代数 epoch；同一锁名的申请在旧租约未过期时须拒绝并返回 E_LOCK_HELD，过期后新持有者接管时 epoch 必须递增 1，且旧 epoch 的续期与释放请求须返回 E_STALE_EPOCH 而不得改写锁记录。
2. 实现续期与过期判定的一致性：续期请求携带申请时获得的 epoch，服务端须以绝对时间戳判断旧租约是否已过期；若续期在过期边界之后到达，即使旧持有者仍在线也必须拒绝，且不得把已过期租约恢复为有效。过期判定与续期写入必须在同一 SQLite 事务内完成，避免并发续期与接管交错导致租约被复活。
3. 实现依赖注册与依赖图：客户端可为锁注册依赖对象，依赖记录包含锁名、依赖对象标识、依赖类型与注册代数；依赖图须能回答任一锁的传递依赖闭包与任一依赖对象被哪些锁引用。同一依赖对象在同一锁下重复注册须幂等，跨锁注册须保留多条引用关系以支持级联失效。
4. 实现锁接管触发的依赖级联失效：新持有者接管使 epoch 递增时，须对该锁的依赖闭包计算失效集合并按固定顺序输出失效通知；失效计算必须基于接管事务提交后的持久化锁状态快照，不得包含旧 epoch 注册的依赖。若失效过程中下游通知失败，必须记录以待重放而非静默丢弃。
5. 实现失效通知的重放与幂等：每次级联失效产生带唯一失效标识与递增序列号的失效事件，下游确认后才标记完成；进程重启后未确认的失效事件须按序列号顺序重放，同一下游对同一失效标识重复收到的通知不得产生重复副作用。重放次数超过配置上限时须标记为失败并保留诊断信息。
6. 实现并发申请与接管的互斥与公平性：同一锁名的申请、续期、释放与依赖注册须串行化到该锁的一致性边界内，不同锁名之间可并行；多个持有者在旧租约过期后同时申请时，须恰好一个成功接管，其余返回 E_LOCK_HELD 并附带当前持有者与租约剩余毫秒，不得出现多个成功接管。
7. 实现进程重启后的租约恢复与中断接管处理：启动时须依据持久化的绝对截止时间恢复各锁有效状态，把中断时处于接管中间状态的事务回滚或前滚到一致点；已过期但未触发失效的锁须在恢复后补算级联失效。已完成的失效不得在恢复后重复生成新的失效标识。
8. 提供本地 HTTP 接口与可重复测试：通过本地 HTTP 提供申请、续期、释放、注册依赖、查询锁状态与依赖闭包、查询失效事件序列的接口，错误以固定业务码在 JSON 中返回。提供使用本地多进程客户端与可注入时钟偏置的测试桩，pytest 用例须在 Windows 离线覆盖过期后续期拒绝、epoch 递增、级联失效闭包、重放幂等、并发接管唯一性与重启恢复，并以固定参数可重复运行。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
