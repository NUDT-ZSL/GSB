当前是空白工作区，需要从零构建一个面向 LLM 偏好对齐与奖励建模数据准备的本地诊断工作台，核心业务问题是偏好对的增量更新与依赖失效。业务对象是本地确定性生成的偏好样本：每条样本含 pair_id、prompt、chosen 回复、rejected 回复、annotator_group、标注版本号与质量标记；偏好对经过多级处理形成奖励建模数据集——质量清洗（长度、重复率、噪声字符比例按配置权重加权打分）→ 近重复检测（基于文档给出的分词与签名相似度）→ 对级一致性判定（prompt 相同或高度相似的偏好对归为同一组）→ 配比采样与数据集清单输出。整个流程被建模为有向无环的计算图，每个节点产出带内容哈希的中间产物并写入本地内容寻址缓存；当某位标注者的样本被修正、质量权重调整或近重复门限变化时，只有依赖这些输入的下游节点需要重算，其余节点必须复用旧缓存。缓存键必须纳入所有影响产物的输入摘要，否则会出现“改了输入却仍命中旧缓存”或“无改动却被全量重算”的两类错误，工作台需要把这两类情况都可视化并可诊断。

任务环境与准备：
安装 Python 3.11 及以上版本，并创建本地虚拟环境（如 venv）。
通过 pip 安装 NumPy 与 pytest，版本以本地可获取的稳定版本为准，无需外网模型或数据下载。
在空工作区中自行创建项目目录结构与模块布局，不使用容器或容器编排。
准备本地确定性样本生成入口：按固定种子生成偏好样本 JSONL 与配置 JSON，样本与配置由题面字段语义定义，不依赖真实账号或线上数据。

业务要求：
1. 实现确定性的偏好对计算图：把质量清洗、近重复检测、对级一致性判定、配比采样四个节点建成有向无环图，节点参数由配置字典决定；同一输入与同一配置下必须产出逐字节一致的中间产物与最终数据集清单，禁止依赖系统时间、字典遍历顺序或未声明的随机状态，随机性只能来自配置中显式给出的固定种子。
2. 实现内容寻址缓存与缓存键构造：每个节点产出附带内容哈希的中间产物写入本地缓存目录，缓存键须纳入该节点全部输入摘要、上游节点产物哈希与节点参数；键相同的请求必须复用快照，键不同必须重算，且缓存键组成须可在诊断视图中逐项展开核对，键组成与产物哈希须能互相校验。
3. 实现增量更新的依赖失效传播：修改某标注者的样本、调整质量权重或近重复门限时，计算受影响节点与受影响 pair_id 集合，复用未受影响上游缓存，仅重算受影响后缀；须输出本次重算节点清单与复用节点清单，并保证局部修改后的结果与从零全量重跑在相同配置下逐字节一致。
4. 实现对级一致性与近重复检测语义：近重复按签名相似度与可配置门限判定，相似对归入同一组，同分时按 pair_id 升序打破平局；同组内不得出现 chosen 与 rejected 交叉矛盾（同一 prompt 下同一回复既被判优又被判劣）的未记录情形，出现时返回 E_PAIR_CONFLICT 并给出 pair_id 与冲突组标识，允许通过配置显式声明保留策略后继续产出。
5. 实现配比采样与欠配归因：在每标注者组与每质量档的样本目标配额下做确定性采样，优先满足总量并允许受限欠配；清单须记录每个配额目标的实际达成量、欠配原因与采样种子，使同一快照同一配置重跑得到相同清单与相同欠配明细。
6. 实现缓存与清单快照的版本化及整体替换：缓存条目与数据集清单各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补；损坏或校验和不符的条目在读取时返回 E_CACHE_CORRUPT 并指明节点名与版本号，禁止使用部分可解析的损坏数据。
7. 实现资源上限与并发提交控制：为近重复候选比较次数、清单内存估算与并行重算节点数设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或降级并在结果中标记降级类别；同一时刻只允许一次增量提交生效，并发冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待，已完成版本不得被旧版本回退覆盖。
8. 实现可视化诊断工作台与跨模块一致性自检：展示计算图拓扑、各节点缓存命中或重算状态、失效传播覆盖范围、组冲突与欠配明细、最近业务错误码，并支持点击节点查看缓存键组成与内容哈希；自检校验图拓扑无环、保留集与剔除集无交集、清单样本均可追溯至质量分与相似度、复用与重算集合无交集且并集覆盖全部受影响节点，不一致返回 E_INCONSISTENT 并指出类别。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证缓存键完整性、局部修改与全量重跑一致及诊断报告正确。
