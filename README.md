当前是空白工作区，需要从零实现一个本地边缘缓存系统的命中率与淘汰诊断管线，核心业务目标是在确定性样本上复现缓存准入、淘汰与热度统计链路中的数值精度问题与误差传播，并给出可追溯的验证结论。本地 JSON 样本给出：缓存条目清单（条目键、内容摘要、字节大小、访问计数、最近访问逻辑时钟毫秒、权重与过期时刻声明）、节点清单（节点名、容量字节上限、淘汰策略为 LRU 或 LFU 或加权混合、权重衰减系数）以及诊断配置（浮点容差、定点标度、采样比例、逻辑时钟步进）。访问轨迹由样本按固定规则给出每个条目的访问时刻序列，不依赖任何外部服务。管线需按可注入逻辑时钟推进访问序列，计算每条目与每个节点的热度得分、命中率与淘汰候选排序，并在浮点通路与定点通路之间比对结果，标记因累计舍入导致排序翻转或命中率偏差的精度敏感点。

任务环境与准备：
确认 Windows 上安装 Python 3.10 及以上，并在命令行中可执行 python 与 pip。
安装 NumPy 与 SQLite 支持：pip install numpy，SQLite 使用 Python 标准库 sqlite3，无需额外安装数据库服务。
准备本地确定性样本目录：缓存条目清单 JSON、节点清单 JSON、访问轨迹 JSON 与诊断配置文件，全部由任务执行者按题面字段语义手工构造或脚本生成，不依赖网络与真实缓存服务。
在空白工作区初始化项目目录与 Python 虚拟环境，确保所有命令在 Windows 命令行中可直接运行。

业务要求：
1. 实现缓存条目清单与节点配置的解析校验：校验条目键与节点名唯一、字节大小为正整数、访问计数非负、权重有限且非负、容量上限为正整数、淘汰策略与权重衰减系数枚举合法，构建条目到节点的映射模型；非法输入必须返回明确业务错误码并保持元数据状态不变。
2. 实现基于可注入逻辑时钟的访问轨迹推进与命中判定：所有访问时刻、过期判定与热度衰减只依赖注入的逻辑时钟毫秒值，不读取系统墙钟；同一轨迹在任意运行次数下必须得到逐位一致的命中序列与命中率，逻辑时钟回拨超过配置容差时返回业务错误码且不改动已提交统计。
3. 实现热度得分与淘汰候选排序：按访问计数、最近访问时刻与权重衰减系数计算每条目热度，LRU、LFU 与加权混合策略须给出不同的候选序列；排序必须为稳定排序并输出每条目得分、排序键与所属策略，得分相同的条目按条目键确定性裁决而非依赖插入顺序。
4. 实现浮点通路与定点通路双路计算与误差溯源：把热度得分、命中率与容量占用统一在受控定点标度下重算，记录每项换算的标度、舍入方向与换算前原始浮点值；当两通路结果差超过容差时必须输出首个分歧条目、两通路中间值与该条目依赖的观测项。
5. 实现精度敏感标记与误差上界传播：对每次加法与乘法累计误差上界，当两个条目的热度差小于给定容差而淘汰裁决依赖该差值时标记为精度敏感，并输出误差来源链（含参与运算的条目键、访问序号与换算步骤），标记结论必须可由持久化的观测项复现。
6. 实现容量约束下的淘汰执行与结果一致性校验：容量超限时按候选序列淘汰条目直到占用不超过上限，淘汰后命中率与占用必须与逐条目全量重算的唯一真值一致；若存在不一致必须区分是排序误差、舍入误差还是容量换算误差，并输出差异条目与两路结果摘要。
7. 实现强制终止后的恢复一致性：把访问水位、已提交流程统计、热度得分快照、精度敏感记录与逻辑时钟水位以事务原子写入 SQLite，每轮提交识别版本变化并整体替换当前结果指针；进程在访问推进或淘汰中途被强制终止后，恢复路径依据持久化状态识别已提交与半提交步骤，只重放未完成步骤且不得重复累计访问计数。
8. 实现多进程并发一致性、幂等与可重复命令行验证：允许多个诊断实例并行处理不同节点，通过 SQLite 事务与文件锁保证同一节点同一访问序号只被计入一次、重复提交相同访问批次幂等，读取方只能看到完整已提交统计；提供 run、resume、status、verify 子命令，status 以稳定排序 JSON 输出命中率、精度敏感数量与回收数量，verify 校验持久化状态与报告一致。
