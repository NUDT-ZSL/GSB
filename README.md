安全团队刚把 Windows 开发环境准备好，项目目录里还没有任何代码，需要为自研防火墙策略审计工具落地首个可运行版本：判定同一批流量裁决任务在两代规则格式下是否给出等价结论。业务对象是本地确定性脚本按固定种子生成的规则映射清单（JSONL，字段含 case_id、五元组（源地址前缀、目的地址前缀、协议、源端口区间、目的端口区间）、规则序号、动作）、两代规则快照（v1 为单文件 JSON，规则以扁平行式记录相对生效秒、无 CIDR 规范化、端口以区间字符串书写、动作以扁平整数码给出；v2 为分片 JSON 加 SQLite 元数据库，记录规范规则键、CIDR 规范化后缀、端口闭开区间标记、绝对生效毫秒时刻、规则代数与墓碑标记）以及一份映射声明，声明哪些 v1 规则对应哪些 v2 规则、映射方向与冲突处置口径。引擎需把两代快照合并成统一规则视图，对每个裁决任务给出命中规则、动作与依据代数，并输出结构化报告。

任务环境与准备：
确认 Windows 本地已安装 Python 3.11 或以上，并可用 python --version 验证。
安装依赖：pip install pytest；SQLite 使用 Python 标准库 sqlite3，无需额外安装。
在工作区预留 samples、state 与 reports 三个子目录，分别存放生成样本、检查点与报告。
任务执行前不预置任何代码或样本文件，全部由题目要求的固定种子生成器在工作区内确定性产出。

业务要求：
1. 实现规则映射清单、两代规则快照与映射声明的严格解析规范化层：校验 case_id 与规范规则键唯一性、地址前缀合法、协议取值白名单、端口区间下界不大于上界、v1 相对生效秒为非负整数、v2 绝对毫秒时刻与代数为非负整数，对非法记录输出含来源类别、记录序号与稳定业务码的拒绝记录并继续处理其余记录。
2. 把 v1 与 v2 规则统一为规范规则视图：v1 相对生效秒须以样本声明的观测时钟为唯一基准换算为绝对毫秒，禁用系统当前时间；地址须按 CIDR 前缀补齐为规范网段，v1 端口区间字符串与 v2 闭开区间标记须归一为同一端点口径；同一规范规则键按规则代数与生效时刻裁决权威来源，墓碑标记必须覆盖较早的非墓碑记录。
3. 实现映射声明的双向对账：按声明的映射方向把 v1 规则与 v2 规则配对，检测 v1 有而 v2 缺、v2 有而 v1 缺、一对多与多对一配对，分别返回 E_MAP_MISSING、E_MAP_EXTRA 与 E_MAP_AMBIGUOUS 并列出涉及规则键；同一规则在映射声明中出现多次时按声明代数裁决，映射结论须与映射声明条目到达顺序无关。
4. 实现裁决任务的规则命中：为每个 case_id 在统一视图中按规则序号顺序求交五元组，地址按规范网段前缀包含关系判定，端口按归一后的端点口径判定，同一 case 多条规则命中时按规则序号优先并由映射声明裁定冲突处置口径；无规则命中、多条规则同序号冲突、规则已墓碑须分别返回稳定业务码并给出命中规则键与依据代数。
5. 实现两代格式等价性裁决：对每个 case_id 分别以 v1 视图与 v2 视图独立裁决，结论不一致时返回 E_NOT_EQUIVALENT 并给出两侧命中规则键与动作差异；等价判定必须依据两侧各自规范视图而非任一单侧结果复用，且须报告可解释的等价理由（命中键相同、映射覆盖或规则语义相同）。
6. 实现规则快照增量到达后的失效闭包：新快照或映射声明补丁到达时，沿规则到映射到裁决任务的依赖关系计算需重判的 case 集合，仅重判受影响部分，并要求每条 case 的结论与从零全量重判逐字段一致；映射或规则依赖出现环时返回 E_MAP_CYCLE 并列出闭环规则键，重判集合须按 case_id 稳定排序。
7. 实现快照识别、事务化账本与强制终止边界：以规则代数、映射代数与规范规则集合变化识别快照整体替换；裁决结论在 SQLite 中按 case_id 与规则键单事务推进，前置校验失败不得改动账本；检查点与报告先写临时文件再整体重命名替换，进程被强制终止后只允许恢复到最后一个完整检查点且不承诺生成退出报告。
8. 交付可交互命令行与确定性本地验证：提供导入快照、等价裁决、导出诊断报告、校验检查点四类子命令，报告为可解析 JSON 并含 case 级结论、两侧命中、业务码、依据代数与失效闭包；样本生成器在真值文件中显式写入每条 case 发送端五元组原始字节与同步标记，验证只依据同步标记与引擎输出比较；任意并发度下结论须与串行一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地两代规则快照与映射清单驱动引擎，核对等价裁决、映射对账、失效闭包与恢复后账本一致。
