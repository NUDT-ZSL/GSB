在空白工作区从零实现一个本地模型推理服务弹性伸缩控制面，用于在确定性样本上复现多副本模型服务的伸缩决策链路：请求负载观测、副本准入、显存与算力预算扣减、并行副本拉起调度以及中断恢复。本地 JSON 给出：模型服务清单（服务名、模型版本、每副本显存需求 MiB、每副本算力单位、最小与最大副本数、冷启动逻辑耗时、批处理窗口）、节点资源池（节点名、GPU 卡数与每卡显存、每节点并发实例上限、拓扑域），以及请求负载轨迹（按可注入逻辑时钟给出每窗口到达率与平均序列长度）。伸缩控制器需把观测窗口换算为副本需求，在资源池显存与并发实例双重预算下并行拉起或回收副本，决策须逐轮次持久化并支持强制终止后按已提交状态恢复。全部依赖本地确定性样本与本地 Python 测试服务，不访问任何真实模型或线上资源。

任务环境与准备：
安装 Python 3.11 及以上版本并确认 sqlite3 与 numpy 可导入，无需 GPU 或外部模型。
在空白工作区准备本地确定性样本：模型服务清单、节点资源池、请求负载轨迹与注入异常清单 JSON 文件。
准备本地 Python 测试服务脚本，按回环地址模拟副本拉起与回收响应并支持注入延迟与错误状态。
确认工作区可写，用于生成分片目录、SQLite 状态库与命令行输出文件。

业务要求：
1. 实现模型服务清单、节点资源池与负载轨迹的解析校验：服务名与节点名唯一、每副本显存与算力为正整数、最小副本数不大于最大副本数、冷启动逻辑耗时为非负整数、请求到达率与序列长度非负有限，非法输入须返回明确业务错误码且不写入任何持久化状态。
2. 实现观测窗口到目标副本数的换算：按到达率、平均序列长度与单副本吞吐能力估算需求副本数，估算过程须记录所依赖的观测项、聚合顺序与向上取整位置，并使相同轨迹在任意运行次数下得到逐位一致的目标副本数。
3. 实现节点级显存与并发实例双重预算的副本装箱：在每卡显存容量、每节点并发实例上限与拓扑域约束下为待拉起副本选择落点，显存与并发任一不足时不得部分放置；装箱须记录每卡剩余显存、被淘汰候选及首个触发约束。
4. 实现并行副本拉起调度器：同一轮次内按服务分组并发拉起副本，同时受每轮总逻辑时间预算与每服务并发拉起上限约束；预算耗尽须放弃剩余未启动副本并记录放弃原因，并区分预算内未启动、拉起后失败与主动放弃三类结局，已启动副本不得被截断为超时。
5. 实现副本生命周期状态机与连续失败计数演进：副本在待拉起、冷启动中、就绪、排空中、已回收之间按规则迁移，迁移须依据本轮完整拉起结果与持久化状态裁决，重启后不得凭内存残留决定副本状态；排空中的副本在排空完成前不得被再次计入可服务容量。
6. 实现基于注入逻辑时钟的退避与再拉起计划：拉起失败副本按连续失败次数计算指数退避并施加确定性抖动与上限，再拉起时间须与每服务并发拉起上限和总预算共同裁决，预算不足以覆盖全部到期副本时按优先级与稳定次序截断并记录截断依据。
7. 实现持久化状态与强制终止后的恢复：把伸缩轮次、副本阶段、显存与并发占用、预算消耗与逻辑时钟水位以事务原子写入 SQLite，每轮提交识别版本变化并整体替换当前快照指针；进程在拉起或回收中途被强制终止后，依据持久化状态识别未提交副本并只重放未完成步骤，不得重复扣减预算。
8. 实现多进程并发一致性与异常链路：允许多个控制面实例并行处理不同服务，通过 SQLite 事务与文件锁保证同一副本同一轮次只被拉起一次、同一节点显存不被并发超卖，重复提交相同轮次结果幂等；拉起目标连接拒绝、响应超出单动作预算、回显副本版本不符、样本摘要不匹配须映射到不同业务错误码，单次异常不得污染其他服务或中断主循环。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
