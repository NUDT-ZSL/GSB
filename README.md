酒店客房服务调度员与前台值班经理共同管理一条边缘推理链路：住客通过客房平板或前台转述提出送水、换毛巾、报修、叫醒等诉求，部署在楼层边缘节点的文本理解模型据此生成应答与工单建议。前台常在请求生成过程中撤销误下单或已由人工处理完的诉求，此时服务必须尽快中止该请求并把它占用的设备显存还原给后续住客请求。调度员要能回看每个被撤销请求的完整轨迹、回收了哪些缓存块、省下的显存是否真被排队请求接上，从而判断撤销操作是否即时生效、批内是否存在块漏回收或重复释放。

任务环境与准备：
使用 Linux（WSL Ubuntu）与 Python 3 运行环境，在仓库内仅依赖标准库与已安装的 NumPy，不访问外部推理服务、账号或网络资源。
在仓库内运行确定性生成器产出请求流、取消事件与配置，并以包内入口一次性跑批调度、回收核对、续算与摘要输出，结果写入仓库内结果目录供本地复查。

业务要求：
1. 读入由固定种子确定性生成的客房服务请求流，每个请求带共享的酒店/楼层/房型提示词前缀、住客诉求后缀、生成 token 上限、到达逻辑时刻、客房号与工单标识，以及边缘服务配置中的 KV 缓存块大小、总块数、显存字节预算、批内最大请求数与逐 token 解码步长。
2. 按逻辑时刻推进批调度：请求到达时按到达顺序尝试占用批内槽位与预填充所需缓存块，预填充完成后进入逐 token 解码，每个解码步追加所需的 KV 缓存块申请，输出逐请求生命周期账目（到达、取得缓存块、预填充完成、已生成 token 数、终态）。
3. 分别处理预填充阶段与解码阶段的取消事件：预填充中取消须立即中止后续块申请，解码中取消须在下一个解码步边界停止并为该请求清算已占块，输出被回收的缓存块标识清单与回收字节数。
4. 对取消事件与生成完成落在同一逻辑时刻的请求，按固定裁决规则（先判取消、同刻多次取消取最早原因）确定终态，其中被裁决为取消的请求不得再产生后续 token，输出竞争裁决记录与按取消原因、取消阶段的统计。
5. 将取消让出的批内槽位与空闲缓存块按排队请求的到达顺序重新接纳，记录接纳请求的工单标识、复用块来源与被取消请求的对应关系，同时核对已用块数与空闲块数之和等于总块数、显存占用不超字节预算。
6. 逐逻辑时刻计算显存占用曲线并输出，标记已释放块被再次分配、块在两请求间重复占用、请求结束后仍有块未归还等异常，形成可逐条定位到块标识与工单标识的核对报告。
7. 从持久化的生命周期账本与缓存块账本恢复批调度状态，让已取消请求不再被重新接纳、已释放块保持空闲，并从续算点继续推进剩余请求流，输出续算前后块占用状态的一致性说明。
8. 输出每次取消生效时刻到对应块回收完成的时延统计，以及按取消原因与取消阶段的回收效率摘要，供前台评估撤销操作的即时性与显存利用率。

验收：
以确定性请求流与构造边界样本核对块数守恒、显存不超预算、同刻竞争裁决、被取消请求不再生成后续 token，并验证续算后状态一致。
