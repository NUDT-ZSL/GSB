在游戏外设与触觉交互产品中，需要从零开发一个本地触觉反馈指令流合成引擎：把一份带时间轴的触觉事件脚本（强度包络、纹理脉冲、敲击瞬态）合成为多个触觉设备各自的驱动指令流，并在合成过程中守住每设备的带宽配额（每帧最大指令数与帧时长）与全局在途指令缓冲预算。输入为程序按确定性规则生成本地 JSON：设备清单（设备标识、采样率、帧时长、支持强度范围与量化档位、每帧最大指令数）、触觉事件脚本（事件类型、起始毫秒、持续毫秒、强度曲线控制点、目标设备），以及全局并发上限、在途缓冲上限与状态目录。核心难点在于：不同设备采样率与帧时长不同，同一毫秒在各自时间轴上对应不同采样点，事件强度必须先在设备采样点域量化再装箱成帧指令；帧指令数上限会迫使强度变化被拆分成多条带持续时长的指令，需保证拆分后的可观测强度序列与逐采样点单独下发完全等价；同时全局在途缓冲预算不足时只能让设备粒度等待，任何补偿与拆分都不得改变时间轴语义。

任务环境与准备：
安装 Python 3.11 及以上版本，并通过 pip 安装 NumPy。
确认工作目录为空，由任务执行者创建项目结构与源码。
编写本地样本生成脚本，按确定性种子生成设备清单与触觉事件脚本 JSON，不依赖真实触觉设备或外部资源。
准备用于触发可处理终止信号的本地测试方式（例如向进程发送 Ctrl+C），并在运行说明中记录。

业务要求：
1. 实现设备清单与事件脚本解析校验：读取 JSON，校验设备标识唯一且非空、采样率与帧时长为正整数、每帧最大指令数为正整数、量化档位为不小于 2 的整数、强度范围为有限数且下限小于上限、事件起始毫秒为非负整数、持续毫秒为正整数、强度曲线控制点时间严格递增且取值在目标设备强度范围内、目标设备存在，非法输入返回带 E_xxx 业务码的 JSON 错误且不产生任何状态文件。
2. 实现设备采样点域的强度包络合成：按每个设备采样率把事件持续区间换算为整数采样点起止，在包络控制点之间做分段线性插值，再把连续强度按该设备量化档位落为整数级，同一事件的起止采样点与逐采样强度只依赖事件声明与设备参数，与设备合成顺序无关，多设备时间轴对齐误差不超过 1 个该设备采样点。
3. 实现每设备每帧的指令装箱与拆分：把设备采样点按帧时长装箱，同一帧内被量化强度相同的连续采样点合并为一条带持续采样点数的指令，装箱后该帧指令数不得超过设备每帧最大指令数，超限时按确定规则把该帧指令拆到后续帧并记录溢出计数；在设备可观测强度上，装箱拆分后的逐采样强度序列必须与不装箱时逐采样点单独下发完全一致，等价性以逐采样强度与持续区间比对判定。
4. 实现全局在途指令缓冲预算下的并行设备合成：以设备为单位并行推进各自采样时钟合成指令，同时处于在途的指令缓冲总量不得超过全局上限，超出时按设备标识确定顺序让部分设备等待，禁止通过降低量化精度、截短持续或丢弃指令来腾出预算；最终各设备指令流与其在并发度为 1 时串行合成结果逐条相同，归并输出按设备标识与采样点序固定排序。
5. 实现设备间同步锚点对齐诊断：按脚本中的同步标记（若干设备需在同一全局毫秒对齐的锚点）检查各设备指令流中对应锚点的实际采样点位置，计算各设备相对参考设备的对齐偏差并以采样点与毫秒双重表示写入报告；任一对齐偏差超过脚本给定允许值时返回 E_SYNC 并指明设备与锚点，不阻断其余设备的合法指令结果写入。
6. 实现帧块级持久化与版本识别恢复：每个设备每个帧块完成后把该块指令、已完成采样点范围与由设备清单与事件脚本规范化摘要构成的版本标识原子写入状态目录，先写同目录临时文件再整体替换，替换前比对已有快照的版本标识，标识变化时不得直接覆盖而须归档旧版本；再次启动时标识一致则只补算缺失帧块并复用已完成块，标识不一致则从头重做。
7. 处理可处理终止信号与强制终止恢复：外部可发送的可处理终止信号只在帧块边界生效，写入中断标记并以约定整数退出码退出，未完成帧块不得留下可被误认为已完成的结果；强制终止后重启仅依据已持久化且摘要有效的帧块状态恢复，不承诺生成退出报告，恢复后各设备指令流须与未中断一次跑完的结果逐条相同。
8. 实现帧块摘要校验与指令流原子导出：全部块完成后逐块比对内容摘要，摘要不匹配、缺失或声明的指令条数与实际不符时判定该块失效并返回 E_DIGEST 且回退补算，不得静默使用失效块；校验通过后按设备标识与采样点序拼装指令流，先写同目录临时文件再整体替换正式输出，并输出含各设备指令条数、溢出计数、对齐偏差与中断次数的 JSON 报告。
