当前是空白工作区，没有现存项目、代码或数据附件。需要从零构建一个面向卷积与插值算子的本地可集成组件与完整示例，核心业务问题是分块执行下的可复现数值验证与异常注入诊断。业务对象是本地确定性生成的算子任务清单（JSONL，字段含 job_id、op_kind、input_shape、kernel_shape 或 scale 参数、stride、padding、interp_mode、seed、weight_seed、dtype、block_policy）以及由 seed 驱动 NumPy 确定性生成的特征图与卷积权重数组，不依赖任何外部数据、模型或服务。算子覆盖二维卷积与最近邻、双线性、双三次插值四类。组件把每次调用建模为：参数校验→分块执行→与逐元素参考实现比对→偏差谱归因与策略记录。需要保证同一输入同一配置下逐字节可复现，并能在异常输入下给出带阶段名的结构化业务码与降级链路说明。

任务环境与准备：
确认 Windows 上可用 Python 3.10 及以上版本，并安装 NumPy 作为唯一第三方依赖。
准备本地样本生成方式：按任务清单中的 job_id、input_shape、kernel_shape 或 scale、seed 与 weight_seed 用 NumPy 还原特征图与权重，不引入外部数据文件。
准备一个本地输出目录用于存放命令行示例产生的 JSON 报告与演示输入，确保目录可写。
不安装容器运行时、不依赖网络服务、真实模型或 GPU，全部计算在本地 CPU 上完成。

业务要求：
1. 实现二维卷积与最近邻、双线性、双三次插值四类算子的统一入口，按任务清单解析 input_shape、kernel_shape 或 scale、stride、padding、interp_mode 与 dtype；对形状维度不符、stride 非正、padding 越界、未知 op_kind 或 interp_mode、dtype 不支持分别返回 E_SHAPE_INVALID、E_PARAM_INVALID、E_OP_UNSUPPORTED、E_DTYPE_UNSUPPORTED 并指明 job_id 与字段。
2. 实现四类算子各自独立的 float64 逐元素参考实现，作为同一快照内的参考真值来源；参考实现不得调用待验证的分块执行路径，且同一 job_id、seed 与配置下参考输出必须逐字节可复现。
3. 实现统一的分块执行路径：卷积与插值共用同一套块划分与越界索引规则，边缘块按显式声明的边界策略处理，block_policy 给出块尺寸候选与选择依据；同一输入与配置下分块结果与参考结果须在给定 float64 容差内一致，并记录最大绝对偏差、最大相对偏差与超容差元素位置。
4. 实现偏差谱归因：把卷积类偏差归因到块边界越界处理、累加顺序或补偿求和介入中的一级，把插值类偏差归因到权重计算、越界邻点选择或累加顺序中的一级，并在结果中输出各级偏差分位数与误差放大比，使主导来源可由偏差明细重算核对。
5. 实现四阶段异常注入框架：在参数校验、块划分、数值计算、偏差比对四个阶段分别提供由输入或参数触发的注入点（如 kernel 含非有限值、块尺寸为零、padding 超出声明范围、容差配置非正），注入不得通过修改源码制造；每次注入须产生带阶段名、业务码与 job_id 的记录。
6. 实现异常归因与降级链路：某阶段产出业务码时下游须按明确策略降级，例如块划分失败时回退到整图单块执行、偏差比对配置非法时退回默认容差并标记降级类别，降级结果必须携带降级类别与触发它的上游业务码；未被任何阶段归因的异常须汇总到结果中而不是静默吞掉。
7. 实现资源上限与规模自适应选路：为单次调用的估计驻留内存、块数量与同时驻留的中间结果数设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或选择更小分块、降到 float32 路径；降级须在结果中标记降级类别，且不得改变已输出块的数值正确性口径。
8. 提供可集成的领域组件接口与完整示例：暴露 conv2d、interpolate、inject_diagnose 与偏差裁决入口，命令行示例读取本地确定性样本输出含策略记录、偏差谱、四阶段注入记录、降级链路与业务码的 JSON 报告，并附一次注入异常输入与一次超预算降级的演示。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地生成样本验证四类算子分块结果与参考一致、偏差归因可核对且注入与降级链路均有记录。
