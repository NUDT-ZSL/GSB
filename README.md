当前为空白工作区，需要从零构建一个面向本地 Windows 环境的跨组件配置分发平台。平台管理一组本地模拟的组件节点（每个节点是一个独立的本地子进程，通过 Windows 回环 TCP 上的 JSON 行协议与平台通信），用户的配置变更以版本化清单形式录入：每个版本包含若干配置项键值、目标节点集合与分发策略（全量或分片）。平台核心职责是把一次配置版本演进编译为分发计划，按节点并行下发，收集各节点的应用回执与派生状态，并把整个演进会话持久化到本地 SQLite 文件；会话在中断后必须从持久化状态恢复到一致视图，且恢复后的节点派生状态必须与重新计算的结果一致。平台另提供结果验证工具，用于校验版本演进、分发计划、回执与最终状态之间的对应关系。

任务环境与准备：
安装 Python 3.11 及以上版本，确认 python 与 pip 在 PATH 中可用；无需 Docker 或其他容器环境。
在本地虚拟环境中安装 Flask 与 pytest（pip install flask pytest），SQLite 使用 Python 标准库 sqlite3。
准备样本配置版本清单 JSON 文件、节点注册表文件与节点模拟脚本，全部位于工作区本地目录，不依赖任何网络服务或真实账号。
确认 Windows 回环地址 127.0.0.1 与动态端口可用，防火墙不拦截本机回环连接；演示脚本按固定顺序运行并输出结构化总结。

业务要求：
1. 实现配置版本清单的加载与强校验：从本地 JSON 文件读取版本清单，校验版本号单调递增且唯一、配置项键合法、目标节点标识必须在节点注册表中存在、分发策略字段完整；非法清单须以 E_MANIFEST 业务码整体拒绝并指出错误位置，不得部分应用。
2. 实现组件节点的本地子进程编排：平台以 Windows 子进程方式启动每个注册节点，通过回环 TCP 的 JSON 行协议下发配置并接收回执，回执含节点标识、应用的配置版本、派生状态摘要与序列号；节点进程崩溃或协议消息格式非法时须以 E_NODE 业务码报告并标记该节点为降级，不得阻塞其他节点的分发。
3. 实现版本演进的状态机：一次分发会话在 prepared、distributing、committed、failed 间迁移，每个迁移须记录触发版本号、已确认节点集合与时间；同一版本重复提交必须幂等，未达到提交条件时禁止进入 committed，并输出当前迁移受阻原因。
4. 实现按节点并行分发调度：依据分发策略把配置项切片后并行下发到目标节点，要求全局并发上限与每节点单次下发超时可配置；某节点超时须按策略重试且不改变单次下发语义，重试结果需与首次回执区分记录，调度须输出每个节点的下发开始与结束观测。
5. 实现回执收敛与派生状态一致性判定：汇总各节点回执后，对每个节点计算其派生状态摘要，并与平台根据配置版本重新计算的期望摘要比对；不一致或节点未回执时须以 E_CONVERGE 业务码报告，并稳定列出偏差节点标识与所属配置版本，禁止以部分节点成功视为会话完成。
6. 实现会话快照的版本识别与整体替换恢复：会话快照持久化到本地 SQLite，含版本清单、分发计划、节点回执、状态机迁移记录与已提交版本号；进程中断后重启须依据持久化状态恢复，若快照版本与当前配置版本不一致须整体替换而非增量合并，恢复后须保证已提交版本号不回退。
7. 实现恢复后的一致性重算校验：恢复会话时对最近一个已提交版本重新计算分发计划与各节点期望派生摘要，与快照中保存的计划及回执逐项比较；因节点降级或配置版本缺失导致不可复现时须以 E_REPLAY 业务码报告并列出不可复现的具体节点与配置项。
8. 提供结果验证工具与可重复演示：验证工具读取会话数据库，校验版本演进、分发计划、回执与最终状态之间的对应关系并输出结构化总结；附带本地样本清单与节点模拟脚本，顺序执行首次分发的正常会话、故障注入后中断并恢复的会话、以及版本升级后的重算校验，输出顺序稳定。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
