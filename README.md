当前是空白工作区，需要从零构建一个面向 Windows 本地环境的 MVCC 可见性实验工作台，作为领域数据编辑与操作应用。系统以本地 SQLite 文件保存表结构与行数据的物理多版本记录（每行带整数事务号 xmin、xmax 与提交状态），并通过 Tkinter 桌面界面与脚本两种方式让用户批量录入读写事务。核心业务是：每个事务在开始时取得一致性快照（活跃事务集合与快照事务号），随后按快照判定每行每个版本对当前事务是否可见；用户在界面中不断切换事务、查看某个键在某事务视角下的可见值与候选版本链，系统须在交互过程中即时给出可见性结论与判定依据，同时后台持续提交新事务并写入新版本。难点在于交互延迟与计算结果一致性之间的权衡：快速路径会走缓存与增量索引，而校验路径必须回到事务日志与版本链逐条重放。会话状态（事务表、版本链、快照缓存、历史判定）须可持久化为命名快照，恢复时识别版本差异并整体替换，强制终止后只依据持久化状态恢复。

任务环境与准备：
安装 Python 3.11 及以上版本，确认标准库 sqlite3、tkinter 可用（Windows 官方安装包默认包含）。
在空白工作区创建项目目录并初始化包结构，无需第三方依赖；如需可视化仅使用 Tkinter。
准备本地确定性样本：一组事务脚本（含 begin、读写、commit、rollback 顺序与事务号）与查询序列，作为 JSON 文件放入项目 samples 目录。
确认工作区具备可写权限以创建 SQLite 会话库与快照文件；运行前清空历史会话目录以保证可重复。

业务要求：
1. 实现事务生命周期与一致性快照的本地持久化：事务在 begin 时分配单调递增事务号与活跃事务集合快照，commit 或 rollback 时写入 SQLite 提交状态；同一事务在快照不变时重复读取同一键不得得到不同结论，非法状态迁移须返回 E_TXN 业务码并保持事务表不变。
2. 实现行版本链的存储与多版本写入：每次写入在 SQLite 中追加带事务号的新版本记录并维护版本链指针，删除以 tombstone 表示；须校验版本链无环、事务号沿链单调、同一事务对同一键只能产生一个最终版本，违反约束以 E_VERSION 整体拒绝该次写入并给出链位置。
3. 实现基于快照的可见性判定核心：对给定快照与键，按 xmin 提交状态、xmax 是否为活跃事务、事务号与快照区间的关系判定目标版本是否可见；须输出判定依据的每一步中间结论（xmin 是否已提交、是否在快照内、xmax 状态），并按稳定顺序枚举候选版本链，相同快照与键重复判定必须得到逐字节一致的结论与依据。
4. 实现交互快速路径与权威重放的分离：界面交互走快照缓存与增量可见性索引给出即时结论，同时提供校验命令走事务日志与版本链逐条重放得出权威结论；任一交互结论与权威重放不一致须以 E_VISIBLE 报告键、事务号与首个分歧步骤，缓存条目须绑定快照版本号，版本变化后旧缓存整体失效而非逐条修补。
5. 实现在后台提交新事务时的交互响应与一致视图：后台按可配置并发上限持续提交写事务，前台可见性查询须在全部已提交事务构成的最新快照下给出结论，且任一次查询内部使用的活跃事务集合与提交状态必须来自同一快照版本，不允许混用；并发提交与查询同时发生时结果须唯一确定。
6. 实现交互延迟观测与判定：对每次可见性查询记录单调时钟起止毫秒，聚合为均值、P95 与最大值的整数定点表示并给出量化误差上界，声明时钟基准与真值来源为本地单调计数；当单次快速路径查询超出显式预算阈值时须记录降级原因，延迟观测不得改变可见性结论。
7. 实现会话快照的版本识别与整体替换恢复：快照持久化事务表、版本链、活跃快照集合、缓存版本与历史判定摘要；重新打开快照时先比较快照版本与当前会话版本，不一致须整体替换事务表与版本链而非增量合并，旧快照保留只读；强制终止后重启只能依据持久化状态恢复，未提交事务标记为回滚且不得声称生成退出报告。
8. 实现历史判定重放校验与异常注入：从快照恢复后按快照记录的事务序列与查询序列重新执行可见性判定并与保存结论逐项比较，不可复现须以 E_REPLAY 报明具体键与事务号；支持以命令行参数注入版本链指针损坏、快照缓存版本错位、事务号回退三类异常，分别以 E_CHAIN、E_CACHE、E_TXN 业务码报告并写入结构化日志，注入仅改变输入文件或参数。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
