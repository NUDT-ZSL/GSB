当前是空白工作区，需要从零构建一个面向 Windows 本地环境的负载均衡健康检查组件，聚焦状态演进与恢复一致性。组件在回环 TCP 与 HTTP 端口上启动若干确定性后端模拟服务（可按本地脚本注入慢响应、连接拒绝、间歇性失败），并以本地 JSON 描述负载均衡器配置：后端池成员、探测协议、探测间隔毫秒、超时毫秒、连续成功与失败阈值，以及慢启动权重表。核心业务是：按固定探测周期持续推进每个后端的健康状态机（unknown、healthy、unhealthy、draining），在状态迁移时同步更新流量权重与可用成员集合，把每次探测与每次迁移写入可持久化的状态账本，并支持从账本快照恢复后继续演进而结论不漂移。组件须提供可交互的专业应用界面与可重复演示脚本，全程不依赖真实网络与外部账号。

任务环境与准备：
Windows 10 及以上，安装 Python 3.11 并确保标准库 sqlite3、socket、subprocess、tkinter 可用
无需第三方网络服务或账号，后端模拟服务与探测目标全部在回环端口由本地脚本启动
准备确定性样本配置文件、后端行为注入脚本与演示脚本，先手动执行一次冷启动收敛以确认界面可打开
确保回环高位端口未被占用，可在演示脚本中以参数指定端口区间

业务要求：
1. 实现负载均衡配置与后端池的加载及强校验：从本地 JSON 读取后端成员（地址须为回环字面量与合法端口）、探测协议、间隔与超时毫秒、连续成功与失败阈值、慢启动权重表；校验成员标识唯一、间隔与超时为正整数且超时小于间隔、权重为非负整数且同池权重和不为零，任一不合法须以 E_POOL 整体拒绝加载并输出出错字段路径。
2. 实现本地确定性后端模拟服务与探测执行器：以子进程在回环端口启动可注入行为的后端（正常、慢响应、连接拒绝、按脚本间歇失败），探测执行器按配置协议与超时发出真实连接与请求，超时必须由真实套接字超时产生而非人为延迟，探测结果须记录协议、起止单调时钟毫秒、响应摘要与单次结论，且不得修改后端脚本以制造结果。
3. 实现健康状态机与慢启动权重演进：按连续成功与失败阈值在 unknown、healthy、unhealthy、draining 间迁移，每次迁移记录触发原因、探测轮次与时刻；后端恢复为 healthy 后按慢启动权重表在若干轮内线性提升权重直至满额，被置为 draining 的后端须在完成在途探测后退出可用成员集合，迁移不得回溯修改历史轮次结论。
4. 实现流量权重与可用成员集合的跨轮次一致性：每轮探测结束后据此轮全部结论计算可用成员集合与各成员生效权重，生效权重之和须与配置的满额权重和对应关系逐项可核验；当某成员在轮内状态变化时其生效权重须按该轮结束状态取值而非混用轮内旧值，集合与权重须与轮次号绑定并在界面与账本中一致呈现。
5. 实现状态账本的持久化写入与强制终止后的恢复：每完成一轮把探测记录、状态迁移、可用成员集合、生效权重与配置版本写入本地 SQLite 账本；进程被强制终止后重启只能依据已持久化的完整轮次恢复并继续推进，未完成轮次须标记为未知并要求重跑，不得声称能生成退出报告或恢复未持久化的在途探测。
6. 实现快照的版本识别与整体替换恢复：快照持久化配置版本、后端成员集合摘要、各成员状态与连续计数、慢启动进度、可用成员集合与最近轮次摘要；重新打开快照时须比较快照配置版本与成员集合摘要与当前磁盘状态，不一致须整体替换全部成员状态与权重而非增量合并，替换须列出被替换成员与被重置的连续计数。
7. 实现恢复后的一致性重放校验与不可复现报告：从快照恢复后按快照记录的配置版本与探测序列在后端模拟服务上重新执行若干轮，将每轮状态迁移、可用成员集合与生效权重与快照记录逐项比较，差异须定位到首个不一致的轮次、成员与字段并输出 E_REPLAY；若因后端注入行为或配置版本不一致导致不可复现，须在报告中说明具体依据。
8. 提供 Tkinter 交互界面与可重复演示脚本：界面展示后端成员状态、连续成功与失败计数、慢启动进度、可用成员集合与生效权重、轮次号与快照列表，渲染顺序稳定；附带确定性样本配置、后端行为脚本与演示脚本，顺序执行冷启动收敛、注入故障后的状态迁移、强制终止后恢复重放三个场景，每个场景输出含轮次号、迁移集合与校验结论的稳定报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
