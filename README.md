需要在一个空白工作区中实现一个面向本地反向代理配置管理场景的「增量下发与依赖失效诊断工作台」。该工作台管理一组上游目标、路由规则与监听端口的代理配置，接受运维人员提交的配置补丁（增删改路由、调整上游权重或健康阈值），并计算受影响的配置依赖子集，只对失效部分重新生成代理运行时快照，而不是整体重建。工作台需要维护配置版本链、依赖图与快照的对应关系，提供本地 HTTP 接口供客户端提交补丁、查询快照差异、触发依赖失效诊断，并通过 SQLite 持久化版本状态以支持进程重启后的恢复。核心难点在于：增量补丁可能跨越多条路由与上游，依赖失效必须沿着路由→上游→健康检查设置的引用链传播；同一上游被多个路由引用时，局部更新不能破坏未受影响路由的运行时行为；并发补丁提交与快照生成之间必须防止陈旧读与版本错配。

任务环境与准备：
安装 Python 3.11 或更高版本，并确保 pip 可用。
在空白工作区创建项目目录，安装 Flask、pytest、pytest-asyncio 等依赖，版本以兼容 Python 3.11 为准。
准备本地样本目录，包含配置文件、补丁样本与预期失效闭包诊断报告，不依赖外网或真实代理服务。
确保 Windows 防火墙允许本地回环端口访问，测试使用本地 HTTP 监听端口，端口号在样本中固定并可配置。
运行 pytest 前设置固定随机种子环境变量，保证测试可重复执行。

业务要求：
1. 实现配置模型与补丁解析：配置包含监听端口、路由前缀到上游组的映射、上游组的目标地址列表与权重、健康检查参数。补丁以 JSON 描述操作序列，每条操作指明操作类型、目标路径与操作数；解析时必须检测目标路径不存在、删除被其他路由引用的上游组、端口冲突等非法操作，返回业务码 E_BAD_PATCH 并拒绝整批补丁，不得部分应用。
2. 维护版本链与依赖图：每次成功应用的补丁生成新版本号，版本记录包含父版本、补丁摘要、受影响实体集合与快照摘要；依赖图须能回答给定实体（路由、上游组、健康检查参数）的传递依赖方与被依赖方，并持久化到 SQLite，重启后依赖图必须与最新版本一致。
3. 实现增量失效计算：应用补丁后，沿依赖图从变更实体出发计算失效闭包，闭包必须包含直接增量实体与所有传递依赖方，但不包含与变更无关的实体；对上游组权重的变更，仅使引用该上游组的路由失效，不得使同一监听端口下的其他路由配置失效。
4. 实现局部快照重建：只对失效闭包内的实体重新生成运行时快照片段，未失效实体复用上一版本快照片段；重建后的完整快照必须与从零重建的结果在语义上等价，可通过规范化序列化后逐字段比较验证；快照生成过程中若某个上游组目标列表为空，须返回业务码 E_EMPTY_UPSTREAM 且不产生新版本。
5. 实现快照差异查询：客户端可指定两个版本号查询快照差异，输出须包含监听端口、路由、上游组三类实体的新增、删除、修改明细，修改明细须按字段级展示变化；若请求的版本号不存在或较新版本号小于较旧版本号，返回 E_BAD_VERSION。
6. 实现并发补丁提交与快照生成的互斥：同一配置的快照生成期间到达的新补丁必须等待当前快照完成后再计算失效闭包，避免基于陈旧依赖图生成快照；并发补丁提交必须串行化版本号分配，保证版本号严格递增且无空洞；若补丁等待超时，须返回 E_CONFLICT 并保留其可重试语义。
7. 实现诊断工作台接口与重启恢复：通过本地 HTTP 提供提交补丁、查询版本链、查询依赖图、查询快照差异、查看失效闭包诊断报告的接口；诊断报告须列出每个失效实体的直接触发变更与传播路径。进程重启后须从 SQLite 恢复版本链、依赖图与最新快照摘要，且拒绝在恢复未完成前接受补丁。
8. 提供本地样本与可重复测试：样本包含至少三个监听端口、五个上游组与十个路由，覆盖共享上游组与健康检查参数变更场景；pytest 用例须在 Windows 离线覆盖非法补丁拒绝、增量失效范围正确、局部与全量快照等价、并发补丁串行化、重启恢复与版本差异查询，测试需在固定随机种子下可重复执行。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证增量补丁的依赖失效闭包、局部快照与全量重建等价、并发版本串行化及重启恢复，并附运行结果。
