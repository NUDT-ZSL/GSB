天文台观测数据管理平台的遥测工程师在长周期巡天观测期间，需要从本地工作台追溯单次曝光失败的原因：望远镜控制、相机读出与数据归档链路把每次曝光与归档作业串联成跨服务的调用链，遥测事件量随曝光批次增长，固定比例采样常常丢掉失败链路又说不清保留依据。平台由实现自带的确定性生成器按固定种子产出：若干曝光任务与归档作业的调用链定义（服务节点、上下游关系与操作名），按逻辑时刻交错的遥测事件流（Trace 标识、Span 标识、父 Span 标识、所属作业、事件时刻、状态与属性），以及采样策略声明（头部采样率、按错误状态与长耗时补充采样的阈值、按作业声明的保留期）。工程师需要从这份输入还原完整调用链树与关键路径，执行并解释采样决策，按作业核对保留量账目。

任务环境与准备：
在 Linux（WSL Ubuntu）上准备 Python 3 运行环境，仅使用语言标准库与 sqlite3、argparse，无需安装第三方包或配置外部服务。
新建工作目录，按命令行入口约定放置实现文件；样本由实现自带的确定性生成器按固定整数种子生成，不依赖真实望远镜、云账号或线上服务。

业务要求：
1. 实现确定性样本生成器与命令行入口：按固定整数种子产出多份观测工程，每份含调用链定义、遥测事件流与采样策略声明，并用命令行子命令分别输出原始工程、还原结果与账目；同一 seed 重放两次的全部输出必须逐字节一致。
2. 从遥测事件流还原 Span 父子关系与 Trace 上下文，跨事件重组出每次曝光任务与归档作业的完整调用链树，对父 Span 未到、重复到达或父标识缺失的事件做确定性处理并给出诊断，按 Span 时刻与耗时计算根到叶的关键路径。
3. 依据采样策略中的头部采样率与链路级采样标记，在链路入口执行确定性头部采样判定并把决策沿整条链传播，每条链路输出被保留或被丢弃的标记及依据（命中比例规则的链路序号、入口标记来源），不得对同一链路给出相互矛盾的决策。
4. 沿已保留链路检测错误状态与耗时超过阈值的 Span，触发末尾补充采样并记录补充保留理由与对应曝光作业；人工构造错误恰好出现在链路末端与耗时恰好等于阈值的样本，判定结果须与声明阈值严格一致且可复现。
5. 按 Trace 标识与观测作业检索关联调用链，输出跨服务的曝光失败根因定位（首个错误 Span 及其下游缺失节点）与关键路径耗时分解，检索结果按作业与时间区间过滤后再聚合，不混入其他作业的链路。
6. 按观测作业与时间区间统计采样后的遥测保留量（Span 数、链路数、属性字节量）并与声明的保留期账目比对，输出各作业保留量账目与超过保留期的标记，账目总额必须与逐链路采样决策聚合完全一致。
7. 在采样策略或保留期参数调整后，仅对受影响的链路重新判定采样与保留量，未受影响链路的关联结果与决策保持不变；局部重判结果须与整批全量重判结果逐项一致，调整前后差异以账目形式呈现。
8. 对 Span 树与采样决策做持久化：用 sqlite3 将已提交链路及其决策落盘，进程在处理中途被信号中断后重启能从已落盘状态续算，不重复计入已提交链路，恢复完成后与一次性完整运行的结果一致。

验收：
同一 seed 下 Span 树、关键路径与采样决策和独立参考还原器一致，账目与逐链路聚合吻合，参数调整后局部重判等于全量重判且中断恢复结果一致。
