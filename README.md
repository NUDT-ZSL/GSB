新工作区需开发一个 Windows 本地钢琴录音修复工作台。输入为 48kHz、16bit、单声道 WAV 片段；用户通过时间轴选区依次施加修复操作：谱减降噪、编辑包络幅度缩放、淡入淡出、基于 STFT 相位重建的局部修补；所有操作以参数化状态树表达。应用须支持完整撤销/重做，并在崩溃或强制终止后从持久化状态恢复到最近一次稳定状态。音频处理需产生可复现的确定性输出，撤销/重做后的听感与客观指标必须与对应状态一致。项目不依赖任何远程服务或真实录音资产，由本地合成钢琴样本驱动。

任务环境与准备：
Windows 10/11，Python 3.11 或 3.12，创建独立虚拟环境。
安装依赖：pip install numpy soundfile PySide6 pytest。
确认声卡非必需；所有音频处理在内存与磁盘完成，不依赖音频设备。
运行 pytest 前确保工作区目录可写，合成钢琴样本由演示脚本在本地产出。

业务要求：
1. 实现参数化音频状态树：每个节点记录操作类型、选区（采样点范围）、参数与父节点 ID；任意节点能重建其完整音频波形。音频处理使用 NumPy 向量化，STFT 窗长 2048、帧移 512，输出 WAV 为 48kHz/16bit 单声道，同一节点重复重建须逐字节一致。
2. 实现撤销/重做栈：分支切换、新操作截断重做分支、撤销上限 200 步；撤销后的波形必须与对应节点缓存或重建结果一致，重做分支中的节点不得被静默丢弃或复用错误父参数。
3. 将状态树、撤销/重做指针与音频缓存（按节点 ID 索引）持久化为工作区目录；缓存以内容哈希命名，节点写入与缓存落盘须原子完成，重启后能从持久化清单重建一致的工作区。
4. 区分受控退出与强制终止：正常退出时写完整清单与版本号；强制终止后重启只恢复到最近一次已提交稳定状态，未提交缓存作为孤儿回收，不得伪造退出报告或损坏既有节点。
5. 提供时间轴选区交互与逐操作应用：选区间不能重叠冲突，同一选区可叠加多操作；交互层只修改状态树，音频重建统一由重建服务触发，避免界面与处理逻辑互相耦合。
6. 实现降噪与局部修补的确定性计算：谱减使用固定噪声估计种子；修补基于选区内外沿样本的 STFT 幅度插值与相位重建，两次运行对同一输入与参数必须输出相同 16bit PCM 样本。
7. 定义业务错误码（E_SEL_RANGE、E_NODE_MISSING、E_CACHE_HASH、E_VERSION_CONFLICT 等）并覆盖异常链路：非法选区、缺失节点、缓存哈希不匹配、持久化版本冲突均返回 JSON 错误对象并保持工作区原状，不得部分写入。
8. 提供可重复演示：命令或界面一键生成合成钢琴样本、执行固定操作序列、撤销与重做、模拟强制终止并重启恢复，输出状态树快照与音频指标报告，供本地复核。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地合成样本验证状态重建、撤销/重做一致性、强制终止恢复与错误码返回，并附演示输出。
