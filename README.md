这个项目从一个全新的本地代码库起步，目录里既没有实现也没有样本文件，目标是为模型训练过程提供一个检查点管理组件，专门验证分片检查点在并行落盘、增量补丁与崩溃恢复这三条链路上是否能保持一致。所有输入都由随题交付的固定种子脚本在本地确定性生成，不依赖真实模型或外部服务；训练计划声明模型层清单、分片策略与保存计划，崩溃注入清单会在落盘或提交阶段强制终止进程。组件需要实现分片派生、并行调度、增量保存与恢复裁决，真正的难点在于并行预算约束下如何让分片调度与恢复后的拼接保持一致，增量保存与全量保存如何逐分片等价，以及强制终止后如何识别半提交状态而不产生孤儿分片。

任务环境与准备：
安装 Python 3.8+ 和 sqlite3。
使用确定性样本脚本生成本地训练计划、分片策略、检查点清单、崩溃注入清单与种子文件，不依赖网络或外部服务。
准备本地工作目录，所有分片文件与 SQLite 账本均存放于该目录。
使用子命令 save、restore、resume、status、verify 运行组件，并通过 SIGKILL 模拟强制终止。

业务要求：
1. 实现训练计划、分片策略与检查点清单的解析校验：模型层名唯一，形状维数为正整数，dtype 枚举合法，分片数不超过层总数，每分片字节上限与每轮并发上限为正整数，检查点版本号单调递增；对非法输入返回明确业务错误码，且不写入任何分片文件或清单。
2. 实现分片内容的确定性派生与内容寻址落盘：按层名与全局种子确定性生成每层参数摘要，分片按参数名哈希分配，分片文件以临时文件加重命名原子落盘；相同计划重复生成必须得到逐字节一致的分片与相同摘要，分片对象按摘要复用，不产生重复副本。
3. 实现并行落盘调度器：同一轮次内并发写分片，同时受每轮并发上限与每轮逻辑时间预算约束；预算耗尽必须放弃剩余未启动分片并记录放弃原因，严格区分预算内未启动、启动后失败与主动放弃三类结局，已启动分片不得被截断。
4. 实现基于注入逻辑时钟的增量补丁与命中复用：落盘与恢复的时间判定只依赖注入逻辑时钟毫秒值，不读取系统墙钟；增量保存只写变化的分片，复用未变化分片并记录命中依据，使增量保存结果与全量保存同一版本得到逐分片一致的文件与摘要。
5. 实现恢复路径的分片拼接一致性裁决：按清单拼接分片并逐分片校验摘要与层形状，同时以逐层独立重建作为对照路径；两者不一致或与参数摘要不符时，区分分片缺失、摘要不匹配与拼接顺序错误并返回不同业务错误码，恢复不得生成部分结果。
6. 实现强制终止后的恢复裁决：把落盘轮次水位、已提交分片清单、参数摘要、命中复用记录与逻辑时钟水位以事务原子写入 SQLite；进程在落盘或清单提交中途被强制终止后，恢复路径识别已提交分片与半提交清单，只重放未提交部分，不得重复写入或产生孤儿分片。
7. 实现多进程并发一致性与幂等提交：多个保存或恢复实例并行操作同一检查点时，通过 SQLite 事务与文件锁保证同一分片同一版本只被提交一次、同一检查点指针只被整体替换一次；重复提交相同分片或清单必须幂等，不得重复计数摘要。
8. 实现异常链路隔离与可重复命令行验证工具：分片缺失、摘要不匹配、版本回退、逻辑时钟回拨超容差、训练计划畸形分别映射到不同业务错误码并保留可诊断字段；提供 save、restore、resume、status、verify 子命令，verify 能重新生成全量分片并逐项比对所有存活检查点。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
执行训练计划解析、并行落盘、增量保存、强制终止、恢复拼接与 verify 命令，确认恢复结果与全量保存一致。
