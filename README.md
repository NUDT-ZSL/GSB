当前是空白工作区，需要从零实现一个本地数据库检查点与 WAL 回放组件，用于在确定性样本上复现 WAL 增量应用、检查点链路演进与崩溃后恢复裁决的完整流程，并支持两代检查点格式互操作。本地样本以目录形式给出：一组按序列号递增的 WAL 段（JSON 行格式，每行含事务号、表名、行键、操作类型、变更前后镜像、依赖的检查点代数与内容摘要哈希），以及两代检查点文件——v1 为单文件 JSON，记录检查点代数、已应用事务水位与各表行数摘要；v2 为分片 JSON 加 SQLite 元数据，记录检查点代数、绝对提交毫秒时间戳、每表行版本摘要、脏页映射与回放代数。组件需加载检查点与 WAL 增量，按事务序校验链连续性并应用到本地 SQLite 表上，维护行版本与来源事务号，在可注入逻辑时钟下判定 WAL 行是否越过失效检查点，支持生成新检查点并以整体替换方式切换检查点指针，同时记录每个事务的回放延迟供诊断。

任务环境与准备：
安装 Python 3.11 及以上版本，确认可执行 python 与 pip 命令。
安装 SQLite 3.35 及以上版本的命令行工具，用于检查生成的元数据库。
通过 pip 安装 numpy，并确认导入成功；不安装其他第三方依赖。
在工作区准备 samples 目录，放入两代检查点文件、WAL 段目录与固定随机种子生成的数据说明书。
确认工作区可写，且 SQLite 可创建本地数据库文件与临时文件。

业务要求：
1. 实现 v1 与 v2 两代检查点及 WAL 段的解析校验：v1 校验检查点代数单调、已应用事务水位为正整数、各表行数摘要与表结构对应；v2 校验分片文件哈希、SQLite 元数据中的回放代数单调、绝对提交时间戳为非负整数、脏页映射键存在；WAL 行须校验事务号严格递增、操作类型枚举、变更前后镜像与操作类型匹配、内容摘要哈希与行内容一致；非法输入返回明确业务错误码且不写入任何持久化状态。
2. 实现 WAL 链连续性与检查点依赖校验：按依赖的检查点代数把 WAL 段归入对应代数区间，识别断链、事务号回退与跨代乱序，构建可回放的有序事务序列；当某段声明的依赖检查点代数在当前链中不存在或已被新代数整体替换时判定该段失效，必须停在失效点之前并返回业务错误码，不得部分回放该段中越过失效点的行。
3. 实现从检查点出发的增量回放与行版本维护：按事务序把插入、更新、删除增量应用到 SQLite 表，维护每行的版本号、来源事务号、删除墓碑与回放代数；回放结果必须与从空库全量重放同一 WAL 链得到的结果逐行逐字段一致，并输出每个事务的回放行数、变更行键与内容摘要，供后续诊断与比对。
4. 实现注入逻辑时钟下的回放延迟计算与精度记录：每个事务的回放延迟由其绝对提交时间戳与注入逻辑时钟的回放时刻换算得到，v1 检查点仅存相对表示时须按声明的标度换算并记录换算标度、舍入方向与换算前原始值；滑动窗口延迟分位数按固定排序与插值规则计算，同一逻辑时钟序列下重放必须逐位一致，逻辑时钟回拨超过容差时返回业务错误码并保持已回放状态不变。
5. 实现检查点创建与整体替换的版本变化识别：按当前已应用水位生成新检查点并转换为 v2 格式登记，提交时以临时表加版本号整体替换当前检查点指针而非逐条覆盖；收到新检查点包时比较清单版本号、回放代数下限与各分片哈希，判定完整替换、增量追加或无需操作，代数回退必须被拒绝并记录拒绝原因。
6. 实现强制终止后的恢复裁决：把已应用水位、已提交事务标记、当前检查点指针、回放延迟记录与未完成事务登记以事务原子写入 SQLite；进程在回放或检查点提交中途被强制终止后，恢复路径依据持久化状态识别已提交但未更新水位的事务与半应用事务，只重做未提交部分并清理无引用临时产物，不得重复应用已提交事务或回退水位。
7. 实现多进程并发一致性与幂等应用：允许多个回放或恢复实例并行处理同一 WAL 链，通过 SQLite 事务与文件锁保证同一事务号同一检查点版本只被应用一次、同一检查点代数只被提交一次，重复应用同一 WAL 段结果必须幂等；读取方只能看到完整已提交事务的可见结果，不得观察到回放中间态或检查点指针与行状态不一致的状态。
8. 实现诊断命令行与可重复验证工具：支持 load、apply、checkpoint、resume、status、verify 子命令，status 以稳定排序 JSON 输出当前水位、检查点代数、已应用事务数、每表行版本摘要与延迟分位数，verify 校验持久化状态、检查点指针与行内容一致并在不一致时给出首个分歧事务与来源 WAL 段；使用固定本地样本连续两次运行输出逐字节一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
