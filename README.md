当前是空白工作区，需要从零构建一个面向本地 Windows 环境的服务网格流量治理工具，聚焦并行调度与资源预算。用户在本地 JSON 文件中声明一组服务与路由规则：每个服务包含若干本地回环上游实例（127.0.0.1 高位端口）、每实例的权重与熔断阈值，每条路由包含匹配前缀、目标服务、超时预算与重试次数。系统须在受全局并发预算与每服务并发配额约束下，把一批请求并行分发到各实例，按权重选择实例、在实例失败时按预算重试、在熔断触发时快速失败，并把治理结果写入本地快照文件与结构化日志。工具须能识别规则版本变化并整体替换路由表与统计快照，同时提供验证工具检查调度轨迹、配额占用与最终结果是否自洽。整个应用需在无外部依赖的情况下，用本仓库附带的本地模拟上游服务完成可重复演示。

任务环境与准备：
安装 Go 1.21 或以上并确认 go 命令在 PATH 中。
在工作区准备样本服务与路由 JSON 文件、本地上游模拟服务与演示脚本，全部位于回环地址与本目录内，不访问外网。
运行前确认回环高位端口空闲；演示脚本顺序执行冷启动轮次、规则变更后热轮次与故障注入轮次，并将快照与日志写入本地输出目录。

业务要求：
1. 实现服务与路由规则的加载与强校验：从本地 JSON 文件读取服务定义与路由表，校验服务名唯一、实例地址为回环字面量且端口在 1 至 65535、实例权重为非负整数且同一服务权重和不得为零、路由前缀以斜杠开头、超时预算与重试次数为整数；任一不合法须以 E_RULE 业务码整体拒绝加载并输出出错记录定位，禁止部分加载。
2. 实现受预算约束的并行请求调度器：依据全局并发上限与每服务并发配额并行分发请求，任一请求须携带单次尝试超时与总重试次数预算；配额耗尽时新请求排队且不得绕过配额，调度器须输出含请求标识、轮次、尝试序号、实例标识与实际耗时的调度轨迹，耗时以单调计数毫秒为观测口径。
3. 实现按权重的实例选择与熔断状态机：按实例权重以确定性算法选择实例，连续失败达到阈值后该实例进入熔断态并在冷却期内快速失败，冷却结束后允许试探；熔断或快速失败须记录触发实例、原因与时刻，重试不得改变单次尝试的成败语义，且同一输入多次运行须得到相同的选择序列。
4. 实现治理结果的验证工具：读取调度轨迹与结果快照，校验每个请求的最终结果是否与其尝试轨迹一致、并发执行是否从未超出全局上限与每服务配额、熔断态实例在冷却期内是否未被选中；不一致须以 E_VERIFY 业务码报告并稳定列出首个偏差请求标识与字段。
5. 实现规则版本识别与快照整体替换：每次请求轮次结束后依据当前规则版本生成结果快照，若轮次期间规则文件被修改则版本变化，快照须整体替换而非与旧快照增量合并；快照之间的版本差异与变更路由须可辨识，旧版本快照保留供对比，禁止新旧实例集合混用。
6. 实现强制终止后的恢复与状态校验：快照持久化进行中的请求预算、已用配额、熔断实例状态与已完成的请求轨迹，进程被强制终止后重启须依据快照恢复；未完成请求须标记为未知并要求重跑，不得声称能生成退出报告，恢复后对最近完成轮次重放校验不一致时返回 E_REPLAY。
7. 实现异常链路与业务码报告：支持以命令行参数注入规则文件损坏、模拟上游不可达、快照写入失败三类异常，分别以 E_RULE、E_UPSTREAM、E_SNAPSHOT 业务码报告并写入结构化日志；注入仅改变输入文件或参数，不得篡改源码，异常后系统须能继续处理后续轮次。
8. 提供可重复的本地演示与结果输出：附带本地 HTTP 模拟上游服务与样本规则文件，顺序执行冷启动轮次、规则变更后热轮次与故障注入轮次三种场景，每个场景结束后输出验证工具总结报告，报告含轮次号、规则版本、请求总数、成功与失败计数、熔断触发次数与配额峰值，且顺序稳定可重复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本与模拟上游验证并行调度、配额约束、熔断与快照整体替换及异常业务码，附运行结果。
