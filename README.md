某安全团队在 Windows 空白工作区启动一次从零开始的产品验证，为自研主机配置基线核查工具搭建离线漂移归因与处置裁决引擎。工作区没有既有代码与样本，全部输入由本地确定性脚本按固定种子生成，不依赖网络、账号或真实主机。业务对象是配置基线的两代证据快照：v1 为单文件扁平 JSON，按主机记录扁平配置键、相对采集秒数、观测值字符串、扁平严重度标记与漂移结论；v2 为分片 JSON 加 SQLite 元数据库，记录主机规范标识、配置项规范键（含点段与数组下标段）、绝对采集毫秒时间戳、证据代数、值归一化形式、证据摘要与墓碑标记。两代快照对同一主机同一配置项可能给出互相矛盾的漂移结论，运维人员需要把它们合并为同一份可追溯的漂移态视图，再依据处置窗口与冻结规则裁决哪些漂移需要立即处置、哪些处于观测宽限、哪些已被墓碑化撤销；处置窗口以整数秒声明，配置观测时刻以毫秒整数声明，两侧换算会引入量化误差，需要在判定余量上显式诊断。

任务环境与准备：
安装 Python 3.11 及以上版本，并确认 python 与 pytest 命令可用。
执行 pip install numpy pytest 安装 NumPy 与 pytest，SQLite 使用 Python 标准库 sqlite3 无需额外安装。
在工作区新建项目目录与样本输出目录，由题目交付的样本生成脚本按固定种子生成本地样本。
确认运行环境可写临时文件并支持文件重命名替换，无需网络、账号或外部服务。

业务要求：
1. 实现两代证据快照的解析与规范化层：v1 记录扁平配置键、相对采集秒、观测值字符串和扁平漂移结论，v2 记录规范配置键、绝对毫秒采集时刻、证据代数、值归化形式、摘要与墓碑标记；须校验主机标识与配置项键在各自快照内唯一、时间为非负整数、代数单调可解析，非法记录输出含快照代次与记录序号及稳定业务码的拒绝清单并继续处理其余记录。
2. 把两代快照合并为统一漂移态视图：v1 的相对采集秒须以样本声明的观测时钟为唯一基准换算为绝对毫秒，禁用系统当前时间；同一主机同一规范配置键按证据代数与采集时刻裁决权威来源，墓碑标记必须覆盖较早的非墓碑记录；当两代对同一键的观测值归一化形式或漂移结论冲突时输出 E_CONFLICT 并给出两侧来源代次与代数，不得静默取其一。
3. 实现观测值可比化：把 v1 的观测值字符串与 v2 的值归化形式按类型对齐（整数、布尔、枚举、区间、掩码），类型不一致或区间端点倒置分别给出独立业务码；同一配置项在多条证据上的观测值须能判定相等、包含或互斥三种关系，并保证该判定结论与证据到达顺序无关，比较结果须附观测依据来源。
4. 实现处置窗口与冻结规则的裁决：漂移首次越过基线上界的观测时刻与处置窗口比较，窗口以整数秒声明而观测为毫秒整数，须显式给出窗口端点换算的量化误差界；当误差界跨越窗口阈值时该漂移判为不确定并单列 E_WINDOW_AMBIGUOUS 且给出比确定超窗与确定在窗之间的判定余量，冻结标记命中的配置项即使超窗也不得被裁决为立即处置。
5. 实现漂移归因闭包：依据配置项之间的依赖声明把某配置项的漂移沿依赖边传播到依赖它的配置项，并沿主机到服务的归属映射归因到服务级根因候选；遇到依赖环返回 E_DEP_CYCLE 并列出环中配置项规范键；归因结果须区分主因与从因且排序稳定，与快照导入顺序无关。
6. 在 SQLite 中维护漂移裁决账本并支持增量证据批次：以主机规范键与配置项规范键为主键记录漂移态、处置结论、依据代数与判定水位，每轮合并在单事务内推进，前置校验失败不得改动账本；新批次到达时计算需重判的主机配置项集合，只重判受影响部分，且每条结论与从零全量重判逐字段一致。
7. 实现检查点演进与强制终止边界：按已合并批次水位与账本摘要持久化检查点到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放比对账本一致性以识别半写残留；快照版本变化（合并口径版本或值归化白名单变化）须整体重建而非增量续接；检查点与裁决报告均先写临时文件再整体重命名替换。
8. 交付可交互命令行与确定性本地验证：提供导入、裁决查询、归因导出、校验检查点四类子命令与可解析 JSON 报告，单份快照失败不得中断同批其他快照，并发度变化下结论与串行完全一致，退出码区分全部成功、部分失败与参数错误；附固定种子样本生成器与 pytest 测试覆盖冲突、量化不确定、依赖环与半写残留。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
