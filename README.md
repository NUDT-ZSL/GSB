本机工作区尚未产生任何代码或样本，团队需要从一个空白目录开始交付一个 Serverless 冷启动与并发控制的本地诊断引擎。业务围绕函数实例冷启动时的状态演进与恢复一致性展开：函数声明给出函数名、冷启动耗时配置、实例并发上限、预热窗口与适用容器规格；调用请求流按可注入逻辑时钟逐条给出调用序号、函数名、请求逻辑时钟、优先级、期望延迟与调用状态；冷启动策略以两代格式并存，v1 为单文件 JSON 记录相对生效秒数与扁平实例池参数，v2 为分片 JSON 加 SQLite 元数据库记录绝对生效毫秒、策略代数与失效墓碑。引擎需在每轮逻辑时间预算与全局并发冷启动上限约束下决定实例预热、调用分发与状态迁移，并支持强制终止后的恢复裁决。

任务环境与准备：
安装 Python 3.10 及以上版本，并使用 pip 安装 fastapi 与 uvicorn。
由固定种子脚本生成本地确定性样本至工作区 data 目录，不依赖网络。
准备可注入逻辑时钟参数，所有时间判定仅使用注入值。

业务要求：
1. 实现函数声明、调用请求流与两代冷启动策略快照的解析校验，确保函数名唯一、冷启动耗时配置为正整数、实例并发上限为正整数、请求序号严格递增且逻辑时钟为非负整数、v1 相对秒数为非负整数，并检查 v2 分片哈希与策略代数单调。
2. 跨版本合并两代冷启动策略并构建统一策略视图，当同一策略键在 v1 与 v2 同时存在时依据声明的逻辑时钟与策略代数裁决最新版本，逻辑时钟相同则按来源格式优先级裁决，合并后保留来源版本、原始时间表示与裁决依据。
3. 依据注入逻辑时钟推进函数实例状态机，使实例在待预热、预热中、就绪、忙碌、回收中之间迁移，状态迁移只依据注入逻辑时钟毫秒值与 SQLite 持久化状态裁决，不读取系统墙钟，保证相同输入重复运行得到逐位一致的状态序列。
4. 在每轮总逻辑时间预算与全局并发冷启动上限双重约束下调度待预热实例，预算或并发上限不足时按函数优先级与请求顺序稳定放弃剩余候选并记录放弃原因，并严格区分预算内未启动、预热中失败与主动放弃三类结局。
5. 为冷启动耗时与逻辑时钟换算建立定点账本，把耗时毫秒按声明定点标度换算为定点整数，登记每次换算的标度、舍入方向与被舍弃余量，并累计误差上界，当两个请求的等待时长差小于容差且调用顺序依赖该差值时标记为精度敏感。
6. 实现调用请求到就绪实例的确定性分发，请求只能分发给当前已就绪且并发余量充足的函数实例，无可用实例时按预热队列顺序触发冷启动，不得分发给预热中或回收中实例，并且分发结果须与单进程串行重放逐请求一致。
7. 支持冷启动策略快照的整体替换与增量补丁失效闭包，收到新策略包时比较版本号、策略代数下限、分片哈希与键集合摘要，判定完整替换或增量追加，版本回退必须被拒绝，替换须以 SQLite 事务整体切换指针而非逐条覆盖，并计算受影响函数的预热缓存闭包。
8. 实现强制终止后的恢复一致性，把函数状态、实例阶段、冷启动水位、定点账本、策略版本指针与逻辑时钟水位以单事务原子写入 SQLite，进程被 SIGKILL 后恢复路径依据持久化状态识别已提交与半提交状态，只重放缺失部分且不重复扣减预算。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
在本地确定性样本上验证函数冷启动状态演进、并发控制预算裁决与恢复后调用分发一致性。
