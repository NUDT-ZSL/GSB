某安全团队需要在离线 Windows 空白工作区从零开发一个配置漂移取证与裁决应用，用于对多台主机的配置基线快照与变更证据进行离线追溯。输入是一组本地确定性 JSON 证据文件：每条证据声明主机标识、采集序号、配置项路径（支持点路径与数组下标路径）、观测值、证据摘要与指向同主机前一条证据的链接标识；另有一份基线声明文件给出各主机在各配置项上的授权值域与生效区间。工具须重建每台主机每个配置项的观测链，判定漂移点（首次偏离授权值域的观测）、识别链断裂与证据被替换（摘要不匹配或链接指向不存在证据），并把跨主机同配置项的漂移归并为事件簇，输出可复核的 JSON 裁决报告与证据链图数据。核心难点是证据链状态与并发导入的耦合：证据可能乱序采集、跨主机并行导入、导入过程可能被强制终止，任何漂移点与事件簇的裁决都必须与按采集序号稳定排序后的串行执行完全一致，且恢复只能依赖持久化的检查点。

任务环境与准备：
安装 Python 3.11 或以上版本，确认 PATH 中 python 与 pytest 可用。
在空白工作区准备源代码目录、证据样本目录、基线目录与输出目录，不依赖网络与外部服务。
安装 pytest（可通过本地离线 wheel 或已预装环境），运行前确认 python -m pytest --version 成功。
样本与测试完全本地生成，观测序号、同步标记与基线生效区间均由样本显式给出，禁止使用系统当前时间作为真值。

业务要求：
1. 实现证据与基线声明的解析规范化层：统一点路径与数组下标路径为规范配置键，校验主机标识与采集序号组合的唯一性、证据链接目标存在性、基线值域端点格式，对非法条目输出含文件序号与业务错误码的拒绝记录并继续处理其余条目，单条非法不得中断整体解析。
2. 实现单主机单配置项的观测链重建：以证据链接标识串接同主机同配置项的观测序列，检测链断裂、自链接与环状链接并返回各自业务错误码且列出链上采集序号；链重建结论须与证据文件到达顺序无关，同采集序号重复投递按证据摘要一致则去重、不一致则判定为证据冲突。
3. 实现证据完整性与替换识别：按证据声明摘要算法（sha256 与 hmac-sha256）校验观测值与路径的规范化内容，摘要不匹配返回篡改业务码，摘要算法与声明位宽不匹配单独返回算法错误码；被判定篡改的证据须从链中排除并在报告中给出其采集序号与所属主机。
4. 实现漂移点与跨主机事件簇裁决：沿每条观测链比较观测值与基线授权值域，把首个越界观测判为漂移点并记录其授权区间来源；对同一规范配置键在多台主机上的漂移点按采集序号与主机标识稳定排序归并为事件簇，并要求值域端点含入语义与基线声明完全一致；整个裁决不得使用系统当前时间，时间相关判定只依据基线生效区间与证据中显式声明的观测序号。
5. 实现乱序证据的并发导入与结论等价性：支持证据文件以任意顺序并发导入，并发度可配置，最终漂移点集合、事件簇成员、链断裂清单与篡改清单必须与按采集序号稳定排序的串行执行完全一致；报告中证据与事件簇顺序须按稳定键归一化，不得依赖字典遍历或线程完成顺序。
6. 实现真实资源预算与并发边界：为整批裁决设置单文件真实耗时上限与待处理文件队列上限，超时以实测耗时判定而非人为延迟，队列超限须拒绝入队并返回可识别业务码且被拒文件计入报告；超时文件须跳过其专属证据链的后续处理而不影响其他主机，也不得声称已终止失控线程。
7. 实现检查点、版本变化重建与强制终止边界：按已完成文件标识与已累计证据链状态持久化检查点，进程被强制终止后只允许从最后一个完整检查点恢复且不承诺生成退出报告；检测到检查点结构版本或摘要算法白名单变化时须整体重建而非增量续接，检查点与裁决报告均先写临时文件再重命名整体替换，并发写入以文件锁串行化且锁冲突返回可识别业务码。
8. 实现裁决报告、证据链图与确定性本地测试：JSON 裁决报告含文件级结论、每主机每配置项观测链状态、漂移点、事件簇、业务错误码与出错序号，另输出证据链图数据文件（节点、链接边、篡改与漂移标记）；附样本生成器（显式记录发送端观测值与同步标记作为真值来源）与 pytest 测试，覆盖乱序、链断裂、环状链接、篡改、事件簇归并、队列拒绝、超时、并发度差异与中断恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证乱序并发导入与串行裁决等价、业务错误码、预算拒绝及检查点恢复正确性。
