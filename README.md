从一个空仓库出发，需要构建一个面向搜索推荐场景 CTR 与 CVR 联合预估的本地领域数据编辑与操作组件，并附完整示例。业务对象是本地确定性生成的三类样本能力：展示日志样本（JSONL，字段含 request_id、timestamp_ms、user_id、item_id、numeric_feats 键值对、categorical_feats 键值对、label_click、label_convert）；特征规范文件（v1 为竖线分列的行式且无字段名，v2 为带字段名的键值配置并引入逐特征缺失策略，v3 为结构化嵌套描述并引入特征默认值与版本化统计口径）；以及离线特征统计量快照。核心业务问题是：同一批样本与特征规范会以 v1、v2、v3 三种版本并存到达，需要互操作读取、双向迁移并在迁移中记录补全与丢弃；特征规范或统计量以更高版本到达后，必须精确识别受影响的样本与派生特征，复用未受影响的上游缓存，仅重算受影响的样本特征与 CTR/CVR 打分明细；任意一次打分必须可追溯回当时所用的特征规范版本、统计量快照与缓存键，依赖版本已变化而仍被引用的旧产物必须被拒绝。所有数据与统计量均由固定种子在本地确定性生成，不依赖任何外部服务、真实账号或线上站点。

任务环境与准备：
安装 Python 3.11 或 3.12，并在空仓库根目录创建虚拟环境：python -m venv .venv 后激活 .venv\Scripts\activate。
安装依赖：pip install "numpy>=1.26,<2.1" "pyarrow>=15,<18"（PyArrow 仅用于本地列式样本读写，全部数据本地生成）。
准备本地确定性样本：用固定种子生成展示日志 JSONL、v1/v2/v3 三份特征规范样例与离线统计量快照，样例数量与字段在示例脚本中显式声明并随仓库提交。
所有命令在 Windows 命令提示符或 PowerShell 中执行，示例脚本输出 JSON 报告并写入本地工作目录，运行前无需网络与外部账号。

业务要求：
1. 实现 v1、v2、v3 三种特征规范格式的读取器，按格式头或字段集分派解析路径；未知版本返回 E_VERSION_UNSUPPORTED，竖线字段数不符、键名缺失、必填字段缺失或数值不可解析返回 E_FORMAT_INVALID 并指明行号与字段，读取结果须携带版本号、原始行摘要与内容校验和。
2. 实现 v1 升级到 v2、v3 与 v3 降级到 v2、v1 的双向迁移器，把任意版本规范化为统一的内部特征规范表示；升级时补全缺失策略、特征默认值与统计口径并逐项记录补全来源；降级时对 v1 无法表达的逐特征缺失策略与默认值按显式声明的丢弃或展平规则处理并输出丢弃记录；迁移补全与丢弃记录须可重放出同一内部表示。
3. 实现确定性的样本解析与特征装配阶段：按 request_id 升序、再按 timestamp_ms 升序处理样本，数值特征按内部规范做标准化、类别特征按固定规则编码、交叉槽位按内部规范展开，缺失值按当前版本声明的策略填充；同一输入、同一内部规范与同一种子下必须逐字节产出相同特征矩阵与装配摘要，同分时按 request_id 升序打破平局，重复 request_id 返回 E_DUP_REQUEST。
4. 实现 CTR 与 CVR 联合打分与特征统计量累积：由装配特征与离线统计量按显式声明的打分口径计算点击与转化概率，逐样本记录各特征项贡献与统计量版本，使最终分数可由逐项明细独立重算一致；须支持可配置的严格比较与容差带比较两种概率门限策略及次正规数保护，保证恰好落在门限附近的样本在重复运行下判定不被舍入翻转，门限策略或容差非法分别返回 E_THRESHOLD_INVALID 与 E_TOLERANCE_INVALID。
5. 实现特征装配、打分与统计量累积三类节点的内容寻址缓存：每类产物附带内容哈希落盘到本地目录，缓存键须纳入样本内容哈希、内部规范版本、特征规范内容校验和、统计量快照版本与上游产物哈希；键相同必须复用快照、键不同必须重算，并提供入口按 request_id 查询键组成与产物哈希以核对复用是否真实发生。
6. 实现特征规范或统计量以更高版本到达、或某样本标签被修正时的定向失效传播：区分仅概率门限变化（只影响打分与判定）、仅统计量快照更新（影响打分及下游）、特征规范版本提升（影响装配及全部下游）三类情形，计算受影响节点与受影响 request_id 集合，复用未受影响上游产物，仅重算受影响后缀；须输出本次重算节点清单、重算与复用样本集合，并保证增量结果与全量重算逐字节一致。
7. 实现打分结果追溯与过期结果拒绝：每条 CTR/CVR 打分须记录所用缓存键、特征规范版本、统计量版本与节点路径，可按该记录重放出相同概率、贡献明细与门限判定；当缓存键所依赖的任一版本已变化而结果仍来自旧键时返回 E_LINEAGE_BROKEN 并指出 request_id 与失效版本，禁止静默使用旧结果。
8. 实现快照版本识别与整体替换、并发提交控制、资源上限及跨模块一致性自检：规范快照、统计量快照与打分结果快照各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符返回 E_CACHE_CORRUPT；同一时刻只允许一次增量提交生效，并发冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待；为驻留特征矩阵内存与并行重算节点数设可配置上限，超限返回 E_RESOURCE_LIMIT 或降级并标记降级类别；自检校验三类节点处理的 request_id 集合一致、缓存键与产物哈希互相可核对、重算与复用集合无交集且并集覆盖全部受影响集合，并提供命令行示例输出迁移记录、装配摘要、逐项贡献、失效报告与业务码。
