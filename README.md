在空白工作区从零实现一个本地键值存储引擎的索引与过期语义管理组件，核心要求是支持多种历史版本的快照格式互操作，并在升级与降级查询中保持过期键的可见性语义一致。本地样本提供两组快照文件：v1 格式使用单文件 JSON，记录键、值、过期时间戳与简单的线性索引；v2 格式使用分片 JSON 加 SQLite 元数据，索引为内存哈希表并记录索引版本号与键的墓碑标记。引擎需读取并合并不同版本快照，建立统一的内存索引，支持按精确键、前缀与过期状态查询，同时实现快照整体替换时的版本变化识别与过期键清理策略。过期判定依赖本地注入的逻辑时钟，所有时间戳以整数毫秒表示，键的过期语义包含“已过期但保留墓碑”与“已过期可物理删除”两种模式，不同版本快照的默认模式不同，互操作时必须显式迁移并记录迁移决策。整个过程在 Windows 本地文件系统上完成，不依赖网络服务或外部数据库实例。

任务环境与准备：
安装 Python 3.11 或以上版本，确保标准库 sqlite3 与 json 可用，无需第三方包。
在空白工作区创建项目目录，准备本地样本：v1 单文件 JSON 快照若干份，v2 分片 JSON 加 SQLite 元数据库若干份，覆盖键重叠、墓碑、过期边界与格式错误用例。
准备固定逻辑时钟序列样本文件，所有演示与验证均从该文件注入时钟值，不读取系统时间。
确认 Windows 本地文件系统支持临时文件加 rename 的原子写入语义，SQLite 数据库文件位于项目本地目录。

业务要求：
1. 实现 v1 与 v2 两种快照格式的解析器：v1 读单文件 JSON，校验键值字段、过期时间戳整数类型与线性索引长度一致性；v2 读分片 JSON 与 SQLite 元数据库，校验分片哈希、索引版本号、墓碑标记与逻辑时钟快照；格式错误必须返回明确业务错误码（如 E_V1_FORMAT、E_V2_SHARD_HASH、E_INDEX_VERSION）且不修改任何持久化状态。
2. 实现跨版本快照合并与统一内存索引构建：同一键在 v1 与 v2 中同时存在时，按快照声明的逻辑时钟序号裁决最新版本，若序号相同则依据来源优先级；合并时必须保留每个键的来源版本、原始过期时间戳与墓碑状态，并生成可追溯的合并决策记录。
3. 实现过期语义的模式迁移：v1 快照中的键默认“过期即可物理删除”，v2 快照中的键默认“过期但保留墓碑”；加载旧版本快照进入新版本索引时必须显式执行模式迁移并记录迁移映射，查询时按迁移后的统一语义返回键的可见性、逻辑删除或物理不存在状态，不得静默改变已有键的过期行为。
4. 实现快照整体替换的版本变化识别：当收到新的快照包时，比较包内清单版本号、逻辑时钟下限与各分片哈希，判定是完整替换、增量追加还是无需操作；整体替换必须识别版本回退并拒绝或按策略降级，不得把旧版本快照覆盖到更新版本之上而不留审计记录。
5. 实现精确键、前缀与过期状态三类查询：查询结果以稳定排序 JSON 输出键、值、来源版本、过期状态与墓碑标记；前缀查询需利用内存索引避免全量扫描，过期状态查询需区分“活跃”“已过期保留墓碑”“已过期可删除”三种结果，边界时间戳（恰好等于过期时间）按显式定义处理。
6. 实现逻辑时钟注入与过期判定一致性：所有过期判定基于可注入的逻辑时钟毫秒值，不得读取系统墙钟；同一逻辑时钟下重复查询必须得到完全一致结果，逻辑时钟回拨或跳跃超过阈值时返回业务错误码并保持索引状态不变。
7. 实现持久化状态与恢复：将合并后的索引版本、迁移决策、快照替换审计记录与清理水位线原子写入 SQLite；进程被强制终止后，依据持久化状态识别未完成的合并或替换操作，恢复时只重放未提交步骤，不得出现索引版本与审计记录不一致。
8. 实现命令行接口与可重复演示：支持 load、merge、query、replace、status 子命令；status 以 JSON 输出当前索引版本、各来源快照版本、迁移决策数量与墓碑键数量；使用固定本地样本连续执行两次完整流程，输出必须逐字节稳定。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地 v1/v2 样本快照验证合并、过期语义迁移、版本回退拒绝与恢复后查询结果稳定。
