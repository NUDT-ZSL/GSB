团队决定先做一个独立原型：在 Windows 本地空工作区实现一个离线代码签名时间戳审计组件，用于判定一批已签名构件在时间戳权威机构（TSA）签发令牌多次轮换后，构件签名时刻能否被可信地锚定。工作区只有随题交付的固定种子样本生成脚本，没有任何既有代码，全部样本由该脚本确定性生成，不依赖真实 TSA、网络或账号。样本包含构件签名记录（构件标识、签名值摘要、本地签名时刻整数毫秒、绑定的时间戳令牌标识）、时间戳令牌声明（令牌标识、签发毫秒时刻、覆盖的签名值摘要、令牌代的签发者标识、令牌有效期起止）以及两代 TSA 信任快照：v1 为单文件 JSON，记录相对生效秒、扁平 TSA 签发者标识集合与扁平撤销列表；v2 为分片 JSON 加 SQLite 元数据库，记录规范签发者标识、绝对毫秒注册时刻、TSA 代数、撤销原因码与墓碑标记。组件须合并两代信任快照，判定每个令牌的签发者是否在令牌签发那一刻被信任，再据以锚定构件签名时刻，并输出可复现的审计账本。

任务环境与准备：
在 Windows 本地安装 Python 3.11 及以上版本，并确保 python 与 pip 可在命令行调用。
安装 SQLite 3 命令行工具用于账本抽查，Python 标准库 sqlite3 模块即可满足实现需要。
安装 pytest：在项目根目录执行 pip install pytest。
工作区为空目录，运行随题交付的固定种子样本生成脚本生成构件签名记录、时间戳令牌声明、两代 TSA 信任快照与真值文件。
执行 pytest 运行本地测试集，样本与测试均不依赖网络、真实 TSA 或外部账号。

业务要求：
1. 实现构件签名记录、时间戳令牌声明与两代 TSA 信任快照的严格解析规范化层：校验构件标识与令牌标识唯一、签名值摘要为合法十六进制且长度符合声明算法、令牌签发时刻与有效期起止为整数毫秒且起小于止、令牌代与 TSA 代数为非负整数；v1 相对生效秒为非负整数；对非法记录输出含来源类别、记录序号与稳定业务码的拒绝记录并继续处理其余记录。
2. 把 v1 与 v2 信任快照合并为统一 TSA 信任视图：v1 的相对生效秒须以样本内声明的观测时钟为唯一基准换算为绝对毫秒，禁止使用系统当前时间；同一规范签发者标识按 TSA 代数与注册时刻裁决权威来源，墓碑标记必须覆盖较早的非墓碑记录；签发者集合任一增删、TSA 代数变化或撤销条目集合变化均视为快照整体替换并记录依据代数；两代对同一签发者的可信状态或撤销结论不一致时须给出冲突条目而非静默择一。
3. 实现令牌签发时刻的可信性判定：对每个令牌，在统一信任视图中取其签发毫秒时刻所对应的生效快照代数，校验该令牌代声明的签发者在该时刻被信任、令牌签发时刻落在令牌有效期窗口内、且撤销条目的生效时刻晚于令牌签发时刻；令牌签发时签发者尚未注册、撤销早于签发、令牌代与声明签发者不匹配须分别返回稳定业务码并给出依据代数与令牌代。
4. 实现构件签名时刻的锚定裁决：构件的本地签名时刻只在存在一个可信令牌覆盖其签名值摘要且该令牌签发时刻不晚于本地签名时刻时方被采纳为锚定时刻；无令牌覆盖、令牌不可信、令牌签发晚于本地签名时刻、同一签名值摘要被多个令牌覆盖须分别给出明确结论，多令牌覆盖时须按令牌签发时刻与令牌代稳定排序给出主锚定令牌与备选清单。
5. 实现撤销传播与重锚定闭包：当某签发者被撤销或某令牌代被墓碑化时，沿签发者到令牌代到时间戳令牌到构件签名的依赖关系计算受影响的令牌集合与构件集合，受影响构件须回退为未锚定或改用备选令牌重新锚定；遇签发者与令牌代之间的环状引用返回稳定业务码并列出环中标识；传播结论必须与两代快照与签名记录的到达顺序无关，时刻或代数相同时按规范标识稳定排序确定次序。
6. 在 SQLite 中维护审计账本并实现快照增量到达后的失效闭包：以构件标识与签名值摘要为主键记录锚定结论、主锚定令牌、依据 TSA 代数与判定水位，每轮裁决在单事务内推进，前置校验失败不得改动账本任何状态；新快照或签名记录批次到达时沿依赖关系计算需重锚定的构件集合，仅重锚定受影响部分，并要求结论与从零全量重锚定逐字段一致，不一致时返回可识别业务码。
7. 实现检查点演进与强制终止后的恢复边界：按已处理批次水位与账本摘要把检查点持久化到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放比对账本一致性以识别半写残留，进程被强制终止后不承诺生成退出报告；检测到检查点结构版本或信任合并口径版本变化时须整体重建而非增量续接；检查点与审计报告均先写临时文件并在校验内容可解析后整体重命名替换，同一工作目录并发写检查点须以文件锁串行化且锁冲突返回稳定业务码。
8. 交付可交互命令行与基于同步标记的确定性本地验证：提供导入快照、锚定裁决、导出审计报告、校验检查点四类子命令，报告为可解析 JSON 并含构件级锚定结论、主锚定令牌、业务码、依据代数与重锚定闭包；样本生成器在真值文件中显式写入每条签名记录与令牌的发送端原始时间表示与同步标记，验证只依据同步标记与组件输出比较；单份输入解析失败不得中断同批其他输入，退出码区分全部成功、部分失败与参数错误；附 pytest 测试集覆盖信任冲突、墓碑覆盖、令牌不可信、多令牌覆盖、撤销重锚定、并发导入与强制终止恢复等情形。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

用本地样本验证两代信任快照合并、令牌签发可信性、签名时刻锚定与撤销重锚定闭包，并核对中断恢复后账本一致。
