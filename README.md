交付从新建的代码库开始，需要在 Windows 上从零实现一个本地审计事件落盘组件，以可集成库加完整示例交付。业务对象是审计事件的持久化写入：本地 JSON 样本给出事件流（事件序号、租户、事件类别、载荷摘要、注入逻辑时钟毫秒戳、幂等键）、租户落盘配额声明（每租户每日逻辑窗口内的字节配额、单事件最大字节数、超配额动作）以及落盘策略配置（每轮写入条数上限、每轮逻辑时间预算、写入重试基数与上限、逻辑时钟步进）。组件需把事件按序追加到 SQLite 审计表并维护每租户的字节账本，在配额逼近日志轮转边界时裁决拒绝、归档还是允许超额写入，并保证在进程被强制终止与多进程并发写入后账本守恒、事件不重不漏。

任务环境与准备：
安装 Python 3.11 或以上版本（Windows 官方安装包），在命令提示符中确认 python --version 可用。
创建虚拟环境：python -m venv .venv，然后执行 .venv\Scripts\activate。
安装依赖：pip install pytest。sqlite3 为 Python 标准库，无需额外安装。
在新建代码库中创建 samples 目录，放入事件流 JSON、租户配额声明 JSON 与期望落盘摘要文件；所有样本内容由题目要求确定，不依赖网络、真实账号或外部服务。
在工作区根目录预留 audit 目录用于 SQLite 账本文件与示例输出，所有路径均使用 Windows 本地路径。

业务要求：
1. 实现事件流、租户配额声明与落盘策略的解析校验：事件序号严格递增且唯一、租户名与事件类别枚举闭合、载荷摘要与载荷内容一致、逻辑时钟为非负整数、字节配额与单事件最大字节数为正整数、重试基数与上限合法；非法条目须返回明确业务错误码且不写入任何持久化状态。
2. 实现基于注入逻辑时钟的配额窗口切分与账本重建：按每租户的逻辑日窗口边界把事件唯一归属到窗口，窗口边界只依赖注入逻辑时钟毫秒值，不读取系统墙钟；进程启动或恢复时须能从已落盘事件重建每租户每窗口的已用字节账本，重建结果与增量累加结果逐字段一致。
3. 实现租户字节配额的落盘裁决与超配额动作执行：每事件落盘前比较已用字节加本事件字节与配额及单事件上限，分别裁决允许、拒绝、归档或允许超额，超单事件上限与超窗口配额须使用不同业务错误码；裁决须输出参与比较的账本快照、剩余字节与首个触发约束，且同一事件序列重复运行裁决逐位一致。
4. 实现写入重试与幂等键去重：落盘失败按重试基数与当前尝试次数计算下一次可尝试逻辑时刻并施加确定性抖动与上限，尝试耗尽转入待人工处理并记录原因；同一幂等键重复提交必须幂等且不得重复计入字节账本，已拒绝事件不得因重试进入已落盘集合。
5. 实现每轮写入条数上限与逻辑时间预算下的批量落盘调度：同一轮次内按租户分组批量写入，同时受每轮写入条数上限与每轮逻辑时间预算约束；预算耗尽须停止本轮并保留未写入事件，区分预算内未写入、写入后失败与主动放弃三类结局，已启动写入不得被事后标注为超时。
6. 实现持久化账本与强制终止后的恢复裁决：把事件水位、每租户每窗口已用字节、待人工处理队列、幂等键记录与逻辑时钟水位以事务原子写入 SQLite，每批提交识别版本变化并整体替换当前账本指针；进程在写入或账本提交中途被强制终止后，恢复路径须识别已提交事件与半提交记录，只重做未完成部分且不重复计入字节。
7. 实现多进程并发一致性与业务错误码链路：多个写入实例并行处理不同租户时，通过 SQLite 事务与文件锁保证同一事件序号同一版本只落盘一次、同一租户窗口字节账本不被并发超扣、同一幂等键只物化一次；账本摘要不匹配、配额配置版本回退、幂等键冲突、逻辑时钟回拨超阈值分别映射到不同业务错误码并保留租户名与窗口标识。
8. 提供可重复命令行接口与验证工具：支持 load、write、replay、resume、status、verify 子命令，status 以稳定排序 JSON 输出每租户每窗口已用字节、剩余配额、待人工处理数与逻辑时钟水位，verify 校验已落盘事件集合、账本重建值与事件摘要逐项一致，并附完整示例清单与运行步骤。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
