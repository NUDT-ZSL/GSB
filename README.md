当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向跨语言检索前链路的本地查询改写与索引调度工作台，核心业务问题是查询改写规则、跨语言桥接资源与倒排索引三者格式在版本演进下的互操作，以及改写结果与检索打分的一致性。业务对象是本地确定性生成的多语言文档集合与查询集合：文档 JSONL 字段含 doc_id、doc_lang、terms（term 与词频）与 doc_len；查询 JSONL 字段含 query_id、query_lang、terms、top_k；另有三套并存的改写规则书写形式（v1 无字段名竖线行式、v2 带字段名行式、v3 结构化 JSON，三者表达能力不同），以及一份跨语言词项桥接资源（语言对方向表、词项桥接表、置信度与版本号）。工作台需完成查询改写展开、多语言桥接、倒排索引构建与打分检索整条链路，并对外提供诊断视图。核心矛盾在于：规则格式升级或降级会丢失或补全字段；桥接资源版本提升会使部分已展开候选失效；索引快照与规则快照必须协同版本化，否则查询侧可能对旧索引使用新桥接，导致分数不可解释。

任务环境与准备：
安装 Python 3.11 及以上版本，并用 pip 安装 NumPy，确认 python -c "import numpy" 可在本地成功执行。
准备本地样本生成脚本，以固定随机种子生成多语言文档集、查询集、三套改写规则书写形式与跨语言桥接资源，所有样本与快照目录均位于工作区本地路径。
确认可用的本地进程池与文件写入权限，准备可重复触发的强制终止与重启流程用于恢复验证，不使用容器或任何外部服务。

业务要求：
1. 实现 v1、v2、v3 三种查询改写规则的读取器，按版本头或字段集分派解析路径；未知版本返回 E_VERSION_UNSUPPORTED，行字段数不符、必填字段缺失或数值不可解析返回 E_FORMAT_CORRUPT；解析器须给出源行定位，同一规则集在同一配置下读取产物逐字节一致。
2. 实现 v1 到 v2、v2 到 v3 的双向互操作迁移器：升级时补全桥接置信度权重、最大展开深度与启用标记并逐项记录补全来源；降级时对 v3 中 v1 或 v2 无法表达的嵌套条件与多目标语言声明按显式展平或丢弃规则处理并输出丢弃明细；迁移后须可回读且往返在可表达字段上一致。
3. 实现确定性的查询改写展开与跨语言词项桥接：按规则匹配查询词项，用桥接表把源语言词项展开为目标语言候选词项，每候选携带桥接置信度，受可配置最大候选数与置信度下限约束；展开候选按置信度降序、同分按目标词项字典序排序，同一输入与同一规则及桥接版本下逐字节一致。
4. 实现多语言共享倒排索引的构建与分区：文档按语言分入分区，分区内按 doc_id 升序与 term 字典序生成倒排表并记录词频与文档长度统计；桥接资源版本变化时须识别受影响分区集合，未涉及新版本词项的分区不得被判为受影响，构建产物须可为每条 posting 反查来源文档。
5. 实现桥接置信度参与的打分与 top-k 检索，并保证与未改写基线可比：同一文档被多个候选词项命中时按显式声明规则合并贡献，输出每文档每候选词项的贡献明细使最终分数可由明细独立重算；须同时输出未改写直接检索的基线分数与改写后分数的差谱，用于判断改写是否引入不可解释增益。
6. 实现索引分区快照、规则快照与桥接资源快照的协同版本化：三者各携带单调递增版本号与内容校验和，提交记录须交叉核对三者版本；检测到任一版本号或校验和变化时必须整体替换旧快照而非增量修补，查询侧切换须原子生效且不得读到新旧桥接混用的统计量，版本不匹配返回 E_VERSION_SKEW。
7. 实现强制终止后的分区级恢复：重启时读取已提交分区快照，从未提交分区起点重建，已提交分区不得重算；若中断期间桥接资源版本已变化，须按新版本重新计算受影响分区集合，未被新版本涉及的分区快照仍可复用；恢复后的检索结果须与不间断完整运行逐字节一致。
8. 实现资源预算准入与跨模块一致性自检，并提供可交互诊断工作台：为倒排 posting 总数、解码驻留内存与并行重算分区数设可配置上限，超限时返回 E_RESOURCE_LIMIT 或降级为流式分区打分并标记降级类别；自检校验规则展开所用桥接版本与索引分区版本在提交记录中可核对、贡献明细可重算分数、复用与重算分区集合无交集且并集覆盖受影响分区，不一致返回 E_INCONSISTENT 并指出类别。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
