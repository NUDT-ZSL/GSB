在空白工作区构建一个面向本地确定性合成图像的专业 OCR 文字检测与识别交互工作台，用于反复调整检测与识别参数并查看版面分析结果。输入为一个本地样本目录：若干程序生成的 PNG 版面图像（固定分辨率，由固定种子在浅色背景上绘制横排文字条带、字符块与噪声，字符由内置点阵字模渲染，每张图附一份版面真值 JSON 记录每个文字行与字符的整数像素边界框）；一份检测配置 JSON（滑窗尺度列表与步长、二值化阈值、行合并的投影间距与连通条件、最小字符高度、候选框得分阈值、线程池并发数、交互延迟预算毫秒、快照提交间隔）；一份识别配置 JSON（内置字模匹配的模板集合与匹配度量、置信度阈值、行内切分的最小字符宽度、同分决断顺序）。用户通过交互命令反复调整检测与识别参数，后台执行确定性检测、行聚合、字符切分与模板识别流水线，必须在交互延迟预算内返回当前可用的最新识别结果摘要，且任意编辑序列之后的最终逐行逐字符结果必须与从零按最终参数完整执行得到的结果一致。

任务环境与准备：
确认 Windows 上可用 Python 3.10 及以上解释器，创建独立虚拟环境。
安装 Pillow 与 NumPy（版本以 pip 解析到的兼容版本为准），不引入任何 OCR、深度学习框架或外部模型服务依赖。
在本地样本目录准备程序生成的 PNG 版面图与配套版面真值 JSON，字符使用内置点阵字模渲染，生成脚本与随机种子随工作区提供以保证确定性。
准备检测配置 JSON、识别配置 JSON 与交互命令流文件，交互命令只通过参数注入异常，不修改源码。
运行前确认无网络依赖、无真实站点或账号依赖，全部数据与测试均在本地完成。

业务要求：
1. 实现图像与真值加载层：扫描输入目录下所有 PNG 版面图，校验容器头、尺寸与像素模式，解码为 uint8 灰度数组；同步读取版面真值 JSON 并校验文字行与字符边界框为整数、位于图像范围内且同行字符框纵向重叠；无法解码、尺寸不符或真值越界时分别输出 E_IMAGE_DECODE、E_IMAGE_SHAPE、E_TRUTH_OUT_OF_RANGE 业务码并记入失败清单，其余图像继续处理。
2. 实现确定性文字检测：按检测配置的滑窗尺度列表与步长计算窗内笔画密度与边缘强度特征，与二值化阈值比较得到候选文字块，再依据投影间距与连通条件将候选块聚合为文字行候选，输出每个候选行的整数边界框、内部分块计数与得分；所有坐标为整数像素并做边界裁剪，检测链路禁止随机源，同一图像与同一配置在任意运行中输出必须逐字段一致。
3. 实现字符切分与模板匹配识别：对每个文字行候选沿水平投影做字符切分，切分受最小字符宽度约束，过窄片段按配置与相邻片段合并而不是直接丢弃；切出的字符块与内置字模模板按配置的匹配度量逐一打分，取最高分模板为识别结果，同分时按配置的固定决断顺序确定，输出每字符的整数边界框、识别结果字符、得分与次优模板得分。
4. 实现基于内容指纹的增量失效判定：为检测、行聚合、字符切分、模板识别各阶段产物计算由图像内容指纹、检测与识别参数指纹、字模模板版本号派生的缓存键；当用户修改检测阈值、滑窗参数、行合并间距、匹配度量或置信度阈值时，仅使受影响阶段及其下游失效并纳入重算集合，未失效阶段必须直接复用产物且不得重新执行该阶段计算；复用与重算阶段清单须在报告中体现。
5. 实现交互延迟预算内的响应语义：每条交互命令触达后，在配置的交互延迟预算毫秒内优先返回最近一次已完成的最新结果摘要（已完成行数、当前逐行识别文本、受影响行清单与进度），预算内无法给出最新参数下结果时返回带 E_INTERACT_BUDGET_PENDING 的中间摘要而不阻塞后续命令；预算耗尽不得以线程超时描述为已终止计算，后台计算的可处理退出须走状态持久化路径。
6. 保证多次交互后增量结果与全量执行结果一致：从任意初始状态执行任意编辑序列，每次命令后增量运行得到的逐行识别文本、逐字符边界框与得分、行候选顺序、复用清单与诊断摘要，必须与从空白工作区按相同最终图像与最终配置一次性全量执行的结果逐字段一致；一致性比对须以从零全量执行结果为真值来源，并以同一同步标记（全局版本号）对齐两侧输出。
7. 实现阶段快照整体替换与恢复一致性：各阶段以临时文件加原子替换方式提交快照，快照含阶段名、配置哈希、字模版本号、已完成图像列表、产物摘要与全局版本号；快照写入须识别版本变化并整体替换而非逐文件覆盖；收到可处理的退出信号时完成当前阶段快照与进度记录后以整数退出码 0 退出；进程被强制终止后重启仅依据已完整替换的快照恢复并输出恢复点版本号，不得承诺强制终止后生成退出报告或完成中的行结果。
8. 实现并发执行一致性与诊断报告输出：使用线程池并发执行检测与字符识别，最大并发数取自配置，每个任务携带由文件名、行序号与阶段名派生的稳定排序键，无论线程调度顺序与并发度如何，最终图像顺序、行顺序、字符顺序、复用清单与失败清单顺序必须与单线程按文件名顺序执行一致；每次完整运行生成 JSON 诊断报告，含逐行识别文本、逐字符边界框与得分、缓存命中与失效清单、各命令响应耗时与是否超预算、快照版本号、业务码与失败清单，报告以临时文件加原子替换写盘。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地合成版面图验证检测识别结果、增量与全量一致性、预算响应与恢复语义，附运行报告。
