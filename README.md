当前是空白工作区，需要从零构建一个面向本地 Windows 环境的 DNS 解析与缓存服务，作为可交互的专业应用与可重复演示。服务在回环 UDP 与 TCP 端口接收 DNS 查询，按本地权威区完成解析，并把结果写入带 TTL 的缓存。上游有两种确定性数据源：RFC 1035 线格式报文样本与本地 JSON 简化区记录，两者须归一为同一内部记录模型。服务不访问真实域名或线上解析器，而是把查询转发给本地 TCP 回环上的上游解析器子进程，并校验上游返回报文的应答链是否与本地缓存和权威区一致。系统需处理压缩指针防护、大小写折叠、CNAME 链、TTL 递减、转发应答校验与并发查询下的缓存一致视图，所有输入为本地文件或回环端口。

任务环境与准备：
安装 Go 1.21 或以上版本并确保 go 命令在 PATH 中可用。
准备本地确定性样本：RFC 1035 线格式查询与应答报文样本文件、JSON 区记录文件各一份，内容与文件名由演示脚本引用。
准备本地上游解析器模拟脚本（以 Go 或 Python 实现均可），仅监听 127.0.0.1 回环 TCP 端口并返回确定性应答或冲突应答样本；无需访问真实 DNS 服务或外部网络。
确认回环 UDP 与 TCP 端口可绑定，演示与客户端只使用 127.0.0.1。
在空白工作区初始化 Go 模块，运行演示脚本前先构建可执行文件并核对样本文件路径参数。

业务要求：
1. 实现 DNS 查询与响应报文的线格式编解码：解析报文头各计数字段与问题段，支持名称压缩指针展开并防御指针环、指针向前与越界偏移，非法报文须返回 E_WIRE 业务码并记录出错偏移；UDP 响应超过 512 字节须置截断标志并降级返回，TCP 须以两字节长度前缀正确分帧，两端不得互相污染状态。
2. 实现本地 JSON 区记录格式的加载与归一：记录含名称、类型（A、AAAA、CNAME、NS、SOA）、TTL 与 RDATA 文本，加载时校验名称合法、类型受支持、TTL 为整数且不超过上限，非法记录以 E_ZONE 整体拒绝加载；JSON 记录与线格式样本须归一为同一内部记录模型，两种来源对同一逻辑记录须得到相同归一表示与相同应答。
3. 实现名称大小写不敏感匹配与通配符、CNAME 链解析：查询名须按 ASCII 大小写折叠后匹配，CNAME 跟随须限制最大跳数并在超限或成环时返回 E_CNAME；通配符记录仅在最左标签位置参与匹配，存在精确匹配时不得回落到通配符，解析结论须记录命中记录来源与匹配方式供上层引用。
4. 实现带 TTL 的缓存与过期回收：缓存键含归一化查询名、类型与类别，命中时按经过时间递减 TTL 并输出剩余值，过期条目须回收且不再命中；负应答按 SOA 最小 TTL 缓存并可配置上限；容量上限下按确定策略淘汰，不允许依赖 map 遍历顺序做淘汰决策。
5. 实现向本地回环上游解析器转发查询并校验应答链一致性：对本地权威区未覆盖的名称发起 TCP 转发，校验上游响应的事务标识、问题回显、应答记录名与类型链是否自洽，压缩指针展开后须能还原每条应答记录；上游不可达或应答链不一致须分别以 E_UPSTREAM、E_CHAIN 报告，且不得把可疑应答写入缓存。
6. 实现并发查询下的缓存一致视图：多个 UDP 与 TCP 查询并发到达时，同一缓存键的读取与回填须保证读到的条目要么是回填前完整状态要么是回填后完整状态，不出现半写条目；并发回填同一键须收敛到唯一结果并记录胜出者来源，服务在并发压力下不得把 TTL 计算为负值或让不同来源的同键条目交叉残留。
7. 实现转发结果与本地命中的来源归因及缓存条目版本识别：每条缓存条目记录来源（权威区、负应答、上游转发）、首次写入时间基准与来源序列号；当上游应答与本地权威区对同名同名类型给出冲突数据时须按明确规则仲裁并记录冲突两侧来源，来源序列号或时间基准变化时条目须整体替换而非字段合并。
8. 提供可交互命令行专业应用与可重复演示：以交互循环配合本地回环客户端展示查询文本、命中来源、剩余 TTL、CNAME 链与转发结果，附带确定性线格式样本、JSON 区文件与本地上游解析器模拟脚本及演示脚本，顺序执行冷启动查询、TTL 递减后重查、上游冲突应答与并发查询四个场景并输出顺序稳定的总结。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证线格式与 JSON 双通道解析、TTL 缓存递减、转发应答链校验与并发一致视图，输出稳定业务码。
