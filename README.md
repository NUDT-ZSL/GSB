工作室账号服务准备做一次离线验证：口令摘要要从旧算法档位迁到新档位，同时找回密码用的重置令牌要能一次性消费并追溯签名来源；眼下目录里没有任何代码，只有一台装了 Python 的 Windows 开发机。全部业务数据由随题交付的固定种子脚本确定性生成：用户凭据清单给出用户标识、盐、摘要算法档位与迭代参数、摘要占位值；重置令牌流按可注入逻辑时钟给出令牌标识、所属用户、签发与过期时刻、使用次数、旧摘要签名与一次性标记；两代策略快照并存，v1 为单文件 JSON，记录相对生效秒与扁平算法档位白名单，v2 为分片 JSON 加 SQLite 元数据库，记录绝对生效毫秒、策略代数与墓碑标记。团队要先把解析、合并、迁移裁决与令牌消费这条链路跑通。

任务环境与准备：
确认 Windows 开发机已安装 Python 3.11 或 3.12，并可用 python --version 验证。
在空工作目录中创建项目结构，不依赖网络与外部服务；仅使用标准库 sqlite3、hashlib、json、threading，不使用容器环境。
编写固定种子样本生成脚本，确定性生成本地用户凭据清单、重置令牌流、两代策略快照与真值标记文件，执行一次即可复现全部输入。
准备 pytest（如未安装可用 python -m pip install pytest），任务开始前确认可运行 python -m pytest --version。
运行前确认工作目录可写，样本、检查点与报告输出路径均在本地目录内。

业务要求：
1. 实现用户凭据清单、重置令牌流与两代策略快照的严格解析规范化层：校验用户标识唯一、盐长度与迭代参数为正整数、摘要算法档位在白名单内、令牌签发时刻小于过期时刻、v1 相对生效秒为非负整数、v2 绝对毫秒与策略代数为非负整数，对非法记录输出含来源类别、记录序号与稳定业务码的拒绝记录并继续处理后续记录。
2. 把两代策略快照合并为统一裁决视图：v1 的相对生效秒须以本地样本声明的观测时钟为唯一基准换算为绝对毫秒，不得使用系统当前时间；同一规范策略键按策略代数与生效时刻裁决权威来源，墓碑标记必须覆盖较早的非墓碑记录；当两代对同一用户的算法白名单或迭代下限给出冲突结论时判定为 E_POLICY_CONFLICT 并保留双方依据。
3. 实现摘要迁移判定：对每个用户按生效策略比较其当前算法档位与迭代参数，低于策略要求者判为待迁移，已在新档位者判为已达标；同一用户存在多条凭据记录时按凭据代数裁决，禁止把更早代数的达标结论当作当前结论，并要求迁移结论在任意快照导入顺序下保持一致。
4. 实现重置令牌使用裁决：令牌签发时刻落在用户当前生效策略窗口内、未被使用、签名与旧摘要一致即允许使用一次；过期、签名不符、重复使用、用户已迁移到新档位后仍以旧档位令牌签发等情形各自返回稳定业务码，所有时刻比较以观测时钟为唯一真值来源。
5. 实现策略代数升级与墓碑化的失效闭包：策略快照升级后，沿用户到令牌的依赖关系计算因算法档位或迭代下限变化而需重新裁决的用户集合与需作废的令牌集合，仅重判受影响部分，并要求重判结论与从零全量重判逐条一致；失效闭包须在报告中列出触发来源策略键。
6. 在 SQLite 中维护裁决账本并实现单事务推进：以用户标识与令牌标识为主键记录迁移状态、令牌状态、依据策略代数与判定水位，每轮裁决在单事务内完成，前置校验失败不得改动账本任何状态；账本格局版本（算法白名单或迭代下限口径变化）与当前不一致时须整体重建而非增量续接。
7. 实现检查点演进与强制终止后的恢复边界：按已处理批次水位与账本摘要持久化检查点到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放比对账本一致性以识别半写残留；检查点与裁决报告均先写临时文件再整体重命名替换，替换前校验内容完整可解析，同一工作目录并发写入以文件锁串行化，锁冲突返回 E_LOCK。
8. 交付可交互命令行与确定性本地验证：提供导入、迁移裁决、令牌使用、导出诊断报告、校验检查点五类子命令，报告为可解析 JSON 并含用户级迁移状态、令牌使用结论、业务码、依据策略代数与失效闭包；单份输入解析失败不得中断同批其他输入，退出码区分全部成功、部分失败与参数错误；附固定种子样本生成器与 pytest 测试集，并显式验证输入样本未被修改。
