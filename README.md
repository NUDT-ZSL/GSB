为语音识别（ASR）数据工程团队构建一个本地可运行的领域数据编辑与操作应用，核心是音频格式互操作与版本兼容。工作区为空，需从零创建项目。输入是本地音频分段样本目录：每个分段含 segment id、声道数（1 或 2）、采样率、位深、PCM 数据文件（WAV）与一份标注片段文件（含起止时间戳与转写文本，时间以秒为单位、精度到毫秒）。团队需要在该应用中对分段做裁剪、声道混合、重采样与位深转换，把结果导出为统一的目标格式，并按 ASR 微调数据集的清单格式（JSONL，含格式描述、音频摘要与标注偏移）生成快照。难点在于：不同来源分段的格式矩阵（采样率、声道、位深、编码）必须能互操作并归一到同一规范；编辑操作与快照之间存在版本兼容问题，旧版本清单可能无法直接套用到新格式上，需要识别并处理。所有处理只在本地确定性样本上进行，不调用任何外部模型或在线服务。

任务环境与准备：
安装 Python 3.11 及以上版本，创建虚拟环境。
安装 FastAPI、uvicorn、NumPy、soundfile、pytest；soundfile 需附带可用的 libsndfile 二进制。
在本地生成确定性样本：覆盖 8000/16000/44100/48000 Hz、8/16/24/32 位、单声道与立体声的短 WAV 片段及对应标注 JSON，样本与脚本放入 samples 目录。
确认工作目录为空，SQLite 使用标准库自带模块，无需外部服务。

业务要求：
1. 应用须提供分段导入与格式探测：读取本地 WAV 头校验声道数、采样率与位深是否与分段元数据一致，支持 8000/16000/44100/48000 Hz、8/16/24/32 位、单声道与立体声；不一致时返回 E_FORMAT 业务码并指出分段 id 与实际探测到的字段，不得写入任何音频缓存或清单记录。
2. 须实现格式归一管线：把分段统一重采样到目标采样率、目标声道数与目标位深，重采样须使用带限插值并保证输出长度与按秒计算的目标帧数误差不超过 1 帧；声道混合须提供单声道下混与立体声复制两种策略，策略由配置显式给出，未指定时返回 E_PARAM 而不是自行猜测。
3. 位深转换须做确定性量化：24 位与 32 位整数输入降为 16 位时须做峰值归一化与关闭抖动的截断，量化误差与削波样本数须在结果统计中给出；转换后同一输入重复运行须逐字节一致，且不得因浮点累积导致间歇性溢出样本。
4. 标注片段须随音频编辑同步迁移：裁剪与重采样后时间戳按输出采样率重新对齐到毫秒，跨越裁剪边界的标注须被截断并记录截断前后时长；标注时间越界、起止倒置或转写文本为空时分别返回 E_LABEL 业务码并给出分段 id 与片段下标，且不得产出部分清单。
5. 编辑操作须以版本化清单表达：每次导出生成整体替换的清单版本，清单含目标格式描述、每个分段的音频摘要（帧数、采样率、声道、位深与内容哈希）与标注偏移；读取清单时若检测到音频摘要与磁盘文件不一致或版本描述与当前目标格式不兼容，须返回 E_STALE 并定位到分段，禁止把旧清单静默套用到新格式。
6. 须实现版本兼容判定：导入旧版本清单时，按清单声明的格式描述与当前目标格式逐字段比较，只有可无损映射的差异（如 32 位到 16 位整数截断需显式声明、立体声到单声道需声明混合策略）才允许迁移，无法映射的差异返回 E_COMPAT 并列出不兼容字段；迁移结果须标记来源清单版本号。
7. 编辑与导出须在 SQLite 中以分段粒度做事务提交，音频缓存文件写入须先落临时文件再原子替换并登记内容哈希；进程被强制终止后重启，须核对已提交分段的内容哈希与缓存文件，重算未提交分段且不重复处理已提交分段，恢复后的清单与无中断执行须逐字段一致。
8. 须提供确定性本地演示入口：固定一组覆盖多种采样率、声道与位深的样本及编辑操作序列，跑出各分段归一前后格式、量化误差与削波数、标注截断数、清单版本序列与兼容判定结论的可重复结果，并给出可用等价参数复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地多格式音频样本验证归一、标注迁移、版本兼容判定与中断恢复，生成清单快照并输出可重复结果。
