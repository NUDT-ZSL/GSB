项目初始状态是空目录，需要从零实现一个本地负载均衡健康检查的跨版本状态映射与漂移诊断工作台。真实负载均衡器在滚动升级期间会同时存在两代健康检查状态快照：v1 以单文件 JSON 记录实例 ID、相对失败秒数、连续失败计数与扁平状态标记；v2 以分片 JSON 加 SQLite 元数据库记录实例规范 ID、绝对失效毫秒时间戳、状态代数、连续失败与成功计数、有效权重与墓碑标记。两代快照对同一实例的健康状态可能给出不一致结论，运维人员需要把两代快照合并为统一状态视图，并按检查计划回放本地 Python 回环测试服务的探测结果，判定状态漂移来源：是实例真实状态变化、时间语义换算误差、还是旧快照残留未清理。工作台需在可注入逻辑时钟下推进检查轮次，支持两代快照互操作、实例状态映射、漂移归因与中断恢复，最终以稳定排序 JSON 和 Web 页面呈现诊断结论。

任务环境与准备：
Windows 10 或 11，安装 Python 3.11 或 3.12，并确保 python 与 pip 已加入 PATH。
执行 pip install flask==3.0.3 requests==2.32.3 安装 Web 框架与回环 HTTP 客户端依赖。
在空目录中创建 samples 目录，放入 v1 单文件快照、v2 分片 JSON 与 SQLite 元数据样例、检查计划与漂移注入清单；所有样本由本地脚本确定性生成，不依赖外部网络。
启动本地 Python 回环 HTTP 测试服务（监听 127.0.0.1 的随机高位端口），按样本路径返回成功、状态码不符、慢响应与拒绝连接。
准备本地 SQLite 工作目录用于持久化状态，确保进程对工作目录有读写权限。

业务要求：
1. 实现 v1 单文件快照与 v2 分片 JSON 加 SQLite 元数据的解析校验：v1 校验实例 ID 唯一、相对失败秒数为非负整数、连续失败计数为非负整数且不超过声明阈值、扁平状态标记枚举闭合；v2 校验分片文件哈希、状态代数单调、绝对失效毫秒时间戳为整数、墓碑标记与失效时刻一致；非法输入返回明确业务错误码（如 E_BAD_SNAPSHOT、E_HASH_MISMATCH）且不写入任何持久化状态。
2. 实现跨版本实例状态合并与统一映射：同一实例在两代快照中同时存在时，依据快照声明的逻辑时钟与状态代数裁决最新状态，逻辑时钟相同按来源格式优先级；合并后每个实例须保留来源版本、原始时间表示与裁决依据，v1 相对失败秒数在注入逻辑时钟下换算为绝对失效时刻并记录换算标度与舍入方向；无法裁决的实例标记为待人工判定并输出两代原始值，不得静默取其一。
3. 实现基于注入逻辑时钟的健康检查轮次驱动与状态机演进：检查间隔、超时预算与窗口边界只依据注入逻辑时钟毫秒值推进，不读取系统墙钟；本地回环 HTTP 测试服务按路径返回成功、状态码不符、慢响应与拒绝连接；实例在健康、可疑、不健康之间迁移须依据已提交窗口结果与持久化状态裁决，连续失败与成功计数不得被并发重复累加，重启后不得凭内存残留决定状态。
4. 实现漂移归因判定：对合并后状态与回放探测结论不一致的实例，区分真实状态变化、时间语义换算误差、旧快照墓碑残留与两代快照代数冲突四类来源，输出首个触发证据（涉及字段、两代原始值与换算中间值、检查轮次号）；归因结论必须可追溯到具体快照版本与检查轮次，且相同输入重复运行得到逐位一致的归因结果与证据链。
5. 实现快照整体替换的版本变化识别与读取隔离：收到新快照包时比较清单版本号、状态代数下限、各分片哈希与实例集合摘要，判定完整替换、增量追加或无需操作，版本回退必须被拒绝并返回 E_VERSION_ROLLBACK；整体替换须以临时表加版本号整体切换当前状态指针而非逐条覆盖，进行中的检查轮次必须绑定其开始时的快照版本至结束，读者不得观察到新旧快照混合状态。
6. 实现强制终止后的恢复一致性：把已提交检查轮次水位、实例状态与计数、快照版本指针、漂移归因记录与逻辑时钟水位以事务原子写入 SQLite；进程在检查驱动或快照替换中途被强制终止后，恢复路径依据持久化状态识别已提交轮次与半提交实例，只重放未完成轮次且不得重复推进连续计数；恢复后统一状态视图须与未中断运行逐字段一致。
7. 实现多进程并发一致性与幂等提交：允许多个检查进程并行处理不同实例、多个快照更新进程并行提交，通过 SQLite 事务与文件锁保证同一实例同一轮次同一版本只提交一次、同一快照版本只被整体替换一次、连续计数不被并发重复累加，重复提交相同轮次结果或相同快照包必须幂等；读取方只能看到完整已提交版本。
8. 提供 Flask 诊断接口与可重复命令行验证：支持 load、check、merge、resume、status、verify 子命令或等价 HTTP 端点，status 以稳定排序 JSON 输出每个实例来源版本、健康状态、连续失败与成功计数、有效权重、漂移归因与逻辑时钟水位；verify 校验持久化状态与快照摘要一致并输出差异报告；连接拒绝、响应超出单次检查预算、状态码不符、畸形响应、分片哈希不匹配分别映射到不同业务错误码并在输出中保留可诊断字段。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地两代快照与回环探测样本，验证跨版本状态合并、漂移归因、中断恢复与并发幂等结果。
