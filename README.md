在 Windows 开发环境上，团队为游戏配音节目交付一条离线多通道声场合成链路，当前工作区仍是空白目录。业务目标是：给定六面体录制棚、若干发声点与一个多通道扬声器阵列，用镜像声源法逐频段重建棚内冲激响应，再与各声源干信号逐频段卷积合成多通道环绕声。验收关注的不是渲染画面而是能量守恒：各表面吸声系数、路径衰减与频段增益须以定点数参与累乘与判定，并同时维护 float64 参考路径，因为镜像声源沿反射链逐步累乘、逐频段求和时舍入会改变“能量是否可忽略”的裁定，从而改变冲激响应的能量分布与最终声场。样本由本地确定性脚本按固定种子生成，不依赖真实录音设备、网络或外部素材。

任务环境与准备：
确认 Windows 本地已安装 Python 3.11 或以上，并可在命令行直接调用 python 与 pip。
安装依赖：pip install numpy==1.26.4，WAV 读写使用 Python 标准库 wave，不引入音频库。
新建空工作区目录，自行编写固定种子样本生成脚本，生成录制棚场景 JSON、各声源干信号 WAV 与版本化状态目录。
确认工作区具备可写状态目录与输出目录，运行前清空历史状态以免与本次样本的版本标识混淆。

业务要求：
1. 实现录制棚场景与输入校验：读取本地 JSON 场景与各声源干信号 WAV，校验棚体三轴尺寸与各表面吸声系数为有限正数且吸声系数位于 (0,1)、声源与扬声器坐标处于棚内且互不重合、目标采样率与声道布局属于允许集合、重建阶数与最大反射次数为非负整数、频段边界严格递增且落在奈奎斯特频率内，非法输入返回带 E_xxx 业务码的 JSON 错误且不产生任何输出。
2. 实现定点数学层与浮点参考对照：各阶路径衰减、逐频段增益与能量累加先按规格定点标度量化为整数再参与判定与累加，同一量同时维护 float64 参考值；逐镜像声源记录两者绝对差值，标出首次超过能量残差容差的镜像声源序号与所处阶数，最终“能量是否可忽略”的裁定只依据定点结果，浮点路径仅用于诊断报告。
3. 实现镜像声源枚举与确定性阶序调度：按重建阶数与最大反射次数枚举六面反射产生的镜像声源，同一反射路径只被枚举一次，枚举次序以阶数、反射面序列与声源标识构成的字典序为最终决胜；每个镜像声源携带由反射历史决定的路径长度与吸声乘积，同一场景重复枚举必须得到逐镜像声源相同的路径长度与阶数归属。
4. 实现逐频段冲激响应重建：把每个镜像声源的到达延迟按目标采样率换算为不短于理论延迟的整数采样点偏移，按路径距离衰减与吸声乘积得到频段幅度权重，用逐频段线性相位分数延迟滤波器叠加到该频段冲激响应上；同一镜像声源在任意并发度与任意分块划分下的频段贡献必须逐采样点相同，频段边界处不得出现能量丢失或重复计入。
5. 实现误差传播的残差溯源：当某频段某采样点的定点累加结果与浮点参考偏差超过容差时，按镜像声源阶数与频段依赖关系反演出贡献该点的镜像声源集合及各自残差贡献，给出首个越限的频段、采样点与阶数，并说明偏差主要沿吸声累乘放大还是沿频段求和放大；溯源须指向真实执行过的累加记录而非事后重演。
6. 实现分块级持久化与版本识别恢复：按频段与镜像声源阶数把重建任务划分分块，每块完成后把该块冲激响应、累计残差摘要及由场景参数、干信号内容与种子规范化摘要构成的版本标识原子写入状态目录，先写同目录临时文件再整体替换；再次启动时版本标识一致则复用已完成块只补算缺失块，不一致则从头重做，禁止新旧版本冲激响应混用。
7. 实现并发分块重建与资源预算上限：按场景声明的并发上限使用有界线程池调度待算分块，同时处于计算中的冲激响应采样缓冲与残差记录总量不得超过内存预算，超出时按频段与镜像声源标识的确定顺序让后续块等待而非降低定点标度或缩短分数延迟滤波器；任一分块异常时取消其余待处理分块并返回首个错误。
8. 处理可处理终止信号与强制终止的差异并原子写出：可处理终止信号只在分块边界生效，须在写入中断标记并以约定整数退出码退出前保证未完成分块不留下可被误认为已完成的结果；最终多通道 WAV 与残差溯源报告先写同目录临时文件再整体替换正式输出，替换前读取已有输出文件的采样率与内容摘要版本信息，仅版本变化时才替换，失败时保留旧文件。
