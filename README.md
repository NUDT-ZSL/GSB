在空白工作区从零实现一个本地查询连接顺序优化与执行一致性验证引擎，用于在确定性样本上复现多表连接的顺序枚举、代价模型裁决与交互延迟约束下的结果一致性保障。样本以本地 JSON 给出：表描述（表名、行数、每列 NDV、列宽字节、连接键与外键语义）、连接查询模板（表集合、连接谓词、过滤谓词选择率、排序与限制子句）以及执行配置（延迟预算毫秒、代价权重、枚举上限、容差参数）。引擎需为每个查询枚举候选连接顺序与连接算法（嵌套循环、哈希连接、排序归并），以自研代价模型估算每候选的启动代价与总代价，在启动延迟预算约束下选取最优计划，同时保证同一查询在不同并发度、不同枚举上限与中断恢复后得到逐位一致的计划决策与结果摘要。同一查询的结果还需通过固定顺序的全量单流算法计算唯一真值来比对，所有过程在本地文件系统与 SQLite 上完成，不依赖真实数据库服务。

任务环境与准备：
安装 Python 3.11 及以上版本，确认 sqlite3 标准库可用，无需任何第三方包或网络访问。
在空白工作区创建项目目录与本地 samples 目录，准备表描述与查询模板 JSON 样本以及对应的固定表数据文件。
确认可以启动多个本地 Python 进程并读写同一目录下的 SQLite 文件，用于并发与强制终止场景的准备。

业务要求：
1. 实现样本表描述与查询模板解析校验：校验表名唯一性、行数为正整数、NDV 与列宽合法、连接谓词两端列存在且类型可比、过滤选择率在区间内，构建表与谓词的元数据模型；非法输入必须返回明确业务错误码 E_BAD_SAMPLE 或 E_BAD_QUERY，且不写入任何持久化状态。
2. 实现连接顺序与连接算法候选枚举：对每个查询生成所有合法的连接树与连接算法组合，枚举受计划上限约束且必须识别左右次序被交换律消解的重复计划；输出候选需为稳定排序并带有唯一计划标识，超出枚举上限时按确定性规则截断并记录截断原因。
3. 实现代价模型与启动延迟预算裁决：对每个候选分别估算启动代价与总代价，权重可配置且运算顺序固定，使相同输入多次估算逐位一致；在启动延迟预算内选择总代价最小的计划，若无候选满足预算则按明确规则降级并返回可诊断报告，不得静默违反预算。
4. 实现计划结果一致性与真值来源：按选定计划以确定性算法在本地样本数据上执行连接与过滤，得到结果行摘要；同时用固定顺序的全量单流算法计算唯一真值，两者逐行比对，任何不一致必须标记为一致性异常并输出差异行与来源计划标识。
5. 实现交互延迟观测与精度记录：记录每个候选代价估算中浮点中间值的累计误差上界，当两个候选总代价差小于容差且排序依赖该差值时标记为精度敏感排序；延迟观测必须依据可注入的逻辑时钟推进，不得读取系统墙钟，同一逻辑时钟序列下重放必须得到逐位一致的重放记录。
6. 实现持久化状态与强制终止后的恢复：把查询轮次、样本摘要、候选枚举结果、选定计划、结果摘要与精度敏感记录原子写入 SQLite，每轮提交识别版本变化并整体替换当前结果指针；进程被强制终止后依据持久化状态识别未提交轮次并只重算缺失候选，不得回退已提交轮次或重复提交已完成计划。
7. 实现多进程并发一致性与幂等：允许多个分析进程并行处理同一批查询模板，通过 SQLite 事务与文件锁保证同一查询同一版本的最优计划只提交一次，重复提交相同候选结果必须幂等；读取方只能看到完整已提交轮次而非枚举中间态，样本摘要变化必须使旧计划失效。
8. 实现异常链路与可重复命令行验证工具：连接谓词类型不匹配、计划枚举为空、预算无法满足、结果不一致、样本摘要不匹配分别映射到不同业务错误码；提供 plan、execute、resume、status、verify 子命令，status 与 verify 以稳定排序输出 JSON，使用固定本地样本两次运行输出完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
