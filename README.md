某数据安全团队需要在离线 Windows 工作站上构建一个敏感信息流追踪工作台，用于对本地确定性 JSON 样本中的敏感字段（如证件号、手机号、银行卡号）在多版本文档之间的流转路径进行追踪与编辑校验。工作区为空，需从零开发。样本为一组带版本号与依赖声明的文档快照，每份文档包含字段清单、字段级敏感标记、字段之间的派生引用关系以及版本变更记录；工具需重建字段级敏感信息传播路径，在编辑场景下校验修改是否破坏了既定的脱敏约定与派生一致性，并输出可复现的 JSON 诊断报告与流转图数据。核心难点在于格式互操作与版本兼容：样本支持两种字段寻址格式（点路径与数组下标路径）和两种派生声明版本，旧版声明缺少传递性标记，新旧版本混用时流转追踪结果必须一致且可解释。

任务环境与准备：
确认 Windows 工作站已安装 Python 3.10 或以上版本与 pytest，且能离线运行。
在空白工作区创建项目目录，不预置任何代码、样本或配置文件。
准备本地确定性样本生成脚本所需的固定随机种子与输出目录，全程不访问网络与外部数据源。

业务要求：
1. 实现多版本文档快照与字段寻址的解析规范化层：支持点路径（a.b.c）与数组下标路径（a[2].b）两种寻址格式并统一为规范寻址键；校验版本号格式、派生引用目标是否存在、数组下标是否越界，对非法条目输出含文档版本与条目序号的 E_FIELD 拒绝记录并继续处理其余条目。
2. 实现跨版本文档的字段血缘重建：依据派生引用声明把敏感字段的上游来源与下游派生字段连成字段级血缘边，支持传递闭包；当同一字段在相邻版本中寻址格式改变（点路径与下标路径互换）时必须按规范化寻址键识别为同一字段，不得因格式差异断链或重复计为新增字段。
3. 实现派生声明格式的版本兼容分派：v1 声明缺少传递性标记即视为直接派生不向下传递，v2 声明携带传递性标记需按标记传播敏感性；同一文档内混用两种声明版本时须按字段所属声明版本分别处理，并对无法归入已知版本的声明返回 E_VERSION 而非静默降级。
4. 实现敏感信息流转追踪与脱敏约定校验：沿血缘边计算每个字段的敏感等级传播结果，检测绕过脱敏约定的编辑（如对敏感源字段的直接下游赋予明文标记、删除脱敏字段但保留下游派生引用），分别返回 E_MASK_BYPASS 与 E_DANGLING_DERIVE 并给出字段规范寻址键与文档版本。
5. 保证追踪结论与版本混用及声明顺序无关：对同一组文档快照，任意合法的声明排列顺序与新旧声明混用方式下，字段敏感等级、血缘边集合与违规清单必须完全一致；输出中的字段顺序须按规范寻址键稳定排序，不得依赖字典遍历顺序或输入排列。
6. 实现增量编辑会话与检查点：按已应用文档版本水位与追踪状态持久化检查点，恢复时只从最后一个完整检查点继续；检测到检查点结构版本或派生声明规则版本与当前不一致时须整体重建而非增量续接，不得把旧版追踪结论与新版声明混合使用。
7. 实现原子快照写入与强制终止后的恢复边界：检查点、诊断报告与流转图数据均先写临时文件再整体替换，替换前校验内容完整性；同一工作目录并发写检查点须以文件锁串行化，锁冲突返回 E_LOCK；进程被强制终止后只允许恢复到最后一个完整检查点，不得承诺生成退出报告，也不得出现半写文件。
8. 实现诊断工作台命令行与本地样本测试：提供导入、追踪、编辑校验、导出报告四类子命令，单份文档解析失败不中断同批其他文档，退出码区分全部成功、部分失败与参数错误；附确定性样本生成器与 pytest 测试，样本内显式记录版本同步标记作为真值来源，验证只依据标记与规范化追踪结果比较，覆盖寻址格式互换、声明版本混用、脱敏绕过与中断恢复等情形。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地多版本样本验证字段血缘重建、新旧声明混用一致性、脱敏违规业务码与检查点恢复正确性。
