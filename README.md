# 韵律边界标注诊断应用

本目录已包含从零实现的可运行诊断应用。快速开始：

```bash
pip install -r requirements.txt
python run.py --mode full
bash scripts/verify_acceptance.sh
```

默认报告：`artifacts/diagnostic_report.json`；统一账本：
`artifacts/annotation_ledger.jsonl`；逐帧特征：`artifacts/frame_features.jsonl`。

关键说明：

- 架构、错误码、缓存/恢复语义：`docs/TECHNICAL.md`
- 实际测试与验收结果：`docs/VALIDATION.md`
- 自动化测试：`tests/test_diagnostics.py`
- 交互查询：`python run.py --mode interactive`
- 缓存追溯：`python run.py --mode trace --utterance U001`

支持 `--precision`、`--decision-tree-version`、`--interrupt-point` 及环境变量
`PROSODY_PRECISION`、`PROSODY_TREE_VERSION`、`PROSODY_INTERRUPT_AT`。

---

语音合成小组刚结束一次韵律标注工具的迁移评估，工作目录仍然没有可运行代码，需要从零构建一个可交互的韵律边界标注诊断应用。系统面向多说话人语音合成前端的韵律层级预测，核心问题不是音色克隆，而是两代韵律决策树在格式版本演进下的互操作、标注结果跨版本的一致性裁决，以及决策树推理中的数值精度与误差传播。全部输入由本地确定性脚本按固定种子生成，不依赖真实音频库、外部服务或网络：脚本生成每个说话人的基频、能量与停顿时长参数，按发音时间轴拼成16kHz单声道PCM，同时提供逐帧声学特征真值（帧长20ms，字段含frame_index、speaker_id、f0_true、energy_true、pause_label）与韵律标注任务清单（JSONL，字段含utterance_id、speaker_id、text、start_ms、end_ms、precision_profile、decision_tree_rev、logical_clock_ms）。两代决策树格式并存，v1为单文件JSON记录相对秒与扁平规则，v2为分片JSON加SQLite元数据库记录绝对毫秒、规则代数与失效墓碑。任务需在WSL Ubuntu本地独立实现，不依赖GPU或付费资源。

任务环境与准备：
在 Linux（WSL Ubuntu）上安装 Python 3.10 及以上版本，并安装 NumPy（SQLite3 通常随 Python 内置），无需外部服务。
创建空工作目录，将提供的固定种子脚本放入其中，运行脚本生成确定性样本：16kHz PCM、逐帧真值、韵律标注任务清单、两代决策树快照；不依赖任何真实音频文件或网络。
设置命令行入口，脚本应支持 `python run.py --mode full` 执行全量诊断，并允许通过环境变量或参数注入精度档、决策树版本与中断信号点。

业务要求：
1. 实现确定性的声学特征提取与韵律边界候选生成阶段：按配置帧长20ms与帧移10ms切分16kHz单声道PCM，帧边界以样本索引精确确定，计算短时能量、基频候选与过零率，并结合停顿时长输出逐帧声学特征；同一utterance_id、同一种子与同一配置下所有特征值、帧边界与候选边界必须逐字节可复现，帧数必须与采样率和起止毫秒推算的样本数严格一致，不一致时返回E_FRAME_COUNT_MISMATCH，候选边界同分时按帧索引升序、再按边界类型升序裁决。
2. 实现两代韵律决策树的读取器与双向迁移器：v1单文件JSON扁平记录相对秒与决策规则，v2分片JSON加SQLite元数据库记录绝对毫秒、规则代数与失效墓碑，读取时按版本头或字段集分派解析路径，未知版本返回E_VERSION_UNSUPPORTED，字段缺失、竖线字段数不符或时间戳倒退返回E_FORMAT_CORRUPT；迁移时升级补全规则代数、失效墓碑与绝对毫秒并逐项记录补全来源，降级对v2中v1无法表达的墓碑或嵌套规则按显式丢弃或展平规则处理，迁移后新旧决策树在相同输入上必须产生完全相同的内部规则表示与相同的边界判定序列，若因表达能力不足导致语义不可完全还原则返回E_SEMANTIC_LOSS。
3. 实现基于两代决策树的跨版本边界裁决：对同一utterance分别用v1和v2决策树推理，输出逐候选边界的类别、置信度、决策路径及所用规则版本，并按显式声明的优先级（真值标签大于v2大于v1，同级按规则编号升序）合并为统一标注账本；当两代决策树在同一候选边界给出不同类别时，记录冲突详情并按声明规则裁决，冲突候选数超过配置阈值时返回E_CONFLICT_OVERFLOW；账本必须可由逐候选判定明细独立重算一致，且v1与v2任一版本重跑结果逐字节相同。
4. 实现float64、float32与定点缩放整数三档共用同一算子语义的精度档执行层：定点档的缩放因子与舍入模式由precision_profile显式给出，声学特征归一化、决策树节点阈值比较与置信度累加在三个精度档下使用同一套公式和运算顺序；同一输入在不同精度档下结果的差异必须仅来自数值精度损失本身，切档不得改变帧索引集合、边界候选集合或决策树遍历路径；所有中间累加以声明精度执行，float64档作为该快照内参考真值。
5. 实现逐级误差传播计算与主导来源归因：以同输入float64整段路径为参考真值，结合逐帧真值f0_true与能量真值作为观测口径，输出特征规范化、节点阈值比较、置信度累加与边界分类各级的绝对偏差、相对偏差、误差区间与误差放大比，并定位主导误差来源级别；当偏差超过配置容差时返回E_TOLERANCE_EXCEEDED并输出首个超差位置及级别；误差谱统计必须由逐帧偏差明细独立重算一致，且在门限附近的候选边界在多档精度重复运行下判定不得出现舍入翻转。
6. 实现决策树规则修订或输入修正后的定向依赖失效传播与缓存管理：为每个utterance建立内容寻址缓存，缓存键纳入PCM内容哈希、决策树版本、precision_profile、规则代数及上游产物哈希；当某utterance的revision提升、决策树规则调整或precision_profile切换时，按缓存键计算受影响utterance集合，复用未受影响utterance的已提交特征与标注结果，仅重算受影响后缀；必须输出本次重算utterance清单与复用清单，并能按缓存键追溯任意标注结果的精度档与决策树版本。
7. 实现四阶段状态机与强制终止恢复：声学特征提取、边界裁决与账本写入、误差谱归因、报告导出四阶段各自产生带单调递增版本号、已完成utterance_id集合与内容校验和的持久化快照，只有该阶段全部样本处理完成才以临时文件写入后原子替换提交；重启时读取最近已提交阶段快照，从该阶段记录的下一utterance继续推进，已提交utterance的特征、标注与误差统计不得重算或重复写入账本，未提交的中间缓存与账本条目必须丢弃并从阶段起点重建；恢复后的完整状态与无中断执行逐字节一致。
8. 实现输入与配置校验链路、并发提交控制及资源上限：重复utterance_id、帧长帧移非法、precision_profile未知、参考边界标注不匹配、决策树版本回退分别返回结构化业务码并指明字段；同一时刻只允许一个快照提交或阶段提交生效，并发冲突时后到者立即返回E_STAGE_BUSY而不阻塞等待；为单次处理utterance数、驻留声学特征内存、缓存条目数设可配置上限，超限时按显式优先级降级到分批流式或提升剪枝阈值并记录降级类别。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
本地样本下验证跨版本裁决、多精度误差谱、失效重算与中断恢复，逐帧可复算并输出诊断报告。
