当前是空白工作区，需要从零实现一个本地 QoS 流量整形与队列调度的数据处理管线及其结果验证工具，全部在 Windows 上以本地确定性样本运行，不依赖真实网卡、抓包或外部服务。样本以 JSON 给出：分类器规则（按 DSCP 或五元组匹配映射到整形类别）、每类整形参数（承诺速率与峰值速率以比特每秒表示、突发桶深度以字节表示、双桶令牌桶的峰值桶深度、队列深度与丢弃策略为尾丢弃或加权随机早期丢弃）、整形器层级（父类到子类的层级与每子类保证带宽与权重），以及一组按可注入逻辑时钟毫秒给出的到达事件流（事件序号、字节数、类别标签、到达时刻）。管线需在固定逻辑时间步进下推进双令牌桶、逐跳队列与加权轮询调度，输出每一时刻每类别的令牌余额、队列占用、通过、整形等待与丢弃字节数，并给出每类别可达吞吐与时延的派生估计。核心难点是速率与令牌量的小数字节换算、突发深度的定点表示与多级整形层级之间派生量的浮点误差累计会沿调度链传播，必须在相同样本上给出可复现、可追溯、可验证的结果。

任务环境与准备：
确认 Windows 上已安装 Python 3.11 或更高版本，并可在命令行调用 python 与 pip。
安装 NumPy 并为 Python 环境准备内置 sqlite3 模块，无需其他第三方包与网络访问。
在空白工作区创建项目目录，准备固定的整形配置、到达事件流与注入清单 JSON 样本文件，样本内容与种子固定。
确认本地文件系统可创建 SQLite 数据库文件与临时目录，用于元数据持久化与恢复验证。
准备两次重复运行的对比脚本，确保样本与逻辑时钟注入序列完全一致。

业务要求：
1. 实现整形配置与到达事件流的解析校验：类别名唯一、承诺与峰值速率及桶深度为合法的正整数表示、峰值桶深度不小于承诺桶深度、队列深度为正整数、父类引用闭合且层级无环、每子类保证带宽之和不超出父类承诺速率、事件序号严格递增且到达时刻为非负整数，非法输入须返回明确业务错误码并保持样本与持久化状态不变。
2. 实现速率到每逻辑步令牌增量的定点换算：把承诺速率、峰值速率与桶深度统一换算为受控定点整数表示，记录每项的标度、舍入方向与换算前原始浮点值，未满一个定点单位的累加余量必须逐桶保存以免步进间误差丢失，相同配置重复换算必须得到逐位一致的定点值与余量。
3. 实现双令牌桶整形与逐类队列的先入先出处理：每类同时维护承诺桶与峰值桶，每步进令牌增量按先承诺后峰值次序累加且不得透支，超出承诺桶的部分只在峰值桶有余量时保留为超过承诺速率的突发，令牌余额、余量与队列占用只能依据已提交步进的完整结果推进。
4. 实现事件到达时的通过、整形等待与丢弃裁决：依可用令牌与队列深度裁决三种结局，尾丢弃与加权随机早期丢弃须给出确定性的丢弃候选与选择依据，被整形等待的事件保留到达顺序，同一事件序列在任意运行次数下须得到逐位一致的通过等待丢弃序列。
5. 实现加权轮询调度与层级带宽保证：父类在多个子类间按权重分配步进额度，子类未用完的额度按既定规则结转或回收，父类总发送量不得超过其整形后可用令牌；调度顺序与名额分配须为稳定排序，并输出每步进每子类的实际发送字节、轮询次数与额度不足原因。
6. 实现整条整形链的浮点误差累计与精度敏感标记：对令牌余额、队列占用与派生吞吐时延记录每次加法乘法的误差上界，当两类别的可达吞吐差值或两子类的调度名额差值小于给定容差而结论依赖该差值时标记为精度敏感，输出误差来源链含参与类别、事件序号与换算步骤。
7. 实现派生吞吐与时延估计并给出真值对照：按固定聚合顺序对每类别的通过字节与等待时长计算滑动窗口吞吐与分位时延，同时以逐事件全量重算得到唯一真值，两条路径逐项比对，不一致须区分是定点换算误差、令牌累积误差还是调度顺序差异，并输出首个分歧项与中间值。
8. 实现强制终止后的恢复一致性与多进程幂等提交：把已提交步进水位、各类令牌余额与余量、队列内容摘要、调度额度结转与逻辑时钟水位以事务原子写入 SQLite，进程在令牌更新或调度中途被强制终止后只重放水位之后的步进且不得重复消耗令牌或重复发送字节；多实例并行时保证同一步进同一版本只提交一次且读者只见完整已提交步进，并提供 load、shape、resume、status、verify 子命令输出稳定排序 JSON。
