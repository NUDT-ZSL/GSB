离线推荐召回团队把用户—商品点击购买记成一张极度稀疏的二部图邻接矩阵，非零交互只占全表很小一部分，却集中在少数热门行上，冷门行几乎全空。上线前性能工程师要在本地对一小批真实稀疏片段试跑用户兴趣扩散的稀疏矩阵乘，即邻接矩阵乘稠密兴趣向量，并据此挑出可用的内核配置。麻烦堆在输入本身：同一批数据同时以 Matrix Market 与 CSR/CSC 文本三种片段交付，规格还分三个声明版本，字段命名、索引从 0 还是从 1 起、权重是原始计数还是千分比各不一样，直接把片段喂进内核会行号错位、结果量纲漂移；而单行极密、单列极密的片段让统一分块出现严重负载倾斜。团队要一个能逐批核对、跨版本归一，并能对格式与分块给出可复现依据的稀疏矩阵乘内核工作台。

任务环境与准备：
准备 Linux 环境下的 Python 3 运行环境，并安装运行所需的 NumPy；工作目录为空白工作区，需自行创建项目结构与命令行入口。
仓库内需附带的输入包括：三种片段格式的稀疏矩阵样本、对应的稠密兴趣向量、三份声明版本规格与运算规格 JSON，样本需覆盖高度偏斜、单行极密、单列极密、含空行与索引从 1 起的版本片段。
运行边界为本地确定性计算，不访问网络、不依赖真实账号或外部服务；稠密参考计算与内核实现均在本机执行，便于逐批复算。

业务要求：
1. 读取仓库内的三种片段格式（Matrix Market、CSR 文本、CSC 文本）与三份声明版本规格，把字段命名、索引基数与权重单位归一为统一的行列位置和数值模型；同一非零元素在所有版本下必须落到相同行号、列号与权重，归一后的矩阵维度以各版本声明的最高索引为基准。
2. 对归一后的矩阵与运算规格，按行、列非零分布选出一个稀疏格式（CSR 或 CSC），并给出可直接复算的非零分布统计与格式选择依据；选择过程需读取运算方向（按行累加或按列累加）作为判定输入，禁止固定输出单一格式。
3. 按选定格式与声明的批大小预算对矩阵分批，输出逐批的非零元素区间与稠密向量分块复用表；对单行极密矩阵必须保证单行不被拆到不同批次，对空行必须显式记录而不跳过。
4. 逐批执行稀疏矩阵乘并累加结果向量，同时记录每批扫描的非零元素个数、稠密向量分块命中次数与结果元素增量；累加过程需保证同一结果元素的所有贡献只被计入一次。
5. 输出内核运行账目，包含非零元素扫描总数、批次数、单位结果元素的平均非零扫描量，以及扫描量超过均值若干倍的热点批次标识，热点判定阈值由运算规格声明。
6. 用独立的稠密参考计算产出真值向量，逐元素比对稀疏矩阵乘结果，输出最大绝对误差、误差分布直方图与超出容差的元素位置列表；容差由运算规格声明，比对必须在归一后的同一坐标上进行。
7. 对同一矩阵至少比较两种格式或分块策略下的结果与运行账目，在结果一致的前提下按扫描量与热点批次给出推荐配置与逐条依据；两种策略结果不一致时必须报告冲突并拒绝给出推荐。
8. 保证三个声明版本归一后产出逐元素相同的结果向量与相同的运行账目，并输出跨版本差异清单，逐条列出被修正的字段名、索引偏移与权重换算因子；任一版本归一失败时给出可定位到具体元素与字段的业务错误码，且不得写出部分结果。

验收：
以独立稠密参考计算为真值逐元素核对结果与容差；在极偏斜与索引从 1 起的版本片段上核对分块、归一与跨版本一致性及推荐依据。
