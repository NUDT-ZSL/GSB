这项需求没有既有代码，需要从零构建一个面向检索前链路稀疏召回索引构建与查询的本地可集成领域组件与完整示例，核心业务问题是在文档与查询双批次持续到达时的并行调度、计算预算准入以及中断后的增量快照恢复。业务对象是本地确定性生成的文档批次清单与查询批次清单（JSONL，文档含 doc_id、batch_no、terms 词项与词频、doc_len；查询含 query_id、batch_no、terms、top_k），以及由固定种子驱动 NumPy 生成的词项权重表。系统把一次召回服务建模为多级流水：批次摄入与词项校验→倒排累积与分区统计→固定维度稀疏特征投影→查询打分与 top-k 汇总。用户需要看到每批次被准入、降级或拒绝的完整依据，以及在进程被强制终止后由已提交快照继续推进且结果与不间断运行逐字节一致。

任务环境与准备：
安装 Python 3.11 或更高版本，并执行 pip install numpy==1.26.4。
在 Windows 本地工作区创建项目目录，确认可启动本地进程池（spawn 模式），不依赖外部服务或网络。
准备本地确定性批次样本生成器（固定种子与参数按题目约定），生成文档与查询批次 JSONL 及词项权重表供命令行示例读取。

业务要求：
1. 实现确定性的批次摄入与稀疏特征投影核心：按 batch_no 与 doc_id 升序摄入文档，依据固定种子词项权重表把文档词项投影为固定维度稀疏向量，输出逐文档向量与词项校验结果；同一批次清单与同一配置下必须逐字节可复现，同分时按 doc_id 升序打破平局。
2. 实现倒排累积与分区统计阶段：按词项累积文档频次、分区文档数与平均文档长度，分块累积时按显式声明的归约顺序归约，并提供可配置补偿求和；须保证逐词项统计可由逐文档明细独立重算一致，且分区统计与全局统计口径可互相核对。
3. 实现面向并行槽位、总乘加预算与驻留稀疏缓冲内存三重约束的调度计划器：为每个批次估算乘加次数与内存占用，在约束下决定准入批次集合、执行顺序与并发度；计划须记录每批次的代价估算、共享词项权重复用与准入结论，同一观测下计划逐字节一致。
4. 实现预算冲突的显式裁决规则：当并行槽位、乘加预算与内存任一不足时，按声明优先级在批次规模、词项去重收益与查询优先级之间裁决，被拒或降级批次返回 E_COMPUTE_BUDGET、E_MEMORY_BUDGET 或 E_SLOT_LIMIT，并在计划中记录裁决依据与被降级批次的执行规模。
5. 实现本地进程池执行与结构化异常回传：按调度计划把批次分组分派到本地进程池执行投影与统计，分块边界与归并顺序必须确定性可复现；worker 内异常须以业务码与阶段名回传主进程并归因到具体 batch_no，单批次失败不得中断其余批次。
6. 实现强制终止后的增量快照恢复：摄入、倒排累积、投影、打分四阶段在批次边界提交带单调递增版本号、已完成 batch_no 集合与内容校验和的检查点，写入以临时文件落后原子替换；重启时从最近一次已提交检查点继续，已提交批次不得重算，未提交的稀疏缓冲须丢弃重建，恢复结果须与不间断运行逐字节一致。
7. 实现检查点与统计量快照的版本识别及整体替换：检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK；同一时刻只允许一个批次计划提交生效，冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待。
8. 实现门限与 top-k 判定的稳定性保护及跨模块一致性自检：对相似度门限提供严格比较与容差带比较两种策略及次正规数保护，保证门限附近查询的 top-k 在多档精度重复运行下不被舍入翻转；自检校验各阶段 batch_no 集合一致、重算集合与复用集合无交集且并集覆盖全部受影响集合、top-k 分数可由稀疏向量与词项统计独立重算，不一致返回 E_INCONSISTENT。
