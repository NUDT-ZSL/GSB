需要在空白工作区中实现一个面向本地服务可靠性运营的「SLI 与 SLO 错误预算估算组件」，用于在离线环境下复现真实 SRE 机制：SLI 由本地样本事件流（时间戳、服务名、请求结果类别 good/bad、延迟毫秒、事件序号）计算，SLO 配置声明目标值、评估窗口长度、窗口类型（滚动窗口或日历窗口）以及错误预算策略。运营需求要求组件同时维护多个评估窗口（例如 5 分钟、1 小时、7 天）的 SLI 与剩余错误预算，并在预算消耗速率异常时给出告警决策；然而不同窗口的数据规模差异极大，短窗口只需读取少量最近事件，长窗口可能包含数十万条历史事件，若对每个窗口独立全量扫描则计算不可接受，若缓存聚合结果则必须处理乱序事件、迟到事件与窗口滑动导致的精度问题。组件还需支持从持久化状态恢复、并发查询与事件写入、以及当样本事件超过设定容量时的聚合降采样，并在降采样与精确计算之间给出可验证的误差边界。该组件需以可集成模块与完整示例交付，包含本地样本生成器与离线可重复测试。

任务环境与准备：
安装 Python 3.11 及以上版本，创建本地虚拟环境并安装 pytest 与 NumPy（版本以终端显示为准）。
确认工作区为空目录，样本事件与 SLO 配置全部由本地生成器与配置文件产生，无需外网、账号或附件。
所有路径使用 Windows 本地路径，SQLite 使用标准库 sqlite3，测试以 pytest 在离线状态运行。

业务要求：
1. 实现事件流摄入与 SLI 计算：每条样本事件包含单调递增序号、时间戳、服务名、结果类别与延迟毫秒，SLI 按 good 事件占比计算并保留至少六位十进制有效位；同一序号重复摄入须幂等去重，结果类别非法或时间戳早于允许的迟到边界须返回业务码 E_BAD_EVENT 且不得进入任何窗口的统计。
2. 实现多窗口滚动聚合的数据结构：同时维护 5 分钟、1 小时、7 天三个窗口的 good/bad 计数与预算消耗，短窗口必须每分钟粒度精确，长窗口允许分桶预聚合；窗口滑动时过期分桶须被淘汰，任何窗口的 SLI 查询结果不得使用已滑出该窗口的事件，且各窗口结果须在同一逻辑时刻上自洽。
3. 实现乱序与迟到事件处理：事件可能以乱序到达，须按时间戳插入正确分桶并修正受影响的窗口计数；迟到事件若落入仍被窗口覆盖的时间范围必须补算，若已滑出最长窗口则仅记录为拒绝计数并返回 E_TOO_LATE；补算后所有窗口的 SLI 与预算必须立即反映修正，不得残留旧值。
4. 实现容量上限与聚合降采样：当事件总量超过配置容量时，须对最老的时间分桶做有损聚合（保留计数与延迟分布摘要而非原始事件），降采样必须记录每个被聚合分桶的样本数与摘要类型；降采样后短窗口仍须精确，长窗口的 SLI 估算须给出与精确值比较的误差上界并随查询返回。
5. 实现错误预算与燃烧速率告警决策：剩余预算按目标值与窗口内总请求数计算，燃烧速率按多窗口组合规则评估（短窗口高速率与长窗口低速率须同时满足才触发高优先级告警）；告警决策须输出触发规则、涉及窗口、当前速率与剩余预算，未触发时也须给出各窗口的评估值与最接近触发的规则，且决策在相同输入下确定可复现。
6. 实现 SQLite 持久化与重启恢复：分桶计数、降采样摘要、事件去重水位、窗口锚点与告警状态须持久化，事务提交后才对查询可见；重启后须恢复各窗口计数与预算并使查询结果与重启前一致，未提交的写入不得出现，恢复时须识别已被降采样分桶的摘要避免重复聚合。
7. 实现并发查询与写入的一致性：事件摄入与多窗口查询可能并发，查询须看到某个一致的时间点快照，不得观察到部分写入导致某窗口计数与总请求数矛盾；并发摄入同一序号须只有一个生效，降采样与摄入同时进行时被聚合分桶的边界须锁定，保证不丢失也不重复计数。
8. 提供本地样本与完整示例：内置确定性样本生成器（固定随机种子）生成含乱序、迟到、超容量与突发故障的至少二十万条事件，示例脚本展示多窗口 SLI、降采样误差上界、告警决策与重启恢复；pytest 用例须在 Windows 离线可重复覆盖乱序补算、迟到拒绝、降采样精度、告警组合规则、重启一致性与并发快照。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
