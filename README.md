当前是空白工作区，需要从零实现一个本地 QUIC 传输协议的丢包恢复与拥塞控制推演引擎，并交付数据处理管线与结果验证工具。与面向字节流的 TCP 不同，QUIC 以包号空间与帧为单位推进：每个数据包携带若干 STREAM 帧与 ACK 帧，包号单调递增且不可重排使用，丢包判定依赖 ACK 帧中的确认区间与包号阈值，拥塞控制以包为单位记账而非以字节为单位。本地 JSON 场景文件给出：连接参数（初始最大数据量、初始最大流数量、每条流初始流量控制额度、最大 UDP 载荷字节、ACK 延迟因子）、收发行为脚本（按可注入逻辑时钟描述的应用层写流、ACK 帧到达并携带确认区间与接收时间、探测超时、路径 MTU 变化、对端 MAX_DATA 与 MAX_STREAM_DATA 帧更新、连接关闭帧）、拥塞控制配置（初始拥塞窗口以包计、慢启动阈值、拥塞避免算法参数、持久拥塞检测阈值与恢复参数、探测超时退避上限）以及观测采样配置。引擎需以注入逻辑时钟推进 QUIC 的包发送、ACK 处理、丢包检测与拥塞窗口演进，计算任一时刻可发送的包数与可发送的流内字节区间，并记录每个事件后的窗口账本与状态轨迹。核心难点在于：包号空间存在多个（初始、握手、应用），ACK 确认区间可能跨包号空间且存在重叠与乱序，丢包检测既要按包号阈值又要按时间阈值判定；拥塞窗口以包计而流量控制以字节计，两者在可发送判定中必须联合又不互相回退，任何浮点增量的舍入余量若丢失都会在多次拥塞避免后使可发送判定在容差边界翻转；引擎需同时维护事件驱动推演路径与逐时刻全量重算路径两条轨迹并逐事件比对，任何分歧都必须能归因到具体事件、具体换算登记与被依赖的观测。

任务环境与准备：
安装 Python 3.11 及以上版本，并用 pip 安装 numpy 与 pytest（版本以本地可用为准）。
在空白工作目录下创建项目根与 data、state 子目录，并准备本地 JSON 场景文件（连接参数、收发行为脚本、拥塞控制配置与观测采样配置）。
确认 SQLite 由 Python 标准库 sqlite3 提供，无需额外服务；所有推演在本地单机完成，不使用容器、外网或真实网络对端。

业务要求：
1. 实现连接参数与收发行为脚本的解析校验：初始最大数据量与每条流额度为正整数，最大 UDP 载荷字节在协议允许范围内，ACK 帧携带的确认区间必须合法（下界不大于上界且落在已发送包号范围内），探测超时事件不得引用尚未发送的包号，MAX_DATA 更新不得使额度回退；非法场景须返回明确业务错误码（如 E_BAD_SCENE、E_ACK_RANGE、E_FC_REGRESS）且不写入任何持久化状态。
2. 实现多包号空间的发送与 ACK 处理状态演进：在初始、握手、应用三个包号空间内分别分配单调不减的包号并记录每个数据包携带的帧摘要，ACK 帧的确认区间须按包号空间归属拆分并合并重叠区间；已确认包不得再次确认，被声明为已确认的包不得再次进入丢包判定，每个包的状态迁移须记录触发帧序号与逻辑时钟毫秒值，使任一包状态可由事件序列重新推导。
3. 实现丢包检测并以包为单位记账拥塞窗口：同时支持按包号阈值（收到更大包号的 ACK 即判定较小未确认包丢失）与按时间阈值（包未确认时间超过探测超时）两种判定来源，两种来源判定同一包丢失须去重；拥塞窗口以包计随慢启动与拥塞避免演进，拥塞避免阶段每次增量的标度、舍入方向与被舍弃余量必须逐次登记并在下次增量中参与累加，使同一逻辑时钟序列重复推演得到逐位一致的窗口包数序列。
4. 实现拥塞窗口（包计）与流量控制（字节计）联合的可发送判定：任一时刻可发送包数不得超过拥塞窗口余量，可发送字节不得超过连接级与流级流量控制额度的较小余量，两者任一不足即限制发送但不得使另一维度回退；每个事件后输出可发送包数、各流的可发送字节起止偏移与两个维度各自的余量定点表示，输出须为稳定排序且可直接与全量重算结果逐字段比对。
5. 实现基于注入逻辑时钟的探测超时与退避：探测超时只依据注入的逻辑时钟毫秒值与当前平滑往返时延估计判定，延迟确认不得使超时提前触发；超时后退避倍数按确定性规则递增并受退避上限约束，超上限须返回明确业务错误码并令连接进入可诊断失败态；须区分“尚未启动探测即被放弃”与“已启动后超时”两类结局，不得把未启动状态记为超时。
6. 实现事件驱动推演与逐时刻全量重算的双路径轨迹一致性校验：两条路径对同一场景得到包状态、拥塞窗口与可发送区间轨迹后逐事件比对，任何不一致须输出首个分歧事件号、两条路径的中间值、该事件依赖的观测（ACK 确认区间与接收时间采样点）以及涉及的换算登记序号；一致性判定必须基于持久化轨迹而非内存对象。
7. 实现持久化状态与强制终止后的恢复：把各包号空间的最大已发送包号、拥塞窗口与慢启动阈值、在途未确认包集合摘要、流级与连接级额度、在途探测超时状态、舍入登记序列与逻辑时钟水位以事务原子写入 SQLite，每次推演提交识别版本变化并整体替换当前轨迹指针而非逐条覆盖；进程被强制终止后恢复路径须识别已提交事件与半提交事件，只重放水位之后的事件且不重复计入任何包确认或窗口额度，恢复失败不得声称生成完整轨迹。
8. 实现多进程并发一致性与可重复命令行演示：多个推演实例并行处理同一场景的不同事件段时，通过 SQLite 事务与文件锁保证同一事件同一版本轨迹只提交一次、同一包号不被并发重复确认、同一流量控制额度不被并发超发，重复提交相同事件结果必须幂等，读取方只能看到完整已提交轨迹；提供 run、resume、status、verify 子命令，status 以稳定排序 JSON 输出各包号空间最大包号、拥塞窗口、在途包摘要与逻辑时钟水位，verify 校验持久化轨迹与双路径校验结论一致。
