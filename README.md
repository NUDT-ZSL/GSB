在空白工作区从零实现一个跨组件数据处理管线及其结果验证工具，用于在本地确定性样本上复现多组件协同中的状态演进与恢复一致性问题。管线由三个本地组件构成：采集器按批次读取本地 JSON 批次文件（每批含记录键、数值字段、标签与批次序号）；转换器对记录执行归一化、去重与聚合，产出中间结果；汇出器把中间结果按稳定顺序写入本地结果文件与 SQLite 元数据库。三个组件通过持久化的批次账本协同：每个批次在账本中记录阶段状态（已登记、已转换、已汇出、已作废）、逻辑时钟戳与内容摘要。管线支持在任意阶段被强制终止后依据持久化状态恢复，识别未提交阶段并只重放未完成步骤；同时提供 verify 子命令依据持久化账本与结果文件比对一致性与完整性。所有数据、时钟与批次均为本地固定样本，不依赖网络与外部服务。

任务环境与准备：
安装 Python 3.11 及以上版本，确保 sqlite3 标准库可用
安装 NumPy（用于确定性数值聚合），版本需与 Python 3.11 兼容
在空白工作区创建项目目录，准备固定的本地 JSON 批次样本与故障注入清单
确认工作目录可写，用于 SQLite 账本文件与结果文件的原子落盘

业务要求：
1. 实现批次采集与账本登记：读取本地 JSON 批次文件，校验批次序号唯一性、记录键格式、数值字段类型与标签枚举合法性，把批次内容摘要（确定性哈希）与登记状态原子写入 SQLite 账本；非法批次必须返回明确业务错误码并保持账本与其他批次状态不变。
2. 实现转换器的确定性数值管线：对通过校验的记录执行归一化、按键去重与分组聚合，浮点运算顺序与聚合顺序必须固定，使相同输入在任意运行次数下产生逐位一致的结果，并记录每个输出记录到来源批次与记录键的追溯映射。
3. 实现跨组件阶段推进与状态机：批次在已登记、已转换、已汇出、已作废之间按规则迁移，每步推进必须依据账本中持久化的前置状态与内容摘要裁决，不得凭内存残留决定；摘要不匹配时拒绝推进并给出业务错误码。
4. 实现强制终止后的恢复一致性：任一阶段被强制终止后，恢复路径依据账本识别未提交阶段与半写入产物，只重放未完成步骤且不得重复已完成步骤；恢复后结果文件与账本必须描述同一组已提交批次，不得出现账本已汇出而结果缺失或结果多余。
5. 实现并发与幂等控制：允许多个处理实例并行推进不同批次，通过 SQLite 事务与文件锁保证同一批次同一阶段只提交一次，重复提交相同阶段结果必须幂等；读取方只能看到完整已提交的阶段状态而非中间态。
6. 实现作废与重放语义：对标记作废的批次，账本记录作废来源与逻辑时钟戳，其结果记录必须从后续聚合视图中排除但保留审计痕迹；重新激活同一批次序号时必须识别为新的逻辑版本，旧版本的追溯映射不得被覆盖。
7. 实现异常链路与业务错误码：批次文件缺失、JSON 畸形、记录键重复、数值溢出、摘要不匹配、账本版本回退分别映射到不同业务错误码，并在输出中保留可诊断字段；单个批次异常不得中断其他批次的正常推进或污染已提交结果。
8. 提供命令行接口与结果验证工具：支持 ingest、transform、export、resume、status、verify 子命令，status 以稳定排序输出每批次的阶段、摘要与逻辑时钟，verify 依据账本与结果文件比对记录数量、追溯映射与摘要一致性；使用固定本地样本两次运行输出完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地样本验证批次状态推进、强制终止后恢复与 verify 一致性检查，异常批次返回明确业务码。
