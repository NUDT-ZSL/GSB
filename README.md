在空白工作区从零实现一个本地正向与反向代理转发系统的配置热更新与依赖失效诊断工作台。代理系统支持正向代理（CONNECT 隧道与普通 HTTP 转发）和反向代理（按 Host/Path 路由到本地上游测试服务），上游由本地可编程 HTTP 测试服务模拟，可按路径返回状态码、延迟、畸形响应与断开连接。代理行为由一组声明式配置对象描述：监听规则、路由匹配、上游组、健康状态、超时与重试预算、连接复用参数，对象之间可相互引用（路由引用上游组，上游组引用成员，重试策略被多路由共享）。运行期通过配置接口提交增量更新（新增、修改、删除对象），代理需在不中断既有连接的前提下让更新生效，并精确判定哪些缓存与依赖（路由解析结果、上游成员快照、连接池、健康状态缓存、重试策略快照）因此失效需要重建。工作台需持久化版本化配置、依赖图与失效事件，支持强制终止后恢复并解释任意一次转发的路由决定链。

任务环境与准备：
Windows 10/11，安装 Python 3.11 或以上，创建虚拟环境并确认 asyncio 与 sqlite3 标准库可用（无需第三方网络库）
准备本地可编程 HTTP 上游测试服务脚本，可按路径返回状态码、延迟、畸形响应与主动断开，仅监听回环地址
准备固定本地配置样本与脚本文本，包含路由、上游组、成员、重试策略及引用关系，并附增量补丁样例
为强制终止恢复测试预留可重放的操作序列说明，随机数与抖动规则需可在样本中固定

业务要求：
1. 实现声明式配置对象模型与依赖图：监听规则、路由、上游组、上游成员、重试策略五类对象以 ID 相互引用，加载时校验引用闭合性与字段合法性，构建对象级依赖图并检测环；非法引用或循环必须返回业务错误码且不改变已生效版本，并提供图查询接口返回指定对象的直接与传递依赖。
2. 实现增量配置更新与依赖失效判定：以补丁形式提交对象的新增、修改、删除，计算受影响对象闭包，精确标记解析缓存、成员快照、连接池、健康缓存与重试策略快照中哪些失效需重建、哪些可安全复用；未受影响的路由在更新前后必须继续用原缓存服务，不得全量重建。
3. 实现反向代理转发与路由决定链记录：按 Host 与 Path 最长匹配选择路由与上游成员，执行连接、超时与重试预算，成功与失败均记录完整决定链（命中的配置版本、路由、上游成员、失效与重建原因），决定链须可回放重放且与配置版本严格对应。
4. 实现正向代理 CONNECT 隧道与普通 HTTP 转发：正向路径的隧道与请求必须与反向路径共享同一并发与超时预算模型，隧道建立后按字节双向转发，客户端或上游单侧断开需及时释放另一侧并计入统计；不得让隧道长期占用已失效的路由缓存。
5. 实现版本化持久化与强制终止恢复：配置版本、依赖图、失效事件与决定链原子写入 SQLite，每次提交产生新版本号并整体替换当前快照指针；强制终止后恢复时识别未提交版本与半写入事件，能正确回滚到最近完整版本，并重建当前生效快照索引，恢复结果与提交顺序一致。
6. 实现并发一致性与幂等：允许多个更新请求与转发请求并发，通过 SQLite 事务与文件锁保证同一版本号只提交一次、同一更新请求重复提交幂等；转发请求读取快照时必须看到某个完整版本而非更新中间态，连接池重建不得导致已复用连接被错误关闭或遗漏回收。
7. 实现异常链路与业务错误码：上游连接拒绝、响应超时、畸形响应头、上游提前断开、配置引用缺失与环、补丁格式错误分别映射到不同业务错误码，转发层与配置层异常互不污染；单次失败不得中断监听循环或提交不完整配置版本。
8. 提供命令行工作台与可重复演示：支持 serve、apply、graph、explain、status 子命令，explain 以稳定排序输出指定请求的决定链与失效原因，status 输出各缓存命中与重建计数；使用固定本地样本与脚本化请求执行两次，输出完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本与测试上游验证增量更新生效、依赖失效精准、决定链可回放及恢复一致性。
