当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向 OCR 文字检测识别的本地可视化诊断工作台。业务对象是本地确定性生成的页面样本：每页由固定种子在固定尺寸灰度画布上按版面模板绘制若干文本行，每行由确定性笔画模板拼出并携带真值框与真值字符串；页面清单为 JSONL，字段含 page_id、image_seed、image_shape、line_count、charset_version、policy。识别链路被建模为有向无环计算图：页面预处理→文本行检测→行区域特征提取→字符模板匹配打分→行识别输出→页面指标聚合。每个节点产出带内容哈希的中间产物写入本地内容寻址缓存，缓存命中可跳过重算。核心业务问题是增量更新与依赖失效：当字符模板库提升版本、追加新页面、修正某行真值或调整检测阈值时，只有依赖这些输入的节点与行需要重算，其余必须复用旧缓存；但缓存键必须覆盖全部语义输入，模板库版本变化时旧快照必须整体替换而非增量修补，任何失效遗漏或错误复用都必须能被诊断出来并定位到具体行。

任务环境与准备：
安装 Python 3.11 及以上版本，并确认标准库 tkinter 可用。
使用 pip 安装 NumPy，版本 1.26 或更高，用于确定性像素数组与特征计算。
准备一个空工作目录作为项目根目录，任务开始前其中不存在任何源码或数据文件。
确认本地无网络依赖，所有样本由代码内固定种子生成，不使用任何外部图像或 OCR 模型资源。

业务要求：
1. 实现确定性的 OCR 计算图：把页面预处理、文本行检测、行区域特征提取、字符模板匹配打分、行识别输出、页面指标聚合建成有向无环图，节点连接由配置决定；同一 page_id、同一 image_seed 与同一配置下必须逐字节一致的中间行框、逐行识别串与页面指标，禁止依赖系统时间、字典遍历顺序或未声明状态。
2. 实现内容寻址缓存与缓存键构造：每个节点产物附带内容哈希写入本地缓存目录，缓存键须纳入页面像素内容哈希、行框摘要、字符模板库版本、检测阈值与上游节点哈希；键相同必须复用快照，键不同必须重算，且每个缓存条目须能导出键组成明细供诊断查看，键组成缺项时返回 E_CACHE_KEY_INVALID 并指出缺项字段。
3. 实现增量更新的依赖失效传播：追加新页面、提升字符模板库版本、修正单行真值或调整检测阈值时，计算受影响节点与受影响页面及行集合，复用未受影响上游缓存，仅重算受影响后缀；须输出本次重算节点清单与复用节点清单，并保证未受影响的页面识别串与指标逐字节不变。
4. 实现字符模板库版本变化与整体替换：模板库携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧模板快照而非增量修补；损坏或校验和不符的条目在读取时返回 E_CACHE_CORRUPT 并指明版本号，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK，版本未变的快照必须复用而不得重算。
5. 实现按行分块识别与整页一次性识别的逐字节一致性：块边界处的特征归一化统计量、行间去重阈值与置信度量化口径必须与整页口径完全相同，逐块拼接结果与一次整页识别结果逐行逐字符相同；检测到差异返回 E_CHUNK_MISMATCH 并输出首个不一致的行号与字符位置。
6. 实现资源与并发写控制：为单页行数、模板匹配候选比较次数、缓存条目总量与驻留特征内存估算设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或降级为逐行流式识别并标记降级类别；多个任务并发写同一缓存键时须保证只有一个提交生效，并发提交冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待，冲突不得破坏已提交条目。
7. 实现跨模块一致性自检与异常链路归因：校验图拓扑无环、缓存键与产物哈希互相可核对、复用节点集合与重算节点集合无交集且并集覆盖全部受影响节点、页面指标可由逐行明细独立重算一致；检测到不一致返回 E_INCONSISTENT 并输出不一致类别与定位信息；解析失败、检测空结果与模板匹配失败须归因到具体 page_id 与阶段名。
8. 提供本地可交互诊断工作台与可重复演示：展示计算图拓扑、各节点缓存命中或重算状态、失效传播覆盖的页面与行、字符准确率与行准确率、模板库版本、最近业务错误码，允许点击节点查看缓存键组成与内容哈希，并触发一次演示——加载本地确定性样本、提升模板库版本、执行增量识别并与识别整页结果做一致性对照，演示不依赖外部服务或真实图像资源。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
运行本地确定性页面样本，验证增量识别复用正确、模板库版本变化整体替换及整页一致性。
