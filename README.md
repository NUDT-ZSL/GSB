安全运营团队需要在 Windows 空白工作区独立实现一个离线告警关联与去噪引擎，用于判定同一批主机入侵检测告警在两代关联规则下是否给出同一份事件簇划分。工作区当前没有代码与样本，全部输入由随工程交付的固定种子脚本确定性生成，不依赖网络、账号或真实主机。业务对象包含三部分：告警流为 JSONL，每行含 alert_id、host_id、alert_ts_ms（整数毫秒）、rule_key、severity（整数档位）、process_guid、parent_process_guid 与 payload_digest；两代关联规则快照并存，v1 为单文件 JSON，记录相对生效秒、扁平匹配串列表、去重窗口秒与启用标记，v2 为分片 JSON 加 SQLite 元数据库，记录规范规则键、绝对生效毫秒时刻、规则代数、去重窗口毫秒、墓碑标记与依赖的父规则键；另有一份按逻辑时钟注入的规则补丁批次流。引擎须把告警按规则版本与去重窗口归并为事件簇，识别补丁到达后受影响的告警与事件簇，并在受控并发与资源预算下完成重算。真正的难点是规则代数切换与去重窗口口径（v1 相对秒与 v2 绝对毫秒）耦合在同一归并键上：窗口端点量化误差会让本应归入同一簇的告警分属两簇，而补丁批次乱序到达又可能让已提交的簇划分失效。

任务环境与准备：
Windows 本地工作区，Python 3.11 通过官方安装包安装并加入 PATH，验证 python --version 与 pip --version 可执行。
安装依赖：pip install pytest==8.2.0（仅测试使用），标准库 sqlite3、json、hashlib、threading 直接可用，不引入其他第三方库。
运行随工程交付的固定种子样本生成脚本，在本地生成告警流 JSONL、v1/v2 规则快照、规则补丁批次流与真值同步标记文件，生成过程不访问网络。
确认工作区可写并预留 SQLite 数据库、检查点目录与快照临时目录，执行示例命令前先运行 pytest 收集阶段确认无缺失文件。

业务要求：
1. 实现告警流、两代规则快照与补丁批次的严格解析规范化层：校验 alert_id 唯一性、同一 alert_id 内 alert_ts_ms 为非负整数且不冲突、severity 落在声明档位区间、rule_key 可被规则快照解析、payload_digest 格式合法；v1 的相对生效秒与去重窗口秒须为非负整数，v2 的绝对毫秒时刻、规则代数与去重窗口毫秒须为非负整数且规则代数在链上单调；对非法记录输出含来源类别、记录序号与稳定业务码的拒绝清单并继续处理其余记录。
2. 把 v1 与 v2 规则快照合并为统一规则视图：v1 的相对生效秒须以样本声明的观测时钟为唯一基准换算为绝对毫秒，禁止使用系统当前时间；同一规范规则键按规则代数与生效时刻裁决权威来源，墓碑标记必须覆盖较早的非墓碑记录；当两代对同一规则键的去重窗口、匹配串或启用标记给出不一致结论时输出 E_RULE_CONFLICT 并标明冲突字段与两侧依据代数。
3. 实现告警到规则版本的时间轴定版：每条告警须绑定其 alert_ts_ms 时刻生效的规则版本，邻近窗口边界的告警须给出定版余量；当两代时间口径换算后告警落点处于两候选规则生效区间的重叠带时不得随意择一，须单列 E_VERSION_AMBIGUOUS 并给出两个候选规则键与各自依据代数，该业务码须计入报告且不影响其余告警定版。
4. 实现事件簇归并：对同一 host_id 上归并键相同（按规则键与规范化 payload_digest 派生）、告警时刻落在当前生效去重窗口内且 process_guid 谱系可达的告警归入同一事件簇，簇代表取最早告警时刻并以规范键破平；检测 process_guid 与 parent_process_guid 构成的谱系环并返回 E_PROC_CYCLE 且列出环中标识序列；簇划分结论须与告警到达顺序无关。
5. 实现去重窗口口径的精度诊断：v1 的去重窗口秒换算到毫秒后须显式给出窗口端点量化误差界，并为每个事件簇累计窗口边界判定余量；当某条告警的加入判定因累计误差界跨越窗口端点阈值而在定点路径与 float64 参考路径下结论不同时，单列 E_WINDOW_AMBIGUOUS 并报告两条路径各自的簇归属与残差，该簇不得被静默合并。
6. 实现规则补丁增量到达后的失效闭包：每个补丁批次在单个 SQLite 事务内完成，前置校验失败不得改动账本；补丁使某规则窗口、匹配串、启用标记或墓碑状态变化时，沿规则键到告警到事件簇的依赖关系计算需重算的告警与簇集合，仅重算受影响部分，并要求重算后的规则视图、簇划分、歧义清单与拒绝清单与从零全量重算逐字段一致，不一致返回 E_RECOMPUTE_MISMATCH。
7. 实现受控并行调度与真实资源预算：以 host_id 为独立任务单元按可配置并发度执行归并，并对整批设置单主机实测耗时上限、待处理主机队列上限与单主机告警处理数上限；耗时须以真实墙钟测量判定而非人为延迟常量，超时返回 E_TIMEOUT 并终止该主机后续处理、队列超限须拒绝入队并计入报告、超告警数返回 E_BUDGET；任意并发度与任意到达顺序下结论必须与串行执行完全一致。
8. 实现检查点演进、原子快照整体替换与强制终止后的恢复边界：按已应用补丁水位与簇划分摘要把检查点持久化到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放比对以识别半写残留；检查点结构版本或规则合并口径版本变化时须整体重建而非增量续接；检查点与诊断报告均先写临时文件并在校验内容可解析后整体重命名替换，同一工作目录并发写入以文件锁串行化且锁冲突返回 E_LOCK；进程被强制终止后不承诺生成退出报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
