当前是空白工作区，需要从零构建一个面向本地 Windows 环境的文档数据库查询执行引擎组件。引擎以本地 JSON 文档集合为存储载体，文档为嵌套对象，支持按字段路径（点分路径）过滤、投影、排序与分页的查询；一次查询经解析为规范化查询标识后，进入计划阶段选择扫描与索引路径，再进入执行阶段产出结果集。核心业务是：同一查询在多次执行中必须产出逐字节一致的结果与稳定的执行统计；当文档集合被增量修改时，依赖该集合的查询计划缓存与统计快照须被识别失效；整个查询会话（集合版本、计划缓存、执行追踪、结果摘要）需持久化为可命名快照并支持整体替换恢复；引擎还需支持以命令行参数注入文档损坏、计划缓存过期、结果重放不一致三类异常并给出可复现的业务码报告。

任务环境与准备：
安装 Go 1.21 或更高版本并确认 go 命令在 PATH 中可用。
在空白工作区初始化 Go 模块，仅使用标准库 encoding/json、net/http 与 os 等。
准备本地确定性样本集合 JSON 文件与演示脚本，全部位于工作区目录内，不访问网络。
运行环境为 Windows，演示与校验均通过本地命令行执行。

业务要求：
1. 实现本地文档集合的加载与强校验：从本地 JSON 文件读取集合定义与文档数组，文档字段支持嵌套对象与标量；校验集合名唯一、文档主键字段存在且唯一、字段路径片段只允许字母数字下划线、非法文档须以 E_DOC 业务码整体拒绝加载并指出首个出错文档下标与字段路径。
2. 实现查询解析与规范化标识：支持字段路径等值、范围、IN 列表与 AND/OR 组合的过滤条件，以及投影字段列表、排序键与分页偏移限制；同一语义查询在空白、键顺序与大小写折叠差异下必须得到相同规范化文本与查询标识，含不支持语法的查询返回 E_QUERY。
3. 实现计划选择与计划缓存：对每个规范化查询在可用路径（全量扫描与基于字段路径的候选索引）间按确定性代价规则选择执行计划，计划中记录所用索引与代价明细；计划缓存以集合版本号与索引集合版本号为键，任一版本变化后旧计划须被识别为过期并重新编译，缓存条目整体替换而非增量合并。
4. 实现查询执行器与稳定结果输出：按选定计划执行过滤、投影、排序与分页，排序需基于显式排序键与稳定决胜规则，结果集序列化后须逐字节一致；执行统计包含扫描文档数、命中文档数、所用路径与集合版本，相同输入多次执行必须得到相同统计。
5. 实现跨查询的结果与计划一致性校验：提供校验命令，对同一查询用扫描路径与索引路径分别执行并逐文档比较结果是否等价，索引路径与扫描路径结果不一致时以 E_PLAN 业务码报告并列出首个差异文档主键；索引集合为空时校验须退化为仅验证扫描路径并明确标注。
6. 实现查询会话快照与整体替换恢复：快照持久化集合版本、索引集合版本、计划缓存、查询历史与各查询结果摘要；恢复时先比较快照版本与当前会话版本，若不一致须整体替换当前集合、索引与计划缓存状态而非增量合并，恢复后重复执行历史查询须得到相同结果摘要，版本缺失导致不可复现时返回 E_REPLAY。
7. 实现异常注入与结构化日志：支持以命令行参数分别注入文档损坏、计划缓存过期、结果重放不一致三类异常，三类异常须以 E_DOC、E_CACHE、E_REPLAY 业务码报告并写入结构化日志；注入仅改变输入文件或启动参数，不得修改引擎源码或测试用例来制造失败。
8. 提供可集成的组件 API 与完整示例：以 Go 包暴露集合加载、查询解析、计划选择、执行、校验、快照保存与恢复的接口，并附带本地确定性样本集合与演示脚本，顺序执行首次全量查询、修改集合后增量查询、快照恢复后重放三个场景，输出顺序稳定且包含业务码与统计摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证查询结果逐字节一致、计划缓存失效识别与快照恢复重放，并触发三类注入异常。
