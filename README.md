交付从新建的代码库开始，需要从零实现一个本地时序指标采集引擎的分区落盘与配额令牌账本组件，以算法实现与可复现实验环境的形式交付。业务目标是：多条指标流按标签哈希分入固定数量的存储分区，每条流到达时须在每租户写入字节配额与全局落盘令牌双重约束下裁决写入、缓冲还是丢弃，并在配额耗尽时按确定性规则追平缓冲区，使落盘顺序与账本在中断恢复后仍可复现。本地 JSON 样本给出：指标流清单（租户名、指标名、标签集合、采样周期逻辑毫秒、单样本字节数）、分区配置（分区数、每分区缓冲条数上限、每轮落盘条数上限、每轮逻辑时间预算）、租户配额声明（每租户每逻辑窗口写入字节上限、借调上限、是否允许借调）以及令牌配置（全局落盘令牌桶容量、补充速率、逻辑时钟步进）。全部时间判定只依赖注入的逻辑时钟毫秒值，不读取系统墙钟。

任务环境与准备：
安装 Python 3.11 或更高版本，并确认命令行可执行 python --version 与 pip --version。
创建本地虚拟环境（python -m venv .venv），Windows 下通过 .venv\Scripts\activate 激活后执行 pip install numpy==1.26.4 与 pip install pytest==8.2.2。
工作区 samples 目录放置指标流清单、分区配置、租户配额声明、令牌配置与用于恢复验证的样本 JSON，全部由本地脚本生成且不依赖外部数据源。
确认 Python 标准库 sqlite3 可用，无需安装外部数据库服务；SQLite 状态库、缓冲区文件与日志统一放在工作区内固定目录。
全程不依赖容器、外部网络、真实监控系统或 GPU，测试在单机 Windows 上以注入逻辑时钟驱动。

业务要求：
1. 实现指标流清单、分区配置、租户配额声明与令牌配置的解析校验：租户名与指标名组合唯一、标签键值格式合法、分区数为正整数、缓冲条数上限与每轮落盘条数上限为正整数、采样周期与非负整数窗口边界条件一致、单样本字节数为正整数、令牌桶容量与补充速率为正整数；非法输入返回明确业务错误码（如 E_BAD_STREAM）且不写入任何持久状态。
2. 实现按标签哈希的确定性分区路由：同一租户同一指标同一样本必须始终映射到同一分区，分区映射规则与哈希种子固定使相同输入逐位复现；每个分区维护独立的到达序号单调递增且不跳号，跨分区允许并行但全局到达顺序须由注入逻辑时钟与样本序号共同界定并输出可核对的归属清单。
3. 实现每租户字节配额账本与配额窗口切分：按注入逻辑时钟把写入归属到租户的配额逻辑窗口，每窗口已用字节、剩余配额与借调量须在同一事务内随写入原子更新；同一租户同一窗口重复提交相同样本必须幂等且不得二次计入已用字节，窗口切换时须从前一窗口账本结出冻结余量作为审计依据。
4. 实现全局落盘令牌桶与每租户配额的联合落盘裁决：每轮落盘前同时检查租户剩余配额与全局令牌余额，令牌按补充速率与注入逻辑时钟累加，任一不足即裁决为缓冲而非丢弃并记录首个触发约束（租户、窗口、所需字节或所需令牌）；租户允许借调时在借调上限内可借用额度，借出量须单独记账并标记归还义务。
5. 实现积压缓冲的确定性追平调度：缓冲区满或配额恢复后按租户、窗口与到达序号的稳定次序追平落盘，同时受每轮落盘条数上限与每轮逻辑时间预算约束；预算耗尽须放弃剩余未落盘样本并记录放弃原因，严格区分预算内未启动、落盘后失败与主动放弃三类结局，已启动落盘不得被截断后记为未启动。
6. 实现配额与令牌账目的误差记录及精度敏感标记：已用字节、剩余配额、借调量与令牌余额按声明定点标度换算，登记每次换算的标度、舍入方向与被舍弃余量并累计加法乘法的误差上界；当两个租户或两个分区的可用额度差小于比对容差且落盘裁决依赖该差值时标记为精度敏感，输出误差来源链（租户、窗口、登记序号与换算步骤）。
7. 实现账本与缓冲状态的持久化及强制终止后的恢复裁决：把分区到达水位、每租户每窗口已用字节与借调账本、令牌余额与上次补充时刻、缓冲区内容摘要、精度敏感标记与逻辑时钟水位以事务原子写入 SQLite，每轮提交以版本号整体替换当前账本指针并拒绝版本回退；进程在落盘或账本提交中途被强制终止后，恢复路径识别已提交样本与半提交缓冲，只重做缺失样本且不重复计入已用字节或令牌扣减。
8. 实现多进程并发一致性、幂等提交与可重复命令行演示：多个落盘实例并行处理不同分区时，通过 SQLite 事务与文件锁保证同一分区的同一样本序号只落盘一次、租户配额与全局令牌不被并发超扣、借调账本不被重复记账，重复提交相同样本必须幂等；提供 load、ingest、flush、resume、status、verify 子命令，status 以稳定排序 JSON 输出各租户已用字节、令牌余额、缓冲深度与精度敏感记录。
