在空白工作区从零实现一个本地 DNS 解析缓存系统，需兼容两种历史缓存快照格式并将其统一为可查询、可降级、可诊断的多级缓存。v1 快照为单文件 JSON，记录域名、记录类型、TTL 剩余秒数、应答区记录与权威标记；v2 快照为分片 JSON 加 SQLite 元数据，记录域名规范形式、按类型的记录集合、创建时间与过期时间（毫秒时间戳）、否定缓存标记（NXDOMAIN/NODATA）以及缓存代数。本地还提供一个可编程的 DNS 测试服务器（Python 实现，监听本地回环地址的 UDP/TCP 端口），可根据配置的区文件返回 A、AAAA、CNAME、MX、TXT、SRV 记录，并支持注入 NXDOMAIN、空应答、截断应答（TC 置位）与 SERVFAIL。系统需在可注入的逻辑时钟下管理 TTL 递减、过期淘汰、否定缓存与 CNAME 链缓存，并支持在快照整体替换时识别版本变化、拒绝版本回退，同时提供解析、预热、诊断与审计命令行。全部样本、区文件与快照均由本地确定性脚本生成，不依赖任何真实域名或线上 DNS。

任务环境与准备：
Windows 10/11，安装 Python 3.10 或以上，并确保 python 命令可用。
创建全新工作区目录，安装 dnspython 库（pip install dnspython），用于构造和解析本地 DNS 测试服务器的报文。
编写本地确定性样本生成脚本，生成 v1 单文件 JSON 快照、v2 分片 JSON 与 SQLite 元数据库，以及 DNS 测试服务器所用的区文件（A、AAAA、CNAME、MX、TXT、SRV 记录及注入 NXDOMAIN、空应答、截断、SERVFAIL 的场景），所有域名使用本地保留名或自定义后缀，不依赖真实 DNS。
启动本地 DNS 测试服务器，监听回环地址的 UDP 与 TCP 端口，端口号由样本配置指定，确保该端口未被占用。

业务要求：
1. 实现 v1 与 v2 两种快照格式的解析与校验：v1 校验域名合法性、TTL 剩余秒数为非负整数、应答记录与权威标记的对应关系；v2 校验分片文件哈希、SQLite 元数据库中的缓存代数单调性与毫秒时间戳类型、否定缓存标记的枚举合法性；格式错误、字段缺失或哈希不匹配必须返回 E_SNAPSHOT_FORMAT 并保持已有缓存不变。
2. 实现跨版本快照合并与统一缓存索引构建：同一域名同一记录类型在 v1 与 v2 同时存在时，依据快照声明的逻辑时钟与缓存代数裁决最新版本，若冲突且无法裁决则按来源优先级；合并后每个缓存条目须保留来源版本、原始 TTL 或过期时间戳、否定缓存状态与 CNAME 链完整路径，用于后续诊断与审计。
3. 实现 TTL 与否定缓存的统一语义迁移：v1 的剩余秒数 TTL 与 v2 的绝对过期时间戳在注入逻辑时钟下统一换算为绝对过期时刻，换算时记录精度差异；v1 不支持的否定缓存迁移为 v2 语义并标记迁移决策；逻辑时钟回拨或跳跃超过阈值时必须返回 E_CLOCK_ANOMALY 并冻结淘汰，不得删除任何未过期条目。
4. 实现多级缓存查询与 CNAME 链解析：查询按精确键与记录类型命中缓存，CNAME 链需逐级解析并缓存每一跳，返回稳定排序 JSON 包含记录、TTL 剩余、来源版本与链路径；缓存未命中时通过本地 DNS 测试服务器解析并按 TTL 写入缓存；解析中的截断应答需切换 TCP 重试，SERVFAIL 与超时需按负数缓存策略处理，并区分 E_TRUNCATED_RETRY、E_UPSTREAM_SERVFAIL、E_UPSTREAM_TIMEOUT。
5. 实现快照整体替换的版本变化识别：收到新快照包时比较清单版本号、缓存代数下限、各分片哈希与条目摘要，判定完整替换、增量追加或无需操作；整体替换必须整体替换当前缓存快照指针而非逐条覆盖；版本回退必须被拒绝并返回 E_VERSION_ROLLBACK，同时记录被拒绝的审计事件。
6. 实现持久化状态与强制终止后的恢复：把当前缓存快照指针、迁移决策、替换审计记录与淘汰水位线原子写入 SQLite，每批次提交采用临时表加版本号整体替换；进程被强制终止后，恢复路径依据持久化状态识别未提交的合并或替换操作，只重放未提交步骤，不得把半写入的条目暴露给查询。
7. 实现并发一致性与幂等查询：允许多个查询进程与快照替换进程并行，通过 SQLite 事务与文件锁保证同一快照版本只提交一次、同一替换请求重复提交幂等；查询方读取时必须看到某个完整版本的缓存快照而非替换中间态，并发写入相同域名记录时按逻辑时钟与代数裁决，不得出现缓存条目互相覆盖导致代数回退。
8. 实现诊断命令行与可重复演示：支持 load、resolve、warmup、replace、status、verify 子命令；status 以稳定排序 JSON 输出缓存版本、各记录类型条目数、迁移决策数、否定缓存条目数与最近替换审计；verify 校验持久化快照指针与条目摘要的一致性；使用固定本地区文件与快照执行两次完整流程，输出必须逐字节一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
