在空白工作区构建一个面向本地电商搜索的查询理解与意图解析服务，用于对用户查询做归一化、意图分类、实体槽位抽取与查询改写，并输出可复现的实验报告。输入为本地 JSONL 查询样本，每行包含查询 ID、原始查询文本、可选会话上下文与标注字段；同时提供本地小型意图词表、实体词典（品牌、类目、属性限定词）与改写规则表。服务需要实现查询归一化（全半角、大小写、空白与标点折叠）、意图打分（基于词表特征与规则权重的确定性打分，禁止随机性）、槽位抽取（最大匹配加歧义消解）与改写建议生成（同义归一、丢词补全、类目扩展）。核心挑战是可复现验证与异常注入：同一输入在不同批次、不同并发度下必须产出逐字段一致的结果；实验环境要支持按配置注入畸形查询、词典缺失、规则冲突与评分越界等异常，并验证服务在异常下的隔离、业务码与报告链路。所有输入样本、词表、词典、规则表与注入配置均需由实现方在项目内自行定义格式并生成，任务不提供任何数据附件。

任务环境与准备：
安装 Python 3.11 及以上版本，创建虚拟环境并安装 numpy 与 pytest，版本以本地 wheel 缓存为准。
在项目 data 目录放置自备的查询 JSONL 样本、意图词表、实体词典与改写规则表，均为 UTF-8 文本，格式在任务内自行定义并写入文档。
准备注入配置文件与多组并发度、改写条数配置，全部为本地文件，不访问网络。
运行方式为本地命令加 pytest，不依赖数据库、容器或外部服务；Windows 下路径统一使用 pathlib 处理。

业务要求：
1. 实现查询归一化阶段：对每条查询做全半角折叠、英文大小写折叠、连续空白合并与标点剥离，输出归一化文本、被修改位置列表与阶段指纹；空查询或仅含标点的查询产出 E_EMPTY_QUERY 业务码并进入失败清单，不中断其余样本处理。
2. 实现基于词表特征与规则权重的确定性意图打分：从本地意图词表加载各类目的特征词与权重，按命中特征、位置衰减与规则表加分合成每类意图得分，得分做 L2 归一化到 0 至 1；同分时按类目名称字典序确定主意图，禁止使用随机数或线程调度顺序影响结果。
3. 实现实体槽位抽取与歧义消解：对归一化文本做品牌、类目、属性三类词典的最大匹配，重叠候选按最长优先、同长按词典优先级、再按起始位置升序消解；被更高优先级匹配吞并的候选记录为被抑制项，输出槽位列表、被抑制项与 E_SLOT_OVERLAP 计数。
4. 实现查询改写建议生成：基于规则表生成同义归一、类目扩展与丢词补全三类改写，每条建议携带来源规则 ID、触发依据与预估收益分值；建议按预估收益降序、同分按规则 ID 字典序排列，最多输出可配置条数，规则表缺失引用时输出 E_RULE_MISSING 并跳过该条规则。
5. 实现异常注入实验台：以独立注入配置文件指定畸形查询比例、词典条目移除清单、规则冲突对与评分越界样例，注入后服务必须以确定性顺序执行并输出每条样本命中的注入项编号；注入配置本身哈希纳入报告，保证同一注入配置可复现出完全相同的失败清单与业务码序列。
6. 实现并发与串行结果一致性：使用线程池并发处理样本，最大并发数取自配置，每条样本任务携带由查询 ID 与阶段名派生的稳定排序键；无论并发度如何，最终意图结果、槽位顺序、改写建议顺序与失败清单顺序必须与单线程顺序执行逐字段一致。
7. 实现阶段快照与恢复：归一化、意图打分、槽位抽取、改写生成各阶段以临时文件加原子替换方式持久化快照，快照含阶段名、配置哈希、注入配置哈希、已处理游标与结果指纹；恢复时若配置或注入配置哈希不符输出 E_CONFIG_MISMATCH 并拒绝恢复；一致时从游标继续且最终报告与不中断运行一致。
8. 实现失败隔离、退出语义与实验报告：单样本在任一阶段抛异常时记录查询 ID、阶段名、业务码与异常类型并继续其余样本；收到可处理的退出信号时完成当前阶段快照后以整数退出码 0 退出，强制终止后仅依据已持久化快照恢复；报告以原子写盘输出各意图分布、槽位统计、改写条数、注入项命中矩阵、失败清单与各阶段耗时。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本与注入配置验证意图解析结果、并发一致性与恢复后报告，附运行输出。
