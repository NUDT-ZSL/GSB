航空公司的航班保障调度平台里，延误预测与地面保障资源分配两类模型要按航班计划、保障任务与实时运行数据滚动出推理建议，而这些数据的张量形状随当日航班数与保障任务数不断变化，同一模型版本在不同形状下反复触发完整编译使推理延迟难以控制。平台工程师与调度算法维护人员需要一套本地可复现的编译缓存组件：把模型版本与输入张量形状联合编码为编译键，命中即复用编译产物，未命中时只对受形状影响的算子做静态形状专用编译，形状无关子图沿用既有产物；在缓存容量受限与模型版本更新、形状突变的交替事件中，逐请求给出编译键、命中判定、逐出记录、增量重编译范围与命中率统计，并以独立全量编译路径作为数值基准核对专门化产物输出一致。

任务环境与准备：
准备 Linux（WSL Ubuntu）上的 Python 3 运行环境，仅使用标准库，无需安装第三方包或配置外部服务。
从新工作区创建项目，在本地实现确定性工程生成器、编译缓存组件与全量编译基准路径，样本与解析真值均由生成器按固定种子产出。
运行时以命令行入口驱动生成工程、推进请求序列与模型更新事件，并将缓存快照写入本地文件供重启恢复验证。

业务要求：
1. 解析题内确定性生成器按固定种子产出的推理服务工程，包括多个模型的计算图描述（算子类型、输入输出张量形状、静态参数）、模型版本清单、编译缓存配置与按逻辑时刻到达的请求序列，检查图结构引用完整性，对缺失输入、形状维度非正、算子张量不闭合等构造异常的工程输出可识别的业务错误码并跳过该请求。
2. 对每条推理请求以其模型版本与输入张量形状的规范化表示联合生成编译键，输出编译键及各键的缓存查询结果（命中或未命中），同版本同形状必须得到稳定一致的键，不同形状或不同模型版本必须得到不同键，并记录首次出现请求的键登记来源。
3. 对未命中的编译键执行形状专门化编译：识别计算图中依赖输入形状的算子并编译为静态形状专用内核，形状无关子图复用已有编译产物，输出编译产物标识与按算子或子图分项的编译耗时，编译产物标识须由键与子图标识稳定派生以便复算核对。
4. 为编译缓存设定容量上限，容量不足时按最近最少使用策略逐出编译产物并输出含被逐出键与被释放子图范围的逐出记录，逐出后再次出现同一编译键须重新编译并产出与首次一致的编译产物标识，同时汇总整体命中率与累计编译耗时。
5. 处理模型版本更新事件：使该模型全部编译键失效并保留其余模型产物，仅重编译受更新影响的算子或子图，输出增量重编译范围与重编译耗时，同一事件下未受影响子图的编译产物标识必须保持不变。
6. 当请求形状变化而计算图结构未变时仅对新形状触发形状专门化编译并登记缓存，同时命中形状无关子图已有产物，输出形状专门化编译次数与缓存键在各模型版本及形状段上的分布摘要，并核对次数与请求形状序列一致。
7. 以独立全量编译路径为基准逐请求比对推理输出，形状专门化产物与全量编译结果的逐元素误差须在给定容差内，超差时输出请求标识、超差元素位置与最大偏差值并记为不一致，同时说明专门化路径实际减少的编译工作量。
8. 将编译缓存状态与编译键映射以快照持久化到本地文件，重启后从最近快照恢复并对恢复后请求复算编译键与命中判定，要求恢复后命中判定与中断前一致，快照写入须整体替换并识别版本变化，恢复不得依赖重新全量编译。

验收：
以确定性推理服务工程与边界样本核对编译键、命中判定、逐出记录与增量重编译范围，并与全量编译基准逐请求比对输出一致。
