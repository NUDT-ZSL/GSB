本地工作区尚为空目录，需按新方案独立实现一个 LLM 预训练语料去重环节的诊断工作台。全部输入由固定种子脚本在 Linux（WSL Ubuntu）上确定性生成，不依赖外部网络或数据集。业务对象包含语料分片清单（JSONL，每行含 shard_id、doc_id、text、lang、source、token_estimate、content_hash）与去重配置：分块签名长度、相似度阈值、候选比较窗口、校验模式（full 或 digest）及采样种子。工作台将去重校验建模为多级计算图：分片摄入与校验→分块签名生成→候选桶划分与签名摘要→候选比较与相似判定→结果聚合与统计导出。核心业务问题是签名配置跨版本演进时的增量失效传播，以及按 doc_id 的交互查询与批量全量处理的结果一致性。

任务环境与准备：
在 Linux（WSL Ubuntu）上安装 Python 3.10 及以上版本，并安装 NumPy、pytest 依赖。
在工作目录中新建空文件夹作为项目根目录，将随题交付的固定种子样本生成脚本放入 scripts/ 目录，运行该脚本生成本地语料分片 JSONL 与配置 JSON 文件。

业务要求：
1. 实现确定性的分片摄入与分块签名生成节点：按 shard_id 与 doc_id 升序解析 JSONL 分片，校验归一化 text 非空、content_hash 与文本一致性，并按配置分块长度把归一化文本切分为若干签名块，输出每个文档的块签名列表、文档级签名摘要与桶归属，同一输入与同一配置下必须逐字节相同。
2. 实现基于哈希桶的候选对生成与签名摘要比较节点：按文档级签名摘要分桶，仅在相同桶内并按配置候选比较窗口生成候选对，窗口外文档不得比较；候选对比较返回命中块位置与相似度摘要，比较过程必须记录每对候选的签名块偏移与摘要冲突状态。
3. 实现相似判定与代表筛选节点：按命中块位置计算相似度，相似度达到配置阈值时判定为近重复对，并按质量分降序、再按 doc_id 升序保留代表，被剔除文档必须记录其近重复邻居、命中块位置与阈值比较明细，判定过程不得使用任何隐式排序或近似截断。
4. 实现签名配置（分块长度、候选窗口、阈值、校验模式）与语料分片修订的增量依赖失效传播：缓存键纳入分片内容哈希、配置版本与上游节点哈希，配置增加版本号或分片 content_hash 变化时计算受影响文档与受影响节点集合，复用未受影响上游签名与比较结果，仅重算受影响后缀并输出重算文档清单、复用文档清单以及两者是否无交集且并集覆盖全部分片。
5. 实现按 doc_id 的交互查询接口与批量全量处理的一致性裁决：单文档查询返回该文档的块签名、候选比较轨迹、相似判定结论与剔除状态，查询结果必须与批量全量处理结果中同一 doc_id 的记录逐字节一致，延迟以本地查询循环实际计时为观测并按比较次数和签名块数给出估算记录，超配置预算返回 E_LATENCY_BUDGET。
6. 实现签名与判定结果的内容寻址缓存和配置快照的整体替换：每个节点产物以内容哈希落盘，缓存键须纳入该节点全部输入摘要、上游产物哈希、配置版本与参数，键相同必须复用、键不同必须重算；签名配置、统计量与剔除清单快照各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照，回退尝试返回 E_SNAPSHOT_ROLLBACK。
7. 实现并发提交控制、资源上限与强制终止恢复：同一时刻只允许一个配置快照提交生效，并发冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待；为单次处理分片数、单文档签名块数与驻留缓存内存设可配置上限，超限返回 E_RESOURCE_LIMIT 或按显式优先级降级；执行器在分片批次边界持久化检查点，重启后从最近已提交批次继续，已提交批次不得重算。
8. 实现输入与配置校验链路以及跨模块一致性自检：重复 doc_id、content_hash 与文本不一致、lang 超出受控集合、配置参数非法分别返回结构化业务码并指明字段；自检校验各节点处理的 doc_id 集合完全一致、候选对比较闭包可由桶配置重算、剔除清单与判定明细一致、重算与复用集合无交集且并集覆盖全部受影响分片，不一致返回 E_INCONSISTENT。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
运行本地确定性样本验证签名去重、增量失效传播及交互查询与批量结果一致性，返回结构化报告。
