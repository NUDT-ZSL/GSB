当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向表格与流式特征数据的特征漂移监控专业应用，并附带可重复演示。业务对象是本地确定性生成的特征快照流：以固定随机种子按批次生成若干数值列与类别列的样本，并可在指定批次注入分布漂移（均值平移、方差放大、类别占比变化、缺失率上升）。监控链路被建模为多级流水：分批复核与统计量累积→逐特征漂移检验（数值列用分位数或均值漂移检验，类别列用占比距离）→漂移判定与严重度分级→告警工件生成与汇总。核心业务问题是增量更新与依赖失效：参考窗口随批次滑动、某特征统计口径调整、单一特征被禁启用或某列被重定义后，要能准确算出依赖这些输入的监控产物哪些需要重算、哪些可以复用，并对旧告警做追溯。

任务环境与准备：
安装 Python 3.11 及以上版本，并安装 NumPy 与 SciPy（可离线 wheel 安装，建议固定版本）。
确认工作目录为空且可写；样本由程序按固定随机种子在本地生成，不使用外部数据集或网络下载。
准备本地缓存目录与持久化目录（普通文件系统即可），演示运行前可清空以观察从零构建与增量构建的差异。

业务要求：
1. 实现确定性的分批复核与统计量累积层：按列类型（数值、类别）累积均值、方差、分位数与类别占比，类别列与数值列口径显式区分；同一输入批次、同一配置与固定种子下必须逐字节产出相同统计量与批次指纹，禁止依赖字典遍历顺序或系统时间。
2. 实现逐特征漂移检验与严重度分级：数值列按配置的检验方式（均值漂移或分位数距离）计算漂移量与判定阈值，类别列按占比距离计算；同分或同漂移量时按特征名升序打破平局，输出每特征漂移量、判定结果与严重度等级，且判定必须可由统计量明细独立重算一致。
3. 实现监控产物以内容寻址方式缓存：每特征的统计量与检验结果附带内容哈希落盘，缓存键须纳入参考窗口内样本内容哈希、检验方式与阈值、统计口径版本、特征列定义摘要与上游产物哈希；键相同必须复用快照，键不同必须重算，且每个缓存条目的键组成可查询。
4. 实现增量更新的依赖失效传播：参考窗口滑动、单特征统计口径调整、某特征被禁用或启用、某列被重定义为另一类型时，计算受影响特征与受影响批次集合，复用未受影响上游产物，仅重算受影响后缀；须输出本次重算集合与复用集合，并保证结果与从零全量重算逐字节一致。
5. 实现参考窗口滑动与窗口外样本语义：滑窗后移出窗口的批次信息必须从统计量中正确移除而非增量近似，须显式区分“窗口内统计量”与“全量累计统计量”，并在报告中记录窗口起止批次与移除量；窗口长度非正或滑动步长越界分别返回 E_CONFIG_INVALID 并指明字段。
6. 实现告警工件的版本化与旧告警追溯：告警工件携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧工件而非增量修补；对任一旧告警可按其记录查询当时所用缓存键、窗口范围与配置版本并据此重放出同一告警，追溯失败返回 E_LINEAGE_BROKEN 并指明缺失项。
7. 实现资源上限与并发控制：为单批样本数、缓存条目总量、同时驻留的统计量内存估算与并行重算特征数设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或降级并标记降级类别；多个任务并发写同一缓存键时须保证只有一个写入生效，其余读到完整快照而非半写文件。
8. 提供本地可交互应用与跨模块一致性自检：展示参考窗口范围、逐特征漂移量与严重度、命中或重算状态、失效传播覆盖范围、告警列表与最近业务错误码，并允许触发一次演示——注入分布漂移后查看告警，再滑动一次参考窗口观察增量重算；自检校验复用与重算集合无交集且并集覆盖受影响集合、告警可由漂移明细复算一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证增量失效与全量重算一致、漂移告警可追溯、异常码与并发写入正确。
