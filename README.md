团队首次为稀疏矩阵乘算子引入多格式真值账本，目标是对同一 CSR 输入分别按 v1 行优先扁平表、v2 分片 JSON 加位图索引、v3 列块压缩描述三种结构视图独立执行 SpMM 与 SpMSpM，并裁决各视图的结构解析、时间戳对齐和浮点累加结果是否一致。输入由本地固定种子脚本确定性生成，结构变化以逐批写入事件到达，事件可能同时修改行指针、列索引和数值数组；系统需在写入后按行区间精确重建受影响乘法贡献。当前工作目录没有代码和样本，所有依赖均可离线安装。

任务环境与准备：
安装 Python 3.10 及以上版本，并安装 NumPy 1.24 以上用于确定性数组生成与矩阵乘计算。
工作目录设置为 Linux（WSL Ubuntu）下的空新工作区，无需真实网络、GPU、模型或外部数据集。
使用随工程交付的固定种子脚本生成 CSR 矩阵任务清单、三种格式样本和写入批次事件，不依赖实时账号或在线站点。

业务要求：
1. 实现 CSR 矩阵样本的确定性摄入与结构校验：由固定种子生成行指针、列索引和值数组，要求行指针单调不降、每行列索引升序且无越界、NNZ 与数组长度一致；同一 case_id、同一种子及同一配置下必须逐字节产出相同的初始 CSR 结构，任何结构违规都返回 E_STRUCT 并拒绝进入后续阶段。
2. 实现 v1 单文件 JSON、v2 分片 JSON 加 SQLite 位图索引、v3 列块压缩描述三种真值账本格式的独立读取器；未知版本返回 E_VERSION_UNSUPPORTED，行字段数不符、列索引重复、分片边界越界或位图覆盖不足分别返回 E_FORMAT、E_INDEX_DUP、E_SHARD_BOUND、E_BITMAP_COVER，字段缺失或数值不可解析返回 E_FIELD_MISSING 或 E_PARSE。
3. 实现三种格式到统一 CSR 内部表示的双向迁移：v1 到 v2、v3 时补全分片边界、位图摘要、列块映射与结构代数默认值并逐项记录补全来源，v3 到 v1 时对无法表达的列块压缩与位图校验按显式丢弃规则处理且在迁移报告中注明；迁移后的行指针、列索引和值数组必须语义一致，不一致返回 E_SEMANTIC_DRIFT 并同时输出首个差异行与列位置。
4. 实现批量写入事件的接收与失效传播：写入批次携带单调递增写入版本号、受影响行区间及该区间的完整内容哈希，行区间重叠、版本回退或哈希不匹配的批次整体拒绝并返回 E_WRITE_CONFLICT；合法批次按行区间起始行升序应用，每行区间只允许被同一写入版本覆盖一次，并输出受影响行区间、关联列索引范围及触发写入版本，未涉及的行区间不得被标记失效。
5. 实现按行区间的内容寻址缓存与增量重算：每个行区间在当前写入版本下的 CSR 片段以内容哈希落盘，缓存键纳入行区间内容摘要、写入版本、格式来源和上游片段哈希；未受影响行区间直接复用缓存产物，受影响行区间从最新片段重建乘法贡献并替换旧产物，同时输出重算行区间清单、复用行区间清单和触发写入版本，重算与复用区间必须无交集且并集覆盖全部行区间。
6. 实现三种格式视图下的结构和数值一致性裁决：对同一 case_id 分别执行 SpMM 与 SpMSpM，逐行区间比较解析后的 CSR 结构、乘法输出和中间贡献缓存哈希，结构不一致返回 E_STRUCT_VIEW，数值不一致返回 E_CROSS_VIEW_MISMATCH；裁决必须从内容和行区间缓存独立复原，禁止直接引用内存中的旧结果。
7. 实现四阶段状态机与强制终止恢复：解析校验、迁移语义、增量重算、结果汇总逐阶段推进，每阶段产生带单调递增版本号、已完成行区间集合与内容校验和的持久化快照，仅当该阶段全部行区间处理成功才原子替换；重启后从最近已提交快照继续，已提交阶段不得重算或重复计入，未提交的写入和重算中间状态必须丢弃并从阶段起点重建。
8. 实现异常注入与跨模块一致性自检：在结构摄入、格式解析、写入接收、重算四阶段提供由输入参数触发的注入点（如行指针非单调、位图越界、列索引越界、写入哈希不匹配），每次注入产生结构化业务码和阶段记录；最终校验各阶段行区间集合一致、重算与复用覆盖完整、缓存哈希可由输入复现、增量结果与一次整体重建在 float64 下逐元素一致，不一致返回 E_INCONSISTENT。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
