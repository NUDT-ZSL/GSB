原型演进会议已经确定，首个可演示版本需要在当前空白的 Linux（WSL Ubuntu）工作区交付一个服务于本地消息队列的锁租约配额账本组件。业务焦点从批量授予移至配额账本的动态阈值与预算公平性。固定种子脚本确定性生成租约配额配置（租户名、资源键、基准配额、弹性比例、租约时长毫秒、当前配额代数）；申请轨迹（申请序号、租户、资源键、请求配额、注入逻辑时钟毫秒、优先级）；配额漂移观测（观测序号、租户、实际占用、观测逻辑时钟）以及两代策略快照（v1 为单文件 JSON 扁平参数表，v2 为分片 JSON 加 SQLite 元数据存储阈值与失效墓碑）。系统需在全局预算约束下动态调整租户配额阈值，并在中断恢复与并发提交下保证每个租户的配额释放与阈值漂移收敛一致。

任务环境与准备：
确保 Linux（WSL Ubuntu）环境具备 Python 3.11 以上版本及 pip 可用。
安装依赖：pip install numpy，sqlite3 使用标准库。
创建空工作目录，并准备固定种子样本生成脚本以产生配额配置、申请轨迹、偏移观测和快照文件。
确认 SQLite 文件所在目录可写入，所有数据由本地种子脚本确定性生成，不依赖网络服务。

业务要求：
1. 实现租约配额配置、申请轨迹、漂移观测与两代策略快照的解析校验：租户与申请序号唯一，资源键闭合，基准配额与弹性比例为正有限数，时钟均为非负整数，v1 相对秒数与 v2 绝对毫秒均合法，快照代数单调，任何非法输入返回业务错误码且不启动处理。
2. 在可注入逻辑时钟下计算每个资源键的租约配额占用账本：申请入账时按声明弹性比例预估峰值，释放时按实际实际占用冲销并登记差值，账本每个条目记录配额代数、预计与实际的定点换算标度、舍入方向及误差累计上限。
3. 依据漂移观测计算配额定点偏差与动态阈值收敛：对每个租户的观测占用与配额定点真值计算差值及偏差比，若偏差超过当前策略阈值则生成配额阈值上调或下调决策，阈值调整必须按策略代数单调推进并与配额定点换算同源一致。
4. 在全局配额预算与单租户阈值调整的双重约束下执行公平的阈值调度：每轮从漂移超限租户中按公平标签与稳定排序挑选候选，调整量总和不得超过全局每轮阈值调整预算，预算不足时优先调整危险租户并记录放弃原因及剩余预算。
5. 实现租户配额释放的按量削峰与阈值回退：出现释放差值超过安全水位时执行削峰，回退阈值必须满足与全局预算一致的公平性原则，削峰成本记账不得使任何租户的剩余配额与安全水位出现负值，并保留削峰日志。
6. 处理策略快照的跨版本合并与失效闭包：v1 与 v2 并存时按逻辑时钟与代数选择最新策略，合并后为每个租户输出来源版本与生效时间；策略失效闭包须沿租户资源键递归计算，未受影响租户的现有阈值与配额结论不被重复计算。
7. 实现流水线状态持久化与原子恢复：把已入账申请序号、配额账本、阈值动态、策略版本、公平调度轮次水位与逻辑时钟水位以事务写入 SQLite，进程被强制终止后恢复时依据此持久化状态重放缺失轮次，不得重复扣减配额或改变上一轮已提交的阈值。
8. 保证并发一致性与可重复诊断输出：多个组件实例并行处理时通过 SQLite 事务与文件锁保证同一申请序号只入账一次、同一策略版本只生效一次，重复提交幂等；提供命令行子命令 load、run、adjust、resume、status、verify，status 以稳定排序 JSON 输出每租户动态阈值、账本摘要和调度轮次。
