在空白工作区从零实现一个本地基础设施配置一致性诊断引擎，用于在确定性样本上复现多层配置数值参数的精度问题与误差传播。样本以本地 JSON 给出：服务拓扑清单（服务名、实例、依赖边、配置分层）、每层的数值参数（超时毫秒、重试倍率、采样率、容量上限、权重），以及一致性策略配置（容差参数、换算规则、单位精度、逻辑时钟步进）。引擎需将多层配置的数值参数统一换算为定点表示，沿依赖边计算派生量（如最坏链路超时、有效容量、加权采样率），检测同一参数在多层之间的不一致，追踪浮点误差在依赖链中的累积，输出可复现的 JSON 诊断报告。全部在本地确定性运行，不依赖真实集群。

任务环境与准备：
确认 Windows 上安装 Python 3.11 及以上并可在命令行调用 python。
创建空白工作目录作为项目根目录，不使用容器。
安装 NumPy 与 SQLite 依赖（SQLite 使用 Python 标准库 sqlite3，NumPy 通过 pip 安装并记录版本）。
准备本地固定 JSON 样本：服务拓扑清单、分层数值参数与一致性策略配置，全部为本地文件。

业务要求：
1. 实现拓扑与配置解析校验：读取本地 JSON 拓扑与每层数值参数，校验服务名唯一性、依赖边两端闭合、超时与容量为正、采样率在区间内、权重有限，构建服务与依赖有向图并检测环；非法输入必须返回明确业务错误码且不写入任何持久化状态。
2. 实现数值统一换算与定点表示：把超时毫秒、重试倍率、采样率、容量与权重统一换算为受控定点整数表示，记录每项换算的二进制定点标度与舍入方向，使相同输入多次换算逐位一致，并保留舍入前原始浮点值用于误差溯源。
3. 实现沿依赖边的派生量计算：按拓扑序计算最坏链路超时（超时乘以重试倍率沿边累计）、有效容量与加权采样率，聚合顺序与浮点运算顺序固定，使结果逐位可复现，并为每个派生量记录其依赖的服务层级路径与中间值链。
4. 实现多层配置一致性判定：同一参数在不同层的取值按容差裁决是否一致，不一致时输出涉及的服务、层级、换算后定值与容差余量；一致性判定必须基于定点换算后比较，不得直接以未换算浮点比较而放大误判。
5. 实现误差传播检测：对每个派生量记录定点换算与浮点运算的累计误差上界，当两个候选配置的派生量差值小于给定容差且结论依赖该差值时标记为精度敏感，并输出误差来源链、受影响的服务对与误差上界。
6. 实现依赖失效的增量诊断：某层参数被修改或删除时，沿依赖边计算受影响闭包，精确标记哪些派生量与一致性结论需要重算、哪些可安全复用，未受影响服务不得被重算且结论必须保持不变，失效决策须可追溯。
7. 实现持久化状态与强制终止后的恢复：把诊断轮次、样本摘要、派生量与误差记录原子写入 SQLite，每轮提交识别版本变化并整体替换当前结果指针；恢复时依据持久化状态只重算缺失部分，不得重复已完成计算或回退状态。
8. 实现多进程并发一致性与可重复命令行：多个诊断实例并行处理同一批服务时通过 SQLite 事务与文件锁保证同一服务同一轮次只提交一次，重复提交幂等；支持 load、diagnose、resume、status、report、verify 子命令，report 以稳定排序 JSON 输出诊断报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本运行 diagnose 与 resume 两次，校验诊断报告、误差来源链与恢复后结果逐位一致。
