电网计量中心的数据存储管理员面对的是智能电表批量上报与历史重传交织的写入流：同一台区同一采集窗口的电量、电压电流与质量标记常被多次重传，仅有个别字段不同，按文件整体落盘使仓库迅速被重复内容占满。管理员希望把多源连续计量记录按记录序列化后的内容定义边界切成块，以块摘要作为内容地址登记块索引与引用计数，写入时逐块判定是否已存在，历史归档删除时递减引用计数并回收归零块；同时需要按台区编号与毫秒采集区间在块索引上做范围检索，并在分块策略参数调整后只影响新写入数据。由于真实计量数据不可外取，全部输入由实现自带的固定种子生成器产出，管理员需在本地反复演示与诊断分块边界、去重命中与回收账目。

任务环境与准备：
准备 Linux（WSL Ubuntu）环境与 Python 3 运行环境，本题使用 Python 标准库 hashlib、zlib、sqlite3、json 与 tkinter，运行前需通过系统包管理器安装 python3-tk 图形运行库，未提供容器化启动方案。
在工作目录下新建空项目，块索引数据库文件、确定性样本输出与回收清单均落在该目录内的本地文件，不依赖任何真实电网计量系统、网络服务或账号。
通过命令行入口按固定种子生成样本并推进写入、重复上报与归档删除事件流，诊断视图从同一块索引数据库读取数据，保证命令行与视图观察到的块摘要、引用计数与检索命中一致。

业务要求：
1. 实现确定性样本生成器：按固定种子产出若干台区（台区编号、电表集合、采集频率、批量上报窗口）与逐条计量记录（台区编号、电表编号、毫秒采集时刻、有功/无功电量、电压、电流、质量标记），再产出按逻辑时刻交错的写入、内容相同或仅个别字段不同的重复上报、以及历史归档删除事件流，相同种子必须得到逐字节相同的序列化记录流。
2. 对每个待写入文件的记录序列化字节流使用滚动哈希计算内容定义边界，在满足边界掩码的窗口位置切块并在文件尾部闭合最后一块，输出块边界位置、块长度与各块摘要；同一条记录前缀后接不同后续内容的两个文件必须在前缀部分产生完全一致的块边界与摘要。
3. 以块摘要为内容地址在 SQLite 中建立块索引，登记块长度、摘要与引用计数，写入时逐块判定摘要是否已存在：已存在则仅递增引用计数并记录逻辑映射，不存在则存储新块并置引用计数为一，输出去重命中块数、新增块数与每个受影响块的引用计数变更。
4. 建立文件级到块级的逻辑映射清单，支持按文件标识追溯其全部块及各自引用计数，也支持按块摘要反查引用该块的文件集合，两者在重复上报与删除发生后仍须与块索引中的引用计数互相对得上。
5. 在块索引上按台区编号前缀与毫秒采集时间区间执行范围检索，返回命中的逻辑记录对应的文件标识、块偏移与摘要；检索结果须与逐条重放记录内容比对一致，不得返回已被删除文件中的块。
6. 当写入、重复上报与历史归档删除按事件流交错发生时，对删除文件逐块递减引用计数，把归零块标记为可回收并统计回收字节，输出去重前后的占用对比、归零块清单与回收前后总占用字节，且任意时刻所有块的引用计数之和必须等于有效逻辑块引用数。
7. 在分块策略参数（目标块大小、边界掩码位数）变化后，仅对之后的新写入数据按新策略分块，已存储块的索引与引用计数保持不变，并输出新旧策略各自的块命中率与去重率对比，使管理员能判断是否需要为历史数据重新分块。
8. 提供一个本地 tkinter 诊断视图，按文件展示分块边界与偏移、按块展示摘要与引用计数、按台区与时间区间展示检索命中，并能在写入与删除事件推进后刷新视图，用于人工核对账目。

验收：
以独立参考分块器复算的块边界、摘要与引用计数为基准，校验去重、区间检索、交错删除后的回收账目与策略切换一致性。
