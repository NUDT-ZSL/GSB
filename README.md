安全团队刚拿到一块新的 Windows 开发机，工作目录里只有随题交付的固定种子样本生成脚本，没有任何既有代码。团队要为自研内存边界守卫组件落地首个可运行版本：离线读取本地确定性生成的内存访问轨迹，判定越界并与区域声明账本对账。轨迹为 JSONL，每行含 trace_id、access_seq、region_id、base_offset、access_size、access_kind（read/write）、arena_size 与逻辑毫秒戳；区域声明文件给出每个区域在 arena 中的合法区间、生命周期、代次与父区域引用。核心矛盾是并行判定与资源预算的耦合：同一 arena 的访问必须按 arena 分别调度以控制在途内存，而预算不足时又要保证最终越界结论与串行执行逐条一致，并让 SQLite 账本在强制终止后仍可追平。

任务环境与准备：
安装 Python 3.11 或 3.12（Windows 官方安装包），确保 python 与 pip 可在命令行直接调用。
执行 pip install numpy==1.26.4 pytest==8.2.2 安装依赖，全部为本地包，不需要网络服务、账号或外部数据。
在空工作目录中运行随题交付的固定种子样本生成脚本，生成 JSONL 轨迹、区域声明文件、真值同步标记文件与本地测试服务所需的初始状态目录。
确认工作目录可创建临时文件与执行文件重命名，用于检查点原子替换与文件锁串行化验证。

业务要求：
1. 实现区域声明与访问轨迹的解析规范化层：校验 trace_id 与 region_id 唯一性、arena_size 为正整数、base_offset 与 access_size 为非负整数且 base_offset+access_size 不溢出 64 位、access_kind 属 read/write 白名单、逻辑毫秒戳非负；对非法记录输出含来源文件、行号与业务码的拒绝记录并继续处理其余记录。
2. 在 SQLite 中建立区域边界账本并实现单事务推进：以 region_id 与 access_kind 为主键记录累计访问数、越界数、越界上界与已处理 access_seq 水位；每批推进要么整体生效要么完全不改动账本，前置校验失败不得留下部分写入，账本格局版本（越界判据版本或区域声明代次口径）变化时整体重建而非增量续接。
3. 实现单次访问与多级区域区间的越界判定：把访问区间与自身区域声明区间及其所有祖先区域区间求交，完全落在自身区间内判合法，越过自身区间但落在祖先区间内、跨越祖先区间、区间端点相接或零长度访问须分别给出稳定业务码与规范化的越界偏移证据，祖先引用缺失或成环须单独返回并列出环中 region_id。
4. 实现按 arena 切分任务的并行调度与真实资源预算：以 arena 为独立任务单元按可配置并发度执行，并对整批设置累计在途字节预算、单 arena 实测耗时上限与待处理任务队列上限；预算判定须基于任务实际加载的轨迹字节数与真实墙钟耗时，不得以声明值、固定常量或人为延迟代替；超预算或超时的 arena 须被标记并以对应业务码计入报告，且不得中断其余 arena 的判定。
5. 保证并行判定与串行判定逐条等价：相同输入在任意并发度、任意预算档位与任意到达顺序下，每个区域的越界结论、越界证据集合与拒绝清单必须与按 access_seq 稳定排序的串行执行完全一致；重复 access_seq 按首次出现为真值并记录重复次数，序号缺口返回可识别业务码并给出缺失区间；报告中区域与证据顺序须按稳定键归一化，不得依赖字典遍历或完成顺序。
6. 实现检查点演进与强制终止后的恢复边界：按已处理批次水位与账本摘要持久化检查点到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放比对账本一致性以识别半写残留；检查点与诊断报告均先写临时文件、校验内容可解析后整体重命名替换，替换前须识别快照版本变化；进程被强制终止后不承诺生成退出报告，同一工作目录并发写检查点须以文件锁串行化，锁冲突返回 E_LOCK 且不破坏既有账本。
7. 实现越界诊断报告与基于同步标记的真值对照：报告为可解析 JSON，含批次级结论、每区域每访问方向的状态、业务码、越界偏移证据与预算降级信息；样本生成器须在轨迹内显式写入每条访问的发送端原始区间、同步标记与预期判定区间，验证只依据这些标记与账本输出比较，不得使用生成器的中间计算结果作为真值；单份输入解析失败不得中断同批其他文件，退出码区分全部成功、部分失败与参数错误。
8. 提供确定性本地样本生成器与 pytest 测试集：覆盖合法访问、越界、跨祖先、区间相接、零长度、祖先环、序号缺口与重复、预算超限、超时、并发度差异、强制终止恢复与半写残留等情形，测试须断言业务码、越界证据偏移、并发与串行等价性、账本与检查点恢复后状态正确，并验证检测过程不修改输入文件。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证并行与串行判定等价、预算超限处理及强制终止后账本恢复一致。
