# VPN 隧道转发离线诊断引擎

本仓库已交付可运行的 Python 标准库实现、固定种子样本生成器、CLI 与 pytest 测试集。完整设计、定点公式、检查点恢复语义和实测结果见 `docs/TECHNICAL_NOTES.md`。

```bash
pip install -r requirements-dev.txt
python -m vpn_diag.cli generate-sample -o samples/fixed_seed_sample.json
python -m vpn_diag.cli import-sample -i samples/fixed_seed_sample.json -w .vpn_diag
python -m vpn_diag.cli run -s samples/fixed_seed_sample.json -w .vpn_diag --start-echo
python -m vpn_diag.cli progress -w .vpn_diag
python -m vpn_diag.cli export-report -w .vpn_diag -o artifacts/diagnostic-report.json
python -m vpn_diag.cli verify-checkpoint -w .vpn_diag -s samples/fixed_seed_sample.json
python -m pytest -q
```

CLI 五类核心子命令：`import-sample`、`run`、`progress`、`export-report`、`verify-checkpoint`。测试覆盖非法样本、MTU 不可行、容差歧义、画像切换、重传耗尽、回显缺失/真实超时、并发上限差异和强制终止恢复。

---

团队手头只有一份需求说明，代码尚未动工：需要在 Windows 本地空白工作区实现一个 VPN 隧道转发的离线诊断引擎，在确定性样本上复现内层载荷分片封装、逐轮转发推进、链路画像变化与中断后的结果重放。本地 JSON 样本声明隧道对端清单（对端名、回环监听地址、外层 MTU、内层载荷长度分布、链路权重、加密占位开销）、链路画像（往返时延毫秒、丢包率、可用带宽、抖动上限）与转发策略（分片阈值、每轮并发上限、单轮逻辑时间预算毫秒、重传预算、容差、逻辑时钟步进），另有按逻辑时钟注入的重传与链路变化事件流。转发目标由本地回环 UDP 回显服务提供，服务端对每个收到的分片回显确认，使每轮的到达、重传与完成判定都可观测和重放。核心矛盾在于：时延、丢包率、带宽与抖动的累加必须以定点运算参与分片可发送判定与重传裁定，而累计舍入误差会改变某个分片是否被判定为可重传，进而改变整条转发时间线与完成时刻。

任务环境与准备：
安装 Python 3.11 及以上版本，使用标准库 sqlite3、socket、struct、json、threading 与 pytest；执行 pip install pytest 安装测试框架。
确认本机回环接口可用，测试用 UDP 回显服务绑定 127.0.0.1 的临时端口，仅本机通信，不依赖外部网络、账号或真实 VPN 服务。
样本与配置由随工程交付的固定种子脚本生成，输出到工作区本地目录，Windows 路径与逻辑时钟均以脚本内常量固定，保证多次运行结果一致。

业务要求：
1. 实现样本与策略的严格解析规范化层：校验对端名与回环监听地址唯一性、外层 MTU 为不小于内层载荷预估上限的正整数、链路权重与带宽为正数、丢包率与抖动上限落在 0 到 1 的定点区间内、分片阈值与重传预算为非负整数；非法记录输出含来源类别、记录序号与稳定业务码的拒绝记录，并继续处理其余记录。
2. 实现内层载荷到分片的封装决策：给定外层 MTU、加密占位开销与分片阈值，以整数运算计算单分片可承载的内层载荷上界，越过外层 MTU 减去占位开销的边界或上界为 0 时返回 E_MTU_INFEASIBLE；载荷长度分布在整条转发时间线上的分片切分结果必须与样本声明的同步标记逐一可比。
3. 实现逐轮转发的定点推演：每轮按每对端并发上限选出可发送分片，用定点标度累加往返时延、丢包惩罚、带宽受限排队时延与抖动，产出该轮分片状态与逻辑时钟步进；同时维护一条 float64 参考路径，报告须给出两路径在分片可发送判定上的分歧项与累计残差，单轮逻辑时间预算被超出时以该轮截断而非整体失败。
4. 实现链路的数值精度与误差传播诊断：为每个分片累计各分量误差上界，当某分片累计误差界跨越容差阈值使得可发送或需重传的裁定在两路径下不同时，单列 E_TOLERANCE_AMBIGUOUS 并给出两条路径各自的裁定与余量；重传预算的消耗判定须以定点整数计数而非浮点比较。
5. 实现链路画像变化与异常链路事件的处理：按注入事件流在指定逻辑时刻切换某对端的链路画像或触发丢包段，切换后已发出但未确认分片的超时重传判定须依据切换后的画像重新计算，并在报告中把受影响分片归入画像切换闭包；未在重传预算内完成的对端返回 E_TRANSFER_STALL 并给出最后一次有效进度。
6. 与本地回环 UDP 回显服务完成真实交互：对每个可发送分片实际发包并观测回显确认，确认到达按真实墙钟测量并记录实测往返时延与定点估计值的偏差；未达容差的偏差不得静默忽略，须在报告中计入观测偏差并标明对端与分片键；服务不可达时须以真实超时机制终止该轮并返回明确业务码。
7. 实现检查点演进与强制终止后的恢复边界：按已完成逻辑轮次水位、对端进度与误差累计状态持久化检查点到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放校验与检查点一致以识别半写残留；检查点结构版本或定点标度版本变化时整体重建而非增量续接；快照与报告先写临时文件再整体重命名替换。
8. 交付可交互命令行与确定性本地验证：提供导入样本、执行转发推演、查询对端进度、导出诊断报告、校验检查点五类子命令，报告为可解析 JSON 并含对端级与分片级结论、业务码、两路径分歧项与累计残差；附固定种子样本生成器与 pytest 测试集，覆盖非法样本、MTU 不可行、容差歧义、画像切换、重传耗尽、回显缺失、并发上限差异与强制终止恢复。
