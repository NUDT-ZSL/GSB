当前是空白工作区，需要从零构建一个面向稀疏矩阵乘（SpMSpM / SpMM）场景的可集成算子组件与完整示例，核心业务问题是数值精度与误差传播。输入为本地确定性生成的稀疏矩阵样本：由固定种子生成 CSR 结构（JSON 元数据含 case_id、shape_mnk、nnz_a、nnz_b、dtype、seed、分块候选集），并按 seed 用 NumPy/SciPy 还原对应 CSR 矩阵；组件需对 A×B（稀疏×稀疏）与 A×D（稀疏×稠密）两类调用按 nnz 规模与稠密维自适应选择分块策略（行分块尺寸、累加顺序、是否走聚合中间路径），以 float64 稠密参考实现作为该快照内的真值来源，输出每次调用的策略决策记录、逐元素偏差统计与误差谱（偏差分位数、最大偏差位置、误差放大比），并沿分块累加链路定位主导误差来源。分块累加顺序、合并归约与次正规数缩放都会改变结果舍入，因此需要在策略选择、误差裁决与资源预算之间做显式取舍。观测口径与真值来源如下：每个 case 的 CSR 矩阵与稠密参考结果由同一 seed 与同一 JSON 元数据确定性重建，参考实现不经分块与补偿求和，逐元素偏差以参考矩阵为唯一真值来源计算；分块路径与降级路径均须在同一参考下比较，禁止从不可重建的信息推断偏差。

复杂度依据：
- 数值或时间精度：要求 3、4、6 相互制约，分块累加与补偿求和改变舍入，容差裁决与误差谱定位须以稠密参考真值为唯一真值来源；
- 性能与正确性取舍：要求 2、5、6 冲突，更大分块省中间缓冲但累加路径更长、精度与内存预算需显式裁决并记录取舍；
- 跨模块一致性：要求 7 与 1、2 关联，SpMM 与退化稠密路径、行主序与列主序视图结果须可互相核对；
- 异常链路：要求 1、8 关联，非法形状、dtype 不支持、资源超限须沿异常链路归因到阶段与 case_id。

任务环境与准备：
安装 Python 3.10 及以上，并安装 NumPy 与 SciPy 的稳定版本，确保可在 Windows 本地导入。
准备一个工作目录用于存放本地确定性样本生成脚本、CSR 元数据 JSON 与运行输出。
运行前用固定 seed 生成稀疏矩阵样本与稠密参考结果，确认样本与输出目录可写。
确认命令行入口能在无网络与无外部服务条件下独立运行并输出 JSON 报告。

业务要求：
1. 实现 SpMM 与 SpMSpM 的统一算子入口，按 JSON 元数据解析 CSR 形状、nnz、dtype 与批次语义，对非法形状、dtype 不支持、CSR 索引越界或行指针非单调、nnz 声明与实际不符分别返回 E_SHAPE_INVALID、E_DTYPE_UNSUPPORTED、E_CSR_INVALID，并指明 case_id 与字段。
2. 实现基于 nnz 规模与稠密维的分块策略决策器：选择行分块尺寸、累加顺序与是否走聚合中间路径，输出含决策依据的代价估计记录；同一输入与配置下决策必须逐字节一致，分块尺寸须整除或覆盖全部行且不得遗漏任何非零元。
3. 实现分块执行路径与补偿求和累加：按选定分块完成稀疏乘与跨块归约，支持可配置的补偿求和以降低舍入误差；分块路径结果须与 float64 稠密参考实现在给定容差内一致，并记录观测到的最大绝对偏差与最大相对偏差。
4. 实现误差谱诊断与偏差裁决：输出偏差分位数、最大偏差元素位置、误差放大比，并沿分块累加链定位主导误差来源为行分块、跨块归约或稀疏索引求和中的哪一级；超出容差返回 E_TOLERANCE_EXCEEDED 并指出越界元素与偏差量，禁止放宽容差掩盖错误。
5. 实现规模与资源预算控制：为单次调用的估计内存、分块数量与聚合中间缓冲设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或降级到较小分块；降级须在结果中标记降级类别，且不得改变已输出元素的计算语义与容差判定口径。
6. 实现策略冲突裁决：当精度要求与内存预算在同一规模上冲突时（更大分块省中间缓冲但累加路径更长精度更低，更小分块精度更优但分块数逼近或超出预算），须按显式优先级规则裁决并在策略记录中说明取舍理由，裁决结果必须可复现。
7. 实现跨模式一致性自检：校验 SpMM 与稠密维为 1 的退化路径在相同结构输入上产出一致结果、行主序与列主序视图下结果在转置语义上可核对、分块归约中间量可重算出最终矩阵；检测到不一致返回 E_INCONSISTENT 并指出不一致类别与 case_id。
8. 提供可集成的领域组件与完整示例：暴露 spmm、spspmm、策略决策与误差谱诊断入口，命令行示例读取本地生成样本输出含结果摘要、策略记录、误差谱、业务码与降级标记的 JSON，并附一次注入异常输入与一次超预算降级的演示。
