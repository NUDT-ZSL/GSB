# 梯度同步与环形 AllReduce 一致性引擎

本仓库提供纯本地、确定性的梯度同步模拟：固定种子样本、SQLite 事务状态、ReduceScatter/AllGather 两阶段调度、预算/内存/故障结局码、规格整体替换、强杀恢复以及逐轮 verify。

## 快速开始

```bash
python samples/generate_samples.py
python main.py load samples --db state/gradient_engine.db
python main.py run --db state/gradient_engine.db
python main.py status --db state/gradient_engine.db
python main.py verify --db state/gradient_engine.db
python -m pytest -q
```

一键端到端验收（自动制造第 3 轮提交前强杀、resume、比对轨迹和内存账本）：

```bash
python main.py demo --dir demo_workspace
```

常用恢复演练：

```bash
python main.py load samples --db state/crash.db
python main.py run --db state/crash.db --crash-before-commit-round 3  # 预期退出码 86
python main.py resume --db state/crash.db
python main.py verify --db state/crash.db
```

手动注入：

```bash
python main.py inject --db state/gradient_engine.db \
  --type node_fault --node n1 --clock 200
python main.py inject --db state/gradient_engine.db \
  samples/injections.json
```

`status` 始终输出稳定排序 JSON，包含每节点当前持有分片、已完成分片、规格版本、内存占用和结局码。设计细节见 `docs/TECHNICAL_DESIGN.md`，实际验证记录见 `docs/VALIDATION.md`。

## 原始任务说明

这是一次从空工作区开始的分布式训练通信实现任务：需要在本地构建一个梯度同步引擎，验证环形 AllReduce 在节点加入退出和参数分片调整时的并行预算与中断恢复一致性。所有输入由固定种子脚本生成，不依赖真实网络或外部集群。训练计划 JSON 声明模型层清单、参数分片方式与每分片字节大小；节点清单声明各工作节点标识、回环通信地址、算力配比与可用内存上限；梯度事件流按注入逻辑时钟给出每个节点产生的梯度分片、分片序号和预期提交时刻。引擎需模拟分层 AllReduce 的 ReduceScatter 与 AllGather 阶段，在每轮并发同步上限与单轮同步时间预算约束下裁决分片流转，并将分片完成状态、内存占用与日志水位持久化。关键难点在于：当分片完成进度因节点故障或预算耗尽而滞后时，回放必须依据持久化状态续算，不能重复确认已完成分片，也不能依赖内存残留来计算预测；同时参数分片规格变更必须整体替换既有视图，并在视图替换过程中阻止新旧混合的提交。

任务环境与准备：
安装 Python 3.10 或 3.11，并安装 numpy 与 sqlite3（标准库自带）。
任务执行前由固定种子脚本生成训练计划 JSON、节点清单 JSON、梯度事件 JSONL 与注入清单 JSON 到工作目录的 samples/ 下。
准备可执行脚本入口为 main.py，并确保工作目录可写。

业务要求：
1. 实现训练计划、节点清单与梯度事件流的解析校验：模型层名与节点标识唯一，参数分片方式非空且分片序号连续从零开始，每分片字节大小为正整数且各层分片集合完整覆盖该层全部参数，节点回环通信地址格式合法且内存上限为正整数，梯度事件的分片序号必须在对应层分片集合内且事件序号严格递增，非法输入必须返回明确业务错误码且不得写入任何持久化状态。
2. 在注入逻辑时钟下推进每个同步层级的 ReduceScatter 与 AllGather 两阶段：分片完成时刻只依据注入逻辑时钟毫秒值与事件的预期提交时刻，不读取系统墙钟，同一节点对同一分片的重复上报必须幂等且只有首次提交才会推进该分片的完成集合，分片完成集合与阶段游标在任意顺序到达的合法事件序列下必须收敛一致。
3. 模拟并行同步调度并强制遵守每轮并发上限与每轮同步时间预算：每轮从待处理分片集合中按节点标识和分片序号的稳定顺序挑选候选，同时启动数不得超过并发上限，预算耗尽时必须终止本轮并放弃剩余候选，预算不足导致的放弃必须与节点故障导致的滞后在输出中使用不同结局码区分，已启动的分片必须按注入时钟推进其完成状态，不得事后标记为超时。
4. 依据当前参数分片规格构建校验视图，并在每次规格变更时进行整体替换而非逐片覆盖：规格版本号必须单调递增，替换前所有同步用分片必须绑定到对应规格版本，替换期间不得接受旧规格分片的完成上报，完成集合与阶段游标以新规格为基准重新裁量，同一节点在不同规格下的分片完成状态必须分账管理，旧规格的持久化条目保留历史但不再参与当前轮次推进。
5. 把每轮调度决策、分片完成集合、阶段游标、内存占用与逻辑时钟水位以事务原子写入 SQLite，并支持强制终止后的恢复：恢复时依据持久化状态识别已提交分片、已淘汰规格与半提交轮次，续算只重放缺失或未提交的分片，不得重复累加已完成分片的内存占用，恢复后的分片完成集合必须与无中断一次性运行的结果完全一致。
6. 在每轮同步结束后审计内存占用账本：按每分片字节大小、分片版本与持有节点计量当前内存占用，任一节点内存占用超过其上限时必须在该轮结束时把超出部分真实标记为滞后并阻止该节点继续承接新分片，标记必须与预算不足的放弃记录区分，且内存账本必须在事务中与调度结果一起提交，不得出现分片完成集合与内存账本不一致的中间态。
7. 实现节点故障注入的受控模拟与恢复：按注入清单在指定逻辑时刻把节点标记为故障，故障节点未完成分片必须从该节点当前持有集合中回滚到待处理集合，已确认分片由其他节点重新承接，恢复路径必须基于持久化状态重置故障节点内存占用并重新调度相应轮次，不得依赖运行期内存残留，故障注入不得改变其他节点已提交分片的历史结论。
8. 提供命令行接口与可重复演示，支持 load、run、inject、resume、status、verify 子命令；status 以稳定排序 JSON 输出每节点当前持有分片、已完成分片、规格版本、内存占用与结局码，verify 对注入逻辑时钟序列重放并逐轮比对调度结果与内存账本，不一致时必须给出首个分歧事件序号与两个账本摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地种子生成的训练计划与梯度事件，验证并行同步调度、规格整体替换与中断恢复后分片完成集合和内存账本的一致性。
