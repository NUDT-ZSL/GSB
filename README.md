当前是空白工作区，需要从零构建一个面向 Windows 本地环境的 SRE 限流熔断与降级决策领域组件。系统以本地 JSON 文件描述服务治理策略：每个服务包含令牌桶限流参数（整数速率与突发容量）、熔断器参数（滑动窗口分钟数、失败率阈值、最小请求数、半开试探数）与降级链（有序的降级目标及其权重）。业务事件流以 NDJSON 录入，每行含毫秒时间戳、服务标识、结果（成功/失败/超时）与请求耗时。组件须按事件流顺序推进限流、熔断与降级决策，并输出每个事件时刻的决策结果。核心难点在于：限流器的令牌补充、熔断器的失败率与窗口滑动、降级目标权重选择都涉及比例与速率计算，需以整数定点方式完成并给出量化误差上界；同时降级链上多级降级的成功概率会沿链条逐级传播误差，需给出可追溯的误差界。组件须支持治理策略版本演进、会话快照整体替换恢复与历史决策重放校验，并提供可集成的 Python 包与完整示例。

任务环境与准备：
安装 Python 3.11 或以上，并确保 pip 可用
安装 NumPy（用于样本事件流的确定性批量构造与摘要计算），版本以本地 wheel 安装为准
在空白工作区创建项目根目录，准备本地样本策略 JSON 与事件流 NDJSON 的存放目录
确认 Windows 本地可运行 Python 子进程与文件写入，无需任何网络账号或外部服务

业务要求：
1. 实现治理策略与事件流的加载与强校验：从本地 JSON 读取服务策略，校验服务标识唯一、限流速率为正整数、突发容量非负整数、熔断窗口分钟数与最小请求数为正整数、失败率阈值为 0 至 100 的整数百分比、降级链目标不重复且权重和为正；从 NDJSON 读取事件流，校验时间戳毫秒整数单调不减、结果属于成功/失败/超时、耗时非负；任一不合法须以 E_POLICY 或 E_EVENT 业务码整体拒绝加载，并输出文件行号与字段路径。
2. 实现定点数基础设施与误差界推导：提供以会话参数指定的缩放因子（10 的整数幂）把比例、速率与权重统一量化为定点整数，所有乘法与除法须以整数运算完成并显式截断方向；对令牌补充量与失败率计算给出以整数格表示的误差上界，该上界须随运算级数逐级合成并在决策报告中列出，禁止在核心判定路径中使用浮点中间值。
3. 实现令牌桶限流决策：按事件时间戳推进令牌补充，补充量为速率与经过毫秒的整数运算结果并受突发容量封顶，令牌不足时拒绝请求；限流决策须与定点误差界一并输出，且在补充量与容量边界上按显式规则处理（不得因截断方向产生超发或漏发），同一事件序列重复推进必须得到逐位相同的令牌余量轨迹。
4. 实现熔断器滑动窗口与半开状态机：按分钟窗口统计成功、失败与超时计数，窗口滑出时整体移除整分钟数据而非逐条递减；失败率以定点方式与阈值比较，达到最小请求数要求后触发打开，冷却后半开按试探数限制放行，试探结果决定关闭或再次打开；状态迁移须记录触发窗口标识、定点失败率与所用阈值，超时与失败在统计口径上须明确区分。
5. 实现降级链决策与误差沿链传播：主路径不可用时按降级目标权重以确定性算法选择降级目标，权重选择不得依赖字典或哈希遍历顺序；多级降级时各级成功概率的定点值沿链条合成为端到端成功概率，须给出逐级贡献与合成误差上界，并输出降级结果是否被误差界主导的标注；当权重和为零或降级链耗尽时须以 E_DEGRADE 业务码报告而非静默放行。
6. 实现策略版本演进与快照整体替换恢复：策略文件被修改后版本号单调递增，会话快照持久化策略版本、定点缩放因子、限流器令牌状态、熔断窗口计数、逐事件决策轨迹与逐级误差界；重新打开快照时须先比较快照策略版本与当前策略版本，不一致须整体替换限流与熔断状态而非增量合并，恢复后须能从快照断点继续推进新事件且新旧版本差异可辨识。
7. 实现历史决策重放校验与不可复现报告：从快照恢复后按快照记录的缩放因子与策略版本重新推进每个事件，将限流判定、熔断状态、降级选择与误差上界与快照逐项比较；因缩放因子变化或策略版本缺失导致结果不一致时须以 E_REPLAY 业务码报告并定位首个差异事件序号与差异字段，同时列出该事件的定点输入与两侧输出。
8. 提供可集成的 Python 包 API 与完整示例：以包形式暴露策略加载、定点量化、限流推进、熔断更新、降级决策、误差界合成、快照保存与恢复、重放校验的接口，附带本地确定性样本策略与事件流及演示脚本，顺序执行冷启动决策、修改失败率阈值后决策、快照恢复重放三个场景；支持以命令行参数注入策略字段越界、事件时间戳回退、快照缩放因子缺失三类异常，分别以 E_POLICY、E_EVENT、E_GRID 业务码报告并写入结构化日志。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
