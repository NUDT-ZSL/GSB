当前是空白工作区，需要从零实现一个本地列式分组聚合的计算引擎与诊断工作台，专项处理数据倾斜下的交互延迟与计算结果一致性问题。本地 JSON 样本给出：列式批次文件（批次序号、行数、按列存储的分组键/数值/标记数组、批次内容摘要），若干聚合查询（分组键、求和/均值/方差/计数、可选滑动窗口行长与步长），以及执行配置（单次查询逻辑时延预算毫秒、每批最大行数、热点分组键判定阈值与倾斜比例、内存缓冲上限 MiB、定点标度、浮点容差、逻辑时钟步进）。样本中部分分组键被刻意放大为热点键，使逐批精确聚合在时延预算内无法完成，必须引入预聚合、两阶段合并或热点键分流等手段，而任何加速手段都不允许改变最终聚合结果与行序。引擎需按批次流式推进、可中断恢复，并在报告中区分热点成因、加速路径与实际使用的聚合模式。

任务环境与准备：
安装 Python 3.11 或以上版本，并确认可用 numpy 与标准库 sqlite3 模块（版本以本机安装为准）。
准备固定本地样本目录：列式批次 JSON 文件若干（含热点分组键）、聚合查询描述 JSON 与执行配置 JSON，全部由任务方提供，禁止依赖网络或外部数据源。
确认工作区可写，用于 SQLite 状态库与临时溢出文件的原子落盘与回读。
执行前清理旧的 SQLite 状态库与临时目录，确保两次运行的初始状态一致。

业务要求：
1. 实现列式批次文件与聚合查询描述的解析校验：列名唯一、各列数组长度与批次行数一致、批次序号严格递增且内容摘要与列内容一致、分组键与聚合表达式引用的列存在且类型可比、窗口行长与步长为正整数且步长不大于行长、定点标度与容差为正；非法输入须返回明确业务错误码（如 E_BAD_BATCH、E_BAD_QUERY、E_BAD_CONFIG）且不写入任何持久化状态。
2. 实现逐批精确聚合的唯一真值通路：按固定聚合顺序与固定浮点运算顺序对每个分组累计计数、求和、平方和与均值，并输出按分组键稳定排序的 JSON 结果；相同输入重复运行必须逐位一致，NaN 与无穷输入须按统一规则保留并不参与分组键比较，该通路作为后续加速通路比对真值的唯一来源。
3. 实现热点分组键识别与倾斜判定：依据热点阈值与倾斜比例在批次流推进中识别被放大的分组键，输出热点键列表、其行数占比与判定所依赖的观测（批次序号与行数统计）；判定不得依赖全量预扫描，须在只读已到达批次的条件下给出可复现结论，热点键集合变化须记录触发批次序号。
4. 实现至少一项受预算约束时仍能加速的聚合路径（如热点键预聚合后两阶段合并、热点键分流到独立累加通道、或按分组键排序后分段合并），并给出加速路径与原精确通路在相同输入下的结果逐行逐值一致性校验；两条通路结果任何不一致须输出首个分歧分组键、两条通路中间值与触发批次，且不得以容差放宽掩盖真实差异。
5. 实现单次查询逻辑时延预算下的执行模式裁决：以注入逻辑时钟毫秒值计量每批处理耗时，当精确通路超出时延预算时按明确规则切换到加速通路，切换点、切换触发条件与被否决模式的原因须记录；时延计量不得读取系统墙钟，同一逻辑时钟序列下必须得到逐位一致的切换序列与最终结果。
6. 实现内存缓冲上限与批量合并的资源约束：每个分组与热点累加通道的中间状态占用须与配置内存上限比较，超限时必须按确定性规则合并或溢出到本地临时文件后回读，回读须校验摘要；溢出与回读的分组数、字节数须计入报告，且溢出前后聚合结果须与未溢出运行逐值一致。
7. 实现强制终止后的恢复与幂等提交：把查询水位、已提交批次摘要、每分组状态版本、热点键集合版本、执行模式决策与逻辑时钟水位以事务原子写入 SQLite；进程在批次处理或状态溢出中途被强制终止后，恢复路径须识别已提交批次与半提交分组，只重放缺失批次且不得重复累加计数或平方和，恢复后结果与不中断运行逐位一致。
8. 实现多进程并发一致性与可重复诊断命令行：多个实例并行推进同一查询的不同批次时，通过 SQLite 事务与文件锁保证同一批次同一分组状态版本只提交一次、内存预算不被并发超卖、重复提交相同批次结果幂等；提供 run、resume、status、verify 子命令，status 以稳定排序 JSON 输出热点键、执行模式、时延观测与溢出统计，verify 校验持久化状态与输出结果的一致性。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
