某安全团队需要在离线 Windows 空白工作区从零开发一个安全策略交互一致性验证管线，用于在受限并发与延迟预算下向本地策略校验服务提交规则组判定请求并核对结论一致性。输入为本地确定性 JSON 策略声明文件（规则标识、条件区间与端点标记、动作、生效优先级、版本号）与一份请求清单，请求清单声明每个规则组的期望返回时限（整数毫秒）与期望结论摘要。管线需通过本地确定性校验服务（由工作区自带、支持按规则组查询的小型本地进程内或本机 HTTP 服务）执行判定，记录每条请求从提交到结论可见的真实交互延迟，核对返回摘要与本地独立计算结果是否一致，并输出可复现的 JSON 报告。核心难点在于交互延迟与计算结果的一致性耦合：服务可能响应延迟、超时、返回顺序错乱或返回陈旧版本结论，管线既要按请求清单的时限判定时效，又要保证核对结论与本地计算逐条一致，并在被强制终止后从检查点恢复。

任务环境与准备：
确保 Windows 本地可用 Python 3.11 及以上解释器，仅使用标准库 concurrent.futures、json、threading 与 pytest，无需网络与外部服务。
在空白工作区创建项目目录，安装 pytest（pip install pytest），确认工作目录具有可写权限以生成临时文件与检查点。
样本、本地校验服务与检查点文件均由自带生成器生成，运行脚本在本地启动校验服务并执行请求清单，不依赖真实账号、线上站点或付费资源。

业务要求：
1. 实现策略声明与请求清单的解析规范化层：逐条校验规则标识唯一性、条件区间下界不大于上界且端点标记取值合法、优先级为整数、期望返回时限为正整数、期望结论摘要格式合法，对非法条目输出含条目序号与业务错误码的拒绝记录并继续处理其余条目，输出规范化规则组与请求集合。
2. 实现本地确定性校验服务：以规则组为查询单元返回该组冲突对与遮蔽关系的结论摘要，服务须支持按摘要版本号区分不同策略声明版本，并支持注入确定性延迟档位（固定毫秒数）与乱序返回模式；服务端结论必须由独立的本地计算得出，不得直接复用管线侧已算结果，以形成可核对的对照。
3. 实现交互延迟采集与时限判定：每条请求的交互延迟从提交时刻计到其结论完成可见时刻，须以真实墙钟测量；对超出请求清单期望时限者标记为超时并给出实测延迟值与超出量，超时请求不得被丢弃，且单条请求超时不得中断同批其余请求的提交与核对。
4. 实现响应一致性核对：把服务返回的结论摘要与管线本地按同一规范化规则组独立计算的结果逐条比对，摘要不符返回 E_MISMATCH 并记录差异字段；当服务返回的摘要版本号与当前策略声明版本不一致时返回 E_STALE 并拒绝采纳该结论，陈旧结论不得覆盖本地计算结果。
5. 实现乱序与并发等价保证：在任意并发度、乱序返回模式与延迟档位组合下，最终每条请求的核对结论、超时清单与陈旧拒绝清单必须与串行执行并以请求稳定键排序的结果完全一致；报告中请求与规则组顺序须按稳定键归一化，不得依赖服务返回顺序或任务完成顺序。
6. 实现资源预算与队列上限控制：并发度、单请求真实耗时上限与待处理请求队列上限均可配置，超时判定基于实测耗时而非人为延迟常量；单请求耗时超限以 E_TIMEOUT 标记、队列超限须拒绝入队并计入报告，二者均不得中断同批其余请求的提交与核对。
7. 实现检查点、版本识别与强制终止后的恢复边界：按已完成请求标识与已核对结论持久化检查点，恢复时只从最后一个完整检查点继续，进程被强制终止后不承诺生成退出报告；检测到检查点结构版本、策略版本或服务摘要版本变化须整体重建而非增量续接；检查点与报告均先写临时文件再重命名整体替换，同工作目录并发写入以文件锁串行化，锁冲突返回 E_LOCK。
8. 提供确定性本地样本与 pytest 测试集：样本显式记录每条请求的服务侧同步标记与期望结论摘要作为真值，验证端只依据这些标记与管线输出比较；覆盖一致、摘要不符、陈旧版本、超时、队列超限、乱序返回、并发度差异与检查点中断恢复等情形，并断言业务错误码、并发与串行等价以及恢复后状态正确。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证交互超时记录、摘要一致性与陈旧拒绝正确，并发核对结论等价于串行，附运行结果。
