当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向中文知识图谱构建的本地数据处理管线与结果验证工具。业务对象是本地确定性生成的语料分片（JSONL，字段含 shard_id、doc_id、sent_no、text、char_len）以及随附的实体词典、关系模式表与三元组真值清单。管线把一次知识图谱构建建模为多阶段流程：分片摄入与校验→分词与实体识别（基于随附实体词典做确定性最大匹配，候选跨度带码点起止偏移与词典版本）→关系抽取（按关系模式表在实体对之间做触发词与模式匹配，产出候选三元组及置信分数）→实体归一与去重（把别名字面量归并到规范实体）→图谱汇总与统计。核心业务问题是数据规模变化下的算法取舍：语料分片数、单文档实体数与候选实体对规模会显著波动，词表匹配与实体对枚举在实体密集文档上呈平方级增长，因此系统必须在精确枚举路径与受限近似路径之间按规模与预算做可复现的裁决，同时保证同一文档不会在两个路径下得到互相矛盾的三元组，且图谱统计必须能由逐文档明细独立重算。

任务环境与准备：
安装 Python 3.11 及以上版本，勾选将其加入 PATH，确认在 PowerShell 中可直接运行 python 与 pip。
安装 NumPy（如 pip install numpy），仅使用本地已安装版本，不访问任何在线服务或外部数据集。
准备本地确定性样本生成脚本或步骤：按固定种子生成语料分片 JSONL、实体词典、关系模式表与三元组真值清单，样本放置在项目 data 目录下。
确认工作目录可读写，用于存放抽取结果、快照文件与日志输出；无需数据库、消息队列或任何容器环境。
在 PowerShell 中执行命令行入口完成一次基线运行与一次注入异常输入的演示，检查生成的 JSON 报告可正常打开。

业务要求：
1. 实现分片摄入、分词与实体识别阶段：按随附实体词典做确定性最大匹配，输出每个实体跨度的码点起止偏移、实体类型与匹配来源词典版本；同一 doc_id 在同一词典版本与同一配置下必须逐字节产出相同跨度集合，同长度同起点时按实体类型编号升序打破平局，并保证跨度落在文本码点范围内且互不重叠。
2. 实现关系抽取与候选三元组阶段：在实体对之间按关系模式表的触发词与模式做匹配，输出候选三元组（头实体跨度、尾实体跨度、关系类型、置信分数），同分时按头跨度起点、尾跨度起点、关系类型编号依次升序裁决；须记录每条三元组命中的模式行号与触发词偏移，使置信分数可由分项明细独立重算一致。
3. 实现实体归一与去重阶段：把别名字面量归并到规范实体，输出规范实体字典与别名映射，须保证任一别名只映射到一个规范实体、同一规范实体下的跨度集合与别名集合可互相核对；检测到别名冲突或规范实体自引用分别返回 E_ALIAS_CONFLICT 与 E_NORMALIZE_CYCLE 并指出冲突别名。
4. 实现基于数据规模的自适应抽取取舍器：按分片数、单文档实体数、候选实体对规模与驻留内存余量在精确枚举路径与受限近似路径之间选择，输出含规模观测与代价估计的取舍记录；同一观测下决策必须逐字节一致，且所选路径不得遗漏任何被声明为必须命中的高置信模式命中。
5. 实现精确路径与近似路径的跨路径一致性裁决：同一文档若两路径均有结果，须输出三元组集合差异、逐三元组置信度偏差与召回估计，并说明差异来自近似枚举遗漏还是模式匹配口径不同；当差异导致图谱统计口径不可比时返回 E_PATH_DIVERGENCE 并指出首次分歧的文档与三元组。
6. 实现候选实体对预算与驻留内存的双重准入裁决：按单文档实体数与关系模式数估算实体对枚举代价，在总比较预算与内存上限内决定准入与降批规模；超限时返回 E_PAIR_BUDGET 或 E_RESOURCE_LIMIT，降级到近似路径时必须在结果中标记降级类别与其影响的文档集合。
7. 实现抽取配置、词典与图谱快照的版本化管理及整体替换：实体词典、关系模式表与图谱统计快照各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补；重启加载时识别版本变化并整体替换，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明快照类别与版本号。
8. 实现结果验证工具与跨阶段一致性自检：独立复核每个文档的实体跨度、三元组与别名映射，校验三元组两端实体存在于同一文档实体集合、去重后每条三元组恰出现一次、图谱统计可由逐文档明细独立重算；检测到不一致返回 E_INCONSISTENT 并指出不一致类别与 doc_id。
