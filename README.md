在空白工作区构建一个面向本地视频片段的离线目标检测与候选匹配管线，用于多路摄像头素材的批量结构化处理。输入为一个本地样本目录，内含若干合成视频片段（AVI 容器、固定分辨率与帧率，画面为程序生成的几何目标与背景噪声）、一份检测模型参数 JSON（滑窗尺度列表、颜色/边缘特征阈值、得分融合权重）以及一份匹配配置 JSON（车辆与行人两类目标的候选池容量、IoU 匹配阈值、每路视频的处理帧预算）。管线需要对多路视频并行调度，逐帧完成滑窗检测与候选框聚合，再跨帧做目标候选匹配与轨迹串联，最后输出结构化检测结果与预算消耗报告。核心难点在于并行调度与帧预算之间的冲突：多路视频共享有限工作线程与总帧预算，必须在超预算时按优先级截断而非无界排队，同时保证同输入下结果可复现；检测得分、IoU 匹配与轨迹串联涉及数值精度与阈值边界；任一路解析失败、帧损坏或配置非法必须被隔离且可定位。

任务环境与准备：
安装 Python 3.10 及以上版本，并安装 numpy 与 opencv-python（含视频编解码支持）的固定版本。
在本地生成合成视频样本：不同分辨率与帧率的 AVI 文件若干，画面含可区分的几何目标与噪声，并记录每段视频的目标真值帧区间作为验证输入。
准备模型参数 JSON 与匹配配置 JSON 样本，包含多尺度窗口、阈值、候选池容量、并发数与总帧预算等字段，另准备若干非法配置用于异常注入。
确认工作目录可写，用于存放中间快照、原子写盘临时文件与最终 JSON 报告。

业务要求：
1. 实现视频帧读取与解析层：扫描输入目录下所有视频文件，按扩展名与容器头校验可用性，逐帧解码为 uint8 数组并携带文件名、帧序号、时间戳；对无法打开或中途解码失败的文件记录 E_DECODE_FAIL 业务码与失败帧序号，不得使整批任务中断。
2. 实现滑窗检测器：依据模型参数中的多尺度窗口尺寸与步长，在每帧上计算颜色均值与边缘密度特征，按融合权重得到候选得分，超过检测阈值的窗口输出为候选框，坐标为整数像素且做边界裁剪；同一目标被多尺度重复命中时按得分降序做非极大值抑制，IoU 阈值取自参数。
3. 实现候选匹配与轨迹串联：将连续帧候选框按类别分别与已有轨迹做 IoU 匹配，匹配阈值可配置，匹配成功则追加到轨迹并更新轨迹中心与速度估计，未匹配候选按候选池容量上限决定新建轨迹或丢弃最旧低分轨迹；轨迹 ID 在整批运行内全局唯一且分配顺序确定。
4. 实现并行调度与帧预算控制：多路视频通过工作线程池并发处理，最大并发数与全局总帧预算取自配置；调度器按路线优先级与已消耗帧数动态分配预算，预算耗尽时对未完成路线输出 E_BUDGET_EXHAUSTED 并标记截断帧号，而非让线程无界等待或越界读取；线程池关闭时回收全部工作线程。
5. 保证并行结果与串行执行的一致性：每条检测与匹配任务携带由文件标识、帧序号与窗口索引派生的稳定排序键，无论线程调度顺序如何，最终输出中轨迹的顺序、轨迹内帧序列以及候选框顺序必须与单线程顺序执行逐字段一致，并通过配置切换并发数验证。
6. 实现异常隔离与可处理退出：单帧检测异常、匹配异常或配置字段缺失时，记录路线名、帧序号、阶段名与异常类型到失败清单并继续处理其余路线；收到可处理的退出信号时完成当前帧结果落盘与预算报告后以整数退出码 0 退出；强制终止后仅能依赖已原子写盘的中间结果恢复，不得承诺生成退出报告。
7. 实现阶段性中间结果持久化与恢复：检测阶段与匹配阶段各自以临时文件加原子替换方式写盘，快照包含阶段名、配置哈希、已处理帧游标与轨迹摘要；重启时读取最新快照，若配置哈希不一致输出 E_CONFIG_MISMATCH 并拒绝恢复，一致时从游标继续，恢复后的最终结果与不中断运行一致。
8. 实现结构化结果与预算报告输出：以 JSON 输出每条轨迹的类别、轨迹 ID、逐帧框坐标与得分，以及各路线已处理帧数、被截断帧号、线程峰值占用与总耗时；报告字段名与业务码须与前述要求一致，并在每次完整运行结束时原子写盘。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地合成视频与配置验证并行检测、轨迹匹配、预算截断、恢复一致性与异常隔离结果。
