终端检测与响应产品原型评审刚结束，编码阶段启动，工作区仍为空目录，需要在 Windows 本地从零交付一个终端进程行为策略判定引擎。业务对象是本地确定性生成的三类输入：进程行为事件流为 JSONL，每行含 event_seq、endpoint_id、process_guid、parent_process_guid、policy_key、action_kind、risk_level、observed_ms 与 payload_digest；策略声明以两代格式并存，v1 记录相对生效秒、扁平匹配串与动作码，v2 记录绝对毫秒生效时刻、规范策略键、规则代数与墓碑标记；另有一份进程谱系声明给出进程与其父进程、所属会话的归属关系。引擎须沿进程谱系把事件归并为以根进程为单位的判定单元，对每个单元计算命中策略与动作，识别跨代策略声明冲突和谱系分叉引发的归并歧义，并把结论写入账本与结构化报告。真正的难点在于谱系分叉与策略代际冲突相互耦合：同一 process_guid 可能在不同会话中出现多份父进程声明，归并单元会随声明到达而拆分或合并，而策略修订又会改变受影响单元的判定结论，二者必须同时保证与到达顺序无关且与全量重算逐条一致。

任务环境与准备：
安装 Python 3.11 及以上版本，使用虚拟环境隔离依赖。
安装 numpy（用于确定性摘要与规范化计算）与 pytest（用于本地测试），版本在 requirements 中固定。
确认工作区为空目录，不依赖外部服务、真实账号或网络，全部输入由随题交付的固定种子脚本本地生成。
先执行样本生成步骤，产出事件流 JSONL、进程谱系声明、两代策略声明与真值文件，真值文件记录发送端原始字段与同步标记。
准备本地快照与检查点目录并确保可写，用于验证原子替换、文件锁冲突与强制终止后的恢复路径。

业务要求：
1. 实现事件流、进程谱系声明与两代策略声明的严格解析规范化层：v1 的相对生效秒须以样本内声明的观测时钟为唯一基准换算为绝对毫秒，不得使用系统当前时间；校验 endpoint_id、process_guid 与 parent_process_guid 的取值合法性、action_kind 白名单、risk_level 取值范围、observed_ms 为非负整数、payload_digest 长度与所声明算法位宽匹配、规则代数与墓碑标记合法，对非法记录输出含来源类别与记录序号的业务码拒绝记录并继续处理其余记录。
2. 实现进程谱系归并：以 parent_process_guid 为边把事件归并到根进程判定单元，检测缺失父进程声明、父子自引用与任意长度谱系环，分别返回独立业务码并列出环中 process_guid 序列；同一 process_guid 被多个会话声明不同父进程时判为谱系分叉，须返回分叉业务码并给出该进程的所有候选根进程，分叉进程不得被静默归入任一侧。
3. 把两代策略声明合并为统一策略视图：以规范策略键为实体键，按规则代数与生效时刻裁决同一策略的权威来源，墓碑标记必须覆盖较早的非墓碑记录；匹配串按规范化口径对齐，当两代对同一策略键的动作码、匹配串或生效窗口给出不一致结论时进入冲突清单并保留两侧依据代数，冲突清单须与声明到达顺序无关。
4. 实现判定单元内的策略命中裁决：按 observed_ms 落在生效窗口内、匹配串与事件 payload_digest 规范化内容相符两个条件筛选命中策略，同一单元多条策略命中时按规则代数、动作码与规范策略键的稳定顺序裁决出唯一结论，被压制策略须进入命中明细；命中判定只能依据统一策略视图与事件本身，不得引用样本生成器的中间计算结果。
5. 实现策略修订与谱系变动的增量重判闭包：策略声明增量到达或墓碑化、谱系声明使某进程从单一归并变为分叉或反向合并时，沿策略键到事件到判定单元的依赖关系计算需重判的单元集合，仅重判受影响部分，并要求重判后的单元结论、命中明细与分叉清单与从零全量重判逐条一致，不一致时返回重判不一致业务码。
6. 保证归并与裁决与到达顺序无关：相同输入在任意事件与声明交错顺序、任意批量切分下，每个判定单元的结论、命中明细、谱系分叉清单与拒绝记录必须完全一致；observed_ms 或规则代数相同时须以规范策略键与 process_guid 的稳定排序确定次序，不得依赖到达顺序或字典遍历顺序，报告中的单元与命中项须按稳定键归一化。
7. 实现检查点演进与强制终止后的恢复边界：按已处理批次水位与归并裁决账本摘要把检查点持久化到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放比对账本一致性以识别半写残留；进程被强制终止后仅允许恢复到最后一个完整检查点，不承诺生成退出报告；检查点结构版本或合并口径版本变化时须整体重建而非增量续接。
8. 实现真实资源预算、原子快照与批处理容错：并发度、单单元实测耗时上限、待处理单元队列上限与单单元事件处理数上限均可配置，耗时以真实墙钟测量判定而非人为延迟常量，超时返回 E_TIMEOUT 并终止该单元后续处理，超事件数返回 E_BUDGET，队列超限须拒绝入队并计入报告；检查点与报告均先写临时文件、校验内容可解析后整体重命名替换，同一工作目录并发写检查点以文件锁串行化并在冲突时返回 E_LOCK；单份输入解析失败不得中断同批其余输入，退出码区分全部成功、部分失败与参数错误，业务码统一写入可解析 JSON 报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
