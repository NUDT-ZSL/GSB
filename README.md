交付从新建的代码库开始，需要构建一条面向 SRE 值班场景的数据处理管线与结果验证工具，用于在本地确定性样本上复现限流、熔断与降级三类策略在异常注入下的决策轨迹。本地 JSON 样本给出：服务拓扑清单（服务名、实例 ID、上游依赖、优先级、故障域）、限流策略（按服务与全局两级令牌桶的容量、补充速率、突发深度）、熔断策略（滑动窗口长度与步长、失败率阈值、半开探测次数、冷却逻辑毫秒）、降级策略（降级档位序列、每档允许的流量比例、恢复阶梯）以及按可注入逻辑时钟给出的事件流（请求序号、服务名、结果标记、延迟微秒、异常注入标记）。管线需在注入逻辑时钟下逐事件推进状态，输出每次决策的判定依据与业务错误码，并支持进程被强制终止后的恢复与多进程并发提交。核心矛盾是：限流额度消耗与熔断窗口统计必须共享同一事务边界，而降级档位推进又依赖熔断结论，任何一处独立提交都会让另一处读到前后不一致的状态。

任务环境与准备：
Windows 10/11 本地环境，安装 Python 3.11 或 3.12（python.org 官方安装包，勾选 Add python.exe to PATH）。
创建虚拟环境并安装依赖：python -m venv .venv，然后 .venv\Scripts\python -m pip install --upgrade pip，再安装 numpy、pytest、pytest-json-report（版本自选但需在依赖清单中固定）。
确认 SQLite 通过标准库 sqlite3 可用，无需额外安装数据库服务；所有路径使用项目内相对目录，避免依赖系统盘权限。
在仓库内准备样本目录 samples/，包含拓扑策略与事件流 JSON、异常注入清单；样本不依赖任何网络、账号或付费资源，全部由本地文件构成。
提供 pytest 用例入口与子命令脚本入口，命令示例统一在 README 中说明；运行前通过 python -m compileall 验证源码可编译。

业务要求：
1. 实现服务拓扑、限流、熔断、降级四类策略与事件流的解析校验：服务名与事件序号唯一、上游依赖闭合且无环、令牌桶容量与补充速率为正整数、滑动窗口步长为正整数且不大于窗口长度、失败率阈值在开区间内、降级档位比例严格递增且以 1.0 收尾、逻辑时钟毫秒为非负整数；任一条目非法须返回不同业务错误码（如 E_BAD_POLICY、E_BAD_TOPOLOGY、E_BAD_EVENT）且不写入任何持久化状态。
2. 实现基于注入逻辑时钟的限流裁决：每事件按服务级与全局级两级令牌桶计算可用令牌与按补充速率累加的新增令牌，容量与突发深度共同决定单事件可消耗上限；令牌不足时须裁决拒绝并记录所需等待逻辑时长，同一事件序列在任意运行次数下必须得到逐位一致的允许或拒绝序列与令牌余额轨迹，且全程不读取系统墙钟。
3. 实现滑动窗口统计与熔断状态机演进：按窗口长度与步长确定性切分窗口并把每事件唯一归属一个窗口，窗口内成败计数只在窗口完整提交后计入下一次失败率判定；熔断器在关闭、打开、半开之间迁移，半开探测次数达到上限且探测全部成功方可闭合，失败须重新打开并重置冷却逻辑毫秒；重启后不得凭内存残留决定熔断状态。
4. 实现降级档位的流量比例推演与恢复阶梯：当熔断器打开或全局错误预算耗尽时按降级档位序列逐档降低允许流量比例，恢复时按恢复阶梯逐档回切，每一步回切须校验目标服务健康结论与持久化熔断状态，中途失败必须停留在上一稳定档位并记录裁决依据；降级档位推进不得使被拒绝请求反过来计入熔断窗口的失败统计。
5. 实现三级状态的单事务联动提交：每事件的令牌扣减、窗口计数写入、熔断状态迁移与降级档位推进必须在同一 SQLite 事务内提交，读取方只能看到完整已提交事件，不得出现令牌已扣而窗口未计或熔断已开而降级未推的中间态；同一事件序号重复提交必须幂等且不得重复累加计数或令牌。
6. 实现强制终止后的恢复裁决：把已提交事件水位、两级令牌余额与补充时钟、窗口摘要、熔断状态与本轮半开探测计数、降级档位以事务原子写入 SQLite 并识别版本变化整体替换指针；进程在限流裁决、窗口提交或档位推进任一阶段被强制终止后，恢复路径须识别已提交事件与半提交事件，只重放水位之后的事件且不重复计入令牌或失败率；恢复后须能重建出与不中断运行逐字段一致的决策轨迹。
7. 实现受控异常注入与异常链路隔离：按注入清单在解析、限流、熔断、降级四阶段分别注入策略版本冲突、令牌桶补充时钟回拨超容差、窗口摘要不匹配、半开探测计数越界与降级档位非法回退；每种异常映射到不同业务错误码并在输出中保留可诊断字段（事件序号、服务名、阶段、依据窗口号）；单个服务异常不得污染其他服务的令牌余额、窗口计数与熔断状态。
8. 提供数据处理管线与结果验证工具：支持 load、run、replay、resume、status、verify 子命令，status 以稳定排序 JSON 输出各服务令牌余额、窗口号、失败率、熔断状态、降级档位与逻辑时钟水位；verify 校验持久化状态与全量重放结果逐字段一致，并对长度、失败率与比例的定点换算记录舍入方向与误差上界，使所有诊断字段可复现。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
