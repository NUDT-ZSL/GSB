在程序化关卡生成场景中，需要从零开发一个本地关卡约束求解引擎，用于为网格地图分配房间与走廊并满足连通性、间距与区域限制。输入为 JSON 描述的关卡规格：网格宽高、不可用格集合、约束条件集合（包括连通性、最小房间数、区域面积上界、房间间距下界、起点终点可达等），以及确定性随机种子。引擎按约束顺序逐步求解，每步可能对网格进行修改，并产生中间状态快照。业务需求来自关卡编辑器中的“试算与续算”：设计者在求解过程中可主动中断，之后再次启动须从保存的快照恢复并继续求解，且最终结果必须与不间断求解完全一致；快照被外部修改或版本过期时须能识别并安全拒绝。所有输入由程序按确定性规则生成本地样本，不依赖任何外部资源。

任务环境与准备：
Windows 10 或更高版本，安装 Python 3.10 及以上并确保 python 与 pip 在 PATH 中。
安装 NumPy 1.24 及以上版本，使用 pip install numpy 完成。
无需外部服务、账号、数据集或附加文件；所有测试样本由程序按题目中的确定性规则生成。
准备一个空白工作目录作为项目根目录，确保有可写权限以创建快照目录与输出文件。

业务要求：
1. 实现关卡规格与约束集合解析：读取 JSON 规格，校验网格宽高为正整数、不可用格坐标在网格范围内、约束类型属于允许集合、数值参数为有限数且满足自身定义域（如最小房间数不超过可用格数、间距下界为非负整数），非法输入返回带 E_xxx 业务码的 JSON 错误且不产生任何快照或输出文件。
2. 实现确定性约束求解流程：按约束集合声明顺序逐个应用约束，每个约束对网格的修改只依赖当前网格状态与种子派生的确定性伪随机序列，同一规格与种子重复求解必须得到逐格相同的最终网格与相同约束应用计数，禁止依赖全局随机状态或系统时间。
3. 实现约束间冲突检测与回退：当后续约束与已满足约束冲突（如新增走廊切断已有连通区域）时，记录冲突约束对并回退到最近一次不冲突的网格状态再尝试替代方案，回退深度上限由规格给出；超过上限返回 E_CONFLICT 并报告无法满足的约束标识，不得输出部分满足的网格。
4. 实现分步状态快照：每成功应用一个约束后，把当前网格、已应用约束序号、种子与约束集合的规范化摘要构成的版本标识写入快照目录，快照整体替换前须比对版本标识，版本变化时不得直接覆盖旧快照，需先归档或标记旧版本。
5. 实现中断与续算恢复：求解过程在约束边界可被可处理终止信号中断，中断时写入中断标记并以约定整数退出码退出；再次启动时读取中断标记与最新快照，版本标识一致则从下一约束继续求解，不一致则从头重做；强制终止后仅依赖已持久化快照恢复，不承诺生成退出报告。
6. 实现快照防篡改与拒绝：对每份快照计算内容摘要并与快照中记录的摘要比对，摘要不匹配或缺失时判定快照失效并返回 E_DIGEST；续算恢复时必须拒绝失效快照并回退到最近一份有效快照或从头开始，禁止静默使用被篡改状态继续求解。
7. 实现并发约束预检与资源上限：在应用约束前，按规格中的并发数并行对候选约束做可行性预检（如区域面积上界与房间间距下界），使用有界线程池且同时处理的候选状态数量受内存预算限制，任一预检失败时取消其余任务并汇总首个错误，最终选定的约束应用顺序与串行预检结果一致。
