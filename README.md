当前是空白工作区，需要从零构建一个面向本地 Windows 环境的多集群配置分发账本诊断台，聚焦云原生多集群配置分发中的交互延迟与计算结果一致性。用户在本地 JSON 文件中声明一组集群（每个集群含集群标识、回环端口、节点列表与配置版本）以及一组配置分发任务（任务引用若干配置键与目标集群，并规定聚合口径）。系统须在回环 TCP 端口上运行确定性集群模拟服务，接收配置分发请求并按配置版本执行确定性聚合计算，返回聚合摘要与计算耗时。诊断台须在界面中持续展示分发任务进度、各集群的配置版本与聚合结果摘要，同时记录每次分发与查询的交互延迟，并验证界面展示的结果与按配置版本重算的权威结果一致。

任务环境与准备：
安装 Python 3.11 或以上版本，并确认标准库 tkinter 可用（Windows 官方安装包默认包含）。
准备本地确定性样本数据文件与多集群声明 JSON 文件，样本数据用于集群模拟服务的确定性聚合。
在任务工作区创建项目目录，SQLite 使用 Python 标准库 sqlite3，无需额外安装数据库服务。
运行前确认回环端口未被占用，演示脚本按顺序启动集群模拟服务并触发分发与快照操作。

业务要求：
1. 实现多集群声明与分发任务的加载及强校验：从本地 JSON 读取集群定义、节点列表、配置版本与分发任务，校验集群标识唯一、端口为回环字面量且全局唯一、配置版本号单调递增、任务引用的配置键必须存在且目标集群已声明；任一不合法须以 E_CONFIG 业务码整体拒绝加载并输出出错字段路径，不得部分加载。
2. 实现确定性集群模拟服务与本地回环通信：以子进程在指定回环端口启动集群模拟服务，接收 JSON 行协议的分发请求，按配置版本对确定性样本数据执行聚合并返回聚合摘要与计算耗时毫秒；相同请求重复发送必须返回逐字节一致的聚合摘要，服务端与客户端时钟基准须在报告中明确声明，真值来源为按同一配置版本在本地重算的聚合摘要。
3. 实现分发任务的并行调度与进度账本：在全局并发上限与每集群并发配额约束下并行向各集群分发任务，任一分发须携带单次超时与重试次数，配额耗尽时任务排队且不得绕过配额；每完成一个集群的分发结果须写入本地 SQLite 账本，记录任务标识、集群标识、配置版本、聚合摘要、计算耗时与单调时钟起止毫秒。
4. 实现界面交互的快速展示与权威重算分离：Tkinter 界面从账本读取并展示任务进度、各集群当前配置版本与聚合结果摘要，展示走增量缓存快速路径；同时提供权威重算命令，按账本中每条结果的配置版本重新在本地重算聚合摘要并逐项比较，不一致须以 E_VERIFY 报告任务标识、集群标识与首个差异键。
5. 实现交互延迟观测与预算判定：对每次界面查询与权威重算记录单调时钟起止毫秒差，按任务与集群聚合为均值、P95 与最大值的整数定点表示并给出量化误差上界；当单次界面查询超过显式预算阈值时须记录 E_LATENCY 并输出该次查询的起止时刻与所用数据版本，延迟统计不得掩盖超预算事件。
6. 实现配置版本演进后的结果失效与整体替换：当某集群配置版本递增时，旧版本下该集群的全部聚合结果与界面缓存须标记为陈旧且不得参与当前展示与统计；新版本结果到达后当前视图须整体替换而非增量合并，替换时须稳定列出发生变化的集群、旧配置版本与新配置版本，并保证版本变化期间不出现新旧版本结果混排。
7. 实现会话快照的版本识别与强制终止后的恢复：快照持久化集群声明版本、分发任务、账本结果、延迟统计口径版本与已完成集群集合；进程被强制终止后重启只能依据账本中已完整写入的结果恢复，未完成的分发须标记为未知并要求重跑，不得声称生成退出报告；重新打开快照时须比较快照声明版本与当前声明版本，不一致须整体替换当前账本状态而非增量合并。
8. 实现恢复后的一致性重放校验与异常注入：从快照恢复后按快照记录的配置版本与分发任务重新在本地重算聚合摘要并聚合，将聚合摘要、配置版本与延迟统计口径与快照记录逐项比较，不可复现须以 E_REPLAY 报明具体任务与集群；另支持以命令行参数注入集群服务端口占用、配置版本回退、账本记录摘要损坏三类异常，分别以 E_PORT、E_VERSION、E_LEDGER 业务码报告并写入结构化日志。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
在本地多集群模拟服务上验证分发账本、延迟观测与版本替换，并确认权威重算与恢复重放结果一致。
