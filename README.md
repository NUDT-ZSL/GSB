当前是空白工作区，需要从零构建一个面向本地 Windows 环境的 CDN 边缘缓存一致性可视化与诊断工作台。系统在本地回环端口启动一个源站模拟进程与多个边缘节点模拟进程，边缘节点依据本地 JSON 配置的缓存策略（TTL、键组成、缓存容量与逐出规则）缓存源站响应，并周期性向源站校验内容版本（ETag 与 Last-Modified）。核心业务是：对一段可重复的请求序列，在多个边缘节点与源站之间验证缓存内容与源站版本的一致性，识别陈旧条目、键冲突与逐出导致的错误命中，并在人为注入源站更新、网络不可达与逐出压力时观察一致性变化。工作台采用 SQLite 持久化一次诊断会话（配置版本、请求轨迹、命中记录、一致性结论与快照），并以 Tkinter 展示缓存条目、版本差异与命中归因，所有判定须可复现。

任务环境与准备：
安装 Python 3.11 并在任务开始前确认 python 与 pip 可用，Tkinter 随官方 Python 安装包提供。
无需第三方网络库或外部服务，所有模拟进程均使用 Python 标准库 socket 与 threading 在回环端口通信。
准备本地确定性样本内容文件、缓存策略 JSON、异常注入参数样例与演示脚本目录，任务执行前不预先存在实现代码。
在 Windows 上确认可用回环高位端口段并允许本地子进程启动，运行演示脚本前关闭占用这些端口的其他程序。

业务要求：
1. 实现源站与边缘节点的本地编排：以命令行参数在回环高位端口启动一个源站模拟进程与至少三个边缘节点进程，节点通过回环 TCP 上的 JSON 行协议向源站取内容并回报状态；端口被占用须以 E_PORT 业务码报告，任一进程启动失败须整体清理已启动进程并记录结构化日志，不得遗留孤儿进程。
2. 实现缓存策略配置的加载与强校验：从本地 JSON 文件读取每条内容路径的 TTL 秒数、缓存键组成字段列表、每节点缓存容量与逐出规则，校验 TTL 为正整数、键组成字段互不重复且属于受支持集合、容量为正整数、路径不重复；非法配置以 E_CONFIG 整体拒绝加载并输出具体错误位置。
3. 实现按缓存键的存取与逐出机制：边缘节点按策略把响应写入缓存并记录内容版本（ETag 与 Last-Modified）、写入时间基准与剩余 TTL；容量超限时按声明的逐出规则逐出条目并记录逐出事件；同一请求重复命中须返回同一条目且剩余 TTL 按单一时钟基准递减，键组成不同的请求不得命中同一条目。
4. 实现与源站的版本一致性校验：边缘节点在 TTL 到期或收到强制校验指令时向源站校验内容版本，若源站版本变化须整体替换该缓存条目并递增条目版本号，若校验失败须按策略回源或标记为陈旧；陈旧条目在被重新校验前不得作为新鲜命中返回，返回陈旧内容须显式标注并计入一致性结论。
5. 实现人为异常注入与可复现验证：支持以命令行参数注入源站内容更新、源站连接不可达、逐出压力三类异常，分别以 E_STALE、E_UPSTREAM、E_EVICT 业务码记录到诊断轨迹；注入仅改变输入文件、参数或模拟服务行为，不改动工作台源码，相同注入序列重复执行时命中归因与一致性结论须逐条一致。
6. 实现诊断会话快照的版本识别与整体替换恢复：快照持久化到本地 SQLite，含配置版本、缓存条目、逐出事件、请求轨迹与一致性结论；重新打开快照时先比较快照配置版本与当前配置版本，若不一致须整体替换当前缓存状态与轨迹而非增量合并，恢复后须能对快照中的请求轨迹重新执行校验。
7. 实现恢复后的一致性重放校验：从快照恢复后按快照记录的请求序列与注入序列重新驱动边缘节点与源站，将每个请求的命中状态、返回内容版本、一致性标注与快照记录逐项比较；因配置版本或源站内容版本不一致导致不可复现时须以 E_REPLAY 业务码报告并列出首个差异请求序号。
8. 提供 Tkinter 诊断工作台与可重复演示：界面展示每个边缘节点的缓存条目、内容版本、剩余 TTL、逐出事件、命中归因与一致性差异，并展示当前配置版本与快照列表，渲染顺序稳定；附带本地确定性样本内容与演示脚本，顺序执行冷启动缓存、源站更新后校验、逐出压力与恢复重放四个场景，每个场景输出结构化诊断总结。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
