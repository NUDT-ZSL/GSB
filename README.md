水产养殖场边缘网关把多个塘口的溶氧、pH、温度上报流与增氧机控制指令复用到同一条长连接回传平台，运维人员发现某塘口回传历史曲线时，其他塘口的缺氧告警与增氧指令明显滞后。网关侧已有逐逻辑时刻的帧到达记录、连接复用策略声明（最大并发流数、流优先级、流窗口、帧大小上限）、上行带宽与往返时延，以及消费者读取速率变化和链路瞬断事件。运维人员需要一套在本机运行的离线分析工具，说清每条流每帧从就绪到实际发出的等待时长、阻塞源来自哪条大块数据流或慢消费者流、哪些控制指令超出了送达时限，并比较调整并发流上限与窗口分配前后各塘口时延分布的变化。

任务环境与准备：
在 Linux（WSL Ubuntu）上准备 Python 3 运行环境，仅使用标准库，不安装第三方包。
在空工作目录中创建题目源码与内置确定性样本生成器，样本与轨迹输出均落在仓库内文件。
运行内置生成器产出固定种子的塘口网络工程，再通过终端演示入口装载、调度、调整策略与保存快照验证结果。

业务要求：
1. 装载一份塘口网络工程，解析塘口号、传感器类型、控制指令目的设备等流标识，以及每帧的逻辑到达时刻、帧长度、所属流和就绪标记，按逻辑时刻生成逐流有序的到达序列，并对逻辑时刻倒序、流标识重复定义、帧长度非正等输入给出带业务码（E_ORDER、E_DUPSTREAM、E_FRAMELEN）的拒绝结论而非静默跳过。
2. 实现逐帧发送调度器：在声明的最大并发流数、流优先级和流窗口约束下，按逻辑时刻推进帧发送，考虑上行带宽对发送耗时的占用与往返时延对窗口归还的滞后，输出每帧的实际开始与完成发送时刻，且同一逻辑时刻有多帧竞争时按优先级和流标识的确定次序裁决。
3. 以帧就绪时刻到实际开始发送时刻之差定义队首阻塞时延，逐帧输出该值与对应阻塞源，并区分阻塞来自同连接上大块帧占用带宽、窗口被未归还帧占满，还是消费者读取速率下降造成的排队累积。
4. 按流与塘口汇总队首阻塞时延的均值、最大值、分位值与超时帧数，并对控制指令流单独给出是否在声明时限内送达的判定与超时指令清单，清单中每条列出阻塞源流标识与阻塞类型。
5. 处理消费者读取速率变化与链路瞬断事件：速率下降后按新速率影响窗口归还与待发队列，瞬断期间的帧标记为等待并在恢复后继续调度，恢复时刻不早于瞬断结束时刻，且瞬断跨越多帧时不得打乱同流内帧的先后次序。
6. 在已装载工程上调整并发流上限、流优先级次序和窗口分配，重建完整调度轨迹，输出调整前后逐塘口逐流的队首阻塞时延分布对比，并给出针对识别出的阻塞源的优化建议，建议需引用具体流标识与调整项。
7. 支持把装载后的工程与某次调度轨迹状态保存为快照，重新加载后从快照继续调度，续算结果须与不中断全量重算逐帧一致；快照需带版本标识，装载版本不符或字段缺失时返回 E_SNAPVERSION 并提示期望版本。
8. 提供本地可交互演示入口，在终端以命令序列驱动装载、调度、调整策略、保存快照与续算，并对每一操作输出可逐帧核对的调度轨迹摘要与时延统计，全部样本由内置确定性生成器按固定种子产出，不依赖真实网络服务。

验收：
以固定种子工程与手工边界样本，逐帧比对独立参考调度器的发送时刻与队首阻塞时延，核对超时指令清单、策略调整对比及快照续算一致性。
