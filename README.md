项目从零开始，需要构建一个面向 LLM 推理采样与解码策略的本地可视化与诊断工作台，核心业务问题是并行调度与资源预算。业务对象是本地确定性生成的推理任务清单（JSONL，字段含请求标识、提示词 token 序列、采样参数、目标生成长度、种子与优先级），以及由固定种子驱动 NumPy 生成的 logits 序列与词表映射，不依赖任何真实模型或外部服务。系统需把一次批量解码建模为多级流水：按请求分块采样、温度缩放与 top-k/top-p 截断、确定性随机数序列驱动的 token 抽取、逐 step 上下文拼接与完成判定、批量结果汇总。工作台需在可配置的并发槽位、总采样步数预算与驻留缓存内存预算下完成调度，并输出可复核的调度计划与偏差归因。

任务环境与准备：
安装 Python 3.11 或以上版本，并执行 pip install numpy 获取 NumPy 2.x。
在本地工作区创建项目目录，无需数据库、容器或网络服务。
准备本地确定性样本生成脚本，按固定种子生成请求清单、logits 序列与词表映射，样本规模可由命令行参数控制。
确保运行环境支持本地进程池与临时文件原子替换，工作目录可读写。

业务要求：
1. 实现确定性的逐 step 采样核心：按请求的采样参数完成温度缩放、top-k 与 top-p 截断，再用显式声明的固定随机种子驱动的确定性随机数序列逐 step 抽取 token；同一请求、同一参数与同一种子下必须逐字节产出相同 token 序列与逐 step 候选截断记录，禁止依赖系统时间或未声明随机源。
2. 实现批次分块调度层：按可配置的并发槽位与每批请求数把请求分组分派到本地进程池，分块边界、派发顺序与归并顺序必须确定性可复现；每个请求的 token 序列必须与单独执行结果逐字节一致，检测到差异返回 E_BATCH_MISMATCH 并指出请求标识与首个偏差 step。
3. 实现三预算准入裁决：为总采样步数预算、同时驻留 KV 缓存条目数与并发槽位分别设可配置上限，按显式优先级规则在请求优先级、目标生成长度与缓存规模之间裁决准入集合；超限请求分别返回 E_STEP_BUDGET、E_CACHE_BUDGET、E_SLOT_BUDGET 并归因到具体请求标识与超限维度。
4. 实现预算冲突的取舍裁决记录：当增大并发槽位缩短整体完成时间但放大驻留缓存、延长目标生成长度提升质量但放大采样步数预算、收紧 top-p 减少候选但可能淘汰本应保留的 token 时，须按显式优先级规则裁决，并在调度计划中记录所选策略、各请求的准入状态与理由，同一观测下决策逐字节一致。
5. 实现采样产物与调度计划的版本化快照及整体替换：采样结果、预算账本与逐请求决策记录各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补；旧版本不得覆盖新版本，回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符的快照读取返回 E_SNAPSHOT_CORRUPT 并指明快照名与版本号。
6. 实现强制终止后的恢复逻辑：执行器在请求边界提交检查点，重启时读取最近一次已提交检查点，从记录的下一请求继续，已提交请求的 token 序列与已消费预算不得重算或重复计入；未提交的中间采样状态必须丢弃并重建。恢复后的完整结果与不间断运行逐字节一致，恢复报告须列出已提交请求集与重执行请求集且二者无交集。
7. 实现输入与配置校验链路并沿异常链路归因：重复请求标识、采样参数越界、目标生成长度非正、种子不可解析、词表版本缺失分别返回 E_DUP_REQUEST、E_SAMPLING_INVALID、E_LENGTH_INVALID、E_SEED_INVALID、E_VOCAB_VERSION_MISSING 并指明字段；单个请求异常须归因到具体请求与阶段且不影响其余请求继续执行。
8. 实现本地可交互诊断工作台与跨模块一致性自检：展示请求列表、逐请求采样参数、逐 step 候选截断与抽取结果、预算账本余量、调度决策依据、恢复报告与最近业务错误码，支持触发一次含预算超限与一次含强制终止恢复的演示；自检校验参与采样的请求集合与准入集合并集一致、预算扣减与释放可由逐请求明细重算、被拒请求不出现在采样结果中，不一致返回 E_INCONSISTENT 并指出首个偏差位置。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证逐 step 采样、预算裁决、快照替换与中断恢复，核对结果逐字节一致并输出诊断报告。
