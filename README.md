在空白工作区构建一个面向本地确定性样本的搜索精排与重排组件，用于对多路召回候选做特征融合打分、重排与精度可信度诊断。输入为一个本地样本目录：候选集 JSONL（每行含请求 ID、候选物品 ID、各路召回分数、若干稠密特征向量与稀疏特征计数），一份精排配置 JSON（特征权重、归一化方式、融合温度、打分截断区间、定点小数位宽与量化档位、重排窗口大小与多样性惩罚系数、并发数、快照提交间隔），以及一份特征分组表（声明哪些特征属于同一组并存在量纲冲突）。组件需按请求完成特征归一化、加权融合打分、窗口内重排与多样性惩罚，全部打分链路以定点整数运算，并逐级追踪定点量化与归一化带来的误差传播，输出可复现的诊断报告。核心约束是：定点位宽与量化档位必须真实改变中间整数段与最终排序，且同一输入在任意运行中产出逐元素一致的结果。

任务环境与准备：
安装 Python 3.10 及以上，并安装 NumPy 1.24 及以上版本；无需 GPU、数据库或网络访问。
创建空白工作区目录，在其中准备本地确定性样本生成脚本所需的参数文件（权重、特征分组表、精排配置），样本由固定种子程序生成。
确认 Windows 下可正常读写临时文件并进行原子替换操作，快照目录有足够写权限。
准备本地测试入口，可分别执行完整运行、中断后续跑、并发度变更与注入故障四类场景。

业务要求：
1. 实现候选集与配置加载层：逐行解析候选集 JSONL，校验请求 ID 非空、候选物品 ID 在请求内唯一、各召回分数与稠密特征为有限数、稀疏计数为非负整数；加载精排配置并校验权重长度与特征维度一致、定点小数位宽在允许区间内、重排窗口大小为正；不合法条目或配置分别输出 E_INPUT_INVALID 与 E_CONFIG_INVALID 业务码并进入失败清单，其余条目继续处理
2. 实现以定点整数表示的特征归一化与加权融合打分：对每个候选的各路召回分数与稠密特征按配置归一化方式（最小最大或 z 分数）归一化，再依定点小数位宽转为定点整数，按特征权重与融合温度做加权求和，最后按打分截断区间裁剪；同一请求内归一化统计量必须只由该请求参与候选决定，转换点与裁剪点均需记录舍入残差，舍入规则取自配置并写入产物元数据
3. 实现窗口内重排与多样性惩罚：按融合得分降序取重排窗口，窗口内依配置的多样性惩罚系数对与已选候选特征相似度过高的候选做得分折减后重新插入排序；折减计算同样以定点整数执行，相似度相等与折减后得分相等时按候选物品 ID 字典序决断；输出每个请求的最终排序、每次折减的候选对与被折减量，关闭多样性惩罚时必须真实退化为纯得分排序而非静默沿用旧顺序
4. 实现逐级误差传播追踪：对同一请求分别以配置档位与高一档位定点位宽完整计算归一化、加权融合、裁剪与重排折减四个环节，输出各环节逐候选差值与首次超过配置容差所在环节的标注；当某候选在两种位宽下重排名次不一致时记为边界敏感候选并给出其主导贡献特征；最终排序差异清单须按请求 ID 与名次升序排列
5. 实现阶段化快照整体替换与恢复一致性：将加载校验、归一化、融合打分、重排划分为阶段，每个阶段以临时文件写盘后整体替换提交，清单文件记录全局版本号、配置哈希、特征分组表哈希、已处理请求游标与各阶段产物版本；启动时读取最新清单并校验版本号与配置哈希，不一致输出 E_CONFIG_MISMATCH 并拒绝续跑，一致时从游标之后继续，恢复后结果与不中断运行逐字段一致
6. 实现增量失效与缓存复用判定：为归一化统计量、每候选融合得分与每次重排折减计算由请求内容指纹、相关特征指纹与参数指纹派生的缓存键；当增删候选、修改某特征权重或位宽档位时，仅使受影响请求的相关阶段及其下游失效并纳入重算集合，未失效产物必须直接复用且不得重复计算，复用与重算清单须在报告中逐请求列出
7. 实现并发打分与串行结果一致性：使用线程池并发处理请求及其候选打分，最大并发数取自配置；每个候选任务携带由请求 ID 与候选物品 ID 派生的稳定排序键，无论线程调度顺序与并发度如何，最终候选得分、排序结果、折减候选对顺序、误差清单顺序与失败清单顺序必须与单线程按请求顺序处理逐字段一致
8. 实现异常注入隔离、退出语义与诊断报告：以独立注入配置对指定请求的指定阶段施加真实输入故障（非有限特征、权重长度不匹配、位宽越界、相似度恰好等于折减门限），注入项编号写入报告以证明命中；单请求在任一阶段抛异常时记录请求 ID、阶段名、业务码与异常类型并继续其余请求；收到可处理的退出信号时完成当前阶段清单原子替换后以整数退出码 0 退出；每次完整运行输出 JSON 诊断报告，含各请求排序、误差归因摘要、缓存命中与失效计数、失败清单与配置指纹

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
