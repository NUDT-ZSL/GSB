当前是空白工作区，需要从零实现一个本地延迟队列中间件及其领域数据编辑与操作应用。延迟队列以任务为核心对象：生产方按本地 JSON 清单提交任务（任务 ID、主题、触发逻辑时钟毫秒、重试策略标签、载荷内容摘要、最大重试次数），消费方在任务到期后拉取并回报成功或失败。中间件内部以多级时间轮组织到期扫描，并支持在数据规模变化时在精确最小堆与多级时间轮之间切换调度算法。任务失败后按重试策略计算下一次触发逻辑时钟并重新入队，重试次数耗尽后进入死信。全部时间判定只依赖可注入的逻辑时钟毫秒值，不读取系统墙钟。样本为确定性 JSON 任务流与重试策略表，不依赖任何外部服务。

任务环境与准备：
安装 Python 3.11 或更高版本，并确认标准库 sqlite3、json、heapq、multiprocessing 可用。
安装 NumPy（建议 1.26 以上）用于退避时间与规模观测的数值计算。
在本地工作区新建项目目录，准备固定 JSON 任务流样本、重试策略表与逻辑时钟步进配置，样本内容需自洽且可重复。
确认项目目录可写，SQLite 数据库文件与日志目录位于工作区内。
无需容器环境、外部服务或网络访问，全部验证在本地完成。

业务要求：
1. 实现任务清单与重试策略表的解析校验：任务 ID 唯一、主题名合法、触发逻辑时钟为非负整数、最大重试次数为非负整数、重试策略标签存在且其退避基数与上限为合法正整数、载荷内容摘要与内容一致；非法输入必须返回明确业务错误码且不写入任何持久化状态。
2. 实现精确最小堆调度模式与多级时间轮调度模式两种到期扫描算法：最小堆按触发时钟严格排序，时间轮按配置的轮级粒度与轮数分桶；两种模式对同一任务流在相同逻辑时钟序列下必须产生逐位一致的到期任务序列，并提供算法选择依据与切换触发条件的可查记录。
3. 实现数据规模变化下的调度算法自适应切换：依据待调度任务数、触发时钟跨度与时间轮粒度估算两种模式的扫描开销，当规模超过配置阈值时按明确规则切换算法，切换过程中在途到期任务不得丢失或重复触发，并输出实际使用的模式、切换时刻与切换前后的规模观测值。
4. 实现失败重试与指数退避：任务失败后按重试策略与当前重试次数计算下一次触发逻辑时钟，退避计算施加确定性抖动与上限，同一任务同一重试次数重复计算必须得到相同结果；重试次数耗尽的任务进入死信并记录耗尽原因与最后一次错误码，死信不得再次被正常调度命中。
5. 实现消费拉取、成功确认与幂等语义：消费者按主题与逻辑时钟拉取到期任务并回报成功或失败，重复确认、迟到确认与跨消费者确认必须幂等且不得改变已提交结果；未确认任务在拉取超时后按配置重新入队，重试计数与触发时刻必须与持久化状态一致，不得凭内存残留判定重投。
6. 实现持久化状态与强制终止后的恢复：把任务阶段、重试次数、下一次触发逻辑时钟、已提交确认水位与调度模式决策以事务原子写入 SQLite；进程在入队、到期触发或确认提交中途被强制终止后，恢复路径依据持久化状态识别已提交任务与半提交状态，只重放未完成部分且不得重复触发已提交任务或重复计入重试次数。
7. 实现多进程并发一致性与调度模式版本整体替换：允许多个调度实例与消费实例并行，通过 SQLite 事务与文件锁保证同一任务同一版本只被触发一次、同一确认只被提交一次、重试次数不被并发超增；调度模式配置每次变更产生新版本号并整体替换当前模式指针，进行中的扫描必须绑定其开始时的模式版本，读取方不得观察到新旧模式混合。
8. 实现异常链路与可重复命令行演示：任务不存在、重试策略标签缺失、逻辑时钟回拨超过容差、调度模式版本回退、确认引用不存在的拉取记录分别映射到不同业务错误码并保留可诊断字段，单次异常不得中断其他任务的调度；提供 enqueue、poll、ack、resume、status、verify 子命令，status 以稳定排序 JSON 输出任务阶段、重试次数、下一次触发时钟与当前调度模式，verify 校验持久化状态与任务流摘要的一致性。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
