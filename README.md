预算和周期确定后的新项目里，团队需要从零交付一个面向文生图潜空间分块去噪与解码的本地诊断引擎，重点解决分块并行调度与计算误差账本的一致性问题。工作区当前没有任何代码或样本，全部输入由随题固定种子脚本在 Linux（WSL Ubuntu）本地生成：任务清单为 JSONL，字段含 task_id、prompt、prompt_seed、latent_shape、block_grid、sampler_steps、noise_scale、quant_scale、rounding_mode 和 dtype_profile；潜变量由种子驱动 NumPy 确定性生成，无真实模型或外部依赖。系统将生成链路建模为四级流水：文本条件嵌入、初始噪声构造、分块逐步去噪与边界归一化、潜帧解码为 RGB，并把分块执行与整块参考路径的误差账本写入 SQLite 元数据库。

任务环境与准备：
安装 Python 3.10 及以上版本与 NumPy。
使用 pip 安装任何附加依赖（若有）。
运行随题交付的固定种子样本生成脚本，在本地生成任务清单、潜变量和配置 JSON。
准备空白的 SQLite 文件路径供误差账本元数据写入。

业务要求：
1. 实现确定性的文本条件嵌入与初始噪声构造阶段：把 prompt 按受控词表映射为固定维度条件向量，再结合 prompt_seed 与 noise_scale 生成初始潜变量；同一 task_id、同一种子与同一配置下必须逐字节产出相同的条件向量与初始潜帧，忽略大小写差异后哈希一致，禁止依赖系统时钟或未声明的随机源。
2. 实现按 block_grid 分块逐步去噪与边界归一化阶段：每个块独立推进 sampler_steps 步，块内每步去噪后按全局统计量归一化边界元素，归一化统计量必须与整块口径完全同源；块间边界潜变量在 float64 下与一次性整块去噪对应位置逐元素一致，任何由分块导致的相位或归一化偏差都应记录到误差账本。
3. 实现可切换的 dtype_profile 执行层：float64、float32 与定点缩放整数三档共用同一算子语义，定点档的 quant_scale 与 rounding_mode 由配置显式给出；切换 dtype_profile 不得改变各分块调度次序，同一输入在两档下的潜变量与 RGB 输出差异必须可完全归因于量化舍入。
4. 实现并行调度与双重预算准入裁决：按可配置 worker 数与每批任务数把 task 分派到本地进程池执行分块去噪，分块边界、任务派发顺序与归并顺序须确定性可复现；为总去噪迭代次数预算与驻留潜变量内存估算设置可配置上限，超限时按显式优先级返回 E_ITER_BUDGET 或 E_MEMORY_BUDGET 并记录被拒绝任务。
5. 实现误差账本写入与精度档偏差裁决：以 float64 整块参考路径为真值，为每个分块任务输出边界元素偏差与整块拼接后的最大绝对偏差、相对偏差和误差放大比，定位主导误差来源为量化、归一化或分块边界；偏差超过配置容差返回 E_TOLERANCE_EXCEEDED 并携带 task_id 与首个偏差位置。
6. 实现基于内容寻址的缓存与依赖失效传播：任务级条件向量、每步潜变量、归一化统计量和误差账本条目各自携带内容哈希落盘；当某任务的 dtype_profile、quant_scale、block_grid 或 prompt_seed 以更高修订号变化时，只对受影响任务及其下游账本条目做失效重算，未受影响任务必须复用已提交结果，重算与复用集合无交集且并集覆盖全部受影响项。
7. 实现版本化快照、整体替换与并发提交控制：任务清单、预算配置、误差账本和中间缓存快照各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时整体替换旧快照而非增量修补；同一时刻只允许一个快照提交生效，冲突后到者立即返回 E_STAGE_BUSY 且不影响进行中的分块任务。
8. 实现输入校验、强制恢复与跨模块一致性自检：重复 task_id、latent_shape 与噪声维度不符、block_grid 不整除潜空间、quant_scale 非正、预算值非正分别返回结构化业务码；执行器在任务边界提交检查点，强制终止后重启从最近提交处继续且重算已提交任务；自检校验四阶段处理的 task_id 集合一致、每个账本条目可由任务明细独立重算、重用缓存与失败重算记录可互相核对。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
驱动本地确定性样本完成分块去噪与参考对比，核对预算超限、缓存失效与强制恢复后的误差账本一致。
