当前是空白工作区，需要从零构建一个面向本地 Windows 环境的网关限流与鉴权中间件组件，聚焦数据规模变化下的算法取舍。用户在本地 JSON 文件中声明一组路由，每条路由包含路径前缀、鉴权策略（本地令牌表校验或本地签名校验）、限流算法（令牌桶、滑动窗口计数、滑动窗口日志）与对应整数参数（速率、突发容量、窗口毫秒、窗口内最大请求数）；令牌表与策略版本也以本地文件持久化。网关在回环 TCP 端口上以 JSON 行协议接收请求，每条请求携带路由名、客户端标识、令牌与毫秒时间戳，网关须先鉴权后限流，并在被拒时返回稳定业务码 E_AUTH 或 E_LIMIT。核心难点是：当客户端数、令牌表规模与请求时间跨度在不同样本间差异很大时，令牌桶、滑动窗口计数与滑动窗口日志三种限流路径必须对同一请求序列给出一致的放行或拒绝结论，或明确记录其在边界上的差异来源；同时策略版本变化后限流状态与鉴权缓存须整体替换而非增量合并，进程被强制终止后重启只能依据 SQLite 中已持久化的请求账本恢复。

任务环境与准备：
确认 Windows 上已安装 Python 3.11 或以上，并可用 pip 安装 NumPy 与 Tkinter 所依赖的组件；SQLite 使用 Python 标准库 sqlite3，无需额外安装。
在工作区创建项目根目录与 samples 子目录，准备确定性的路由定义 JSON、令牌表 JSON、请求序列 NDJSON 与模拟客户端脚本，样本内容由任务自行生成且不依赖网络。
确认回环高位端口未被占用，进程以命令行参数指定本地端口与工作目录；运行演示前清理上一轮生成的 SQLite 账本与临时目录以保证冷启动可复现。
所有命令与脚本以 Windows 本地方式执行，不涉及容器或外部服务；日志与快照文件统一写入工作区内的固定子目录，便于重复实验。

业务要求：
1. 实现路由、令牌表与请求流的加载及强校验：从本地 JSON 读取路由定义与令牌表，从 NDJSON 读取请求序列，校验路由名唯一、路径前缀合法、限流参数为正整数、窗口毫秒大于零、同一客户端令牌唯一、请求携带的毫秒时间戳单调不减；任一不合法须以 E_SPEC 业务码整体拒绝加载并输出出错文件与行号。
2. 实现鉴权阶段与鉴权结果缓存：按路由声明的策略校验令牌存在性、有效期与绑定客户端，失败返回 E_AUTH 并记录原因，成功则把结果写入带策略版本的缓存；缓存命中须校验条目版本与当前策略版本一致，版本不符时整条缓存失效而非逐条修补，且鉴权结论必须与无缓存逐条校验结果一致。
3. 实现令牌桶、滑动窗口计数与滑动窗口日志三条限流路径：三者按各自声明的整数参数对同一请求序列独立推进状态并对每个请求给出放行或拒绝结论与剩余配额；时间戳推进以请求携带值为准，桶补充量与窗口滑出均以整数运算完成并显式声明截断方向；每条路径须输出逐请求决策轨迹与状态摘要。
4. 实现跨限流算法的结论一致性与边界差异归因：对同一输入比较三条路径的逐请求结论，完全一致时输出一致性摘要，不一致时按请求给出差异时刻、各路径的剩余配额与触发差异的参数边界（如补充截断、窗口对齐或日志保留跨度）；差异归因须与请求遍历顺序无关，且同一请求无论落在序列何处其归因结论须相同。
5. 实现按数据规模自适应的路径选择与取舍记录：依据窗口内最大请求数、窗口跨度与客户端基数按确定性规则选择默认限流路径并输出理由与关键规模参数；当两条候选路径预估每秒工作量之差小于显式阈值时须按稳定决胜规则选择，不得依赖字典或哈希遍历顺序，选择结果须与所选路径的实际决策轨迹对应。
6. 实现策略版本演进与状态整体替换：策略文件或令牌表被修改后版本号单调递增，旧版本限流状态与鉴权缓存须整体替换为新版本派生状态而非增量合并，新版本视图须能稳定列出受影响路由与被清空的缓存条目数；任一展示中的决策结论若其策略版本与当前版本不符须标记为陈旧且不得参与当前汇总。
7. 实现请求账本持久化与强制终止后的恢复：每处理完一个完整请求批次须把批次决策、各路径状态摘要、鉴权缓存版本与策略版本写入本地 SQLite 账本；进程被强制终止后重启只能依据已持久化的完整批次恢复，未完成批次须标记为未知并要求重跑，不得声称能够生成退出报告，恢复后须继续接受新请求。
8. 实现恢复后的一致性重放校验与异常注入：从账本恢复后按记录的策略版本与请求序列重新执行鉴权与三条限流路径，将逐请求结论与账本记录逐项比较，差异须定位到首个不一致的请求序号、路径与字段并以 E_REPLAY 报告；另支持以命令行参数注入策略文件损坏、令牌表版本冲突、窗口毫秒为零三类异常，分别以 E_SPEC、E_VERSION、E_LIMIT 报告并写入结构化日志，注入仅改变输入文件或参数。
