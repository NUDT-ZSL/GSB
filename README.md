当前是空白工作区，需要从零实现一个本地网络流量监测系统的聚合统计引擎，交付可集成的领域组件与完整示例。引擎从本地确定性样本读取流量记录流：每条记录含记录序号、注入逻辑时钟毫秒戳、源与目的回环端点标识、协议标签、方向标记、字节数与包数。业务目标是在固定内存预算内对流量按可配置多级维度（端点对、协议、方向可任意组合成一级或多级分组）做流式聚合，输出字节数、包数、均值与时序分位数，并在内存不足以容纳全部分组状态时把冷分组状态真实溢写磁盘后再回读继续累加。核心矛盾是：分组基数随维度组合与流量规模剧烈变化，内存预算必须硬性成立，溢写与回读又必须保证聚合结果与不做溢写的全量真值逐值一致，且进程被强制终止后能从持久化状态恢复而不重复累加。

任务环境与准备：
安装 Python 3.11 并在工作区创建独立虚拟环境，安装 numpy 与标准库自带 sqlite3，运行 pip install numpy 完成本地依赖。
准备固定本地样本：流量记录流分片文件、聚合计划 JSON、逻辑时钟步进表与溢写目录，全部放在工作区 samples 与 spill 目录下，不依赖外网或真实网络设备。
在工作区确认临时文件原子重命名与 SQLite 文件锁在 Windows 下可用，并约定业务错误码以 E_xxx 形式出现在 JSON 输出或 stderr、进程退出码为整数。
使用固定种子运行演示脚本两次，核对聚合结果、溢写与回读统计及 verify 输出逐字节一致。

业务要求：
1. 实现流量记录流与聚合计划解析：校验记录序号严格递增、逻辑时钟毫秒为非负整数、端点标识为合法回环端点、协议标签与方向标记枚举闭合、字节数与包数为非负整数；聚合计划声明维度组合、分组键规范化规则、内存预算 MiB、单批最大行数、溢写目录与定点标度；非法输入必须返回明确业务错误码且不写入任何持久化状态。
2. 实现固定内存预算下的流式分组聚合状态：每分组维护计数、字节求和、包数求和、平方和与均值，全部分组常驻状态的估算占用不得超预算；预算足以容纳时严格内存聚合，超出时必须把最久未更新的分组状态真实序列化溢写到本地文件并以原子重命名落盘，后续批次按需回读后继续累加，不得以丢弃分组或近似计数代替溢写。
3. 实现溢写回读的一致性校验与分片摘要：每次溢写文件记录分组键、状态字段、所属维度、溢写序号与内容摘要，回读时校验摘要并按溢写序号合并同一分组的多份状态；同一分组多次溢写与回读后的最终状态必须与从未溢写的全量聚合结果逐字段一致，不一致须输出首个分歧分组、两条路径状态值与该分组溢写链。
4. 实现两级内存预算裁决与溢出优先级：内存预算同时约束活跃分组表与回读缓冲，回读缓冲不足时须按确定性规则延迟回读并显式记录延迟原因；当单分组状态本身超出总预算时须返回独立业务错误码而非死循环溢写，并保证此前已提交批次的结果不被回滚。
5. 实现时序分位数与聚合顺序确定性：按固定排序与插值规则计算每分组字节数与包数的时序分位数，浮点通路与定点通路并存，定点换算须记录标度、舍入方向与换算前原始值；相同输入在任意运行次数下逐值一致，NaN 与溢出输入按统一规则裁决并记录。
6. 实现基于注入逻辑时钟的批次水位推进与幂等提交：批次内容摘要校验通过后方可推进水位，摘要不匹配须拒绝推进并保持状态不变；同一批次重复提交必须幂等，不得重复累加计数与字节数；状态演进只依据已提交批次结果裁决，不得凭内存残留决定水位。
7. 实现强制终止后的恢复一致性：把算子水位、已提交批次摘要、每分组状态版本、溢写文件清单、已消费记录序号与逻辑时钟水位以单事务原子写入 SQLite；进程在聚合或溢写中途被强制终止后，恢复路径须识别已提交批次与半提交分组，只重做未完成部分，恢复后结果与未中断运行逐值一致。
8. 实现多进程并发一致性与可重复命令行：多个实例并行推进同一计划的不同批次时，通过 SQLite 事务与文件锁保证同一批次同一分组状态版本只提交一次、同一溢写文件只被物化一次、内存预算不被并发超卖；提供 load、aggregate、resume、status、verify 子命令，status 以稳定排序 JSON 输出水位、活跃分组数、溢写与回读统计，verify 校验持久化状态、溢写清单与全量真值一致；异常链路中样本缺失、摘要不匹配、溢写文件被篡改、逻辑时钟回拨超阈值分别映射到不同业务错误码。
