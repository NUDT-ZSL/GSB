当前是空白工作区，没有现存项目、代码或数据附件。需要从零构建一个可集成的图文生成质量评估领域组件与完整示例，用于对文生图结果做自动质量评估，核心业务问题是交互延迟与计算结果一致性。业务对象是本地确定性生成的评估样本：每张图像由固定种子在固定尺寸画布上确定性渲染，并附带对应提示词与参考描述以及逐样本真值质量分档；评估被建模为多级流水——预处理（降采样、颜色统计）→语义对齐打分（图像分块特征与文本词项嵌入的确定性匹配）→结构一致性打分（边缘与区域分布对比）→质量分归一化与聚合。对外同时提供批量全量评估与按样本 id 的单点查询。核心矛盾是：单点查询若要低延迟，通常依赖粗粒度近似或缓存局部统计量，但批量侧使用全精度计算；两者若不共享同一计算口径与统计量快照，就会出现同一图像在批量报告与交互查询中得分不同、排序不同的问题。样本级异常与快照演进也必须可归因、可核对。

任务环境与准备：
安装 Python 3.10 及以上版本，并安装 NumPy；使用标准库实现持久化与进程池。
准备本地确定性样本生成所需的固定随机种子与受控提示词列表，样本与配置均由工作区自行生成。
确认工作区可写本地缓存与快照目录，用于存放内容寻址条目与版本化快照文件。
在 Windows 本地运行完整示例，使用进程池与本地循环计时，不依赖网络与外部服务。

业务要求：
1. 实现确定性的四级评估流水线：预处理、语义对齐打分、结构一致性打分、质量分归一化与聚合，各阶段输入输出语义明确，图像由固定种子确定性渲染；同一输入、同一配置与固定种子下必须逐字节产出相同的中间特征、各级分数与最终质量分，禁止依赖系统时间、字典遍历顺序或任何未声明的外部状态。
2. 实现批量全量评估与按样本 id 单点查询的统一打分口径：单点查询返回的各级分数与最终质量分，必须与批量报告中同一样本在声明精度内一致，聚合排序同分时按样本 id 升序裁决；检测到偏差返回 E_INCONSISTENT 并指出首次偏差所在的级与样本 id。
3. 实现单点查询的延迟预算控制：按样本 id 查询时，延迟以本地评估循环的实际处理计时作为观测，并按图像像素数、分块数与对齐候选数给出估算记录；超预算时返回 E_LATENCY_BUDGET 并附带已完成阶段标记，禁止以降低精度而不声明口径的方式换取延迟，降级必须显式标记降级类别。
4. 实现统计量与分数的版本化快照及整体替换：归一化统计量、对齐权重与结构对比参数各携带单调递增版本号与内容校验和，提交时整体替换旧快照而非增量修补；切换快照后单点查询必须在原子生效后读取新版本，旧版本不得覆盖新版本，回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT。
5. 实现查询缓存与失效联动：单点查询可缓存特征摘要与各级分数，缓存键须纳入图像内容哈希、文本词项摘要、权重版本与精度配置；当快照版本变化、提示词修正或样本追加时必须计算受影响样本集合并使相关缓存失效重算，须保证缓存命中与否不改变最终分数与排序，并输出命中与重算集合供核对。
6. 实现并发查询与快照切换的隔离：多个单点查询与批量评估可并发执行，快照切换须原子生效，查询侧不得读到新旧统计量混用的中间态；为驻留特征内存与缓存条目数设可配置上限，超限返回 E_RESOURCE_LIMIT 并标记降级类别，并发查询的结果须仍满足与批量结果的一致性约束。
7. 实现输入与配置校验链路：重复样本 id、图像种子与画布尺寸不匹配、提示词为空、精度配置未知、延迟预算或内存上限非正分别返回结构化业务码并指明字段与样本 id；样本级异常须归因到具体级与样本且不得静默丢弃，未被任何级归因的异常须汇总到结果中。
8. 提供可集成的领域组件接口与完整示例，并实现跨模块一致性自检：暴露批量评估、单点查询、快照查询与失效报告入口；自检校验各级处理的样本 id 集合一致、分数区间合法、缓存键与特征摘要可互相核对、缓存命中与重算集合无交集且并集覆盖全部受影响样本，不一致返回 E_INCONSISTENT 并指出类别。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
