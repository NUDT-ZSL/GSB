项目从新工作区启动，需要构建一个面向文生视频关键帧分块扩散生成的本地可交互专业应用。核心业务是在首帧可查询延迟与整段视频一致性之间做可验证取舍，并管理关键帧参数修订引发的缓存失效。业务对象由本地固定种子脚本确定性生成：视频生成任务 JSONL 每行含 clip_id、total_frames、keyframe_interval、frame_shape、noise_seed、prompt（受控词表拼装）、diffusion_steps、block_grid、revision；文本条件由固定种子经词频加权池化得到嵌入，初始噪声由种子确定，逐关键帧通过确定性扩散采样生成，非关键帧由相邻关键帧线性插值得到。系统需支持按关键帧分块生成并查询已就绪帧，同时保证分块关键帧与一次性整段生成逐像素一致；首帧延迟用本地实际处理计时观测，并与块网格大小形成可配置的显式取舍裁决。

任务环境与准备：
准备 Linux（WSL Ubuntu）环境，安装 Python 3.10+、NumPy 和 SQLite3（标准库），无需外部网络。
运行随题交付的固定种子脚本生成本地确定性 JSON 输入，包含视频任务清单和生成配置，存储在当前工作目录下。

业务要求：
1. 实现确定性的条件嵌入与关键帧分块扩散生成流水线，同一 clip_id、noise_seed、prompt 与配置下必须逐字节产出相同的每个关键帧像素与帧索引集合，关键帧间隔与总帧数关系由输入显式约束，非法时返回 E_CLIP_SHAPE。
2. 实现按 block_grid 的关键帧分块生成与已就绪帧查询接口，能返回已生成关键帧的像素区间和内容摘要，并在整段完成前提供部分结果；首帧可查询耗时以本地实际处理计时为观测，并按关键帧块内像素数、diffusion_steps 和相邻关键帧耦合规模给出估算记录。
3. 实现分块关键帧与一次性整段生成在非关键帧插值前的逐像素一致性裁决，块边界处的扩散噪声相位、归一化统计量和条件融合系数必须与整段口径采用同一来源和同一归一化，不一致返回 E_BLOCK_MISMATCH 并输出首个偏差帧索引与像素位置。
4. 实现首帧延迟与一致性的显式取舍裁决，当 block_grid 过小导致边界耦合态增多并放大一致性风险、过大导致首帧耗时超出配置预算时，按配置声明的优先级顺序在块网格、首帧耗时预算和扩散步数近似强度之间裁决，并在生成计划中记录裁决依据和所选块网格。
5. 实现关键帧参数修订后的定向失效传播，当某 clip 的 revision 提升且仅影响该 clip 的关键帧噪声或条件嵌入时，只重算受影响的关键帧块及其下游插值，未涉及此 clip 的其他任务缓存必须复用，并输出本次重算的关键帧集合和复用集合。
6. 实现内容寻址缓存与版本化快照整体替换，关键帧像素、扩散中间态和生成计划均以内容哈希落盘，缓存键纳入 clip_id、noise_seed、revision、block_grid 和上游产物哈希，检测到版本号或校验和变化时整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退返回 E_SNAPSHOT_ROLLBACK。
7. 实现并发查询与生成提交的资源上限控制，多个已就绪帧查询可并发执行，同一时刻只允许一个生成计划或缓存快照提交生效，冲突后到者返回 E_STAGE_BUSY 而不阻塞等待；为单 clip 驻留像素内存和并行生成任务数设可配置上限，超限返回 E_RESOURCE_LIMIT 或降级到串行生成并标记降级类别。
8. 提供本地可交互专业应用与跨模块一致性自检，展示关键帧生成进度、块网格与裁决依据、首块实际耗时、缓存命中和失效传播覆盖范围；自检校验分块与整段像素集合一致、各关键帧可由记录参数独立复算、非关键帧插值可由相邻关键帧重放一致，不一致返回 E_INCONSISTENT。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证分块与整段关键帧生成一致、首帧延迟裁决可复现且参数修订后失效传播正确。
