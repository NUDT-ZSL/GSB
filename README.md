在空白工作区从零实现一个本地 CI/CD 流水线制品缓存管理器，重点解决两代缓存清单格式的互操作与跨版本制品复用裁决。本地样本给出两代制品缓存：v1 为单文件 JSON 清单，记录任务名、制品名、制品内容摘要（SHA-256）、相对写入时间秒数、大小字节与一个扁平任务到制品的映射表；v2 为分片 JSON 加 SQLite 元数据库，记录任务键的规范形式、制品摘要集合、绝对写入时间戳毫秒、缓存代数、命中标签与失效墓碑。流水线由本地 JSON 描述：不同流水线引用不同任务的制品，任务之间可声明上游任务依赖，复用判定必须沿依赖链进行。引擎需加载并合并两代缓存为统一索引，在可注入逻辑时钟下完成复用裁决、失效传播、整体替换识别与中断恢复，并给出稳定可复现的裁决报告。

任务环境与准备：
在 Windows 上安装 Python 3.11 或以上版本，使用的第三方依赖仅从本地 wheel 或离线包安装，不访问网络。
确认标准库 sqlite3 模块可正常使用；准备固定的本地样本目录，包含 v1 单文件清单、v2 分片 JSON 与元数据库、流水线描述与复用任务依赖声明。
准备确定性样本生成与演示脚本所需目录结构，保证脚本可在无网络环境下运行并重复执行。
执行前清空本地缓存索引目录与 SQLite 数据库文件，确保每次演示从同一初始状态开始。

业务要求：
1. 实现 v1 与 v2 两代缓存清单的解析与校验：v1 校验任务名与制品名唯一、内容摘要与制品字节一致、相对写入时间为非负整数、扁平映射表条目与制品声明一致；v2 读取分片 JSON 与 SQLite 元数据库，校验分片内容哈希、缓存代数单调、绝对时间戳为毫秒整数、失效墓碑指向存在的制品；非法清单必须返回明确业务错误码且不写入任何持久化状态。
2. 实现跨版本缓存合并与统一索引：同一任务同一制品在两代缓存中同时存在时，依据清单声明的逻辑时钟与缓存代数裁决最新版本，若无法裁决则按来源格式优先级；合并后每个制品条目须保留来源版本、原始时间表示与原始摘要集合，并输出合并裁决记录，使同一组输入重复合并得到逐位一致的索引与裁决记录。
3. 实现时间语义的模式迁移：v1 的相对写入秒数在注入逻辑时钟下换算为绝对写入时刻并记录换算标度与舍入方向，v2 的绝对毫秒时间戳保持原值；v1 无缓存代数与命中标签的制品迁移为 v2 的统一语义并记录迁移映射，迁移不得改变制品在逻辑上是否仍在缓存有效期内的结论。
4. 实现沿上游依赖链的复用裁决：按流水线描述与任务依赖拓扑序逐任务判定其制品能否复用，裁决需同时考虑制品是否过期、失效墓碑是否存在、上游任务复用结论是否可达；拒绝复用时必须给出首个触发原因与被依赖的任务层级路径，未受影响任务不得被牵连重判。
5. 实现失效增量传播与版本化整体替换：当某任务制品被标记失效或缓存包整体替换时，沿依赖反向计算受影响闭包并精确标记需失效的复用结论；每次替换产生新索引版本并整体替换当前快照指针，收到新缓存包时比较清单版本号、缓存代数下限与分片哈希识别完整替换、增量追加或无需操作，版本回退必须被拒绝。
6. 实现强制终止后的恢复与半写入清理：把当前索引快照指针、合并裁决、迁移决策、复用结论与逻辑时钟水位以事务原子写入 SQLite，替换采用临时表加版本号；进程在合并或替换中途被强制终止后，恢复路径依据持久化状态识别未提交步骤与孤儿产物，只重放未完成步骤，不得重复已完成裁决或回退已提交版本。
7. 实现多进程并发一致性、幂等与业务错误码链路：多实例并行合并或替换同一缓存包时，通过 SQLite 事务与文件锁保证同一缓存版本只提交一次、同一复用裁决重复提交幂等，读取方只能看到完整已提交版本；制品缺失、摘要不匹配、逻辑时钟回拨超阈值、清单版本回退分别映射到不同业务错误码并保留可诊断字段。
8. 提供命令行接口与可重复演示：支持 load、merge、judge、replace、resume、status、verify 子命令，judge 以稳定排序 JSON 输出每个任务的复用结论、触发原因、依赖路径、来源缓存版本与精度标记，status 输出索引版本、各来源缓存版本与失效制品数；演示脚本使用固定本地样本运行两次并产生逐字节一致的输出。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地两代缓存样本完成合并、复用裁决、失效传播与恢复，运行两次输出逐字节一致且异常返回业务错误码。
