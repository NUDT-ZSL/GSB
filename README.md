授权服务的会话固定问题在一次离线渗透复盘中已被确认为真实缺陷：登录成功后会话标识不发生轮换，攻击者预先植入的会话能在权限提升后被复用。团队现在要在 Windows 空白工作区落地一个离线验证组件，用确定性样本证明修复策略确实切断了这条路径，并在进程被中断后仍能复现同一份裁决。样本由随题交付的固定种子脚本生成，不依赖真实账号、外部 IdP 或网络：会话声明给出会话标识、用户标识、签发与过期整数毫秒时刻、绑定设备标识、会话代数、前代会话标识与固定窗口起止；登录事件流按可注入逻辑时钟给出事件序号、会话标识、尝试结果与权限提升标记；轮换策略以两代格式并存，v1 为单文件 JSON，记录相对启动秒、轮换模式与最小轮换间隔秒，v2 为分片 JSON 加 SQLite 元数据库，记录绝对毫秒生效时刻、策略代数、绑定校验要求与墓碑标记。

任务环境与准备：
安装 Python 3.11 并在 PATH 中可用，执行 pip install pytest 以获得测试运行能力。
确认工作目录为空且具备写权限，SQLite 由 Python 标准库 sqlite3 提供，无需额外安装。
使用随题交付的固定种子样本生成脚本产出会话声明、登录事件流与两代策略快照，全部写入本地目录，运行期不访问网络与系统当前时间。

业务要求：
1. 实现会话声明、登录事件流与两代轮换策略的严格解析规范化层：校验会话标识与用户标识唯一性、签发时刻小于过期时刻、会话代数与前代链一致、v1 相对启动秒与最小轮换间隔为非负整数、v2 绝对毫秒时刻与策略代数为非负整数；对非法记录输出含来源类别与记录序号的拒绝清单并继续处理其余记录。
2. 把两代轮换策略合并为统一判定视图：v1 的相对启动秒须以样本声明的观测时钟为唯一基准换算为绝对毫秒，禁止使用系统当前时间；同一规范策略键按策略代数与生效时刻裁决权威来源，墓碑标记必须覆盖较早的非墓碑记录；两代对轮换模式或绑定校验要求给出不一致结论时输出冲突明细，不得静默取其一。
3. 实现会话固定缺陷判定：识别登录事件在已存在的会话上成功且权限提升后会话标识未变的情形，判为 E_SESSION_FIXATION 并给出被复用的原会话标识；识别轮换发生后旧会话标识仍被后续事件引用，判为 E_ORPHAN_SESSION；同一会话在最小轮换间隔内被重复轮换须判为 E_ROTATE_TOO_FAST，上述结论均以合并后策略视图为准。
4. 按会话代数链重建轮换后继关系，撤销某次登录或某个会话时沿会话到后继会话的依赖边计算传递失效闭包，遇到环状前代引用返回 E_SESSION_CYCLE 并列出环中会话标识；失效闭包结论必须与事件到达顺序无关，代数或时刻相同时以稳定键确定次序。
5. 在 SQLite 中维护会话裁决账本：以会话标识与代数为主键记录修复状态、依据策略代数、绑定校验结论与判定水位，每轮裁决在单事务内推进，前置校验失败不得改动任何账本状态；账本格局版本（轮换模式或绑定校验口径）变化时须整体重建而非增量续接，不得把旧策略下的修复结论与新策略混合。
6. 实现检查点演进与强制终止后的恢复边界：按已处理批次水位与账本摘要把检查点持久化到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放比对账本一致性以识别半写残留；进程被强制终止后不承诺生成退出报告；检查点与裁决报告均先写临时文件、校验可解析后整体重命名替换。
7. 保证裁决与处理顺序及并发度无关：同一组样本在任意事件交错顺序、任意批次切分与任意并发度下，每条会话的修复结论、轮换后继关系、失效闭包集合与拒绝清单必须完全一致，输出中的会话与闭包条目须按稳定键归一化；同一工作目录并发写检查点以文件锁串行化，锁冲突返回 E_LOCK 且不得破坏既有账本。
8. 交付可交互命令行与确定性本地验证：提供导入、固定缺陷裁决、撤销传播、导出诊断报告、校验检查点五类子命令，单份样本解析失败不得中断同批其他样本，退出码区分全部成功、部分失败与参数错误；报告为可解析 JSON 并含会话级结论、业务码、依据策略代数与失效闭包，附固定种子样本生成器与 pytest 测试集验证顺序无关性、恢复边界与半写残留识别。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
