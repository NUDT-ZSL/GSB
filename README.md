当前是空白工作区，需要从零构建一个面向 Windows 本地环境的向量化执行实验工作台，用于教学与排障演示列式表达式的求值计划选择。用户以本地 JSON 文件声明一批列式数据块（每列含类型、空值位图与确定性样本值）与一组标量表达式查询（含算术、比较、逻辑与三元条件运算，支持常量、列引用与嵌套括号）。工作台须先把表达式解析为规范化表达式树，再生成两种执行路径：按算子逐个物化中间列的朴素向量化路径，以及按批融合多个算子为单个循环的融合路径；两条路径对同一输入必须产出逐字节一致的列结果，并在报告中给出所用路径、批大小、峰值内存估计与耗时观测。核心业务是：在数据规模变化（行数、批大小、列数与表达式深度）下，系统须自动在两条路径之间做取舍，并保证取舍过程可复现、可解释、可审计，异常输入须按业务码报告。

任务环境与准备：
安装 Windows 可用的 Python 3.11 及以上版本，并确保 tkinter 随官方安装包可用。
使用 pip 安装 NumPy（建议 1.26 及以上），全程不依赖网络服务、真实账号或 GPU。
在空白工作区准备本地确定性样本数据块 JSON、样本表达式 JSON 与演示脚本的运行目录。
确认 Python 进程可在本机启动 Tkinter 窗口并以 stdio 运行演示脚本，日志写入工作区本地文件。

业务要求：
1. 实现列式数据块与表达式查询的加载与强校验：从本地 JSON 文件读取数据块与查询集合，校验列名唯一、列类型属于受支持集合（整数、浮点、布尔）、空值位图长度与行数一致、表达式引用的列必须存在；任一不合法须以 E_DATA 业务码整体拒绝加载，并输出具体数据块、列或表达式位置。
2. 实现表达式解析与规范化：支持算术、比较、逻辑与三元条件运算及嵌套括号，生成稳定的表达式树；同一语义表达式在空白与冗余括号差异下须得到相同的规范化文本与结构摘要，不支持的操作符或语法须以 E_EXPR 业务码报告，比较方向不同不得视为同一表达式。
3. 实现朴素向量化执行路径：逐算子对整列或分批数据物化中间列，严格遵守列的整数、浮点与布尔类型语义，除以零与空值传播须按显式规则处理并在报告中标记；相同输入多次执行必须产出逐字节一致的列结果与稳定顺序的中间列摘要。
4. 实现算子融合执行路径：把相邻且类型兼容的算子融合为单趟批内循环，减少中间列物化；融合边界须按明确规则划分（如三元条件与空值传播点不得跨越），融合后的列结果必须与朴素路径逐字节一致，不一致须以 E_FUSE 业务码报告首个差异行号。
5. 实现按数据规模自适应的路径选择与取舍记录：依据行数、批大小、列数与表达式深度按确定性规则选择执行路径，并输出做出该选择的理由、关键规模参数与预估工作量；当两条路径预估代价之差小于显式阈值时须按稳定决胜规则选择，不得依赖哈希或字典遍历顺序。
6. 实现批大小枚举与峰值内存估计：对候选批大小集合估算每条路径的峰值物化内存（整数字节）与批数，输出候选排名；估计须与输入规模（行数、列宽、中间列数）相容，相同参数组合多次估计必须得到同一整数结果并给出估计所依赖的观测口径与真值来源。
7. 实现实验会话快照与版本识别的整体替换恢复：快照持久化数据块内容摘要与版本、查询集合、规模参数、选中路径、候选排名与执行结果摘要；重新打开快照时须比较快照数据版本与当前数据版本，不一致须整体替换当前会话状态而非增量合并，恢复后重跑同一查询须得到相同路径与结果摘要，否则以 E_REPLAY 业务码报告。
8. 实现异常注入与可重复演示：支持以命令行参数注入列类型不匹配、空值位图长度错位、批大小为零三类异常，分别以 E_TYPE、E_NULLMAP、E_BATCH 业务码报告并写入结构化日志；附带确定性样本数据、样本表达式与 Tkinter 界面（展示表达式树、路径选择理由、候选批大小排名与结果摘要，渲染顺序稳定）及演示脚本，顺序执行首次求值、放大数据规模后求值与快照恢复重跑，输出顺序稳定的总结。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
在本地确定性样本上验证两条执行路径结果一致、规模自适应取舍可复现及快照恢复重跑一致。
