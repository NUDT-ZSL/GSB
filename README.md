项目目录还未包含任何实现，首个交付物是面向表格特征工程的分箱与编码诊断引擎，用于验证并行调度与资源预算约束下的结果一致性。输入由固定种子本地确定性生成：逐行样本含 row_id、数值列、类别列与标签；分箱配置给出 bin_count、bin_method（equal_width 或 equal_freq）、encoding_method（one-hot 或 target encoding）、量化参数（quant_scale、zero_point）；两代配置快照并存，v1 为单文件 JSON 记录相对秒与扁平参数，v2 为分片 JSON 加 SQLite 元数据库记录绝对毫秒、版本号与内容摘要。引擎将处理建模为有向无环计算图：输入校验、全局分箱边界计算、编码生成与量化、缓存写入与统计导出。并行调度能缩短耗时但提升驻留内存，增大分箱数提高编码区分度却增加比较与存储开销，精度档切换改变数值传播；这些约束必须在声明预算下达成一致，并支持强制终止后从检查点恢复。

任务环境与准备：
Linux（WSL Ubuntu）环境，已安装 Python 3.8+、NumPy 1.21+ 与 SQLite3 标准库。
执行前提供固定种子样本生成脚本，在本地确定生成样本 JSONL、配置快照与输入清单。
确保工作目录可读写，无外部网络依赖，所有测试样本与脚本随项目交付。

业务要求：
1. 实现确定性的输入校验与全局分箱边界计算阶段：按 row_id 升序解析样本，逐列校验数值列取值非 NaN、类别列取值落在受控词表内，根据每列配置的 bin_count 与 bin_method 计算全局分箱边界，equal_width 按数值范围均分、equal_freq 按样本分位数确定，同分或同边界时按列名字典序升序裁决；同一输入与配置下边界与校验摘要必须逐字节相同，任何非法输入返回结构化业务码。
2. 实现基于分箱边界与编码配置的编码生成阶段：one-hot 对分箱索引生成稀疏独热向量，target encoding 按分箱内目标均值并施加配置平滑系数生成稠密编码，量化阶段以显式声明的 quant_scale 与 zero_point 完成 int8 量化与反量化，所有映射与舍入规则固定；同一分箱边界、编码方法与量化参数下编码结果必须确定性可复现，且 int8 量化后的反量化值需记录误差区间。
3. 建立四阶段内容寻址缓存：输入校验、分箱边界、编码生成、统计导出各自以内容哈希落盘，缓存键纳入上游样本内容哈希、分箱配置版本、量化参数、编码方法与节点参数；键相同必须复用快照、键不同强制重算，缓存写入采用临时文件后原子替换，损坏或校验和不符返回 E_CACHE_CORRUPT。
4. 实现按可配置 worker 数与每批行数将样本分块分派到本地进程池的并行调度层，分块边界、任务派发顺序与归并顺序必须确定性可复现；worker 内异常须以结构化业务码回传主进程并归因到具体 row_id 或批次，单个样本失败不得静默丢弃且不得影响其他样本的已提交结果。
5. 建立分箱数、量化参数与并行度之间的冲突裁决机制：当增大分箱数提升编码区分度但逼近内存上限、提高并行度缩短耗时但放大驻留内存、收紧量化降低误差却增加编码长度时，按配置声明的优先级顺序在质量、内存与延迟之间决策，被拒绝或降级的批次必须显式返回业务码并记录替代方案与决策依据。
6. 实现所有配置与结果的版本化快照及整体替换：分箱配置、量化参数、编码结果与缓存统计各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK；v1 与 v2 配置快照需双向互迁，迁移后均能还原同一语义下的绝对毫秒与相对秒映射。
7. 实现强制终止后的恢复逻辑：执行器在批次或阶段边界提交检查点，检查点包含已完成批次集合、阶段名称与内容校验和，重启时从最近已提交检查点继续，已提交批次或阶段不得重算或重复计入，未提交的中间分箱边界、编码状态或缓存指针必须丢弃并从检查点重建；恢复后的最终编码与统计结果与一次性完整运行逐字节相同。
8. 实现输入与配置校验链路、资源上限与跨模块一致性自检：重复 row_id、配置版本回退、编码方法未知、量化参数非法分别返回 E_DUP_INPUT、E_CONFIG_VERSION、E_CODE_METHOD 等业务码；为驻留内存、并行槽位与比较次数设可配置上限，超限返回 E_RESOURCE_LIMIT 并按声明策略降级；自检校验缓存键与产物互相可核对、重算与复用集合无交集且并集覆盖全部受影响集合。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本运行引擎，验证分箱编码与参考一致、并行调度可复现、中断恢复后输出逐字节相同且资源预算与业务码正确。
