某安全运营团队需要在离线 Windows 工作站上构建一个审计事件关联与取证工具。工具读取本地确定性 JSONL 审计事件流，每个事件含 event_id、trace_id、actor、action、object、ts（整数毫秒）、seq（同一 trace 内单调递增）以及可选 parent_event_id，用它们重建任意 trace 的因果链，并把跨 trace 的关联事件归入取证案件。核心难点是：事件流可能乱序到达、重复投递或丢失，导致已建成的案件结论与已持久化的检查点不一致。工具必须能以检查点为单位恢复，识别版本变化，并且在强制终止后不承诺输出退出报告，只能依靠已持久化状态恢复到最后一个一致边界。所有数据与测试均在本地生成，不依赖网络、账号或外部服务。

任务环境与准备：
准备 Windows 工作站与 Python 3.11 及以上版本，使用 venv 创建隔离虚拟环境。
在虚拟环境中安装 pytest（版本由本地 wheel 或已可用缓存提供），不依赖网络服务。
创建空白工作目录作为作业根，确认有写入临时文件与重命名权限，无需其他外部服务或样本附件。

业务要求：
1. 实现事件流读取与规范化层：逐行解析本地 JSONL 审计流，校验必填字段类型与 ts、seq 的取值范围，对畸形行记录含行号与业务错误码的拒绝记录并继续处理后续行，输出规范化事件集合与拒绝清单。
2. 实现 trace 内因果链重建：按 parent_event_id 建立父子关系，检测缺失父事件、父事件自环与跨 trace 的父子引用，分别返回 E_ORPHAN、E_CYCLE 与 E_CROSS_TRACE 并在报告中给出涉事 event_id 与 trace_id。
3. 实现同一 trace 内 seq 单调性与重复投递判定：识别完全重复事件、同 event_id 内容冲突、seq 回退与 seq 空洞，重复按 event_id 去重且以首次出现为真值，其余情况进入异常链路报告，不得静默丢弃。
4. 实现跨 trace 关联规则引擎：依据可配置规则（如 actor 相同且 object 相同且时间窗内）把事件聚合成取证案件，规则匹配需与乱序输入无关，同一组事件在任意合法到达顺序下案件成员与案件键必须一致。
5. 实现检查点与状态演进：以已处理 seq 水位与案件聚合状态持久化检查点到本地文件，恢复时从检查点继续，并区分检查点版本变化（结构版本或规则版本不同）触发整体重建，不得将旧版聚合状态与新规则混合。
6. 实现原子持久化与强制终止后的恢复边界：检查点与案件快照均先写临时文件再重命名整体替换，快照写入需识别版本变化；模拟进程被强制终止时只允许恢复到最后一个完整检查点，不承诺生成退出报告，也不得出现半写文件被当作有效状态。
7. 实现乱序与并发安全：支持乱序导入（事件 ts 与到达顺序不一致），聚合结果必须与事件最终排序结果等价；对同一工作目录的并发检查点写入需用文件锁保证串行，锁冲突时返回 E_LOCK 而非破坏状态。
8. 实现可交互命令行与可重复演示：提供导入、查询案件、导出报告、校验检查点四类子命令，退出码区分成功、部分失败与参数错误，业务错误码统一写入 JSON 报告；附确定性本地样本生成脚本与 pytest 测试集覆盖上述异常与恢复路径。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
