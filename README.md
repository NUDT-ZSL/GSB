当前是空白工作区，需要从零实现一个面向本地 Kubernetes 调度模拟场景的 Pod 亲和性与节点打分数值精度诊断工作台。工作台接收节点资源清单、Pod 亲和/反亲和规则（requiredDuringScheduling 与 preferredDuringScheduling 两类）、节点标签与插件打分权重，执行过滤与打分，输出调度决策及诊断报告。真实调度中节点打分由多个插件（节点资源平衡、Pod 拓扑分布、preferred 亲和性）的浮点分数加权求和，权重与分数的小数位在多层插件间传播累积误差，可能使两个节点的打分排序在容差边缘翻转。工作台必须支持可配置的十进制有效位、相对误差容差与确定性并列裁决，并在诊断中显式量化每个插件对最终分数的误差贡献与传播路径。系统通过本地 HTTP 接口对外提供服务，状态持久化到 SQLite 以支持重启恢复与并发调度模拟。输入输出、错误码与舍入规则须在题面内自洽，不依赖任何集群或外部服务。

任务环境与准备：
安装 Python 3.11 及以上版本，并确保 pip 可用。
在空白工作区创建虚拟环境并安装 fastapi、uvicorn、pytest 的指定版本，记录到 requirements.txt；分数与误差计算仅使用标准库 decimal，不引入 NumPy。
准备本地 JSON 样本目录，包含至少五个节点描述、两个 Pod 亲和/反亲和规则输入与一个固定随机种子生成器脚本。
确认 SQLite 由标准库提供，无需额外服务；所有测试与演示在 Windows 本机离线运行。

业务要求：
1. 实现调度输入模型与校验：节点描述包含节点名、可分配 CPU 毫核与内存字节（整数）、标签映射与污点列表；Pod 描述包含资源请求、required 亲和/反亲和规则与 preferred 偏好权重。输入以 JSON 提供，非法资源值、重复节点名、未知操作符须分别返回业务码 E_BAD_RESOURCE、E_DUP_NODE、E_BAD_OPERATOR，且校验失败不得进入过滤阶段。
2. 实现过滤阶段的精确语义与诊断记录：节点资源不足、required 亲和未满足、required 反亲和冲突、污点未被容忍均须被过滤，每个被过滤节点须记录首个触发的过滤插件名与原因键；过滤结果须按节点名确定性排序，诊断报告须列出通过过滤的候选集合与每个被拒节点的拒绝依据。
3. 实现多插件打分与加权求和：实现节点资源平衡、Pod 拓扑分布（按节点标签域统计同域 Pod 数）与 preferred 亲和性三类插件，每个插件输出 [0,100] 的分数，最终分数按插件权重加权求和并以配置的十进制有效位截断输出；每个插件的原始分、权重、加权分与截断后分须逐项记录。
4. 实现数值误差传播的量化诊断：对每个节点，须依据各插件原始分与权重的小数位截断规则计算累计误差上界，并输出误差贡献从大到小的插件排序；误差上界须以十进制定点字符串给出（不依赖二进制浮点默认表示），并说明所用有效位与权重，使调用方能判断候选间排序是否可靠。
5. 实现容差内的确定性并列裁决：当两候选节点最终分数差值小于配置的相对容差（默认 0.02）时判定为并列，按更少资源碎片、更多可用内存、节点名字典序的固定次序裁决；裁决结果须在诊断报告中标记为 tied 并附裁决键序列，相同输入多次执行须得到完全相同的裁决与固定字段顺序的输出。
6. 实现并发调度请求与状态隔离：工作台须支持多个调度模拟请求并发执行，同一请求内的过滤、打分与诊断在单一事务快照上完成，不同请求间的中间状态不得互相污染；并发写入 SQLite 时须串行化事务提交，锁等待超过配置超时返回 E_LOCK_TIMEOUT 且不得留下部分写入的诊断记录。
7. 实现持久化与重启恢复：每次调度模拟的输入摘要、候选集合、各插件分数、误差上界、并列裁决与最终选定节点须写入 SQLite；进程重启后须能按请求标识查询历史诊断，且恢复后对同一输入重新模拟的结果与历史记录的规范化 JSON 逐字段一致，未提交事务的中断写入不得可见。
8. 实现本地 HTTP 诊断接口与可重复测试：提供提交调度模拟、查询诊断报告、列出历史请求、查询节点评分明细的接口；诊断报告须包含误差传播路径、并列裁决依据与总计算耗时。pytest 用例须在 Windows 离线覆盖过滤拒绝、截断误差导致的排序翻转、并列裁决稳定性、并发锁超时与重启恢复，并提供固定随机种子生成的本地样本。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
