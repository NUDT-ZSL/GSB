在空白工作区构建一个面向本地确定性样本的 LLM 推理采样与解码策略工作台，核心解决解码配置与采样轨迹在多种交换格式之间的互操作与版本兼容问题。输入为一个本地样本目录：一份词表与子词切分规则文件、一份按固定种子程序生成的模型打分表（每个上下文指纹对应一组 logits 向量，避免依赖任何真实模型权重）、一份请求流 JSONL（每行含请求 ID、上下文指纹、最大生成长度与可选的结束符号列表），以及两个版本的解码策略交换文件：v1 为单行扁平键值文本，采样参数以整数或字符串表示（温度以千分比整数给出、top_k 为整数、top_p 与重复惩罚以千分比整数给出、种子为 32 位无符号整数、解码器类型只能取 greedy 或 sampling）；v2 为 JSON，采样参数为浮点（温度与重复惩罚为浮点数、top_p 为 0 至 1 浮点、种子为 64 位整数、解码器类型新增 beam 并带 beam 宽度与长度归一化指数）。两版本在温度精度、top_p 语义、种子位宽、解码器能力与字段命名上均不等价，降级时不可避免损失信息。工作台需解析两版本策略为统一中间表示，支持编辑温度与核采样等字段、按请求覆盖策略、在版本间转换并重放请求，输出可逐字段比对的采样轨迹与损失报告。

任务环境与准备：
安装 Python 3.10 及以上版本，创建虚拟环境并用 pip 安装 numpy 与 pytest（版本不限，需可在 Windows 本地离线环境使用已缓存包）。
在空白工作区创建题目要求的目录结构，准备本地确定性样本：词表与子词规则文件、按固定种子生成的打分表、请求流 JSONL、v1 扁平键值策略文件、v2 JSON 策略文件、异常注入配置与并发及快照配置。
确认 Windows 控制台可输出 UTF-8，所有产物路径使用相对工作区的本地目录，不依赖网络、真实模型权重或外部服务。
准备一份记录固定种子、期望逐请求 token 序列与降级损失清单的本地基线样本，供运行后比对使用。

业务要求：
1. 实现双版本解码策略解析器与统一中间表示：v1 扁平键值文本行须解析出千分比整数温度、整数 top_k、千分比 top_p、千分比重复惩罚、32 位种子与 greedy/sampling 解码器；v2 JSON 须解析出浮点温度与重复惩罚、0 至 1 的 top_p、64 位种子以及含 beam 宽度与长度归一化指数的 beam 解码器；解析结果统一为带来源版本号与原始字段快照的策略对象，未知键、类型不符、越界值分别输出 E_POLICY_UNKNOWN_KEY、E_POLICY_TYPE 与 E_POLICY_RANGE 业务码并进入失败清单，不得静默忽略。
2. 实现策略版本双向转换器与损失信息旁路：v1 升 v2 时千分比温度与重复惩罚按精确换算表转为浮点，32 位种子零扩展为 64 位，greedy 与 sampling 保持解码器语义；v2 降 v1 时浮点温度按可配置量化档位折叠为千分比整数、top_p 钳制到零与一千之间、64 位种子在超出 32 位范围时按配置规则截断或报 E_SEED_WIDTH，beam 解码器降级为 sampling 且 beam 宽度与长度归一化指数写入旁路元数据文件；降级损失清单须列出每个被改动字段的原值、新值与损失类别，同一策略重复转换必须得到逐字段一致的降级损失清单。
3. 实现确定性采样解码器集：按统一中间表示执行 greedy、sampling 与 beam 三种解码，logits 取自本地打分表并由上下文指纹定位；sampling 依次应用重复惩罚、温度缩放、top_k 截断与 top_p 核采样，温度为零时退化为贪心，top_k 为零表示不截断，top_p 达到一千表示不截断；随机源为请求指纹与种子派生的固定序列，同一请求与策略在任意运行中必须生成逐 token 一致的序列；beam 须在相同打分表上按固定移进顺序展开并按分数与序列字典序稳定决断，三条路径的输出须包含每步候选得分与前若干候选的分数，便于逐字段比对。
4. 实现格式互操作编辑操作集：提供单请求策略覆盖、全局策略字段修改、请求批量重放与策略版本显式切换四类编辑；单请求覆盖只影响该请求的解码结果，全局修改须使全部未显式覆盖请求的采样轨迹失效并重算，显式覆盖请求的轨迹必须保持命中；批量重放须按请求 ID 稳定顺序执行并输出与单条逐一执行完全一致的逐请求 token 序列与候选得分摘要；版本切换须触发按需转换并按新版本语义重新解码，已被旁路元数据记录的损失字段须在结果中显式标注。
5. 实现基于内容指纹的采样轨迹复用与失效判定：为每个请求的采样轨迹计算由上下文指纹、策略规范化指纹、打分表指纹与解码器实现版本号派生的缓存键；当策略字段、请求覆盖或打分表变化时，仅使受影响请求的轨迹失效并纳入重算集合，未失效请求必须直接复用轨迹产物且不得重新解码；复用与失效清单须在结果中逐请求列出，并区分策略级失效、请求级失效与打分表级失效三种来源。
6. 保证编辑序列下增量解码与全量解码的逐请求等价性：从任意初始状态施加包含 v1 与 v2 策略切换、全局字段修改、单请求覆盖、批量重放与请求删除的编辑序列，每次编辑后增量运行得到的逐请求 token 序列、每步候选得分、候选排序、损失标注与复用失效清单，必须与从空白工作区按相同最终策略与请求集全量解码的结果逐字段一致；比较须在 greedy、sampling 与 beam 三种解码器以及 v1 与 v2 两种来源策略下分别成立。
7. 实现版本化快照整体替换与强制终止后的恢复判定：解码策略、逐请求轨迹与旁路元数据各阶段以临时文件加原子替换方式持久化，清单文件记录全局版本号、策略来源版本、策略规范化指纹、打分表指纹、已完成请求列表与各产物版本；启动时以清单版本号与当前配置指纹判断是否命中，版本或指纹不符输出 E_SNAPSHOT_STALE 并按配置决定是否从已完整替换的产物恢复；收到可处理的退出信号时完成当前请求轨迹落盘与进度记录后以整数退出码 0 退出，进程被强制终止后重启仅依据已完整替换的产物与进度记录恢复并输出恢复点信息，不得承诺强制终止后一定生成退出报告。
8. 实现并发解码与串行结果一致性、异常注入隔离与诊断报告：使用线程池并发执行逐请求解码，最大并发数取自配置，每个请求任务携带由请求 ID 与解码步序号派生的稳定排序键，无论线程调度顺序与并发度如何，最终请求结果顺序、每步候选顺序、失败清单顺序与复用统计必须与单线程按请求 ID 稳定顺序执行一致；以独立注入配置指定缺字段策略行、越界采样参数、超 32 位种子、未知解码器类型与空打分表条目等样例，注入项编号写入报告以证明命中；单请求在解析、转换或解码阶段抛异常时记录请求 ID、阶段名与业务码并继续其余请求；每次完整运行生成 JSON 诊断报告，含逐请求 token 序列摘要、各解码器路径得分摘要、降级损失清单、缓存命中与失效统计、版本转换记录、注入命中清单、快照版本号与失败清单，报告以临时文件加原子替换方式写盘。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地打分表与双版本策略样本验证三种解码器的增量解码与全量解码逐字段一致，并覆盖降级损失、恢复与异常注入。
