当前为空白工作区，需要从零构建一个可集成的矩阵乘算子组件与完整示例，覆盖 2D GEMM 与批量 BMM 两类调用。输入为本地确定性生成的矩阵样本（JSON 元数据字段含 case_id、shape、dtype、layout、seed、batch 描述）以及由 NumPy 依据 seed 生成的对应浮点数组；组件需按输入规模自适应选择分块策略（分块尺寸、循环顺序、是否走批量聚合路径），在 float64 参考实现与分块实现之间给出数值偏差与容差判定，并输出每次调用的策略决策记录。业务关注点在于数据规模变化与算法取舍：小规模时整块计算的精度与开销更优，大规模或大批次时必须分块与聚合，但分块会改变累加顺序从而引入舍入偏差，需要在不牺牲正确性的前提下给出可解释的取舍与预算控制。参考真值来源为同一输入上用 NumPy float64 整块乘法的结果，偏差观测与容差判定均以该结果为唯一口径。

任务环境与准备：
安装 Python 3.10 及以上，并安装与版本匹配的 NumPy；无需 GPU 或外部服务。
创建空白工作区目录，生成确定性矩阵样本与 JSON 元数据，固定随机种子以保证可复现。
准备一份参考实现的数值口径说明与容差配置示例，用于示例与演示运行。

业务要求：
1. 实现 2D GEMM 与批量 BMM 的统一算子入口，按输入元数据解析形状、dtype、布局与批次语义，对非法形状、dtype 不支持、批次维度不一致分别返回 E_SHAPE_INVALID、E_DTYPE_UNSUPPORTED、E_BATCH_MISMATCH，且错误须归因到具体 case_id。
2. 实现基于输入规模的分块策略决策器：按矩阵维度与批次大小选择分块尺寸、循环顺序与批量聚合方式，输出可复现的策略记录（含决策依据的维度与代价估计），同一输入与配置下决策必须逐字节一致。
3. 实现分块执行路径：按选定分块完成累加并支持可配置的补偿求和以降低舍入误差，分块路径结果须与 float64 参考实现在给定容差内一致，容差随规模设定并记录观测到的最大绝对与相对偏差。
4. 实现数值一致性裁决：比较分块结果与参考实现的偏差，超出容差返回 E_TOLERANCE_EXCEEDED 并指出越界元素位置与偏差量，未超出时输出偏差统计；不得以放宽容差掩盖真实错误。
5. 实现规模与资源预算控制：为单次调用的估计内存、分块数量与批量聚合中间缓冲设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或降级到较小分块，降级须在结果中标记降级类别且不得改变正确性判定结果。
6. 实现策略冲突裁决：当精度要求与内存预算在同一规模上冲突时（更大分块省内存但累加精度更低，更小分块精度更优但分块数超预算），须按显式优先级规则裁决并在策略记录中说明取舍理由，裁决结果必须可复现。
7. 实现跨模式一致性自检：校验 GEMM 与 batch=1 的 BMM 在相同输入上产出一致结果、布局变化（行主序与列主序）下结果在转置语义上可核对，检测到不一致返回 E_INCONSISTENT 并指出模式与 case_id。
8. 提供可集成的领域组件接口与完整示例：暴露 gemm、bmm、策略决策与偏差裁决入口，命令行示例读取本地生成样本输出含结果摘要、策略记录、偏差统计与业务码的 JSON，并附一次注入异常输入与一次超预算降级的演示。
