迁移方案定稿之后，团队拿到的是目标说明而不是旧工程：需要在 Windows 空白工作区中独立实现一个可集成的骨骼动画片段状态机回放组件，用于验证角色动作在版本迁移与断线重连后能否回放到同一份动画状态。工作区没有任何既有代码与样本，全部输入由随交付的固定种子脚本确定性生成，不依赖真实引擎、外部资源或网络：骨架层级声明给出骨骼名与父骨、静止位姿局部变换；每个动画片段由若干骨骼通道的关键帧轨道驱动，轨道记录整数逻辑毫秒时刻与数值；状态机转移规则给出参数阈值、打断优先级与循环次数；另有一份编辑脚本按顺序描述对关键帧、通道数值、片段时长与转移条件的增删改。逐帧推进产出骨骼姿态快照与状态转移事件流。两代动画快照并存，v1 为单文件 JSON，以相对片段秒数与扁平骨骼通道姿态记录；v2 为分片 JSON 加 SQLite 元数据库，用规范片段标识、绝对逻辑毫秒戳、状态代数与墓碑标记记录。

任务环境与准备：
在 Windows 工作区安装 Python 3.11 及以上，并执行 pip install numpy 安装 NumPy，SQLite 使用标准库 sqlite3 无需额外安装。
运行随工程交付的固定种子样本生成脚本，在本地生成骨架、关键帧轨道、状态机规则、编辑脚本与两代动画快照样本，不下载任何外部数据。
准备一个空的状态目录与输出目录，确认工作区没有既有的动画引擎代码或缓存文件，全部实现从零开始。

业务要求：
1. 实现骨架、关键帧轨道、状态机规则、编辑脚本与两代快照的解析校验：骨骼名唯一且父骨可拓扑排序成无环图、静止位姿平移为有限数、每骨每通道关键帧时刻为非负整数且严格递增、数值有限、转移条件引用的参数已声明、v1 相对秒可换算为绝对毫秒；非法输入返回带 E_SCHEMA 的 JSON 错误且不产生任何输出文件。
2. 实现确定性逐帧姿态求值：在整数逻辑毫秒时间轴上按规格步长推进，关键帧之间按通道做线性或球面插值，再沿父链累乘得到全局姿态；同一输入与同一编辑脚本无论分块切分与并发度如何，重复求值须得到逐帧逐骨骼逐分量完全相同的姿态。
3. 实现状态机逐帧转移与事件流生成：每帧依据当前参数值与转移条件按打断优先级选出目标片段，循环片段按循环次数决定结束，片段切换时按规格处理进入时刻的姿态衔接；转移事件流须与姿态序列同源生成，不得事后从姿态反推，同一逻辑时刻不得出现两条互斥转移。
4. 实现编辑后依赖图与失效闭包计算：为每个帧区间分块记录其依赖的关键帧区间、所涉骨骼通道、片段归属与转移条件；编辑脚本任一步发生后只把沿父链可达骨骼、被修改通道覆盖的帧区间、以及因片段时长或转移条件变化而移位的后续区间标记失效，其它块必须保持原结果，报告逐条列出失效理由。
5. 实现增量重算与全量重放一致性：只对失效块重算并在相邻保留帧处按同一插值口径衔接，增量后的姿态与同输入从头全量推进逐帧逐骨骼分量差值不超过规格姿态容差，转移事件序列完全一致；报告需列出重算块数、复用块数与首个超容差位置。
6. 实现两代快照合并与防篡改版本识别：把两代快照换算到同一逻辑毫秒轴，同代同规范标识按状态代数取新、墓碑优先于无墓碑记录，两代冲突按代数与时刻裁决并逐条产出可定位到分片与骨骼通道的冲突项；每份快照计算内容摘要并与记录比对，摘要不匹配、缺失或声明帧数与实际不符时返回 E_DIGEST 并回退最近有效快照，禁止静默使用。
7. 实现分块级持久化与中断恢复语义：按逻辑毫秒分块把姿态、转移事件与由骨架、轨道及规则规范化摘要构成的版本标识写入状态目录，先写同目录临时文件再整体替换，替换前识别旧版本标识变化；可处理终止信号只在分块边界生效并以约定整数退出码退出，强制终止后仅依据已持久化且摘要有效的块恢复且不承诺生成退出报告。
8. 实现并发推进与内存预算及断线追平：按配置并发上限用有界线程池推进互不相同的片段状态，同一片段帧推进保持有序，在途关键帧插值缓冲与姿态快照总量受内存预算限制，超限时按片段标识确定顺序等待而非降低插值精度；客户端离线后重连须先按逻辑毫秒差序补齐缺失姿态区间再回放事件流，偏差时定位首个不一致逻辑毫秒、片段标识与骨骼通道并输出 E_REPLAY 报告。
