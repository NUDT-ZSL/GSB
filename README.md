从一个空仓库出发，实现一个本地平台升级与兼容场景下的服务伸缩决策组件：同一组服务在不同平台版本间迁移时，伸缩策略存在 v1 扁平 JSON 与 v2 分片 JSON 加 SQLite 元数据两代格式，且需要在每轮总逻辑时间预算与每故障域并发动作上限约束下并行下发放缩决策。本地 JSON 样本给出：服务清单（服务名、当前副本数、每副本核数与内存、依赖上游、故障域、优先级）、节点资源池（核数与内存余量、拓扑域）、两代伸缩策略（v1 记录相对生效秒数与档位比例，v2 记录绝对生效毫秒、策略代数与失效墓碑）、负载轨迹，以及裁决配置（每轮逻辑时间预算毫秒、每故障域并发上限、容差与定点标度、逻辑时钟步进）。组件需要把两代策略合并为统一伸缩视图，按依赖拓扑序在预算内并行裁决每个服务的扩缩容动作，并保证进程被强制终止后依据持久化状态恢复而非依赖内存残留。

任务环境与准备：
安装 Python 3.11 及以上版本，并确认 python 与 pip 可在 Windows 命令行直接调用。
执行 pip install numpy==1.26.4 安装数值运算依赖；SQLite 使用 Python 标准库 sqlite3，无需额外安装。
在空工作区创建项目目录，准备本地 JSON 样本：服务清单、节点资源池、v1 扁平策略、v2 分片 JSON 与元数据库、负载轨迹及裁决配置，全部由本地脚本确定性生成。
确认工作区对当前用户可读写，用于存放 SQLite 状态库与临时换算登记文件；不依赖网络、容器或任何外部服务。

业务要求：
1. 实现服务清单、节点资源池与两代伸缩策略的解析校验：服务名唯一、依赖上游存在且无自环、每副本核数与内存为正整数、v1 相对生效秒数为非负整数且档位比例严格递增并以 1 收尾、v2 分片哈希与策略代数单调且绝对毫秒戳为整数；非法输入须返回明确业务错误码（如 E_BAD_SAMPLE、E_VERSION_ROLLBACK），且不得写入任何持久化状态。
2. 实现跨版本策略合并与统一伸缩视图：同一服务在两代策略中同时存在时依据声明的逻辑时钟与策略代数裁决最新版本，逻辑时钟相同按来源版本优先级；合并后每个参数保留来源版本、原始时间表示与裁决依据，v1 相对秒数在注入逻辑时钟下换算为绝对生效时刻并记录换算标度与舍入方向。
3. 实现按依赖拓扑序的并行扩缩容裁决：同轮内按故障域分组并发处理服务动作，同时受每轮总逻辑时间预算与每故障域并发上限约束；预算耗尽必须放弃剩余未启动动作并记录放弃原因，严格区分预算内未启动、启动后失败与主动放弃三类结局，已启动动作须执行完毕，不得以事后标注代替真实预算判定。
4. 实现节点核数与内存双重预算下的副本落点共享裁决：在每节点剩余核数、内存与拓扑域约束下为待扩容副本选择落点，任一项不足即不得部分放置，并输出每节点剩余量、被淘汰候选与首个触发约束；缩容须先于同域扩容回收资源，保证同轮内不出现因动作顺序导致的虚假资源不足。
5. 实现扩缩容决定的定点账本与误差传播记录：对每个服务的请求副本量、有效资源量、成本增量与预算余量按声明定点标度换算，登记舍入方向与被舍弃余量，累计每次加法与乘法的误差上界；当两个服务的资源或成本差小于容差且裁决依赖该差值时标记为精度敏感并输出误差来源链（含服务名、换算登记序号与参与层级路径）。
6. 实现策略补丁的增量失效闭包与结论复用：以补丁形式提交档位比例、依赖关系或失效墓碑的修改，沿依赖图计算受影响闭包，精确标记哪些服务的伸缩结论、落点与精度敏感标记需重算、哪些可安全复用；未受影响服务的结论必须逐字保持不变且不得被重算。
7. 实现策略版本整体替换与强制终止后的恢复：收到新策略包时比较版本号、策略代数下限与分片哈希，判定完整替换、增量追加或无需操作并拒绝版本回退；把轮次水位、副本数、节点占用、精度敏感记录与逻辑时钟水位以事务原子写入 SQLite，进程被强制终止后只重放未提交动作且不重复扣减资源账目。
8. 实现多进程并发一致性与可重复命令行：多个裁决实例并行处理不同故障域时，通过 SQLite 事务与文件锁保证同一服务同一轮次同一版本只被裁决一次、节点核数与内存不被并发超卖，重复提交幂等；提供 load、reconcile、resume、status、verify 子命令，status 以稳定排序 JSON 输出每服务副本数、节点余量与精度敏感标记，verify 校验持久化状态与重算结果一致。
