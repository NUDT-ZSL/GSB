当前是空白工作区，需要从零构建一个面向跨语言检索相关性建模的数据处理管线与结果验证工具。业务对象是本地确定性生成的多语言查询-文档对样本（JSONL，字段含 pair_id、query_id、query_lang、doc_lang、query_text、doc_text、relevance_grade），另有一份可配置的跨语言对齐资源：语言对映射表、词级翻译对照表与相关性打分权重表。管线被建模为多阶段流程：文本归一化与语言识别→跨语言词项对齐（借助翻译对照表把查询词项映射到文档语言侧，缺失映射按声明的回退策略处理）→词项级相关性打分（TF-IDF 加权与词项覆盖率的组合打分）→对级相关性分级与排序汇总。每个阶段产出带内容哈希的中间产物，只有阶段全部完成才可提交。核心难点在于长时间运行中的状态演进：进程可能被强制终止，重启后必须从最后一次已提交的阶段快照继续，进行中未提交的中间工作必须丢弃；同时对齐资源的版本变化、映射冲突与降级路径都必须可追溯，且最终排序结果要与不间断完整运行逐字节一致。

任务环境与准备：
安装 Python 3.11 或以上版本，并安装 NumPy（版本自选且记录于本地说明）。
准备本地脚本按固定种子生成多语言查询-文档对样本、翻译对照表与语言对映射表，全部写入工作区本地目录，不依赖网络或外部数据源。
准备本地持久化目录用于阶段快照与资源快照，确认工作区可读写，并预留可触发强制终止的演示入口。
无需容器、外部服务或真实账号；所有演示与验证均在本机以确定性样本与本地进程执行。

业务要求：
1. 实现文本归一化、语言识别与跨语言词项对齐三阶段的确定性管线：对每条 pair 产出查询侧与文档侧规范词项序列，并按语言对映射与翻译对照表把查询词项投射到文档语言侧；同一输入与同一对齐资源版本下必须逐字节产出相同的中间产物，缺失映射按声明的回退策略处理并在结果中标记回退类别。
2. 实现词项级相关性打分与对级分级汇总：基于 TF-IDF 加权与词项覆盖率组合分数，按配置权重得出每条 pair 的相关性分数并映射到分级；须保证同一快照同一配置重跑得到相同分数与相同排序，且分级边界处的样本判定不得被浮点舍入翻转。
3. 实现归一化、对齐、打分、汇总四个阶段的状态机，每阶段产生带单调递增版本号与内容校验和的阶段快照，只有该阶段全部 pair 处理完成才提交；提交顺序、阶段状态与版本号必须在持久化存储中原子可见，部分完成的阶段不得提交。
4. 实现强制终止后的恢复逻辑：重启时读取已提交快照，从最后一次已提交阶段继续；进行中未提交的中间对齐与打分结果必须丢弃并从该阶段起点重建，已提交阶段的 pair 不得重算；恢复后的最终排序与分级须与不间断完整运行逐字节一致。
5. 实现对齐资源版本变化与整体替换：语言对映射、翻译对照表与打分权重各携带版本号与内容校验和，检测到版本变化时必须整体替换旧快照而非增量修补；损坏或校验和不符的资源加载时返回 E_SNAPSHOT_CORRUPT 并指明资源类别与版本号。
6. 实现并发提交控制与资源上限：同一时刻只允许一个阶段提交生效，并发冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待，已完成阶段不得被旧版本回退覆盖（回退尝试返回 E_SNAPSHOT_ROLLBACK）；为单阶段 pair 数、对齐候选映射数与中间驻留内存设可配置上限，超限时返回 E_RESOURCE_LIMIT 或降级并在结果中标记降级类别。
7. 实现输入与异常校验链路：重复 pair_id、query_lang 与 doc_lang 不在受控语言集合内、翻译对照表条目格式错误、relevance_grade 越界分别返回对应业务码（E_DUP_PAIR、E_LANG_UNSUPPORTED、E_MAP_FORMAT、E_GRADE_INVALID），解析失败与写入失败须沿异常链路归因到阶段名与 pair_id。
8. 实现结果验证工具与跨阶段一致性自检：验证工具独立复核各阶段快照、词项覆盖统计与排序明细可重算一致；自检校验各阶段 pair_id 集合完全一致、保留与回退映射无交叉计数、最终排序中每条 pair 恰出现一次，不一致返回 E_INCONSISTENT 并指出不一致类别与版本号。
