项目启动会上确定由一人完成首版。当前 Linux（WSL Ubuntu）工作区尚无任何代码或样本，需要从零构建一个面向服务注册中心与健康探测的本地诊断工作台，交付数据处理管线与结果验证工具。业务目标是将注册中心上报的服务实例观测流转换为可差分推进的拓扑状态账本，并处理两代健康探测规则快照带来的增量更新与依赖失效。本地样本由随题交付的固定种子脚本确定性生成：注册清单声明服务名、实例 ID、回环观测端点、期望状态码集合、租约代数与状态世代号；探测观测流为 JSONL，每条含实例 ID、观测序号、注入逻辑时钟毫秒、观测状态码、观测延迟与观测摘要哈希；健康探测规则存在 v1 单文件 JSON（相对生效秒数与扁平实例到规则映射）与 v2 分片 JSON 加 SQLite 元数据库（绝对生效毫秒、规则代数、依赖上游规则列表与失效墓碑）两代格式。引擎需在可注入逻辑时钟下对两代规则快照做跨版本合并，按规则代数推进实例健康状态机，并计算规则变更后的依赖失效闭包，确保同一批观测流在任意加载顺序与中断恢复后得到逐位一致的健康结论账本。

任务环境与准备：
Linux（WSL Ubuntu）开发环境，已安装 Python 3.10 或更高版本。
安装依赖：pip install flask numpy（SQLite 使用标准库 sqlite3）。
随工程交付固定种子样本生成脚本，本地运行生成注册清单、观测流 JSONL 及两代规则快照文件。

业务要求：
1. 实现注册清单、探测观测流与两代健康探测规则快照的解析校验：服务名与实例 ID 唯一，观测端点为合法回环地址，期望状态码集合非空且元素为三位整数，观测序号在同一实例内严格递增且观测摘要哈希与内容一致，v1 相对生效秒数为非负整数且扁平映射与规则声明一致，v2 分片哈希正确且规则代数单调，任何非法输入必须返回明确业务错误码并保留可诊断字段。
2. 实现两代健康探测规则的跨版本合并与统一规则视图构建：同一规则键在 v1 与 v2 中同时存在时，依据规则声明的逻辑时钟与规则代数裁决最新版本，逻辑时钟相同则按来源格式优先级裁决；v1 相对生效秒数在注入逻辑时钟下换算为绝对生效毫秒并记录换算标度与舍入方向，合并后每条规则须保留来源版本、原始时间表示与裁决依据，且 v2 的失效墓碑必须显式标记为已失效而非从规则视图消失。
3. 实现基于注入逻辑时钟的探测观测差分解算与实例健康状态机演进：按实例 ID 和观测序号将观测流有序归并，观测序号相同则按逻辑时钟裁决，逻辑时钟相同按摘要哈希稳定排序；每次观测按期望状态码集合判定成功、状态码不符或缺失（补洞），只有真实失败才递增连续失败计数，租约代数落后或规则失效时观测须被隔离；健康状态在健康、可疑、失联之间迁移，迁移只依赖已提交观测与持久化状态。
4. 实现规则增量更新驱动的依赖失效闭包计算与观测窗口一致性判定：以补丁形式提交规则依赖关系、失效墓碑或生效时刻修改，沿规则依赖图计算受影响实例闭包，精确标记哪些实例的健康结论、连续失败计数与规则代数绑定需重算、哪些可安全复用；未受影响实例的健康账本不得被重算，同时两代规则快照对同一实例的健康结论差异须按规则代数与逻辑时钟裁决并记录差异来源。
5. 实现探测观测流的分片加载与任意加载顺序下的收敛保证：观测流可拆分为多个分片文件独立加载，每个分片记录内容摘要与覆盖的实例及观测序号区间；引擎须在任一分片暂时缺失时仍能推进已完整分片的观测，但不得提交缺失分片覆盖区间的健康结论；当全部分片最终到齐后，按相同合并规则得到的健康结论账本必须与一次性加载全部观测流的结果逐位一致，并输出分片加载顺序无关性证明。
6. 实现强制终止后的恢复一致性与半提交观测裁决：把每个实例已提交状态世代、连续失败计数、租约代数、待裁决观测缓冲区内容摘要、已加载分片清单与逻辑时钟水位以事务原子写入 SQLite，每次提交识以临时表加版本号整体替换当前账本指针；进程在观测归并、规则替换或健康结论提交中途被强制终止后，恢复路径须识别已提交世代与半提交观测，只重放缺失部分且不得重复递增失败计数或产生新旧混合的健康状态。
7. 实现多进程并发一致性与幂等提交：允许多个探测观测处理进程和规则更新进程并行操作同一注册中心，通过 SQLite 事务与文件锁保证同一观测序号同一实例版本只被提交一次、同一规则代数只被整体替换一次、连续失败计数不被并发超扣；重复提交相同观测或相同规则补丁必须幂等，读取方任意时刻只能看到完整已提交的健康账本，不得看到部分更新的规则视图或观测缓冲区。
8. 提供数据处理管线与结果验证工具：支持 load、merge、reconcile、patch、resume、status、verify 子命令，merge 输出跨版本规则合并与时间换算的完整决策链，status 以稳定排序 JSON 输出每个实例的健康结论、连续失败计数、规则代数绑定与逻辑时钟水位，verify 能对任意加载顺序与强制终止恢复后的健康结论账本做一致性校验并逐位比对，失败时返回 E_RESULT_MISMATCH 及首个不一致实例与观测序号。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证规则合并、健康状态演进、依赖失效与中断恢复后，账本结果逐位一致。

## 交付运行指南

实现代码位于 `workbench/`，测试位于 `tests/test_workbench.py`，完整设计与实测记录见 `docs/TECHNICAL_NOTES.md`。

```bash
pip install -r requirements.txt
python scripts/generate_sample.py --out samples
bash scripts/acceptance.sh
```

常用命令：

```bash
python -m workbench load --db artifacts/demo.db --registry samples/registry.json
python -m workbench merge --db artifacts/demo.db --v1 samples/rules_v1.json --v2-manifest samples/rules_v2_manifest.json --clock-ms 1760000000000
python -m workbench load --db artifacts/demo.db --observations samples/observations.jsonl
python -m workbench reconcile --db artifacts/demo.db --clock-ms 1760000000000
python -m workbench patch --db artifacts/demo.db --patch samples/patches/patch_alpha_tombstone.json --clock-ms 1760000120000
python -m workbench resume --db artifacts/demo.db
python -m workbench status --db artifacts/demo.db
python -m workbench verify --self-test
python -m workbench serve --db artifacts/demo.db
```

`verify` 不一致时返回退出码 `20` 和 `E_RESULT_MISMATCH`，错误详情包含首个不一致实例与观测序号。
