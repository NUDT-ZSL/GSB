某安全团队需要在离线 Windows 空白工作区从零开发一个备份完整性与防篡改恢复引擎，用于校验本地确定性备份清单并安全恢复状态。备份由一批版本化快照构成：每个快照声明版本号、文件条目列表（相对路径、内容摘要、声明长度、篡改标记），以及上一个快照的指纹链。恢复请求按顺序应用增量快照，必须验证指纹链完整性、拒绝被篡改的条目、检测快照回滚与分叉，并将恢复状态以原子快照持久化。核心难点在于恢复过程中状态演进与一致性：快照可能乱序到达、指纹链可能断裂或分叉、恢复可能被强制终止；引擎必须在任何中断点只暴露最后一个完整一致状态，且篡改检测、回滚判定与恢复结论必须与快照到达顺序无关。所有处理在本地完成，不依赖网络或外部数据。

任务环境与准备：
Windows 10 或 11 本地工作站，Python 3.11 及以上，仅使用标准库（json、hashlib、hmac、pathlib、threading），文件锁可自行用独占创建实现，无网络依赖。
创建空白工作区目录，不预置任何项目文件；所有样本与测试由任务自身生成器产出。
准备本地磁盘足够空间存放快照样本与恢复副本，测试运行前无需启动任何外部服务。

业务要求：
1. 实现备份快照清单的解析与规范化层：逐条解析本地 JSON 快照，校验版本号格式、条目相对路径合法性与唯一性、内容摘要算法白名单（SHA-256 与 HMAC-SHA256）、声明长度为非负整数，对非法条目输出含快照版本与条目序号及业务错误码的拒绝记录并继续处理其余条目。
2. 实现指纹链的构建与完整性校验：依据每个快照声明的上一快照指纹计算链式校验结论，检测指纹断裂、指纹不匹配、自引用与环状引用，分别返回 E_CHAIN_BREAK、E_FINGERPRINT、E_CYCLE；指纹校验必须使用白名单内算法并在报告中输出实际计算摘要的前缀，环检测结论与快照到达顺序无关。
3. 实现快照回滚与分叉检测：当收到版本号低于已生效水位、或同一前驱指纹派生出多个后继快照时，分别返回 E_ROLLBACK 与 E_FORK 并列出涉及的快照版本；回滚判定须以已持久化检查点中的水位为观测依据，分叉判定须保留所有分支标识，不得静默选择其一生效。
4. 实现篡改条目识别与恢复排除：逐条目比对内容摘要与声明长度及实际内容摘要，摘要不匹配返回 E_TAMPER、声明长度与实际长度不一致返回 E_LENGTH；被篡改条目须从恢复结果中排除并在报告中给出其相对路径，同时保证其余合法条目仍按快照顺序应用，恢复结论不得因篡改条目而整体放弃。
5. 实现恢复状态机与检查点演进：按快照版本水位与已应用条目集合持久化检查点，恢复时只从最后一个完整检查点继续；检测到检查点结构版本或摘要算法白名单变化时须整体重建而非增量续接，不得把旧策略下的校验结论与新策略混合，检查点与恢复状态须原子写入并保证稳定字段顺序。
6. 实现强制终止后的恢复边界与原子快照整体替换：检查点与恢复快照均先写临时文件再整体重命名替换，替换前校验内容完整性；同一工作目录并发写入须以文件锁串行化，锁冲突返回 E_LOCK；进程被强制终止后只允许恢复到最后一个完整检查点，不得承诺生成退出报告，也不得出现半写文件残留。
7. 实现恢复结论与快照到达顺序无关的一致性保证：支持增量快照乱序导入，最终每条恢复请求的生效快照、篡改排除集合与回滚分叉结论必须与按版本号稳定排序后的执行结果完全一致；输出中的快照与条目顺序须按稳定键归一化，不得依赖到达顺序或字典遍历顺序。
8. 提供可交互命令行与确定性本地样本测试：实现导入快照、执行恢复、查询状态、校验检查点四类子命令，单次恢复失败不中断同批其他恢复请求，退出码区分全部成功、部分失败与参数错误，业务错误码统一写入 JSON 报告；附确定性样本生成器与 pytest 测试集，覆盖指纹断裂、回滚、分叉、篡改条目、锁冲突与强制终止恢复，并断言输入快照处理后未被修改。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证指纹链校验、篡改排除、回滚分叉判定、检查点恢复及原子快照写入。
