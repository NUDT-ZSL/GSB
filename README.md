当前是空白工作区，需要从零构建一个面向 Windows 本地环境的聚合与窗口函数数据处理管线与结果验证工具，属于计算引擎方向。用户在本地 JSON 文件中声明若干列式输入表（含整数时间戳列、分组键列与数值列）以及一组聚合与窗口查询：聚合支持按分组键求计数、求和、最小、最大与均值，窗口支持按分组键分区、按时间戳排序的滑动区间 SUM 与序号类计算。管线须把每条查询解析为稳定的规范化标识，编译为执行计划并在本地数据上流式推进，逐分区维护分组聚合状态与窗口环形缓冲状态；核心业务是：分组状态与窗口状态在多次批次推进之间必须可持久化、可恢复，快照整体替换后重新推进须与不中断推进逐字节一致，同时支持指令注入的分批边界、乱序到达与损坏快照来验证异常链路。

任务环境与准备：
安装 Python 3.11 或以上版本，确认 Tkinter 可用（Windows 官方安装包默认包含）。
无需第三方依赖，仅使用标准库（json、sqlite3、argparse、threading、logging）。
在空白工作区创建项目目录，准备本地确定性样本表 JSON、查询 JSON 与快照输出目录。
确认工作区可本地读写文件与启动子进程，不依赖网络、账号或外部数据。

业务要求：
1. 实现输入表与查询定义的加载与强校验：从本地 JSON 文件读取表结构与行数据，校验表名唯一、列名合法且类型受支持、整数时间戳列存在、行内时间戳按显式声明处理单调或允许乱序、查询引用的列必须存在且类型与聚合算子相容，任一不合法须以 E_SCHEMA 整体拒绝加载并给出出错表、行号与字段定位。
2. 实现聚合与窗口查询的解析与规范化标识：支持按分组键的计数、求和、最小、最大、均值聚合，以及按分组键分区、按时间戳排序的滑动区间 SUM 与行序号计算，拒绝子查询与不支持的算子并返回 E_EXPR；同一语义查询在空白、键顺序与大小写折叠差异下必须得到同一规范化文本与结构摘要，标识须写入执行轨迹。
3. 实现按分组键维护的聚合状态：每个分组维护计数、求和、极值与均值的定点整数状态，均值以缩放因子与截断方向显式定义的定点方式表示并给出量化误差上界；同一行不得被重复累加，批次边界不得改变最终结果，状态中须携带定点口径版本，报告逐分组输出状态摘要。
4. 实现滑动窗口的环形缓冲状态推进：窗口按时间戳区间与最大行数双约束定义，须维护环形缓冲并正确处理进入、滑出与乱序到达的行；乱序行依显式规则决定是否计入窗口及是否触发局部重算，滑出行的移除不得改变仍在窗口内行的贡献，窗口状态摘要须可持久化并记录区间闭合规则。
5. 实现分批推进时的状态持久化与快照整体替换恢复：状态快照持久化已处理行游标、每分组聚合状态、每分区窗口环形缓冲内容、状态格式版本与定点口径版本；重新打开快照时须比较快照版本与当前查询参数版本，不一致须整体替换分组与窗口状态而非增量合并，恢复后从行游标继续推进。
6. 实现恢复后与不中断推进的逐位一致性校验：从快照恢复并推进剩余批次，与一次性不中断处理全部数据在最终聚合结果、窗口结果与状态摘要上逐位比较，差异须定位到首个不一致的分组键、分区键、时间戳与字段并输出 E_DIVERGE；一致时输出可逐项核对的摘要对照记录。
7. 实现指令注入的异常链路与业务码：支持以命令行参数注入快照损坏、分批边界落在窗口中途、乱序比例超限三类异常，分别以 E_SNAPSHOT、E_BATCH、E_ORDER 业务码报告并写入结构化日志；注入仅改变输入文件或参数，不得修改源码，异常发生后已持久化状态仍须能被验证工具读取。
8. 提供 Tkinter 界面与结果验证工具：界面展示查询列表、规范化标识、每分组聚合状态、每分区窗口内容、已处理游标与快照列表，渲染顺序稳定；验证工具独立读取快照与结果文件，校验聚合与窗口结果是否与状态摘要对应、状态版本与定点口径版本是否一致，并输出固定顺序的总结报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证聚合与窗口结果逐位一致、快照恢复后继续推进与不中断推进一致，异常参数返回对应业务码。
