这份需求说明刚交到团队手中，工作目录仍是空的，只有一台装好 Python 的 Linux（WSL Ubuntu）开发环境。目标是先落地一个可运行的独立诊断引擎，验证长时序视频生成链路在强制终止后能从已提交检查点恢复、并与一次性生成逐帧一致。输入全部由本地固定种子脚本生成：视频生成任务清单为 JSONL，字段含 clip_id、total_frames、frame_shape、noise_seed、motion_mode、block_size、propagation_steps、revision；每个 clip 的初始噪声帧由固定种子驱动 NumPy 生成，后续帧按显式声明的传播算子从相邻块逐步生成。引擎需完成分块传播生成、按块可持久化检查点、强制终止恢复、缓存依赖失效追踪，并输出逐帧像素级诊断报告。

任务环境与准备：
安装 Python 3.10 或更高版本，并安装 NumPy。
准备一个本地固定种子样本生成脚本，能输出视频生成任务清单 JSONL 与初始噪声帧参数。
创建空工作目录，配置可执行权限用于原子文件替换。

业务要求：
1. 实现确定性的分块时序传播生成：按 block_size 把帧序列切块，每个块内以前一块尾帧为条件按 propagation_steps 逐步生成，块内帧与一次性按同一传播算子生成的对应帧必须逐像素相同；propagation_steps 或 block_size 非法时返回 E_PROPAGATION_INVALID 并指明 clip_id 与参数字段。
2. 实现按块可持久化检查点：每个块完成后产生带单调递增版本号、已完成帧序号集合与内容校验和的检查点，仅当该块内全部帧生成并校验通过才允许提交；提交须以临时文件写入后原子替换，部分完成的块不得提交为已完成状态，版本冲突时返回 E_CHECKPOINT_CONFLICT。
3. 实现强制终止后的恢复逻辑：重启时读取最近一次已提交检查点，从记录的下一块或下一帧继续生成，已提交帧的噪声与像素内容不得重算或重复计入；未提交的中间帧与传播状态必须丢弃并从该块起点重建，恢复后的完整帧序列须与不间断完整运行逐字节一致，未能恢复已提交帧返回 E_RECOVERY_MISMATCH。
4. 实现基于内容寻址的帧缓存与缓存键构造：每个帧产物附带内容哈希落盘，缓存键须纳入噪声种子、clip_id、帧序号范围、block_size、propagation_steps 与上游帧内容哈希；键相同必须复用快照，键不同必须重算，不得以时间戳等非确定输入作为键的一部分，缺少必要上游哈希时返回 E_CACHE_KEY_INVALID。
5. 实现生成参数或噪声修订后的依赖失效传播：当某 clip 的 revision 提升、noise_seed 变化或 propagation_steps 调整时，计算受影响帧集合为从变更点起该块及其下游全部帧，复用未受影响上游已提交帧缓存，仅重算受影响后缀；须输出重算帧集合与复用帧集合并保证并集覆盖全部帧且无交集，遗漏或重叠返回 E_INVALIDATION_MISMATCH。
6. 实现进度快照与缓存的状态一致性自检：校验检查点中已完成帧集合与实际磁盘缓存内容一致、帧缓存键与帧内容哈希互相可核对、重算帧与复用帧无交集且并集覆盖全部帧；检测到任何不一致返回 E_STATE_INCONSISTENT 并输出首个偏差帧与检查点版本，禁止静默修补或跳过不一致状态。
7. 实现并发提交控制与资源上限：同一时刻只允许一个块检查点提交生效，并发提交冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待，已完成块不得被旧版本覆盖；为单 clip 生成块数、驻留帧像素内存与传播中间状态数设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或降级到更小块并标记降级类别。
8. 实现输入与配置校验链路及诊断报告输出：重复 clip_id、total_frames 与噪声数组维度不符、block_size 或 propagation_steps 非正、revision 回退分别返回结构化业务码并指明字段与 clip_id；最终输出含逐帧校验和、检查点版本、重算与复用集合、恢复报告及最近业务错误的 JSON 报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定种子样本验证分块生成与恢复逐帧一致，并检查缓存失效与错误码。
