政务服务平台的值班工程师与服务质量管理员需要在接入真实监控前，先固化为本地可验证的合成探测归因口径。平台覆盖办件受理、电子证照签发与证照核验等业务接口，服务目录登记了各服务依赖关系与责任团队。探测记录按逻辑时刻记录接口响应码、耗时与失败原因，单次超时或抖动不能直接判为不可用，需要区分偶发失败与持续性故障，并把可用性下降事件归因到具体服务、接口和失败模式，形成可交接的归因报告供值守处置。

任务环境与准备：
在 Linux（WSL Ubuntu）下准备 Python 3 运行环境，仅使用标准库，无需安装第三方包。
工作目录从空目录开始，由题目实现自行生成固定种子的合成探测记录、真值标注与归因报告文件。
运行方式为本地命令行入口，输出结果文件与 stderr 错误码均可在本机复现。

业务要求：
1. 要求实现探测记录生成器：依据固定种子与探测策略（探测周期、节点数量、服务与接口清单）生成确定性的合成探测记录与真值标注文件，记录包含探测时刻、服务标识、接口标识、响应状态码、响应耗时毫秒、失败原因分类与来源节点，且同一输入种子下输出逐字节一致。
2. 要求按服务与接口做时序聚合：对每个探测时刻输出滑动窗口内的探测次数、失败次数、失败率以及响应耗时的 P50、P95、P99 分位值，窗口长度取自策略声明，禁止跨越不同服务的记录混合统计。
3. 要求判定可用性下降事件：同时应用连续失败阈值与延迟分位阈值，区分偶发失败（窗口内失败率低于阈值但存在孤立失败）与持续性故障（连续失败次数达到阈值），并为每个事件记录起始与结束逻辑时刻、涉及的服务与接口。
4. 要求对每个可用性下降事件按失败模式分类统计，结合时间窗口重叠度与服务依赖关系对候选根因打分排序，输出根因候选列表及对应证据区间（起止时刻与涉及接口）。
5. 要求利用服务目录中的依赖关系传播影响，从根因候选出发沿依赖图标注受影响的全部下游服务与接口清单，并区分直接受影响与间接受影响。
6. 要求生成按责任团队分组的可用性摘要，包含该团队负责服务的事件数量、主要失败模式、待处理事件按优先级排序的清单，且摘要中各事件的统计口径与逐事件归因结果严格一致。
7. 要求输出归因报告，包含事件时间线、证据区间与根因候选排序；报告以确定性快照方式持久化到文件，内容包含输入摘要与参数版本，重新计算相同输入时报告内容保持稳定，参数变化时能识别版本差异。
8. 要求对异常输入做显式处理：探测记录缺失字段、时间戳乱序、接口不在服务目录中、分位阈值超过窗口长度等情况以结构化错误码输出到 stderr 并拒绝该批次，不得静默丢弃或产生部分归因结果。

验收：
以固定种子生成探测记录与真值标注，验证各时刻失败率与延迟分位数和独立计算器一致，可用性事件匹配标注且根因候选前三包含真实根因，责任团队摘要与逐事件归因汇总一致。
