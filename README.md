在空白工作区从零实现一个本地推理服务的动态批处理与调度内核，重点解决批处理窗口、优先级插队与队列水位演进过程中的数值精度与误差传播问题。本地 JSON 样本给出：模型描述（每层参数量、每请求输入与输出 token 数、每副本算力单位）、副本清单（副本 ID、可用算力、显存上限 MiB、批处理窗口逻辑毫秒、最大批大小、支持序列长度上限）、请求轨迹（请求序号、到达逻辑时钟毫秒、优先级、输入 token 数、最大输出 token 数、期望截止逻辑时钟）与精度配置（算力占用与延迟估算所用的定点标度、浮点容差、误差上界预算、逻辑时钟步进）。内核需把请求按到达顺序纳入各副本的批处理窗口，在算力与显存双重预算下裁决每批容纳的请求集合，估算每批用于调度比较的算力占用、显存占用与预计排队时长，估算须固定运算顺序以保证逐位可复现；同时记录每次估算的定点换算与浮点累计误差谱，当两个候选批或两个副本的估算差小于容差而批组成或副本选择依赖该差值时标记为精度敏感。进程被强制终止后需按 SQLite 中的窗口水位、已提交批次与请求状态恢复并继续，不得凭内存残留决定哪些请求已入批。

任务环境与准备：
安装 Python 3.11 或以上，并安装 numpy 与标准库 sqlite3；无需 GPU、网络或外部服务。
在工作区创建空目录结构：样本描述 JSON、SQLite 元数据库路径与临时目录。
准备固定样本：模型描述、副本清单、请求轨迹与精度配置，全部为本地 JSON，请求轨迹含到达与截止逻辑时钟以及优先级的边界取值。
确保 Windows 下文件原子重命名与文件锁可用，并为强制终止场景准备可重复的终止点脚本。

业务要求：
1. 实现模型描述、副本清单与请求轨迹的解析校验：副本 ID 唯一、每副本算力为有限正数、显存上限与最大批大小为正整数、支持序列长度上限不小于任一请求的输入输出 token 数、请求序号唯一、到达与截止逻辑时钟为非负整数、期望截止不早于到达，构建请求到副本候选的映射；非法输入必须返回明确业务错误码（如 E_BAD_REQ、E_REQ_NO_REPLICA）且不写入任何持久化状态。
2. 实现按到达逻辑时钟推进的批处理窗口切分与请求归属：窗口边界由副本批处理窗口逻辑毫秒与注入逻辑时钟共同决定，不读取系统墙钟；每个请求必须唯一归属一个副本的一个窗口且不得同时计入两个窗口，窗口期满未满批也必须以提交态关闭；同一轨迹在任意运行次数下必须得到逐位一致的窗口划分与请求归属。
3. 实现算力与显存双重预算下的批组成裁决：在最大批大小、副本可用算力与显存上限约束下决定每批容纳的请求集合，优先级插队必须显式记录被跳过请求与首个触发约束；批组成决策须记录所依赖的观测项（各请求 token 数、副本剩余算力与显存、窗口剩余逻辑时长）与聚合顺序，使相同观测在任意运行次数下得到相同批组成。
4. 实现批估算量的定点换算与误差谱记录：把每批的算力占用、显存占用与预计排队时长各自按声明定点标度换算，记录每项换算的标度、舍入方向与换算前原始浮点值，并对每次加法与乘法累计误差上界；当两个候选批或两个副本的估算差小于给定容差且决策依赖该差值时标记为精度敏感，输出误差来源链，含参与参数、请求序号与换算步骤。
5. 实现请求生命周期状态机与连续失败计数演进：请求在待入批、已入批、执行中、已完成、已超期之间迁移，迁移须依据已提交窗口结论与持久化状态裁决，重启后不得凭内存残留决定请求状态；已超期请求必须与执行失败区分记录，且不得继续占用副本算力与显存额度。
6. 实现强制终止后的恢复与断点续算：把窗口水位、已提交批次清单、请求状态、算力与显存占用、误差谱与逻辑时钟水位以事务原子写入 SQLite；进程在窗口提交或批组成裁决中途被强制终止后，恢复路径依据持久化状态识别已提交批次与半提交窗口，只重放未提交部分，不得重复占用额度，也不承诺一定生成退出报告。
7. 实现副本规格版本整体替换与旧版本识别：副本清单每次变更产生新版本号并整体替换当前副本快照指针，需比较算力、显存与批窗口参数判定是完整替换、增量追加还是无需操作；版本回退必须被拒绝，进行中的窗口必须绑定其开始时的副本版本直至关闭，读取方不得观察到新旧副本参数混合的估算。
8. 实现多进程并发一致性与可重复命令行演示：多个调度进程并发推进同一副本时通过 SQLite 事务与文件锁保证同一窗口同一版本只被提交一次、同一请求序号同一版本只被入批一次，重复提交相同窗口结果必须幂等；提供 load、dispatch、resume、status、verify 子命令，status 以稳定排序 JSON 输出各副本窗口水位、已提交批数、精度敏感标记数与误差上界，verify 校验持久化状态与批次清单一致。
