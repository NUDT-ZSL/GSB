当前是空白工作区，需要从零实现一个本地多环境部署清单的互操作与收敛验证引擎，核心业务目标是让同一套服务在开发、预发、生产三个环境的部署参数具备可复现的一致性判定能力，并能定位不一致来源。本地样本提供两代部署清单：v1 为单文件 YAML，按环境记录服务名、镜像标签、副本数、超时毫秒、重试倍率、资源上限与一个扁平的服务到参数映射；v2 为分片 JSON 加 SQLite 元数据库，记录服务规范名、环境、绝对生效时刻毫秒戳、清单代数、参数键值集合、依赖上游服务列表与失效墓碑。引擎需加载并合并两代清单为统一环境视图，在可注入逻辑时钟下判定跨环境参数一致性，沿依赖图计算派生量，并支持受控异常注入与强制终止后的恢复。全部样本与测试在本地文件系统上确定性运行，不依赖真实集群、云端账号或外部网络。

任务环境与准备：
在空白工作区创建项目目录，安装 Python 3.11 与 PyYAML、pytest（pip 安装即可），无需容器与外部服务。
准备本地样本：v1 单文件 YAML 清单、v2 分片 JSON 与 SQLite 元数据库、三环境服务参数表、依赖上游列表、注入清单与固定的逻辑时钟步进表，全部随项目提供。
确保 SQLite 使用 Python 内置 sqlite3，测试在本地文件系统上以固定种子与固定逻辑时钟序列运行。

业务要求：
1. 实现 v1 YAML 与 v2 分片 JSON 加 SQLite 元数据两代部署清单的解析与校验：v1 校验服务名在环境内唯一、超时毫秒与副本数为正整数、重试倍率为有限正数、扁平映射与参数声明一致；v2 校验分片文件哈希、清单代数单调、绝对生效时刻为毫秒整数、参数键与值类型匹配。非法条目须返回明确业务错误码（如 E_BAD_MANIFEST、E_DIGEST_MISMATCH）且不写入任何持久化状态。
2. 实现跨版本清单合并与统一环境视图构建：同一服务同一环境在两代清单中同时存在时，依据清单声明的逻辑时钟与清单代数裁决最新版本，逻辑时钟相同则按来源格式优先级；合并后每个参数须保留来源版本、原始时间表示与裁决依据，并输出冲突项清单而非静默丢弃一侧数据。
3. 实现时间与参数语义的模式迁移：v1 中缺失绝对生效时刻的参数在注入逻辑时钟下换算为绝对生效时刻并记录换算标度与舍入方向，v1 无清单代数与依赖上游声明的服务迁移为 v2 统一语义并记录迁移映射；迁移不得改变参数在逻辑上是否过期，重复迁移须幂等。
4. 实现跨环境一致性判定与依赖派生量计算：同一服务在三个环境中的超时毫秒、重试倍率与资源上限按容差裁决是否一致，并沿依赖上游边累计最坏链路超时与有效资源上限，运算顺序固定使相同输入逐位可复现；不一致时须输出首个分歧参数、涉及环境与容差余量。
5. 实现基于注入逻辑时钟的版本兼容判定：所有过期判定、生效时刻比较与回滚窗口只依赖注入的逻辑时钟毫秒值，不读取系统墙钟；v2 新增字段在 v1 路径读取时按声明默认语义降级并记录兼容降级清单，逻辑时钟回拨超过容差须返回业务错误码并保持视图不变。
6. 实现清单包整体替换的版本变化识别与回退拒绝：收到新清单包时比较清单版本号、清单代数下限、各分片哈希与参数摘要，判定完整替换、增量追加还是无需操作；整体替换须以临时表加版本号切换当前视图指针而非逐条覆盖，版本回退须被拒绝或按策略降级并记录决策依据。
7. 实现可复现异常注入与业务错误码链路：按本地注入清单在解析、合并、迁移、判定四个阶段注入受控异常（畸形 YAML 字段、分片哈希不匹配、清单代数冲突、依赖成环、逻辑时钟回拨），每种异常映射到不同业务错误码并保留可诊断字段；注入不得修改样本文件或污染已完成阶段的持久化状态。
8. 实现持久化状态、强制终止后的恢复与多进程幂等：把统一视图版本、合并裁决、迁移决策、一致性结论与逻辑时钟水位以事务原子写入 SQLite；进程在合并或替换中途被强制终止后恢复路径须识别未提交步骤并只重放未完成步骤；多个实例并发提交同一清单版本时通过事务与文件锁保证只提交一次且重复提交幂等。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
