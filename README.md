团队接到一项需要独立交付首个可用版本的新能力，当前 Linux（WSL Ubuntu）工作区没有任何既有代码或样本，需要从零构建一个可集成的状态演进与恢复一致性诊断组件，并附完整示例。全部输入由随工程交付的固定种子脚本确定性生成，不依赖真实集群、外部服务或 GPU。业务对象是状态机任务清单（JSONL，每行含 task_id、state_seed、num_steps、block_size、quant_scale、revision、logical_clock_ms），状态数组由固定种子驱动 NumPy 确定性生成。组件把一次状态演进建模为有向无环计算图：初始状态校验→分块状态变换→跨块归约→状态快照提交→恢复裁决，并维护定点换算与浮点累加的误差账本。两代配置快照并存，v1 为单文件 JSON 记录相对生效秒与扁平参数，v2 为分片 JSON 加 SQLite 元数据库记录绝对毫秒、配置代数与失效墓碑。系统需要在可注入逻辑时钟与固定内存预算下，给出可复现的状态输出、误差传播诊断，以及任务修订或配置换版后的增量失效闭包与中断恢复裁决。

任务环境与准备：
在 Linux（WSL Ubuntu）上准备 Python 3.10 及以上环境，安装 numpy，离线执行 pip install numpy；sqlite3 使用 Python 标准库即可，无需额外依赖。
新建空工作目录，编写固定种子脚本生成任务清单 JSONL、两代配置快照与状态数组，确保同一种子多次运行生成完全相同的本地样本。
所有输入、配置与输出均使用本地文件路径，不依赖网络、外部服务或 GPU。

业务要求：
1. 实现确定性的任务摄入与初始校验节点：按 task_id 与 logical_clock_ms 升序解析 JSONL 任务清单，校验 state_seed 与状态维度一致、block_size 能整除状态维度、quant_scale 为正数、revision 非回退；同一输入、同一种子与同一配置下必须逐字节产出相同的分块边界与初始校验和。
2. 实现分块状态变换与跨块归约层：变换函数按显式声明的步数迭代更新状态，块内采用 float64 补偿求和，跨块归约顺序必须确定性可复现；分块串行拼接结果与整段一次执行结果在 float64 下逐元素一致，且每个状态的变换轨迹可追溯到具体块与归约索引。
3. 实现可切换的精度档执行层：float64、float32 与定点缩放整数三档共用同一算子语义，定点档缩放因子与舍入模式由配置给出；切换精度档只允许结果差异来自数值精度损失本身，禁止改变变换顺序、分块边界或归约口径。
4. 实现误差账本与主导来源归因：以 float64 整段路径为参考真值，输出初始校验、分块变换、跨块归约与定点量化各级的最大绝对偏差、相对偏差和误差放大比，并定位主导误差来源；偏差超过容差时返回 E_TOLERANCE_EXCEEDED，账本中必须记录首个偏差步骤与量化边界。
5. 实现任务修订与配置代数提升的定向依赖失效传播：区分仅 revision 提升、仅配置代数提升与 block_size 变化三类情形，按内容寻址缓存键计算受影响任务集合，复用未受影响任务已提交状态摘要与误差账本，仅重算受影响后缀，并输出重算与复用任务集合。
6. 实现两代配置快照的读取、迁移与整体替换：v1 升级到 v2 时补全绝对毫秒、配置代数与失效墓碑并逐项记录补全来源，v2 降级到 v1 时对无法表达的墓碑按显式丢弃规则处理；检测到版本号或校验和变化时必须整体替换旧快照，回退尝试返回 E_SNAPSHOT_ROLLBACK。
7. 实现阶段状态机与中断恢复：任务在阶段边界提交带单调递增版本号、已完成 task_id 集合与内容校验和的检查点，重启后从最近已提交检查点继续，已提交任务不得重算或重复计入，未提交的中间变换与账本条目标记作废；恢复后的最终状态账本必须与无中断执行逐字节一致。
8. 实现并发提交控制与跨模块一致性自检：同一时刻只允许一个检查点或配置快照提交生效，并发冲突时后到者立即获得 E_STAGE_BUSY 且不阻塞等待；自检校验误差账本可由记录参数独立复算、重算与复用集合无交集且并集覆盖全部受影响任务，不一致返回 E_INCONSISTENT 并标明首个偏差任务。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证状态计算、误差诊断与恢复后的账本逐字节一致。
