省级气象观测数据中心的数据保留管理员与灾备值班工程师正在准备一次归档数据灾备演练。区域自动气象站与雷达观测网络的归档数据在主备两端分别落盘，各站点按要素以批次序号顺序写入，每个站点类别声明了恢复点目标与可接受缺口阈值。演练中会出现归档中断与灾备切换，主备落盘进度不一致，只比较最后提交位点无法定位中间缺失的观测批次，也无法判断缺口是否超出该站点等级的恢复点目标，导致核心预警站在灾后复盘时才发现关键时段观测缺失且没有补传依据。管理员需要一套本地可重复运行的缺口核算与恢复点结算组件，输出逐站点的数据缺口区间、超标裁决、补传动作清单与切换后的恢复点达成账目。

任务环境与准备：
在 Linux（WSL Ubuntu）上准备 Python 3 运行环境，仅使用标准库，不安装第三方包。
工作目录从空目录开始创建项目，题内确定性生成器、参考计算器与核对器均以仓库内文件提供。
运行入口为命令行脚本，生成器与主流程均可通过命令行参数指定种子与工程文件路径，输出 JSON 报表。

业务要求：
1. 实现确定性归档工程生成器，按固定种子产出若干站点的观测批次记录，每条记录含站点编号、要素类型、批次序号、写入时刻（epoch 毫秒）、站点保留等级，并生成主备两端各自已落盘批次清单与最后提交位点，以及按逻辑时刻排列的切换、中断与恢复事件序列，同一份工程可通过命令行参数整体重放。
2. 按站点、要素与批次序号对齐主备两端已落盘批次，分别输出主端有而备端缺失、备端有而主端缺失两类批次集合，处理批次序号不连续与同一批次在两端写入时刻不一致的情况。
3. 将缺失批次按写入时刻归并为连续数据缺口区间，每个区间输出起止时刻、缺口记录数与涉及要素，区间归并需正确跨越中断事件边界，并保证缺口记录数等于区间内实际缺失批次数。
4. 依据站点类别声明的恢复点目标与可接受缺口阈值，将每个缺口区间换算为是否超标的裁决并给出超标量，缺口时长或记录数恰好等于阈值时判定为未超标，并在报表中标注判定所依据的阈值与单位。
5. 对超标缺口生成补传或重建动作清单，按站点保留等级与缺口时长确定处理优先级，同一优先级内按缺口起始时刻先后排序，输出动作类型、目标站点要素与触发的缺口区间引用。
6. 对灾备切换与中断恢复事件，以事件之后各站点最后提交位点为恢复点核对实际恢复程度，结算各站点是否达成本轮恢复点目标，输出未达标站点清单与恢复点差值。
7. 汇总按站点与要素分组的数据缺口与恢复点达成报表，标注触发补传的依据区间与判定阈值，报表内容与前面各需求的计算结果保持一致并可逐项追溯。
8. 内置独立缺口区间参考计算器与恢复点核对器，对主流程输出逐站点逐要素复核，报告首个不一致的站点要素及其对齐依据，并用人工构造的主备位点相同但中间批次缺失、缺口恰好等于阈值与切换后部分补传样本验证归并与裁决路径。

验收：
以独立参考计算器和人工样本核对缺口区间、超标裁决与恢复点达成账目一致。
