为语音端点检测（VAD）算法团队从零构建一个本地可运行的离线评估与异常注入服务，核心问题是可复现验证与异常注入。工作区为空，需自行初始化项目。输入是本地样本目录：一份音频清单 JSONL，每条含 clip id、相对路径、采样率、声道数、位深、帧长毫秒与帧移毫秒；每个音频为本地确定性合成的 PCM WAV，采样率覆盖 8000 与 16000 Hz，位深覆盖 16 位与 32 位浮点，声道数覆盖单声道与双声道，时长数秒，含静音段与若干段人工构造的带噪语音段；一份真值标注 JSONL，每条含 clip id 与按帧下标给出的语音帧标记序列，另有一份噪声注入配置 JSON，声明注入片段、注入幅度与注入位置。团队需要在统一帧网格上把 VAD 判定结果与真值逐帧比较，输出指标与逐帧差异清单，并支持以输入参数注入异常来验证错误链路。VAD 本身采用本地确定性能量与过零率双门限决策器实现，不依赖任何外部模型或网络。帧数由时长与帧长帧移换算得到，换算须声明取整规则并作为观测口径。

任务环境与准备：
安装 Python 3.11 与 pip，创建虚拟环境并安装 numpy、fastapi、uvicorn、httpx、pytest，版本以安装时锁定为准。
确认工作区为空目录，用任务自带的确定性 WAV 合成脚本生成本地样本、标注 JSONL 与噪声注入配置，全部置于本地 examples 目录。
确认 SQLite 标准库可用，预留本地数据目录与端口，无需外部账号、网络或 GPU。
运行前置检查：python -c "import numpy, fastapi" 与 sqlite3 版本输出记录到本地日志。

业务要求：
1. 入口接收样本目录、标注文件、噪声注入配置与服务端口，校验清单字段完整、音频文件存在且 WAV 头与清单声明的采样率、声道数、位深一致、帧长与帧移为正毫秒且帧移不超过帧长；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不得创建任何结果文件或临时目录。
2. 须实现确定性 VAD 决策器：先按清单声明把各声道下混为单声道，再按帧长与帧移划分帧，用短时能量与过零率双门限逐帧判决，判决阈值由显式参数给出；同一音频与参数重复运行须得到逐帧一致的判决序列，禁止依赖系统时间、全局随机状态或文件遍历顺序。
3. 噪声注入须按配置把指定片段以指定幅度叠加到指定位置，叠加须以饱和方式限制在目标位深范围内且逐样本确定性；注入后音频摘要与削波样本数须写入诊断，注入配置位置越界、幅度非有限或片段不存在时返回 E_INJECT 并定位 clip id 与注入序号。
4. 评估须在统一帧网格上逐帧比较判决与真值：帧数须按时长与帧长帧移换算并声明取整规则，真值长度与换算帧数不一致时返回 E_LABEL 并给出 clip id 与实际帧数与期望帧数；比较须输出命中、虚警、漏检计数与帧级指标，以及可定位到 clip id 与帧下标的差异清单。
5. 每次评估须以整体替换方式生成版本化快照，含配置指纹、逐 clip 判决摘要、指标与差异清单文件哈希；读取快照时若检测到数据库版本与磁盘文件哈希不一致、配置指纹变化或残留旧版本结果文件，须返回 E_STALE 并定位到 clip 与版本号，禁止汇入旧数据。
6. 须提供 HTTP 接口：创建评估作业、查询作业进度与逐 clip 帧级统计、获取版本化快照；作业未完成时读取快照返回 E_PENDING。错误响应与正常响应须共用同一 JSON 结构，业务码与定位字段不得因错误类型不同而缺失或改名，错误发生前已提交的进度不得被回滚。
7. 评估进度须在 SQLite 中以 clip 粒度事务提交，判决结果文件先写临时文件再原子替换并登记内容哈希；进程被强制终止后重启须核对已提交 clip 的内容哈希与结果文件，重算未提交 clip 且不重复处理已提交 clip，恢复后的指标与差异清单须与无中断执行完全一致。
8. 须提供确定性本地演示入口：固定一组覆盖单声道与双声道、16 位整数与 32 位浮点、不同帧长与帧移、含静音与带噪语音的样本及注入序列，跑出逐 clip 帧级指标、注入削波数、快照版本序列与恢复前后一致性结论的可重复结果，并给出用等价参数注入 E_PARAM、E_INJECT、E_LABEL、E_STALE 的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
