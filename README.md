当前是空白工作区，没有现存代码或数据附件，需要从零构建一个面向分块注意力推理的本地可集成算子组件与完整示例，核心业务问题是交互式首块延迟与整段计算结果的逐字节一致性。业务对象是本地确定性生成的推理任务清单（JSONL，字段含 case_id、seq_len、head_dim、n_heads、q_block_len、kv_block_len、causal、dtype、seed、latency_budget_ms），Q/K/V 数组由固定种子驱动 NumPy 确定性生成，不依赖真实模型文件、GPU 或外部服务。系统把一次调用建模为按 Q 分块逐个输出注意力结果的流水：用户先请求前若干 Q 分块的可查询结果，再请求后续分块，最后请求完整输出。核心矛盾是：按 Q 分块可显著缩短首块可查询耗时，但分块边界处的在线归一化统计量合并口径若与整段一次性计算不同，逐块拼接结果就会与整段输出出现像素级偏差；同时 Q 分块与 KV 分块两个尺寸互相牵制，一方过小会放大另一方归约开销。组件须交付可复现的命令行验证入口与 JSON 报告。

任务环境与准备：
安装 Python 3.10 及以上版本，创建虚拟环境并安装 NumPy（建议 1.24 及以上），不需要 GPU 或外部数据集。
在工作区创建项目目录与本地样本生成脚本，按任务清单字段用固定种子生成 Q/K/V 数组与 JSONL 样例，快照与输出目录均置于项目内本地路径。
准备命令行入口运行分块注意力、分块就绪查询与整段一致性裁决演示，结果与报告写入本地目录，全过程在 Windows 本机完成。

业务要求：
1. 实现确定性的分块注意力核心：按 q_block_len 与 kv_block_len 两级分块完成打分、在线 softmax 归一化与输出累加，causal 语义下禁止访问未来位置；同一 case_id、同一 seed 与同一配置下必须逐字节复现全部分块统计量与输出，同分或同位置按显式声明的索引顺序裁决。
2. 实现按 Q 分块逐块就绪的查询接口：能查询已就绪 Q 分块的输出与其起止位置，并在整段计算完成前返回部分结果；首块可查询耗时以本地计算循环的实际处理计时作为观测，并按首块 Q 分块长度、KV 分块数与每块打分规模给出估算记录，超时返回 E_LATENCY_BUDGET 并附带已完成分块清单。
3. 实现分块输出与整段一次性输出的逐字节一致性裁决：块边界处的在线归一化统计量合并口径必须与整段口径完全相同，逐块拼接结果与整段结果逐元素相同，不一致返回 E_BLOCK_MISMATCH 并输出首个偏差位置、所在 Q 分块与合并偏差量。
4. 实现 q_block_len 与 kv_block_len 的联合取舍裁决：当缩小 Q 分块降低首块耗时但增加在线归一化合并次数、缩小 KV 分块降低单块驻留内存但放大分块数量与归约开销时，按显式优先级规则在首块耗时、驻留内存与合并次数之间裁决，并在分块计划中记录裁决依据、所选两档分块与各候选组合的代价估计。
5. 实现数值稳定性保护：分块最大值、归一化分母与输出累加的中间量以 float64 计算，提供可配置的次正规数保护与舍入模式，并要求各分块统计量可合并还原为整段 softmax 分母，还原偏差超出声明容差返回 E_STABILITY_VIOLATION 并指出分块位置。
6. 实现分块计划与就绪分块清单的版本化快照及整体替换：分块计划、归一化参数与就绪分块清单各携带单调递增版本号与内容校验和，提交时整体替换旧快照而非增量修补；加载时识别版本号或校验和变化并整体替换，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或不符返回 E_SNAPSHOT_CORRUPT。
7. 实现输入与配置校验链路：重复 case_id、seq_len 与数组维度不符、q_block_len 或 kv_block_len 非正、n_heads 与数组形状不一致、causal 取值非法分别返回结构化业务码并指明字段与 case_id；样本级异常须归因到具体阶段名，不得静默丢弃。
8. 提供可集成的领域组件接口与完整命令行示例，并实现跨模块一致性自检：暴露分块注意力计算、分块就绪查询、整段一致性裁决与快照查询入口；自检校验分块处理与整段处理的 case_id 集合一致、合并统计量可重算出整段分母、就绪分块清单与已产出输出可互相核对，不一致返回 E_INCONSISTENT。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
