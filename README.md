本地 Linux（WSL Ubuntu）工作目录没有历史代码和样本，先交付一个面向 LLM 多轮对话状态管理的诊断引擎。业务输入由本地固定种子脚本确定性生成，不依赖真实账号或网络：对话轮次清单为 JSONL，字段含 session_id、turn_no、user_text、assistant_text、slot_candidates（键值对及置信度）；槽位状态快照以三种并存格式给出，v1 为单文件 JSON 扁平记录相对秒，v2 为分片 JSON 加 SQLite 记录绝对毫秒与状态代数，v3 为结构化嵌套描述含变更历史与校验和；另有解析规则配置声明槽位合并策略与澄清门限。系统把一次对话状态推进建模为有向无环计算图：轮次解析、槽位候选打分、槽位合并、待澄清集合生成、状态摘要，核心约束是格式迁移必须语义等价，轮次撤回或追加时仅重算受影响后缀，并发提交与强制终止恢复不得破坏已提交状态。

任务环境与准备：
安装 Python 3.10 及以上版本，使用 pip install numpy 安装基础依赖。
创建空项目目录，准备本地确定性样本生成脚本（含对话轮次 JSONL、三格式快照与解析配置）。
确保 Linux（WSL Ubuntu）环境可运行 Python 与 SQLite，无外部网络依赖。

业务要求：
1. 实现 v1、v2、v3 三种槽位状态格式的读取器，按版本头或字段集分派解析路径；未知版本返回 E_VERSION_UNSUPPORTED，行字段数不符、必填字段缺失或数值不可解析返回 E_FORMAT_CORRUPT，且不依赖真实账号或网络。
2. 实现三套格式到统一内部表示的双向迁移器：升级时补全状态代数、变更历史与校验和默认值并逐项记录补全来源，降级时对无法表达的嵌套变更历史按显式丢弃规则处理；迁移后内部状态必须完全相同，若因表达能力不足导致语义不可还原返回 E_SEMANTIC_DRIFT。
3. 实现确定性的轮次解析与槽位候选打分节点：按 turn_no 升序解析对话轮次，对每个槽位候选依据置信度与来源轮次加权打分，同分按来源轮次升序再按槽位键字典序裁决；同一会话、同一配置与固定种子下必须逐字节产出相同打分结果。
4. 实现槽位合并节点：同一槽位键出现新候选时按来源轮次覆盖，来源轮次相同时取高分，仍相同按候选值字典序裁决并标记冲突；合并结果须记录获胜候选与全部被覆盖候选，且被覆盖候选不得在最终状态中继续可见。
5. 实现待澄清集合生成节点：由合并后的槽位状态与助手澄清请求推导待澄清槽位集合，须校验待澄清槽位均存在于状态中且其获胜候选置信度低于澄清门限，违反分别返回 E_PENDING_SLOT_MISSING 与 E_CONFIDENCE_ABOVE_THRESHOLD。
6. 实现内容寻址缓存与增量失效传播：候选打分、槽位合并、待澄清集合与状态摘要均以内容哈希落盘，缓存键纳入上游输入摘要、解析配置版本与上游产物哈希；轮次撤回或追加时计算受影响后缀并仅重算该后缀，复用未受影响上游产物，缓存键相同必须复用、键不同必须重算。
7. 实现状态快照的版本化整体替换与并发提交控制：快照携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，回退尝试返回 E_SNAPSHOT_ROLLBACK；同一时刻只允许一个快照提交生效，冲突时后到者立即返回 E_STAGE_BUSY 而不阻塞等待。
8. 实现字节级一致性裁决与输入校验链路：校验任意槽位值均可经其缓存键、来源轮次与候选解析重放出同一值，重复 session_id、slot_key 命名非法、置信度越界分别返回业务码并指明字段；最终报告须包含统一内部状态视图、迁移补全与丢弃明细、重算与复用集合，且本地确定性样本重跑结果逐字节一致。
