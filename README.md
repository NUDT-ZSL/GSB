当前是空白工作区，需要从零构建一个面向多模态协同推理的本地数据处理管线与结果验证工具。业务对象是本地确定性生成的图文对样本：每张图由固定种子生成的确定性像素数组（RGB，固定尺寸）与对应文本描述组成，样本清单为 JSONL，字段含 pair_id、image_seed、image_shape、text、modality_mask、stage_hint。推理流程被建模为多阶段协同管线：图像编码阶段产出图像嵌入，文本编码阶段产出文本嵌入，融合阶段按 modality_mask 对齐两个嵌入并产出联合表示，评分阶段依据联合表示产出匹配分数与预测标签并被阈值化为最终裁决。核心业务问题是状态演进与恢复一致性：每个阶段产生可持久化的阶段快照，管线在长时间运行中被强制终止后必须从最后一次已提交阶段恢复，不得把进行中的中间结果当作已完成结果，也不得因恢复产生重复样本或重复计分。样本规模、各阶段数值口径、快照格式与业务错误码均在题目内给定，不依赖任何外部服务、数据集或附件。

任务环境与准备：
准备 Windows 本地工作区，安装 Python 3.11 并确认可创建虚拟环境。
通过 pip 安装 NumPy 与标准库外所需的纯本地依赖，不引入任何外部服务或网络数据。
运行前用固定种子生成本地图文对样本与样本清单，确保样本、配置与快照目录均位于工作区内。
准备可重复的强制终止演示脚本：以子进程启动管线并在指定阶段中断，验证恢复后与完整运行结果一致。

业务要求：
1. 实现图像编码、文本编码、融合、评分四个阶段的协同推理管线，各阶段输入输出语义明确；同一 pair_id 与同一图像种子必须产出逐字节一致的中间嵌入与最终分数，禁止依赖除固定种子与显式配置外的任何外部状态。
2. 实现各阶段的可持久化阶段快照，快照携带单调递增版本号与内容校验和，只有该阶段全部样本处理完成才提交快照；提交顺序、阶段状态与版本号必须在持久化存储中原子可见，部分完成的阶段不得提交。
3. 实现强制终止后的恢复逻辑：重启时读取已提交快照，从最后一次已提交阶段继续向下执行，已提交阶段的样本不得重算或重复计入；进行中未提交的中间工作必须丢弃并从该阶段起点重建，恢复结果须与不间断完整运行的结果逐字节一致。
4. 实现快照版本变化与整体替换：检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，损坏或校验和不符的快照返回 E_SNAPSHOT_CORRUPT 并指明阶段名与版本号，禁止使用部分可解析的损坏数据继续推理。
5. 实现跨阶段一致性自检与重复检测：校验四个阶段处理的 pair_id 集合完全一致、评分阶段每条样本恰被计分一次、中间嵌入维度与 modality_mask 语义匹配；出现样本泄漏到相邻阶段、重复计分或维度错配时返回 E_INCONSISTENT 并指出不一致类别与 pair_id。
6. 实现并发提交控制与资源上限：同一时刻只允许一个阶段提交生效，并发提交冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待，已完成阶段不能被旧版本回退覆盖；为单阶段样本数、嵌入内存与快照条目数设可配置上限，超限返回 E_RESOURCE_LIMIT 并按明确策略拒绝。
7. 实现输入与异常校验链路：重复 pair_id、modality_mask 取值非法、图像种子与形状不匹配、text 为空分别返回 E_DUP_PAIR、E_MASK_INVALID、E_SEED_SHAPE、E_EMPTY_TEXT 并归因到具体 pair_id；写入磁盘失败等异常须沿异常链路归因到具体阶段与版本，不得静默吞掉。
8. 提供结果验证工具与可交互诊断应用：验证工具独立复核各阶段快照、嵌入维度、计分覆盖与恢复一致性；应用展示当前阶段、快照版本、各阶段样本计数、最近业务错误码，并允许触发一次演示运行，演示用本地确定性样本并注入一次强制终止后恢复与一次损坏快照场景。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证多阶段推理、强制终止后恢复与快照一致性，并检查异常业务码与验证工具输出。
