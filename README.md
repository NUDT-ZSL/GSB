当前是空白工作区，需要从零实现一个本地隧道与 VPN 转发组件的路径裁决内核，并以可集成组件加完整示例的形式交付。本地样本以 JSON 给出隧道对端清单（对端名、服务监听回环地址、外层封装 MTU、内层应用载荷长度分布、链路权重、是否启用加密占位标记）、链路画像（往返时延毫秒、丢包率、可用带宽、抖动上限）以及转发策略配置（分片阈值、每轮并发转发上限、单轮逻辑时间预算毫秒、重传预算、容差参数、逻辑时钟步进）。转发目标由本地回环 UDP/TCP 回显服务模拟，接收方按分片序列号重组并回报重组摘要，不依赖任何真实 VPN 协议栈或外部网络。核心业务目标是让内层载荷在不同规模变化下选择分片与封装尺寸、以及逐包直发与聚合发送之间的算法取舍，并在链路画像变化、重传与中断恢复时保持重组结果一致。

任务环境与准备：
安装 Python 3.11 或更高版本，并安装 NumPy 与 pytest（pip install numpy pytest），无需任何外部网络服务。
在工作区建立样本目录，放入隧道对端清单、链路画像与转发策略三个 JSON 文件，以及用于启动本地回环 UDP/TCP 回显服务的测试脚本。
准备一个本地 SQLite 数据库文件路径用于持久化分片水位与隧道状态，确保工作区可写。
运行 pytest 做环境自检，确认本地回显服务可在回环地址上正常收发。

业务要求：
1. 实现隧道对端清单、链路画像与转发策略的解析校验：对端名唯一、监听地址为合法回环地址、外层 MTU 与内层载荷长度为正整数且内层载荷不大于外层 MTU 的可封装上限、丢包率与抖动上限在合法区间、并发上限与逻辑时间预算为正整数；非法条目必须返回明确业务错误码（如 E_BAD_ENDPOINT、E_BAD_MTU）且不写入任何持久化状态。
2. 实现内层载荷的确定性分片与封装：按外层 MTU、分片阈值与加密占位开销计算每片可携带载荷字节数，分片序号连续且最后一片标记结束，相同输入重复分片必须得到逐字节一致的分片头与分片摘要；分片重组须按序列号还原原载荷并比对整体摘要，乱序、缺片与重复片必须能区分并映射到不同业务错误码。
3. 实现逐包直发与聚合发送两种转发算法的规模自适应裁决：负载低于阈值时逐包直发，高于阈值时按聚合窗口把多个分片合并封装发送；裁决须依据可观测的内层载荷长度分布、并发上限与链路带宽，输出选定算法、切换触发条件与被否决算法原因，并说明估计所依赖的观测项；采样点由配置显式列出，使相同样本在不同运行次数下得到逐位一致的选择结果。
4. 实现链路画像变化下的自适应 MTU 与重传演进：当链路丢包率或往返时延变化触发 MTU 下调时，进行中的转发必须用新尺寸继续下发后续分片，已发送未确认分片不得改尺寸；丢包确认后按重传预算重传缺失分片，重传次数超预算须让该隧道进入可诊断失败态并返回对应业务错误码，不得把未确认分片当作已送达。
5. 实现基于注入逻辑时钟的转发轮次推进与超时语义：所有分片发送时刻、聚合窗口边界、重传退避与单轮预算判定只依据注入的逻辑时钟毫秒值，不得读取系统墙钟；超时须由真实等待计时与主动中止共同实现而非事后标注，同一逻辑时钟序列下重放必须得到逐位一致的分片发送轨迹与重组结果。
6. 实现转发状态与分片水位的持久化及强制终止后的恢复：把每隧道已提交分片水位、在途未确认分片区间、重传计数、当前 MTU、重组摘要与逻辑时钟水位以事务原子写入 SQLite；进程在分片下发或重组回报中途被强制终止后，恢复路径依据持久化状态识别已确认与半提交分片，只重传未确认分片且不得重复计入已确认载荷；强制终止后不承诺一定生成退出报告。
7. 实现多进程并发一致性与幂等重传：允许多个转发实例并行处理不同隧道，通过 SQLite 事务与文件锁保证同一隧道同一分片序号同一版本只被确认一次、在途区间不被并发超发，重复提交相同分片确认必须幂等；读取方只能看到完整已提交的分片水位而非中间态，同一隧道不得同时出现两份互相覆盖的在途区间。
8. 提供可集成组件与可重复命令行示例：以库形式暴露对端加载、分片、转发、重组校验与状态查询接口，并提供 load、tunnel、forward、resume、status、verify 子命令，status 以稳定排序 JSON 输出每隧道的 MTU、已确认分片水位、在途区间、重传计数与选定转发算法，verify 校验持久化状态与本地回显服务回报的重组摘要一致；使用固定本地样本两次运行输出完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地回环回显服务与固定样本，验证分片重组一致、规模自适应算法裁决、链路变化重传与强制终止后恢复重传不重复。
