安全团队在刚就绪的 Windows 开发环境上着手搭建一个离线 TLS 握手分析诊断工具，工作目录里还没有任何文件。输入样本全部由本地确定性脚本按固定种子生成，不依赖真实站点或外部网络：握手记录流为 JSONL，每行含连接标识、方向、记录序号、逻辑毫秒戳、记录类型与分片载荷的十六进制，载荷需按记录序号重组为若干证书消息与握手消息；证书消息给出叶子、中间与根证书的确定性构造字段（主体、签发者、序列号、有效期起止整数毫秒、公钥指纹与签名占位摘要）。另有两代信任锚快照：v1 为单文件 JSON，记录别名、指纹、相对信任秒与启用标记；v2 为分片 JSON 加 SQLite 元数据库，记录规范别名、绝对生效毫秒、信任代数、墓碑与吊销标记。引擎要在分片重组之上合并两代信任锚、构建并校验证书链、判定信任结论与吊销传播，并在并发、预算与强制终止场景下保持结论可复现。

任务环境与准备：
在 Windows 开发机安装 Python 3.11 或更高版本，使用命令 python -m venv .venv 创建虚拟环境并以 .venv\Scripts\activate 激活。
安装依赖：pip install numpy pytest；SQLite 使用 Python 标准库 sqlite3，无需额外安装。
确认工作目录为空，运行前不预置任何样本、证书或快照文件，全部由工作区自带脚本按固定种子确定性生成。
所有文件读写、锁与计时均在本地完成，不访问网络、真实账号或外部证书服务。

业务要求：
1. 实现握手记录流与两代信任锚快照的解析规范化层：校验连接标识与方向合法、记录序号在连接内单调唯一、分片载荷为偶数长度十六进制；v1 快照别名与指纹格式、v2 快照规范别名与绝对毫秒时间戳、信任代数与墓碑标记须逐条校验，非法条目输出含来源文件与记录序号的业务码并继续处理其余记录。
2. 实现同一连接内按记录序号的分片重组：处理乱序到达、重复分片、缺口与跨连接混入，重复分片按首次出现为真值并在报告中记录次数，缺口返回 E_FRAG_GAP 并给出缺失序号区间，跨连接混入返回 E_MIXUP；重组结论必须与分片到达顺序无关，且重组后的消息长度须与消息声明的长度字段一致。
3. 实现两代信任锚快照的合并与版本识别：以规范指纹为实体键合并 v1 与 v2 记录，按信任代数与绝对生效时刻裁决权威来源，墓碑标记须覆盖较早的非墓碑记录；受信集合任一增删、信任代数或吊销条目变化均视为快照整体替换并识别版本变化；两代对同一实体启用状态或生效时刻不一致时须给出冲突记录并以代数高者为权威。
4. 实现证书链构建与握手期校验：依据重组出的证书消息顺序校验签发者与主体衔接、公钥指纹在信任锚合并视图中的可信状态、有效期窗口以样本声明的观测时钟为唯一真值来源（禁用系统当前时间）；签发者断裂、根不受信、链长为零、有效期越界分别返回稳定业务码并给出出错消息序号。
5. 实现吊销与过期的沿链失效传播：依据合并视图中吊销标记与证书有效期，区分叶吊销与中间吊销并标明传播到哪些连接；当同一连接存在多条候选链时须给出候选链集合并按受信程度与代数稳定排序，传播结论须与快照导入顺序无关。
6. 实现真实资源预算与并发控制：并发度、单连接重组与校验的真实耗时上限、单连接分片数与总展开字节上限均可配置，耗时以真实墙钟测量判定而非人为延迟，超时返回 E_TIMEOUT 并终止该连接后续处理，超分片数返回 E_FRAGS、超展开字节返回 E_BUDGET；超限连接不得中断其余连接的处理。
7. 实现检查点演进与强制终止后的恢复边界：按已完成连接标识与聚合结论持久化检查点，恢复时只从最后一个完整检查点继续并校验重放结论与检查点一致以识别半写残留；检查点结构版本或合并口径版本变化时须整体重建而非增量续接；进程被强制终止后只允许恢复到最后一个完整检查点，不承诺生成退出报告。
8. 交付结构化诊断报告、确定性样本生成器与本地测试：报告为可解析 JSON，含连接级结论、分片重组状态、选中链与候选链、信任结论、业务码与出错消息序号，另输出链与信任锚依赖图数据；报告与检查点先写临时文件再重命名整体替换，同工作目录并发写须以文件锁串行化且锁冲突返回 E_LOCK；样本生成器须显式写入同步标记与期望结论摘要作为真值来源，并覆盖乱序分片、缺口、跨连接混入、两代快照冲突、墓碑覆盖、吊销传播、超时与锁冲突场景。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
