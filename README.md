多屏互动团队要在 Windows 本地工作区实现一个投屏会话诊断工作台，用于验收手机向客厅大屏、会议室副屏同时投屏时，两代投屏会话快照能否合并出同一份可重放的屏幕状态。工作区目前为空目录，全部输入由本地确定性脚本按固定种子生成，不依赖真实设备、局域网或线上服务。样本包含：投屏会话清单（会话标识、组播组、投屏协议版本 S1/S2、发送端与各接收屏的角色、屏幕几何：宽高像素与缩放比、起点逻辑毫秒）；按可注入逻辑时钟给出的帧事件流（事件序号、会话标识、接收屏标识、帧序号、采样时刻逻辑毫秒、帧载荷摘要、编码类型、是否关键帧）；两代会话快照——v1 为单文件 JSON，记录相对起始秒数、扁平接收屏状态标记与帧序号；v2 为分片 JSON 加 SQLite 元数据库，记录接收屏规范标识、绝对毫秒时间戳、会话代数、关键帧序列号、迟到容忍窗口与墓碑标记。两代快照对同一接收屏的最近关键帧与播放位置可能给出不一致结论，需要合并为统一视图并支持按帧事件重放校验。

任务环境与准备：
Windows 本地工作区，Python 3.11 及以上，安装 NumPy 与标准库 sqlite3（随 CPython 提供），执行 pip install numpy。
无需真实投屏设备、局域网或外部服务；样本与两代快照由仓库内固定种子脚本生成到本地目录。
工作日开始时目录为空，需自行创建项目结构与运行入口。

业务要求：
1. 实现样本生成器与输入解析校验：用固定种子确定性生成会话清单、帧事件流与两代快照，并校验会话标识唯一、屏幕几何为有限正数、帧序号单调、逻辑时钟毫秒为非负整数、v1 相对秒数与 v2 绝对毫秒可换算到同一时间轴，非法输入返回带 E_xxx 业务码的 JSON 错误且不产生输出。
2. 实现两代会话快照合并为统一状态视图：按元数据将 v1 相对起始秒数换算为绝对逻辑毫秒，同代同接收屏标识按会话代数取新、墓碑标记优先于无墓碑记录，两代对同一接收屏的关键帧序号或播放位置冲突时按代数与逻辑时刻裁决并逐条产出可定位来源的冲突项。
3. 实现按会话代数与迟到容忍窗口的帧采纳裁决：帧事件到达时依据其采样时刻与当前会话代数的迟到容忍窗口判定采纳、迟到丢弃或触发代数回退，代数回退须重建该接收屏自最近关键帧起的播放状态，裁决轨迹须可复现且不依赖事件到达顺序之外的任何状态。
4. 实现确定性帧重放与状态演进：按采纳裁决结果在整数逻辑毫秒上推进每个接收屏的关键帧序号、已解码帧序号与播放位置，关键帧到达时重置解码基线；同一事件流与初始快照重复重放必须得到逐接收屏逐字段相同的状态序列与相同采纳计数。
5. 实现重放裁决校验与偏差定位：把帧事件流按逻辑时刻逐条重放并与合并后的快照逐接收屏比对关键帧序号、播放位置与会话代数，发现偏差时定位首个不一致逻辑时刻、接收屏标识与字段，输出带业务码 E_REPLAY 的 JSON 报告，校验通过时同样产出含统计的报告。
6. 实现快照防篡改与版本识别：对每份快照及其分片计算内容摘要并与记录摘要比对，摘要不匹配、缺失或声明接收屏数与实际不符时判定失效并返回 E_DIGEST，合并与恢复须拒绝失效快照并回退到最近一份有效快照，禁止静默使用。
7. 实现分块级持久化与中断恢复：按逻辑时刻分块把合并视图、采纳裁决轨迹与由会话清单和事件流规范化摘要构成的版本标识原子写入状态目录，先写同目录临时文件再整体替换；可处理终止信号只在分块边界生效并写入中断标记，强制终止后仅依据已持久化且摘要有效的分块状态恢复。
8. 实现并发快照加载与帧重放的资源上限：按配置并发上限使用有界线程池并行加载与校验快照分片，同时在途的快照数据与重放缓冲总量受内存预算约束，超出预算时按接收屏标识确定顺序等待而非降低校验精度，任一分片失败时取消其余任务并返回首个错误。
