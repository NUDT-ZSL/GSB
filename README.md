主题乐园的游乐设施排队区与配套互动屏上要上线一款轻量策略小游戏，玩家扮演乐园运营者，在限定回合内为巡园角色规划补给运输与行军路线，角色需依次访问若干游乐设施完成巡检，途中使用补给站与休息区。运营策划需要先在本机得到一套可独立复核的结算内核，把设施节点拓扑、路径距离、初始补给与体力、每回合天气事件与游客流量修正系数、玩家提交的行军与补给指令序列作为输入，输出逐回合消耗明细、越界告警、各设施满意度与可回放的决策轨迹。园区里路径距离长短不一、天气与客流叠加使消耗非线性变化，手工试算难以保证多回合口径一致，也难以判断补给配置是否合理。

任务环境与准备：
在 Linux（WSL Ubuntu）下准备 Python 3 运行环境，仅使用标准库，不安装第三方包。
在工作区创建项目目录，内置确定性样本生成器与命令行入口，运行所需样本由生成器按固定种子产出。
准备本地运行说明，使拓扑配置、指令序列与推演报告能够在同一环境下重复执行并比对结果。

业务要求：
1. 解析乐园拓扑描述（设施、补给站、休息区节点，带方向或双向的连接路径及整数距离），构建图结构并计算任意两节点之间的基础行军体力消耗与补给消耗，消耗须随距离呈确定函数关系；对不可达节点要明确标记为不可达而非给出虚假数值，并支持玩家指定一条包含多个途经节点的路线时逐段汇总消耗。
2. 按回合读取天气事件与游客流量修正系数，对基础体力与补给消耗施加定点整数修正（以百分数或千分比为单位的整数因子，向下取整并写明舍入规则），输出每回合修正后的消耗值以及每条修正来自哪个天气事件或客流系数，保证同一输入重复推演结果完全一致。
3. 逐回合推演玩家的行军移动与补给分配指令，更新角色当前所在节点、体力值与补给库存；当体力不足或补给短缺导致某条指令无法执行时，须在第几回合、哪个节点报告对应告警并说明拒绝该指令的政策（跳过、截断或中止），且告警不能破坏后续回合的可继续推演。
4. 在玩家按顺序完成目标设施的访问序列后，依据到达时的剩余体力、该回合的补给结余与访问时长占比计算每个设施的游客满意度整数评分，并汇总为整体评分；未访问的目标设施要单独列出并影响整体评分的计算口径。
5. 生成最终运营效率报告，包含体力和补给的总消耗、各设施满意度、全部关键告警的列表以及按回合压缩的玩家决策轨迹摘要，报告须为确定性的可序列化结构，同一组输入多次生成结果逐字段相同。
6. 提供关卡参数（路径距离、初始补给与体力、天气事件序列、目标设施访问顺序）的配置修改入口，修改后重新推演的结果必须与对修改后参数从零全量重算的结果完全一致；同时要能指出哪些回合的消耗明细因参数变化而改变。
7. 内置确定性样本生成器，按固定种子产出小型乐园拓扑与玩家指令序列（含至少一个故意造成补给或体力越界的场景），生成器输出可复现，供在没有真实园区数据时验证结算逻辑。
8. 对拓扑与指令输入的异常形态做显式校验与报告，包括节点悬空引用、负距离、重复路径、天气事件回合越界、指令引用不存在节点等，校验失败时给出可定位的整数错误位置而不是静默修正数据。

验收：
用小型乐园拓扑与手算消耗对照逐段结算和回合推演，并验证参数修改后增量重算与全量重算的明细和评分完全一致。
