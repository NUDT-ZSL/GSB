当前仓库只完成了目录初始化和依赖声明，尚未产生任何实现或样本，首版需要落地一个面向全景分割像素掩码的主动探测与真值账本一致性诊断引擎，业务核心从交互查询转移到主动探测驱动的真值校验、跨格式语义冲突管理与延迟账本审计。全部输入由随工程交付的固定种子脚本在本地确定生成：每个探测序列含固定尺寸 RGB 图像、注入的主动探测计划（探测坐标、预期类别与实例、探测优先级）以及同一区域以 v1 身份单通道行式、v2 类别-实例双通道加置信度矩阵、COCO RLE 游程编码三种格式分别给出的真值。引擎需将三态真值解析为账本后，依据探测计划检查像素级归属、实例编号与忽略区，并输出审计账本与失效追踪。

任务环境与准备：
创建 Python 3.10 虚拟环境，安装 numpy；账本持久化使用 Python 标准库 sqlite3。
编写固定种子样本生成脚本，在本地生成 RGB 图像、三种格式的全景分割真值和主动探测计划。
准备运行配置 JSON，包含探测时间预算、冲突覆盖率阈值、格式优先级、账本版本和审计输出路径。

业务要求：
1. 实现三种真值格式的独立解析器与统一账本构建，v1 行式、v2 分片 JSON 加 SQLite 元数据、RLE 游程编码均需完成逐像素范围、通道一致性与实体编号校验，未知版本或字段缺失返回 E_FORMAT_UNSUPPORTED 或 E_FORMAT_CORRUPT，并保留原始格式的逐块校验和。
2. 实现主动探测计划的解析与优先级队列，每个探测点记录坐标、期望类别与实例、探测优先级和时间预算，重复坐标按优先级高者保留，优先级相同的探测点按计划顺序升序执行，使探测顺序完全可复现，并输出拒绝或抑制的探测点清单。
3. 实现三态真值的语义归并与代价敏感冲突裁决，对同一像素位置比较三种格式的类别、实例号与忽略区标记，以像素级可信度加权投票裁决，同权重情况下按 RLE、v2、v1 的格式优先级打破平局；冲突像素数超过主动探测计划覆盖比例时返回 E_GT_SEMANTIC_CONFLICT 并附首冲突位置。
4. 基于裁决后的账本执行主动探测：按探测点返回账本中的类别、实例号、命中的格式来源与探测状态，结果必须可由像素坐标和账本版本独立重放；在执行过程中以本地实际处理计时观测每个探测点的完成时间，并区分高速命中与需回退解析的慢速探测。
5. 维护探测账本与进度账本的原子提交、版本号与内容校验和，进度账本记录已确认探测点、候选重解析探测点与时间预算消耗，任一次提交必须整体可见；检测到版本回退、校验和失败或账本损坏时返回 E_SNAPSHOT_ROLLBACK 或 E_SNAPSHOT_CORRUPT。
6. 在探测时间预算与账本一致性之间做显式降级调控：当慢速探测占预算比例超过阈值时，未区分格式来源的探测点降级为聚合结果回传并标记降级类别，已确认的探测点不得重复计费；降级策略执行后继续下一轮探测前必须写回账本。
7. 生成可追溯的审计报告，报告每条主动探测点需包含坐标、三态真值原始字段、裁决过程与最终账本结果、探测耗时、降级标记及业务码，且内容可通过本地确定性样本与账本版本重新生成一致。
8. 实现跨模块一致性自检，校验每像素位置的三态归并结果与源格式字段互相可追踪、进度账本中的已提交探测点与审计报告逐条对应、账本与源格式校验和满足声明一致性，任何不一致返回 E_INCONSISTENT 并给出首个偏差探测点。
