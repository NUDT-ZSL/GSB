验收清单刚下发，本地 Linux（WSL Ubuntu）工作区尚为空目录，需要按照清单独立实现一个多模态协同推理自适应路由的本地诊断工作台，重点验证模态相似度门限配置在多格式版本演进下的互操作性与决策缓存的一致性。全部输入由固定种子脚本在 Linux（WSL Ubuntu）本地确定性生成，不依赖外部网络或数据集：推理请求流 JSONL 每行含 request_id、prompt_text、image_seed、text_revision、image_revision；推理配置包含模态相似度门限、路由预算、候选计划数量、调度器并发上限与精度档。系统需把路由决策建模为多级流水线，管理两代门限配置快照的增量更新与依赖失效，并确保在并行调度与故障恢复下决策结果可复现。

任务环境与准备：
安装 Python 3.10 及以上版本，使用 pip 安装 numpy；样本由固定种子脚本生成，运行在 WSL Ubuntu 本地，除标准库与 numpy 外不依赖其他外部包。

业务要求：
1. 实现 v1 单文件 JSON 与 v2 分片 JSON 加 SQLite 元数据库的模态相似度门限配置读取器，按版本头或字段集分派解析路径；未知版本返回 E_VERSION_UNSUPPORTED，字段缺失、数值不可解析或时间戳倒退返回 E_FORMAT_CORRUPT，并禁止使用缺省值掩盖元数据冲突。
2. 实现两代门限配置到统一内部表示的双向迁移，v1 升级到 v2 时补全绝对毫秒时刻、配置代数与失效墓碑并逐项记录补全来源；v2 降级到 v1 时对无法表达的增量修订号按显式丢弃规则处理并输出丢弃记录；迁移后内部表示必须逐字段一致，若表达能力不足导致语义不可还原则返回 E_SEMANTIC_LOSS。
3. 实现确定性的自适应路由决策核心，对每个推理请求按模态相似度门限执行候选路由、参数融合与分数融合，决策过程记录每一步操作数与舍入模式；同一请求、同一配置与固定种子下必须逐字节产出相同决策值、中间操作数与业务码。
4. 建立基于内容寻址的四节点缓存，缓存键纳入输入摘要、上流产物哈希、门限配置版本、路由预算与精度档；当配置代数提升、请求修订或门限参数变化时计算受影响决策集并仅重算后缀节点，复用未受影响缓存，输出重算与复用清单且两者无交集、并集覆盖全部受影响节点。
5. 实现并行调度下的资源预算裁决与决策一致性，按可配置 worker 数与请求批次分派到本地进程池，分块边界与归并顺序确定性可复现；为总浮点操作预算与驻留内存设上限，超限时按显式优先级在路由精度、调度延迟与内存之间裁决并返回结构化业务码。
6. 实现调度状态检查点与强制终止恢复，检查点携带单调递增版本号、已完成请求集合与内容校验和，仅当一批内全部请求处理成功才原子替换；重启后从最近检查点继续，已提交请求不得重算或重复写入，未提交中间决策状态必须丢弃并重建。
7. 实现并发提交控制与账本整体替换，同一时刻只允许一个配置快照或调度检查点提交生效，冲突时后到者立即返回 E_STAGE_BUSY 而不阻塞等待；检测到账本版本或校验和变化必须整体替换旧快照而非增量修补，旧版本回退尝试返回 E_SNAPSHOT_ROLLBACK。
8. 实现跨模块一致性自检与本地诊断报告，校验缓存键与产物哈希可独立复算、重算与复用集合无交集且并集覆盖全部受影响请求、恢复后业务码与全量重放一致，不一致返回 E_INCONSISTENT 并输出首个偏差请求与节点。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证路由决策、配置迁移、增量失效传播与恢复正确性。
