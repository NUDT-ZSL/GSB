本工作台从空白目录起步，面向多级健康探测状态机的诊断场景。输入全部由随工程交付的固定种子脚本本地确定性生成，不依赖真实服务、网络或账号。注册清单声明服务名与实例 ID、回环端点及长期状态世代；每个实例被划分为若干探测级别，观测流按注入逻辑时钟给出各级别的成功数、失败数与平均延迟；同时存在两代健康判定阈值快照，v1 为单文件 JSON 记录相对生效秒数与扁平阈值，v2 为分片 JSON 加 SQLite 元数据库记录绝对生效毫秒、阈值代数与失效墓碑。工作台需把两代阈值合并为统一判定视图，按可复现的级别加权规则推进实例在健康、降级、失联、隔离间的状态迁移，维护每实例的连续失败与恢复弧项，并在中断恢复后给出与一次性推进一致的状态账本。

任务环境与准备：
安装 Python 3.10 或更高版本（默认系统 Python 即可，若需虚拟环境可执行 python3 -m venv .venv 并激活）。
安装 Flask 与 SQLite 支持：pip install Flask，SQLite3 使用 Python 标准库，无需额外依赖。
准备本地固定种子样本生成脚本，可生成注册清单、多级观测流、v1/v2 阈值快照与补丁文件；所有数据仅存于本地工作目录。

业务要求：
1. 实现注册清单、多级观测流与两代阈值快照的解析校验：服务名和实例 ID 唯一，回环端点合法；每个实例声明的探测级别集合非空且各级别无重复，观测在实例内按级别序号严格递增，逻辑时钟非负，成功失败计数为非负整数，平均延迟有限；v1 阈值为非负整数数组且长度与探测级别数一致，v2 阈值分片哈希与阈值代数单调，失效墓碑合法；对任何不符合约束的输入必须返回独立业务错误码并定位到具体实例与级别。
2. 跨版本合并两代健康判定阈值，构建统一阈值视图：同一实例同一级别在 v1 与 v2 同时存在时依据快照声明的逻辑时钟与阈值代数裁决最新版本，逻辑时钟相同则按来源格式优先级裁决；合并后每条阈值须保留来源版本、原始时间表示、原始失败数数组与裁决依据，v1 相对生效秒数换算为绝对生效毫秒时记录换算标度、舍入方向与转换前原始值。
3. 在注入逻辑时钟下按级别加权规则计算每一观测窗口的健康得分：所有窗口边界与超时判定只依据注入逻辑时钟毫秒值，不读取系统墙钟；每个观测必须唯一归属一个窗口，同一逻辑时钟序列下重复运行得到逐位一致的得分；加权系数必须来自合并后的阈值视图，未迁移或已失效的阈值不得参与计算并须输出被排除的阈值代数及原因。
4. 驱动实例在健康、降级、失联、隔离四个状态间的迁移，迁移规则由健康得分与失败数阈值联合裁决：每实例都记录连续失败与恢复弧项，隔离状态不得自动解除，必须在达到恢复阈值且连续恢复逻辑时长满足要求后才回到健康；迁移只能依据已提交窗口结论与持久化状态裁决，重启后不得凭内存残留改变状态，并输出每一次迁移的触发级别、触发阈值与原始观测证据。
5. 实现强制终止后的恢复一致性，包括可处理终止与真实强制终止（如 SIGKILL）两种场景：把实例状态、连续失败与恢复计数、窗口水位、统一阈值指针、观测流已提交序号与逻辑时钟水位以事务原子写入 SQLite；进程在解析、合并或状态迁移中途被强制终止后，恢复路径依据持久化状态识别已提交的窗口与半提交观测，只重放缺失的后缀，恢复后各级别得分与状态迁移链必须与未中断的一次性执行逐项一致。
6. 实现阈值快照的增量更新与依赖失效闭包裁决：以补丁形式提交阈值修改、实例 ID 变更或失效墓碑标记，沿实例到级别的引用关系计算受影响闭包，精确标记哪些实例的缓存得分、状态迁移结论与恢复弧项必须失效重算，哪些可安全复用；未受影响的实例在后续窗口提交前不得被重新计算且其历史结论必须保持不变。
7. 实现多进程并发一致性与幂等提交：允许多个诊断实例并行处理不同服务实例的观测窗口，通过 SQLite 事务与文件锁保证同一实例同一级别同一观测序号只被提交一次、同一阈值快照版本只被整体替换一次、连续失败与恢复计数不被并发重复累加；重复提交相同窗口或相同阈值补丁必须幂等，读取方只能看到完整已提交的状态版本。
8. 提供可重复命令行接口与可验证业务错误码：支持 load、merge、probe、patch、resume、status、verify 子命令；status 以稳定排序 JSON 输出每实例当前状态、各级别最新得分、连续失败与恢复计数、当前阈值代数及逻辑时钟水位；verify 能对任意历史状态与窗口摘要进行重新计算并比对，发现不一致时返回可诊断的字段级差异。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
