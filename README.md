当前是空白工作区，需要从零实现一个本地推理服务的动态批处理调度与诊断引擎，全部在 Windows 上以确定性样本运行，不依赖外部服务、真实模型或 GPU。本地 JSON 样本给出：模型描述（层名、每层参数量、每请求输入与输出 token 数）、副本清单（副本 ID、可用算力单位、显存上限 MiB、批处理窗口逻辑毫秒、最大批大小、支持序列长度上限、每副本并发调度上限）、请求轨迹（请求序号、到达逻辑时钟毫秒、优先级、输入 token 数、最大输出 token 数、期望截止逻辑时钟）以及精度与调度配置（算力占用与延迟估算的定点标度、浮点容差、每轮总逻辑时间预算、最大并发批次数）。引擎需在可注入逻辑时钟下推进批处理窗口、在算力与显存双重预算内组装批次、维护请求生命周期与连续失败计数，并把每一轮决策与误差账本事务化落盘，使进程被强制终止后仍能续算且结果逐位可复现。

任务环境与准备：
安装 Python 3.10 及以上版本，创建虚拟环境并安装 NumPy 与 pytest，均使用本地离线 wheels 或已联网 pip 安装；不依赖 Docker、容器运行时、GPU 或外部服务。
在空白工作区建立项目目录，准备本地确定性 JSON 样本：模型描述、副本清单（含多版本用于版本替换场景）、请求轨迹与精度调度配置，样本由脚本按固定种子生成并附带内容摘要。
确认 SQLite 由 Python 标准库 sqlite3 提供并启用 WAL 模式；准备用于注入强制终止的本地测试脚本，在窗口提交与批次裁决两个阶段分别触发进程终止以验证恢复路径。

业务要求：
1. 实现模型描述、副本清单与请求轨迹的解析校验：副本 ID 唯一、每副本算力为有限正数、显存上限与最大批大小为正整数、支持序列长度上限不小于任一请求的输入输出 token 数之和、请求序号唯一、到达与截止逻辑时钟为非负整数且截止不早于到达、定点标度与容差为正；非法输入必须返回明确业务错误码且不写入任何持久化状态。
2. 实现按到达逻辑时钟推进的批处理窗口切分与请求归属：窗口边界由副本批处理窗口逻辑毫秒与注入逻辑时钟共同决定，不读取系统墙钟；每个请求必须唯一归属一个副本的一个窗口且不得同时计入两个窗口，窗口期满未满批也须按到期提交，并向请求生命周期提供归属证据。
3. 实现算力与显存双重预算下的批组成裁决：在最大批大小、副本可用算力、显存上限与批窗口到期时间约束下决定每批容纳的请求集合，优先级插队必须显式记录被跳过请求与首个触发约束；每批须输出所依赖的观测项（各请求 token 数、剩余算力与显存）与被否决请求的原因。
4. 实现批估算量的定点换算与误差谱记录：把每批的算力占用、显存占用与预计排队时长按声明定点标度换算，记录每项换算的标度、舍入方向与换算前原始浮点值，并对每次加法与乘法累计误差上界；当两个候选批次或两个副本的估算差值小于容差且批组成裁决依赖该差值时标记精度敏感。
5. 实现请求生命周期状态机与连续失败计数演进：请求在待入批、已入批、执行中、已完成、已超期之间迁移，迁移须依据已提交窗口结论与持久化状态裁决，重启后不得凭内存残留决定请求状态；已超期请求必须与执行失败区分统计，连续失败计数只在真实执行失败时递增。
6. 实现强制终止后的恢复与断点续算：把窗口水位、已提交批次清单、请求状态、算力与显存占用、误差谱与逻辑时钟水位以事务原子写入 SQLite；进程在窗口提交或批组成裁决中途被强制终止后，恢复路径须识别已提交窗口与半提交批次，只重放未完成部分且不得重复扣减算力或重复推进超期计数。
7. 实现副本规格版本整体替换与旧版本识别：副本清单每次变更产生新版本号并整体替换当前副本快照指针，需比较算力、显存与批窗口参数判定是完整替换、增量追加还是无需操作；版本回退必须被拒绝，进行中的窗口必须绑定其开始时的副本版本至结束，禁止读到新旧混合副本参数。
8. 实现多进程并发一致性与可重复命令行演示：多个调度进程并发推进同一副本时，通过 SQLite 事务与文件锁保证同一窗口同一版本只被提交一次、同一请求序号同一版本只被入批一次，重复提交相同窗口结果必须幂等；提供 save、schedule、train、resume、status、verify 子命令，status 以稳定排序 JSON 输出窗口水位、请求状态、误差谱与精度敏感标记。
