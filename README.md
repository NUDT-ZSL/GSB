代码尚未动工，工作目录目前只有一份转写数据治理需求，需要在 Linux（WSL Ubuntu） 本地从零构建一个可诊断组件。业务输入全由随工程交付的固定种子脚本确定性生成：本地 16kHz 单声道 PCM（若干语音活动段与静音段拼接，叠加可配置增益）及两代转写标注格式并存，v1 为扁平行式文本（utterance_id|start_ms|end_ms|text|confidence），v2 为分片 JSON 加 SQLite 元数据库（绝对毫秒、说话人标签、词级时序与修订号）。组件需完成转写格式互操作、跨版本合并裁决、基于语音活动边界的刷新传播，并以可集成库加完整示例交付。

任务环境与准备：
安装 Python 3.10+ 与 NumPy，使用 pip 安装依赖；提供固定种子样本生成脚本，生成本地 PCM 与 v1/v2 转写文件。

业务要求：
1. 实现固定种子驱动的 16kHz 单声道 PCM 确定性合成与帧级语音活动特征提取，按配置帧长与帧移生成短时能量、过零率及能量分位统计，复用同一帧分段逻辑支持后续转写对齐与差异归因。
2. 实现 v1 扁平行式与 v2 分片 JSON 加 SQLite 元数据库的转写读取器，两代格式均需按版本头或字段集解析，字段缺失、绝对毫秒倒退、重复 utterance_id 或 start_ms 大于 end_ms 时返回对应结构化业务码。
3. 实现 v1 到 v2 与 v2 到 v1 的双向转写迁移，迁移时对缺失字段补全默认值并记录补全来源，对 v1 无法表达的说话人标签、词级时序与修订号按显式丢弃或展平规则处理，迁移后毫秒边界必须保持不变。
4. 实现两代转写跨版本裁决，同一音频区间在 v1 与 v2 内容不一致时按 confidence 高者优先、再按修订号高者优先、再按 utterance_id 字典序裁决，并以区间重叠对为粒度输出覆盖、冲突或补充三类裁决结论。
5. 实现转写刷新传播与依赖失效，当 v2 某条 utterance 的 text 或词级时序发生修订时，只对与该条重叠或受词级时间触发影响的其他 utterance 计算失效集合，复用未受影响转写已提交结果，并保证增量刷新与整体重算逐毫秒一致。
6. 实现内置一致性检查，任一时间点最多一个 utterance 覆盖且所有 utterance 并集可还原声明转写区域，冲突或缺口时返回 E_OVERLAP 或 E_GAP；对任意毫秒点可查询当时生效的转写记录，并支持用缓存键和依赖链重放。
7. 实现转写、迁移与裁决产物的内容寻址缓存，缓存键纳入 PCM 内容哈希、转写内容摘要、格式版本、配置参数与上游产物哈希，键相同复用、键不同重算，并在配置变化时识别受影响区间做定向失效而非全量清空。
8. 实现配置与转写快照的版本化整体替换和并发提交控制，快照携带单调递增版本号与内容校验和，检测到版本或校验和变化必须整体替换旧快照，并发冲突时后到者返回 E_STAGE_BUSY 不阻塞等待。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定种子样本验证转写加载、迁移、裁决、失效传播与恢复一致性，并输出诊断报告。
