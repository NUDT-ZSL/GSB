在空白工作区从零实现一个本地容器镜像分层与构建缓存管理引擎（不依赖真实容器运行时与镜像仓库）。构建计划由本地样本给出：每个构建计划是一组有序步骤，每步声明基础层引用、文件变更动作（新增/修改/删除）、环境变量与构建参数。引擎需要把每一步物化为内容寻址的分层快照，维护步骤到层的映射缓存，支持在任意步骤中断后从持久化元数据恢复并判断哪些缓存可复用、哪些必须重建。镜像清单以 OCI 风格的 JSON 描述（layer 的 digest、size、diff 元数据），全部在本地文件系统与 SQLite 元数据中完成，输出结果需可重复演示。

任务环境与准备：
Windows 上安装 Python 3.11 或更高版本，创建虚拟环境并安装 pytest。
准备空白工作区目录，确认本地文件系统可执行原子 rename 与文件锁操作。
运行任务前无需外部服务、真实镜像仓库或容器运行时，全部样本与元数据在本地生成。

业务要求：
1. 实现内容寻址的对象存储：每个分层快照按确定性规则计算 SHA-256 digest，写入本地对象目录并原子落盘（临时文件 + rename），相同内容重复写入必须得到同一 digest 且不产生重复对象。
2. 实现构建计划解析与步骤物化：按顺序应用文件新增/修改/删除动作，生成每一层的 diff 元数据并在 OCI 风格清单 JSON 中正确记录层的 digest、size 与顺序，清单中的层顺序必须与计划顺序一致。
3. 实现步骤级构建缓存映射：以步骤内容、已解析构建参数和父层 digest 为缓存键，命中时复用已有层不再重算，未命中时重建并将新旧映射写入 SQLite；构建参数变化必须使该步骤及其全部下游缓存失效，而上游缓存保持可复用。
4. 实现中断后状态演进与恢复：构建过程在任意步骤被强制终止后，依据 SQLite 与对象目录中的持久化状态判定构建处于未完成、部分提交或已提交中的哪种阶段，恢复时只清除未提交的临时对象并继续构建，不能承诺为被强制终止的步骤生成退出报告。
5. 在恢复路径中实现引用计数与垃圾回收：对象以引用计数标识被哪些层和缓存映射引用，恢复或重建后对零引用对象执行回收，同时保证仍被任何已完成清单引用的对象绝不被删除。
6. 保证并发安全：同一计划的多实例并发构建必须通过 SQLite 事务与文件锁保证同一缓存键只有一个实例完成物化，其余实例等待或复用结果；不得出现同一 digest 对象被并发写坏或清单引用到未落盘对象。
7. 实现输入校验与异常链路：计划中出现非法路径穿越（如 .. 越界）、引用不存在的父层、循环依赖或损坏的对象 digest 时必须返回明确的业务错误码并保持元数据与对象目录处于一致可用状态，不能留下半写入记录。
8. 提供可重复的命令行交互与演示脚本：支持构建、恢复、状态查询与缓存统计子命令，状态查询以 JSON 输出每层 digest、缓存命中情况与回收数量，演示脚本使用固定本地样本产生两次运行结果完全一致的输出。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证分层 digest 一致性、参数变更缓存失效、中断恢复与并发构建，并检查错误码与垃圾回收。
