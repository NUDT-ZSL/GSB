在空白工作区从零实现一个面向文档数据库的本地片段索引存储与查询执行组件，重点解决索引快照的跨版本互操作、可复现查询执行与受控异常注入三类耦合问题。本地样本提供两代索引快照：v1 为单文件 JSON，记录文档 ID、字段值、片段偏移与一个扁平倒排表；v2 为分片 JSON 加 SQLite 元数据，记录字段级倒排、文档版本号、片段校验和与删除墓碑。查询模板为受限的文档查询子集（字段等值、范围、多字段合取与片段回取）。组件需加载并合并两代快照为统一内存索引，执行查询并回取原始片段，同时在解析、合并、查询与回取各阶段支持按本地注入清单注入受控异常，保证每次运行输出逐位一致、异常可归因、状态可从中断中恢复。全部数据与测试服务均在本地，不依赖网络、真实账号或外部存储。

任务环境与准备：
Windows 环境，安装 Python 3.11 及以上，确认 python 与 sqlite3 模块可用。
无需网络与外部服务，全部样本快照、查询模板与注入清单由任务自建并放在本地工作目录。
在空白工作区初始化项目目录，SQLite 元数据库与索引文件均落在本地路径，不依赖系统墙钟。
运行前清理本地临时目录，保证两次运行从同一初始样本状态开始。

业务要求：
1. 实现 v1 与 v2 索引快照解析器：v1 校验文档 ID 唯一性、字段值类型、片段偏移区间与扁平倒排表条目一致性；v2 读取分片 JSON 与 SQLite 元数据，校验分片内容哈希、文档版本号单调、片段校验和与墓碑标记合法性，失败时返回明确业务错误码且不写入任何索引状态。
2. 实现跨版本快照合并与统一内存索引构建：同一文档在同一字段上同时出现在 v1 与 v2 时，按快照声明的逻辑时钟与文档版本号裁决最新值，版本号相同则按来源优先级；合并后每个文档字段须保留来源版本、原始片段偏移与墓碑状态，作为后续回取、失效判定与诊断的唯一依据。
3. 实现受限查询执行：支持字段等值、范围、多字段合取与按命中回取片段，回取时校验片段校验和，校验失败须与未命中区分并映射不同业务错误码；查询结果以稳定排序 JSON 输出文档 ID、命中字段、片段内容、来源版本与回取状态。
4. 实现查询计划缓存与依赖失效判定：以查询模板、涉及字段与命中的快照版本号为缓存键，快照替换或合并产生新索引版本时精确失效受影响模板而保留其余缓存；失效决策须可追溯，输出每个被清理缓存项的触发来源与未受影响项数量。
5. 实现异常注入机制：按本地注入清单在解析、合并、查询与片段回取四个阶段注入受控异常（畸形 JSON 字段、版本号冲突、校验和不匹配、偏移越界），每种异常映射到不同业务错误码并保留可诊断字段；注入不得修改样本快照文件或破坏已提交索引状态。
6. 实现快照整体替换与版本变化识别：接收新快照包时比较清单版本号、逻辑时钟下限、分片哈希与文档摘要，判定完整替换、增量追加或无需操作；整体替换须以原子方式替换当前索引快照指针而非逐条覆盖，版本回退须被拒绝并返回业务错误码。
7. 实现持久化状态与强制终止后的恢复：把索引版本、合并裁决、注入记录与查询缓存摘要原子写入 SQLite，提交采用临时表加版本号整体替换；进程被强制终止后恢复时识别未提交的合并或替换步骤，只重放未完成步骤，不得出现索引已替换而元数据仍指向旧版本的状态。
8. 实现多进程并发一致性与可重复命令行演示：多个实例并发加载或替换同一快照时通过 SQLite 事务与文件锁保证同一版本只提交一次且重复提交幂等，读取方只能看到完整已提交版本；提供 load、merge、query、inject、replace、status、verify 子命令，固定样本下两次运行输出逐位一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
