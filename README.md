在空白工作区从零实现一个本地多集群配置分发引擎，业务目标是让同一组应用配置从全局基线经区域层覆盖后下发到多个成员集群，并在配额账本与审批门禁约束下给出可复现的下发裁决。本地样本以 JSON 与 YAML 给出三层：全局基线（应用名、镜像、副本数、资源请求、超时毫秒、开关项）、区域覆盖层（区域名、对全局键的覆盖值、是否允许该区域差异覆盖）、集群覆盖层（集群名、所属区域、对区域键的覆盖值、副本数上限、资源配额）。另提供成员集群清单（集群名、所属区域、健康标记、可接收的最大副本总量与资源总量）、下发准入规则（差异覆盖是否需审批、审批有效期逻辑毫秒、变更窗口、每轮下发并发上限与逻辑时间预算）以及可注入逻辑时钟步进表。引擎需把三层配置合并为每个集群的有效配置，检测覆盖冲突与配额溢出，生成可审计的下发裁决记录。不得依赖真实 Kubernetes 集群、kubectl 或网络。

任务环境与准备：
Windows 10/11，安装 Python 3.11 并确保 python 与 pip 在 PATH 中。
执行 pip install pyyaml 安装依赖，版本以本地 wheel 可解析为准，不访问外部服务。
在工作区根目录创建 samples/ 目录，放入自编的全局基线、区域覆盖层、集群覆盖层、成员集群清单、准入规则与可注入逻辑时钟步进表样本。
确认 SQLite 由 Python 标准库提供，无需额外安装数据库服务；命令行子命令均为本地进程调用，不监听网络端口。
运行前清空工作区内的状态目录与 SQLite 文件，使首轮加载从空白状态开始，并预置若干含越权覆盖与配额溢出的负样本用于异常验证。

业务要求：
1. 实现三层配置、集群清单与准入规则的解析校验：应用名在全局层唯一、区域覆盖层引用的区域必须存在于集群清单、集群覆盖层引用的集群必须属于其声明的区域、副本数与资源请求为正整数、覆盖开关为布尔、审批有效期与并发上限为正整数；越层引用、类型不符与非法上限须分别返回不同业务错误码且不写入任何持久化状态。
2. 实现三层合并的有效配置构建：按全局、区域、集群顺序覆盖同名键，结果逐位可复现；每个生效键须记录来源层、被覆盖的层列表与合并路径，并区分被区域差异覆盖策略明确允许的覆盖与越权覆盖，越权覆盖不得静默生效而须作为冲突候选项登记。
3. 实现覆盖冲突检测与审批门禁裁决：同一键在区域层与集群层给出不同值且策略未允许差异覆盖时判定为覆盖冲突，冲突须给出键路径、各层取值与首个越权来源；需审批的差异覆盖须匹配有效审批记录（含审批对象、逻辑时钟有效期与审批范围），审批过期或范围不匹配的覆盖必须被拒绝并返回独立业务错误码。
4. 实现每集群副本总量与资源总量的配额账本核算：合并后的有效配置须在提交前与集群配额账本比较，任一集群超出最大副本总量或资源总量即拒绝该集群的有效配置并给出首个触发约束的键与余量；账本更新与有效配置提交须在同一事务内完成，任何时刻账本不出现负余量。
5. 实现变更窗口与逻辑时钟下的下发调度：变更窗口外的下发请求须排队并记录可执行的最早逻辑时刻，窗口内下发按每轮并发上限与每轮逻辑时间预算调度；预算耗尽须放弃剩余未启动集群并记录放弃原因，严格区分预算内未启动、启动后失败与主动放弃三类结局，已启动下发不得被截断为超时。
6. 实现配置版本与账本的持久化及强制终止后的恢复：把有效配置版本指针、各集群账本、审批消费记录、下发轮次水位与逻辑时钟水位以事务原子写入 SQLite，版本提交须以临时表加版本号整体替换指针而非逐条覆盖，版本回退须被拒绝；进程在合并、配额扣减或下发中途被强制终止后，恢复路径须识别已提交与半提交步骤并只重放未完成部分。
7. 实现多进程并发一致性与幂等提交：多个引擎实例并行处理不同集群时，通过 SQLite 事务与文件锁保证同一集群同一配置版本只被提交一次、同一审批记录只被消费一次、集群账本不被并发超扣，重复提交相同下发裁决必须幂等；读取方只能看到完整已提交版本而非合并中间态。
8. 实现配置下发结果的回读对账与可重复命令行验证：下发后重新比对期望有效配置与集群回读配置，确认残留差异仅来自被显式放弃或拒绝的键；提供 load、merge、plan、apply、resume、status、verify 子命令，status 以稳定排序 JSON 输出每集群当前版本、账本余量与冲突计数，verify 输出每个残留键的判定依据链。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地三层样本验证合并裁决、冲突审批、配额账本与中断恢复后下发结论一致，附命令行运行结果。
