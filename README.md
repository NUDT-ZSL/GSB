当前是空白工作区，需要从零实现一个面向本地事务隔离与锁等待机制模拟的数据库内核组件。组件维护一张带主键与普通索引的内存表，接收并发事务脚本，每个事务包含若干读、写、范围扫描与提交/回滚操作，并发执行时按所配置的隔离级别（READ COMMITTED、REPEATABLE READ、SERIALIZABLE）施加行级与范围锁，并对冲突操作做锁等待排队。锁等待不是无限等待：每个事务在开始时可声明等待预算（毫秒），预算耗尽即进入等待预算耗尽判定并避免误判为死锁；范围锁与索引间隙锁的获取顺序由事务访问顺序与索引键序共同决定，因此并发顺序不同会导致不同的锁等待链。组件须维护事务状态机、锁表、等待队列与超时诊断，并把事务日志与锁事件持久化到 SQLite，以支持进程重启后的未完成事务回滚与锁表重建。

任务环境与准备：
安装 Python 3.11 或以上版本，创建虚拟环境并安装 pytest、httpx 用于本地接口测试（SQLite 支持由 Python 标准库 sqlite3 提供）。
确认 Windows 下可用本地回环地址与临时目录，所有 HTTP 服务仅绑定 127.0.0.1，端口由测试配置注入。
准备本地事务脚本样本目录与固定并发编排配置，所有样本与测试数据随项目生成，不依赖外网、真实数据库实例或缺失附件。
以 pytest 在项目根目录离线运行全部用例，运行前清理临时数据目录以保证可重复。

业务要求：
1. 实现事务脚本解析与执行模型：脚本由事务标识、隔离级别、等待预算与操作序列组成，操作类型须包含按主键读、按主键写、按索引键范围扫描、插入、提交与回滚。解析须校验操作引用列存在且类型匹配，非法脚本返回 E_BAD_SCRIPT 且不进入执行；同一脚本在相同并发编排下须产生确定性的操作次序记录。
2. 实现 READ COMMITTED 与 REPEATABLE READ 的可见性语义：READ COMMITTED 下每次读须看到最近已提交版本，REPEATABLE READ 下同一事务重复读同一键须返回首次读取快照中的值，且不得看到其他事务在其后提交的新值。版本链须保留提交序号与创建事务标识，回滚事务写入的版本不得进入可见链。
3. 实现行锁与索引范围锁的获取与等待队列：写操作须占用对应行锁，范围扫描按扫描区间占用间隙锁，锁之间的相容矩阵须显式定义共享锁与排他锁、行锁与间隙锁的相容关系。冲突时新请求进入该锁对象的 FIFO 等待队列，被唤醒方须重新校验相容性，不得因先到者释放而跳过仍在等待的前驱。
4. 实现 SERIALIZABLE 冲突检测与异常处理：在 SERIALIZABLE 级别下须对读写依赖做冲突图检测，检测到环时选择一个牺牲事务回滚并返回 E_SERIALIZATION_FAILURE，牺牲者选择须按等待预算剩余最少、写入量最小、事务标识字典序的固定次序裁决并记录依据；不得让两个事务同时被选为牺牲者。
5. 实现等待预算与死锁判定的区分：等待方在预算耗尽时必须返回 E_LOCK_BUDGET_EXHAUSTED 并输出其等待链与被等待事务持有的锁集合，不得简单记为死锁。真实死锁须由等待依赖图成环判定并返回 E_DEADLOCK，两者错误码与诊断字段必须区分；预算判定须基于单调时钟测量而非固定延迟模拟。
6. 实现 SQLite 持久化与重启恢复：事务状态、锁持有记录、等待队列位置、事务日志与提交序号须在事务提交点原子写入 SQLite；进程重启后须将处于运行中的事务标记为已中止并回滚其未提交版本、释放其锁并从等待队列中移除并唤醒后继。恢复后对同一脚本重放须与未中断执行在已提交结果上一致。
7. 实现并发事务调度与资源预算接口：通过本地 HTTP 提供提交事务脚本、查询事务状态与锁表快照、查询等待链诊断、取消事务的接口。调度器须在最大并发事务数与单轮推进预算约束下推进事务，超预算的事务须有序推迟且推迟时间计入其等待预算；取消事务须释放锁并唤醒等待者，取消后其后续操作返回 E_TX_ABORTED。
8. 提供本地样本与可重复测试：样本脚本须覆盖脏读禁止、不可重复读禁止、范围锁冲突、写偏斜被识别、等待预算耗尽、真实死锁、取消唤醒与重启回滚。pytest 用例须在 Windows 离线运行、使用固定并发编排与单调时钟注入，测试中断言须比对错误码、等待链结构与已提交数据快照。
