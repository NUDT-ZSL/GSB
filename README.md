在空白工作区构建一个本地确定性的视频预测与运动时序渲染诊断工作台，用于程序生成的运动时序样本上的文生视频与图生视频双路径预览。输入为一个本地样本目录：两份运动时序描述 JSONL，分别记录每个片段 ID 的逐帧几何图元运动轨迹（位置、速度、加速度、形变参数，由固定种子程序生成）与逐帧语义标签序列；一份双路径生成配置 JSON，包含受限词表与哈希词袋嵌入维度、种子、去噪步数、引导强度、帧数、分辨率档位集合（例如 64x64、128x128、256x256 三档）、图生视频替代步数、各档位噪声表与引导表路径、并发数与首帧预算毫秒；一份图生视频初始图集合（PNG，各档位尺寸）。管线需按档位逐级渲染多分辨率预览序列，并在同一片段上比较文生路径与图生路径的去噪共享段。核心难点是数据规模变化（片段数、帧数与分辨率档位可跨量级放大）与算法取舍之间的耦合：档位越高单帧去噪代价越大，而首帧响应预算、全局去噪步数预算与内存占用同时受限，必须在档位升级时机、去噪步复用范围与批量调度方式之间做可审计的取舍。

任务环境与准备：
安装 Python 3.11，并安装 NumPy 与 Pillow（pip install numpy pillow），无需 GPU 或任何在线服务。
在工作区创建 samples 目录，按题面提供的固定种子生成规则准备运动时序 JSONL、图生初始图 PNG、各档位噪声表与引导表及双路径配置 JSON，所有文件均为本地确定性样本。
确认进程具备当前工作区读写权限，渲染产物、阶段快照与清单写入工作区内独立子目录，不依赖系统临时目录之外的路径。
准备异常注入用例：通过配置参数构造缺字段、帧数不一致、噪声表长度不符、预算为零等输入，验证业务码与失败清单，不修改任何被测源码。

业务要求：
1. 实现运动时序样本与双路径配置加载层：解析两份运动时序 JSONL 与配置 JSON，校验片段 ID 唯一、逐帧轨迹与语义标签帧数一致、分辨率档位集合单调递增且每档噪声表与引导表长度等于去噪步数、种子与引导强度取值合法；不合法时分别输出 E_TIMESERIES_INVALID、E_CONFIG_INVALID 并进入失败清单，失败样例不得阻断其余合法片段进入渲染。
2. 实现提示词编码与潜变量初始化阶段：按受限词表做哈希词袋嵌入并归一化，以配置种子与片段 ID 派生固定随机源生成各档位初始潜变量；文生路径以提示词嵌入初始化，图生路径以初始图编码潜变量初始化；两条路径的初始化产物须带内容指纹与依赖清单，同一输入与配置下重复运行必须逐元素一致。
3. 实现图生视频替代步与共享去噪判定：图生路径以配置替代步数覆盖前若干去噪步，替代步之后文生与图生路径必须共享同一去噪计算与噪声引导语义；工作台须显式输出两条路径的共享段与分歧段清单，并验证共享段内两条路径的中间潜变量逐元素相同，分歧段内必须不同，否则记录 E_PATH_DIVERGENCE 业务码。
4. 实现档位自适应选择器与去噪步预算调度：依据片段数、帧数、当前档位单帧代价估计与配置的全局去噪步预算、内存占用上限，从预置策略表选择本批次要渲染的档位、每片段去噪步数与批量调度方式（逐帧串行、帧维批量、跨片段合并），输出含参考规模指标、候选策略评分与选择理由的决策记录；预算不足时对未渲染档位输出 E_DENOISE_BUDGET_PENDING 并保留可继续的中间状态，不得静默丢弃。
5. 实现首帧预览预算与增量档位升级：交互请求触达后先在配置的首帧预算内以最低档位产出可用的首帧预览与进度摘要，预算内得不到时返回带 E_PREVIEW_BUDGET_PENDING 业务码的中间状态而非阻塞；档位升级只能复用低档位已验证的潜变量与去噪结果，已复用的步不得重新计算，升级后的高分辨率帧必须由真实上采样与后续去噪得到，不得直接缩放低档位终帧冒充。
6. 保证增量渲染与全量渲染在多档位下逐帧一致：从任意初始状态执行包含提示词、种子、步数、引导强度、帧数、初始图、档位集合收窄或扩张与局部潜变量补丁的编辑序列，每次编辑后增量运行得到的各档位最终像素帧、中间潜变量与档位复用清单，必须与从空白工作区按相同最终输入与配置一次性全量运行的结果逐像素一致。
7. 实现阶段快照整体替换与强制终止后的恢复判定：将初始化、逐去噪步、档位升级、解码划分为阶段，各阶段产物以临时文件加原子替换方式持久化，清单文件记录全局版本号、配置哈希、档位集合指纹、已完成片段与步序游标；读取时以清单版本号与配置哈希判定命中或失效，识别档位集合变化；收到可处理的退出信号时完成当前阶段产物与清单替换后以整数退出码 0 退出，强制终止后仅依据已完整替换的产物恢复且不得承诺生成退出报告。
8. 实现并发渲染与串行结果一致性、异常隔离与诊断报告：使用线程池并发执行去噪步与逐帧解码，最大并发数取自配置，每个任务携带由片段 ID、档位、步序号与帧序号派生的稳定排序键，无论线程调度顺序与并发度如何，最终帧顺序、中间潜变量清单顺序、档位复用清单与失败清单顺序必须与单线程按相同稳定顺序执行一致；单阶段异常时记录片段、档位、步序或帧序与异常类型并继续；每次完整运行生成 JSON 报告，含各档位帧数与最大通道差、共享段判定、预算消耗、决策记录、快照版本号与失败清单。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证双路径多档位渲染、预算与档位取舍、增量与全量逐像素一致及异常恢复，输出诊断报告。
