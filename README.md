当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向多模态图文协同推理的本地数据处理管线与结果验证工具。业务对象是本地确定性生成的图文对样本：每张图由固定种子生成固定尺寸 RGB 像素数组，文本描述由受控词表拼装，样本清单为 JSONL，字段含 pair_id、image_seed、image_shape、text_tokens、modality_mask、stage_hint、priority。推理被建模为四阶段协同流水：图像编码（分块均值与固定权重投影得图像嵌入）→文本编码（词频加权池化得文本嵌入）→融合（按 modality_mask 选择拼接或加权门控）→评分（相似度与偏置得最终分数）。长批量运行时需要支持按对分块并行、可配置的资源预算准入、阶段快照提交与强制终止后的恢复；同一 pair_id 与同一 image_seed 必须产出逐字节一致的中间嵌入与分数。

任务环境与准备：
确认 Windows 上已安装 Python 3.10 及以上，并可用 pip 安装 NumPy 与 psutil。
准备本地工作目录作为持久化快照与结果输出路径，无需任何真实账号、外部服务或网络访问。
用固定种子生成本地确定性图文对样本清单与像素数组，作为演示与验证输入。
提供触发强制终止与注入损坏快照的本地方式，仅用于验证恢复与业务码处理。

业务要求：
1. 实现图像编码、文本编码、融合、评分四个阶段的协同推理流水线，各阶段输入输出语义明确；同一 pair_id 与同一 image_seed 在相同配置下必须产出逐字节一致的中间嵌入与最终分数，禁止依赖除固定种子与显式配置外的任何外部状态。
2. 实现各阶段的可持久化阶段快照，快照携带单调递增版本号、已完成 pair 集合与内容校验和，只有该阶段全部 pair 处理完成才提交；提交记录须原子可见，部分完成的阶段不得提交为已完成状态。
3. 实现强制终止后的恢复逻辑：重启时读取最后一次已提交快照，从下一阶段继续推进，已提交阶段的 pair 不得重算或重复计入；未提交的中间嵌入必须丢弃并从该阶段起点重建，恢复后的完整结果须与不间断完整运行逐字节一致。
4. 实现快照版本变化与整体替换：检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明阶段名与版本号，禁止使用部分可解析的损坏数据。
5. 实现按对分块的并行调度与资源预算准入：按可配置的 worker 数与每批 pair 数把 pair 分组分派到本地进程池，分块边界与归并顺序必须确定性可复现；为驻留嵌入内存、单阶段 pair 数与并行任务数设可配置上限，超限时返回 E_RESOURCE_LIMIT 或按明确策略降批并标记降级类别。
6. 实现预算冲突的显式裁决规则：当并行度提高缩短整体耗时但放大驻留内存、批大小扩大减少归并开销但逼近 pair 数上限、并行任务数增加分摊内存但逼近槽位上限时，须按声明的优先级顺序在进度、内存与并行度之间裁决，并在调度报告中记录裁决依据、所选路径与降级来源；同一观测下裁决结果必须可复现。
7. 实现结构化异常回传与异常链路归因：worker 内异常须以业务码与阶段名回传主进程并归因到具体 pair_id，单个 pair 失败不得静默丢弃；重复 pair_id、modality_mask 取值非法、image_seed 与 image_shape 不匹配、text_tokens 为空分别返回 E_DUP_PAIR、E_MASK_INVALID、E_SEED_SHAPE、E_TEXT_EMPTY。
8. 实现跨阶段一致性自检与结果验证工具：校验四阶段处理的 pair_id 集合完全一致、融合阶段每条 pair 恰被计分一次、重算集合与复用集合无交集且并集覆盖全部受影响 pair；检测到不一致返回 E_INCONSISTENT 并指出类别与版本号，验证工具须能独立复核快照内容与恢复结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证四阶段推理可复现、中断后恢复与完整运行一致、预算超限与快照损坏按业务码处理。
