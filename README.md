在空白工作区构建一个面向本地确定性样本的多路召回与融合排序实验工作台，用于诊断数据规模变化下的召回通道选择与融合算法取舍。输入为一个本地样本目录：用户与物品的交互日志 JSONL（每行含用户 ID、物品 ID、时间戳与交互类型，由固定种子程序生成，含冷启动用户、长尾物品与周期性热度），一份物品词典 JSONL（每行含物品 ID 与标题词项列表，用于词面召回），一份召回配置 JSON（词面召回通道、协同过滤通道、热度通道的开关与权重，各通道候选数上限，融合策略选项，排序特征权重，评估抽样比例，并发数，快照提交间隔），以及一份多档数据规模描述（用户数、物品数与交互数可从配置放大到若干档）。工作台需完成交互解析与统计、多路召回候选生成、融合打分与排序、离线评估，并在规模档切换与配置编辑后只重算受影响的部分，输出可复现的对比报告。

任务环境与准备：
Windows 上安装 Python 3.11 与 NumPy（pip install numpy），无其他外部依赖与网络访问。
在工作区创建 samples 目录，放入题目要求的交互日志 JSONL、物品词典 JSONL、召回配置与多档规模描述样本，随机源均由配置中的固定种子派生。
准备可写的结果目录用于阶段快照与报告输出，并确认进程能以整数退出码结束以观察退出语义。

业务要求：
1. 实现交互日志与物品词典解析统计层：读取交互 JSONL 与物品词典 JSONL，校验用户 ID 与物品 ID 非空、时间戳可解析、交互类型在配置枚举内、词典词项非空，统计每用户交互数、每物品交互数与全局时间跨度；非法行、重复行、时间戳乱序、词典缺失物品分别输出 E_LOG_INVALID、E_LOG_DUPLICATE、E_LOG_ORDER、E_ITEM_MISSING 业务码并进入失败清单，合法后构建确定性的用户物品交互索引与物品词项索引。
2. 实现多路召回通道：词面通道按物品标题词项与用户历史词项的重合度召回，协同过滤通道按物品共现余弦相似度召回，热度通道按时间衰减后的交互热度召回；每通道候选数受配置上限约束，同分时按物品 ID 字典序排序，通道关闭或数据不足时输出空候选并记录跳过原因，全程禁止随机打散。
3. 实现融合打分与排序器：支持分数归一化后加权融合与倒数排名融合两种策略，按配置特征权重对候选计算最终得分；当某通道候选数为零时其权重按配置规则重分配并记录重分配明细；最终排序同分时按融合前各通道名次向量字典序决断，输出候选、各通道贡献与最终名次。
4. 实现规模自适应策略选择器：依据用户数、物品数、交互密度与冷启动用户比例，从预置策略表中选择启用的召回通道组合、各通道候选数上限与融合策略，输出可审计决策记录，包含所参考的规模指标、候选策略评分与最终选择理由；同一规模描述必须得到相同决策。
5. 实现增量复用与失效判定：为召回通道产物、归一化统计量、融合结果与评估指标分别计算由上游内容指纹与参数指纹派生的缓存键；当规模档切换、通道开关或权重、融合策略、排序权重变更时，仅使受影响部分及其下游失效并纳入重算集合，未失效部分必须直接复用且不得重复计算，复用与重算清单须在报告中列出。
6. 保证增量运行与全量重建的结果一致性：从任意初始状态执行包含规模档切换、通道开关、权重调整与融合策略切换的编辑序列，每次增量运行得到的最终推荐列表、各通道贡献分解、决策记录与评估指标，必须与从空白工作区按相同最终输入与配置一次性全量运行的结果逐字段一致。
7. 实现并发评估与串行结果一致性：使用线程池并发执行各规模档或各通道的评估与统计计算，最大并发数取自配置，每个候选任务携带由规模档标识与通道名派生的稳定排序键；无论线程完成顺序如何，最终指标表顺序、候选列表顺序、失败清单顺序与报告内容必须与单线程按稳定键顺序执行完全一致。
8. 实现阶段快照、恢复与异常链路：召回、融合、评估各阶段以临时文件加原子替换方式持久化快照，快照含阶段名、配置哈希、规模档标识、已处理用户游标、产物摘要与版本号，恢复时若配置哈希或规模档不符输出 E_CONFIG_MISMATCH 并拒绝恢复；单用户在任一阶段抛异常时记录用户 ID、阶段名、业务码与异常类型并继续其余用户；收到可处理的退出信号时完成当前阶段快照后以整数退出码 0 退出，强制终止后仅依据已完整替换的快照恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地多档规模样本验证召回融合结果、增量与全量一致性及异常业务码，附运行报告。
