项目从零开始，需要构建一个面向客服对话文本的情感与风险判定本地应用，核心业务问题是判定配置与风险词表在版本演进下的格式互操作，以及会话级判定结果的增量失效追溯。业务对象是本地确定性生成的对话样本：每段会话由固定种子拼装若干条消息（JSONL，字段含 conv_id、msg_no、speaker、text、locale、annotator_group），并配三套并存的判定配置书写形式：v1 为无字段名的竖线分列行式（情感类别|风险类别|门限三段，无精度声明），v2 为带字段名的行式配置（含情感权重、风险类别集合、风险词表与门限），v3 为结构化嵌套 JSON（额外含否定词表、程度副词表、精度档与衰减系数）。判定链路为：文本归一化→消息级情感打分与风险词命中→会话级加权聚合与风险分级→判定快照提交。需要保证同一语义配置在 v1、v2、v3 三种形式下经加载与迁移后产出相同判定结果，当 v1 表达能力不足时显式返回 E_SEMANTIC_DRIFT；同时配置版本或风险词表变化时须定向重算受影响会话并拒绝过期结果。

任务环境与准备：
安装 Python 3.11 或以上版本，并执行 pip install numpy==1.26.4 以提供确定性数组运算。
创建新工作区目录，在其中准备本地确定性样本：对话会话 JSONL、v1/v2/v3 三套判定配置文件、否定词表与程度副词表；样本与配置均由固定种子脚本一次生成并写入磁盘，不依赖任何外部账号或网络资源。
确认运行环境为 Windows，本地持久化目录可读写，用于写入内容寻址缓存、判定快照与追溯记录。
在命令行中通过 python 入口运行应用，触发一次跨版本裁决、一次增量修改后的失效传播与一次过期结果拒绝演示。

业务要求：
1. 实现 v1、v2、v3 三种判定配置的读取器，按版本头或字段集分派解析路径：未知版本返回 E_VERSION_UNSUPPORTED，竖线字段数不符、键名缺失、必填字段缺失或门限不可解析返回 E_FORMAT_CORRUPT；读取产物须保留来源版本与原始行定位，同一配置文件重读得到逐字节一致的解析结果。
2. 实现 v1 到 v2、v2 到 v3 的升级迁移器与 v3 到 v1 的降级迁移器：升级时补全缺失的否定词表、程度副词表、精度档与衰减系数并逐项记录补全来源；降级到 v1 时对 v1 无法表达的否定词表、程度副词表、精度档与衰减系数按显式声明的丢弃或展平规则处理并输出丢弃明细；任一步迁移不得静默篡改已有字段值，迁移产物须记录来源版本与目标版本。
3. 实现确定性的文本归一化与消息级情感打分：依据随附否定词表与程度副词表对归一化文本做加权情感分数，三分类取最高分且同分按固定类别顺序裁决，同分消息按 msg_no 升序打破平局；同一会话、同一配置与固定种子下必须逐字节产出相同归一化文本、逐消息分数与类别，且逐消息分数可由归一化文本与词表独立重算一致。
4. 实现风险词级命中、上下文合并与会话级聚合分级：按受控风险类别集合与风险词表输出每条消息的命中类别、命中码点区间与合并后的风险候选，无命中时形成空命中，区间越界返回 E_SPAN_OUT_OF_RANGE；再按消息权重与 v3 声明的衰减系数把情感分数与风险候选聚合成会话级分数与风险分级，聚合口径显式声明，分级越出受控风险等级集合返回 E_LEVEL_INVALID，且聚合结果可由逐消息明细与权重独立重算一致。
5. 实现跨版本判定结果裁决：同一会话在 v1、v2、v3 三种书写形式经加载与迁移后必须产出相同消息级类别、相同风险命中区间与相同会话级分级；当因 v1 表达能力不足导致语义不可完全还原时返回 E_SEMANTIC_DRIFT 并指出首个差异会话、消息与字段；裁决须覆盖否定词与程度副词缺省时的等价路径，并记录各形式所用迁移补全项。
6. 实现判定快照的内容寻址缓存与增量失效传播：每条消息的归一化文本、情感分数与风险命中，以及会话级聚合结果各以内容哈希落盘，缓存键须纳入会话内容哈希、风险词表与情感权重版本、否定词表版本与门限；修改某会话消息、增加风险词条或调整门限时计算受影响消息与会话集合，复用未受影响上游产物仅重算受影响后缀，并输出本次重算会话与消息集合及复用集合，局部修改后的最终判定须与全量重算逐字节一致。
7. 实现判定结果追溯与过期结果拒绝：任一会话级判定须记录所用缓存键、配置版本与节点路径，可按该记录重放出相同会话级分数、分级与命中明细；当缓存键所依赖的任一版本已变化而结果仍来自旧键时返回 E_STALE_RESULT 并指出 conv_id 与来源版本；追溯记录缺失或重放结果不符返回 E_LINEAGE_BROKEN。
8. 实现判定快照与配置的版本化整体替换及并发提交控制：会话级判定结果、风险词表与情感权重配置各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT；同一时刻只允许一个判定快照提交生效，并发提交冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
