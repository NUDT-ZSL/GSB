在空白工作区从零实现一个本地事务隔离与锁等待诊断工作台，用于在确定性样本数据库上复现多事务并发下的隔离级别行为、锁等待与资源预算调度。样本以本地 SQLite 数据库给出：表结构与数据、预置并发事务脚本（每个事务由有序操作组成，操作包含读、写、范围扫描、行锁与表锁声明、重试声明），以及调度配置（隔离级别、每事务锁等待预算毫秒、全局并发事务上限、检测周期与容差参数）。工作台需以多个本地工作进程并行执行事务脚本，通过 SQLite 事务结合自建锁表实现共享锁与排他锁、锁等待队列、等待超时与死锁检测，并在每事务锁预算与全局并发上限双重约束下决定事务启动、等待与放弃策略。所有时间判定基于可注入的逻辑时钟，进程内由调度器按固定步长显式推进，不读取系统墙钟，保证同一脚本两次运行产生逐位一致的调度记录与诊断报告。诊断报告以 JSON 输出每个事务的隔离级别、加锁序列、等待时长、放弃原因、冲突对象与死锁环。

任务环境与准备：
安装 Python 3.11 或以上，并确认标准库 sqlite3、multiprocessing 可用；文件锁可用标准库 sqlite3 事务配合本地锁文件实现，不需要联网安装额外包。
在空白工作区创建项目目录，准备本地 SQLite 样本库与事务脚本、调度配置 JSON，样本数据固定且不依赖外部服务。
确认 Windows 上多进程启动方式为 spawn，测试脚本以模块入口编写并置于 if __name__ == '__main__' 保护下，避免依赖 fork 语义。
准备可重复演示脚本入口，固定逻辑时钟推进步长序列与随机种子，确保两次运行输出可逐位比对。

业务要求：
1. 实现并发脚本与调度配置的解析校验：读取本地事务脚本与调度配置，校验操作序列合法性、隔离级别枚举、锁等待预算与并发上限范围、重试次数上限，构建每个事务的可执行操作描述；非法脚本或配置必须返回明确业务错误码并保持样本库与元数据不变。
2. 实现共享锁与排他锁的锁表与等待队列：以 SQLite 锁表持久化每行每表的持有者、锁模式与等待顺序，读操作获取共享锁、写操作获取排他锁，范围扫描需按范围段登记；锁申请冲突时进入先进先出等待队列，等待顺序必须与调度记录一致，释放锁时按队列顺序唤醒而非依赖进程调度时序。
3. 实现锁等待预算与全局并发上限的并行调度：在每事务锁等待预算毫秒与全局并发事务上限双重约束下决定事务启动与等待放弃，预算耗尽必须给出放弃原因并释放已持有锁；区分预算内未启动、启动后等待超时放弃与主动回滚三类结局，已放弃事务不得在后续轮次被错误复启。
4. 实现死锁检测与解除：按检测周期遍历锁表等待图识别环路，输出完整死锁环并选择确定性牺牲事务回滚，其余事务应能继续推进；检测必须在逻辑时钟推进下可重复，不得依赖进程实际耗时，解除后等待队列顺序与锁归属必须保持一致。
5. 实现隔离级别语义模拟与冲突诊断：按脚本声明的隔离级别裁决脏读、不可重复读与幻读的可见性，输出每个事务读到的行版本与判定依据；当隔离级别声明的行为与实际锁保护不足以阻止异常读时，必须在诊断报告中标记为隔离缺口并给出冲突对象与来源事务。
6. 实现逻辑时钟注入与时间精度一致：锁等待时长、检测周期与重试退避全部基于可注入的逻辑时钟推进，不得读取系统墙钟；同一逻辑时钟序列下重放必须得到逐位一致的调度记录，逻辑时钟回拨超过容差时返回业务错误码并保持锁表状态不变。
7. 实现持久化状态与强制终止后的恢复：把事务阶段、锁持有与等待队列、死锁牺牲决策、等待预算消耗与调度摘要原子写入 SQLite；进程被强制终止后依据持久化状态识别未提交轮次与半写入锁记录，只清理未提交记录并重建等待队列，不得承诺为失控进程补写退出报告，恢复后重建的队列须与最近一次已提交调度摘要一致。
8. 实现多进程并发一致性与异常链路：多个调度进程并行使同一事务同一操作只被提交一次，通过 SQLite 事务与文件锁保证锁表与调度记录不被并发写坏，重复提交相同结果幂等；连接失败、脚本引用不存在表、锁记录被损坏、等待队列版本不一致分别映射到不同业务错误码，单个事务异常不得中断其他事务或污染已提交调度记录。
