当前是空白工作区，没有现存项目、代码或数据附件。需要从零构建一个面向摘要与改写任务的本地数据处理管线与结果验证工具，核心业务问题是数值精度与误差传播。业务对象是本地确定性生成的长文本与参考摘要样本：原文由固定种子从受控词表拼装成句序列（JSONL，字段含 doc_id、sent_no、text、char_len、ref_summary_units），另有一份改写配置，声明抽取式摘要打分权重（位置、长度、词频、覆盖度）、句子压缩比、改写温度与平滑系数、数值精度档（float64、float32 与定点缩放整数，其中定点档带缩放因子与舍入模式）、聚合门限与输出精度。管线被建模为多级流水：句子切分与词频统计→句子打分与区间估计→摘要单元选择（按分数与预算选句）→改写得分归一化与文本产出→摘要级质量评估（覆盖度与压缩率）。核心矛盾是：句子打分经词频归一化、平滑与权重加权后传给选择阶段，选择结果又决定改写阶段的归一化分母，任一阶段的对数域缩放、定点截断、平局打破与门限比较策略都会沿链路放大，使摘要集合、改写得分与最终质量指标在精度档切换或重复运行时发生漂移。任务需要给出逐级误差谱、主导来源归因与可复现验证，而不只是给出一个摘要结果。

任务环境与准备：
安装 Python 3.10 及以上版本，并确认 numpy 与 pytest 可导入；版本以本地已安装为准，不依赖外网下载。
在空白工作区创建项目目录与虚拟环境，样本用固定种子在本地生成，不引用任何外部语料或在线服务。
确认可在 Windows 命令行运行 pytest 与项目入口脚本，并预留本地缓存与快照目录的读写权限。

业务要求：
1. 实现确定性的句子切分、词频统计与句子打分阶段：按受控词表统计词频，对每个句子按位置、长度、词频与覆盖度四个分项加权得到基础分数，同分时按 sent_no 升序打破平局；同一 doc_id、同一配置与同一精度档下必须逐字节产出相同的分项分数、总分与选中句子序列，禁止依赖系统时间、字典遍历顺序或任何未声明外部状态。
2. 实现可切换的精度档执行层：float64、float32 与定点缩放整数三档共用同一算子语义，定点档的缩放因子与舍入模式由配置显式给出；同一输入在不同精度档下结果的差异必须只来自精度损失本身，切换精度档不得改变小样精度下应完全一致的样本结果，且每档须输出档位标识与生效的缩放因子、舍入模式记录。
3. 实现改写得分归一化阶段与摘要单元选择阶段的耦合：选择阶段按分数与长度预算选出摘要单元集合，改写阶段对选中单元得分做归一化并施加温度与平滑处理；须显式记录归一化分母的来源与选择阶段所用预算，当预算导致选中集合为空时返回 E_EMPTY_SELECTION 并保留各句分项分数供归因，禁止在无选中集合时静默产出空摘要。
4. 实现逐级误差传播计算与主导来源归因：以 float64 档作为该快照内的参考真值，输出词频归一化、加权求和、平滑处理、定点量化、选择门限比较与改写归一化各级的绝对偏差、相对偏差、误差区间与误差放大比，并定位主导误差来源为哪一级；归因结果须可追溯至逐句分项偏差明细，并给出误差放大比的计算口径。
5. 实现门限判决与摘要单元选择的数值稳定性保护：对句子入选门限与改写得分门限提供严格比较与容差带比较两种策略及次正规数保护，保证恰好落在门限附近的句子的判定在重复运行与多精度档下不被舍入翻转；门限策略变更必须在诊断报告中标记并给出受影响的句子数与方向。
6. 实现由输入或参数触发的错误注入与异常链路归因：权重不为正、平滑系数越界、精度档未知、缩放因子非正、重复 doc_id、text 为空、ref_summary_units 缺字段等分别返回结构化业务码并指明 doc_id 与阶段名；样本级异常不得中断整批处理，须汇总为异常清单，未被任何阶段归因的异常须显式登记。
7. 实现配置与统计量快照的版本化管理及整体替换：打分权重、平滑与门限配置、各精度档的误差谱统计各携带单调递增版本号与内容校验和，加载时检测到版本号或校验和变化必须整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT。
8. 实现跨级一致性自检与结果验证工具：校验各级处理的 doc_id 集合完全一致、误差区间顺序合法、定点档偏差可由缩放因子与舍入模式重算出、选中句子集合与分项分数可核对、质量指标可由逐句明细独立重算一致；检测到不一致返回 E_INCONSISTENT 并指出不一致类别与 doc_id，验证工具须能复跑两次并比对完整输出哈希一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
