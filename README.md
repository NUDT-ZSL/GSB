在空白工作区从零实现一个本地故障隔离与容灾切换的并行裁决组件，用于在确定性样本上复现故障域划分、隔离动作并行下发与资源预算约束下的恢复切换决策。本地 JSON 样本给出：服务拓扑清单（服务名、实例 ID、所属故障域、依赖边、优先级、健康基线阈值）、故障事件流（事件序号、服务名或实例 ID、故障类型、注入逻辑时钟毫秒戳、影响半径估计）、隔离与恢复策略配置（每轮隔离动作总时间预算毫秒、每故障域并发隔离上限、隔离动作重试预算、恢复切流的流量比例阶梯、连续失败次数阈值、容差参数与逻辑时钟步进）。隔离动作的落点由本地回环地址上的可编程 HTTP 控制面测试服务模拟，可按路径返回成功、拒绝、慢响应与畸形响应；该服务由本任务自带的 Python 脚本在本机启动，仅监听回环地址。组件需按故障事件流在可注入逻辑时钟下并行下发隔离动作，在总预算与并发上限双重约束下裁决启动与放弃，维护每个实例的隔离阶段与连续失败计数，并在故障域整体不可用时推演容灾切换与恢复阶梯。

任务环境与准备：
确认 Windows 上可用 Python 3.10 及以上版本，并安装 NumPy 与标准库 SQLite3，无需容器
在工作区创建 samples 目录，准备拓扑、故障事件流、隔离与恢复策略配置的本地 JSON 样本文件
实现本地可编程 HTTP 控制面测试服务，由 Python 脚本启动并仅监听回环地址，可按路径返回成功、拒绝、慢响应与畸形响应以支撑隔离动作下发
准备可注入逻辑时钟的驱动入口与 SQLite 数据库文件路径，确保多次运行使用相同样本与时钟序列可复现输出

业务要求：
1. 实现拓扑、故障事件流与策略配置的解析校验：校验服务名与实例 ID 唯一、依赖边两端闭合、故障域标签非空、事件序号严格递增、逻辑时钟毫秒戳非负、故障类型枚举合法、预算与并发上限为正整数、流量比例阶梯单调，构建服务到实例与故障域的映射及依赖有向图并检测环，非法输入必须返回明确业务错误码且不写入任何持久化状态。
2. 实现基于可注入逻辑时钟的并行隔离调度器：同一轮次内按故障域分组并发下发隔离动作，同时受每轮总时间预算与每故障域并发上限双重约束；预算耗尽必须放弃剩余未启动动作并记录放弃原因，且区分预算内未启动、启动后等待超时与主动放弃三类结局，已启动动作不得被简单截断为超时，同一逻辑时钟序列下重放必须得到逐位一致的调度记录。
3. 实现实例隔离阶段状态机与连续失败计数演进：隔离成功、单次失败、连续失败超阈、健康检查恢复分别驱动实例在正常、观察、隔离中、已隔离、恢复中之间迁移，迁移必须依据本轮完整下发结果与持久化状态裁决，重启后不得凭内存残留决定阶段；隔离动作按重试预算重试，超预算进入明确失败态并可查询。
4. 实现隔离效果与故障传播的合并裁决：当故障事件影响半径覆盖同一依赖链上的多个实例时，需先计算受影响的故障域闭包再决定隔离粒度，避免对同一故障域重复下发互相覆盖的动作；裁决必须输出每个被隔离实例的触发来源事件、所属故障域与隔离粒度依据，未受影响的故障域实例不得被重算或改变原有阶段。
5. 实现容灾切换与恢复阶梯推演：当某故障域整体不可用时按依赖拓扑把流量切换到备用域，恢复时按配置的流量比例阶梯逐步回切，每一步回切须校验目标域健康结论与持久化状态，回切中途失败必须停留在上一稳定阶梯并记录证据；推演不得依赖系统墙钟，且必须说明切换结论所依据的观测与逻辑时钟。
6. 实现强制终止后的恢复与半完成隔离清理：把实例隔离阶段、连续失败计数、故障域不可用判定、已下发动作与确认状态、切换阶梯与逻辑时钟水位以事务原子写入 SQLite；进程在隔离下发或回切任一阶段被强制终止后，恢复路径依据持久化状态识别已提交与未确认动作及半完成切换，只重试未确认部分，强制终止后的恢复不得承诺生成完整退出报告。
7. 实现多进程并发一致性与幂等提交：允许多个裁决实例并行处理不同故障域，通过 SQLite 事务与文件锁保证同一实例同一轮次同一隔离动作版本只被一个进程确认、同一故障域不可用判定只被提交一次，重复提交相同下发结果或切换结论必须幂等；读取方只能看到完整已提交轮次状态，不得观察到下发中间态或半覆盖的隔离视图。
8. 实现隔离执行期异常链路与业务错误码：控制面连接拒绝、响应超出单动作超时、响应状态码不符合期望、响应回显的隔离版本与期望不符、目标返回畸形响应、样本摘要不匹配分别映射到不同业务错误码并在结果中保留可诊断字段；单个实例或故障域异常不得污染同轮其他故障域结果、中断调度主循环或留下半写入的隔离与切换记录。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地测试控制面验证并行隔离裁决、预算放弃、容灾切换阶梯与强制终止后的幂等恢复一致性。
