当前只有一台干净的开发机，需要从零实现一个本地流式查询执行引擎的连接算子运行时重优化组件。与在编译期一次性枚举连接顺序不同，本场景中三张表以列式批次持续到达，连接管线按初始查询计划逐批执行；真实基数与键分布会偏离初始统计快照，组件须依据已提交批次的实测观测判定代价模型漂移，并在漂移超阈时对流式连接管线做出可复现的重优化裁决。本地 JSON 样本给出：表描述（表名、行数、每列 NDV、列宽字节、连接键语义、是否带倾斜键）、初始查询计划（连接顺序、每步算法、初始选择率与代价估计）、批次到达剧本（批次序号、各表本批行数、到达逻辑时钟毫秒）、重优化配置（漂移阈值、冷却逻辑毫秒、切换代价预算、观测窗口批次数、定点标度、浮点容差、逻辑时钟步进）以及注入清单路径。批次数据由确定性生成器按表描述与种子产出，不依赖外部数据源。

任务环境与准备：
安装 Python 3.10 或更高版本，在干净虚拟环境执行 pip install numpy 与 pip install pytest。
SQLite 使用 Python 标准库 sqlite3，确认模块可用；本地文件系统需支持临时文件加原子重命名。
在空工作区创建项目目录，准备本地 JSON 样本：表描述、初始查询计划、批次到达剧本、重优化配置与注入清单各一份。
测试数据全部由样本与种子生成，不访问网络或外部数据源；用 pytest 运行本地确定性测试。

业务要求：
1. 实现表描述、初始查询计划与批次到达剧本的解析校验：表名唯一、行数与 NDV 关系合法、列宽为正整数、连接谓词两端列存在且类型可比、批次序号严格递增且各表行数为非负整数、到达逻辑时钟为非负整数、计划中每步算法在声明枚举内；非法输入必须返回明确业务错误码且不写入任何持久化状态。
2. 实现确定性流式批次数据生成：依据表描述、全局种子与批次序号逐批产出列式数组，倾斜键按声明比例集中分布，相同种子与描述在任意运行次数下必须产出逐位一致的每批摘要与行数，并把每批摘要作为后续漂移观测与真值比对的唯一事实来源。
3. 实现流式连接的逐批执行与实测观测：按初始计划逐步推进连接，每个观测点只从已提交批次的完整结果导出实测输入行数、实测输出行数与实测选择率，不得用后续批次信息回填；同时以单流嵌套循环在已提交批次上计算唯一真值，实测输出须与真值逐行一致，偏差须能定位到具体连接步。
4. 实现代价漂移判定与重优化触发裁决：以初始统计快照估计值与实测观测计算偏差比，按漂移阈值与重优化冷却逻辑毫秒裁决是否触发重优化；触发时必须输出漂移来源（表名与连接键）、偏差比、所用观测批次区间、触发阈值与阈值余量，且同一观测序列在任意运行次数下得到相同的触发结论。
5. 实现重优化后的执行形态切换：切换只能发生在批次边界，进行中的批次必须按原形态完成；在切换代价预算内决定改为哪一连接顺序与算法，输出被否决候选及首个否决原因，预算不足须保留原形态并返回独立业务错误码，切换后累计结果与不切换情形在相同批次上的最终结果必须一致。
6. 实现漂移观测与切换代价的误差账本：记录每个观测点与每次偏差比计算中定点换算的标度、舍入方向与被舍弃余量，并累计加法与乘法的误差上界；当两个候选执行形态的估计总代价差小于浮点容差且切换裁决依赖该差值时标记为精度敏感，输出参与表名、观测批次区间、换算步骤与误差上界。
7. 实现持久化状态与强制终止后的恢复：把批次水位、已提交批次摘要、当前执行形态版本、漂移触发记录、精度敏感标记与逻辑时钟水位以事务原子写入 SQLite，每次形态切换以版本号整体替换当前形态指针并拒绝版本回退；进程在批次执行或形态切换中途被强制终止后，恢复路径只重放水位之后的批次且不得重复累计漂移观测或耗时。
8. 实现多进程并发一致性与可重复命令行演示：多个执行实例并行推进同一计划的不同批次时，通过 SQLite 事务与文件锁保证同一批次同一形态版本只提交一次、形态指针只被整体替换一次，重复提交相同批次结果必须幂等，读取方只能看到完整已提交批次；提供 load、run、inject、resume、status、verify 子命令，并按注入清单在生成、观测、切换三个阶段注入摘要不匹配、观测样本为零、切换预算非法等异常，各自映射独立业务错误码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证漂移触发、形态切换后结果一致、异常注入与强制终止恢复状态正确。
