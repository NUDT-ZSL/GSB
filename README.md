油气管线调度中心的运行工程师在每条输送指令下发前，必须确认指令引用的管段、阀室、泵站与储罐各自归属于哪个运营单位，是否存在委托运营造成的多级归属链，以及这些资源当前是否因检修或移交而不可用。由于管线资源分属多个运营单位且常有归属变更，人工沿归属关系逐跳核对既慢又容易把过期归属当作现行归属。现在需要一套本地可反复运行的台账内核：解析资源清单与所有权声明，沿归属与委托运营边计算每个资源的完整归属链，核验每条调度指令的资源归属与可用状态，在归属变更后只重算受影响资源并更新台账，最后以全量重算为独立参照比对增量结果，保证调度指令与资源归属一致。

任务环境与准备：
在 Linux（WSL Ubuntu）下准备 Python 3 运行环境，仅使用标准库（sqlite3、http.server、json、unittest），无需安装第三方包。
在空工作区创建项目目录，运行确定性样本生成器按固定种子生成资源清单、所有权声明、调度指令与状态事件样本文件，样本与生成器一并保留在仓库内。
启动本地 HTTP 服务后，通过浏览器或命令行访问台账查询页面，验证资源归属链、指令冲突清单与一致性报告均可读取。

业务要求：
1. 解析油气管线资源清单与所有权关系声明，构建以资源对象为节点的归属关系图。对象标识在全图唯一，归属边必须指向已声明对象且方向不得成环；委托运营边需携带委托起止桩号范围与授权单位，若范围越出所属管段设计桩号区间则记为参数不完整。所有错误须输出资源标识、边标识与错误码（E_OBJ_UNKNOWN、E_OWN_CYCLE、E_PARAM_RANGE 等），按资源清单出现顺序稳定排序。
2. 对每个资源沿归属边与委托运营边计算完整归属链，输出逐跳路径、最终所属运营单位与链长。归属链遇到同一资源出现在自身路径上时终止并标注循环链；委托运营边只在资源当前桩号落入委托起止范围时生效，落入重叠范围的多条委托边须按授权优先级选择唯一生效边并记录落选边。归属链结果须可持久化到 SQLite 台账表，供后续核验与增量更新复用。
3. 对每条调度指令引用的资源集合逐一核验：资源的最终所属单位必须与指令要求运营单位一致，且资源状态在指令操作时段内不得为检修或停用。输出冲突资源清单，逐条给出资源标识、冲突类型（归属不符、状态不可用、归属链缺失）与冲突原因；指令引用的资源若在归属图中不存在，须以 E_REF_MISSING 单独标记，不得静默跳过。
4. 按运营单位分组汇总资源归属数量、指令占用次数与冲突次数，形成资源归属台账。同一资源被多条指令引用时占用次数按指令去重计数；归属汇总须区分直接归属与经委托运营得到的间接归属，并在台账中保留每个运营单位下资源标识列表的稳定排序视图。
5. 当归属关系或资源状态发生变更时，沿归属图反向依赖边推导受影响资源集合，只对这些资源重算归属链并更新 SQLite 台账。归属边变更需同时使下游所有经过该边的资源失效；状态变更只影响该资源自身的调度核验结果。增量更新须在单事务内完成，部分失败时回滚到变更前状态并返回 E_TX_ABORT。
6. 以全量重算结果作为独立参照，逐资源比对增量更新后的归属链路径、最终所属单位、状态与冲突标记。输出一致性报告，列出比对资源总数、一致数、首个分歧资源标识及其字段级差异；若全量重算与增量结果在归属链路径顺序上不一致，即使最终单位相同也须判为分歧。
7. 提供本地 HTTP 接口与交互式台账查看页面，调度工程师可按资源标识查询归属链与历史变更记录，按指令编号查看归属核验冲突清单。接口返回 JSON，页面用 Python 标准库 http.server 渲染，所有查询直接读取 SQLite 台账；查询不存在的标识返回 HTTP 404 与 E_QUERY_MISSING 业务码。
8. 实现确定性样本生成器，按固定种子生成资源清单、所有权声明、调度指令序列与状态事件，并附带至少包含循环归属、委托范围重叠、指令引用缺失资源与状态临界时段的边界样本。样本与生成器须写入仓库内文件，同一固定种子多次生成的样本内容逐字节一致，供增量与全量比对反复使用。

验收：
以手工构造资源清单与归属关系为准，核对归属链路径、指令冲突清单、增量与全量重算逐资源一致，并确认分歧资源定位正确。
