在游戏 UI 与排版管线中，字形轮廓常因字重调整、亚像素定位或渲染分辨率变化而需要重新光栅化。当前为空工作区，需从零开发一个本地矢量字形轮廓增量光栅化引擎：把若干字形轮廓渲染为带抗锯齿的灰度位图，并在一组字形轮廓或渲染参数被编辑后，只重算受影响的字形与分块。输入为一个 JSON 场景描述：字形轮廓数据文件（每个字形由若干闭合轮廓的二次贝塞尔与直线段组成，坐标以字体单位给出）、字体规格（unitsPerEm、基线偏移）、每字形目标像素尺寸与亚像素 X 偏移、渲染分辨率、每像素超采样倍数、分块规格、并发上限、在途采样缓冲内存上限、编辑脚本（描述对轮廓控制点、目标尺寸与亚像素偏移的修改）与状态目录。字形轮廓由程序按确定性规则生成本地样本，不依赖任何真实字体文件。真实难点在于：增量重算后的合并结果必须与从头全量光栅化逐像素一致，而依赖失效的判定又必须足够精确，不能因过度保守而退化为全量重算。

任务环境与准备：
安装 Python 3.10 及以上版本，并确保 numpy 可导入；无需 GPU、字体文件或网络。
在空白工作区创建项目目录，按题目要求实现命令行入口与状态目录结构。
编写样本生成脚本，按确定性规则生成本地 JSON 场景、字形轮廓数据文件与编辑脚本，样本规模覆盖多个字形与多个分块。
准备一个本地运行命令用于执行渲染、中断恢复与报告校验，并确保输出文件与状态目录均位于工作区内。

业务要求：
1. 实现场景描述与字形轮廓解析：读取 JSON 场景与轮廓数据文件，校验 unitsPerEm 与基线偏移为有限数、每个字形至少含一个闭合轮廓、曲线段与直线段的控制点坐标均为有限数且下标引用在轮廓点范围内、编辑脚本中的修改目标存在且新坐标为有限数，非法输入返回带业务码的 JSON 错误且不产生任何输出文件。
2. 实现字体单位到像素域的曲线扁平化：按每字形目标像素尺寸与超采样密度把控制点换算为像素单位，二次贝塞尔按与超采样密度相关的像素容差自适应细分为折线段，细分深度有上限且达到上限时降级为可确定的弦近似，扁平化后的折线在容差内逼近原曲线，且结果只依赖控制点与参数而不依赖调度顺序。
3. 实现扫描线覆盖填充与抗锯齿：以超采样网格的采样点为基准构造扫描线，用非零环绕规则判定采样点内外部，覆盖值按超采样命中比例量化到 0 至 255 的整数灰度，亚像素 X 偏移参与采样点位置计算，字符间距与位图尺寸须与场景描述一致，单字形渲染结果与逐采样点串行计算的像素值逐像素相同。
4. 实现字形与分块级依赖记录及失效判定：为每个分块记录其对字形轮廓几何、目标像素尺寸、亚像素偏移与超采样倍数的依赖，编辑脚本任一步发生后只把几何包围盒覆盖到的分块与被修改参数波及的分块标记为失效，其余分块必须保持原结果；失效集合与逐分块重算结果须与全量重算逐像素一致，且不得因过度保守把未受影响分块全部置为失效。
5. 实现分块级持久化与版本识别：每个分块完成后把其灰度结果、依赖记录摘要与由全部轮廓内容及渲染参数规范化摘要构成的版本标识原子写入状态目录，先写临时文件再整体替换，替换前比对已有分块的版本标识，标识变化时不得直接覆盖而须先归档旧版本；再次启动时版本标识一致则只渲缺失块，不一致则从头重做。
6. 实现并发分块渲染与资源上限：按场景中的并发上限使用有界线程池调度待计算分块，同时处于计算中的分块采样缓冲总量不得超过内存上限，超出时按分块索引序让后续块等待而非降低超采样倍数，任一分块异常时取消其余待处理分块并返回首个错误，最终拼装结果与固定并发度为 1 时的结果逐像素相同。
7. 处理可处理终止信号与输出原子写出：可处理终止信号只在分块边界生效，须在写出中断标记并以约定整数退出码退出前保证未完成分块不留下可被误认为已完成的结果；强制终止后重启仅依据已持久化且摘要有效的分块状态恢复且不承诺生成退出报告；全部块完成后先写同目录临时文件再整体替换正式位图文件，替换前读取已有位图的尺寸与摘要版本信息，版本不同才替换。
8. 实现块级摘要校验与增量报告：全部块完成后逐块比对内容摘要，摘要不匹配、缺失或声明的像素数不符时判定该块失效并返回 E_DIGEST 且回退补渲，不得静默使用失效块；同时输出 JSON 报告，含每字形分块数、复用块数、失效块数、失效原因分类与业务码，报告与位图要么同时更新要么都保持旧版本。
