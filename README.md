为零样本目标检测（ZSL）离线评估团队从零构建本地可运行的索引构建与结果验证管线，核心是倒排索引的压缩构建与交互查询延迟下的计算结果一致性。输入为本地样本目录：一份类别—查询映射 JSONL，每条含 query id、查询文本、意图槽位键值、已见与未见类别名集合；一份候选结果 JSONL，每条含 candidate id、候选类别名、文本嵌入向量（固定维度 float64）与置信度；一份真实标注 JSONL，每条含 image id、类别名与框坐标。管线需把候选按类别与意图槽位构建倒排索引，用差分编码与变长整数做倒排链压缩，并提供低延迟查询接口与可复现验证工具。工作区为空，需从零创建项目；所有样本由本地脚本确定性生成，不依赖网络、真实账号或外部数据集，运行平台为 Windows。

任务环境与准备：
安装 Python 3.10 及以上，使用虚拟环境并安装 fastapi、uvicorn、numpy、pytest。
在空工作区创建项目目录与本地样本目录，样本由脚本确定性生成，不依赖网络与真实数据集。
确认本机可用 SQLite 与多进程运行环境，Windows 下测试路径与文件锁行为。
运行前清空索引与结果目录，保证演示入口从固定输入可复现。

业务要求：
1. 入口接收样本目录、候选文件、映射文件与索引配置，校验文件存在、query id 唯一、嵌入维度一致、置信度位于 [0,1]、压缩块大小与内存预算为正整数；任一非法返回 E_PARAM 并指出文件与行号，且不创建任何索引或临时文件。
2. 倒排索引须按类别名与意图槽位键构建倒排链，链内按文档编号升序存放，同一文档只出现一次；类别或槽位在映射中缺失时返回 E_CLASS 或 E_INTENT 并定位 query id 与键名，不得静默跳过。
3. 倒排链须用差分编码加变长整数做压缩，压缩块可独立解码；同一索引在任意块大小与写入顺序下解码后的倒排链必须与未压缩形式逐条一致，块边界不得改变解码结果，索引重构须整体替换并生成新版本号。
4. 查询须用压缩倒排链做候选相交与融合打分，只解码涉及块，未命中块不得全量解码；同一查询在冷缓存与热缓存下返回的候选集合、排序与分数须逐位一致，同分按 candidate id 字典序稳定排序。
5. 须记录并暴露每次查询的解码块数、扫描候选数、耗时与命中块位置；低延迟路径不得用近似剪枝替代精确相交，任何剪枝结果须与全量扫描结果逐一核对一致，否则返回 E_VERIFY。
6. 索引版本变化须使缓存自然失效：查询缓存以索引版本号与查询指纹为键，读取缓存时若索引版本或查询指纹不一致须返回 E_STALE 并给出新旧版本号，禁止返回旧版本命中结果。
7. 索引构建与查询统计须在 SQLite 中以块与查询粒度事务提交，索引文件先写临时文件再原子替换并登记内容哈希；进程被强制终止后重启须核对已提交块哈希，重算未提交块且不重复消费已提交块。
8. 须提供确定性演示与验证工具：固定样本与配置跑出倒排链数量、压缩前后字节数、逐查询解码块数与结果摘要、恢复前后一致性结论的可重复结果，并给出可用 curl 复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证倒排压缩解压一致、查询冷热缓存结果相同及中断恢复后结果不变。
