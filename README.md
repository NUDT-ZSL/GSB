某安全团队需要在离线 Windows 工作站上构建一个安全策略一致性验证工具。工作区为空，需从零开发。输入是一组策略声明文件（本地 JSON 描述的策略条目，含规则标识、作用对象、条件表达式、生效优先级与版本号）以及一份并行验证任务清单；工具须在受限资源预算内并行调度验证任务，判断各策略条目之间是否存在冲突、遮蔽或依赖环，并输出可复现的结构化验证结果。核心难点在于并行调度与资源预算的耦合：任务切分粒度、并发度、单任务超时与累计内存预算相互制约，任何一处判定必须与顺序执行时的判定一致；同时需处理任务异常、部分失败、强制终止后的状态恢复以及结果快照的版本一致性。全部样本、测试与运行都在本地完成，不依赖网络、账号或外部数据。

任务环境与准备：
确认使用 Windows 本地环境，安装 Python 3.11 及以上版本并确保其命令行可用
在空工作区中准备项目目录，安装 NumPy 与 pytest 的本地可用版本，无需网络服务、账号或外部数据
准备本地策略声明与任务清单样本生成脚本的运行入口，所有样本与报告写入工作区内的本地目录

业务要求：
1. 实现策略声明与任务清单的解析与规范化层：逐条校验规则标识唯一性、作用对象合法性、条件表达式的语法与禁用算子、优先级取值范围及版本号格式，对非法条目产出含条目序号与业务错误码的拒绝记录并继续处理其余条目，规范化结果须保留原始声明用于后续复现。
2. 实现策略冲突检测：对同一作用对象上条件区间可交叠且动作互斥的规则对判定为冲突，对高优先级规则完全覆盖低优先级规则可达条件的判定为遮蔽，对规则间引用关系做环检测并返回环中规则序列；冲突、遮蔽与依赖环须分别使用互不相同的业务错误码，并确保判定与规则在文件中的出现顺序无关。
3. 实现并行调度器：把验证任务按作用对象与规则分组切分为独立任务，按可配置并发度在工作线程或子进程中执行，任务完成顺序不得影响最终结论；并发度、单任务超时与任务队列上限均可配置，超出上限时须拒绝入队并返回可识别的业务错误码而非静默丢弃。
4. 实现资源预算控制：为整批验证设置累计内存预算与单任务执行时长上限，预算判定必须基于任务实际分配量与实测耗时，不得以声明值或人为延迟代替；超预算任务须被标记为资源超限并以对应业务码计入报告，且不得中断其余任务；预算耗尽时须给出明确的批次级结论。
5. 实现结果的一致性与可复现性：相同输入在任意并发度下的验证结论、冲突对集合与拒绝清单必须完全一致，输出中的任务顺序需按稳定键归一化；同时需输出批次的调度摘要（任务数、成功数、资源超限数、失败数），摘要须与明细交叉自洽。
6. 实现状态持久化与恢复：验证过程按批次写入检查点，记录已完成任务标识与已累计预算消耗，进程被强制终止后仅允许从最后一个完整检查点恢复，不得承诺生成退出报告；恢复时须识别检查点结构版本与策略版本变化并整体重建，禁止把旧版本任务结果与新策略混合。
7. 实现原子写入与快照整体替换：检查点、最终报告与调度摘要均先写临时文件再重命名整体替换，重命名前需校验内容完整性；同一工作目录的并发写入须以文件锁串行化，锁竞争时返回可识别的锁冲突业务码，且不得出现半写文件或损坏已有快照。
8. 实现确定性本地样本生成与自动化测试：生成覆盖无冲突、冲突、遮蔽、依赖环、超时、内存超限、并发度差异与检查点中断恢复的样本，测试须验证并发与顺序结论等价、业务错误码与退出码、恢复后状态正确性，以及检测过程不修改输入样本文件。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证并行与顺序结论一致、资源超限和中断恢复行为，并核对报告与退出码。
