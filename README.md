团队准备在 Linux（WSL Ubuntu）本地从零实现一个用于电话会议录音的语音端点检测（VAD）规则引擎，重点解决多人说话场景下两代VAD规则配置的互操作与增量失效问题。当前工作区没有任何代码或样本，全部输入由固定种子脚本确定性生成，不依赖网络、外部服务或GPU。业务对象是本地确定性合成的16kHz单声道PCM会议信号，由固定种子生成多个说话人的语音活动段、间歇静音和增益跳变点，并叠加可配置平稳底噪，同时提供逐帧真值文件（帧长20ms，含frame_index、sample_start、sample_end、is_speech、speaker_id_true、noise_floor_true）。VAD规则配置以两代格式并存：v1为单文件JSON扁平结构，按说话人记录能量门限、最小静音时长和相对生效秒，无字段头版本标识；v2为分片JSON加SQLite元数据库，记录绝对毫秒时间戳、说话人标签、规则代数与作用域墓碑。系统需沿时间轴把两代规则互迁对齐到统一毫秒基准，检测端点漂移并输出可回溯的业务码。

任务环境与准备：
在Linux（WSL Ubuntu）下创建空项目目录，安装Python 3.10+、NumPy并确认sqlite3模块可用。
创建固定种子样本生成脚本generate_samples.py，使用随机种子确定性生成16kHz单声道PCM及v1/v2 VAD规则配置与逐帧真值文件，输出到本地data/目录。
编写main.py作为命令行入口，运行本地生成样本并完成规则读取、互迁对齐、能量包络估计、漂移检测、恢复模拟与一致性自检。
不依赖网络、外部数据集或GPU，所有样本均在本地由脚本确定性生成且内容可复现。

业务要求：
1. 实现确定性的分块语音能量包络估计：按配置帧长与帧移切分16kHz单声道PCM，帧边界以样本索引精确确定，每块独立计算短时能量与过零率并输出包络节段，同一输入、同一种子与配置下包络值、块边界和业务码必须逐字节一致。
2. 实现v1单文件JSON与v2分片JSON加SQLite元数据库的VAD规则读取器，按格式头或字段集分派解析路径，未知版本返回E_VERSION_UNSUPPORTED，字段缺失、数值不可解析或时间轴重叠分别返回E_FORMAT_CORRUPT、E_PARSE_ERROR、E_TIMELINE_OVERLAP。
3. 实现两代VAD规则的双向互迁与对齐：v1升级到v2时补充分片索引、规则代数与相对秒到绝对毫秒的换算字段并逐项记录补全来源，v2降级到v1时对无法表达的规则代数与作用域墓碑按显式丢弃规则处理并输出丢弃记录，迁移后每个时间点的能量门限和说话人标签语义必须保持不变。
4. 实现多人说话端点漂移检测与来源裁决：当任一分块包络统计量相较前一版本规则曲线超过容差时记录漂移事件，并定位到贡献最大的说话人活动段、短时能量子带与增益跳变点，裁决结果在float64与定点缩放整数双精度路径下保持一致的业务码与漂移类别。
5. 实现基于内容寻址的分块缓存与版本化整体替换：缓存键纳入PCM内容哈希、VAD规则版本、帧长帧移与上游包络哈希，键相同复用、键不同重算；当规则曲线或音频修订变化时整体替换旧快照而非增量修补，并输出受影响分块集合和复用集合。
6. 实现四阶段状态机与强制终止恢复：包络估计、规则互迁对齐、漂移裁决、报表导出四阶段各产生带单调递增版本号、已完成utterance_id集合与内容校验和的持久化快照，只有该阶段全部样本处理完才原子提交；重启后从最近已提交快照继续，已提交分块不得重算或重复计入，未提交中间状态必须丢弃并重建。
7. 实现并发提交控制与资源预算：同一时刻只允许一个规则快照或漂移裁决提交生效，冲突时后到者立即返回E_STAGE_BUSY而不阻塞等待；为驻留包络统计量内存、缓存条目数和并行处理分块数设可配置上限，超限时按显式优先级返回E_RESOURCE_LIMIT或降级为串行处理并标记降级类别。
8. 实现跨模块一致性自检与结果可回放：最终漂移报表中每条事件须记录其包络块、规则版本与预计算哈希，可按记录独立重放出相同漂移类别与样本区间；自检确保分块串行处理与整段一次性处理的漂移判定和业务码一致，发现差异返回E_STATE_INCONSISTENT并指出首个偏差位置。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
