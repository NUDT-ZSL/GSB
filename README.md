当前是空白工作区，需要从零构建一个面向本地 Windows 环境的边缘缓存一致性领域组件，用于教学与排障演示。系统在本地回环 TCP 端口上运行一个确定性内容源服务与多个边缘缓存节点模拟进程，每个节点持有带版本号与毫秒级 TTL 的缓存条目；内容源以本地 JSON 文件声明内容路径、内容版本（ETag）、字节内容与派生关系（某路径的内容由其他路径内容按确定性规则组合而成）。用户在 Tkinter 界面或脚本中提交缓存策略变更（TTL、缓存键组成字段、容量与逐出规则）与内容版本演进，系统须按策略把条目写入或逐出，并在内容版本变化时沿派生关系推导受影响的缓存条目并使其失效。核心难点在于：策略与内容双版本演进下缓存条目的状态演进必须可追溯，强制终止后的恢复只能依据持久化的账本与快照，且快照必须识别版本差异并整体替换而非增量合并。

任务环境与准备：
Windows 本地安装 Python 3.11 及以上，确认 python 与 sqlite3 标准库可用，Tkinter 随官方安装包提供。
在空白工作区创建目录结构：源服务、节点模拟脚本、样本内容 JSON、演示脚本与 Tkinter 入口。
准备本地确定性内容样本与派生关系声明文件，不使用真实站点或外部网络资源。
确认回环高位端口未被占用，演示脚本按参数选择端口并在占用时返回 E_PORT。

业务要求：
1. 实现内容源与边缘节点的本地编排：以命令行参数在回环高位端口启动内容源进程与至少三个边缘节点进程，节点通过回环 TCP 上的 JSON 行协议拉取内容并回报条目状态；端口被占用须以 E_PORT 业务码报告并写入结构化日志，不得静默重试到其他端口。
2. 实现缓存策略与内容声明的加载与强校验：从本地 JSON 读取路径级 TTL 秒数、缓存键组成字段、节点容量、逐出规则与内容派生关系；校验 TTL 为正整数、键组成字段互不重复、派生关系无环且引用路径存在，任一不合法以 E_POLICY 整体拒绝加载并输出定位信息。
3. 实现按缓存键的条目存取与逐出：每个条目记录内容版本 ETag、写入时刻的单调时钟毫秒基准、剩余 TTL 与条目版本号；容量超限时按声明的逐出规则逐出并记录逐出事件，命中时按经过毫秒递减 TTL，过期条目不得再被命中，条目版本号须随内容版本变化递增。
4. 实现内容版本演进时的派生失效传播：当某路径内容版本变化时，沿派生关系推导全部直接与间接下游路径，按稳定拓扑顺序使其在各节点的缓存条目失效并整体替换为新内容版本；传播轨迹须逐条记录触发源路径与受影响路径，且传播顺序不依赖字典或哈希遍历顺序。
5. 实现策略版本与内容版本的双版本账本：每次策略变更或内容演进都产生单调递增的账本版本号，账本以本地 SQLite 持久化记录条目状态、逐出事件、失效传播轨迹与版本引用；缓存的查询与写入须绑定单一账本版本，混合引用两个版本的状态须被拒绝并返回 E_VERSION。
6. 实现快照的版本识别与整体替换恢复：快照持久化账本版本、内容版本集合、策略版本、缓存条目与传播轨迹；重新打开快照时须比较快照版本集合与当前磁盘状态，不一致须整体替换全部缓存条目与派生关系而非增量合并，旧快照保留为只读备份，恢复报告列出被替换的条目数与版本差异。
7. 实现强制终止后的恢复与一致性重放校验：节点或内容源被强制终止后重启只能依据持久化账本恢复已完成条目状态，未完成写入须标记为未知并要求重跑，不得声称生成退出报告；恢复后按快照轨迹重放失效传播并与保存集合逐项比对，不可复现时以 E_REPLAY 报明具体依据。
8. 提供 Tkinter 诊断工作台与可重复演示：界面展示各节点缓存条目、内容版本、剩余 TTL、逐出事件、失效传播链与账本版本，渲染顺序稳定；附带本地确定性内容样本与演示脚本，顺序执行首次冷启动填充、内容演进后的派生失效传播、策略变更后整体替换三个阶段，并支持以参数注入策略文件损坏、派生成环、端口占用分别返回 E_POLICY、E_CYCLE、E_PORT。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证缓存条目状态、派生失效传播及快照整体替换恢复的一致性，并附运行输出。
