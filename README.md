当前为空白工作区，需要从零构建一个面向内部资料目录的采集与编辑操作台，用于在本地授权环境中抓取结构化目录数据，并让操作员在采集结果上做字段级编辑与版本流转。本地目标站点由同一进程内的确定性 HTTP 服务提供：列表页分页且条目由脚本二次渲染后才出现，详情页按页面内声明的 schemaVersion 采用不同字段结构，可配置注入 503、慢响应和会话过期。采集端需要把原始响应与规范化记录写入 SQLite，并在采集过程中对速率做自适应控制：当服务端返回限流响应或延迟升高时必须收缩在途并发并排队，恢复后逐步放开，不能靠固定 sleep 冒充背压。操作台还需要支持操作员对已采集记录的字段编辑，编辑结果以新版本写入，同时保持与采集端共享同一份规范化字段集合和版本号语义，使重新采集不会静默覆盖人工编辑。整个交付包含本地站点服务、采集调度器、编辑存储层、可交互界面和确定性演示脚本。

任务环境与准备：
Windows 本地环境，安装 Python 3.11 及以上版本，并创建虚拟环境。
在虚拟环境中安装 FastAPI、uvicorn、httpx、Jinja2、pytest 等依赖，版本以本地 wheel 或离线包可得为准。
在项目内准备本地确定性站点服务的静态页面与脚本样本，覆盖两个 schemaVersion、分页、二次渲染、503、慢响应和会话过期开关。
确认可写工作目录与 SQLite 文件路径，准备可通过配置参数注入异常与版本切换的运行入口。

业务要求：
1. 实现列表页就绪判定与分页推进：必须以条目容器出现且条目计数连续两次观测稳定作为渲染完成标记，不得以固定等待替代；分页游标由页面声明的总页数和下一页标识共同推进，超时返回 E_RENDER_TIMEOUT 并记录观测快照。
2. 实现按 schemaVersion 选择的详情解析：至少覆盖两个结构版本的字段差异，未知版本降级为保留原始字段并标记 unresolved，不得静默丢弃数据；解析结果需携带所用版本证据，供后续编辑层和差异报告引用。
3. 实现自适应背压调度器：以在途请求上限、重试等待队列长度和近期响应延迟为观测输入，遇限流或延迟升高时收缩并发并让新请求排队，恢复后按有界步长回放；所有参数可配置且有硬上限，预算耗尽时不得无限开连接。
4. 实现限流与 503 的有界退避重试：区分限流、临时服务错误和条目级解析失败三类结果，重试耗尽记为条目级失败而非任务级失败，退出汇总中必须分别统计，且重试等待期间不得占用在途配额之外的无界资源。
5. 实现采集记录与人工编辑的版本共存规则：采集以业务标识加 schemaVersion 构成幂等键，人工编辑生成递增修订号的新版本；重新采集不得静默覆盖已有修订，冲突时写入待裁决记录并返回业务码 E_EDIT_CONFLICT，保留双方来源标识。
6. 实现会话过期识别与重放：检测到会话过期响应时重新获取会话并重放当前请求，重放次数有上限；超过上限返回 E_SESSION 且任务保持可恢复状态，过期响应体不得作为正常数据入库，重放请求须遵守同一背压预算。
7. 实现持久化检查点与恢复：以检查点记录已完成条目键集合、当前分页游标和调度器限速状态，进程被强制终止后仅依赖库中状态续跑，已确认条目不得重复入库；恢复前后已确认条目计数与修订号序列须保持一致，不承诺补写退出报告。
8. 交付可交互编辑操作台与确定性演示：操作台支持创建采集任务、查看进度与失败明细、对记录做字段级编辑并查看版本历史、触发恢复；本地站点与采集器通过配置中的地址端口协作，版本切换和异常均通过配置参数注入，演示脚本重复执行得到相同的条目计数、失败分类与修订汇总。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
