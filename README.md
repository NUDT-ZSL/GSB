当前是空白工作区，需要从零实现一个本地 SLI 与 SLO 错误预算管理及诊断工作台，以 Flask 提供交互查询界面，SQLite 持久化状态。业务目标是：给定一组 SLO 定义（服务名、SLI 类型、目标值、滚动窗口长度与步长、合规周期、燃尽率告警阈值）和一份观测事件流（事件序号、服务名、逻辑时钟毫秒戳、结果标记、延迟毫秒、是否计为合法请求），工作台需在可注入逻辑时钟下完成滚动窗口切分、窗口内 SLI 聚合、错误预算消耗与燃尽计算，并输出可复现的窗口报告与燃尽告警结论。核心矛盾是：交互查询要求低延迟响应，而窗口聚合、合规周期累计与燃尽计算涉及多次浮点求和与除法，若在查询时现场重算可能超出查询延迟预算；若预计算并缓存，则必须保证缓存结果与精确重算结果逐位一致，且逻辑时钟回拨、迟到事件、窗口边界跨越等异常不能污染已提交窗口。

任务环境与准备：
安装 Python 3.10 及以上版本，并确保 pip 可用。
安装 Flask 2.3 及以上版本与 pytest，安装命令为 pip install flask pytest。
准备本地样本目录，包含 SLO 定义 JSON、观测事件流 JSON 与逻辑时钟步进配置 JSON，样本由脚本确定性生成，不依赖外部网络。
确保存在 SQLite 可写的工作目录，用于持久化窗口结论与缓存。
使用 pytest 运行本地测试，验证窗口聚合、缓存一致性、并发幂等与恢复路径。

业务要求：
1. 实现 SLO 定义与观测事件流的解析校验：校验 SLO 名与服务名唯一、SLI 类型枚举合法、目标值在开区间内、窗口长度与步长为正整数且步长不大于窗口长度、事件序号严格递增、逻辑时钟戳非负、结果标记与合法请求标记为布尔值；非法输入返回明确业务错误码（如 E_BAD_SLO、E_BAD_EVENT）且不写入持久化状态。
2. 实现基于可注入逻辑时钟的滚动窗口切分与事件归属：所有窗口边界与燃尽时间推进只依赖注入的逻辑时钟毫秒值，不读取系统墙钟；每个事件必须唯一归属一个窗口，同一逻辑时钟序列下重复运行得到逐位一致的窗口划分；迟到事件（逻辑时钟早于已关闭窗口末端）不得改动已关闭窗口结论，须记录延迟归属原因。
3. 实现窗口内 SLI 与错误预算的精确聚合：请求成功率统计合法请求数、成功数、失败数与预算总量及已消耗量；延迟达标率按固定排序与插值规则计算分位数并判定达标；剩余预算与燃尽率按固定运算顺序计算，并记录每次加法与除法的累计误差上界，相同输入多次运行结果逐位一致。
4. 实现合规周期内的多窗口预算演进与燃尽率告警判定：按合规周期累加各窗口预算消耗，依据燃尽率阈值与多窗口连续触发规则判定告警状态；告警状态迁移必须依据持久化的窗口结论与逻辑时钟裁决，重启后不得凭内存残留决定，告警解除同样需要持久化的连续未触发证据。
5. 实现窗口结论的持久化与强制终止后的恢复：把 SLO 版本、窗口摘要、告警状态与已提交事件水位以事务原子写入 SQLite，每次窗口推进识别版本变化并整体替换当前结果指针；进程被强制终止后，恢复路径依据持久化状态识别未提交窗口并只重算缺失部分，不得重复累加预算消耗。
6. 实现交互查询的预计算缓存与一致性校验：对窗口报告与燃尽结论建立缓存，缓存键包含 SLO 名、窗口版本与事件水位；查询时若缓存命中则直接返回，但必须提供校验模式对同一请求执行精确重算并逐字段比对，不一致时返回业务错误码（如 E_CACHE_MISMATCH）并输出首个差异字段与两条路径的中间值；缓存必须在窗口版本或事件水位变化时精确失效。
7. 实现多进程并发一致性与幂等提交：允许多个聚合实例并行处理同一 SLO 的不同窗口，通过 SQLite 事务与文件锁保证同一窗口同一版本摘要只提交一次，重复提交相同窗口结果必须幂等；读取方只能看到完整已提交版本，不得观察到中间态；缓存写入与窗口提交须在同一版本语义下协调，避免读到旧版本缓存配新版本水位。
8. 实现异常链路与可重复命令行诊断：事件结果标记非法、窗口内合法请求数为零、逻辑时钟回拨超过容差、样本摘要不匹配、缓存校验不一致分别映射到不同业务错误码并保留可诊断字段（SLO 名、窗口号、事件序号）；单个异常事件不得中断其他 SLO 的窗口推进；提供 load、aggregate、query、resume、status、verify 子命令，status 与 verify 输出稳定排序 JSON。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
