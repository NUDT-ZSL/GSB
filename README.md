体育科学研究所的动作分析研究员每天面对同一名运动员几十段可穿戴传感器训练记录，粗排只按动作类别与片段时长把候选片段拉出来，名次排列几乎与运动员本人的专项、训练年限和伤病历史无关，教练回看时经常先点到与旧伤部位负荷冲突的片段，或是漏掉质量已经明显下滑的重复组。研究所希望把历史训练片段做成可逐请求核对的精排重排链路：每名运动员与其当前训练周期阶段构成一次排序请求，候选片段先对齐传感器统计量、动作类别与运动员档案特征，再分别计算动作质量、负荷风险和档案匹配度三路得分，最后按请求级权重融合并稳定重排。研究员还需要看到每次排序的得分分解、与上一轮名次的变化对照、哪些片段因伤病标签被上调了负荷风险，以及按运动员与训练周期分组的名次一致性统计，从而判断这套融合策略是否值得推广到下一阶段集训。

任务环境与准备：
在 Linux（WSL Ubuntu）上准备 Python 3 运行环境，并安装 NumPy、FastAPI、uvicorn 与 pydantic 等第三方包；SQLite 使用 Python 标准库 sqlite3，不需要独立数据库服务。
在仓库内运行题内确定性生成器，按固定种子生成训练记录工程并初始化 SQLite 数据库文件；本地 HTTP 服务与交互界面均在本机启动，不访问外部站点或真实训练数据。

业务要求：
1. 用固定种子的确定性生成器产出训练记录工程写入 SQLite：若干运动员档案（专项、训练年限、伤病历史标签列表）、每人的多段训练片段（加速度与角速度通道序列、动作类别、重复次数、片段时长、人工标注动作质量分），并把每个运动员某一训练周期阶段的候选片段集合组织成一次排序请求，请求携带档案快照与周期阶段。
2. 对候选片段的传感器通道序列计算统一统计量（各通道均值、方差、峰值因子、过零率与重复节奏稳定度），同时把动作类别、专项与伤病标签对齐到同一数值表示；同一片段在通道采样点数不同或标签书写顺序不同时，统计量与表示必须一致。
3. 逐候选片段计算动作质量、负荷风险与档案匹配度三路得分，并输出每路得分及其特征贡献明细；负荷风险须按伤病历史标签与片段涉及的动作类别、峰值负荷联合上调，命中同一伤病部位的多条标签只上调一次。
4. 按请求级权重把三路得分融合为精排得分，权重随训练周期阶段变化并在请求配置中声明；按融合得分对候选片段稳定重排，同分候选依确定性次序规则落位，输出精排名次、得分分解与名次变化对照。
5. 识别负荷风险因伤病标签被上调的片段，输出上调依据（命中的标签、动作类别、峰值负荷与上调幅度）以及需重点回看的片段清单，清单须覆盖被上调片段与名次下滑超过阈值的片段。
6. 对同一请求在候选输入顺序打乱或特征字段顺序变化时输出完全一致的精排名次与得分分解；以题内确定性生成器内嵌的独立精排得分参考计算为真值逐请求核对名次与三路得分，报告首个名次偏差超阈值的请求及其得分依据。
7. 按运动员与训练周期阶段分组统计重排后的名次一致性（成对比较一致率、关键片段命中率与名次扰动幅度），分组输出一致性统计并在样本内汇总整体结果。
8. 提供本地 HTTP 服务与交互编辑界面：可提交/查看排序请求、编辑请求级权重与周期阶段、浏览得分分解、名次变化与重点回看清单，并展示分组一致性统计；非法请求参数与缺失档案须返回明确业务错误码而非崩溃。

验收：
以题内独立精排参考计算逐请求核对名次与三路得分分解，并检查同分稳定落位、伤病风险上调依据与输入乱序下名次一致。
