在空白工作区从零实现一个本地 TCP 连接状态与拥塞控制推演引擎，用于在确定性样本上复现连接状态机演进、拥塞窗口计算与观测结果一致性。本地 JSON 场景文件给出：链路描述（往返时延毫秒、带宽、接收窗口、是否启用窗口缩放）、连接行为脚本（按逻辑时钟描述的应用层读写、对端 ACK 到达、重复 ACK、超时事件、对端通告窗口变化）、拥塞控制配置（初始窗口、慢启动阈值、拥塞避免算法参数、快速重传与快速恢复开关、重试预算）以及观测采样配置。引擎需以可注入逻辑时钟推进 TCP 状态机（LISTEN、SYN-SENT、ESTABLISHED、FIN-WAIT、TIME-WAIT 等），维护拥塞窗口 cwnd、慢启动阈值 ssthresh、已发送未确认字节与接收窗口，并在同一事件序列下产生逐位一致的窗口与状态轨迹。所有网络事件由本地脚本驱动，不发起真实网络连接。

任务环境与准备：
安装 Python 3.10 及以上，并安装 NumPy（pip install numpy），版本以能正常导入为准。
确认工作区可创建本地目录与 SQLite 数据库文件，无需外部网络或服务。
准备固定本地 JSON 样本：链路描述、连接行为脚本、拥塞控制配置与观测采样配置各一份，作为演示与校验输入。
准备运行命令行的终端环境，可重复执行 run、resume、status、verify、report 子命令。

业务要求：
1. 实现链路与连接行为脚本的解析校验：校验往返时延为正整数毫秒、接收窗口为正、窗口缩放因子在合法范围、脚本事件按逻辑时钟非降序排列、超时事件不得引用尚未发送的字节区间，构建事件时间线与连接初态；非法输入必须返回明确业务错误码（如 E_BAD_LINK、E_BAD_SCRIPT）并保持引擎状态不被部分写入。
2. 实现 TCP 连接状态机演进：依据脚本事件在 LISTEN、SYN-SENT、SYN-RECEIVED、ESTABLISHED、FIN-WAIT-1、FIN-WAIT-2、CLOSE-WAIT、LAST-ACK、TIME-WAIT、CLOSED 之间迁移，每次迁移记录触发事件、逻辑时钟戳与前置状态；非法迁移（如未建连即发送数据）必须被拒绝并返回业务错误码，引擎不得凭内存残留决定状态。
3. 实现慢启动与拥塞避免的窗口演进：按拥塞控制配置计算每次确认到达后的 cwnd 与 ssthresh 变化，启用快速恢复时正确处理重复 ACK 与部分确认，超时事件按确定规则回退窗口；窗口计算必须使用受控定点表示并记录每步的舍入方向，使相同事件序列在任意运行次数下产生逐位一致的 cwnd 轨迹。
4. 实现发送与接收窗口联合约束下的可发送区间计算：任一时刻已发送未确认字节数不得超过 min(cwnd, 对端通告窗口)，接收窗口变化事件须立即影响可发送区间而不回退已发送数据；输出每个事件后的可发送字节上限、在途字节数与窗口阻塞原因，窗口阻塞与拥塞阻塞必须可区分。
5. 实现基于可注入逻辑时钟的超时与重传语义：重传超时只依据注入的逻辑时钟毫秒值判定，不读取系统墙钟；超时后重传最老未确认段并受重试预算约束，超预算必须返回明确业务错误码并令连接进入可诊断的失败态；同一逻辑时钟序列下重放必须得到逐位一致的重传记录，逻辑时钟回拨超过容差时返回业务错误码并保持状态不变。
6. 实现事件轨迹一致性与真值对照：对同一场景分别按事件驱动推演与逐时刻全量重算两条路径得到窗口与状态轨迹，两者逐事件比对，任何不一致必须标记为一致性异常并输出首个分歧事件、两条路径的中间值与该事件依赖的观测；同时记录源脚本内容摘要作为真值来源，摘要不匹配时拒绝推演。
7. 实现持久化状态与强制终止后的恢复：把连接阶段、cwnd、ssthresh、在途字节区间、重试计数、逻辑时钟水位与事件轨迹摘要以事务原子写入 SQLite，每轮推演提交识别版本变化并整体替换当前轨迹指针；进程被强制终止后，恢复路径依据持久化状态识别未提交事件与半写入轨迹，只重放未完成事件，不得重复推进已提交事件的窗口状态。
8. 提供多进程并发幂等与可重复命令行演示：允许多个推演实例并行处理同一场景的不同事件段，通过 SQLite 事务与文件锁保证同一事件同一版本轨迹只提交一次，重复提交相同事件结果必须幂等，读取方只看到完整已提交轨迹；支持 run、resume、status、verify、report 子命令，report 以稳定排序 JSON 输出状态迁移链、cwnd 轨迹与阻塞原因统计，演示脚本用固定样本两次运行输出逐字节一致。
