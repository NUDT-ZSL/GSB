在空白工作区构建一个面向本地确定性样本的 CTR 精排预估数据处理管线与结果验证工具，用于广告与推荐场景下的点击率预估候选打分。输入为一个本地样本目录：候选集 JSONL（每行含请求 ID、候选物品 ID、多路召回分数、稠密特征向量与稀疏特征计数），一份本地小型权重参数包（特征权重向量、偏置项与特征分组表，声明哪些特征同组且存在量纲冲突），一份精排配置 YAML（归一化方式、定点小数位宽与量化档位、融合温度、打分截断区间、线程池并发数、全局打分预算、单请求预算配额、快照提交间隔、异常注入清单路径），以及一份异常注入清单 JSON（指定对哪些请求的哪些阶段施加非有限特征、权重长度不匹配、位宽越界等真实输入故障）。管线需完成特征归一化、定点量化、加权融合打分、分批调度与结果验证报告。核心难点是并发打分调度在全局预算与单请求配额下的资源控制，以及定点打分在归一化、量化、融合、截断四个环节的误差必须可追踪且与串行执行逐字段一致。

任务环境与准备：
准备 Windows 本地 Python 3.11 环境，安装 numpy 与 PyYAML，不依赖任何网络服务或固定 GPU。
在空白工作区创建样本目录，准备由本地脚本生成的候选集 JSONL、权重参数包与精排配置 YAML，并附一份异常注入清单 JSON。
准备验证脚本入口，用于按相同配置分别以并发数 1 与大于 1 运行、模拟可处理退出与强制终止后重启对比结果。
确认运行目录可写，用于临时文件与清单文件的原子替换提交。

业务要求：
1. 实现候选集与参数包加载层：逐行解析候选集 JSONL 与权重参数包，校验请求 ID 非空、候选物品 ID 在请求内唯一、召回分数与稠密特征为有限数、稀疏计数为非负整数、权重长度与特征维度及特征分组表一致；对空请求、非法 JSON、未知特征组与位宽越界分别输出 E_REQ_EMPTY、E_JSON_INVALID、E_GROUP_UNKNOWN、E_WIDTH_INVALID 业务码并进入失败清单。
2. 实现以定点整数表示的特征归一化与量化阶段：对每个候选的各路召回分数与稠密特征按配置归一化方式（最小最大或 z 分数）归一化，再依定点小数位宽转为定点整数，最小最大归一化在分母为零时按固定规则置零并记录该候选；输出归一化统计量、定点特征向量与阶段内容指纹，同一请求与配置下多次运行结果必须逐项一致。
3. 实现加权融合打分与截断阶段：按特征权重与融合温度对定点特征求和并加偏置，求和顺序固定为特征索引升序，结果按打分截断区间裁剪并以确定性舍入输出；同分候选按召回分数降序、再按候选物品 ID 字典序决断；输出每候选最终得分、各特征组贡献分解与得分指纹，并保证改动任一特征权重会真实改变其贡献分解。
4. 实现逐级误差传播追踪：对同一请求分别以配置位宽与高一档位宽完整计算归一化、量化、加权融合、截断四个环节，输出各环节逐候选差值与首次超过配置容差所在环节的标注；当某候选在两种位宽下排序名次不一致时记录边界敏感样本并注明翻转对及其贡献主项，报告须区分环节标注与样本清单。
5. 实现全局打分预算与单请求配额的并行调度器：多请求通过线程池并发打分，最大并发数取自配置；调度器维护全局剩余预算并按请求 ID 稳定顺序分配单请求配额，某请求累计点数超出配额即中止并以 E_REQ_QUOTA_EXCEEDED 记录，全局预算耗尽时对未完成请求输出 E_BUDGET_EXHAUSTED 并保留其在就绪队列中的位置，不得以线程超时冒充预算终止。
6. 保证并发打分结果与串行执行逐字段一致：每条候选任务携带由请求 ID 与候选物品 ID 派生的稳定排序键，无论线程调度顺序与并发度如何，最终候选得分、排序、贡献分解顺序、失败清单顺序与预算扣减序列必须与单线程按请求 ID 稳定顺序执行的结果完全一致，比较须在配置位宽与高一档位宽下分别进行。
7. 实现阶段化快照整体替换与强制终止后的恢复判定：归一化、量化、融合打分、截断各阶段以临时文件加原子替换方式持久化，清单文件记录全局版本号、配置哈希、参数包哈希、已处理请求游标与各阶段产物版本；启动时读取最新清单并校验版本号与配置哈希，不一致输出 E_CONFIG_MISMATCH 拒绝续跑，一致时从游标续跑且恢复后结果与不中断运行一致；收到可处理的退出信号时完成当前请求产物提交后以整数退出码 0 退出。
8. 实现异常注入隔离与验证报告输出：按注入清单对指定请求的指定阶段施加非有限特征、权重长度不匹配与位宽越界等真实输入故障，注入项编号写入报告以证明命中；单请求在任一阶段抛异常时记录请求 ID、阶段名、业务码与异常类型并继续其余请求，失败请求不得进入汇总；每次完整运行生成 JSON 报告，包含每请求排序结果、各环节误差摘要、预算消耗曲线、快照版本号与失败清单，字段名与业务码须与前文一致并以原子替换写盘。
