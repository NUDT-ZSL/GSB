Windows 空白工作区里要落地一个自研内存边界守卫组件的首个可运行版本，用于离线分析本地确定性生成的内存访问轨迹并判定越界，工作区当前没有任何代码与样本。轨迹样本为 JSONL，每行记录一次访问：trace_id、access_seq、region_id、base_offset、access_size、access_kind（read/write）、arena_size 与逻辑毫秒戳；另有区域声明文件，声明每个区域在 arena 中的合法区间、生命周期与父区域引用。核心业务问题是：访问轨迹以乱序、重复、缺口的方式分批到达，组件需在 SQLite 中维护每个区域的越界访问账本与已处理水位，并对每个区域给出最终越界结论与证据链。难点在于分批到达、修订轨迹与强制终止后，账本必须能从最后一个完整检查点恢复，且分批处理的结论与从零全量处理逐条一致；同时区域声明存在版本演进与墓碑标记，需识别整体替换并重算受影响区域。

任务环境与准备：
安装 Python 3.11 或更高版本，并在工作区创建虚拟环境。
安装依赖：pip install numpy pytest。
SQLite 使用 Python 标准库 sqlite3，无需额外安装。
准备本地固定种子样本生成脚本，生成区域声明 JSON、访问轨迹 JSONL 与真值同步标记文件。
在 Windows 本地目录中运行 pytest 与命令行示例，不连接外部网络或服务。

业务要求：
1. 实现区域声明与访问轨迹的严格解析规范化层：校验 region_id 与 trace_id 唯一性、arena_size 为正整数、base_offset 与 access_size 为非负整数且 base_offset 不大于 arena_size、access_kind 取值白名单（read/write）、父区域引用可解析且不构成环；对非法记录输出含文件标识、行号与稳定业务码的拒绝记录并继续处理其余记录。
2. 在 SQLite 中建立区域边界账本：以 region_id 与 access_kind 为主键记录累计访问次数、越界次数、越界上界与已处理 access_seq 水位；每批轨迹在单事务内推进账本，前置校验失败不得改动任何账本状态，账本格局版本变化时须整体重建而非增量续接。
3. 实现单次访问与区域的越界判定：把每次访问的区间与区域声明区间及其所有祖先区域区间求交，访问区间完全落在祖先区间内但越过自身区域上界判为 E_BOUND_OVER，跨越祖先区间判为 E_ANCESTOR_OVER，落在已结束生命周期之后的访问判为 E_AFTER_LIFE；判定必须以规范化后的整数偏移为唯一依据，不得使用浮点。
4. 实现乱序、重复与缺口轨迹的等价处理：重复的 access_seq 按首次出现为真值并记录重复次数，缺口返回 E_SEQ_GAP 并给出缺失区间；任意合法到达顺序下，每个区域的越界结论、越界证据集合与拒绝清单必须与按 access_seq 稳定排序后的串行处理完全一致，报告中证据顺序须按稳定键归一化。
5. 实现区域声明的版本演进与墓碑：区域声明携带代次与墓碑标记，同一 region_id 按代次裁决权威来源，墓碑覆盖较早的非墓碑声明；某区域声明的区间或生命周期变化时，沿父子区域引用计算受影响区域集合，仅重判这些区域的轨迹并保证其结论与从零全量重判逐条一致；遇到区域引用环返回 E_REGION_CYCLE 并列出环内 region_id。
6. 实现检查点演进与强制终止后的恢复边界：按已处理批次水位与账本摘要持久化检查点到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放比对账本一致性以识别半写残留；进程被强制终止后不承诺生成退出报告；检查点结构版本或账本格局版本变化时须整体重建而非增量续接。
7. 实现原子快照整体替换与并发写隔离：检查点与越界诊断报告均先写临时文件，校验内容可解析后再整体重命名替换，替换前须识别快照版本变化；同一工作目录并发写检查点须以文件锁串行化，锁冲突返回 E_LOCK 且不得破坏既有账本或产生半写文件。
8. 交付可交互命令行与确定性本地验证：提供导入轨迹、查询区域越界结论、导出诊断报告、校验检查点四类子命令，报告为可解析 JSON 并含区域级结论、业务码、越界偏移证据与水位；单份输入解析失败不得中断同批其他输入，退出码区分全部成功、部分失败与参数错误；附固定种子样本生成器与 pytest 测试集，覆盖越界、重复、缺口、版本替换、环引用、检查点中断与并发锁冲突。
