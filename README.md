某安全团队需要在离线 Windows 空白工作区从零开发一个依赖供应链完整性诊断工作台，用于在本地确定性清单中追踪依赖构件版本、哈希与签名状态的传播风险。输入是一批本地 JSON 清单文件：每份清单声明项目标识、清单版本、构件条目（构件标识、版本表达式、内容哈希、哈希算法、签名状态）以及构件之间的依赖引用与可选的版本约束区间。工作区的任务是把依赖关系建成图，沿依赖边判断版本约束是否可满足、构件哈希与声明算法是否自洽、签名缺失是否向下游传播，并把传播结果与误差界以可解析 JSON 报告与依赖传播图数据的形式输出。核心难点在于数值精度与误差传播：版本表达式可能混用精确版本、上下界区间与闭开区间端点，区间求交时必须给出可复核的舍入与包含误差界，且该误差界要在多级依赖链中逐层传播并保持可比较；同时诊断结论须与清单导入顺序、区间端点写法与算法声明顺序无关，中间状态可恢复。

任务环境与准备：
确认运行于 Windows，安装 Python 3.10 及以上版本，并确认 numpy 与 pytest 可用（可离线 wheel 安装）。
准备一个空白工作目录作为新工作区，不放置任何现存代码、样本或历史报告；所有样本由题目要求的本地生成器产出。
无需网络、账号或外部服务；生成器与测试必须可在本地离线反复执行并得到相同结果。

业务要求：
1. 实现依赖清单的解析与规范化层：逐条校验项目标识与构件标识唯一性、清单版本格式、哈希算法白名单（sha256 与 hmac-sha256）、签名状态取值在已签/未签/未知三值内，对非法条目输出含条目序号与业务错误码的拒绝记录并继续处理其余条目，不得中断整批。
2. 实现版本表达式与约束区间的规范化：统一精确版本、上下界区间与闭开区间的端点表示，把版本分解为可比较数值分量，并按最大分量分辨率构造可复核的量化误差界与包含误差界，端点含入与否必须以规范化后的闭开标记为唯一依据。
3. 实现依赖图构建与约束求交：以依赖引用为有向边建图，对同一构件被多条入边约束时求区间交集，交集中还需在报告中给出交集的误差界合成结果；检测依赖图中的自引用与任意长度环并返回 E_CYCLE 并列出环中构件标识序列，环检测结论须与条目到达顺序无关。
4. 实现数值误差沿依赖链的传播估计：为每个构件计算从根到叶累计的版本约束误差界与哈希校验舍入误差上界，误差界须依据区间端点量化分辨率与哈希摘要按算法声明的位宽推导，并在报告中区分可满足、不可满足与误差界重叠导致的不确定三种判定，不确定项须单列。
5. 实现哈希与签名完整性判定：按构件声明的哈希算法校验内容哈希是否与规范化摘要一致，算法与摘要位宽不匹配返回 E_HASH_ALGO、摘要不匹配返回 E_HASH_MISMATCH；未签或未知签名状态的构件须沿依赖边向下游传播签名缺失标记，被标记的下游构件不得被判为完整，且需在报告中给出传播路径。
6. 实现基于同步标记的真值对照：本地样本生成器在清单内显式记录每个构件的原始版本分量、同步标记、声明算法与预期误差界区间，验证端只依据这些同步标记与规范化区间比较，不得把生成器的中间计算结果当作业真值；报告须给出观测一致与不一致的计数及不一致条目定位。
7. 实现诊断工作台的原子报告与批处理容错：JSON 诊断报告含清单级结论、每构件约束判定、业务错误码、区间误差界与传播路径，另输出依赖传播图数据文件（节点、边、误差界与完整性标记）；报告与图数据均先写临时文件再整体重命名替换，单份清单失败不得中断同批处理，退出码区分全部成功、部分失败与参数错误。
8. 实现增量校验的检查点与顺序无关保证：按已应用清单版本水位与聚合结论持久化检查点，恢复时只从最后一个完整检查点继续，检测到检查点结构版本或哈希算法白名单版本变化时须整体重建而非增量续接；同一组清单在任意合法导入顺序下构件的约束判定、误差界与签名传播集合必须完全一致，输出中构件顺序按稳定键归一化。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
