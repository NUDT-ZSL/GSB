当前是空白工作区，没有现存项目、代码或数据附件。需要从零构建一个面向本地 Windows 环境的告警降噪与根因关联领域组件，交付形式为可集成的领域组件与完整示例。用户在本地 JSON 文件中声明一组告警规则与服务拓扑：每条告警规则含规则标识、目标服务、指标条件与严重级；服务拓扑以有向依赖边描述上游对下游的依赖，边可携带依赖权重。运维侧以 NDJSON 录入原始告警事件流，每行含告警标识、规则标识、目标服务、毫秒时间戳与观测值。组件须把原始告警按服务拓扑与时间邻域聚成告警簇，为每个簇推导根因候选并输出降噪后的簇级告警；当用户增量修改告警规则或服务拓扑时，须准确推导受影响的簇与关联结论并使其失效，重算范围不能整体推倒重来。会话状态（规则、拓扑、事件游标、簇、根因结论与失效轨迹）须持久化到本地 SQLite，恢复时识别版本差异并整体替换。系统以命令行启动本地演示会话，Tkinter 界面仅用于展示诊断视图，不承担主流程。

任务环境与准备：
在 Windows 本地安装 Python 3.11 或以上版本，确认 pip 可用。
创建空白工作目录并把仓库根目录置于其中，无需任何外部服务或网络访问。
仅使用 Python 标准库（sqlite3、json、tkinter、hashlib、logging 等），不安装第三方依赖。
准备本地确定性样本：规则与拓扑 JSON 文件、原始告警 NDJSON 文件、变更集 JSON 文件，均由演示脚本生成或随仓库存放。
确认工作目录可写，以便 SQLite 快照文件、结构化日志与演示输出落盘。

业务要求：
1. 实现告警规则、服务拓扑与事件流的加载及强校验：从本地 JSON 读取规则与服务依赖边，从 NDJSON 读取原始告警；校验规则标识与服务名唯一、严重级属于受支持集合、依赖边两端服务存在且服务名在规则与拓扑间一致、事件时间戳为非负整数毫秒且单调不减、观测值为有限数值；任一不合法须以 E_SPEC 业务码整体拒绝加载，并输出出错文件标识与行号。
2. 实现基于拓扑与时间邻域的告警聚类：以固定整数毫秒的时间窗口与拓扑可达关系把原始告警聚成簇，聚类结果须与输入遍历顺序无关；同一服务的告警在窗口重叠时须合并为同一簇而非产生重复簇，跨服务的上下游告警按拓扑方向并入同一簇；输出每个簇的成员告警标识列表、覆盖时间区间与涉及服务集合，重复运行须得到逐字节一致的簇摘要。
3. 实现簇内根因候选推导与降噪输出：对每个簇按拓扑入度、严重级与时间先后按确定性规则评定根因候选并排序，输出候选服务、支撑告警集合与判定理由；被判定为传播性告警的成员须在降噪输出中折叠并标注触发的根因候选，排序不一致时须有显式决胜规则；推导不得依赖字典或哈希遍历顺序。
4. 实现规则与拓扑增量变更的失效传播：用户以变更集（新增、修改、删除规则或依赖边）更新后，须准确推导受影响的簇集合与根因结论并标记失效，未受影响簇的结论须保持不变且可校验；删除仍被其他服务依赖的服务须拒绝并返回 E_DEPEND 列出依赖者；失效集合与重算范围须以稳定顺序记录到失效轨迹。
5. 实现增量失效后的局部重算与结果一致性：仅对失效簇重新聚类与推导根因，增量重算结果须与全量重算在簇成员、根因候选与降噪输出上逐字节一致，不一致须以 E_INCR 报告首个差异簇标识；报告须给出本轮重算簇数、复用簇数与两者之和是否等于当前簇总数。
6. 实现会话状态的版本识别与整体替换恢复：快照持久化到本地 SQLite，含规则集合版本、拓扑版本、事件游标、簇与根因结论、失效轨迹；重新打开快照时须比较快照版本与当前规则、拓扑版本，不一致须整体替换当前规则、拓扑与簇状态而非增量合并，旧快照保留为只读并可辨识差异版本。
7. 实现恢复后的一致性重放校验与异常链路：恢复后按快照记录的事件游标与规则版本重新聚类并推导根因，与快照保存结论逐簇比较，因版本缺失或事件游标超前导致不可复现时须以 E_REPLAY 报明具体依据；另支持以命令行参数注入事件时间戳回退、快照版本缺失两类异常，分别以 E_TIME、E_SNAP 业务码报告并写入结构化日志，注入仅改变输入文件或参数。
8. 提供可集成的组件 API、诊断界面与完整示例：以 Python 包暴露加载、聚类、根因推导、增量变更、重算校验、快照保存与恢复的接口；Tkinter 界面展示规则与拓扑依赖边、簇成员、根因候选与理由、本轮失效集合、重算与复用簇数及快照版本差异，渲染顺序稳定；附带本地确定性样本规则、拓扑与事件流及演示脚本，顺序演示冷加载全量聚类、增量修改一条被依赖规则后的局部重算、快照恢复后重放三个场景，每个场景输出稳定顺序的诊断总结。
