当前为空工作区，需从零开发一个本地流媒体自适应缓冲仿真与恢复一致性引擎，用于视频点播客户端的缓冲状态演进验证。输入为一个 JSON 仿真会话描述与程序按确定性规则生成本地样本：网络轨迹文件（每段给出可用带宽与往返时延）、媒体清单（若干分片按序排列，每片给出编码码率、以媒体时间计的时长与字节大小）、客户端初始参数（启动缓冲目标、最大缓冲上限、安全余量、码率选择策略与切换罚分系数）、事件脚本（播放中途暂停、跳转播放时刻、网络轨迹切换点、可处理终止信号触发点），以及状态目录与快照存档目录。仿真须在统一的媒体时间轴与整数毫秒事件时钟上推进：每次分片下载完成、缓冲排空、缓冲触顶都可能改变下一分片码率的选择。真实难点在于状态演进与恢复：客户端被暂停、跳转或中断后再次启动，必须从持久化快照恢复出与不中断连续仿真逐事件一致的缓冲水位、下载进度与码率决策序列，同时并发预取不得改变决策结果。

任务环境与准备：
安装 Python 3.11 与 NumPy，使用标准库 json、threading、hashlib、signal 等，不依赖网络与外部服务。
在工作区创建状态目录与快照存档目录，样本由程序按固定种子生成网络轨迹、媒体清单与事件脚本。
准备用于注入版本变化与快照篡改的本地样本副本，以及模拟可处理终止信号的测试脚本。

业务要求：
1. 实现仿真会话描述解析与输入校验：读取 JSON、网络轨迹与媒体清单，校验分片码率与字节大小为有限正数、分片媒体时长为正整数毫秒、轨迹各段带宽为正、往返时延为非负整数、启动缓冲目标不超过最大缓冲上限、跳转时间为非负整数且不超过媒体总时长；非法输入返回带 E_xxx 业务码的 JSON 错误且不写出任何状态文件。
2. 实现统一媒体时间轴与整数毫秒事件时钟：把分片下载时长由字节大小与轨迹带宽换算为整数毫秒的完成时刻，缓冲水位按同一时间轴以毫秒累计与排空，播放进度与跳转均落在整数毫秒边界；时间换算的取整规则须单一确定，同一输入重复仿真得到逐事件相同的完成时刻与缓冲水位序列，禁止依赖浮点累加顺序。
3. 实现确定性自适应码率选择：在每个分片下载起始时刻，依据当前缓冲水位、以已完成分片的字节数与下载时长估计的带宽与安全余量按策略选出码率，含切换罚分与缓冲触顶时的降码率规则，并验证所选分片在播放到下个分片完成前不会排空缓冲；决策只依赖已发生事件与当前状态，禁止读取未来轨迹段或分片大小，同一状态序列必产出相同决策序列。
4. 实现暂停、跳转与网络轨迹切换的事件语义：暂停期间缓冲不再排空但下载可继续、恢复播放以暂停时刻续接；跳转须丢弃不在新播放点之前的缓冲并按新位置重新选择分片；轨迹切换只影响其后开始的分片下载，已完成下载不受影响；各事件在事件脚本中的顺序处理结果须与理论缓冲水位一致。
5. 实现快照标识与阶段化持久化：每个分片下载完成、暂停、跳转与轨迹切换后把缓冲水位、播放时刻、当前分片序号、已下载分片摘要与网络轨迹游标写入状态目录，并以由媒体清单内容、轨迹内容与客户端参数规范化摘要构成的版本标识整体替换快照；版本标识变化时须识别旧版本并归档或标记失效，不得直接覆盖。
6. 实现中断与恢复一致性：可处理终止信号只在事件边界生效，写入中断标记并以约定整数退出码退出，未完成事件不得留下可被当作已完成的状态；再次启动时版本标识一致则从最近事件继续仿真，不一致则从头重做，强制终止后仅依赖已持久化且摘要有效的状态恢复，不承诺生成退出报告。
7. 实现快照防篡改校验与诊断报告：对每份快照计算内容摘要并与快照记录的摘要比对，摘要不匹配、缺失或声明事件序号与实际不符时判定快照失效并返回 E_DIGEST，恢复时须回退到最近有效快照或从头开始；最终输出 JSON 报告，含逐事件缓冲水位、码率决策、切换次数、排空次数与恢复起点，报告须与仿真日志逐条对应。
8. 实现并发分片预取模拟与资源上限：按会话中的并发数用有界线程池模拟多个并行下载的分片，同时处于处理中的分片下载缓冲总量受内存预算限制，超出时按分片序号确定顺序等待而非降低时间精度；并发调度不得改变码率决策与缓冲水位序列，任一下载任务异常时取消其余任务并返回首个错误。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
