在空白工作区从零实现一个本地平台故障恢复的配置互操作与恢复裁决管线，用于在确定性样本上复现多代恢复配置文件在故障切换与回切过程中的互操作与版本兼容问题。本地样本以 JSON 给出两代恢复配置：v1 为单文件 JSON，记录服务名、故障域、恢复动作脚本（按逻辑时钟描述的启停与切换步骤）、相对回退秒数与扁平服务到动作的映射；v2 为分片 JSON 加 SQLite 元数据库，记录服务规范名、绝对生效时刻毫秒戳、恢复代数、动作优先级标签、依赖上游服务列表与失效墓碑。编排器需加载并合并两代配置，构建统一恢复计划，在可注入逻辑时钟下推演切换与回切裁决，逐动作持久化阶段状态与内容摘要；进程可能在任意阶段被强制终止，恢复时必须依据持久化状态而非内存残留。工具与样本全部在本地 Windows 文件系统上运行，不依赖真实集群、外部站点或容器环境。

任务环境与准备：
准备 Windows 本地工作区，安装 Python 3.11 或以上，并以 pip 安装 numpy 与 pytest 到该解释器。
创建本地样本目录，放置 v1 单文件 JSON 配置、v2 分片 JSON 与 SQLite 元数据库样本，全部由固定数据生成以便重复运行。
准备本地回环 HTTP 测试服务脚本，用于模拟动作下发目标的成功、连接拒绝、超时与回显版本不符响应，不依赖外部网络。
确认工作目录可写，SQLite 文件、临时文件与分片目录均位于工作区内，运行前清理残留临时文件与锁文件。

业务要求：
1. 实现 v1 与 v2 两代恢复配置的解析与校验：v1 校验服务名唯一性、相对回退秒数为非负整数、动作脚本步骤在逻辑时钟上非降序、扁平映射与动作声明一致；v2 校验分片文件哈希、SQLite 元数据中恢复代数单调、绝对生效时刻为非负毫秒整数、上游依赖两端闭合；非法条目必须以明确业务错误码报告且不写入任何持久化状态。
2. 实现跨版本合并与统一恢复计划构建：同一服务在两代配置中同时存在时，依据配置声明的逻辑时钟与恢复代数裁决最新版本，无法裁决时按来源格式优先级；合并后每条动作须保留来源版本、原始时间表示与原始相对回退值，并把两代动作序列编排为按服务的统一计划且保证稳定排序。
3. 实现时间与依赖语义的模式迁移：v1 的相对回退秒数在注入逻辑时钟下换算为绝对回退时刻并记录换算标度与舍入方向，v2 绝对时刻保持原值；v1 无代数与优先级标签的动作迁移为 v2 统一语义并记录迁移映射，同一服务在迁移前后是否处于应回退状态必须保持不变。
4. 实现切换与回切的裁决执行链：按依赖拓扑序逐服务裁决切换动作是否可执行，上游未就绪时下游必须等待并记录触发来源；回切按配置的流量比例阶梯推进，每一步须校验目标服务健康结论与持久化状态，中途失败停留在上一稳定阶梯，输出每服务的决定链与首个触发原因。
5. 实现逻辑时钟注入与精度一致判定：所有生效判定的时间换算、动作窗口与回退时刻只依赖注入的逻辑时钟毫秒值，不得读取系统墙钟；同一逻辑时钟序列下重放必须得到逐位一致的裁决序列，逻辑时钟回拨超过容差时返回业务错误码并保持计划状态不变。
6. 实现强制终止后的恢复裁决：把服务阶段、已提交动作水位、流量阶梯、迁移决策与逻辑时钟水位以事务原子写入 SQLite；进程在切换或回切任一阶段被强制终止后，恢复路径依据持久化状态识别已提交动作与半提交动作，只重放缺失动作且不得重复计入已提交阶梯，恢复后计划视图须与未中断运行一致。
7. 实现配置包整体替换的版本变化识别与回退拒绝：收到新配置包时比较清单版本号、恢复代数下限与各分片哈希及内容摘要，判定完整替换、增量追加或无需操作；整体替换须以临时表加版本号方式切换当前计划指针而非逐条覆盖，版本回退须被拒绝并记录审计，旧版本仅在无已提交计划引用时方可清理。
8. 实现多进程并发一致性、幂等与异常链路：允许多个编排实例并行处理同一批服务，通过 SQLite 事务与文件锁保证同一服务同一动作版本只被提交一次、重复提交幂等、读取方只看到完整已提交阶段；连接拒绝、动作响应超时、回显版本不符、摘要不匹配、依赖成环分别映射到不同业务错误码并保留可诊断字段。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证两代配置互操作、切换回切裁决及强制终止后的恢复一致性，输出结果与状态。
