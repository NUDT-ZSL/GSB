工作室希望先拿到一个能完整演示的战斗数值平衡验证版本，用来在产品化之前确认数值配置不会让关卡出现必败、必然超时或收益失衡。工作区目前为空目录，全部输入由随工程交付的固定种子脚本确定性生成本地 JSON：战斗脚本（回合序列与单位动作）、单位与技能数值表（含定点标度）、关卡配置与平衡判据、并行度与单轮逻辑时间预算、在途战斗状态缓冲内存预算，以及一个按顺序描述属性、倍率与判据修改的编辑脚本。验证链路把每场战斗建模为按回合分块的确定性推演，结果写入 SQLite 账本并输出平衡诊断报告；真正难的地方在于编辑脚本变更数值后必须精确判定哪些战斗分块失效、只重算受影响部分，同时并行推演要在双预算下可复现，且中断与强制终止后结果仍与全量重算一致。

任务环境与准备：
安装 Python 3.11 或 3.12，并执行 pip install numpy 以提供数组与定点累加辅助（标准库 sqlite3、threading、signal 随 Python 提供）。
在 Windows 本地工作区建立空项目目录，并编写或使用随题要求的固定种子样本生成脚本，确定性生成战斗脚本、数值表、平衡判据与编辑脚本等本地 JSON 文件。
确认可写的状态目录与 SQLite 数据库路径，验证同目录临时文件与整体替换在 Windows 上可用；整个任务不依赖网络、真实账号、外部服务或容器环境。

业务要求：
1. 实现样本生成、战斗脚本与数值表的解析校验：校验单位与技能标识唯一、属性与倍率按定点标度可量化、回合内动作逻辑时刻为非负整数且同一时刻保持声明顺序、目标引用存在、平衡判据阈值在定义域内，非法输入返回带 E_xxx 业务码的 JSON 错误且不产生账本写入。
2. 实现定点数值运算层与浮点参考路径：伤害、治疗、暴击与收益系数均先量化为规格定点整数再累加与比较，同步保留 float64 参考值；逐回合记录两者差值，标出首次超过残差容差的回合、单位与技能，最终平衡判定只依据定点结果，浮点仅用于诊断与报告。
3. 实现确定性按回合分块推演：每场战斗按整数回合分块推进单位生命、状态效果与资源，同一回合内动作结算顺序只依赖声明顺序与全序键；同一脚本重复推演必须得到逐回合逐单位逐字段相同的状态与事件，分块并发度不得改变任何结果。
4. 实现编辑脚本的依赖图与失效闭包：为每个战斗分块记录其依赖的单位属性、技能倍率、掉落权重与平衡判据，编辑脚本任一步发生后只把沿引用关系可达的分块标记失效，其余分块复用已持久化结果；报告须逐条列出失效理由与受影响分块数。
5. 实现增量重算与全量结果一致性：只对失效分块重跑推演并在相邻保留分块边界处按同一结算口径衔接，增量后的逐回合状态、事件流与平衡判定须与同输入从头全量推演一致，定点结果逐字段相同、浮点参考差在容差内，否则给出首个不一致回合。
6. 实现 SQLite 账本与阶段完成判定：每分块推演完成后在同一事务内写入战斗标识、分块序号、回合区间、状态摘要与内容摘要，只有某战斗全部分块落入账本后才允许聚合整场结果与平衡结论；账本须在进程被强制终止后可读并识别未完成分块。
7. 实现并行调度与双预算准入：按并行度使用有界线程池调度待算分块，同时处于计算中的战斗状态缓冲总量不得超过内存预算；按可注入逻辑时钟计量每轮耗时，超出单轮逻辑时间预算即结束本轮并让出，未准入分块延后且准入序列在相同输入下可复现。
8. 处理可处理终止信号与原子报告写出：可处理终止信号只在分块边界生效，写出中断标记并以约定整数退出码退出，未完成分块不得留下可被当作完成的结果；强制终止后重启仅依据账本与摘要有效的分块恢复，不承诺生成退出报告；平衡报告先写同目录临时文件再整体替换，替换前比对已有报告的版本标识。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证数值平衡推演、编辑后失效重算与中断恢复，增量结果须与全量重算一致。
