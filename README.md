当前是空白工作区，需要从零实现一个面向本地文档数据库场景的查询执行组件。文档以类 JSON 结构存储于本地 SQLite，每条文档带集合名、文档标识、版本号与嵌套字段。查询请求以受限的文档查询语言描述：按集合过滤（等值、范围、存在性、嵌套路径）、排序、跳过与限量，并声明每批返回条数与游标语义。真实文档数据库的查询执行不是一次全量返回，而是分阶段推进：扫描候选、应用过滤、排序、分批取回，任何阶段都可能因存储层读取失败、查询被取消或资源预算耗尽而中断。组件必须在中断时保留已确定的执行进度，使客户端能凭游标从一致点继续，而不是从头重扫；同时必须提供确定性的异常注入机制，让上述中断链路能在离线环境中被反复复现。难点在于异常注入点与执行阶段、游标快照、SQLite 事务边界与并发查询之间存在多重耦合：注入失败不能污染已提交的查询会话，游标续读必须与中断前看到同一数据版本，取消与预算耗尽必须区分并给出不同业务码。

任务环境与准备：
在本机安装 Python 3.11 及以上版本，确认 python 与 pip 可在命令行直接调用。
安装 pytest 与标准库之外的零依赖可选工具，全部从本地已缓存或离线源安装，不访问外网。
确认 SQLite 由 Python 标准库 sqlite3 提供且支持 WAL 模式，执行 PRAGMA journal_mode 检查返回 wal。
准备一个空白工作目录作为项目根目录，样本数据由项目内固定随机种子生成器产出，无需外部数据集。
运行 pytest 前确认工作目录可写，测试使用临时目录隔离数据库文件，运行结束后清理。

业务要求：
1. 实现文档模型与查询语言的解析与校验：文档含集合名、文档标识、版本号与嵌套字段，查询含集合名、过滤谓词列表、排序键、跳过数、限量与分批大小；须校验嵌套路径存在性、排序键可比性与限量区间，非法查询返回固定业务码 E_BAD_QUERY 且指出出错的谓词序号，不得进入执行阶段。
2. 实现分阶段查询执行器：扫描、过滤、排序、分批取回须是分离阶段，排序阶段产出的有序结果集在会话内以稳定文档标识序固化；每批取回只消费固定条数并返回游标，限量边界与跳过偏移须精确；对同一查询以相同分批大小重复执行，逐批返回的文档标识序列必须完全一致。
3. 实现基于数据版本快照的游标续读：查询会话开始时须固定所读集合的数据版本号，游标绑定该版本与已消费位置；续读时若集合版本已变化须判定为快照失效并返回 E_SNAPSHOT_STALE 而不是返回混合版本结果；版本未变时续读必须跳过已消费部分且不重复返回任何文档。
4. 实现可复现的异常注入机制：注入配置来自请求参数或配置文件，按注入点名称（scan、filter、sort、fetch、commit）与触发计数精确定位，仅在第 N 次进入该注入点时抛出指定异常，其余调用正常执行；同一配置与同一查询须产生完全相同的失败位置与已消费条数，注入不得修改任何已提交的会话状态。
5. 实现中断链路与业务码映射：存储读取失败、注入异常、客户端取消与预算耗尽须映射为不同业务码（E_STORAGE_READ、E_INJECTED、E_CANCELED、E_BUDGET_EXHAUSTED），异常须携带注入点、触发计数与已推进阶段；执行器须区分可继续的中断与不可继续的中断，只有不可继续的中断才使游标作废。
6. 实现失败原子性与会话恢复：任一阶段失败时不得留下部分写入的结果批次记录、残留的事务或半打开的读取游标；已提交的批次记录必须保留且可查询；失败后以相同查询关闭注入重新执行须成功，且成功结果与从未失败过时的规范化输出逐字段一致。
7. 实现并发查询会话与资源预算控制：多个查询会话可并发执行，同一集合的写入与查询须在一致快照边界内隔离；单会话的读取条数预算与执行阶段推进预算超限时须有序中断并返回 E_BUDGET_EXHAUSTED，不得以线程超时冒充已终止；并发续读同一游标须只成功一次，另一次返回 E_CURSOR_IN_USE。
8. 提供本地样本、完整示例与可重复测试：内置确定性样本生成器（固定随机种子）生成至少三个集合、每集合两千条含嵌套字段的文档，示例演示分批取回、各注入点失败与续读恢复；pytest 用例须覆盖非法查询、注入触发计数定位、快照失效、四类业务码区分、失败原子性、并发续读互斥与预算耗尽，全部在 Windows 离线运行。
