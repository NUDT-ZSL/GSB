方案已经确定，但 Linux（WSL Ubuntu）本地工作区还未产生任何代码或样本，需要从零构建一个面向多说话人会议音频的专业应用与可重复演示。业务对象由本地固定种子脚本确定性生成：一段 16kHz 单声道 PCM 会议混合信号，由多个说话人的语音活动段、间歇静音和可配置增益跳变叠加而成，并注入若干换流点异常事件（如说话人切换过快、单说话人抢占、静音异常拉长）。系统要完成换流点事件提取、异常分类、说话人身份稳定裁决，并把检测结果写入双版本账本供追溯。核心难点在于实时帧流处理与批量结果必须逐字节一致，两代标注规则要互迁比对，身份归属在分段修正后还要保持稳定。

任务环境与准备：
安装 Python 3.10 或更高版本，推荐使用 pyenv 管理版本。
安装 NumPy 与 SQLite 库：pip install numpy==1.26.4。
确认工作目录为 Linux（WSL Ubuntu）路径，不依赖外部网络、真实音频数据集或 GPU。
创建项目目录，并将随题交付的固定种子样本生成脚本放入该目录，运行一次生成确定性样本文件。

业务要求：
1. 实现确定性的分块换流点检测：按配置帧长 20ms 与帧移 10ms 切分 16kHz PCM，帧边界以样本索引精确确定，对每块计算短时能量与过零率，识别说话人切换与其他换流点事件，同一音频、同一种子与配置下必须逐块产出相同的换流点事件序列，块边界不得产生与整段检测不同的判定，且在浮点与定点双精度路径下换流点集合必须完全一致。
2. 实现 v1 与 v2 两代换流点异常标注规则的读取器与双向迁移器：v1 为单文件 JSON 扁平行式记录相对秒数与异常阈值，v2 为分片 JSON 加 SQLite 元数据库记录绝对毫秒、异常类型与规则代数，迁移时升级要补全异常类型默认值与阈值来源并逐项记录补全字段，降级对无法表达的嵌套规则按显式丢弃规则处理，迁移后同一时间点的异常判定在两代视图下必须得到相同的业务结论。
3. 实现换流点异常分类与身份稳定裁决：对每个换流点按异常规则分类为正常切换、过快切换、单说话人抢占或静音拉长，并结合帧级说话人特征对每个语音活动段做身份指派，身份指派在同一会话内必须稳定且可回溯，当某前后分段被合并或拆分时仅重算受影响段，未受影响身份标签不得改变。
4. 实现实时查询与批量处理的一致性保证：提供按毫秒时间点或语音段编号的实时查询接口，返回该位置最近换流点状态、当前说话人身份与业务码，查询结果必须与批量处理结果在声明精度内完全一致；查询侧不得引入任何隐式近似，且同一次查询在重复运行下不得出现结果抖动。
5. 实现增量更新与依赖失效传播：当某语音段身份真值被修正、异常规则版本提升或音频修订到达时，按内容寻址缓存键定位受影响帧区间、语音段与账本行，复用未受影响已提交结果并精确重算受影响后缀；必须输出本次重算集合、复用集合与触发变更的规则版本或修订标识，且增量结果与全量重算逐字节一致。
6. 实现六阶段处理状态机与强一致阶段快照：帧特征提取、换流点检测、异常分类、身份裁决、账本写入、审计报告各阶段产生带单调递增版本号与已完成区间集合的持久化快照，只有该阶段全部区间处理完成才原子提交；重启时从最近已提交快照继续，未提交的中间状态必须丢弃并从该快照起点重建。
7. 实现身份时序与换流点顺序的自检：校验同一语音段内身份标签不随时间变化、相邻换流点间隔必须大于声明的最短稳定间隔、换流点时间戳严格升序且无重叠，违反时分别返回 E_IDENTITY_DRIFT、E_SPURIOUS_TURN 或 E_OVERLAP_TURN，并定位到首个违规帧与业务码。
8. 实现跨模块一致性自检与本地可交互演示：提供本地可交互应用展示换流点事件、身份标签、双版本规则视图、缓存命中与重算状态，自检校验实时查询与批量结果一致、增量重放与全量账本一致、阶段快照与最终账本一致，并输出包含最近业务错误码与来源追溯链的诊断报告。
