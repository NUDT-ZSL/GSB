当前是空白工作区，需要从零实现一个本地流式连接管线执行引擎的运行时自适应重优化组件，交付可集成的领域库与完整示例。与编译期一次性枚举连接顺序不同，本场景的核心问题是：连接管线在持续到达的列式批次上推进时，真实基数与分布会逐步偏离初始统计估计，组件必须依据已提交批次导出的实测观测判定代价模型漂移，并在漂移超阈时对流式连接管线的执行形态做可复现的重优化裁决，同时保证该裁决在批次水位演进、执行形态版本替换与进程被强制终止后仍可解释、可续算、可对账。本地 JSON 样本给出：表描述（表名、行数、每列 NDV、列宽字节、连接键语义、是否倾斜）、流式查询计划（初始连接顺序、连接算法、批次到达顺序与每批行数）、初始统计快照（估计选择率与基数）以及重优化配置（漂移阈值、重优化冷却逻辑毫秒、切换代价预算、定点标度、浮点容差、逻辑时钟步进）。数据由确定性生成器按表描述与种子产出，不依赖任何外部数据源，也不依赖特定硬件。

任务环境与准备：
安装 Python 3.11 或以上版本，并用 pip 安装 numpy 与 pytest（版本以 pip 解析结果为准）。
确认系统自带 sqlite3 模块可用，工作区目录可读写；样本与预期结果全部由题目内确定性生成器与清单产出，不使用任何外部数据集或网络服务。
在空白工作区创建项目目录并预留本地块/分片目录与 SQLite 数据库文件位置，运行时以相对路径引用，保证在不同 Windows 机器上可重复。
用于并发与强制终止验证的测试脚本以本地启动的多个子进程模拟并行实例，并在指定批次边界主动结束进程以验证恢复路径。

业务要求：
1. 实现表描述、流式查询计划与初始统计快照的解析校验：表名唯一、行数与 NDV 关系合法、列宽为正整数、连接谓词两端列存在且类型可比、批次到达顺序唯一且每批行数为正整数、初始选择率在开区间内；非法输入必须返回明确业务错误码（如 E_BAD_PLAN、E_BAD_STATS）且不写入任何持久化状态。
2. 实现确定性流式批次生成与连接算子分批执行：按表描述、全局种子与到达顺序产出列式数组，倾斜键按声明比例集中分布，相同种子必须逐位复现每批摘要；连接按计划的顺序与算法逐批推进，每批实测输入行数、输出行数与选择率只能由该批已提交的完整结果导出，不得用后续批次信息回填，使观测在时间上真实可得。
3. 实现代价模型漂移判定与重优化触发裁决：以初始估计与实测观测计算偏差比，按漂移阈值与重优化冷却逻辑毫秒裁决是否触发重优化；触发时必须输出漂移来源（表与连接键）、偏差比、观测所用批次区间、触发依据与阈值余量，并给出冷却窗口内被抑制的重优化请求及其原因。
4. 实现重优化后的执行形态切换与切换代价预算裁决：切换只能发生在批次边界，进行中的批次必须按原形态完成；在切换代价预算内决定改为哪一连接顺序与算法并记录被否决候选及原因，预算不足必须保留原形态并返回 E_SWITCH_BUDGET，不得以降级结果冒充已切换。
5. 实现漂移观测的误差账本与精度敏感标记：记录每个观测点与每次偏差比计算中定点换算与浮点累计的误差上界，当两个候选执行形态的估计总代价差小于容差且切换裁决依赖该差值时标记为精度敏感，输出误差来源链（参与表、观测批次区间、换算标度与舍入方向），并使用更高精度通路复核以便判定标记结论是否稳健。
6. 实现执行形态整体替换与批次水位的持久化推进：每次切换产生新形态版本号并以内容摘要整体替换当前形态指针而非逐条覆盖，需识别完整替换、增量追加与无需操作并拒绝版本回退；把批次水位、已提交批次摘要、当前形态、漂移累计与触发记录以事务原子写入 SQLite，状态只能依据已提交批次推进，摘要不匹配必须拒绝推进。
7. 实现强制终止后的恢复裁决与多进程并发一致：进程在批次执行或形态替换中途被强制终止后，恢复路径依据持久化状态识别已提交批次与半提交形态，只重放缺失批次且不得重复累计漂移观测；多个执行实例并行推进同一计划的不同批次时，通过 SQLite 事务与文件锁保证同一批次同一形态版本只提交一次、重复提交幂等。
8. 实现异常链路隔离与可重复命令行验证：批次摘要不匹配、类型不匹配、漂移观测样本数为零、切换预算非法、形态版本回退分别映射到不同业务错误码并保留可诊断字段，单个异常不得中断其他不受影响批次的已提交状态；提供 run、resume、status、verify 子命令，verify 以单进程串行执行作为真值对照并输出一致性结论与漂移证据。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证流式连接、漂移触发、形态切换与强制终止后恢复续算的结果一致性和错误码。
