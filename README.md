这是一个预算和周期已确认的新项目，团队在本地 Linux（WSL Ubuntu）工作区从零开始。当前目录没有代码、样本或历史实现，需要交付一个可集成领域组件与完整示例。业务目标是验证受控混沌实验的预算账户与中断恢复一致性：实验由本地固定种子脚本确定性生成，不依赖真实集群、外部服务或网络。输入包括实验计划（实验 ID、目标服务、故障类型、故障参数、启动逻辑时钟毫秒、预期持续时长、优先级）、预算配置（每实验预算额度、每轮总逻辑时间预算、全局并发实验上限、退避基数与上限）、观测事件流（事件序号、实验 ID、观测类型为卡点/完成/失败/恢复、观测逻辑时钟毫秒、观测摘要）以及两代预算策略快照。系统需要把每次实验的执行推进建模为受控状态机，在注入逻辑时钟下裁决预算扣减、并发准入与中断恢复，必须同时保证预算账户不会超扣、状态恢复后不重不漏，并能对每个决策给出可复现、可追溯的证据链。

任务环境与准备：
在 Linux（WSL Ubuntu）中安装 Python 3.10 或更高版本。
执行 python -m pip install --user pytest 安装 pytest。
执行 python -m pip install --user numpy 安装 numpy。
执行 mkdir -p sample_data && python generate_samples.py 生成固定种子样本，得到 JSON 输入文件。
执行 python main.py status 验证程序加载样本，不依赖任何网络或外部服务。

业务要求：
1. 解析并校验实验计划、预算配置、观测事件流与两代预算策略快照，实验 ID 唯一，启动逻辑时钟毫秒为非负整数，预期持续时长与退避参数均为正整数，观测事件序号在实验内严格递增，观测摘要与声明内容一致，任何畸形输入必须返回明确业务错误码且不写任何持久化状态。
2. 把两代预算策略快照合并为统一预算视图，同一策略键在 v1 单文件 JSON 与 v2 分片 JSON 加 SQLite 元数据同时存在时，依据声明的逻辑时钟与策略代数裁决最新版本，逻辑时钟相同按来源格式优先级裁决，v1 相对生效秒数在注入逻辑时钟下换算为绝对毫秒并记录换算标度与舍入方向。
3. 在注入逻辑时钟下驱动实验状态机，实验在待准入、执行中、卡点等待、已完成、已失败、已恢复之间迁移，迁移判定只依据注入的逻辑时钟毫秒值与持久化状态，不读取系统墙钟，同一逻辑时钟序列下重复运行得到逐位一致的状态序列。
4. 实现预算账户的原子扣减与恢复，每次实验准入或阶段推进必须在同一 SQLite 事务内更新剩余预算并登记决策序号，任意时刻预算余额不得为负，同一实验重复提交相同观测必须幂等且不得二次扣减，预算不足时实验必须拒绝准入并记录首个触发约束。
5. 在每轮逻辑时间预算与全局并发实验上限双重约束下调度实验准入，每轮按实验优先级与启动逻辑时钟稳定排序，并发数耗尽或预算不足时放弃剩余候选并严格区分预算内未启动、启动后失败与主动放弃三类结局，放弃原因必须可追溯。
6. 基于注入逻辑时钟实现失败退避与恢复编排，实验失败按连续失败次数、退避基数与上限计算下一次可启动逻辑时刻并施加确定性抖动，恢复事件校验实验身份与历史代数，恢复后预算账户必须按规则补足或扣减，同一恢复请求重复提交幂等。
7. 强制终止后的恢复一致性，把实验状态、预算账户、决策序号、退避截止时刻与逻辑时钟水位以单事务原子写入 SQLite，进程在准入、扣减或观测提交中途被强制终止后，恢复路径依据持久化状态识别已提交与半提交记录，只重放缺失部分且不改变既有证据链。
8. 支持多进程并发一致性与可重复命令行演示，多个引擎实例并行处理不同实验时，通过 SQLite 事务与文件锁保证同一实验同一版本只被准入一次、预算账户不被并发超扣、重复提交相同决策幂等，提供 load、run、observe、resume、status、verify 子命令，status 以稳定排序 JSON 输出每个实验的状态、剩余预算与决策摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
