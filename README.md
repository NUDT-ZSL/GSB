团队在一台干净的 Windows 开发机上为新立项的游戏配音与播客交付流水线准备第一份可运行代码，目录里除随工程交付的固定种子脚本外没有任何文件。同一批节目素材要并行产出多档广播交付物，每档需要做门限式响度测量、动态范围预算评估，并根据结论决定是否压限或施加增益校正，最后按目标采样率与位深封装并输出测量报告。素材与配置全部由固定种子脚本确定性生成，不依赖真实音频库、外部服务或网络。业务对象是本地单声道或立体声 WAV 样本、一个 JSON 测量任务描述（含各输入路径、声道布局与权重、统计窗口、门限参数、动态范围上下界、目标采样率与输出位深、并发上限、在途解码缓冲预算、异常注入清单）以及两代测量口径快照：v1 为单文件 JSON，按输入记录判据名、指标阈值、窗口长度与相对生效秒数；v2 为分片 JSON 加 SQLite 元数据库，记录规范输入标识、绝对生效毫秒时间戳、口径代数、墓碑标记与压限建议规则。需要把两代口径合并为统一判据视图后驱动测量与预算判定。

任务环境与准备：
Windows 10/11 本地工作区，Python 3.11 及以上安装到 PATH，安装命令：python -m pip install numpy
确认 sqlite3 随 Python 标准库可用（无需额外安装），不引入任何音频或科学计算外部包
在空目录中创建工程，用随题提供的固定种子脚本生成 WAV 样本、任务描述 JSON、两代口径快照与异常注入清单
运行前确认临时目录可写，所有输入输出与状态目录都位于工作区内，不访问网络

业务要求：
1. 实现任务描述、WAV 文件头与两代口径快照的解析校验：校验采样率属于允许集合、位深为 16 或 24、声道数与声明布局一致、声道权重为有限非负数、窗口长度为正整数、门限参数与动态范围界满足定义域，非法条目按输入标识返回可区分的 E_xxx 业务码并继续处理其余输入。
2. 实现两代测量口径合并为统一判据视图：将 v1 的相对生效秒数按元数据换算为绝对逻辑毫秒，同代同规范输入标识按口径代数取新且墓碑优先于无墓碑记录，两代对同一判据的阈值窗口冲突时按代数与生效时刻裁决并逐条产出可定位到快照来源的冲突项。
3. 实现两阶段门限响度测量：先按统计窗口计算声道加权均方能量，再以相对门限与绝对门限两级筛选有效窗口，积分响度只由通过门限的窗口决定；窗口起止与输入采样点严格对齐，末尾不足一窗的样本按合并口径中的确定规则处理，全静音须给出明确结果而非未定义值。
4. 实现动态范围预算评估与建议动作：按短期响度序列计算峰值与响度范围，依据合并视图中的上下界判定是否越界并给出增益调整量或压限建议；判定只依赖已提交的测量值，与调度完成顺序无关，且在两代口径仅有建议规则变化时复用已完成测量、只重算判定。
5. 实现并行解码与双预算调度：按并发上限使用有界线程池并行解码与测量各输入，同时在途解码缓冲与采样数据总量不超过内存预算，超出时按输入声明顺序让部分输入等待而非降低窗口精度或加权口径；任一输入失败时取消其余待处理任务并返回首个错误，但已完成条目的结果保留。
6. 实现确定性归并与异常汇总报告：多输入结果按输入清单声明顺序而非完成顺序写入报告，报告含每输入输入帧数、门限窗口数、加权响度、动态范围判定、建议动作与业务码；异常注入清单要求对指定输入注入非法位深、错误采样率声明或损坏分片快照，每条注入项须在报告中可追溯。
7. 实现输出转码与报告一致性原子提交：将通过与未通过判定的输入按目标采样率与位深写出，采用有理数比重采样且输出帧数与理论值误差不超过 1 个目标采样点，24 位按小端三字节封装；音频与报告先写同目录临时文件再整体替换，替换前读取已有输出的帧数与版本标识，版本不同才替换，任一写出失败时两者都保持旧版本。
8. 实现口径快照摘要校验、分块持久化与中断恢复：对每份口径快照与测量分块计算内容摘要，摘要不匹配、缺失或声明窗口数与实际不符时判定失效并返回 E_DIGEST，恢复时回退到最近有效分块或重做；可处理终止信号只在输入边界或窗口分块边界生效并写入中断标记与约定整数退出码，强制终止后仅依据已持久化且摘要有效的分块恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证两代口径合并、并行测量与数字预算判定，并核验中断恢复与原子提交结果。
