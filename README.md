需要在一个空白工作区中实现一个面向本地镜像构建流水线的“分层构建缓存服务”，用于模拟云原生场景下容器镜像按层复用的真实机制。服务接收构建计划（基础层引用、指令序列、层内容摘要、目标标签），按内容寻址计算层键，命中缓存时复用已有层，未命中时生成新层并持久化。构建过程必须支持并发构建请求、构建中途失败与进程重启后的状态恢复，并维护标签到清单的版本化映射。构建状态通过 SQLite 持久化，构建事件通过本地 HTTP 接口暴露，客户端可查询、取消与重放构建。由于缓存层是纯本地确定性的，层内容用给定样本目录中的文件计算摘要产生，不依赖任何在线镜像仓库或容器运行时；所有指令都在普通文件系统中表达。该场景的核心难点是缓存命中判定、构建状态演进（排队→构建→成功/失败/取消）、并发构建对同一层的争用，以及崩溃重启后从持久化状态恢复而不是从内存状态重建的一致性。

任务环境与准备：
使用 Python 3.11 及以上版本，创建虚拟环境并安装 fastapi、uvicorn、pytest、httpx。
在空白工作区初始化项目目录，创建本地样本目录并放入若干文本文件，用于确定性层内容摘要。
确认 SQLite 由 Python 标准库提供，无需额外服务；所有测试通过本地回环地址访问接口。
在 Windows 终端中运行 pytest，确保不依赖网络、容器或镜像仓库。

业务要求：
1. 实现构建计划的解析与层键推导：每条指令由操作类型（COPY、RUN、ENV、LABEL）、作用路径和内容摘要组成，层键必须按父层键与指令内容做确定性哈希，同一条指令在不同父层下不得误命中，且必须支持基础层引用为空的情况。
2. 实现 SQLite 持久化的层缓存与标签清单：层记录包含层键、内容摘要、大小、创建序号和引用计数；标签记录包含标签名、清单版本号、层键列表与生成时间。标签更新必须是版本递增的，重新推送相同标签时必须能被识别为版本变化，而不是无条件覆盖。
3. 实现构建任务的状态机：合法状态为 queued、running、succeeded、failed、canceled，非法迁移必须被拒绝并返回业务错误码 E_INVALID_TRANSITION。取消只能作用于 queued 与 running，取消 running 时必须记录已完成的层并保留其缓存条目。
4. 实现并发构建的层争用控制：当多个构建请求同时需要同一个未命中层键时，只能有一个构建真正生成该层，其余构建必须等待并复用结果；等待方失败时不得污染缓存，必须保证同一层键在数据库中只有一条有效记录。
5. 实现进程重启后的状态恢复：服务启动时必须扫描持久化状态，将中断的 running 构建标记为 failed 并写入错误码 E_INTERRUPTED，恢复标签清单与引用计数的一致性，已成功完成的层仍可被后续构建命中，且恢复过程可重复执行而不改变结果。
6. 实现构建事件与查询接口：通过本地 HTTP 提供创建构建、查询构建状态与事件序列、取消构建、查询标签清单的接口。事件必须按序号严格递增且可重复读取，构建失败时事件中要包含失败指令序号与错误码，JSON 字段名与错误码需保持一致。
7. 实现缓存淘汰与引用一致性：提供按容量上限触发淘汰的接口，淘汰时只能删除引用计数为零的层，且必须保证任何标签当前清单引用的层不被删除；淘汰与并发构建同时发生时，不能删除正在被构建等待的层键，结果必须可重复。
8. 提供可重复的本地演示与测试：使用本地样本目录生成确定性的层内容摘要，提供 pytest 用例覆盖命中复用、非法状态迁移、并发争用、重启恢复、标签版本变化与淘汰边界，测试需在 Windows 上可离线运行且多次执行结果一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
在 Windows 本地运行 pytest，验证缓存命中、状态迁移、并发争用、重启恢复与淘汰边界均符合预期。
