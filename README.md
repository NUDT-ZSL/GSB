在游戏动捕配音与多设备现场采集场景中，工程组使用多台采集设备同时录制不同通道（部分设备 44.1kHz 16bit、部分 48kHz 24bit、部分 96kHz 24bit），每台设备有自己的本地时钟，启动时刻与运行速率存在偏差，设备会在录制中产生时钟漂移。采集结束后需要把各通道统一到一条参考时间轴上，生成可编辑的多通道工程，并在编辑器中查看与校准每次采集之间的偏移、漂移与格式差异。当前是空白工作区，需从零开发一个本地桌面工作台。所有多通道 WAV 样本与采集元数据（设备标识、声道数、采样率、位深、声明起始时刻、漂移率、格式版本）由程序按确定性规则生成本地样本，不依赖真实设备、网络或外部音频。格式版本之间存在字段增删与单位变化，工程文件也需支持版本迁移。

任务环境与准备：
安装 Python 3.11 及以上版本，并在空白工作区创建虚拟环境。
安装 numpy 与 PySide6，版本以本地 wheel 可离线安装为准，不引入音频处理或自动微分外部库。
运行前用题目自带样本生成脚本在本地生成多设备多通道 WAV 与会话 JSON，种子固定以保证可复现。
确认运行平台为 Windows，桌面会话可启动本地窗口；不依赖真实采集设备、网络或线上服务。

业务要求：
1. 实现采集会话元数据与多通道 WAV 解析校验：读取会话 JSON 与各设备 WAV，校验采样率属于允许集合、位深为 16 或 24、声道数与元数据声明一致、声明起始时刻为非负整数毫秒、漂移率为有限小数；格式版本不在支持列表时返回业务码 E_VERSION 并指明设备与字段，结构非法返回 E_SCHEMA，且不产生任何工程输出。
2. 实现多设备时钟同步与漂移校正：以会话指定的参考设备采样率为统一时间轴，按各设备声明起始时刻与漂移率把每个通道的采样点映射到参考时间轴，漂移按线性模型逐采样插值补偿，任两通道在同一参考时刻的相对误差不超过 1 个参考采样点；映射结果须同时保留整数采样索引与浮点参考时刻两种表示并写入报告。
3. 实现跨格式版本的字段互操作归一：把不同会话格式版本的元数据字段（时间单位从毫秒改为微秒、声道标签由整数改为名称、增益单位变化）按版本适配规则归一为统一内部模型，未声明适配规则且新旧版本语义不一致的字段判定为不可自动兼容并返回 E_COMPAT 指出设备与字段；归一后同一会话无论以哪个受支持版本表达，内部模型必须逐字段一致。
4. 实现采集通道编辑模型与即时重算：维护可编辑的通道列表（启用或禁用通道、调整每设备起始偏移微调量、逐通道增益、裁剪区间），任一编辑后立即重算统一时间轴上的对齐结果与逐通道有效帧数，参考设备通道被禁用时按确定规则重选参考或返回 E_REF；编辑只影响被改通道的对齐结果且与整段从头计算的差值不超过 1 个参考采样点。
5. 实现逐通道对齐报告与漂移诊断：输出 JSON 报告，含每设备输入帧数、映射后帧数、声明的起始时刻微调量、漂移率、参考时间轴起止采样点、对齐误差估计与业务码，误差估计须由同步标记（各设备样本中的确定性脉冲位置）计算并注明真值来源；漂移率超过会话阈值的设备给出 E_DRIFT 诊断但不阻止其余通道输出。
6. 实现工程文件版本迁移与原子保存：工程文件带格式版本号，加载旧版本工程时按迁移链逐级升级到当前版本并保留未知字段；保存时先写同目录临时文件再整体替换正式工程文件，替换前读取已有工程文件的版本号与内容摘要，版本或摘要变化时不得直接覆盖而须先归档旧版本，写失败保留旧工程并返回 E_SAVE。
7. 实现分块级对齐状态持久化与中断恢复：校准计算按设备与时间分块进行，每块完成后把对齐中间结果、块依赖摘要与由全部输入内容构成的版本标识原子写入状态目录；可处理终止信号只在块边界生效，写入中断标记并以约定整数退出码退出；再次启动时版本标识一致则只重算缺失块，不一致则从头重做，强制终止后仅依赖已持久化且摘要有效的块状态恢复。
8. 实现并发通道加载与资源上限：按会话中的并发上限使用有界线程池并行解码与映射各设备通道，同时在途解码缓冲与映射结果总量不得超过内存预算，超出时按设备标识确定顺序等待而非降低精度；任一通道失败时取消其余待处理任务并返回首个错误，最终对齐结果与串行逐通道处理逐采样一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地生成的多设备样本验证时钟对齐、版本迁移、编辑重算与中断恢复，并检查业务码。
