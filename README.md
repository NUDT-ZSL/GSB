在一台没有历史代码的机器上，需要从零构建一个面向多说话人会议音频的事件检测（AED）本地专业应用，核心业务问题是检测链路的增量更新与依赖失效。业务对象是本地确定性合成的 16kHz 单声道对话音频：用固定种子生成若干说话人的基频、共振峰与能量包络参数，按给定对话时间轴与增益叠加，并注入敲门、咳嗽、键盘敲击、笑声四类事件，每类由确定性波形模板拼出；伴随逐帧真值文件（帧长 20ms，字段含 frame_index、event_type、is_event、sample_start、sample_end）与会话清单（JSONL，字段含 dialog_id、seed、sample_rate、duration_ms、speaker_ids、template_version）。检测链路建模为有向无环计算图：帧级声学特征提取→事件候选检测与类型分类→时间段后处理→帧级与事件级指标聚合。工程实践中，模板库以更高版本到达、单条事件的标注被修正、帧移或最短事件时长参数被调整，都需要精确定位受影响的帧区间与事件集合，复用未受影响的上游产物，并让每条检测结论可被追溯重放。

任务环境与准备：
安装 Python 3.11 与 NumPy（pip install numpy），无需 GPU 与外部服务。
在 Windows 工作目录下新建项目根目录，运行前确认可写本地缓存目录。
准备脚本以固定种子合成 16kHz 单声道 PCM、逐帧真值文件与会话清单，样本完全本地生成。

业务要求：
1. 实现确定性的帧级声学特征提取节点：按配置的帧长与帧移切分 PCM，帧边界以样本索引精确确定，计算短时能量、过零率、谱质心与谱滚降，输出逐帧特征矩阵与帧数；同一 dialog_id、同一 seed 与同一配置下必须逐字节产出相同特征矩阵，帧数与 duration_ms 不一致时返回 E_FRAME_MISMATCH 并指明会话。
2. 实现事件候选检测与类型分类节点：对每个帧窗口按确定性波形模板计算候选事件得分，同分时按事件类型编号升序、再按帧索引升序打破平局，输出候选事件列表（含起止帧、类型、置信度）；事件类型必须来自受控集合，违反返回 E_EVENT_TYPE_INVALID。
3. 实现事件时间段后处理节点：对候选事件按最短事件时长与最短间隔合并，输出毫秒级起止列表，保证按时间升序、互不重叠且落在音频时长内，违反分别返回 E_OVERLAP 与 E_OUT_OF_RANGE；后处理结果必须可由候选明细独立重建。
4. 实现内容寻址缓存与缓存键构造：特征、候选检测、时间段后处理与指标聚合各节点产物附带内容哈希写入本地缓存目录，缓存键须纳入音频分块内容哈希、模板库版本、帧移参数、最短时长与间隔参数以及上游节点哈希；键相同必须复用快照，键不同必须重算，且可按节点名查询键组成与产物哈希。
5. 实现增量更新的依赖失效传播：当模板库提升版本、修正单条事件真值、调整帧移或最短事件时长时，计算受影响节点与受影响帧区间及事件集合，复用未受影响上游缓存，仅重算受影响后缀；须输出本次重算节点清单、受影响时间区间与复用节点清单，并保证结果与整体重算逐字节一致。
6. 实现检测结论追溯与过期结果拒绝：每条事件检测结论须记录所用缓存键、模板库版本、特征版本与节点路径，可按记录重放出相同事件类型、毫秒起止与置信度；当缓存键任一依赖版本已变化而结论仍来自旧键时返回 E_STALE_RESULT 并指出事件编号与旧版本。
7. 实现快照版本化整体替换与并发提交控制：缓存条目、模板库与检测结果摘要快照各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换而非增量修补，回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符返回 E_CACHE_CORRUPT；并发提交冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待。
8. 实现输入与配置校验链路、资源上限及跨节点一致性自检，并提供本地可交互专业应用与可重复演示：采样率非 16000、帧移超过帧长、重复 dialog_id、模板版本未知分别返回结构化业务码；为逐帧特征驻留内存、缓存条目总量与并行重算节点数设可配置上限；应用展示计算图拓扑、各节点命中或重算状态、失效传播覆盖区间、逐事件明细与指标，并支持触发一次增量演示。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
