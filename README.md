当前是空白工作区，需要从零构建一个多租户共享记录集的事务仲裁应用，核心不是实现 MVCC 可见性判定，而是把写写冲突的检测、裁决与消解做成可复现、可追溯的账本。样本以本地 JSON 给出：租户与表描述（租户名、表名、列与类型、每表可声明的冲突消解策略标签）、并发事务脚本（每个事务声明租户、事务开始逻辑时钟毫秒、隔离级别与有序写操作：插入、更新指定列、删除、断言型条件更新），以及仲裁配置（冲突判定容差、逻辑时钟步进、冲突回放次数上限、账本保留代数）。引擎需按提交顺序检测并发事务对同一行或同一列的写写冲突，依据消解策略（后写胜、列合并、拒绝并回滚、人工介入挂起）给出裁决，输出每笔冲突的证据链（双方事务号、被争用的行键与列、各自写入前后值、适用策略与裁决结果），并保证相同脚本在任意运行次数下得到逐位一致的裁决账本与最终记录集。核心矛盾在于：条件更新断言必须在裁决时刻重新求值而不能沿用脚本录制时的观察，列合并策略必须与整行覆盖策略共存于同一张表而不得相互静默覆盖，账本整体替换又要保证正在裁决中的冲突不读到新旧混合的消解策略。

任务环境与准备：
安装 Python 3.11 及以上版本，确认标准库 sqlite3 可用，执行 python -c "import sqlite3" 检查。
在工作区根目录创建本地样本目录 samples/，放入租户表描述、并发事务脚本与仲裁配置文件，全部由本地脚本确定性生成，不访问任何外部服务。
准备一个空白 SQLite 数据库文件用于提交序列表、冲突账本与策略版本指针，运行前无需预置数据。
确认本地文件系统支持临时文件原子重命名，用于账本与策略指针的整体替换。

业务要求：
1. 实现租户表描述、并发事务脚本与仲裁配置的解析校验：表名列名在租户内唯一、列类型枚举合法、每表声明的冲突消解策略标签必须来自闭合枚举集合且整行覆盖与逐列合并策略不得在同表对同一列同时生效、事务号与逻辑时钟毫秒为正整数、写操作引用的列存在且类型相容；非法输入须返回明确业务错误码（如 E_BAD_SCRIPT）且不写入任何持久化状态。
2. 实现写操作的暂存与提交顺序表：事务内的插入、更新指定列、删除先进入各自暂存区并记录目标行键、涉及列的前后值与条件更新断言，提交时按事务号与提交逻辑时钟写入有序提交序列表；同一事务内对同一行同一列的多次更新须合并为一次最终写入并保留中间值审计，未提交事务的暂存写入不得进入最终记录集。
3. 实现写写冲突检测与冲突窗口定义：同一行键上两个已提交或待裁决事务的写入区间重叠即构成冲突，逐列比较写入列集合，整行覆盖视为覆盖全部列；须区分真冲突与因两事务写入列集合不相交而可安全并存的伪冲突，并输出每条冲突的争用键、争用列、双方事务号与检出依据。
4. 实现冲突消解策略的裁决执行：后写胜按提交逻辑时钟取后者、逐列合并须对每个不相交列取各自写入值并在同列冲突时按策略声明裁决、拒绝回滚须撤销后提交方的全部写入且保持先提交方结果、人工介入须挂起该行并输出挂起证据；任何裁决都不得产生未被证据链覆盖的最终值，同一冲突重复裁决须给出相同结果。
5. 实现条件更新断言在裁决时刻的重新求值：条件更新的谓词必须在冲突裁决时基于已提交记录集重新求值，断言不再成立的事务须被判定为失效并回滚或转为人工介入，不得沿用脚本录制时的旧观察；须输出断言原文、求值所依据的记录版本与求值结果，并使相同脚本得到逐位一致的失效判定。
6. 实现冲突账本的证据链持久化与整体替换：每笔冲突的证据链记录争用键、列、双方事务号、前后值、适用策略、裁决结果与被否决候选策略，以事务原子写入 SQLite；消解策略配置每次变更产生新版本并以临时表加版本号整体替换当前策略指针而非逐条覆盖，进行中的冲突裁决必须绑定开始时的策略版本直至结束，读者不得观察到新旧策略混合。
7. 实现强制终止后的恢复裁决：把提交序列表水位、待裁决冲突集合摘要、行级挂起标记、策略版本指针与逻辑时钟水位以事务原子写入 SQLite；进程在暂存提交或裁决中途被强制终止后，恢复路径须识别已提交写入与半提交事务，只重做未裁决冲突且不得重复回滚或重复合并已决冲突，恢复后账本与最终记录集须与不中断运行逐位一致。
8. 实现多进程并发一致性与可重复命令行验证：多个写入进程并行提交不同事务时通过 SQLite 事务与文件锁保证同一事务号同一版本只提交一次、同一行同一列不被并发合并覆盖、重复提交相同事务幂等；提供 apply、conflict、resolve、resume、status、verify 子命令，verify 校验最终记录集、冲突账本与全量顺序重放结果一致，status 以稳定排序 JSON 输出各表行级挂起标记与冲突统计。
