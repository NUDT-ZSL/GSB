为指令微调（SFT）数据工程团队从零构建一个本地可运行的指令数据构造与诊断工作台，核心问题是数值精度与误差传播。输入是本地样本目录：一份原始指令样本 JSONL，每条含样本 id、来源、指令文本、输入文本、输出文本、token 计数与人工质量分（浮点，位于 [0,1]）；一份模板规则文件，声明若干指令模板及其权重、以及模板套用后的期望结构标记；一份评分口径配置，声明各质量因子权重与阈值。团队需要据此完成模板套用、质量加权打分与低质过滤，构造可直接用于微调的样本集合，并诊断每一处数值运算带来的误差如何沿模板选择、打分与过滤链路传播到最终保留集合。工作区为空，需从零创建可用于诊断的 FastAPI 服务。

任务环境与准备：
准备 Windows 本地工作区并安装 Python 3.11，创建虚拟环境。
安装 FastAPI、uvicorn、NumPy 与标准库 sqlite3，版本以本地可用为准。
在样本目录放置固定的指令样本 JSONL、模板规则文件与评分口径配置，作为本地确定性输入。
准备可复现的启动命令与等价请求示例，用于演示入口与服务接口验证。

业务要求：
1. 服务入口接收样本目录、模板规则文件、评分口径配置与浮点容差，校验样本字段完整、人工质量分位于 [0,1]、模板权重非负且和为 1、容差为正小数；任一项非法返回 E_PARAM 业务码并指出出错文件与行号，且不得创建结果文件或临时目录。
2. 模板套用须按每条样本的指令特征在候选模板上做确定性打分，得分由模板权重与特征匹配度的乘积累加得到；须以 NumPy float64 在 log 域累加避免乘积累乘下溢，同分时按模板 id 字典序稳定选择，输出须携带被选模板 id 与对数得分。
3. 质量加权打分须把人工质量分、长度因子与模板得分按配置权重合成，所有中间量须保留 float64 且输出每因子的原始值、权重与乘积累加顺序；同一输入与配置下逐样本得分须逐位可重复，不得依赖字典遍历顺序或未排序集合。
4. 误差传播须可观测：每个样本的最终得分须附带由各因子相对误差与权重平方和合成的不确定度，并按容差标记得分是否稳定；不确定度与稳定性标记须能定位到具体因子，超出容差的样本不得被静默计入保留集合。
5. 过滤规则须按评分阈值与稳定标记共同决策，被过滤样本须记录触发因子与阈值差；阈值配置非法、因子权重为负或和不为 1 时返回 E_SCORE 业务码并指出配置项，禁止在错误配置下产出看似正常的保留集合。
6. 每次构造须以整体替换方式生成版本化快照，含配置指纹、逐样本得分与不确定度摘要、保留集合内容哈希；读取快照时若检测到数据库版本与结果文件哈希不一致或配置指纹变化，须返回 E_STALE 并定位到版本与样本，禁止汇入旧结果。
7. 样本构造进度须在 SQLite 中以样本粒度事务提交，得分与过滤结果原子写入；进程被强制终止后重启须核对已提交样本的结果哈希，重算未提交样本且不重复计分，恢复后的保留集合与快照版本序列须与无中断执行完全一致。
8. 须提供诊断工作台接口与确定性演示入口：输出候选模板命中分布、各质量因子误差贡献、被过滤样本的触发因子计数、保留集合大小与快照版本序列；演示使用固定样本与配置跑出可重复结果，并给出可用等价参数复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定样本验证模板套用、误差传播诊断、过滤决策与快照恢复的可重复一致性。
