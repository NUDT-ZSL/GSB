在空白工作区从零实现一个本地查询执行引擎中的联接与 Shuffle 组件，用于在确定性样本上复现数据规模变化时的算法取舍与可复现实验。本地 JSON 样本给出：左右两侧表描述（表名、行数、连接键列、每列 NDV、列宽字节、是否带倾斜键），连接查询模板（连接类型、连接谓词与过滤选择率），以及执行配置（Shuffle 分区数、单分区内存上限 MiB、分块行数上限、倾斜键阈值、容差参数、逻辑时钟步进）。本地数据由确定性生成器按表描述与种子产出，不依赖任何外部数据源。引擎需为每次查询在广播哈希连接、分片哈希连接与排序归并连接之间依据数据规模与内存预算做出取舍，完成 Shuffle 分区、分区落盘与联接计算，并给出可比较的执行指标与真值校验。

任务环境与准备：
安装 Python 3.10 及以上版本，并确认标准库 sqlite3、multiprocessing、hashlib 可用。
安装 NumPy 1.24 及以上版本，使用 pip 安装并在本地离线环境中完成。
在空工作区创建项目目录，准备本地 JSON 样本：表描述、连接查询模板与执行配置文件各一份，样本内容自包含。
确认工作目录具备本地文件读写权限，用于分区目录、SQLite 状态库与结果文件的落盘。
执行前无需网络、真实数据库服务或 GPU，全部样本与状态均在本地生成。

业务要求：
1. 实现表描述与连接模板的解析校验：校验表名唯一、行数为正整数、连接键列存在、NDV 为正且不超过行数、列宽合法、过滤选择率在开区间内、分区数与分块行数为正整数，构建连接元数据模型；非法输入必须返回明确业务错误码（如 E_BAD_TABLE）且不写入任何持久化状态。
2. 实现确定性本地数据生成器：依据表描述与全局种子逐行生成连接键与非键列，倾斜键按声明比例集中分布，相同种子与描述在任意运行次数下必须产出逐位一致的数据摘要；生成器同时输出每表行数与连接键分布摘要作为后续估计的观测来源与真值来源。
3. 实现 Shuffle 分区与落盘：按连接键哈希把左右两侧数据划入固定数量分区，分区文件以确定性字节序写入本地目录并记录每分区行数、键摘要与大小；同一输入重复 Shuffle 必须得到逐分区逐字节一致的结果，分区行数总和必须等于输入行数且无键跨分区分裂。
4. 实现三种联接算法并按数据规模取舍：实现广播哈希连接、分片哈希连接与排序归并连接，依据每侧行数、分区后最大分区大小与单分区内存上限裁决选择哪种算法，裁决必须给出首个触发条件与被否决算法的原因；选定算法在预算内执行，预算不足时按明确规则降级而非静默溢出。
5. 实现联接结果与真值一致性校验：以固定顺序的全量单流嵌套循环算法计算唯一真值，与选定算法的联接结果逐行比对，输出不一致行数与首个差异行及其来源分区；联接类型语义（内、左外、右外）必须与真值一致，空键与重复键的处理规则须在结果中体现并可追溯。
6. 实现执行指标的规模自适应采样与可比较输出：对同一查询在不同输入规模下分别运行三种算法，输出可比较指标（耗时以注入逻辑时钟计量、峰值分区行数、溢出落盘字节、结果行数）与算法选择依据；规模采样点由配置显式给出，指标必须说明所依赖的观测与真值来源，不得凭墙钟耗时下结论。
7. 实现持久化状态与强制终止后的恢复：把查询轮次、分区提交状态、已提交分区结果摘要、算法选择决策与逻辑时钟水位以事务原子写入 SQLite，每轮提交识别版本变化并整体替换当前结果指针；进程在 Shuffle 或联接中途被强制终止后，恢复路径依据持久化状态识别已提交与半写入分区，只重算缺失分区，恢复后结果与账本必须一致。
8. 实现多进程并发一致性与可重复命令行演示：允许多个执行实例并行处理同一查询的不同分区，通过 SQLite 事务与文件锁保证同一查询同一分区版本只提交一次，重复提交相同分区结果必须幂等，读取方只能看到完整已提交分区；提供 plan、run、resume、status、verify 子命令，status 以稳定排序 JSON 输出算法选择、各分区行数与提交状态，verify 校验持久化状态与结果一致性。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本验证分区、算法取舍、联接结果与真值一致及中断恢复一致性，附运行输出。
