迁移计划确定后，团队需要在 Linux（WSL Ubuntu）空白工作区独立实现一个本地可集成组件与完整示例，用于诊断 LLM 推理采样链路中 TopK 与采样算子在多种任务描述格式和参数版本演进下的互操作性与结果一致性。工作区当前没有任何代码或样本，全部输入由随工程交付的固定种子脚本确定性生成，不依赖真实模型、外部服务或网络。业务对象是本地生成的算子任务清单：任务描述存在三种并存格式，v1 为单文件 JSON 扁平表记录相对生效秒与基础参数，v2 为分片 JSON 加 SQLite 元数据库记录绝对毫秒时间、分块方案与扩展采样参数，v3 为结构化嵌套格式引入候选掩码、误差预算与增量修订号；同一批任务会以不同格式到达，需要先归一化为统一内部表示，再执行 TopK 筛选、温度缩放与 top_p 截断、确定性采样，并输出候选集合、采样序列、误差谱与格式迁移记录。核心难点是格式迁移不能丢失语义约束：v1 无法表达的嵌套掩码与增量修订信息在降级时必须按显式规则处理，任何迁移错误都可能导致后续算子的缓存键错配或采样结果被判为过期。

任务环境与准备：
在 Linux（WSL Ubuntu）环境预装 Python 3.10+ 与 NumPy、SQLite3 标准库，无需 GPU 或外部网络。
使用固定种子生成本地 JSON、JSONL 与 SQLite 样本，覆盖三种任务格式、候选掩码与增量修订字段，确保样本可重复。
题目执行前确保工作区为空，样本生成脚本由交付物自动提供，不依赖真实模型或数据集。

业务要求：
1. 实现 v1、v2、v3 三种任务描述格式的读取器，按版本头或字段集分派解析路径；未知版本返回 E_VERSION_UNSUPPORTED，字段缺失、数值不可解析、分片时间戳倒退或 SQLite 元数据与分片 JSON 不一致时返回 E_FORMAT_CORRUPT 并指明具体字段与行号。
2. 实现三套格式到统一内部表示的双向迁移器：升级时补全分块方案、候选掩码、误差预算与增量修订号的默认值并逐项记录补全来源；降级到 v1 时对无法表达的嵌套掩码与增量修订号按显式声明的丢弃或展平规则处理，迁移后所有任务字段必须完整且在统一表示中可互相校验。
3. 实现确定性的 TopK 筛选与温度缩放：按任务的 k_mode（top_k 或 top_p）、k_value、temperature 与 tie_policy 处理 logits，候选集合按分数降序、同分按索引升序打破平局；同一任务、同一参数版本与同一配置下必须逐字节产出相同候选集合与候选顺序，任何平局规则未显式声明的情况返回 E_TIE_POLICY_UNSPECIFIED。
4. 实现 top_p 截断与候选掩码的联合过滤：在累积概率达到 top_p 时截断候选，候选掩码中的显式排除位置必须在截断前移除且不得被后续采样选中；掩码与 k_value 同时存在时按配置优先级处理，优先级缺失或非法时返回 E_MASK_PRIORITY_INVALID，并输出每个被移除候选的索引与原因。
5. 实现基于固定种子与显式随机数生成器的确定性采样，每个候选按温度缩放与 top_p 截断后的概率分布逐 token 抽取，采样序列与候选顺序完全一致；同一任务、同一种子与同一精度配置下采样结果逐字节相同，任何随机数生成器未显式声明种子时返回 E_SEED_UNSPECIFIED。
6. 实现误差谱诊断：以 float64 全精度路径为参考真值，输出候选分数偏差、采样序列一致性与最大绝对偏差；偏差超过配置容差时返回 E_TOLERANCE_EXCEEDED 并指出 case_id、出现偏差的候选索引与阶段，同时提供可切换的舍入模式与次正规数保护记录。
7. 实现任务描述与采样结果的版本化快照管理：任务快照、参数快照与结果快照各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK；并发提交同一快照时后到者立即获得 E_STAGE_BUSY 而不阻塞等待。
8. 实现输入与配置校验、跨格式一致性自检及可集成的完整示例：重复 case_id、logits 维度与任务参数不符、任务描述迁移后语义不完整分别返回 E_DUP_CASE、E_SHAPE_MISMATCH、E_SEMANTIC_INCOMPLETE；自检须逐任务重算候选与采样结果，三格式归一化后同一任务的采样序列和误差谱完全一致，不一致返回 E_INCONSISTENT 并输出首个偏差位置。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
