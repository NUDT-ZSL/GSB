某动作游戏项目立项后，工作区仍为空目录，团队要交付一套离线骨骼动画关键帧编辑与重算组件，让动画师在时间轴上局部调整动作后快速看到结果。全部输入由本地固定种子脚本确定性生成：骨架层级声明（骨骼名、父骨、静止位姿局部变换、骨段长度）、每个动画片段的关键帧轨道（每根骨骼每个通道的关键帧时刻与数值）、状态机转移规则（参数阈值、打断优先级、循环次数）以及一份编辑脚本，按顺序描述对关键帧、通道数值、片段时长与转移条件的增删改。组件要在整数逻辑毫秒时间轴上逐帧求出骨骼姿态，编辑后只重算受影响的帧与骨骼，其余结果复用持久化快照，并保证增量结果与同一输入从头全量求值逐帧逐通道一致。真实难点是失效闭包：一根骨骼的局部修改会沿父链影响子骨、沿状态机影响后续片段切换，而片段时长变化又会移动其后所有片段的时间边界，需要在有限预算内精确算出需要重算的分块集合。

任务环境与准备：
安装 Python 3.11 或更高版本，并执行 pip install numpy；SQLite 使用标准库 sqlite3，无需额外安装。
在工作区创建 samples 目录，由本地固定种子脚本生成骨架声明、关键帧轨道、状态机规则、编辑脚本与分块规格样本，不依赖任何外部资源。
Windows 环境需支持发送可处理终端的信号模拟（如通过测试脚本触发的进程事件），确保中断与恢复路径可被本地复现实验验证。

业务要求：
1. 实现骨架、关键帧轨道、状态机规则与编辑脚本的解析校验：骨骼名唯一且父骨可拓扑排序无环、静止位姿平移为有限数、关键帧时刻为非负整数且每根骨骼每通道内严格递增、通道数值为有限数、转移条件引用的参数已声明、编辑脚本算子类型属于允许集合；非法输入返回带 E_xxx 业务码的 JSON 错误且不产生任何输出产物。
2. 实现确定性逐帧姿态求值：按规格步长在整数逻辑毫秒上推进，每帧在关键帧之间按通道做线性或球面插值并按父链累乘得到全局姿态；同一输入与同一编辑脚本无论分块并发度如何，重复求值须得到逐帧逐骨骼逐分量完全相同的姿态序列与状态转移事件序列。
3. 实现状态机逐帧转移与事件流：每帧依据当前参数值与转移条件按打断优先级选出目标片段，循环片段按循环次数决定结束，片段切换时按规格处理进入时刻的姿态衔接；转移事件序列须与姿态序列同源生成，不得事后从姿态反推，事件记录须包含触发帧、来源片段、目标片段与决定性条件。
4. 实现依赖图与失效闭包计算：为每个帧区间分块记录其依赖的关键帧区间、所涉骨骼通道、片段归属与转移条件；编辑脚本任一步发生后只把沿父链可达的骨骼、被修改通道覆盖的帧区间、以及因片段时长或转移条件变化而移位受影响时间轴的分块标记为失效，并给出每个分块的失效理由，禁止无差别全量失效。
5. 实现增量重算与全量结果一致性：只对失效分块重算，在相邻保留帧处按同一插值口径衔接；增量后的整段姿态与同输入从头全量求值在逐帧逐骨骼分量上的数值差不超过规格姿态容差，状态转移事件序列完全一致；报告须列出重算块数、复用块数、移植到新时间边界的块数以及首个不一致位置（若出现）。
6. 实现分块级持久化与版本识别：每块完成后把该块姿态、转移事件、失效理由摘要与由骨架、关键帧轨道及规则规范化摘要构成的版本标识原子写入状态目录（先写临时文件再整体替换），替换前比对已有块的版本标识，标识变化时不得直接覆盖而须先归档旧版本；块内容摘要不匹配、缺失或声明帧数不符时判定该块失效并返回 E_DIGEST 且回退重算。
7. 实现并发重算与资源上限：按配置的并发上限使用有界线程池调度待算分块，同时在途的关键帧插值缓冲与姿态数据总量受内存预算约束，超出时按分块索引序让后续块等待而非降低采样精度；任一分块异常时取消其余待处理分块并返回首个错误，已成功分块结果须保留在报告中。
8. 处理可处理终止信号与强制终止的恢复边界：可处理终止信号只在分块边界生效，写入中断标记并以约定整数退出码退出，未完成分块不得留下可被误认为已完成的结果；再次启动时版本标识一致则只补算缺失块，不一致则从头重算；强制终止后重启仅依据已持久化且摘要有效的分块恢复，不承诺生成退出报告，最终姿态与报告须先写临时文件再整体替换。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
