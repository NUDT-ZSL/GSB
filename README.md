当前是空白工作区，没有现存项目、代码或数据附件。需要从零构建一个面向 Transformer 前向计算中 Softmax 与 LayerNorm 两类核心算子的本地可集成组件与完整示例，核心业务问题是分块实现下的可复现验证与异常注入。业务对象是本地确定性生成的算子任务清单（JSONL，字段含 job_id、op_kind（softmax 或 layernorm）、input_shape、block_size、axis、eps、dtype、seed、norm_mode）以及由固定种子生成的特征张量。组件需按分块策略分别实现 softmax 与 layernorm：softmax 需处理分块最大值扫描与在线归一化累加，layernorm 需处理分块均值方差统计与跨块归约；两者都要求分块结果与一次性整段参考实现在 float64 容差内一致。同时需提供由输入或参数触发的四阶段异常注入框架，每次注入产生带阶段名、业务码与 job_id 的结构化记录，并沿异常链路归因到具体阶段，下游按明确策略降级且不得静默吞掉异常。所有输出须逐字节可复现，配置与统计量快照须版本化并整体替换。

任务环境与准备：
安装 Python 3.10 及以上，仅使用标准库与 NumPy，无需 GPU 或网络。
在空白工作区创建项目目录与本地确定性样本生成脚本，样本由固定种子生成浮点张量与任务清单 JSONL。
准备本地测试命令入口，确保可在 Windows 命令行直接运行示例与固定种子重跑比对。

业务要求：
1. 实现 Softmax 与 LayerNorm 两类算子的统一分块入口，按任务清单解析 op_kind、input_shape、block_size、axis、eps 与 dtype，对未知 op_kind、axis 越界、shape 维度不符、dtype 不支持分别返回 E_OP_UNKNOWN、E_AXIS_INVALID、E_SHAPE_INVALID、E_DTYPE_UNSUPPORTED 并指明 job_id 与字段。
2. 实现确定性分块执行路径：Softmax 按分块扫描最大值并在线累加归一化分母，LayerNorm 按分块统计均值与方差并跨块归约，块边界以显式声明的元素索引确定；同一 job_id、同一 seed 与同一配置下，各分块中间统计量与最终输出必须逐字节一致，同值并列时按元素索引升序裁决。
3. 实现分块结果与一次性整段参考实现在 float64 下的逐元素一致性裁决：记录最大绝对偏差、最大相对偏差与超出容差的元素位置；超出容差返回 E_TOLERANCE_EXCEEDED 并输出越界位置与偏差量，不得通过放宽容差或跳过比较掩盖真实错误。
4. 实现四阶段异常注入框架：在输入校验、分块统计、归一化累加、输出写回四个阶段分别提供由输入或参数触发的注入点（如 eps 非正、block_size 非正、统计量溢出缩放、写回索引越界），注入不得通过修改源码制造；每次注入须产生含阶段名、业务码、job_id 与参数摘要的结构化记录。
5. 实现异常归因与降级链路：某阶段产出业务码时下游须按明确策略降级（如跳过在线归一化保留原始分块统计、以 float32 结果替代失败分块），降级结果必须携带降级类别与触发它的上游业务码；未被任何阶段归因的异常须汇总到结果并返回，禁止静默吞掉异常。
6. 实现资源上限与降级执行：为分块数量、单块驻留元素数与中间统计量内存估算设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或降级到更小分块或 float32 路径；降级须在结果中标记降级类别，且不得改变已输出分块的数值。
7. 实现配置与统计量快照的版本化管理及整体替换：分块计划、容差配置与各 job 的统计量各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK；损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明阶段名与版本号。
8. 提供可集成的领域组件接口与完整示例，并实现跨模块一致性自检：暴露 softmax、layernorm、注入诊断与快照查询入口；命令行示例读取本地确定性样本输出含分块统计、偏差谱、四阶段注入记录、降级链路、业务码与重跑哈希的 JSON 报告；自检校验各阶段处理的元素索引集合一致、偏差谱可由分块明细重算一致、降级记录可追溯到具体分块，不一致返回 E_INCONSISTENT 并指出类别。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
