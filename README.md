当前是空白工作区，需要从零构建一个面向 Windows 本地环境的块存储快照与回滚领域组件，用于教学与排障演示。系统把本地二进制样本卷（固定块大小的逻辑块设备镜像）作为存储对象，用户用命令行脚本对卷创建命名快照，快照以写时复制方式记录变更块（变更块位图加数据块引用），并允许把卷回滚到任一历史快照。核心难点在数据规模变化下的算法取舍：当变更块比例、卷块数与快照数量在样本间差异很大时，全量比对、位图扫描与增量链回放三条路径必须产生逐位一致的回滚结果；同时快照清单存在整数格式版本，回滚与快照替换必须识别版本差异并整体替换，禁止新旧快照条目增量合并。组件还须在回滚中断、块数据损坏与快照链引用缺失时给出明确业务码，并提供可集成的包接口与完整示例。

任务环境与准备：
安装 Python 3.11 及以上版本，并确认 numpy 可用（pip install numpy）。
在全新空白目录中初始化项目结构，创建本地确定性样本卷镜像生成脚本与样本快照定义文件。
准备本地演示脚本的固定参数：块大小、卷块数、变更块注入序列，全部以整数或十六进制字符串给出，不依赖网络或外部账号。
确认可在 Windows 命令行直接运行包内示例与审计命令，无需容器或数据库服务。

业务要求：
1. 实现样本卷与块操作的加载与强校验：卷由固定块大小的二进制镜像文件与整数块数描述，支持按块号读写与按十六进制参数注入确定性变更；须校验块大小为受支持的整数集合、镜像长度与块数一致、块号在范围内，非法输入以 E_VOLUME 业务码整体拒绝并输出定位信息。
2. 实现写时复制快照的创建与变更块位图维护：对卷创建命名快照时以位图记录此后被改写的块，快照只持有位图与本版本数据块引用而不复制整卷；同一名称快照不可重复创建，位图块序号与位图长度须与卷块数相容，违反约束返回 E_SNAPSHOT，创建成功后卷版本号单调递增。
3. 实现数据规模自适应的回滚执行路径：当变更块数与卷块数之比低于阈值时走位图差分路径，否则走全量块比对路径，多条快照链回滚时须以增量链回放路径合成目标状态；三条路径对同一输入必须产出逐位一致的回滚结果，报告须输出所用路径、关键规模参数与峰值内存估计整数。
4. 实现回滚过程的原子切换与中断恢复：回滚写入须先落到临时区域，全部块校验通过后再原子替换卷镜像，客户端可凭快照标识与清单版本校验回滚是否完成；回滚中途被强制终止后重启只能依据持久化的位图与临时区域标记恢复，未完成回滚不得被当为成功，也未完成部分不得污染当前卷。
5. 实现快照清单的格式版本识别与整体替换：快照清单携带整数格式版本号与内容摘要，格式版本变化或清单内容摘要不一致时须整体替换全部快照条目与位图，禁止把新旧条目增量合并；替换前的旧清单保留为只读备份，替换须在报告中标明版本差异与受影响的快照标识，并在替换后重建快照链引用。
6. 实现块数据完整性校验与异常链路：回滚前逐块比较引用块数据的摘要与清单登记摘要，不一致以 E_INTEGRITY 拒绝回滚并列出首个损坏块号；快照链引用缺失以 E_CHAIN 报告；三类业务码均写入结构化日志，且校验失败后的卷内容必须与回滚前完全一致。
7. 实现快照链一致性审计与版本化结论：提供审计命令，逐快照校验变更块位图与数据块引用集合对应关系、快照链拓扑可回放至卷初始状态、清单版本与快照版本号匹配；审计结论按版本号持久化，版本不一致时须识别差异并整体替换审计结论而不得增量追加，重复审计同一版本须得到逐项一致的结论。
8. 提供可集成的 Python 包 API 与完整示例：以包形式暴露卷加载、快照创建、回滚、清单替换、审计与日志查询接口，附带本地确定性样本镜像与演示脚本，顺序执行首次快照并回滚、多次快照链回滚、清单版本升级后整体替换三个场景，每个场景输出稳定顺序的规模参数、执行路径与校验结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
