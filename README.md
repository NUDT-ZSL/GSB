产品原型评审通过后，需要从零交付一个本地可运行组件，工作区目前没有任何既有实现。业务输入由固定种子脚本确定生成：命名实体识别结果以 JSONL 形式给出，每行包含 doc_id、sent_id、mention 列表（含实体名、类型、句子内码点区间），另有跨句共指候选清单与两代实体链接规则书并存——v1 为单文件 JSON 记录相对生效秒与扁平描述，v2 为分片 JSON 加 SQLite 元数据库记录绝对毫秒、规则代数与失效墓碑。核心任务是根据上下文证据将同一文档内的实体提及聚合成链接链，在规则版本演进和数据规模变化下保持结果可复现、可追溯并支持强制恢复。

任务环境与准备：
确认本机可用 Python 3.10+，安装 NumPy（用于确定性数值计算），SQLite 使用 Python 标准库，不依赖网络。
在项目目录运行 python3 -m pip install numpy 完成依赖安装。
用随题交付的固定种子脚本生成实体提及 JSONL、候选清单、v1/v2 规则快照及 SQLite 元数据库文件。
创建缓存和检查点子目录，执行流程应在单机 CPU 上于 12 秒内完成一次全部任务。

业务要求：
1. 实现确定性的自动推理与候选证据生成阶段：按 doc_id 和 sent_id 升序解析实体提及，利用规则快照中的上下文特征描述（实体类型、位置、句子窗口）生成候选链接对，每个候选对记录共享实体类型、位置距离、规则代数等证据分项；同一输入、同一种子与同一规则快照下必须逐字节产出相同的候选集合和证据明细，同分时按首个提及码点升序、再按类型字典序打破平局。
2. 实现精确证据聚合与近似签名剪枝双路径：精确路径对每对候选逐一比较全部特征，近似路径先按共享类型签名分桶生成候选并略过低区分度特征，两条路径必须共用同一共指判定口径和平局规则，近似路径须记录剪枝特征明细与候选桶过滤依据。
3. 实现基于规则代数、文档规模和上下文的联合证据打分：融合共享比例、距离衰减和规则代数偏置形成链接置信度，逐项记录贡献使总分可由明细独立重算一致，当同一提及出现在多个冲突候选对时按总分降序、再按规则代数升序裁决，冲突结果可回溯。
4. 实现增量链接合并与依赖失效传播：当新句子到达或某条提及被修订时，仅对关联候选对及其链接链重算证据，未受影响链接闭包必须复用已提交缓存并保持结构不变；输出受影响提及集合、重算候选对清单与触发变更的规则代数跳变依据。
5. 实现 v1、v2 规则快照的读取器与双向迁移：未知版本返回 E_VERSION_UNSUPPORTED，字段缺失或时间戳倒退返回 E_FORMAT_CORRUPT；升级时补全规则代数、失效墓碑与绝对毫秒默认值，降级时对无法表达的代数偏置按显式丢弃或折叠规则处理并写入迁移记录，迁移后内部规则表示必须逐字节一致，否则返回 E_SEMANTIC_DRIFT。
6. 实现从最终链接链到证据溯源的重放验证：任一共指结果须记录所用规则代数、证据分项哈希、缓存键与被剪枝特征列表，可按这些记录独立重放出相同链接链和置信度；当缓存键依赖版本变化而结果仍来自旧键时返回 E_STALE_LINK。
7. 实现四阶段状态机与强制终止恢复：候选生成、路径选择、证据聚合与失效传播各阶段在提及边界提交带单调递增版本号、已完成 doc_id 集与内容校验和的检查点，重启后从最近已提交检查点继续，已提交提及不得重算或重复计入；区分可处理信号、强制终止与脏检查点三种恢复情形。
8. 实现并发提交控制与跨模块一致性自检：同一时刻只允许一个检查点提交生效，冲突时后到者返回 E_STAGE_BUSY，同一会话内链接链不得重复注册；自检校验精确与近似路径结果一致、失效传播覆盖全部受影响提及、每一条链接链可追踪到全部证据明细，不一致返回 E_INCONSISTENT。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定种子样本运行完整链路，验证规则互迁、路径一致性、增量失效与恢复结果可复现。
