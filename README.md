独立的工程验证工作即将开始，当前 Linux（WSL Ubuntu）工作区中尚无代码或样本，需要在全新目录中实现一个面向索引构建与倒排压缩的本地诊断引擎，用于验证搜索推荐倒排索引在配置升级和故障恢复下的一致性。所有输入由随工程交付的固定种子脚本在本地确定性生成：文档批次 JSONL 按 batch_no 和 doc_id 升序描述词项流、词频、文档长度与内容哈希；索引配置由 v1 单文件 JSON 与 v2 分片 JSON 加 SQLite 元数据库两代格式并存，涵盖分块大小、压缩模式、差异编码步长与逻辑时钟；此外还包括可注入的故障文件和恢复指令。系统需要完成文档解析与词项分析、倒排列表构建、分块压缩、版本化账本写入，并支持配置代际迁移与状态恢复。

任务环境与准备：
在 WSL Ubuntu 上安装 Python 3.10 或更高版本。
安装 numpy 依赖：pip install numpy
Python 标准库 sqlite3 开箱可用，无需额外安装。
所有数据与缓存文件存放在本地工作目录，不依赖外部网络。
固定种子脚本用于生成确定性样本，可直接在题目实现中调用。

业务要求：
1. 实现两代索引配置的读取与双向迁移，v1 单文件 JSON 与 v2 分片 JSON 加 SQLite 元数据库均须按版本头定位解析器，字段缺失或编码值非法时返回 E_VERSION_UNSUPPORTED，同时把两代配置规范化为统一的内部参数结构，升级时补齐必要字段并记录补全来源，降级时对无法表示的增量信息按显式丢弃或展平规则处理。
2. 实现文档批次解析与词项分析阶段，按 batch_no 升序读取 JSONL 文档，校验 doc_id 唯一、词项均落在受控词表、文档长度等于词项频次总和，失败时返回 E_BAD_DOC 并指明 doc_id；对每个文档提取规范化词项流与统计摘要，确保同一输入与固定种子下词项流和摘要逐字节一致。
3. 实现倒排列表的增量构建与确定性排序，每个词项的倒排列表内部按 doc_id 升序、再按文档内位置排序，新批次到达时仅对命中词项追加；要求每个文档在列表中仅出现一次，且全局词项统计量（文档频率、位置偏移和）可独立重算验证，违反唯一性或排序错误时返回 E_POSTING_INVALID。
4. 实现可配置的分块压缩与解压，差异编码步长、分块大小与压缩模式由内部配置给出，压缩后为每个分块生成内容哈希，支持仅解码指定词项或分块以支撑失效恢复；解压序列必须与原始整数序列完全一致，块大小非正或编码模式未知时返回 E_COMPRESS_PARAM。
5. 实现配置代数提升或文档批次修订后的定向失效传播，缓存键纳入词项内容摘要、配置版本、分块参数与上游倒排哈希，当配置代数提高或某批次替换时，计算受影响词项与压缩分块集合，复用未受影响词项已压缩结果，仅重算受影响后缀并生成重算/复用清单。
6. 实现四阶段状态机的持久化检查点与故障恢复，阶段按词项分析、倒排构建、压缩、账本提交推进，检查点携带单调递增版本号、已完成批次集合和内容校验和，只有阶段内全部批次处理完成才允许以原子替换方式提交；重启后从最近已提交检查点继续，已提交批次不得重算或重复计入。
7. 实现账本与配置快照的整体替换和并发提交控制，所有账本和快照均带版本号与校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，回退尝试返回 E_SNAPSHOT_ROLLBACK，并对损坏账本返回 E_SNAPSHOT_CORRUPT；同一时刻只允许一个提交生效，并发冲突时后到者立即返回 E_STAGE_BUSY。
8. 实现输入与配置校验、资源上限和跨模块一致性自检，重复 doc_id、批次数倒退、配置版本回退分别返回 E_DUP_DOC、E_BATCH_ROLLBACK、E_CONFIG_ROLLBACK；为单次处理批次大小、驻留倒排内存和排序比较次数设可配置上限，超限时返回 E_RESOURCE_LIMIT 或按显式降级策略处理，并提供本地交互入口查询指定词项的倒排列表、压缩分块状态与最近业务码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
验证配置迁移、压缩正确性、故障恢复与一致性自检均通过。
