当前是空白工作区，需要从零实现一个本地权限与隔离边界场景下的数据处理管线，并提供结果验证工具。管线在受限权限沙箱内运行若干计算任务：每个任务由本地 JSON 清单给出任务名、所需文件系统读写范围、所需环境变量白名单、运行时限与输入数据集；计算内核是确定性的（整数与定点浮点聚合），但任务之间存在共享只读输入与共享输出文件的依赖关系。核心矛盾是交互延迟预算与计算结果一致性之间的冲突：为满足单任务交互延迟预算，管线需要并行调度与缓存中间结果；而并行、缓存与权限边界又可能使任务读到不同版本输入或进入越权路径。管线必须在不突破权限边界的前提下给出可复现的计算结果，并给出可追溯的延迟观测与一致性判定。

任务环境与准备：
确认 Windows 上可用 Python 3.11 及以上，并安装 pytest 与标准库之外的必需依赖（仅 pytest）。
在工作区根下建立 samples 目录，放入固定任务清单 JSON、输入数据集与期望摘要文件，所有路径使用相对路径。
准备一个可写的 SQLite 数据库文件路径与缓存目录，均位于工作区根内，运行前可清空以复现初始状态。

业务要求：
1. 实现任务清单与权限声明的解析校验：校验任务名唯一、读写路径位于工作区根内且不越界、环境变量白名单键名合法、运行时限为正整数毫秒、输入数据集存在且摘要可计算；越权路径、非法白名单与缺失输入必须以不同业务错误码返回，且不产生任何持久化写入。
2. 实现受限权限沙箱执行器：每个任务以独立子进程启动，工作目录限定为声明的读写范围内，环境变量仅注入白名单条目，标准输出与错误输出分离采集；任务试图写入未授权路径或读取未授权文件时须被真实拒绝并映射到独立业务错误码，不得以事后检查代替实际隔离。
3. 实现确定性计算内核与分布式结果一致性：内核按输入数据集执行整数求和、定点换算与加权聚合，运算顺序固定；同一任务在单进程串行执行与沙箱子进程执行两条路径下结果必须逐位一致，不一致时输出首个分歧字段、两条路径中间值与任务依赖来源。
4. 实现并行调度与交互延迟预算：多任务在任务级并行上限与每任务运行时限双重约束下调度，延迟以注入逻辑时钟计量；预算耗尽须放弃剩余未启动任务并记录放弃原因，区分预算内未启动、启动后失败与主动放弃三类结局，已启动任务不得被截断标注为超时。
5. 实现中间结果缓存与依赖失效裁决：以输入摘要、权限声明与内核版本为缓存键复用中间结果，上游任务结果变化或权限声明变化须使下游缓存精确失效；未受影响任务的缓存必须复用且结果不变，失效决策须输出触发来源与被失效的缓存项。
6. 实现强制终止后的恢复一致性：把任务阶段、已提交输出摘要、缓存版本与逻辑时钟水位以事务原子写入 SQLite；进程在调度或计算中途被强制终止后，恢复路径依据持久化状态识别已提交与半提交任务，只重做未完成部分，恢复后结果与不中断运行逐字段一致。
7. 实现多进程并发一致性与业务错误码链路：多个管线实例并行推进同一清单时，通过 SQLite 事务与文件锁保证同一任务同一版本结果只提交一次、缓存键只物化一次，重复提交幂等，读取方只能看到完整已提交结果；越权、超时、摘要不匹配、逻辑时钟回拨分别映射到不同业务错误码。
8. 提供结果验证工具与可重复命令行演示：支持 run、resume、status、verify 子命令，status 以稳定排序 JSON 输出每任务阶段、延迟观测值与缓存命中情况，verify 校验持久化状态、输出文件与缓存摘要的一致性；固定本地样本两次运行输出完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地样本验证沙箱越权拒绝、并行调度结果一致性、缓存失效与中断恢复，两次运行输出完全一致。
