当前是空白工作区，需要从零构建一个面向搜索与推荐前链路的多路召回融合系统，并附带可复现的实验环境。业务对象是本地确定性生成的文档集合与查询集合：文档 JSONL 每行含 doc_id、terms（term 与词频）、doc_len、category、quality_score；查询 JSONL 每行含 query_id、terms、top_k 与可选的过滤条件；另有一份融合配置，声明四路召回（词项倒排、词项前缀、类别热门、向量近似）的启用状态、各路候选数、融合权重、归一化口径、批大小与数值精度标记。系统需要在单机多进程下完成四路召回、跨路候选对齐去重、分数归一化与加权融合，并同时受总候选预算、融合比较预算与驻留内存三重约束；当预算不足时必须按显式优先级裁决降级路径而不能静默丢结果。核心难点在于并行调度的确定性可复现与预算账本的一致性：同一查询在并发执行、降级与快照切换前后必须给出一致且可复核的候选集合与分数明细。

任务环境与准备：
安装 Python 3.10 及以上，并安装 NumPy（建议 1.24 及以上），全部依赖为纯本地包，不联网。
在空白工作区直接创建项目目录，不预置任何样本文件或代码，样本由程序按固定种子确定性生成。
确认系统支持 Python 标准库 multiprocessing 的进程池，在 Windows 下工作目录可写且可创建本地缓存与快照目录。
运行前以环境变量或配置文件指定 worker 数、批大小、预算与内存上限等参数，全部参数需有显式默认值以保证可重复运行。
本地测试与演示只使用程序生成的确定性样本与本地进程池，不依赖任何外部账号、线上站点或付费资源。

业务要求：
1. 实现四路确定性召回：词项倒排按查询词项与文档词频打分，词项前缀按 term 前缀匹配，类别热门按 category 与 quality_score 排序，向量近似按固定种子生成的文档向量与查询向量做相似度排序；每路输出候选 doc_id、原始分与是否因该路候选数上限被截断的标记，同一输入与配置下各路候选集合与顺序必须逐字节可复现。
2. 实现跨路候选对齐与去重：按 doc_id 归并各路候选，同一 doc_id 在多路命中时保留每路原始分与路名，去重口径由配置在“保留最高归一化分”与“保留首路命中”之间选择；须保证最终候选集中无重复 doc_id，未命中的路必须显式记录为空而不是缺省。
3. 实现可配置的分数归一化与融合层：提供分数缩放归一化与排名倒数归一化两种口径，按融合权重加权求和；须逐候选记录每路原始分、归一化分与加权贡献，使最终分数可由明细独立重算一致，归一化口径非法或权重含负值分别返回 E_CONFIG_INVALID 并指明字段。
4. 实现并行调度层：按可配置 worker 数与每批查询数把查询分块分配给本地进程池执行四路召回与融合，分块边界、任务派发顺序与归并顺序必须确定性可复现；worker 内异常须以结构化业务码与阶段名回传主进程并归因到具体 query_id，单个查询失败不得污染其他查询结果。
5. 实现总候选预算与融合比较预算的双重准入裁决：按文档数、各路候选数与过滤条件估算每查询代价，在总候选预算与融合比较预算内决定准入集合与各路候选规模；超限时按显式优先级返回 E_RECALL_BUDGET 或以缩减候选数的降级路径执行，降级须在结果中标记降级路名与实际执行路集合，且被拒查询必须记录拒绝原因。
6. 实现驻留内存上限与淘汰策略：为同时驻留的候选数组与融合中间表设可配置内存上限，超限时按明确的分片淘汰策略释放已归并查询的数据或返回 E_RESOURCE_LIMIT；淘汰策略不得丢失最终统计所需的计数与明细，且上限触发必须在执行计划的资源账本中留痕。
7. 实现精度、内存与延迟之间的显式冲突裁决：当扩大候选数提升召回但逼近内存上限、切换到两段式先粗排后精排提升融合质量但突破融合比较预算、降低并行度节省内存但放大整体延迟时，须按配置声明的优先级顺序裁决，并在策略记录中写出各查询所走路径、被降级的路与取舍理由，同一观测下裁决结果必须可复现。
8. 实现召回统计与融合权重的版本化快照及整体替换：每路召回统计量、归一化参数与融合权重各携带单调递增版本号与内容校验和，提交时整体替换旧快照而非增量修补；加载时检测版本号或校验和变化并整体替换，旧版本不得覆盖新版本，回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明快照名与版本号。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本与固定种子验证四路召回融合、预算降级、快照替换与并行结果重跑一致，并附运行产物。
