某安全团队需要在离线 Windows 空白工作区从零开发一个本地证书链信任管理应用，用于在信任锚集合频繁演化、证书大量被吊销的场景下批量校验证书链声明并给出可复现的信任结论。输入由三部分本地确定性 JSON 组成：证书描述文件声明证书标识、签发者标识、公钥指纹、有效期起止（整数毫秒）与吊销状态；信任锚快照系列声明受信根标识集合、策略版本与吊销条目列表；链声明文件给出从叶到根的有序证书标识序列，并声明期望返回时限与期望结论摘要。应用必须以受控并发调度路径构建与校验任务，在累计预算与单任务真实耗时上限内完成全部链的结论计算，并对同一批输入在任意并发度与任意快照到达顺序下给出完全一致的结论。所有样本由工作区自行生成，不依赖网络、真实证书或外部账号。

任务环境与准备：
准备 Windows 工作站并安装 Python 3.11 及以上版本，确认 python 与 pytest 可执行。
在空白工作区创建项目目录，任务开始前不放置任何既有代码或样本文件。
如需文件锁与原子重命名，仅使用标准库在当前 Windows 文件系统上提供的机制，不引入容器或外部服务。
运行前执行 pytest 收集测试，确认本地样本生成脚本可离线重复生成相同输入。

业务要求：
1. 实现证书描述、信任锚快照与链声明三类输入的严格解析与规范化层：校验证书标识全局唯一、签发者引用可解析、有效期起止为整数毫秒且起小于止、指纹格式合法、快照策略版本格式合法、链声明序列不含重复标识且首尾语义明确，对非法条目输出含来源文件名、条目序号与业务错误码 E_SCHEMA 的拒绝记录并继续处理其余条目。
2. 实现信任锚版本演化模型：每次快照整体声明受信根集合、策略版本与吊销条目，识别快照整体替换——受信集合任一增删、策略版本变化或吊销条目集合变化均视为新版本，并为每条链声明确定其生效快照版本；同一链在任意快照到达顺序下最终生效版本必须与按版本号稳定排序后的结果一致。
3. 实现信任路径构建与结论分级：按链声明给出的标识序列逐级校验签发者关系与实际签发者一致性，结合生效快照判定受信、不受信、部分可信三档结论；根不在受信集合、签名链断裂、链长度为零、缺失中间证书须分别给出稳定业务错误码与出错位置（链内下标），且结论必须记录其依据的快照版本与策略版本。
4. 实现吊销与过期的失效传播：依据生效快照中的吊销条目与证书有效期计算沿链失效；叶被吊销与中间证书被吊销须区分报告并标明该失效传播到哪些依赖链；有效期判定只能以快照中声明的观测时间为唯一真值来源，不得使用系统当前时间；吊销条目迟到时必须触发受影响的链重新计算并更新结论。
5. 实现受控并行的路径构建与校验调度：把校验任务按链声明切分为独立任务，按可配置并发度执行，并设置整批累计任务预算（最大任务数）、单任务真实耗时上限与待处理队列上限；耗时以真实墙钟测量判定而非人为延迟常量，超时返回 E_TIMEOUT、超预算返回 E_BUDGET、队列超限须拒绝入队并计入报告，任何单任务超限不得中断其余任务。
6. 保证调度结论与并发度、任务完成顺序无关：相同输入在任意并发度与任意快照与链交错导入顺序下，每条链的结论、依据版本、失效传播集合与拒绝清单必须完全一致；报告中的链与快照顺序须按稳定键归一化，批级摘要须含任务总数、成功数、超时数、超预算数与拒绝数，并可与逐条明细相互核对。
7. 实现检查点演进与强制终止后的恢复边界：按已处理快照版本水位与链结论状态持久化检查点，恢复时只从最后一个完整检查点继续并校验重放结果与检查点状态一致以识别半写残留；检测到检查点结构版本或策略版本变化时须整体重建而非增量续接；进程被强制终止后不承诺生成退出报告，只保证恢复到最后一个完整检查点。
8. 实现原子快照整体替换、并发写隔离与确定性本地演示：检查点与 JSON 报告均先写临时文件并校验内容完整后整体重命名替换，同一工作目录并发写入以文件锁串行化并在锁冲突时返回 E_LOCK 且不破坏既有状态；交付可交互命令行（导入快照、校验链、查询结论、校验检查点四类子命令，退出码区分全部成功、部分失败与参数错误）与本地样本生成器及 pytest 测试集，覆盖吊销传播、过期、迟到吊销、超时、超预算、并发度差异与强制终止恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证并发校验结论与串行一致、吊销过期传播正确、预算与恢复边界生效，并附运行输出。
