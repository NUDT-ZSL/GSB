在空白工作区从零实现一个本地分布式锁与租约管理引擎，用于在确定性样本上复现锁租约的增量续约与依赖失效过程。样本以本地 JSON 给出：锁资源清单（资源键、持有者、租约时长、租约代数、优先级）、持有者进程清单（身份、心跳周期、会话代数）、以及依赖声明（持锁方声明其工作依赖的配置片段、缓存条目与上游锁键，形成锁键之间的依赖边）。引擎需要维护锁表与租约代数，支持在逻辑时钟推进下处理申请、续约、释放与过期回收，并在依赖边存在时把某个锁键的租约变更或失效沿依赖图传播：依赖方必须判定其缓存与计算结果是否失效、是否需要重新获取上游锁，且失效传播必须精确到受影响闭包而不波及无关锁键。全部状态需持久化，支持强制终止后的恢复与多进程并发的幂等推进。

任务环境与准备：
在空白工作区创建项目目录，安装 Python 3.10 及以上版本，确认 sqlite3 标准库可用，无需第三方依赖。
准备固定本地样本：锁资源 JSON、持有者 JSON、依赖声明 JSON 各一份，数值与时序字段固定，便于两次运行结果逐位一致比对。
确认运行平台为 Windows，使用本地文件系统路径与普通文件锁；运行前清理上一次生成的 SQLite 数据库与输出目录。

业务要求：
1. 实现锁资源、持有者与依赖声明的解析校验：校验资源键唯一性、租约时长为正整数毫秒、租约代数单调、依赖边两端锁键均存在，构建锁表模型与依赖有向图并检测成环；非法输入必须返回明确业务错误码且不写入任何持久化状态。
2. 实现基于可注入逻辑时钟的申请、续约与释放：所有租约到期判定只依赖注入的逻辑时钟毫秒值，不读取系统墙钟；续约必须校验持有者身份与会话代数，非当前持有者或旧会话代数的续约请求必须被拒绝并记录原因，同一逻辑时钟下重复请求结果完全一致。
3. 实现租约过期回收与代数演进：到期锁键进入可回收状态，回收后锁键代数递增并清空持有者信息；回收必须依据持久化租约与逻辑时钟裁决，重启后不得因内存残留而误判，且已过期锁键的历史租约记录需保留用于追溯。
4. 实现依赖失效的增量传播：某锁键租约变更、过期或被释放时，沿依赖图计算受影响闭包，精确标记依赖方的缓存条目与计算结果失效，并判定其是否需要重新获取上游锁；传播必须给出每个失效节点的传播路径与触发来源，未受影响的锁键缓存命中状态不得改变。
5. 实现依赖快照的版本化与整体替换识别：每次失效传播产生新的依赖视图版本，提交时整体替换当前快照指针；收到新依赖声明包时比较版本号与内容摘要，识别完整替换、增量追加与版本回退，回退必须被拒绝或按策略降级并保留审计记录。
6. 实现持久化状态与强制终止后的恢复：锁表、租约代数、依赖视图版本、失效事件与传播记录以事务原子写入 SQLite；进程被强制终止后，恢复路径依据持久化状态识别未提交的续约与未完成的传播轮次，只重放未提交步骤，不得重复推进已提交的失效传播或回退代数。
7. 实现多进程并发一致性与幂等：允许多个管理实例并行处理同一批锁键，通过 SQLite 事务与文件锁保证同一锁键同一版本的租约变更只提交一次，重复提交相同申请或续约必须幂等；读取方只能看到完整已提交的锁表与依赖视图，不得观察到传播中间态。
8. 实现异常链路与业务错误码：锁键不存在、持有者身份不匹配、会话代数落后、续约已过期锁键、依赖图成环、逻辑时钟回拨超阈值分别映射到不同业务错误码，单次异常不得中断其他锁键处理或留下半写入的失效记录。
