团队准备新建一个项目，在 Windows 本地工作区从零实现一个弹性伸缩指标驱动控制面，以算法实现加可复现实验环境的形式交付，用于在确定性样本上复现工作负载按指标自动扩缩容、并行拉起副本与资源预算约束下的裁决，并专项处理伸缩链路上的数值精度与误差传播问题。业务对象是一组声明式伸缩策略：工作负载清单（名称、当前副本数、最小与最大副本数、每副本 CPU 毫核与内存 MiB、拓扑域）、指标源清单（指标名、聚合方式为平均值或分位数、采样窗口逻辑毫秒、目标值与告警阈值、换算定点标度）、伸缩规则（引用的工作负载与指标源、步长与百分比、冷却窗口、冻结窗口、优先级）、资源预算（池总核时与内存上限、每轮总逻辑时间预算毫秒、每工作负载并发动作上限、浮点容差与误差上界预算）。本地 JSON 样本给出按注入逻辑时钟毫秒戳到达的指标采样流与并发事件序列，控制面需完成采样聚合、目标副本数换算、定点误差账本、预算内并行调度与持久化恢复。

任务环境与准备：
Windows 10/11，Python 3.11 及以上，执行 python -m pip install numpy 安装 NumPy
确认标准库 sqlite3 可用并支持基于文件锁的事务；无需 Docker、容器或外部服务
在工作区根目录创建 samples/ 目录，放入由本地脚本确定性生成的工作负载、指标源、规则、预算与采样流 JSON 文件
创建 out/ 目录用于 SQLite 账本与决策快照，运行前确认目录可写

业务要求：
1. 实现工作负载、指标源、伸缩规则与资源预算四类对象的解析校验：名称在各自作用域内唯一，最小副本数不大于最大副本数，每副本 CPU 毫核与内存 MiB 为正整数，聚合方式与分位数参数、告警阈值、冷却与冻结窗口合法，定点标度与误差上界预算为正，规则引用的工作负载与指标源存在；非法输入返回明确业务错误码且不写入任何持久状态。
2. 实现策略对象依赖图与增量规则补丁：以补丁形式提交对象的新增、修改、删除，校验补丁后引用仍然闭合且无环，沿引用关系计算受影响工作负载闭包，精确标记哪些目标副本数缓存、冷却窗口计时与预算预扣必须失效重算、哪些可安全复用；未受影响工作负载在补丁后不得被重算，其结果与依据须逐字段保持不变。
3. 实现指标采样流的确定性窗口聚合：按采样窗口与聚合方式计算每指标源的窗口聚合值，分位数按固定排序与插值规则计算，窗口边界只依赖注入逻辑时钟毫秒值，每个采样唯一归属一个窗口且不得跨窗口重复计入，逻辑时钟回拨超过容差须返回业务错误码；同一采样流在任意运行次数下得到逐位一致的窗口聚合值序列。
4. 实现窗口聚合与目标副本数的受控定点换算与误差账本：把窗口聚合值、目标值与派生副本数按声明标度换算为定点整数，登记每次换算的标度、舍入方向与被舍弃余量，未满一个定点单位的余量必须逐指标源保留并在后续换算中参与，累计每次加法与乘法的误差上界；当定点通路与基于 decimal 的高精度通路结果差超过容差时，须输出首个分歧指标源、两通路中间值与换算步骤编号。
5. 实现指标驱动的目标副本数计算与精度敏感标记：依据窗口聚合、目标值、告警阈值与规则步长和百分比计算目标副本数，多规则命中同一工作负载时按优先级与方向裁决并输出被否决规则及首个否决原因，向上取整与夹在最小最大副本数之内的次序必须固定；当两个候选目标副本数或两条规则的裁决得分差小于容差且结论依赖该差值时标记精度敏感，输出参与规则、误差上界与若改用更高标度是否翻转结论。
6. 实现全局资源预算下的伸缩动作并行调度：在池总核时与内存上限、每轮总逻辑时间预算与每工作负载并发动作上限约束下决定动作启动顺序，预算不足时必须放弃剩余动作并记录放弃原因，严格区分预算内未启动、启动后失败与主动放弃三类结局，已启动动作必须执行完毕，不得以线程超时描述为已终止失控动作；冷却窗口、冻结窗口与按连续失败次数计算的确定性退避只依据注入逻辑时钟毫秒值推进，冻结窗口内不得下发任何扩容动作。
7. 实现持久化状态与强制终止后的恢复一致性：把已提交采样水位、各工作负载副本数与预算账目、在途动作、冷却与退避截止时刻、精度敏感记录以事务原子写入 SQLite，每轮提交识别版本变化并整体替换决策快照指针并拒绝版本回退；进程被强制终止后恢复路径识别已提交轮次与半提交动作，只重放未完成部分且不重复扣减预算、不重复累计误差账本或改变已提交副本数。
8. 实现多进程并发一致性、幂等提交与可重复命令行演示：多个控制面实例并行处理不同工作负载时，通过 SQLite 事务与文件锁保证同一工作负载同一轮次同一规则版本只被裁决并下发一次、池预算不被并发超卖，重复提交相同动作结果幂等；提供 load、apply、decide、edit、resume、status、verify 子命令，status 以稳定排序 JSON 输出各工作负载副本数、定点误差账本与精度敏感标记，verify 校验持久账目与本次运行裁决一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
