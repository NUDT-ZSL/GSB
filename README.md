当前是空白工作区，需要从零实现一个本地灰度路由与流量镜像中间件的控制面与数据面，交付可交互的专业应用和可重复演示。业务对象是一组声明式规则：虚拟服务、按权重或按请求头匹配的灰度路由、上游服务组与成员、镜像策略（把生产流量按比例复制到影子上游、是否异步、是否响应丢弃），对象之间以 ID 相互引用，灰度路由引用上游组，镜像策略引用影子上游组并被多个路由共享。本地由可编程 HTTP 测试服务模拟生产与影子上游，可按路径返回状态码、延迟、畸形响应与断开连接。核心矛盾是规则以补丁增量提交时，必须精确判定哪些解析缓存、成员快照、连接池与镜像采样决策失效需重建、哪些可安全复用；同时每个请求必须绑定开始时的规则版本并记录完整决定链，进行中的镜像复制不得因规则更新而写入半途失效的影子上游，进程被强制终止后依据持久化状态恢复且不得回退已提交规则版本。

任务环境与准备：
安装 Python 3.11 与 pip，创建虚拟环境并安装 FastAPI、uvicorn、httpx、pytest 等在 requirements 中声明版本的依赖。
在工作区准备固定本地样本：规则对象 JSON、补丁序列、请求轨迹与可编程回环 HTTP 上游测试服务的启动配置。
确认 SQLite 可用（Python 内置）与工作区可写，演示脚本在本地生成临时数据库与日志目录。
运行前清除上一轮生成的数据库与产物目录，保证两次演示从同一初始状态开始。

业务要求：
1. 实现声明式规则对象模型与依赖图：虚拟服务、灰度路由、上游组、上游成员、镜像策略五类对象以 ID 相互引用，加载时校验引用闭合、权重为正整数、灰度比例之和合法、镜像比例在合法区间，构建对象级依赖图并检测环；非法引用、循环或字段非法必须返回明确业务错误码且不写入任何持久化状态。
2. 实现补丁式增量规则更新与依赖失效判定：以补丁提交对象的新增、修改、删除，计算受影响对象闭包，精确标记解析缓存、成员快照、连接池、镜像采样决策中哪些失效需重建、哪些可安全复用；未受影响的路由在更新后决定链与统计必须逐字段不变，失效决策须输出触发来源、传播路径与被复用项。
3. 实现基于可注入逻辑时钟的确定性灰度路由裁决：按权重、请求头匹配、灰度比例与稳定哈希决定命中的路由与上游成员，所有时间相关判定只依赖注入的逻辑时钟毫秒值，不读取系统墙钟；权重为浮点求和与乘法时按固定运算顺序，同一请求序列在任意运行次数下必须得到逐位一致的路由结果与成员选择。
4. 实现流量镜像复制与影子上游隔离：镜像按比例采样复制请求到影子上游，镜像失败不得影响主请求结果与状态码，异步镜像须记录请求序号、规则版本、影子成员与完成结局；规则更新后不得把进行中的镜像写入已失效影子上游，须按镜像开始时的规则版本裁决，单次镜像异常不得污染主请求决定链。
5. 实现请求决定链记录与规则版本快照的读取隔离：每个主请求与镜像记录完整决定链，包含开始时的规则版本号与内容摘要、命中的路由、上游成员、失效与复用原因、镜像采样判定依据；进行中的请求必须绑定其开始时的规则快照直到结束，读取方只能观察到某个完整已提交规则版本，不得看到新旧规则混合的状态。
6. 实现规则版本化持久化与强制终止后的恢复：规则版本、依赖图、补丁失效事件、决定链与镜像复制记录以事务原子写入 SQLite，每次补丁提交产生新版本号并以临时表加版本号整体替换当前规则指针；进程在补丁提交或镜像复制中途被强制终止后，恢复路径依据持久化状态识别未提交版本与半写入记录，只重放未完成步骤，不得回退已提交规则版本或重复计入已完成的镜像复制。
7. 实现多进程并发一致性与幂等提交：允许多个补丁提交进程与多个转发进程并行，通过 SQLite 事务与文件锁保证同一规则版本号只提交一次、同一补丁请求重复提交幂等、同一请求序号同一版本的决定链只记录一次；连接池重建与成员快照更新不得出现半更新态，读取方只能看到完整已提交版本。
8. 实现异常链路与业务错误码隔离：上游连接拒绝、响应超出单请求预算、上游返回畸形响应头、上游提前断开、规则引用缺失或成环、补丁格式错误、规则版本与期望不符分别映射到不同业务错误码并在决定链中保留可诊断字段；单次上游失败不得中断监听循环、不得提交不完整规则，也不得影响同版本其他请求的裁决。
