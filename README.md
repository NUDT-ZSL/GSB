当前是空白工作区，需要从零实现一个本地事务锁等待的精度账本诊断引擎，用于在 Windows 上以确定性样本复现并发事务脚本在共享锁表上产生的锁等待时长，并诊断这些时长在累计、换算与边界比较中的数值误差传播如何影响等待放弃与死锁牺牲等回滚决策。本地 JSON 样本给出三部分：SQLite 样本库（表结构与固定数据，可由脚本确定性重建）、并发事务脚本集合（每个事务由有序的读、写、范围扫描与锁声明操作组成，声明隔离级别、锁等待预算与重试上限）、诊断配置（逻辑时钟步进、等待时长定点标度、比对容差、误差上界预算、并发实例上限）。所有等待与放弃时刻只依据可注入逻辑时钟，真值来源为同一脚本在单事务串行执行下逐操作重算得到的等待时长序列。交付算法实现与可复现实验环境。

任务环境与准备：
安装 Python 3.11 或以上版本，并确认 sqlite3 标准库、multiprocessing 与 json 模块可用。
在空工作区创建项目目录，预先放入确定性的样本脚本生成器与事务脚本 JSON 样本、诊断配置文件；样本库由脚本按固定种子重建，不依赖外部数据库服务。
确认没有监听端口或外部网络依赖，所有进程与文件操作限定在工作区目录内，并预留临时目录用于 SQLite 账本与临时表。
执行前检查工作区可写、可用磁盘足够容纳账本数据库与临时文件，运行期间不修改样本与生成器源码以制造失败场景。

业务要求：
1. 实现样本库、事务脚本与诊断配置的解析校验：表名与列名唯一、操作类型与隔离级别枚举闭合、锁等待预算与重试上限为正整数、定点标度与容差合法、脚本引用的表列存在；非法脚本必须返回明确业务错误码（如 E_BAD_SCRIPT、E_NO_TABLE、E_BAD_SCALE）且不创建任何锁表或账本记录。
2. 实现共享锁与排他锁的锁表及先进先出等待队列：以 SQLite 锁表持久化每行与每范围区段的持有者、锁模式与入队序号，读申请共享锁、写申请排他锁、范围扫描按区段登记；冲突申请按稳定次序入队且不得插队，同一事务重复申请已持有模式须以兼容语义处理而非死锁。
3. 实现基于注入逻辑时钟的等待时长计量与舍入账本：入队、获得锁与放弃等待的时刻全部取自注入逻辑时钟毫秒值，等待时长由两端时刻相减后按定点标度换算，每次换算登记被舍弃余量、舍入方向与登记序号；同一脚本在任意运行次数下必须得到逐位一致的等待时长序列与登记序列。
4. 实现等待时长的误差上界累计与来源链：为每个事务累计其各次等待换算与求和的误差上界，输出误差来源链（参与登记序号、余量、权重位置与对应锁资源）；当两个事务等待时长之差小于容差且放弃排序或牺牲选择依赖该差值时标记为账本敏感，并给出若提高标度是否会翻转结论的判断依据。
5. 实现等待预算与全局并发上限下的放弃裁决：在每事务锁等待预算与并发事务上限双重约束下决定等待或放弃，预算耗尽须释放已持有锁并记录放弃原因；须严格区分预算内未启动、入队后等待超时放弃与主动回滚三类结局，超时必须由真实等待计时与主动中止共同实现，不得把未启动事务事后标注为超时。
6. 实现等待图死锁检测与确定性牺牲裁决：按配置周期遍历锁表等待图识别环路，输出完整死锁环与牺牲事务的裁决依据（事务号、等待时长、偏差与误差上界），解除后其余事务须能继续推进且等待队列相对次序不变；检测须在逻辑时钟推进下可重复，不得依赖进程实际耗时。
7. 实现持久化账本与强制终止后的恢复：把已提交等待记录、锁持有与等待队列内容摘要、舍入登记序列、放弃与牺牲决策、逻辑时钟水位以单事务原子写入 SQLite，每轮提交以临时表加版本号整体替换当前账本指针；进程在入队、获锁或放弃中途被强制终止后只重放水位之后的步骤，不得重复累加登记或将已放弃事务复活。
8. 实现多进程并发一致性与可重复诊断命令行：多个实例并行推进不同事务时，通过 SQLite 事务与文件锁保证同一事务同一操作版本只提交一次、同一锁资源不被并发超授、重复提交相同等待记录幂等；提供 run、resume、status、verify 子命令，status 以稳定排序 JSON 输出等待时长、账本敏感标记、误差来源链与牺牲决策。
