在空白工作区从零实现一个本地冷热分层存储的迁移裁决与诊断工作台。样本以 JSON 给出存储桶与对象清单：对象键、字节大小、最近访问逻辑时钟、访问计数、热度权重、声明冷热层、是否允许迁移；分层配置声明热层与冷层容量上限、每轮迁移字节预算、迁移并发上限、冷热阈值与退避参数。工作台需在可注入逻辑时钟下判定每个对象应处层级，在容量与预算双重约束下调度迁移批次，并维护迁移进度与失败重试。核心难点是数据规模变化时精确扫描与采样估算之间的算法取舍，以及中断恢复后迁移账目与层级视图的一致性。所有判定不读取系统墙钟，不依赖外部服务。

任务环境与准备：
安装 Python 3.11 或以上，以及 NumPy 1.26 或以上（pip install numpy），SQLite 使用标准库 sqlite3，无需额外安装。
准备本地样本目录，包含对象清单 JSON、分层配置 JSON 与注入逻辑时钟步进表，样本由脚本确定性生成，不依赖外部服务或网络。
确认工作区为空目录，任务执行前不预置任何代码或持久化数据库文件。

业务要求：
1. 实现对象清单与分层配置的解析校验：对象键唯一、字节大小为正整数、访问计数非负、热度权重有限且非负、冷热层容量上限与每轮迁移字节预算为正整数、迁移并发上限为正整数、退避基数与上限合法；非法输入必须返回明确业务错误码且不写入任何持久化状态。
2. 实现基于可注入逻辑时钟的热度评分与目标层级判定：按最近访问逻辑时钟、访问计数与热度权重计算对象热度得分并映射到冷热层级，评分顺序与加法乘法次序固定，使相同输入在任意运行次数下得到逐位一致的目标层级；逻辑时钟回拨超过容差时返回业务错误码且保持层级视图不变。
3. 实现精确扫描与采样估算两种迁移候选生成模式：精确模式逐对象按热度与层级差生成候选集合并给出精确候选数与字节总量；采样模式按配置采样比例抽取对象后用分层摘要外推候选规模并给出可估计的候选数与字节总量的误差上界；两种模式必须输出所依据的观测项与真值来源说明。
4. 实现数据规模变化下的模式自适应取舍：依据对象总数、单轮候选数与采样误差上界估算两种模式的开销，当规模超过配置阈值时按明确规则在精确与采样模式间切换；切换后必须输出实际使用的模式、切换触发条件与被否决模式的原因，并保证切换不影响已提交迁移账目。
5. 实现容量与预算双重约束下的迁移批次调度：每轮迁移同时受热层与冷层容量上限、每轮迁移字节预算与迁移并发上限约束，选择候选并确定启动顺序；预算或容量不足时必须放弃剩余候选并记录放弃原因，区分预算内未启动、启动后失败与主动放弃三类结局。
6. 实现迁移批次状态机与持久化推进：对象在待迁移、迁移中、已迁移、迁移失败、已放弃之间按规则迁移，迁移成功须原子更新对象层级与两层已用字节账目；迁移失败按连续失败次数计算确定性退避与上限，退避截止时刻只依赖注入逻辑时钟，状态迁移须依据持久化状态与已提交批次结果裁决。
7. 实现强制终止后的恢复一致性与账目校验：把轮次水位、各对象层级、两层已用字节账目、在途迁移登记、退避截止时间与逻辑时钟水位以单事务原子写入 SQLite；进程在调度或迁移中途被强制终止后，恢复路径识别已提交与半提交迁移，只重做未完成部分，恢复后两层已用字节之和必须等于各对象字节按层级归集的结果。
8. 提供多进程并发一致性与可重复命令行演示：多个工作台实例并行处理不同桶时，通过 SQLite 事务与文件锁保证同一对象同一轮次同一版本只被迁移一次、两层容量账目不被并发超卖、重复提交相同批次结果幂等；支持 load、migrate、resume、status、verify 子命令，status 以稳定排序 JSON 输出各对象层级、两层已用字节、退避截止时间与迁移模式，verify 校验账目与持久化状态一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
