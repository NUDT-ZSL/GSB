当前是空白工作区，需要从零构建一个面向多模态模型与数据管线协同的本地工作台，核心业务问题是数值精度与误差传播。业务对象是本地确定性生成的图文对样本清单（JSONL，字段含 pair_id、image_seed、image_shape、text_tokens、label），图像分支由 fixed seed 生成固定尺寸 RGB 像素并做确定性的图像编码（分块均值、归一化、固定权重投影得到图像嵌入），文本分支由 token 序列做确定性嵌入与加权池化得到文本嵌入，融合层把两路嵌入按显式权重拼接并归一化后送入固定的线性打分头。管线每一级都允许配置数值精度档（float64、float32、定点缩放整数）与量化参数，因此误差会沿图像编码、文本编码、融合归一化、打分头逐级放大，最终影响分类判定与排序。工作台需要把一份管线配置与数据快照绑定为可持久化、可整体替换的版本，支持在同一份样本上切换精度档重跑，给出每级的误差区间、放大比与主导误差来源，并能用注入的异常输入与参数复现故障链路。误差区间的构造口径必须显式定义：以 float64 档在同快照同配置下的输出为参考真值，区间由重复量化扰动下的观测极值推导，不得从缺失信息推断。

任务环境与准备：
安装 Python 3.11 与 NumPy（版本固定并写入依赖说明），Windows 本地运行，不依赖 GPU 或外部服务。
在工作区创建项目目录并准备本地样本生成脚本，按给定种子生成图文样本清单与像素数组，确保两次生成逐字节一致。
准备演示用注入输入与降级参数样例：错误种子形状、空文本、未知精度档、非法缩放因子、超内存批大小各一份。
确认磁盘可写以保存配置与数据快照，并预留可复现实验用的输出目录。

业务要求：
1. 实现确定性的图像编码、文本编码、融合归一化与打分头四级流水，各级输入输出语义明确；同一 pair_id、同一输入与同一精度档配置下产出逐字节一致的中间嵌入与分数，禁止依赖除固定种子与显式配置外的任何外部状态。
2. 实现可切换的精度档执行层：float64、float32 与定点缩放整数三档共用同一算子语义，定点档的缩放因子与舍入模式由配置显式给出；同一输入在不同精度档下结果差异必须只来自精度损失本身，切换精度档不得改变计算图拓扑与参与样本集合。
3. 实现逐级误差传播计算：把 float64 档作为该快照内的参考真值，输出各级相对参考的绝对偏差、相对偏差、误差区间与误差放大比，并定位主导误差来源是图像编码、文本编码、融合归一化还是打分头中的哪一级，同时记录各级观测到的偏差分布统计。
4. 实现门限判决与排序的数值稳定性保护：对打分头输出设定可配置的分类门限与 top-k 排序，提供严格比较与容差带比较两种策略及次正规数保护；保证恰好落在门限附近的样本判定在重复运行下不被舍入翻转，门限或容差策略变更必须在诊断结果中标记并重新计算受影响的判定。
5. 实现错误注入与异常链路归因：图像种子与形状不匹配、text_tokens 为空、精度档未知、缩放因子非正或过大、重复 pair_id 等由输入或参数触发时，分别返回结构化业务码（如 E_SEED_SHAPE、E_EMPTY_TEXT、E_PRECISION_UNKNOWN、E_SCALE_INVALID、E_DUP_PAIR），并归因到出错的级与 pair_id，禁止静默吞掉或仅打印日志。
6. 实现管线配置与数据快照的版本化管理：配置与快照携带单调递增版本号与内容校验和，提交时整体替换旧版本而非增量修补；加载时检测版本变化并整体替换，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明版本号，旧版本不得覆盖已提交的新版本。
7. 实现资源上限与降级执行：为单批样本数、嵌入驻留内存估算与定点整数中间位宽设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或降级到 float32 档并缩小批大小，降级必须在结果中标记降级类别、触发上限的级与参数，且不得改变参与样本集合。
8. 实现跨级一致性自检与可交互诊断工作台：校验各级处理的 pair_id 集合一致、误差区间顺序合法、精度档切换前后参与样本可核对、主导误差归因可追溯至偏差明细；不一致返回 E_INCONSISTENT 并指出不一致类别。工作台展示各级误差谱、放大比、门限附近样本、当前配置版本与业务码，并允许触发一次含注入异常与降级路径的演示，仅依赖本地确定性样本。
