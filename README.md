当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向直播场景的实时字幕流处理组件与完整示例，交付形式为可交互的专业应用与可重复演示。业务对象是本地确定性生成的语音转写事件流：用固定种子在给定时间轴上生成逐词事件清单（JSONL，字段含 stream_id、word_index、start_ms、end_ms、word、confidence、lang），事件严格按时间轴推进但到达顺序被打乱成若干乱序窗口以模拟网络抖动；同时配一份显示策略配置，声明最大等待时长、最大行字符数、每屏最大行数、回滚步数与置信度门限。核心业务问题是低延迟分块重排与显示结果一致性：用户先看到未定稿的临时字幕行，随后随着迟到事件到达而被重排与改写，最终必须收敛为与按时间轴完整排序后重排完全一致的定稿字幕。矛盾在于：更短的等待时长降低临时字幕出现延迟，却使更多迟到事件落在定稿之后并触发回滚改写；更长的等待更稳，但延迟超标。引擎需要按分块口径逐窗推进，记录每次版本化改写，并证明任意时刻屏幕上可见的字幕行与同一时刻已接收事件按完整重排口径计算出的结果一致。

任务环境与准备：
在 Windows 空白工作区创建项目目录，仅使用 Python 标准库与 NumPy（建议 Python 3.11 及以上、NumPy 2.x 可离线安装），不依赖 GPU、网络或外部服务。
准备本地确定性样本生成脚本：按 stream_id 与 seed 生成逐词事件清单并打乱为乱序窗口，真实还原到达顺序；样本规模与乱序程度可配置且同种子逐字节可复现。
准备快照与改写历史存储目录，确认进程重启、并发预览请求与延迟预算计时场景可在本地真实执行；准备异常注入输入（超长词、重复 word_index、缺失事件、损坏快照）用于触发各业务码验证。

业务要求：
1. 实现确定性的分块重排核心：把到达事件按可配置窗口边界与最大等待时长聚合为分块，块内按 start_ms 升序、再按 word_index 升序重排，同分打破规则须显式声明；同一事件流、同一到达顺序与同一配置下必须逐字节产出相同的分块划分、块内词序与定稿文本，禁止依赖系统时间或字典遍历顺序。
2. 实现行装配与显示的软换行规则：按最大行字符数、每屏最大行数与词边界约束把词序列装配为字幕行，禁止拆断单词（以词为单位换行），中文与拉丁词混排时按词宽配置计算宽度；装配结果须满足每行不超字符上限、每屏不超行数上限，违反分别返回 E_LINE_WIDTH、E_LINE_SCREEN 并指出 stream_id 与块序号。
3. 实现临时字幕的版本化改写与回滚：迟到事件插入已显示区域时须产生带单调递增改写版本号的行快照，按回滚步数限制可追溯的改写深度，超出深度返回 E_REWRITE_DEPTH；每次改写须记录被替换行、替换原因与触发事件，且任一改写版本的行内容须能由其事件集合独立重算一致。
4. 实现延迟预算与等待时长的取舍裁决：以本地重排循环的实际处理计时观测每块从首事件到定稿的等待，按块内事件数与窗口边界给出估算记录；超过配置最大等待时长返回 E_LATENCY_BUDGET 并附带已完成块数与当前临时版本；当缩短等待会放大改写深度、放长等待会突破延迟预算时，须按显式优先级规则裁决并在每块处理计划中记录所选等待时长与依据。
5. 实现临时视图与完整重排结果的显示一致性裁决：对任意检查点，屏幕上可见的临时字幕行（含未定稿行）必须与用该检查点已接收事件按完整重排口径计算的行内容在声明精度内一致，被迟到事件改写的行必须出现在新版本而非旧版本中；检测到偏差返回 E_VIEW_INCONSISTENT 并指出首个不一致行号与两侧内容。
6. 实现收敛保证与定稿校验：对同一事件流，定稿字幕必须与按时间轴全局排序后一次性重排的结果逐字符相同，即使到达顺序被乱序窗口重排多次；须校验定稿中每个 word_index 恰出现一次、定稿时间轴单调不重叠，重复或缺失分别返回 E_WORD_DUP、E_WORD_MISSING，并输出收敛所用的块数与改写总次数。
7. 实现事件清单与显示策略的版本化快照及整体替换：事件清单、显示策略与行快照各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK；损坏或校验和不符的快照返回 E_SNAPSHOT_CORRUPT 并指明快照类别与版本号。
8. 实现资源上限、并发预览请求控制与可交互演示应用：为单流事件总数、驻留行快照数与改写历史条数设可配置上限，超限时返回 E_RESOURCE_LIMIT 或按明确策略淘汰最旧改写版本并标记降级类别；多个预览请求可并发执行，同一时刻只允许一个快照提交生效，冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待；应用展示当前块序号、临时版本、可见字幕行、改写记录、收敛统计与最近业务错误码，并触发一次含迟到事件回滚与一次超延迟的演示，全部使用本地确定性样本。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
