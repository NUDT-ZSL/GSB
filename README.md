为传统机器学习建模团队构建一个本地可运行的特征编码与选择工作台，核心问题是交互延迟与计算结果一致性。输入是多个本地 CSV 特征数据分片，含样本 id、若干数值特征列与若干类别特征列，以及一份标签文件（样本 id 到类别标签）。工作区为空，需从零创建项目：一个可交互的 FastAPI 服务，提供编码方案选择（独热、目标编码、频次编码）、特征过滤条件（方差阈值、缺失率上限、与标签的相关性阈值）、特征子集提交与查询、最终训练集导出与快照查询接口。核心难点在于：用户会以较低延迟反复调整过滤与编码参数并即时查看候选特征数与预览，但这些交互预览必须与最终提交后经完整重算得到的结果完全一致；同时编码统计量（目标编码的类别均值、频次编码的频次）依赖训练样本，在多次交互中必须保持稳定口径，不能因逐步预览而漂移。

任务环境与准备：
安装 Python 3.11，创建虚拟环境并用 pip 安装 fastapi、uvicorn、scikit-learn、numpy、pandas 与 pytest，版本以 requirements.txt 固定，全部来自本地可获取的 wheel 或已配置的私有索引。
准备本地样本目录：若干 CSV 特征分片（含数值列与类别列、少量缺失值与重复类别）与标签 CSV，置于项目 data 目录，样本为确定性生成，不依赖网络下载。
确认 SQLite 随 Python 标准库可用，工作目录可写，服务监听本地回环端口，演示脚本与 pytest 用例无需外部账号或服务。

业务要求：
1. 服务入口接收分片目录、标签文件与编码配置，校验样本 id 唯一性、分片列一致性、标签覆盖率与编码器参数合法性；非法输入返回 E_PARAM 业务码并指出出错文件与行号，且不创建任何结果文件或临时目录，也不写入任何状态。
2. 须实现确定性数据加载：所有分片按文件名升序拼接并按样本 id 字典序稳定排序，类别特征缺失值统一映射为固定占位符，数值特征空缺值按配置用列均值填充；同一输入下加载结果（样本顺序、各列取值、列类型）须完全可重复。
3. 须实现三种编码器：独热编码、基于标签的类别目标编码与频次编码；目标编码的类别统计量必须只基于当前训练集与标签计算，并对未知类别与低频类别使用可配置平滑项回退，同一类别在重复请求间得到的编码值须逐位一致，不得随请求顺序变化。
4. 交互预览接口须在低延迟预算内返回候选特征数、被过滤特征清单与编码后前若干行的预览值；预览结果必须与用同一参数走完整重算流程得到的结果完全一致，包括过滤后剩余特征集合、列顺序与预览数值，不得因走近似路径产生差异。
5. 过滤规则须支持方差阈值、缺失率上限与与标签的相关性阈值三类条件，多个条件同时生效时按逻辑与合成；相关性须对编码后特征与标签计算且对数值特征与编码特征使用统一口径，任一阈值非法或无法计算时返回 E_FILTER 业务码并指出特征列名，不得静默丢弃。
6. 须实现预览缓存与失效判定：以配置指纹（编码方案、过滤参数、训练集版本）为键缓存编码统计量与预览结果，任何参数变更或训练集版本变化都必须使相关缓存失效；读取缓存时若指纹与当前状态不一致须返回 E_STALE 并指出失效原因，禁止返回旧编码值。
7. 特征子集与编码统计量须在 SQLite 中以配置版本粒度做事务提交，最终导出以原子替换生成版本化快照（含配置指纹、特征清单、编码统计摘要与训练集内容哈希）；进程被强制终止后重启须核对已提交版本与磁盘快照哈希，重算未提交部分且不重复消费已提交配置，恢复后同一配置的导出须与无中断执行完全一致。
8. 须提供确定性本地演示入口：用固定分片与一组覆盖三种编码器、多组过滤阈值的交互序列，跑出每次预览的候选特征数、预览与全量重算一致性结论、缓存失效次数、快照版本序列与最终导出哈希的可重复结果，并给出可用 curl 复现交互与提交的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本验证交互预览与全量结果逐项一致、缓存失效与恢复后导出哈希不变。
