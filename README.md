为零样本目标检测（ZSL）离线评估团队构建本地可运行的查询理解与候选匹配管线，核心是查询意图过滤与服务可复现验证、异常注入。工作区为空，需从零创建项目。输入是本地样本目录：一份查询清单 JSONL，每条查询含 query id、原始查询文本、意图槽位（属性词与关系词的键值）、已见与未见类别名集合；一份类别词表 JSON，含每个类别的文本意图描述与固定维度的嵌入向量；一份候选结果 JSONL，每条候选含 query id、候选 id、候选类别名、意图匹配分数与嵌入向量。管线需完成查询理解（解析意图槽位、按词表校验意图描述）、候选匹配打分与排序，并按已见/未见类别分别汇总评估。核心难点在于：同一查询的候选排序必须可复现，意图过滤只放行满足槽位约束的候选，服务在合法查询、可处理异常与强制终止恢复三类情况下都要给出可验证、可定位的结果，且恢复后的统计与无中断执行逐项一致。

任务环境与准备：
安装 Python 3.10 及以上版本，创建虚拟环境并用 pip 安装 numpy、fastapi、uvicorn、pytest、httpx。
在工作区新建 samples 目录，放置查询清单 JSONL、类别词表 JSON 与候选结果 JSONL，样本须覆盖多查询、同分候选、全部候选被过滤与类别不可映射等情况。
确认 127.0.0.1 上演示端口空闲；数据库与结果文件目录由启动参数指定并在启动前清空，不依赖网络账号或外部服务。
准备中断恢复演示脚本，用固定输入启动服务后以强制终止进程方式中断，再以相同参数重启并比对统计结果。

业务要求：
1. 入口接收样本目录、类别词表、候选文件、意图匹配阈值与服务监听端口，校验文件存在、嵌入维度一致、阈值在开区间内、端口可用；任一非法返回 E_PARAM 业务码且指出出错文件与行号，不创建任何结果文件、临时文件或数据库。
2. 查询理解须解析每条查询的意图槽位：属性词与关系词的键值须能在类别词表中找到对应意图描述，缺失槽位键或类别词表无此描述时返回 E_INTENT 业务码并定位 query id 与槽位键，禁止以空匹配静默放行。
3. 候选匹配打分须由意图匹配分数与归一化嵌入余弦相似度按可配置权重融合，余弦计算统一使用 float64 并在对数域处理极端分数；同一输入与配置下同一查询的候选排序完全可重复，同分时按候选 id 字典序稳定排列。
4. 意图过滤只放行满足查询全部槽位约束的候选，被过滤候选须计入过滤统计并可按 query id 查询；某查询全部候选被过滤时记录空结果并继续其他查询，不得因单查询零候选整体失败或返回错误码。
5. 评估须按真实类别名映射到已见或未见集合，分别汇总排序指标所需的命中计数与假正例计数；类别名不在词表或无法判定已见未见时返回 E_CLASS 业务码并指出 query id 与类别名，不得让划分错误被汇总指标掩盖。
6. 查询、候选过滤与评估汇总须在 SQLite 中以查询粒度做事务提交，结果以原子替换写入分片文件并登记内容哈希；进程被强制终止后重启须从已提交查询继续，核对分片哈希与记录版本，重算未提交查询且不重复消费已提交查询，恢复后的统计须与无中断执行逐项一致。
7. 每次完成评估须生成整体替换的版本化快照，含查询版本号、各查询命中摘要与分片哈希；读取快照时若检测到分片哈希与数据库记录不一致、版本变化或残留旧分片，须返回 E_STALE 并定位到查询与分片，禁止汇入旧数据给出看似正常的数值。
8. 须提供 HTTP 接口：创建评估作业、查询作业进度与过滤统计、获取版本化快照；作业未完成时读取快照返回 E_PENDING。另须提供确定性演示入口，用固定样本与阈值跑出逐查询放行与被过滤候选数、已见未见命中计数、快照版本序列与恢复前后一致性结论，并给出可用等价参数复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证意图过滤、可复现排序、异常业务码与中断恢复后统计一致，附运行结果。
