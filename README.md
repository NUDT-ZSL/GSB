冲压—焊装—涂装—总装多工序车间的质量数据平台需要为一台台工位逐时刻产生的质量事件建立可供班组长追溯的二级索引：班组长按工序、班次与零件批次前缀查询历史记录，以定位超差原因。质量事件持续追加，而工位会随产线改造淘汰、零件批次会按归档周期转入历史，旧索引条目若只增不减，分区会不断膨胀，查询扫描放大，且归档批次仍可能被旧索引命中而返回失效记录。现场希望把逐事件的有序键写入、内存表刷写为不可变段文件、按层合并与失效条目清理、合并后释放旧段空间这一整套维护逻辑做成可在本地离线反复推演的求解器，逐步输出索引条目位置、查询命中顺序、分区占用账目与空间回收动作清单。

任务环境与准备：
在 Linux（WSL Ubuntu）本机准备 Python 3 运行环境，仅使用标准库，不需要第三方包或外部服务。
工作区从空目录开始建立题目工程，质量事件流、分片工程与查询规格全部由题内确定性生成器按固定种子产出，不依赖真实车间设备或线上存储。
运行求解器读取本地生成的输入文件，按逻辑时刻推进并输出查询命中、占用视图与回收动作清单；独立归并参考实现与人工边界样本随工程一并提供，用于逐查询核对。

业务要求：
1. 按工序、班次、零件批次前缀与逻辑时刻为每条质量事件构造有序复合索引键，键的比较须满足工序与班次先分组、批次前缀再按字典序、同一前缀内逻辑时刻递增，并为每条条目记录写入时所在的内存表序号与逻辑偏移，以便后续定位其落在哪个段文件。
2. 内存表条目数达到声明的刷写阈值时整体冻结并刷写为一个不可变段文件，段文件记录有序条目、每条目键与业务事件标识的映射、段大小与所属层；刷写后内存表清空重新累积，同一逻辑时刻之前到达的事件不得跨越到刷写后的新段中造成同键条目次序倒置。
3. 按层维护不可变段文件清单，声明每层的容量上限与可容纳段数，并在每层段数或字节超出上限时确定可提升到下一层的候选段；对任一分区输出当前各层段文件数、条目数与字节占用视图，且视图中的字节数须与逐段记录加总一致。
4. 按工序、班次与批次前缀检索时须归并各层段文件的有序结果，仅返回未被标记失效的条目，并在同一批次前缀跨多个段文件时保持逻辑时刻升序；命中记录中须能区分该条目来自哪个段文件与是否为存续记录。
5. 工位淘汰或批次归档事件到达时，把对应工位编号与批次前缀命中的索引条目标记为失效，输出失效条目计数、涉及的段文件以及仍可查询的存续范围，并给出首个仍会命中该已归档批次的不一致点（若存在）作为诊断依据。
6. 按段内失效条目比例与分区容量阈值挑选合并候选，比例与容量两个条件同时满足或分别触发的优先级需在实现中固定并可核对；合并时丢弃失效条目、重写为新段文件并写入目标层，同时保证合并前后未被标记失效的条目集合与顺序一致。
7. 合并完成并以新段替换后删除被合并的旧段文件，逐次输出空间回收动作清单、回收前后分区字节占用与被回收字节数，且回收前的占用须等于回收后占用加被删段字节之和，任何被删旧段不得再出现在后续查询与占用视图中。
8. 题内内嵌一份独立的段文件归并查询参考实现，只依据写入记录与失效标记计算逐查询命中记录与顺序，求解器须以它为真值逐查询核对并报告首个不一致的查询或段文件及其键依据；同时以人工构造的失效比例恰好达到合并阈值、段文件恰好写满与归档后仍查询旧索引三类样本验证判定边界。

验收：
逐查询命中记录与顺序对齐独立归并参考，且合并选择、失效清理与回收前后占用账目加和一致。
