为零样本语义与实例分割（ZSL）评估团队从零构建一个本地可运行的掩码候选融合与增量类别更新引擎，核心问题是类别词表增量更新后，已缓存的分割结果如何按依赖关系精确失效。输入是本地样本目录：一份图像清单 JSONL，每条含 image id、宽高与若干真实掩码（以 RLE 式行段编码给出像素区间）；一份类别词表 JSON，含每个类别的名称、文本嵌入向量、已见或未见标记与类别版本号；一份候选掩码文件 JSONL，每条含候选 id、所属 image id、掩码区间编码、类别无关置信度与嵌入向量。团队需要完成候选掩码与真实掩码的匹配、按已见与未见类别分别汇总指标，并在类别词表发生增量更新时只重算受影响的图像与类别统计。工作区为空，需从零创建项目，图像合成本地确定性进行，不依赖任何预训练权重。

任务环境与准备：
安装 Python 3.11 及以上版本，创建虚拟环境并用 pip 安装 fastapi、uvicorn、numpy、pytest 与标准库自带 sqlite3 模块。
在工作区新建 samples 目录，手工编写固定图像清单、类别词表（含已见与未见类别及固定维度嵌入）与候选掩码 JSONL，嵌入维度统一为 8。
准备一段类别增量更新序列脚本，包含新增类别、修改嵌入、已见未见迁移与删除类别四种操作，用于演示依赖失效。
确认 http 端口可用，提供可用 curl 复现的请求示例；所有运行在本地完成，不访问外部网络。

业务要求：
1. 引擎入口接收样本目录、类别词表文件、候选掩码文件、IoU 匹配阈值与并行 worker 数，校验文件存在、嵌入维度与词表一致、RLE 区间合法且不越出图像宽高、阈值位于开区间内；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不得创建任何结果文件、临时目录或数据库记录。
2. 须实现确定性 RLE 解码与掩码交集面积计算：行段区间须先按起始位置升序排列并合并重叠或相邻区间，再与图像宽度做越界校验；IoU 计算须保证相同输入在任何 worker 分配与执行顺序下得到逐位一致的交集与并集面积，禁止依赖集合遍历顺序或浮点累加顺序。
3. 候选与真实掩码的匹配须采用确定性贪心：按类别无关置信度降序、同分按候选 id 字典序处理，每个候选匹配当前 IoU 最大且尚未被占用的真实掩码，IoU 相同时按真实掩码下标升序选择；每张图的匹配结果须可重复且与单进程全量处理一致。
4. 候选须通过嵌入向量与类别词表做相似度归属，只归属到相似度最高且不低于配置下限的类别，并列时按类别名字典序稳定选择；无法归属的候选计入未归属统计并继续处理，不得因单候选失败使整图或整体任务失败。
5. 类别词表须支持增量更新：新增类别、修改嵌入向量、把某类别在已见与未见之间迁移与删除类别四种操作，每次更新推进类别版本号；引擎须按类别与图像的依赖关系计算受影响集合，只重算受影响图像的匹配与统计，未受影响结果必须复用已持久化数据。
6. 失效判定须精确到依赖粒度：某图像的真实掩码与候选相似度归属所引用的类别若未被更新，则该图不得重算；诊断报告中须区分“依赖失效被评估但结果未变”和“实际重算”两类图像，并给出各自的计数与 image id 清单，防止粗粒度全量重算掩盖依赖错误。
7. 匹配进度与统计须在 SQLite 中以图像粒度事务提交，匹配结果以原子替换写入不可分割的分片文件并登记内容哈希；进程被强制终止后重启须核对分片哈希与数据库提交标记，重算未提交图像且不重复消费已提交图像，恢复后的类别统计与无中断执行完全一致。
8. 每次类别更新或完整评估须生成整体替换的版本化快照，含类别版本号、各图像匹配摘要与分片哈希；查询快照时若检测到数据库记录与磁盘分片哈希不一致、类别版本变化或残留旧分片，须返回 E_STALE 并定位到类别版本与图像；另须提供确定性演示入口，用固定样本与一段类别增量更新序列跑出重算与复用图像数、已见与未见混淆计数、快照版本序列的可重复结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定样本与类别增量序列验证掩码匹配、依赖失效范围、中断恢复后统计一致及版本化快照。
