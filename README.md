当前是空白工作区，需要从零构建一个面向文生视频与图生视频场景的本地专业应用，核心业务问题是交互延迟与计算结果一致性。业务对象是本地确定性生成的生成任务：提示词经确定性哈希映射为条件向量，随机种子驱动初始潜帧，采样器按配置步数逐步去噪出一段潜帧序列，再经解码模块输出帧序列（固定尺寸 RGB 帧，逐字节可复现）。用户在前端以交互方式逐块预览视频：先请求前若干帧的低延迟预览块，再请求后续块，最后请求完整视频。核心矛盾是：按块分段解码可显著降低首块可见延迟，但分块边界处的归一化统计量、帧间混合与量化策略若处理不当，会使逐块拼接结果与一次性整段解码结果不一致；而若为追求一致而整段重算，则首块延迟预算无法满足。系统须在延迟预算、分块参数与结果一致性之间做显式取舍，并保证同一输入、种子与配置下任意分块方式重跑得到逐字节一致的结果。

任务环境与准备：
安装 Python 3.10 及以上，并在本地虚拟环境中安装 NumPy（版本以能提供确定性浮点数组为准）。
在工作区创建项目目录，样本由固定种子的本地脚本确定性生成，不下载外部数据、不访问网络。
确认可在本地启动多进程（非容器环境），并为并发与资源上限演示预留足够内存与磁盘缓存目录。

业务要求：
1. 实现确定性的生成与解码流水线：提示词哈希、种子初始潜帧、逐步去噪、潜帧解码为 RGB 帧四个阶段串联，帧尺寸与步数由配置给出；同一提示文本、种子与配置下必须逐字节产出相同的中间潜帧与最终帧序列，禁止依赖系统时间、字典遍历顺序或任何未声明的外部状态。
2. 实现流式分块解码：把帧序列按可配置块大小切块，逐块解码并对外提供“已就绪块”查询；首块可见延迟须以本地解码循环的实际处理计时观测并按帧数与解码阶段数给出估算值，超预算时返回 E_LATENCY_BUDGET 并附带已完成阶段与已解码块数，禁止用固定等待冒充计算完成。
3. 实现分块解码与整段解码的逐字节一致性：块边界处的归一化统计量、帧间混合与量化必须与整段解码采用同一口径，逐块拼接结果与一次性整段解码结果逐帧逐像素相同；检测到差异返回 E_CHUNK_MISMATCH 并指出首个不一致的块索引、帧索引与像素位置。
4. 实现延迟与一致性的取舍裁决：当块过大使首块延迟超出预算、块过小使分块边界中间态增多并放大一致性风险时，须按显式优先级规则在块大小、预算与一致性校验强度之间裁决，并在解码计划中记录裁决依据、所选块大小与按本地计时观测的首块延迟估计。
5. 实现图生视频的参考帧锚定：以本地输入图作为首帧锚点，后续帧按配置的锚定强度向参考帧统计量回归；须校验输出首帧与输入图逐像素一致、锚定强度在合法区间内，违反分别返回 E_ANCHOR_MISMATCH 与 E_CONFIG_INVALID，且锚定不得破坏分块一致性。
6. 实现解码快照的版本化与整体替换：解码参数、分块计划与已就绪块清单各携带单调递增版本号与内容校验和，提交时整体替换旧快照而非增量修补；重启加载时识别版本变化并整体替换，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明快照类别与版本号。
7. 实现并发预览请求与资源上限：多个预览请求可并发执行，同一时刻只允许一个分块计划提交生效，并发提交冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待；为单次生成帧数、单块驻留内存与并发解码任务数设可配置上限，超限时返回 E_RESOURCE_LIMIT 或按明确策略降级并标记降级类别。
8. 提供一个本地可交互的专业应用与可重复演示：展示当前生成阶段、块就绪进度、首块实际观测计时、块大小选取、快照版本、一致性校验结论与最近业务错误码，支持切换分块大小并触发一次演示运行——逐块预览后在另一块大小下整段解码并比对逐像素一致性，附一次注入异常输入与一次超预算演示。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
