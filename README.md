团队准备在本地新工作区交付一个 FlashAttention 分块算子诊断组件，当前目录没有任何代码或样本，需要从零构建可集成的领域组件与完整示例，核心业务问题是当某头的 QKV 权重以更高修订版本替换时，只重算受影响的分块及下游归一化统计，同时保证与全量重算逐元素一致。全部输入由随工程交付的固定种子脚本确定性生成：注意力任务清单为 JSONL，每行含 case_id、seq_len、head_dim、num_heads、q_block_len、kv_block_len、weight_revision、dtype、causal、seed；Q、K、V 数组由固定种子驱动 NumPy 确定性生成并存入本地文件。组件把一次分块注意力建模为输入校验与分块计划、分块打分、在线归一化统计、输出写回四个节点，对外提供可集成的领域组件接口与完整示例，并用 SQLite 记录快照账本。核心矛盾在于增量修订必须精确限定在受影响分块与头，同时缓存复用与整体替换不能破坏版本化账本的原子性和重放一致性。

任务环境与准备：
安装 Python 3.10 以上版本和 NumPy，另需标准库 sqlite3、hashlib 与 json。
准备可执行的固定种子样本生成脚本，在本地生成任务清单 JSONL 及 Q、K、V 数组。
使用本地 SQLite 文件完成账本初始化和版本化提交。

业务要求：
1. 实现输入校验与分块计划模块，解析任务清单并校验 seq_len、head_dim、num_heads 与数组维度、q_block_len、kv_block_len 以及 causal 语义声明一致，为每个 Q 分块生成带版本号的计划记录并持久化到 SQLite，重复 case_id 或维度不匹配返回 E_INPUT_INVALID。
2. 实现确定性的分块注意力核心，按 q_block_len 与 kv_block_len 切分执行打分、逐行最大值更新、指数修正及输出累加，所有中间量使用 float64 并配次正规数保护，同一输入同一 seed 下输出必须逐元素可复现。
3. 实现基于内容寻址的四节点缓存，缓存键纳入输入数组哈希、case_id、q_block_len、kv_block_len、dtype 与上游产物哈希；键相同复用快照并拒绝重算，键不同必须重算；输入校验、分块计划、分块打分、归一化统计与输出写回均落盘。
4. 实现权重修订定向失效传播，当某头 weight_revision 提升且 K/V 内容变化时，定位受影响 Q 分块与归一化统计节点，仅重算这些后缀；未受影响分块与头的已提交结果不得重建并输出重算/复用分块清单。
5. 实现整段对照与统一分块稳定性，为每个分块保存局部最大值和归一化分母，合并这些统计量与整段统计量一致，整段输出由分块拼接结果逐元素一致；偏差超过容差返回 E_TOLERANCE_EXCEEDED 并输出首个差异位置。
6. 实现并发提交控制与资源预算，同时只允许一个版本化快照提交生效，并发冲突后到者返回 E_STAGE_BUSY；对单次调用的分块驻留内存和可并行重算的 Q 分块数设可配置上限，超限返回 E_RESOURCE_LIMIT 或降级串行并标记。
7. 实现 SQLite 账本与快照整体替换，每个 case 节点结果写入带单调递增版本号、内容校验和、时间戳和依赖哈希的账本，检测到版本号或校验和变化整体替换旧快照，不允许增量修补；回退尝试返回 E_SNAPSHOT_ROLLBACK。
8. 实现跨模块一致性自检与完整示例，对每个 case 重放关键依赖并按记录重建输出，校验分块整流与账本重放结果一致；命令行示例读取本地确定性样本，输出结果摘要、账本查询、重算/复用清单及业务码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定种子样本验证增量修订与全量重算逐元素一致，并通过账本与自检确认重放结果无未解释偏差。
