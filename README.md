当前是空白工作区，需要从零构建一个面向本地 Windows 环境的容量评估与压测工作台。系统以本地回环 TCP 上的模拟服务（由本仓库附带的本地脚本启动，可配置每请求固定处理耗时与按确定性规则产生的错误率）为压测目标，用户以本地 JSON 场景文件定义一次容量评估：包含若干个阶梯阶段（每阶段给定持续秒数、并发连接数与目标吞吐上限）、一个评估指标集合（成功率、P95 延迟、吞吐）以及一个 SLO 门槛。工作台按阶梯顺序发起负载，按固定采样间隔采样请求结果，把每个阶段的观测聚合为指标，与 SLO 门槛比较后判定该阶段通过或饱和，并把整次会话（场景定义、阶段观测、判定结果、负载参数版本）持久化为可命名快照。核心业务是：压测会话的状态演进必须可回退且恢复后与快照一致；用户在中途修改并发或阶段顺序后重跑，旧阶段的观测必须被识别为陈旧而整体替换；强制终止后只能依赖已持久化的阶段结果恢复，不能假设补出未完成的阶段报告。要求对观测口径、时钟基准与真值来源给出明确定义。

任务环境与准备：
安装 Python 3.11 及以上版本，并确认 Tkinter 可用（Windows 版 Python 安装器默认包含）。
在空工作区创建项目目录并通过 pip 安装 numpy（用于定点统计与分位计算的本地依赖）。
准备本仓库附带的本地模拟服务脚本与确定性样本场景 JSON、演示脚本；不访问真实站点、真实账号或线上压测目标。
确认回环端口 127.0.0.1 上可启动本地模拟服务，运行演示前先检查端口占用以避免与演示冲突。

业务要求：
1. 实现场景文件与本地模拟服务目标定义的加载与强校验：从本地 JSON 文件读取阶梯阶段（持续秒数、并发连接数、吞吐上限）与 SLO 指标门槛，校验阶段序号连续唯一、并发与时长为正整数、门槛比例合法、目标为回环地址；非法输入须以 E_SCENE 业务码整体拒绝加载并输出字段位置。
2. 实现按阶梯顺序的负载驱动与采样观测：每个阶段在独立工作线程组内按并发连接数向本地模拟服务发请求，按固定采样间隔记录成功数、失败数、延迟观测；延迟与时间戳必须写明时钟基准（单调计数毫秒）与真值来源（本地服务端日志回执），禁止仅凭客户端推断成功。
3. 实现阶段级指标聚合与 SLO 判定：从阶段采样聚合成功率、P95 延迟与吞吐（整数定点表示并给出量化误差上界），与 SLO 门槛比较后判定通过或饱和；饱和度判定须区分失败率超限与延迟超限两类原因，并把触发指标与所用聚合口径版本写入阶段结果。
4. 实现负载参数版本与陈旧观测识别：场景中的并发、阶段顺序或门槛被修改后版本号单调递增，此前阶段观测必须被标记为陈旧且不得参与当前判定；重跑产生的新阶段结果须整体替换旧结果而非逐阶段增量合并，替换时须稳定列出被替换的阶段序号与旧新版本差异。
5. 实现压测会话快照与强制终止后的恢复：快照持久化场景定义、负载参数版本、每个已结束阶段的观测与判定、当前阶段进度标记；强制终止后重启只能依据快照恢复已完成阶段的状态，未完成阶段须标记为未知并要求重新执行，禁止承诺生成该阶段的退出报告。
6. 实现恢复后的一致性重放校验：从快照恢复后对快照中每个已结束阶段按其记录的并发与时长在本地模拟服务上重新驱动并重新聚合指标与判定，与快照结果按固定容差逐项比较；因参数版本或目标服务配置不一致导致不可复现时须以 E_REPLAY 业务码报告并列出首个偏差阶段。
7. 实现异常链路与业务码报告：支持以命令行参数注入场景文件损坏、本地模拟服务端口占用、采样时钟回拨三类异常，分别以 E_SCENE、E_PORT、E_CLOCK 业务码报告并写入结构化日志；注入仅改变输入或启动参数，不得通过改动源码制造失败。
8. 提供 Tkinter 交互界面与可重复演示脚本：界面展示阶梯进度、各阶段并发与实测吞吐、成功率与 P95、判定原因、参数版本与快照列表，渲染顺序稳定；附带确定性样本场景与演示脚本，顺序执行冷启动全阶梯压测、修改并发后重跑、快照恢复重放三个场景并输出稳定顺序总结。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地模拟服务跑通阶梯压测并对快照恢复后重放校验结果与判定一致。
