在一台没有历史代码的机器上，需要从零实现一个本地多租户资源配额账本与跨服务预留仲裁引擎，交付可交互的专业应用与可重复演示。业务对象为一组租户、一组资源池与一组服务：租户在资源池上持有配额上限（整数毫核与整数 MiB），服务向租户申请资源预留（申请 ID、服务名、租户、所需毫核与 MiB、申请逻辑时钟毫秒、持有逻辑时长），预留经仲裁后占用租户配额，到期或被撤销时须释放并追平等待队列。本地 JSON 样本给出租户清单（租户名、资源池、配额上限、是否允许超额借调、借调上限）、服务清单（服务名、所属资源池、每轮申请批次、单服务并发预留上限）与申请轨迹（申请序号、租户、服务、所需资源、申请与到期逻辑时钟）。所有时间判定只依赖注入的整数毫秒逻辑时钟，不读取系统墙钟。核心矛盾是：为降低仲裁交互延迟允许同一租户的多个服务并行提交预留，但配额上限、借调规则与释放追平又要求账本在任意时刻严格守恒；并行提交、借调与到期释放交错时，容易出现账本已扣但追平未推进、或追平已推进但账本未释放的中间状态。

任务环境与准备：
安装 Python 3.11 或以上，并确认 python 与 pip 在 PowerShell 中可用；无需外部服务或 GPU。
安装依赖：pip install flask pytest；SQLite 使用 Python 标准库 sqlite3，无需额外安装。
在本地工作区准备确定性 JSON 样本：租户清单、服务清单与申请轨迹各一份，并另备一份含畸形字段、非法借调上限与回退版本的异常样本。
确认本地回环地址可用，Flask 仅监听 127.0.0.1 供诊断命令与演示使用。
运行前清空或新建本地数据目录与 SQLite 文件，保证每次演示从确定状态开始。

业务要求：
1. 实现租户清单、服务清单与申请轨迹的解析校验：租户名与服务名唯一、资源池声明闭合、配额上限与借调上限为非负整数、申请序号严格递增、申请与到期逻辑时钟为非负整数且到期不早于申请、所需毫核与 MiB 为正整数、单服务并发预留上限为正整数；非法条目必须返回明确业务错误码且不写入任何持久化状态。
2. 实现基于注入逻辑时钟的预留到期释放与等待队列追平：预留到期或被撤销时须在同一事务内释放其占用的租户配额并唤醒该租户等待队列中的申请，唤醒按申请逻辑时钟与申请序号稳定排序依次尝试准入，直到配额不足或队列为空；不得因并行提交而跳过任一释放产生的可准入机会，追平结果须记录触发来源释放的申请 ID 与最终未获准入的申请及原因。
3. 实现并行预留提交与配额账本的严格守恒：允许多个服务在同一轮次内并行提交同一租户的预留申请，同时受每轮总逻辑时间预算与单服务并发预留上限约束；每次准入必须在同一事务内扣减该租户的毫核与 MiB 账本并写入预留记录，任意时刻盘点不得出现负余量、重复扣减或预留记录引用了未扣减配额的情形；预算耗尽须放弃剩余未启动申请并记录放弃原因。
4. 实现超额借调裁决与归还义务的账本追踪：当租户配额不足但声明允许超额借调且借调额度有余时，可借调后再准入，借调量须单独记账并记录借出来源（资源池余量）、借调逻辑时刻与归还期限；预留释放时须优先归还借调量再恢复租户余量，归还顺序与归还数量须可追溯，归还账本不平即拒绝该次释放并返回独立业务错误码。
5. 实现定点配额余量与耗用率的误差谱记录与精度敏感标记：租户余量、借调量与耗用率按声明定点标度换算，登记每次换算的标度、舍入方向与换算前原始值并累计误差上界；当两个申请或两个租户的剩余配额差小于浮点容差且准入裁决依赖该差值时必须标记为精度敏感并输出误差来源链（参与租户、申请序号与换算步骤）。
6. 实现强制终止后的恢复与半提交追平的裁决：把已提交流程水位、租户配额账本、预留记录、等待队列内容摘要、借调账本与逻辑时钟水位以事务原子写入 SQLite；进程在准入扣减或释放追平中途被强制终止后，恢复路径须依据持久化状态识别已提交预留与半提交释放，只重放未完成部分，不得重复扣减或重复归还借调量，恢复后账本与不中断运行逐位一致。
7. 实现配额声明版本整体替换与在途预留的版本绑定：租户配额声明每次变更产生新版本号并以内容摘要整体替换当前声明指针而非逐条覆盖，须比较配额上限、借调上限与允许借调标记判定完整替换、增量追加或无需操作；版本回退必须被拒绝并返回业务错误码，进行中的预留继续按其准入时绑定的声明版本结算到期释放，替换后未受影响租户的在途预留不得被重算。
8. 实现多进程并发一致性与可重复命令行演示：多个仲裁实例并行处理同一租户的不同服务申请时，通过 SQLite 事务与文件锁保证同一申请序号同一版本只被准入一次、同一租户配额与借调账本不被并发超扣、等待队列不被并发重复唤醒，重复提交相同申请或相同释放必须幂等；提供 load、submit、release、resume、status、verify 子命令，status 以稳定排序 JSON 输出各租户已用与剩余配额、借调余额、等待队列长度、精度敏感标记与当前声明版本。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
