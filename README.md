当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向客服对话文本的本地情感与风险判定领域数据编辑与操作应用。业务对象是本地确定性生成的对话样本：每条会话由固定种子拼装若干条消息（JSONL，字段含 conv_id、msg_no、speaker、text、locale、annotator_group），并配有判定配置（情感三分类权重、风险类别受控集合、风险词表、判定门限、批大小、缓存策略与精度标记）。判定链路为：文本归一化→按消息切分情感打分（词典与否定/程度修饰的确定性加权）→风险词级命中与上下文合并→会话级聚合（按消息权重与时间衰减）→风险分级门限判决。编辑侧允许修改单条消息文本、调整单条消息权重、拆分与合并会话切片。核心矛盾是：交互式按会话查询必须低延迟返回，而编辑后会话级聚合与风险分级必须与批量全量判定结果完全一致，且缓存、快照版本与并发编辑会让两侧结果偏离。

任务环境与准备：
安装 Python 3.11 或以上版本，并安装 NumPy（版本以本地 wheel 可用为准，安装说明随仓库提供）。
在仓库根目录创建本地确定性样本生成脚本入口，按固定种子生成会话 JSONL、风险词表与判定配置，样本随仓库提交，不访问网络。
确认可在 Windows 本地进程与本地文件系统上运行，不需要 Docker、容器或外部服务。
准备命令行入口与运行说明，使演示流程（基线判定、交互查询、编辑后失效、异常注入）可在本地一次性执行。

业务要求：
1. 实现确定性的文本归一化与消息级情感打分：依据随附否定词表与程度副词表对归一化文本做加权情感分数，三分类取最高分且同分按固定类别顺序裁决，同分消息按 msg_no 升序打破平局；同一会话、同一配置与固定种子下逐消息分数必须逐字节一致，禁止依赖字典遍历顺序或系统时间。
2. 实现风险词级命中与上下文合并：按受控风险类别集合与风险词表输出每条消息的命中类别、命中码点区间与合并后的风险候选，相邻消息同一类别的合并规则须显式声明，无命中时须形成空命中，且命中区间必须落在该消息归一化文本的码点范围内，越界或类别非法返回 E_RISK_SPAN。
3. 实现会话级聚合：按消息权重与时间衰减把情感分数与风险候选聚合成会话级分数与风险分级，衰减与聚合口径必须在诊断报告中显式记录；同一快照与配置下会话级分数与分级都必须可复现，且聚合结果必须能由逐消息明细与权重独立重算一致，重算偏差返回 E_AGG_MISMATCH。
4. 实现交互式按会话查询接口并控制单次延迟：按 conv_id 查询该会话的聚合分数、风险等级与命中明细，须在配置的单次延迟预算内返回；延迟以本地判定循环的实际处理计时作为观测，估算记录给出消息数与风险词表规模；超预算返回 E_LATENCY_BUDGET 并附带已完成阶段标记，禁止以无依据的推测代替真实测量。
5. 实现查询侧与批量侧结果一致性保证：查询返回的会话聚合分数、风险等级、命中明细必须与批量全量判定结果中同一 conv_id 的记录在声明精度内一致，并校验参与判定的消息集合与批次完全相同；检测到偏差返回 E_INCONSISTENT 并指出不一致类别、conv_id 与首个差异消息序号。
6. 实现编辑操作与判定缓存的失效联动：支持修改消息文本、调整消息权重、拆分与合并会话切片，编辑后须保持 msg_no 连续且会话内消息不重复；缓存键须纳入会话内容哈希、消息权重摘要、风险词表与配置版本、精度标记，任一输入变化必须计算受影响的缓存条目集合并仅失效并重算，缓存命中与否不得影响正确性。
7. 实现判定快照与配置的版本化及整体替换：会话级判定结果、风险词表与权重配置各携带单调递增版本号与内容校验和，提交时整体替换旧快照而非增量修补；重启加载时识别版本变化并整体替换、旧版本不得覆盖新版本，回退尝试返回 E_SNAPSHOT_ROLLBACK；损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指出类别与版本号。
8. 实现并发提交控制、资源上限与跨模块一致性自检：同一时刻只允许一个编辑或判定快照提交生效，并发冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待；为会话数、消息总数与缓存条目数设可配置上限，超限返回 E_RESOURCE_LIMIT 并标记降级类别；自检校验缓存条目均可追溯到快照版本、查询与批量消息集合吻合，不一致时返回 E_INCONSISTENT 并指出类别。
