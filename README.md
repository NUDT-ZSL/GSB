当前是空白工作区，需要从零构建一个面向 Windows 本地环境的故障隔离与容灾切换编辑台，作为领域数据编辑与操作应用。用户在 Tkinter 界面或本地 JSON 场景文件中维护一组服务实例（每个实例含服务标识、主备角色、回环端口与健康探测参数）、一组故障注入项（实例不可达、响应超时、返回错误）以及每个服务声明的切换策略（自动或人工、切换冷却毫秒、最小健康副本数）。核心业务是：在受全局并发预算与每服务探测配额约束下并行执行健康探测，判定实例健康状态，在满足策略条件时把服务从主实例切换到备用实例，并在冷却窗口内抑制重复切换；切换过程须保证同一服务任一时刻只推进到一个确定的目标实例，探测结论、切换决策与实例角色变更写入本地 SQLite 会话库，进程被强制终止后只能依据持久化状态恢复。

任务环境与准备：
安装 Python 3.11 或以上版本，确认标准库包含 tkinter、sqlite3、json、threading、socket 与 subprocess。
在空工作区创建项目目录，准备本地样本场景文件与本地回环模拟实例脚本（仅使用 127.0.0.1 高位端口）。
运行前确认样本端口未被占用，必要时通过命令行参数改用其它回环端口。
准备演示脚本按顺序执行全量探测与切换、故障注入后的切换抑制、强制终止后恢复与重放校验三段场景。

业务要求：
1. 实现场景文件与会话库的加载与强校验：从本地 JSON 读取服务实例、故障注入项与切换策略，校验服务标识唯一、主备角色组合合法且每服务恰有一个主实例、回环端口在 1 至 65535 且全局不重复、探测超时与冷却毫秒为正整数、最小健康副本数不超过实例数；任一不合法须以 E_SCENE 业务码整体拒绝加载并给出行号与字段名。
2. 实现受预算约束的并行健康探测：依据全局并发上限与每服务探测配额并行探测各实例，任何探测不得绕过配额；单次探测须区分成功、不可达、超时与错误返回四类结论并记录单调时钟起止毫秒；某实例在探测中失败须按策略重试且重试不得改变单次探测结论，最终以 E_PROBE 记录重试耗尽。
3. 实现实例健康状态机：依据连续成功与失败次数阈值把实例状态在 unknown、healthy、unhealthy 间迁移，每次迁移记录触发原因、探测轮次与时刻；若某实例探测记录缺失，状态须保持 unknown 且不得被推断为 healthy，状态迁移序列须可稳定重放。
4. 实现容灾切换决策与冷却抑制：在服务主实例不健康或健康副本数低于阈值时，按声明策略判定是否切到备用实例；同一服务在冷却窗口内的重复切换请求须被抑制并记录 E_COOLDOWN，人工策略下须拒绝自动切换并登记待确认请求；切换须给出目标实例、触发依据与所用策略版本。
5. 实现服务角色切换的确定性与互斥：同一服务任一时刻只能有一个进行中的切换事务，目标实例选取须按明确且稳定的排序规则，不得依赖字典或哈希遍历顺序；切换完成后主备角色与实例版本号须原子更新，并发切换请求须收敛为唯一成功结果，其余以 E_BUSY 报告。
6. 实现切换后的一致性校验：切换完成后重新探测目标实例与其余实例，校验服务健康副本数是否达到最小要求、角色拓扑是否恰有一个主实例、被替换实例是否被标记为已隔离；不满足须以 E_ISOLATE 报告并列出偏差的实例与字段，隔离标记不得被后续普通探测自动清除。
7. 实现会话快照的版本识别与整体替换恢复：快照持久化到本地 SQLite，含场景版本、策略版本、实例角色与版本号、冷却窗口起点、隔离标记与已完成切换记录；重新打开快照时先比较快照场景版本与当前场景版本，不一致须整体替换当前实例、策略与冷却状态而非增量合并，恢复后未完成切换须标记为未知并要求重跑。
8. 实现恢复后的重放校验与异常注入：从快照恢复后按快照记录的场景版本与探测参数重新执行探测与切换决策，将实例状态迁移、切换目标与业务码与快照逐项比较，因场景版本或策略参数不一致导致不可复现时以 E_REPLAY 报告具体差异；支持以命令行参数注入场景损坏、模拟实例不可达、会话库写失败，分别以 E_SCENE、E_PROBE、E_SNAPSHOT 报告并写入结构化日志。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
