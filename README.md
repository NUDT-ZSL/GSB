当前是空白工作区，需要从零实现一个本地调度插件仿真与诊断工作台，用于在确定性样本上复现插件链裁决并支持受控异常注入，但核心业务问题不是打分公式本身，而是“过滤裁决、亲和性打分与资源账本三者在异常注入下的一致性归属”。本地 JSON 样本给出：节点清单（节点名、可分配 CPU 毫核与内存 MiB、节点标签、污点）、Pod 清单（Pod 名、请求资源、优先级、节点亲和与反亲和规则、拓扑散布约束、容忍声明）、调度配置（过滤插件启用列表、打分插件权重、单轮逻辑时间预算毫秒、重试预算）以及注入清单（按调度轮次在过滤或打分阶段注入节点标签冲突、资源超卖、权重非法等异常）。工作台不依赖真实集群，资源换算使用整数毫核，时间判定使用可注入逻辑时钟。要求把每次裁决落成“决策归属账本”：每个 Pod 的淘汰或绑定都归属于具体插件、轮次与输入摘要，异常注入只允许改变归属记录而不允许污染其他 Pod 的已提交归属与资源账本。

任务环境与准备：
Windows 10/11 或 Windows Server 2019 及以上，安装 Python 3.11 与 pip
安装依赖：pip install numpy==1.26.4；标准库 sqlite3、json、fcntl 替代方案（msvcrt 或文件锁封装）直接使用
在空白工作区创建项目目录，准备节点、Pod、调度配置与注入清单的本地 JSON 样本，样本自包含且不使用网络
确认本地可写目录用于 SQLite 数据库与诊断报告输出，运行时不需要真实集群、容器或外部服务

业务要求：
1. 实现节点、Pod、调度配置与注入清单的解析校验：节点名与 Pod 名唯一，CPU 毫核与内存 MiB 为正整数，污点与容忍键值格式合法，过滤插件启用列表与打分插件权重覆盖全部已声明插件且权重之和为正，注入清单引用的轮次与阶段存在；非法条目返回明确业务错误码（如 E_BAD_NODE、E_BAD_POD、E_BAD_CONFIG、E_BAD_INJECT），且不得写入任何持久化状态。
2. 实现过滤插件链并产出可归属的淘汰记录：依次执行资源可行性、污点容忍、节点亲和、Pod 间反亲和与拓扑散布过滤，每个淘汰记录须携带插件名、节点名、首个淘汰证据（如哪一项请求资源超出、哪条污点未被容忍）与该证据来源字段，资源可行性必须在整数毫核与 MiB 换算后比较，不得以浮点累加请求作为判据。
3. 实现打分插件链并给出加权归一化的可复现中间值：按资源装箱、节点亲和匹配度与拓扑散布均衡度计算原始分，按配置权重归一化为总分，输出每节点每插件的原始分、权重、归一化中间值与总分，并按总分稳定排序、同分按节点名次序决胜；当权重之和为非整数浮点时须给出量化后的总分与误差上界，同一样本两次运行逐值一致。
4. 实现决策归属账本与回放：每轮调度为每个 Pod 记录归属条目（选中节点或淘汰原因、命中插件、绑定前后资源值、输入清单摘要与注入消费标记），回放时校验清单摘要与注入消费水位，摘要不匹配须返回业务错误码并拒绝回放；账本条目一旦提交不得被后续轮次改写，只允许以版本号整体替换指针。
5. 实现注入异常的作用域隔离：按注入清单在过滤或打分阶段注入标签冲突、请求超卖、权重非法、插件缺失，每种异常只改变其指定 Pod 与轮次的归属条目并映射不同业务错误码（含轮次号、Pod 名、节点名、插件名），同轮其他 Pod 的归属与资源账本必须逐字段保持不变，且异常不得阻止本轮其余 Pod 完成裁决。
6. 实现资源账本与归属条目的原子绑定：绑定成功时在同一事务内扣减目标节点 CPU 毫核与内存 MiB、写入归属条目并登记来源 Pod 与轮次，任意时刻对账不得出现负余量、重复扣减或归属条目引用了未扣减的资源；异常或回滚路径不得留下已扣资源却无归属条目的悬挂记录。
7. 实现强制终止后的恢复与多实例幂等：把轮次水位、节点资源账本、Pod 阶段、注入消费水位、账本指针版本与逻辑时钟水位以事务写入 SQLite；进程在过滤、打分或绑定中途被强制终止后，恢复路径只重放未提交部分且不得重复扣减；多实例并发时通过事务与文件锁保证同一 Pod 同一轮次只被绑定一次，重复提交相同绑定结果幂等。
8. 提供命令行接口与可重复诊断演示：支持 load、schedule、inject、resume、status、verify 子命令；status 以稳定排序 JSON 输出各节点剩余资源、各 Pod 归属摘要与注入消费状态；verify 校验资源账本与归属条目的一一对应；固定样本连续两次运行输出逐字节一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
