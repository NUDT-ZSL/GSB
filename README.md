城市公共数据开放目录维护着一批人口、交通与环境统计表，表格由多个部门在不同年代接入，空值普遍存在；同一张逻辑表在目录中留有字段命名、定点小数刻度与空值位图编码各不相同的三个 schema 版本。开放数据查询服务在接入正式列式存储引擎之前，需要一套独立可验收的列式批处理求值组件：按批把列式数据块送入表达式树，逐节点求出结果列与空值掩码，并把求值过程记成可逐批核对的账目，使统计口径不因查询写法或表版本而漂移。资源受限的公共数据网关要求每批计算在声明的行数与列宽预算内完成，超限批次必须按声明策略被拒绝而不是静默截断。

任务环境与准备：
准备 Linux（WSL Ubuntu）下的 Python 3 运行环境，仅使用标准库，无需安装第三方包。
在工作目录中创建项目根目录与入口脚本，样本由题内确定性生成器按固定种子现场产出，不依赖外部数据文件或服务。

业务要求：
1. 实现确定性样本生成器，按固定种子产出列式数据块：每块声明若干列，列类型覆盖整型、定点小数、字符串与布尔，行数固定，空值以显式位图表达；同时产出三个 schema 版本描述同一逻辑数据块，版本差异体现在字段命名规则、定点小数的刻度表示方式与空值位图编码（逐列位串与全局游标编码两种）上，并提供表达式规格集合。
2. 把三个 schema 版本的列式数据块与表达式规格归一为统一内部模型，输出的归一模型需保留原始字段名到统一列名的映射、定点刻度对齐结果与空值位图统一编码，并生成可核对的版本差异清单。
3. 按表达式树对每批数据做列向量化求值，算术、比较、逻辑与函数调用节点均以整列向量为单位计算，输出每个表达式的结果列与对应空值掩码，不得退化为逐行标量调用。
4. 对算术、比较与逻辑节点按三值逻辑传播空值：任一操作数为空时结果空值位置位，逻辑节点的空值与真、假组合按标准三值真值表处理，并统计每节点空值输入数与空值输出数。
5. 按类型提升规则处理跨类型运算，输出每个节点的提升后类型与定点刻度对齐依据；整型与定点混合运算、布尔与整型比较须给出明确一致的提升结论，刻度不一致时按统一刻度对齐后再计算。
6. 对条件表达式用选择向量分离真假分支分别求值再合并，输出各分支选择行数、合并后的结果列与空值掩码，并保证未选中分支中的空值不污染结果。
7. 输出逐表达式节点的求值账目，含求值行数、空值输入数、空值输出数、类型提升记录与分批行数，并保证同一逻辑数据在三个 schema 版本下求值结果与空值掩码一致，差异仅体现在版本差异清单中。
8. 内置独立三值逻辑参考求值器，以整列逐批方式复算并逐批逐节点核对主求值链路的输出；出现不一致时报告首个不一致批次、表达式节点与列位置，并附对应的空值掩码差异。

验收：
以独立三值逻辑参考求值逐批核对结果列与空值掩码，并验证三个 schema 版本归一后求值结果一致。
