当前为空工作区，需从零开发一个本地叙事分支推演引擎，面向互动叙事的剧情编排与校验。剧本由场景节点、带前置条件与副作用的事件、以及分支选择构成，玩家选择会改变世界状态（角色关系值、持有物品、已揭示线索、节点标志），而事件是否可触发取决于这些状态。数据规模会从数十节点增长到数万节点与数十万事件，引擎需要在多种预计算策略之间做算法取舍：小规模可直接逐事件扫描，大规模必须依赖索引或惰性求值才能保持可交互。业务要求是编辑者可以加载剧本、推演任意分支路径、查看每个状态变化的因果链（哪个事件、哪个前置条件、哪个上游选择导致），并在编辑剧本后重新推演验证不会出现死锁分支（所有选择都无可行事件）或未定义状态引用。真实难点在于因果链必须可追溯到真实触发事件而非重新推演臆测，且规模增长时推演结果与因果归因必须与朴素实现逐字段一致。

任务环境与准备：
在 Windows 上安装 Python 3.11 或 3.12，并通过 pip 安装 PyQt6 指定版本。
确认无外部网络依赖，剧本样本与状态目录由程序按确定性规则在本地生成。
准备一个空工作区作为项目根目录，任务开始前不存在任何项目文件。

业务要求：
1. 实现剧本描述解析与校验：读取 JSON 剧本，校验节点标识唯一、事件前置条件与副作用引用的状态键均已在状态声明表中定义、选择指向的节点存在、关系值与数值阈值均为有限数且在声明定义域内，非法输入返回带业务码的 JSON 错误且不产生任何输出。
2. 实现确定性事件推演内核：在每个场景节点内按优先级与声明顺序确定性选择可触发事件，前置条件求值只依赖当前世界状态，副作用按声明顺序应用到状态，同一剧本与同一选择序列重复推演必须得到逐字段相同的世界状态与事件序列，禁止依赖字典或集合遍历顺序。
3. 实现多策略推演的等价性：为事件触发提供逐事件扫描与索引加速两种实现，在规模超过规格给出的阈值时切换策略，两种策略在任意剧本与任意选择序列下产出的可触发事件集合、执行顺序与最终状态必须完全一致，切换点不得改变可观测结果。
4. 实现分支路径推演与死锁检测：枚举或按选择序列推进所有可达分支路径，统计每条路径上的节点数、事件数与终局状态，对任一节点若所有选择在任意可达状态下都无可行事件则标记死锁分支并给出该节点的状态快照，检测结果与全量穷举参考一致。
5. 实现逐状态变化的因果链记录：每次状态键变化记录触发事件标识、该事件被满足的前置条件列表、以及决定该事件可达的上游选择与节点序列，因果链须指向真实执行的事件记录而非事后重演，报告中的状态值与推演日志逐条对应。
6. 实现增量重推演与缓存失效：编辑剧本中某节点的事件或前置条件后，只重推演依赖该节点的分支路径并复用其余缓存结果，缓存以输入内容摘要标识版本，版本变化时整体替换前须识别旧版本并归档，增量结果与从头全量推演逐字段一致。
7. 实现可交互推演应用的规模自适应：提供本地桌面界面加载剧本、逐步或连续推演分支、在因果链视图中定位状态来源，并对大规模剧本采用异步加载与分页展示以免阻塞界面；界面展示的状态与因果数据必须来自已持久化的确定性推演结果而非在视图层重算。
8. 处理中断、并发预计算与资源上限：大规模预计算按并发上限使用有界线程池并在节点边界响应可处理终止信号写入中断状态后以约定整数退出码退出，同时在途的预计算结果受内存预算约束，强制终止后仅依赖已持久化状态恢复且不承诺生成退出报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地小规模与大规模剧本样本验证推演一致性、死锁检测、因果链与增量重推演结果，并检查异常输入业务码。
