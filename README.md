# 多屏推流状态一致性工作台

本目录已交付纯 Python 标准库实现、固定种子样本、16 个自动化测试和一键验收脚本。完整设计见 `docs/TECH_NOTES.md`。

```bash
python3 scripts/acceptance.py
python3 -m multiscreen run --data task --state state --report-out output/report.json
python3 -m unittest discover -s tests -p 'test_*.py' -q
```

最近实测：16 个测试全部通过；29 条样本事件覆盖 2 次代数重建、缺口/关键帧恢复、墓碑合并、摘要回退、workers=1/4 结果一致、2 块后中断（退出码 130）并成功续跑。报告见 `output/acceptance_report.json`。

---

多屏互动小组在立项评审通过后拿到一份目标说明，工作目录里除了随题交付的固定种子样本生成脚本之外没有任何可运行代码。产品要解决的是多人会议场景下，会议室主机同时向侧屏与远端投影端推流时，接收端各自维护的帧采纳状态机如何在代数切换、迟到帧与关键帧丢失之间保持一致，并让两代接收端状态快照能够互相接续。样本全部本地确定性生成：投屏会话清单（会话标识、组播组、协议版本 S1/S2、发送端与各接收端角色、屏幕几何宽高像素与缩放比、起点逻辑毫秒、代数切换容忍窗口）、按可注入逻辑时钟给出的帧事件流（事件序号、会话标识、接收端标识、帧序号、采样时刻逻辑毫秒、帧类型关键/增量/丢弃、编码尺寸与载荷长度），以及两代接收端状态快照——v1 为单文件扁平 JSON，以相对起点秒数记录接收端播放位置与扁平游标；v2 为分片 JSON 加 SQLite 元数据库，记录接收端规范标识、绝对逻辑毫秒戳、会话代数、帧采纳游标与墓碑标记。

任务环境与准备：
安装 Python 3.11，确保 python 标准库与 sqlite3 模块可用，无需第三方包。
在 Windows 工作目录中建立 task 子目录存放会话清单、帧事件流与两代快照，样本由随题交付的固定种子脚本生成。
建立状态目录与输出目录并确认可写；SQLite 元数据库由程序首次运行时创建，无需预置。

业务要求：
1. 实现会话清单、帧事件流与两代快照解析校验：读取本地 JSON 与 SQLite 元数据库，校验会话标识与接收端标识唯一、屏幕几何与缩放比为有限正数、帧序号在同一接收端内严格递增且帧类型与关键帧标记一致、逻辑毫秒为非负整数、v1 相对秒数可按元数据换算为绝对毫秒，非法输入返回带 E_xxx 业务码的 JSON 错误且不产生任何状态。
2. 实现以关键帧为恢复点的帧采纳状态机：每个接收端按帧序号与采样时刻推进采纳游标，关键帧可无条件建立解码基线，增量帧只在游标连续且采样时刻落在当前代数容忍窗口内才被采纳，否则进入等待缺口状态并可被后续关键帧或代数切换打断，同一事件流在任意并发度下须得到逐接收端逐字段相同的采纳序列与等待缺口区间。
3. 实现会话代数切换的游标重建：当事件流中的代数切换标记或容忍窗口超限触发代数变更时，按规格规则从该接收端最近采纳的关键帧重建播放位置与游标，并重新计算跨越切换点的等待缺口，重建结果须给出旧代数游标、新代数基线与被丢弃的增量帧清单，且与逐帧串行推进完全一致。
4. 实现两代接收端状态快照合并为统一视图：把 v1 相对秒数换算到绝对逻辑毫秒轴，同代同规范接收端标识按会话代数取新、墓碑标记优先于无墓碑记录，两代对同一接收端游标或播放位置冲突时按代数与逻辑时刻裁决，冲突项须定位到快照来源分片与接收端标识并逐条记录裁决依据。
5. 实现重放裁决校验与偏差定位：把合并视图与帧事件重放结果按逻辑时刻逐接收端比对采纳游标、播放位置、会话代数与等待缺口，发现偏差时定位首个不一致逻辑时刻、接收端标识与字段并输出带 E_REPLAY 的裁决报告，校验通过时同样产出含统计与摘要的报告。
6. 实现快照分片防篡改与版本识别：为每份快照及其分片计算内容摘要并与记录摘要比对，摘要不匹配、缺失或声明的接收端数与实际不符时判定该分片失效并返回 E_DIGEST，合并与恢复须拒绝失效分片并回退到最近一份有效分片，禁止静默使用失效分片继续重建游标。
7. 实现分块级持久化与中断恢复：按逻辑时刻分块把合并视图、状态机采纳轨迹与由会话清单和事件流规范化摘要构成的版本标识原子写入状态目录，先写同目录临时文件再整体替换；可处理终止信号只在分块边界生效并写入中断标记后以约定整数退出码退出，强制终止后重启仅依据已持久化且摘要有效的分块恢复且不承诺生成退出报告。
8. 实现并发分片加载与帧重放资源上限：按配置并发上限使用有界线程池并行加载与校验快照分片，同时在途快照数据与重放缓冲总量受内存预算约束，超出预算时按接收端标识确定顺序等待而非降低校验精度，任一分片失败时取消其余任务并返回首个错误，最终合并与重放结果须与并发度为 1 时逐字段相同。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
