在空白工作区构建一个可集成的分块增量注意力（FlashAttention 风格）算子组件与完整示例，面向本地确定性合成的 Q/K/V 张量序列。注意力按输出块分块计算：每个输出块读取对应查询块与按块累积的 K/V 状态，K/V 以块为单位增量追加，追加后已有块的行级 softmax 统计量（最大值与指数和）随之改变，下游输出块若不重算就会出现数值偏差。核心挑战是增量追加与依赖失效：新 K/V 块只应使读取了受影响 K/V 区间的输出块及其下游重算，未受影响块必须复用已持久化结果；追加还受单次重算预算约束，预算不足时须保留待重算队列并在后续批次收敛。组件需要明确观测口径：块级行最大值、指数和、输出块指纹与逐元素输出，真值由 float64 串行全量参考路径给出。

任务环境与准备：
安装 Python 3.11 与 NumPy（pip install numpy），不依赖 GPU 与外部数据。
在空白工作区建立项目目录，任务开始前不存在任何源码、样本或配置。
用固定种子编写本地样本生成脚本，产出多组 Q/K/V 块序列、K/V 追加编辑序列、异常注入配置与 float64 参考路径。
准备并发数、块大小、重算预算与快照路径的示例配置各一份，供示例运行验证。

业务要求：
1. 实现分块增量注意力内核：输入 float32 的查询块、按块追加的 K/V 序列与块大小配置，对每个输出块按块累加 Q*K^T、以行级最大值做稳定指数归一化，再与 V 块加权求和得到输出块；块内计数顺序固定为查询行、键位置、通道，非整除尾部块须精确裁剪；输出每块的行最大值、指数和、输出张量与块指纹，同一输入多次运行必须逐位一致。
2. 实现块级依赖图与精确失效判定：为每个输出块记录其读取的 K/V 块区间、配置指纹与产出指纹；新 K/V 块追加或替换某 K/V 区间后，仅将读取了该区间的输出块及其按因果顺序的下游输出块标记失效并纳入重算集合，未失效输出块必须直接复用已持久化结果且不得重新执行内核；失效与复用清单须随结果输出并可审计。
3. 实现单次重算预算调度：每批增量运行依据失效集合与配置的单次重算预算（按输出块计）决定本批重算的块，预算不足时按块序号稳定顺序保留待重算队列并以 E_RECOMPUTE_PENDING 业务码标记未完成块，后续批次继续收敛；任何批次都不得为凑齐预算而跳过更早的失效块，收敛后全部输出块指纹须与一次性全量计算一致。
4. 实现增量与全量的数值等价性：从空状态出发施加包含 K/V 块追加、中间 K/V 块替换与块大小配置变更的编辑序列，每次增量运行得到的各输出块张量、行最大值、指数和与指纹，必须与从空白工作区按相同最终输入一次性全量计算的结果在逐元素容差内一致；块大小变更必须真实改变分块边界与累加链，不得沿用旧分块结果。
5. 实现持久化快照与版本识别：以临时文件加原子替换方式将输出块张量、行统计量、依赖图与产出指纹写入快照，快照含全局版本号、配置指纹与已完成块列表；启动时以版本号、配置指纹与输入指纹判定快照是否为最新有效，版本不匹配时输出 E_SNAPSHOT_STALE 并拒绝续跑；强制终止后仅依据已完整替换的快照恢复，恢复点须可在报告中追溯。
6. 实现并发分块计算与串行结果一致性：使用线程池并发计算彼此无依赖的输出块，最大并发数取自配置；每个块任务携带由块序号派生的稳定排序键，无论线程调度顺序与并发度如何，最终输出块顺序、失效与复用清单顺序、重算队列顺序、预算扣减序列与失败清单顺序必须与单线程按块序号顺序执行一致。
7. 实现异常注入与失败隔离：以独立注入配置指定非有限输入元素、K/V 块长度与查询块不匹配、块大小为零、预算为零与快照版本被篡改等样例，注入项编号写入运行报告以证明命中；单块在打分、归一化或加权阶段抛异常时记录块序号、阶段名、业务码与异常类型并继续其余块，异常块不得流入下游复用。
8. 实现精度审计与结果报告：对每个输出块以 float64 串行参考路径给出真值，输出最大绝对误差、最大相对误差与超差元素所在块的归因摘要，并区分误差来自行最大值选择、指数和累加还是加权求和；报告含每批失效与复用块数、重算预算消耗、快照版本号、恢复点、失败清单与业务码，以临时文件加原子替换写盘并按块序号排序输出。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
