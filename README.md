某安全团队在离线 Windows 空白工作区从零开发一个注入类漏洞静态检测工作台。输入是一批本地确定性构造的源码片段清单：每份清单为 JSON，声明文件标识、语言方言（html、sql、shell、js-string 四种之一假想方言）、若干汇点记录（汇点标识、所在行号、上下文类型、需要的编码族），以及若干污点源到汇点的数据流路径记录（路径标识、源标识、途经的编码变换序列列表）。工具须为每条路径判定其在到达汇点时是否已被正确编码：把编码变换序列归一为规范编码族链，与汇点声明的上下文类型所要求的编码族比对，识别遗漏编码、编码顺序颠倒（先转义再解码回原文导致还原失败）与编码族不匹配三类缺陷，并对同一汇点被多条路径汇聚的情形给出综合判定。核心难点是数据规模变化与算法取舍：小清单须做逐路径精确比对并给出每种缺陷的具体位置，大清单须切换为按汇点分组的批处理与编码族等价类判定以控制开销，同时保证两种模式下的缺陷集合与汇点判定完全一致；此外需输出可交互的诊断工作台界面与可复核 JSON 报告。

任务环境与准备：
安装 Python 3.11 与 pip，创建虚拟环境
pip 安装 Flask 3.x 与 pytest 8.x，全部为本地依赖，无需网络账号
在空白工作区规划 samples、reports、checkpoints 三个本地目录并确保可写
无需容器、外部服务或真实站点，全部样本由工作区自带生成器确定性产出

业务要求：
1. 实现源码片段清单与流路径记录的解析规范化层：校验文件标识唯一性、方言取值在四种白名单内、汇点行号为正整数、编码变换序列中的变换名属已知集合，对非法记录输出含记录序号与业务错误码的拒绝记录并继续处理其余记录，不得因单条非法记录中断整份清单。
2. 实现编码变换序列到规范编码族的归一：把每类变换映射为编码族与方向（编码或解码），合并连续同类变换并消去成对的编码-解码抵消，输出规范编码族链与抵消记录，抵消判定须保留被消去变换的原始序号以便报告定位。
3. 实现路径级缺陷判定：对缺少汇点所需编码族的路径返回 E_MISSING_ENC，对编码后又被解码回原文的路径返回 E_ORDER，对编码族与汇点上下文不匹配的路径返回 E_MISMATCH，三类缺陷须分别给出路径标识、缺陷变换序号与所需编码族，互不叠报。
4. 实现同一汇点多路径汇聚的综合判定：当某汇点由多条路径到达时，取所有路径均满足所需编码才判为安全，任一路径存在缺陷则汇点判为可注入并保留所有缺陷路径明细；对同一汇点的重复路径须按路径标识去重且以首次出现为真值，去重后仍须保留缺陷计数。
5. 实现随数据规模变化的算法取舍：以路径记录总数与汇点总数为规模观测值，低规模时逐路径精确比对，超过阈值时切换为按汇点分组并结合编码族等价类剪枝的批处理模式，报告中须显式标记本次模式与等价类剪枝比例；两种模式下缺陷集合、汇点判定与拒绝记录必须完全一致。
6. 实现真实资源预算控制：并发度、单份清单实测耗时上限与单位清单处理路径数上限均可配置，耗时以真实墙钟测量判定而非人为延迟常量，超时返回 E_TIMEOUT、超限返回 E_BUDGET，被超限终止的清单不得中断同批其他清单且须计入报告。
7. 实现检查点与版本变化重建：按已完成文件标识与汇点聚合结论持久化检查点，恢复时只从最后一个完整检查点继续，检测到检查点结构版本或方言白名单版本变化时须整体重建而非增量续接；检查点与报告均先写临时文件再整体重命名替换，同一工作目录并发写入以文件锁串行化，锁冲突返回 E_LOCK。
8. 交付领域可视化诊断工作台与确定性本地测试：提供本地 Web 工作台展示汇点分组摘要、缺陷路径明细、编码族链与规模模式标记，并输出可解析 JSON 报告（含文件级结论、每汇点判定、每路径缺陷码与序号）与退出码区分全部成功、部分失败与参数错误；附样本生成器与 pytest 测试集，覆盖抵消、顺序颠倒、族不匹配、去重、规模阈值切换、超时与锁冲突。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

## 实现交付与快速上手

环境（用户态 uv 安装，无需 sudo / 容器）：

```bash
uv python install 3.11
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -r requirements.txt
```

常用命令：

```bash
.venv/bin/python -m injection_workbench.cli generate           # 确定性样本 -> samples/
.venv/bin/python -m injection_workbench.cli run 'samples/*.json' \
    --report reports/report.json                               # 分析 + JSON 报告 + 检查点
.venv/bin/python -m injection_workbench.cli web --port 5055    # 本地诊断工作台
.venv/bin/python -m pytest -q                                   # 32 个测试
```

关键设计与缺陷码、规模模式、资源预算、检查点、退出码详见
`docs/TECHNICAL_NOTES.md`。
