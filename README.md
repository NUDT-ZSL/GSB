在空白工作区从零实现一个本地 Kubernetes 调度与亲和性诊断工作台，用于在确定性样本上复现调度打分、资源装箱与亲和性过滤链路中的数值精度问题与误差传播。样本以本地 JSON 给出：节点清单（节点名、可分配 CPU/内存/GPU 的整型或小数毫核数值、污点、拓扑域标签）、Pod 清单（资源请求、亲和性与反亲和性规则、拓扑散布约束、优先级、亲和权重）以及调度配置（各插件打分权重、资源分数换算公式、容差参数）。工作台需实现调度框架式管线：过滤阶段处理资源可行性、污点容忍与节点亲和/反亲和，打分阶段按资源装箱、节点亲和权重与拓扑散布计算得分，并对浮点累加、权重归一化与小数资源换算做误差追踪，产出可解释的诊断报告。全部在本地文件系统与 SQLite 上运行，不连接真实集群。

任务环境与准备：
Windows 环境，安装 Python 3.10 及以上并确保 python 与 sqlite3 模块可用；无需连接真实 Kubernetes 集群。
安装 NumPy（用于浮点误差上界计算的确定性数值运算），版本以本机 pip 默认稳定版为准。
在空白工作区创建项目目录，准备本地样本：节点清单 JSON、Pod 清单 JSON、调度配置 JSON，以及可注入非法条目的样本变体。
准备并发与恢复验证脚本所需的多进程运行条件，以及固定逻辑时钟注入参数，使结果可重复。
不提供任何已有代码或数据附件，全部内容由任务执行者按题面自行创建。

业务要求：
1. 实现节点与 Pod 清单解析及数值模型：校验节点可分配资源为整型毫核或受控小数、Pod 请求不超过合法范围、标签键值格式、拓扑域标签闭合；把所有资源量统一换算为整数毫核或定点小数，记录换算后每项的二进制表示与舍入偏差，非法条目返回明确业务错误码且不写入状态。
2. 实现过滤阶段：依次判定资源可行性、污点容忍、节点亲和与反亲和、必须满足的 Pod 间反亲和与拓扑散布约束，过滤结果按节点稳定排序输出并记录每个节点被淘汰的首个原因；资源可行性判定必须在定点换算后比较，不得因浮点累加把超卖节点误判为可行。
3. 实现打分阶段与权重归一化：按资源装箱、节点亲和匹配度、拓扑散布均衡度计算各插件原始分，再按配置权重归一化为总分，输出每节点每插件的原始分、权重、归一化中间值与最终总分；归一化必须对权重和为浮点非整数配置产生可复现的定点结果，同一输入多次运行逐位一致。
4. 实现数值误差传播检测：对每节点每个插件的浮点中间值记录加法与乘法的累计误差上界，当两个节点的总分差小于给定容差而排序结果依赖该差值时，标记为精度敏感排序，并输出误差来源链与受影响的节点对；差异低于容差时必须给出确定性的最终裁决规则而非随机顺序。
5. 实现调度决策解释与回放：对一次调度输出 JSON 报告，包含选中节点、过滤淘汰链、打分明细、精度敏感标记与误差上界；给定同一报告与清单可回放得到完全一致的结果，回放需校验清单内容摘要一致，摘要不匹配时返回业务错误码而不复用旧报告。
6. 实现持久化与强制终止后的恢复：把调度轮次、清单摘要、过滤与打分中间结果、精度敏感记录原子写入 SQLite，每轮次提交整体替换当前结果指针并识别版本变化；恢复时依据持久化状态识别未提交轮次并只重算缺失部分，不得把未完整落盘的中间结果当作已提交。
7. 实现并发一致性与幂等：允许多个调度分析进程并行处理同一批清单，通过 SQLite 事务与文件锁保证同一轮次同一节点插件结果只提交一次，重复提交相同轮次幂等；读取方只能看到完整已提交轮次结果，不得观察到半写入的打分明细。
8. 提供命令行工作台与可重复演示：支持 load、schedule、explain、resume、status、verify 子命令，explain 以稳定排序输出指定 Pod 的决策链与误差来源，verify 校验持久化状态与报告一致性；使用固定本地样本运行两次需产生完全一致输出。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证过滤、打分、精度敏感标记、恢复与并发幂等，并附重复运行一致的结果。
