供水管网水质监控平台的数据工程师与调度分析员需要定期核查管网各监测点上报的余氯、浊度、pH 指标是否满足安全标准，并按管段拓扑与监测点位置查询异常事件。监测记录中大量指标因传感器离线或上报失败而为空，现有的分区查询路径对空值比较与连接处理不一致，导致下推后部分分区把空值当成零值参与阈值过滤，异常事件漏报与误报并存。为此需要构建一个以 SQLite 为本地存储的谓词下推执行内核：将查询请求按管段分区与监测点分区拆分，对涉及空值的比较谓词采用三值逻辑显式处理，连接操作区分内连接与外连接的空值匹配规则，并以集中式执行结果为基准逐查询核对下推结果的一致性，同时输出水质超标清单与因指标缺失需人工复核的清单。

任务环境与准备：
准备 Linux（WSL Ubuntu）上的 Python 3 运行环境，仅使用 Python 标准库中的 sqlite3、random、json、unittest 等模块，不安装第三方包。
在工作目录中创建项目目录结构，初始化 SQLite 数据库文件用于存放生成数据、查询结果与快照表。
运行确定性数据生成器产出管段拓扑、监测点、监测记录与查询请求，并依据固定种子复核生成结果可重复。

业务要求：
1. 提供确定性数据生成器，按固定种子产出管段拓扑表（管段编号、上下游节点、所属区域、管径、材质）、监测点表（监测点编号、所属管段、安装位置、监测指标类型）与逐时刻水质监测记录（监测点编号、采样时刻、余氯、浊度、pH、水温，指标可为空），空值比例与分布可由种子参数控制，生成结果与配套真值一并持久化到 SQLite。
2. 实现查询计划分解器，将每个查询请求按管段分区与监测点分区拆分为可下推的过滤谓词清单和集中式剩余处理步骤，输出每个分区的下推谓词表达式与连接执行计划，并在 SQLite 中记录分区归属与谓词文本。
3. 对每个分区执行下推的过滤谓词时严格采用三值逻辑：空值参与阈值比较时既不满足条件也不被当作零值，谓词结果只保留 TRUE 行，输出每个分区命中记录及空值参与比较的判定解释（谓词、空值字段、判定结果 UNKNOWN）。
4. 对监测点与管段连接区分内连接与外连接的空值匹配规则：内连接中任一侧连接键为空时不产生匹配行，外连接中保留含空值键的行并在结果中标记连接空值来源，输出连接结果与空值匹配说明。
5. 以集中式执行同一查询（在 SQLite 内对全量记录直接执行三值逻辑过滤与连接）的结果为基准，逐查询比对各分区下推结果合并后的命中记录集合、空值处理标记与记录顺序，任何不一致须标记并定位到具体分区与分歧谓词，输出一致性核对报告。
6. 依据查询结果与空值判定，输出两类清单：余氯低于下限、浊度高于上限或 pH 超出区间的超标监测点及采样时刻；因对应指标缺失而需人工复核的监测点及缺失时间区间，两类清单与生成器构造的真值一致。
7. 在下推谓词或分区规则调整后，仅重算受影响分区的过滤与连接，并与全量下推执行结果逐查询比对，确保增量结果与全量结果在命中集合、空值处理标记与记录顺序上完全一致，重算范围由谓词变更与分区规则变更的差异确定。
8. 将每个查询的下推谓词清单、分区命中结果、连接结果、一致性核对报告与两类清单持久化到 SQLite 快照表，支持从指定快照续算并识别分区规则版本变化，版本不一致时拒绝续算并给出明确提示。

验收：
以确定性生成的水质监控数据和人工边界样本，核对下推执行与集中式三值逻辑执行逐查询完全一致，超标与复核清单同构造真值吻合。
