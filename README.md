在空白工作区从零实现一个本地丢包与网络故障诊断系统，交付可交互的专业应用与可重复演示。系统输入为本地 JSON 诊断场景：探测目标清单（目标名、回环探测端点描述、期望状态码、探测周期、单次探测超时预算、连续失败阈值）、探测脚本（按可注入逻辑时钟给出每轮探测批次，包含探测类型与探测序号）以及诊断配置（每轮并发探测上限、每轮总逻辑时间预算、滑动窗口长度与步长、丢包率与延迟抖动判定阈值、容差参数、逻辑时钟步进）。探测目标由本地 Python 回环 HTTP 测试服务模拟，可按路径返回状态码、注入固定比例丢包（连接拒绝或提前断开）、慢响应、抖动延迟与畸形响应，不依赖任何真实网络、账号或外部服务。系统需在每轮并行探测与总预算约束下完成探测、按窗口统计丢包率与延迟分位、判定链路故障域与故障类型，并把诊断结论与决定依据持久化，支持中断后恢复与并发多实例运行。核心矛盾是：为满足每轮交互延迟预算而并行与提前放弃探测，会与丢包率与分位延迟计算结果的一致性冲突，系统必须让预算放弃的探测与真实丢包的探测在统计上可区分、可追溯。

任务环境与准备：
确认 Windows 上可用 Python 3.10 及以上版本，并能安装 numpy 与 pytest 到本地虚拟环境，无需容器或外部服务。
在空白工作区创建项目目录，准备本地回环 HTTP 测试服务脚本与固定 JSON 诊断场景样本（目标清单、探测脚本、诊断配置），样本与脚本均随项目提交。
准备 SQLite（Python 标准库 sqlite3 自带）作为持久化后端，并准备用于演示与 verify 的固定逻辑时钟步进表。
预留可重复演示的运行说明与样本目录结构，确保所有探测目标仅指向回环地址。

业务要求：
1. 实现诊断场景解析与校验：目标名与探测序号唯一、探测端点为合法回环地址、探测周期与超时预算为正整数且周期不小于超时预算、滑动窗口步长不大于窗口长度、丢包率与抖动阈值在合法区间；非法条目必须以明确业务错误码报告且不写入任何持久化状态。
2. 实现基于可注入逻辑时钟的并行探测调度器：同一轮次内按目标分组并发探测，同时受每轮并发上限与总逻辑时间预算双重约束，预算耗尽时必须放弃剩余未启动探测并记录放弃原因；已启动探测不得被简单截断为丢包，必须区分预算内未启动、超出单次探测真实等待约束的失败与主动放弃三类结局。
3. 实现探测结果分档与滑动窗口统计：把结果分为成功、状态码不符、超时、连接拒绝、畸形响应，按窗口长度与步长确定性切分窗口并统计丢包率与延迟分位数（固定排序与插值规则）；预算主动放弃的探测不得计入丢包率分母，必须在输出中单列并说明排除依据，使排除后口径可被独立重算复现。
4. 实现链路故障域判定与决定链记录：依据连续失败阈值、窗口丢包率与延迟抖动阈值驱动目标在健康、可疑、疑似丢包、不可达之间迁移，并输出每个结论的决定链（含命中窗口、样本计数、排除的放弃探测、首次触发阈值与所用配置版本），同一结论在重复判定下必须逐字段一致。
5. 实现强制终止后的恢复一致性：把轮次水位、各目标状态、窗口摘要、放弃探测清单、配置版本与逻辑时钟水位以事务原子写入 SQLite；进程在任意轮次被强制终止后，恢复路径依据持久化状态识别已提交轮次与半提交轮次，只重放未提交部分，不得重复计入窗口样本或回退状态。
6. 实现多进程并发一致性与幂等：允许多个诊断实例并行处理不同目标，通过 SQLite 事务与文件锁保证同一目标同一轮次同一配置版本只提交一次、窗口计数不被并发重复累加，重复提交相同轮次结果必须幂等；读取方只能看到完整已提交轮次而非中间态。
7. 实现配置版本整体替换与旧版本识别：诊断配置每次变更产生新版本号并以内容摘要整体替换当前配置指针而非逐条覆盖；进行中的轮次必须绑定其开始时的配置版本至结束，版本回退必须被拒绝并返回业务错误码，替换后未受影响目标的既有结论不得被重算。
8. 提供命令行交互与可重复演示：支持 load、probe、diagnose、resume、status、verify 子命令，status 以稳定排序 JSON 输出各目标状态、丢包率、放弃探测数与当前配置版本，verify 校验持久化状态与输出一致；演示脚本使用固定本地样本两次运行产生逐字节一致的报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

使用本地回环探测样本验证并行探测、丢包统计与故障判定，并验证放弃探测可区分及中断恢复后结果一致。
