需要在新工作区从零构建一套面向数据血缘与版本迁移的验证工具，供数据平台团队在模型与管道结构升级前后核对血缘关系的一致性与迁移结果的可复现性。输入是一组本地确定性样本：多张表的字段元数据、字段级血缘边（上游表字段到下游表字段）、以及若干版本迁移规则（重命名、拆分、合并、类型变更、字段废弃），迁移规则按版本号顺序应用。系统需要把迁移前的血缘图与迁移后的血缘图都落到 SQLite，支持按版本重放得到逐位一致的最终血缘状态，并能在迁移过程中注入可配置异常（规则顺序冲突、目标字段不存在、版本回退、环状血缘），异常下必须保持库中状态可回滚且给出明确业务码。交付物包括血缘迁移算法实现、异常注入与恢复机制、以及可重复执行得到相同结论的本地实验环境与控制台。

任务环境与准备：
确认 Windows 上安装 Python 3.11 及以上版本，并可在命令行调用 python 与 pip。
创建虚拟环境并安装 FastAPI、uvicorn、pytest 与 SQLite 相关标准库依赖，SQLite 使用 Python 内置版本。
在项目内准备本地确定性样本文件：表字段元数据、字段级血缘边、按版本排序的迁移规则与异常注入配置，全部以 JSON 文件提供，不依赖网络与真实账号。
任务执行前不预置任何源码或数据库，工作区为空；运行前由实现自行初始化 SQLite 库文件。

业务要求：
1. 实现血缘图模型与版本化迁移引擎：实体为表字段与字段级血缘边，迁移规则按版本号升序应用，每个版本应用后生成可查询的血缘快照；同一输入从空库重放任意次，最终血缘边集合与版本号序列必须逐位一致。
2. 实现五类迁移规则的语义：字段重命名需同步改写所有引用该字段的血缘边端点，拆分需把一个上游字段的血缘边按可配置权重分配到多个下游字段，合并需汇聚多条血缘边并保留来源标识，类型变更只更新字段类型不改变边，废弃字段需删除其入边与出边并记录被删边清单。
3. 解决迁移规则的顺序冲突：当同一版本内多条规则作用于同一字段（例如先重命名再拆分，或重命名目标与既有字段重名）时，必须依据规则的显式执行序号或声明的依赖关系确定顺序，无法确定时返回 E_RULE_ORDER 并回滚该版本的全部变更，不得留下部分应用状态。
4. 实现按版本的快照与回滚边界：每个版本应用前记录可回滚的前置状态标记，单个版本失败时数据库必须回到该版本应用前的完整状态，已成功的历史版本不受影响；回滚后再次以修正参数重放该版本应得到与首次尝试无关的独立结果。
5. 实现环状血缘与非法迁移检测：迁移产生字段级环、目标字段不存在、源字段已被废弃仍被引用、版本号非递增或回退均视为非法迁移，分别返回 E_CYCLE、E_TARGET_MISSING、E_STALE_SOURCE、E_VERSION_REGRESS，且检测发生在写库前或在事务内可撤销。
6. 实现迁移前后血缘差异报告：对指定两个版本给出血缘边的新增、删除、端点字段变化的集合差异，并可按表或字段下钻追溯每条差异由哪个迁移规则与版本导致；差异报告必须与快照逐一对应，不得包含快照中不存在的边。
7. 提供可复现的实验环境与异常注入：异常通过配置文件或请求参数注入（规则冲突、环、目标缺失、版本回退等），演示脚本从同一份本地样本出发执行全部场景并无网络依赖地重复运行，输出每次运行的业务码序列与最终血缘计数汇总，多次运行结果必须一致。
8. 交付可交互控制台与持久化状态：控制台可加载样本、应用单个或连续版本、查看任一版本快照与差异报告、触发回滚；所有版本与快照信息持久化在 SQLite 中，进程被强制终止后重启只能依据库中已提交状态识别最后完整版本，不承诺补写未提交版本的退出报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
