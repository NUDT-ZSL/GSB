在空白工作区从零实现一个面向云原生可观测性的事件时间窗降噪关联工作台，在不依赖真实监控后端的前提下，于确定性本地样本上复现乱序事件的窗口归属、降噪结论与拓扑变更引发的失效重算。本地 JSON 样本提供三部分：服务拓扑快照（服务名、实例 ID、上游依赖、故障域、实例权重，带拓扑版本号与生效逻辑时钟）；事件桶文件（每个桶为乱序到达的原始告警，字段含事件序号、实例 ID、规则名、严重度、告警发生逻辑时钟毫秒、到达逻辑时钟毫秒、指标值、是否处静默维护窗口）；拓扑变更补丁（依赖增删、静默窗口调整、实例权重变更，带目标拓扑版本与内容摘要）。工作台需按事件时间而非到达时间判定水位并触发窗口关闭，同一实例同一规则在窗口内形成降噪组，依据拓扑上游路径给出关联证据链与降噪结论；补丁到达后需沿依赖反向闭包判定哪些窗口结论失效、哪些可复用。所有时间推进只依据样本给出的逻辑时钟值，进程被强制终止后需依据 SQLite 持久化状态恢复窗口与失效记录。

任务环境与准备：
安装 Python 3.10 及以上版本，确认标准库 sqlite3、json、hashlib、argparse 可用，无需第三方依赖包
在空白工作区创建项目根目录，自行划分源码、本地样本与 SQLite 数据库文件的存放路径
手工准备固定本地样本：拓扑快照 JSON、事件桶 JSON（含乱序到达事件与静默维护标记）、拓扑变更补丁 JSON（含依赖增删与静默窗口调整）、异常注入清单 JSON
确认全部命令在 Windows 控制台可运行，路径统一使用 pathlib 相对路径，时间推进只读取样本中的逻辑时钟字段

业务要求：
1. 实现三份样本的解析与校验：拓扑快照要求服务名与实例 ID 唯一、上游依赖两端闭合且无自环、拓扑版本号单调、生效逻辑时钟非负；事件桶要求事件序号唯一、发生与到达逻辑时钟均为非负整数、严重度枚举合法、实例必须在拓扑中已声明；补丁要求目标版本号与父版本号连续、内容摘要与字段一致；任一类非法输入须返回独立业务错误码并保证不写入任何持久化记录。
2. 实现按事件时间的水位推进与窗口关闭：以每个实例每规则的事件发生逻辑时钟计算水位，水位只由已到达事件推进，迟到事件（发生时钟小于当前水位）不得改动已关闭窗口而必须进入迟到簿记；窗口边界、允许迟到阈值与关闭时机全部由逻辑时钟整数毫秒裁决，不得读取系统墙钟，相同到达顺序序列在任意运行次数下必须得到逐位一致的窗口边界与关闭顺序。
3. 实现窗口内降噪组与关联证据链构建：同一实例同一规则在窗口内的告警按固定规则去重与合并，统计被静默或维护窗口覆盖的抑制数、首末告警时刻与代表事件（严重度与实例权重裁决、同权按事件序号），并沿拓扑上游闭包生成从代表事件到上游实例的证据链；每份证据须记录所用拓扑版本，结论与证据链以稳定排序输出，且相同输入重复执行逐字节一致。
4. 实现拓扑补丁的增量失效闭包裁决：补丁提交时沿依赖反向计算受影响实例与窗口闭包，区分哪些已关闭窗口的降噪结论、证据链与迟到簿记需重算、哪些可安全复用；未受影响窗口的结论与证据链必须逐字保持不变，失效清单要记录触发字段、触发补丁版本与传播路径，不得以全量重算冒充增量失效。
5. 实现静默窗口变更的结论演进与迟到事件再裁决：新增或撤销静默与维护窗口会改变抑制数与代表事件，窗口撤销后原先被抑制的告警不得直接提升为代表事件，而须与迟到簿记按事件时间重新裁决；已关闭窗口在新拓扑版本下的结论演进须保留前序版本结论用于追溯，状态迁移只能依据持久化记录裁决，重启后不得凭内存残留决定窗口归属。
6. 实现持久化状态与强制终止后的恢复：把拓扑版本指针、事件水位、窗口状态、迟到簿记、失效清单与证据链摘要以事务原子写入 SQLite，每次版本提交采用临时表加版本号整体替换指针并识别版本回退；进程在窗口关闭或补丁传播中途被强制终止后，恢复路径须识别未提交窗口与半写入失效项，只重放未完成部分且不重复计入已关闭窗口的事件。
7. 实现多进程并发一致性与版本化读取：允许灌入实例与补丁实例并行运行，通过 SQLite 事务与文件锁保证同一拓扑版本只提交一次、同一窗口同一版本结论只提交一次，重复提交相同补丁或相同窗口结果必须幂等；查询方在任一时刻只能看到某个完整提交版本的水位与结论，不得观察到新旧拓扑混合的中间视图。
8. 实现异常链路隔离与可重复命令行：依赖成环、补丁引用不存在实例、事件引用未声明实例、静默区间端点倒置、拓扑版本回退、窗口摘要不匹配分别映射到不同业务错误码并保留可诊断字段，单个异常不得中断其他实例的窗口推进；提供 load、ingest、apply、resume、status、verify 子命令，status 以稳定排序 JSON 输出拓扑版本、各实例水位与窗口状态，verify 校验持久化记录与输出一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
