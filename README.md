当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向全景分割（像素掩码）的本地专业工作台，核心业务问题是交互预览延迟与批量计算结果一致性。业务对象是本地确定性生成的样本：每张图由固定种子生成固定尺寸 RGB 像素数组与真值，真值以 v1 单通道类别索引掩码与 v2 双通道（类别标识、实例序号）加像素置信度矩阵两种版本并存，外部交换格式为 COCO 风格 RLE 游程编码 JSON（含类别与实例列表、忽略区标记）。系统把一次全景分割后处理建模为多级流水：三格式解析与校验→掩码合并为统一全景掩码→语义 mIoU 与实例 PQ 指标聚合→结果快照提交。用户在前端以交互方式按像素坐标或按实例编号查询：该位置或该实例的类别、实例号、置信度与所属指标贡献，并可拖动查看整图掩码。核心矛盾是：交互查询必须走预构建的索引与缓存以压低延迟，而批量评估走完整流水；两条路径的掩码与指标必须逐像素、逐实例一致，且任一方触发快照更新后查询侧不得读到新旧混合的掩码与统计量。

任务环境与准备：
安装 Python 3.10 及以上版本与 NumPy，确认本地可执行并记录版本
无需 GPU、外部数据集、真实账号或网络服务，所有样本由固定种子在本地生成
创建空白工作区目录，准备用于生成固定尺寸 RGB 像素、v1/v2 掩码与 RLE 样本的本地生成脚本配置参数
预留本地持久化目录用于快照与缓存文件，确认工作区可读写

业务要求：
1. 实现 v1、v2 与 RLE 三种读取器，按版本头与字段集分派解析路径；未知版本返回 E_VERSION_UNSUPPORTED，头部截断、游程越界、像素总数与图像尺寸不符返回 E_FORMAT_CORRUPT 并指出字段偏移；同一输入与同一配置下解析结果逐字节可复现。
2. 实现三格式掩码合并为统一全景掩码：每像素至多一个类别与至多一个实例，忽略区像素不参与计分，实例编号在同图内唯一；违反分别返回 E_PIXEL_CONFLICT、E_INSTANCE_DUP，并校验合并所需的类别与实例映射表版本一致。
3. 实现基于掩码合并结果的查询索引构建：支持按像素坐标与按实例编号两类查询，索引须记录每个实例的像素范围、类别与置信度统计，同一输入与配置下索引结构逐字节可复现，且查询所需元数据不得依赖批量流水之外的隐式状态。
4. 实现交互查询接口与延迟预算控制：单次查询须在配置的延迟预算内返回类别、实例号、置信度与指标贡献；延迟以本地查询循环的实际处理计时为观测，并按索引条目数与掩码尺寸给出估算记录；超预算返回 E_LATENCY_BUDGET 并附带已完成阶段与已检查条目数。
5. 实现查询侧与批量侧的一致性保证：查询返回的类别、实例号与所属指标贡献，必须与批量评估结果中该像素或该实例的记录在声明精度内一致；检测到偏差返回 E_INCONSISTENT 并输出首个偏差位置、查询路径与批量路径两侧取值。
6. 实现语义 mIoU 与实例 PQ 指标聚合：匹配 IoU 阈值与忽略区口径由配置给出，同分按实例编号升序打破平局；指标须可由逐图逐像素明细独立重算一致，并按类别输出 IoU 与实例命中明细。
7. 实现索引与指标快照的版本化及整体替换：快照携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换而非增量修补；快照切换须原子生效，查询侧不得读到新旧混合的掩码与统计量；损坏或校验和不符返回 E_SNAPSHOT_CORRUPT。
8. 实现本地可交互工作台与跨模块一致性自检：展示掩码视图、逐像素或逐实例查询结果、延迟观测、指标明细、快照版本与最近业务错误码，并允许触发一次演示；自检校验查询索引与掩码可互相核对、指标与明细可重算、快照版本在索引与统计量间一致，不一致返回 E_INCONSISTENT 并指出类别。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证三格式解析、像素与实例查询结果与批量指标一致，并覆盖超预算与快照替换异常。
