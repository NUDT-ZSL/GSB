在空白工作区从零实现一个本地服务网格流量治理控制面组件，用于在确定性样本上复现路由规则下发时的并行调度与资源预算决策。样本以本地 JSON 给出：服务注册清单（服务名、实例 ID、实例地址、权重、健康状态与所在拓扑域）、流量策略清单（虚拟服务路由、按权重与版本的流量拆分、超时与重试预算、每服务并发上限）以及全局调度配置（每轮次下发总时间预算、每服务并发上限、退避基数与抖动规则）。下发目标由本地可编程 HTTP 测试服务模拟：每个实例在回环地址上监听，可按路径返回状态码、慢响应、拒绝连接与畸形响应，并可在响应中回显收到的规则版本号用于校验一致性。控制面需要把每轮策略变更解析为面向各实例的并行下发任务，在总时间预算与每服务并发上限双重约束下决定启动顺序与放弃策略，按结果推进实例的规则版本与连续失败计数，并对失败实例计算确定性退避与再下发时间。全部状态须持久化，支持中断恢复、并发多实例运行与可重复演示，输出稳定排序的 JSON 诊断报告。

任务环境与准备：
Windows 本地安装 Python 3.11 及以上，并使用标准库 sqlite3、json、socket、http.server、multiprocessing 与 concurrent.futures
在空白工作区创建项目目录、样本 JSON 文件与启动脚本目录，不引入第三方服务、容器或网络依赖
准备本地可编程 HTTP 测试服务脚本，监听 127.0.0.1 回环端口，支持按路径返回状态码、慢响应、拒绝连接、畸形响应与规则版本回显
准备固定逻辑时钟配置文件与确定性抖动参数，确保两次演示运行的调度序列与输出完全一致

业务要求：
1. 实现服务注册与流量策略清单的解析校验：服务名与实例 ID 唯一、实例地址为合法回环地址、权重为正整数、每条路由的流量拆分权重和与版本标签闭合、超时与重试预算为合法正整数值；非法条目必须以明确业务错误码报告并且不写入任何持久化状态。
2. 实现面向实例的并行下发调度器：同一轮次内按服务分组并发下发规则，同时受每服务并发上限与每轮总时间预算约束；预算耗尽时必须放弃剩余未启动任务并记录放弃原因，已启动任务不得被简单截断为超时，需区分预算内未启动、启动后单任务超时与主动放弃三类结果。
3. 实现实例规则版本状态机与连续失败计数演进：下发成功、单次失败、连续失败超阈、健康状态翻转分别驱动实例在待更新、当前、落后、隔离之间迁移，迁移必须依据本轮完整结果与持久化状态裁决，重启后不得凭内存残留决定实例是否已同步到某版本。
4. 实现确定性退避与再下发计划：失败实例按连续失败次数计算指数退避间隔并施加确定性抖动与上限，健康实例按基础间隔再下发；再下发时间需与每服务并发上限和总预算共同裁决，预算不足以覆盖全部到期任务时按优先级与到期先后给出确定的取舍顺序。
5. 实现持久化状态与强制终止后的恢复：把实例规则版本、连续失败计数、退避截止时间、本轮调度摘要与下发结果以事务原子写入 SQLite；进程被强制终止后依据持久化状态识别未完成轮次与未确认下发，只重试未确认部分，不得重复已确认下发或回退实例版本。
6. 实现多进程并发一致性与幂等：允许多个控制面实例并行处理同一批服务，通过 SQLite 事务与文件锁保证同一实例同一轮次同一版本只被一个进程确认，重复提交相同下发结果必须幂等；读取方只能看到完整已提交轮次的状态快照，不得观察到半写入的版本推进或连续失败计数。
7. 实现下发期异常链路与业务错误码：连接拒绝、响应超出单任务超时、响应状态码不符合期望、响应中回显规则版本与期望不符、目标返回畸形响应分别映射到不同业务错误码并在结果中保留可诊断字段；单个实例异常不得污染同轮其他实例结果或中断调度主循环。
8. 提供命令行接口与结果验证工具：支持 load、dispatch、resume、status、verify 子命令，status 以稳定排序 JSON 输出每实例的规则版本、连续失败计数、退避截止时间与最近轮次摘要，verify 校验持久化状态与调度摘要一致性；使用固定本地样本与测试服务执行两次须产生完全一致的输出。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本与测试服务验证并行下发、预算放弃、退避与中断恢复，两次运行输出一致。
