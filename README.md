当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向中文客服工单文本分类与意图识别的本地可集成组件与完整示例，核心业务问题是数据规模变化下的算法取舍，以及意图配置在标注修正与规模演进下的增量快照与判定一致性。业务对象是本地确定性生成的工单样本：每条工单含 ticket_id、query_text（从受控中文词表按固定种子拼装）、locale、intent_label_gold（可缺失表示未标注）；另有一份意图规则配置，声明每个意图的触发关键词、优先级权重、置信门限、回退意图与批大小，关键词匹配以码点偏移为准。组件需在规则精确打分路径与基于关键词倒排的近似候选路径之间按数据规模取舍，输出每条工单的意图、命中关键词码点偏移与置信度，并支持标注修正与配置版本演进下的增量重算与结果可复现。

任务环境与准备：
在 Windows 本地安装 Python 3.10 及以上版本，并确认 Python 与 pip 可正常调用。
安装 NumPy 依赖（如 pip install numpy），不依赖任何外部服务、真实账号或网络数据。
在空白工作区创建项目目录，样本与意图配置由固定种子在本地确定性生成，无需下载附件。
准备一个本地可写的缓存与快照目录用于内容寻址产物与版本快照落地，确认 Windows 路径可读写。

业务要求：
1. 实现确定性的意图判定核心：对每条工单按配置关键词做最长优先匹配，输出意图、命中关键词及其在 query_text 中的码点起止偏移、置信度；同分时按关键词长度降序、再按意图标签字典序打破平局；同一输入与同一配置版本下必须逐字节产出相同意图、偏移与置信度，禁止依赖字典遍历顺序或系统时间。
2. 实现精确路径与近似候选路径两条判定路径：精确路径对全部关键词逐一比对；近似路径先按字符级签名分桶生成候选关键词，再在候选内做完整匹配；两条路径必须共用同一最长优先匹配口径与同一平局规则，且近似路径须记录每条件被剪掉的关键词数量与桶内候选数。
3. 实现基于数据规模的自适应路径取舍器：按工单数、关键词总数、平均查询码点长度与关键词平均长度选择精确或近似路径，必要时选择分批流式执行，输出含规模观测与比较次数估计的取舍记录；同一观测下决策必须逐字节一致，且所选路径必须全覆盖全部工单与全部启用的意图规则，不得遗漏任何工单或意图。
4. 实现跨路径一致性裁决：对同一工单集合同时产出两条路径结果时，输出意图一致率、偏移差异与置信度偏差谱，并区分差异来自候选剪枝遗漏还是平局规则应用不同；当差异导致意图标签不可比对时返回 E_PATH_DIVERGENCE 并输出首个偏差工单与所属关键词；禁止用扩大容差或跳过近似路径掩盖真实差异。
5. 实现匹配比较次数与驻留内存的双重预算准入：按工单数与关键词候选数估算比较代价，在总比较预算与驻留关键词表内存上限内决定准入规模与是否降批；超限时分别返回 E_MATCH_BUDGET 与 E_RESOURCE_LIMIT，降批须在结果中标记降批类别且不得改变已判定的工单结论，未准入工单不得出现在结论集合中。
6. 实现意图配置与标注修正的增量失效传播：当某意图关键词被增删、置信门限调整或某工单标注被修正时，按内容寻址缓存键计算受影响工单集合与受影响规则集合，复用未受影响的判定产物，仅重算受影响工单；须输出本次重算工单清单与复用清单，并保证全量修改后重跑结果与增量重算结果逐字节一致。
7. 实现配置快照的版本化与整体替换：意图配置连同受控意图标签集合携带单调递增版本号与内容校验和，加载时检测到版本号或校验和变化必须整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK；受控意图集合收缩导致已有判定意图不再合法时按回退意图处理并标记回退类别，无回退意图可用时返回 E_LABEL_RETIRED。
8. 实现输入与配置校验链路、异常链路归因并提供本地可集成示例：重复 ticket_id、query_text 为空、置信门限越界、关键词为空串、意图标签不在受控集合内、未知配置版本分别返回结构化业务码并指明字段；每条判定须记录所用缓存键、规则版本与门限版本，可按记录重放出相同意图与偏移，追溯链缺失或重放不符返回 E_LINEAGE_BROKEN；命令行示例读取本地确定性样本，输出含意图结果、码点偏移、路径取舍记录、跨路径偏差谱、重算与复用清单、业务码与重放校验结论的 JSON 报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
