需要在空白工作区中实现一个面向本地微服务场景的“服务注册与健康探测中间件”。该中间件维护服务实例的注册信息（服务名、实例标识、地址、权重、租约时长、元数据），并周期性对已注册实例执行健康探测。探测分为两类：主动探测（通过本地 HTTP 端点模拟实例健康状态）与被动心跳（实例按租约上报心跳）。核心难点在于探测任务必须并行调度，但整体受资源预算约束：同时进行的主动探测数量有并发上限，单轮探测总请求数受预算限制，超出预算的实例必须被有序推迟而非简单丢弃，且推迟不得导致租约过期误判。租约到期、探测失败、探测超时三类事件需产生一致的实例状态迁移，并通过 SQLite 持久化，使进程重启后租约剩余时间、探测重试计数与巡逻轮次可恢复。实例状态变化需以事件序列暴露，客户端可查询当前健康视图与历史事件。

任务环境与准备：
安装 Python 3.11 及以上版本，并创建虚拟环境。
安装 FastAPI、uvicorn、httpx、pytest、pytest-asyncio 等依赖，版本在 requirements 中固定，全部可离线安装。
准备本地样本配置：服务注册清单、租约上下界、并发上限、单轮预算、连续失败阈值与探测超时参数。
准备本地 HTTP 探测桩的默认健康状态与延迟配置，运行前确认不依赖外网与真实账号。
在 Windows 上使用 pytest 运行用例，确认 SQLite 数据目录可写且可清理。

业务要求：
1. 实现服务实例注册与租约模型：注册请求包含服务名、实例标识、地址、权重、租约时长与元数据，同一服务名与实例标识重复注册须视为续约并重置租约计时，租约时长须落在配置的上下界内，越界时返回业务码 E_BAD_LEASE 且不写入存储，注册成功返回带剩余租约毫秒数的视图。
2. 实现并行健康探测调度器：每轮巡逻按配置的并发上限并行执行主动探测，探测请求必须带有基于 asyncio 的真实超时取消语义，超时实例记为探测失败而非阻塞整轮；单轮预算（最大探测数）耗尽后，剩余实例必须按权重从高到低、同权重按注册序号升序进入下一轮候选队列，不得被标记为不健康。
3. 实现租约与探测结果的统一状态迁移：实例状态取值必须为 active、suspect、unhealthy、expired，合法迁移由心跳续约、探测成功、探测失败、租约到期驱动，非法迁移须拒绝并返回 E_INVALID_TRANSITION；超过连续失败阈值但租约未到期的实例进入 unhealthy，租约真正到期后才可进入 expired，expired 实例不得参与后续巡逻。
4. 实现探测预算与并发控制的交互一致性：当并发上限小于本轮候选数时，未被调度的实例其租约剩余时间必须按实际等待时间扣减，调度器需保证被推迟的实例不会因等待而错误地越过 expired 边界；若某实例在等待期间收到心跳续约，必须从其新租约重新排队而不丢失队列位置信息。
5. 实现 SQLite 持久化与重启恢复：持久化实例租约截止时间（绝对时间戳）、连续失败计数、当前巡逻轮次与待处理候选队列；进程重启后须恢复剩余租约、失败计数与巡逻进度，重启时将处于探测中的实例回退为可再次调度的状态并记录 E_RECOVERED 事件，已过期实例保持过期且不复活。
6. 实现健康视图与事件查询接口：通过本地 HTTP 提供注册、注销、心跳、查询实例健康视图、查询服务聚合健康状态与分页查询事件序列的接口；事件须带严格递增序号、实例标识、事件类型与时间戳，同一实例的视图必须能由事件序列重建，JSON 响应字段名与错误码需全局一致。
7. 实现注销与资源回收的一致性：主动注销须将该实例从巡逻候选队列移出并释放其占用的并发预算名额，注销后其后续心跳须返回 E_UNKNOWN_INSTANCE；服务内全部实例注销或过期后，该服务的聚合健康状态必须变为空集而非 unhealthy，回收过程与正在进行的探测并发发生时不得产生悬空预算占用或重复事件。
8. 提供本地确定性探测桩与测试：实现可配置健康状态、响应延迟与故障注入的本地 HTTP 探测桩，测试桩不依赖外网；pytest 用例须在 Windows 离线覆盖续约重置、并发上限推迟、预算耗尽排队、真实超时取消、重启恢复与注销回收，并验证推迟实例不越过过期边界。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
