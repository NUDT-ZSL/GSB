当前是空白工作区，需要从零实现一个本地 API 网关的准入控制中间件，核心业务目标是让每一次请求的准入决策在配置热更新、限流窗口推进、鉴权凭证轮换与进程被强制终止后仍保持一致。网关以本地 JSON 提供声明式配置：路由规则（Host、Path 前缀、目标上游、所需权限域）、限流策略（按路由与按租户两级令牌桶的容量与补充速率、滑动窗口长度与步长）、鉴权策略（API Key 与 JWT 的密钥版本、密钥轮换生效逻辑时钟、权限域到路由的授权矩阵、凭证吊销列表）以及逻辑时钟步进表。上游由本地 Flask 测试服务模拟，可按路径返回状态码、注入慢响应与拒绝连接；网关自身以 Flask 暴露回环监听端口处理转发请求并记录决定链。所有时间推进只依赖注入的逻辑时钟毫秒值，不读取系统墙钟。

任务环境与准备：
在 Windows 上安装 Python 3.11 及以上版本，并确保 pip 可用。
在空工作区创建虚拟环境并安装 Flask 3.x 与 pytest，仅使用标准库 sqlite3、hashlib、hmac 与 threading，不引入其他运行时依赖。
准备本地确定性样本目录：网关配置 JSON、API Key 与 JWT 密钥及吊销列表、请求回放脚本、逻辑时钟步进表，以及用于模拟上游的 Flask 测试服务脚本（监听 127.0.0.1，可按路径返回状态码、慢响应与连接拒绝）。
预留本地 SQLite 数据库文件与网关监听回环端口，验证前清空样本与数据库到初始状态，所有操作均在本地回环地址完成。

业务要求：
1. 实现配置解析与鉴权授权矩阵校验：校验路由 Host 与 Path 前缀唯一性、目标上游为合法回环地址、令牌桶容量与补充速率为正整数、滑动窗口步长不大于窗口长度、API Key 与 JWT 密钥版本号单调、权限域到路由的授权矩阵引用闭合、吊销列表条目类型合法；非法配置必须返回明确业务错误码（如 E_BAD_ROUTE、E_BAD_LIMIT、E_BAD_AUTH_MATRIX）且不写入任何持久化状态，不得部分应用。
2. 实现基于可注入逻辑时钟的令牌桶限流裁决：按路由与租户两级令牌桶计算每次请求的可用令牌与补充量，容量补充只依据注入的逻辑时钟毫秒值，不读取系统墙钟；同一请求序列在任意运行次数下必须得到逐位一致的允许或拒绝序列，逻辑时钟回拨超过配置容差时必须返回业务错误码并保持令牌余额不变。
3. 实现滑动窗口统计与限流窗口水位推进：按窗口长度与步长确定性切分窗口并把每次请求唯一归属一个窗口，窗口内计数与拒绝数只在窗口完整提交后计入下一窗口的判别，跨越窗口边界的请求不得同时计入两个窗口；跨重启恢复后窗口归属与计数不得改变。
4. 实现鉴权裁决与密钥版本轮换：对 API Key 与 JWT 校验签名摘要、过期逻辑时钟、密钥版本与吊销状态，轮换后旧版本密钥必须在其声明的宽限窗口结束后失效；鉴权失败的请求不得消耗限流令牌，鉴权成功但被限流拒绝的请求必须记录两个阶段的裁决依据，且密钥轮换不得让已吊销凭证重新生效。
5. 实现强制终止后的恢复与限流计数一致性：把租户令牌余额、当前窗口摘要、密钥版本水位、吊销记录、决定链与已提交请求序号以事务原子写入 SQLite；进程在任意请求处理中途被强制终止后，恢复路径依据持久化状态识别已提交请求与半提交请求，只补算未提交请求，不得重复扣除令牌、重复计入窗口或以恢复为由放宽后续准入。
6. 实现配置热更新的版本化原子切换与读者隔离：限流与鉴权配置以版本号加内容摘要提交，每次提交整体替换当前配置快照指针而非逐条覆盖；进行中的请求必须绑定其开始时的配置版本直至结束，读者不得观察到新旧配置混合生效；版本回退必须被拒绝并返回业务错误码。
7. 实现多进程并发一致性与幂等裁决：允许多个网关工作进程并行处理同一租户请求，通过 SQLite 事务与文件锁保证同一请求序号同一配置版本只被裁决一次、令牌余额与窗口计数不被并发超扣，重复提交相同请求结果必须幂等，读者只能看到完整已提交状态。
8. 实现异常链路与业务错误码隔离：上游连接拒绝、上游响应超出单请求预算、上游返回畸形响应、配置版本与期望不符、请求摘要不匹配分别映射到不同业务错误码并在决定链中保留可诊断字段；单次上游异常不得污染同租户其他请求的限流计数或中断网关主循环。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地 Flask 上游与固定样本验证限流鉴权裁决可复现、强制终止后计数一致、配置版本原子生效。
