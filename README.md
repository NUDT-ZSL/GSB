某数据安全团队需要在离线 Windows 空白工作区从零开发一个敏感标记派生守卫引擎，用于对本地确定性 JSON 字段描述集进行敏感标记传播与策略一致性校验。输入是一组字段描述记录，每条含字段路径（支持点路径与数组下标路径）、来源字段引用列表、脱敏状态（明文/脱敏/不可见）、策略标识与声明版本（v1 无传递标记，v2 携带传递标记）；引擎需沿来源引用重建传播链，判定脱敏策略违规与派生环，并输出可复现的 JSON 报告与可操作诊断命令。核心难点在于：来源引用可在任意声明顺序下到达，脱敏状态可能沿链被低等级声明覆盖，且当来源引用成环时传播结论不唯一；引擎需保证结论与声明顺序无关、对上位与下位脱敏状态冲突给出稳定判定，并在环注入与深层链场景下产出与顺序无关的真值来源。工作区无任何样本与代码，全部样本由本地确定性生成器产出。

任务环境与准备：
Windows 工作站，安装 Python 3.11 及以上并确保 python 与 pip 在 PATH 中可用。
在空白工作区创建项目目录，安装 pytest（建议 8.x）作为测试依赖，全部依赖从本地或已配置的包源获取。
确认无需网络、账号、外部数据集或额外样本，全部输入由项目内确定性生成器在本地产出。
运行前清理工作区内的临时报告与样本输出目录，保证每次实验从同一初始状态开始。

业务要求：
1. 实现字段描述集的解析与规范化：统一点路径与数组下标路径为规范寻址键，校验字段路径唯一性、来源引用目标是否存在、脱敏状态取值在明文/脱敏/不可见三值内、声明版本为 v1 或 v2，对非法记录输出含记录序号与业务码 E_RECORD 的拒绝清单并继续处理其余记录。
2. 实现来源引用图的构建与环检测：以来源引用为有向边建图，检测自引用与任意长度环并返回 E_CYCLE 且列出环中规范寻址键序列；对同一对字段的重复引用边去重并记录重复次数，环检测结论须与记录到达顺序无关。
3. 实现与声明顺序无关的敏感标记传播：依据来源引用传递脱敏状态，明文源向脱敏目标传播须判定为脱敏降级违规 E_DOWNGRADE，不可见源向任意目标传播须判定为信息泄露违规 E_LEAK；同一字段收到来自多个来源的冲突状态时须按明文优先于脱敏、脱敏优先于不可见的固定次序归一，结论不得依赖到达顺序。
4. 实现 v1 与 v2 声明版本的兼容分派：v1 记录仅直接传递不外延，v2 记录的传递标记为真时沿链外延传播、为假时等同直接传递；同一描述集内混用两版本须按各来源记录自身版本分别处理，若某字段所有来源版本不统一导致传播结论不唯一须返回 E_VERSION_CONFLICT 并输出冲突来源键。
5. 实现依赖环与降级违规的注入复现机制：引擎接受口径明确的注入参数对象（可强制指定环长度、强制字段降级、伪造来源版本混用、构造深层传播链），生成器按参数产出描述集，验证端只依据描述集内同步标记与注入参数记录判定，不得使用生成器中间结果作为真值，并输出观测一致与不一致计数。
6. 实现并发校验与资源控制：支持对多个描述集并发校验，并发度、单描述集真实耗时上限与单描述集最大字段处理数均可配置，超时以真实计时判定返回 E_TIMEOUT、超字段数返回 E_FIELDS；并发度变化不得改变任一描述集的违规清单、业务码与稳定输出顺序。
7. 实现原子报告写出与批处理容错：报告为可解析 JSON，含描述集级结论、每字段传播状态、违规业务码、环路径与观测一致计数；报告先写临时文件再整体重命名替换；单个描述集失败不得中断同批其他描述集，退出码区分全部成功、部分失败与参数错误，业务码统一写入报告。
8. 提供确定性本地样本生成器与 pytest 测试集：覆盖顺序无关传播、环注入、版本混用冲突、降级与泄露违规、超时、超字段数与并发度差异；测试须断言业务码、环路径、观测一致计数、报告顺序稳定性及退出码，并验证被校验描述集在检测前后内容未被修改。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地生成样本验证顺序无关传播、环注入复现与并发一致性，输出可解析报告及退出码。
