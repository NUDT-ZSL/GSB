在游戏音频素材库与版权比对场景中，需要从零开发一个本地音频指纹与相似片段检索引擎：对参考曲目与待检曲目分别生成指纹，检索待检曲目中与参考曲目相似的片段，给出片段在两条时间轴上的起止采样点、相似度得分与对齐关系，并生成可集成的组件与完整示例。输入为程序按确定性规则生成的本地 WAV 样本（16bit 单声道，采样率 16kHz/44.1kHz/48kHz，可包含变速、增益偏移、局部插入与背景噪声）以及一个 JSON 检索任务描述，描述中给出参考与待检文件清单、指纹参数（帧长、帧移、频带划分、峰值邻域规格）、候选检索参数（哈希桶容量、投票窗口、最小匹配数）、数值容差规格（定点标度、得分容差、时间偏移容差）、并发上限与在途频谱缓冲内存预算。真实难点在于指纹的时间定位与得分依赖逐帧频谱的浮点量，变速与重采样会让同一内容的时间偏移产生非整数帧漂移，需在整数帧域与浮点参考之间控制误差传播。

任务环境与准备：
安装 Python 3.10 及以上版本，并确保 numpy 可导入；无需其他第三方依赖与外部可执行文件。
在空工作区创建项目目录，确认可写入样本目录、状态目录与输出目录。
使用程序按确定性规则生成测试 WAV 样本（16bit 单声道，含变速、增益偏移、局部插入与噪声变体）及检索任务 JSON 描述，样本由任务执行者自行生成，不依赖外部附件。
确认系统可运行本地命令行示例程序，并可通过发送可处理终止信号或直接结束进程验证中断与恢复行为。

业务要求：
1. 实现检索任务描述与输入 WAV 解析校验：读取 JSON 与各 WAV 文件，校验采样率属于允许集合、位深为 16、声道数为 1、帧长与帧移为正整数且帧移不大于帧长、频带边界严格递增且落在奈奎斯特频率内、定点标度与各类容差为正数，非法输入返回带业务码的 JSON 错误（如 E_RATE、E_SCHEMA）且不产生任何输出。
2. 实现逐帧频谱与峰值指纹提取：按帧长与帧移对每首曲目分帧并加窗后做频谱分析，按频带划分与峰值邻域规格选出频谱峰值点，生成以频带与帧间差为键的指纹项；帧起止采样点须与源文件严格对应，变速输入的帧边界换算按有理数比计算并记录每帧的理论浮点时间与整数采样点位置。
3. 实现浮点参考与定点累计的得分计算对照：指纹匹配得分按哈希碰撞投票累计，得分累计同时保留 float64 参考值与规格定点标度下的整数值，记录两者逐步差值并标出首次超过得分容差的位置；最终排名只依据定点得分，同一输入重复运行排序与得分必须完全一致。
4. 实现候选片段检索与时间偏移估计：按投票窗口与最小匹配数从匹配指纹中聚合候选片段，估计待检片段相对参考片段的时间偏移，偏移须同时给出整数帧偏移与以采样点表示的浮点参考偏移，二者换算差不得超过时间偏移容差；对变速输入须在报告中标注偏移随位置漂移的方向与幅度。
5. 实现相似片段边界细化与重叠消解：对每个通过最小匹配数的候选片段按相邻帧匹配密度细化起止边界，得到的片段在两条时间轴上均以整数采样点表示且不越界；多个候选片段重叠时按规格规定规则消解（保留得分高者或合并），消解结果须与逐个候选独立计算后再合并的结果一致。
6. 实现并发检索与资源预算控制：按并发上限使用有界线程池并行处理待检曲目的分帧频谱计算，同时在途频谱缓冲帧数受内存预算限制，超出预算时按曲目清单声明顺序等待而非降低帧长或频带精度；任一曲目失败时取消其余任务并返回首个错误，最终每个候选片段的结果不受并发调度顺序影响。
7. 实现组件化交付与可集成的示例：把指纹提取、索引检索与片段定位拆分为可独立调用的模块并保持接口稳定，提供完整示例程序演示从生成样本、建立参考索引、检索待检曲目到输出片段的端到端流程；示例输出须为 JSON 报告，含每对曲目的片段列表、得分、整数帧偏移与浮点参考偏移、首次超容差位置与业务码。
8. 实现异常注入下的错误链路与原子输出：按任务描述中的异常注入清单在指定曲目注入截断文件、全静音段、错误采样率声明或超出频带范围的参数，引擎须对受影响曲目给出可区分的业务码并继续处理其余曲目；最终报告与检索结果先写同目录临时文件再整体替换正式文件，失败时保留旧版本并返回 E_WR。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地生成的变速与噪声样本验证片段定位精度、得分一致性与异常业务码，并附运行结果。
