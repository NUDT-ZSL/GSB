容量评估首版的工程实施刚刚排入迭代，负责的工程师在本地 WSL Ubuntu 机器上还没有写过一行代码，工作区里只有一份需求文档。需要从零构建一个可运行的容量评估诊断引擎，将服务实例的请求轨迹流转换为容量指标，并在两代容量阈值快照带来的增量更新与依赖失效下作出可复现的容量评估结论。全部输入由随题交付的固定种子脚本确定性生成：容量评估场景声明服务清单（服务名、实例 ID、服务等级、期望请求速率）、请求轨迹流（每条记录含请求序号、服务名、实例 ID、注入逻辑时钟毫秒戳、耗时毫秒、成功标记、丢弃标记）、容量指标定义（CPU 利用率、内存占用率、请求延迟 P95、吞吐达标率的换算参数与定点标度）以及两代容量阈值快照（v1 为单文件 JSON，记录相对生效秒数与扁平阈值；v2 为分片 JSON 加 SQLite 元数据库，记录绝对生效毫秒、阈值代数、依赖的服务等级与失效墓碑）。引擎需在注入逻辑时钟下完成滑动窗口聚合、指标定点换算、跨版本阈值合并、阈值补丁失效闭包、容量拐点判定与异常注入恢复，并保证同一输入任意运行次数下逐位一致。

任务环境与准备：
在 WSL Ubuntu Linux 上准备 Python 3.10 或以上版本，安装 SQLite3 与 NumPy，无需外部网络或 GPU。
使用随题交付的固定种子脚本生成容量场景、请求轨迹、指标定义、两代阈值快照、补丁与异常注入清单到本地临时目录。
确认工作目录为空，不依赖任何真实服务或线上站点。

业务要求：
1. 实现容量评估场景、请求轨迹流、指标定义与两代阈值快照的解析校验，确保服务名与实例 ID 唯一、请求耗时与吞吐相关字段为非负有限数、成功与丢弃标记枚举合法、指标定义的定点标度为正整数、v1 相对生效秒数为非负整数、v2 分片哈希与阈值代数单调，并在任意非法字段出现时返回明确业务错误码且不写入任何状态。
2. 依据注入逻辑时钟把请求轨迹切分为滑动窗口，窗口长度与步长均来自指标定义，每个请求必须唯一归属一个窗口且不重不漏，窗口边界只依赖注入逻辑时钟毫秒值而不读取系统墙钟，同一轨迹在任意运行次数下产生逐位一致的窗口划分和每窗请求集合摘要。
3. 对每个容量指标执行受控定点换算，把 CPU 利用率、内存占用率、请求延迟 P95 与吞吐达标率按各自标度换算为整数，登记每次除法与乘法的被舍弃余量、舍入方向与登记序号，并按窗口累计误差上界，输出包含窗口号、参与请求区间、换算标度与余量的误差来源链。
4. 跨版本合并两代容量阈值快照并构建统一阈值视图，同一服务等级同一指标在 v1 与 v2 同时存在时依据声明的逻辑时钟与阈值代数裁决最新版本，逻辑时钟相同则按来源格式优先级裁决，v1 相对秒数在注入逻辑时钟下换算为绝对毫秒并记录换算标度、舍入方向与舍入前原始值，合并后保留来源版本、原始时间表示与裁决依据。
5. 以补丁形式提交阈值修改、依赖服务等级变更或失效墓碑时，沿服务等级到指标的依赖边计算失效闭包，精确标记哪些窗口容量值、误差账本与精度敏感标记需要重算、哪些可安全复用，未受影响的窗口结论与依赖摘要不得改变，且同一补丁多次提交必须幂等。
6. 在阈值快照变更或指标换算参数调整时，以基于 decimal 的高精度全量重算作为唯一真值对照，与定点通路逐窗口逐指标比对，输出两通路数值、绝对偏差、相对偏差与结论是否翻转，偏差超过误差上界预算的窗口必须返回独立业务错误码并保留参与比较的换算登记序号。
7. 依据每窗口指标与合并后的阈值判定容量拐点，当两个服务或两个窗口的同一指标差小于给定容差且容量评估结论依赖该差值时标记精度敏感，输出误差来源链、误差上界以及若改用更高定点标度是否翻转结论，容量拐点判定必须记录触发的窗口号、阈值证据与被否决的候选结论。
8. 把滑动窗口水位、已提交窗口摘要、阈值合并裁决、失效闭包记录、精度敏感记录与逻辑时钟水位以事务原子写入 SQLite，进程在窗口聚合、定点换算、阈值替换或补丁提交中途被强制终止后，恢复路径依据持久化状态识别已提交与半提交步骤，只重放缺失部分且保证余量账本不重复累计，并支持多进程并发一致性与幂等提交。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
验证本地样本下容量评估的确定性、跨版本阈值失效恢复与精度账本一致性，并比对高精度全量结果。

## 工程实现快速入口

可运行实现位于 `capacity_engine/`，测试位于 `tests/`，完整说明见 `docs/TECHNICAL.md`，实际验证记录见 `VALIDATION.md`。

环境准备（Python 3.10+；当前验证机已具备 Python `sqlite3` 3.37.2 和 NumPy 2.0.0）：

```bash
python3 -m pip install -r requirements.txt
# 可选：手工使用 sqlite3 shell 时，在 WSL Ubuntu 执行
# sudo apt-get update && sudo apt-get install -y sqlite3
```

```bash
python3 -m capacity_engine.cli seed --dir /tmp/capacity-sample
python3 -m capacity_engine.cli validate --input /tmp/capacity-sample
python3 -m capacity_engine.cli run --input /tmp/capacity-sample --out /tmp/capacity-run
python3 -m capacity_engine.cli verify --out /tmp/capacity-run
python3 -m unittest discover -s tests -v
python3 scripts/acceptance.py
```

崩溃恢复示例：

```bash
python3 -m capacity_engine.cli run --input /tmp/capacity-sample \
  --out /tmp/capacity-crash --crash-at patch_commit \
  --crash-patch patch-001-gold-cpu-threshold

# 进程以 86 退出后，去掉 --crash-at 重跑即可
python3 -m capacity_engine.cli run --input /tmp/capacity-sample --out /tmp/capacity-crash
```

主要产物包括 `reports/baseline.json`、`reports/<patch_id>.json`、`capacity_state.sqlite` 和 `run_summary.json`。
