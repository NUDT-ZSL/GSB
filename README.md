本次开工的代码库还没有任何提交，团队要在一台全新的 Linux（WSL Ubuntu） 开发机上交付首个可运行版本，用于诊断多源遥测变量的在线预测器漂移。全部输入由本地固定种子脚本确定性生成，不依赖外部服务、真实账号或数据集：观测流含若干变量在不同采样率下的时间序列，每条记录带变量序号、源名称、逻辑毫秒与数值向量，并注入缺失、离群和局部变化段；预测器配置声明输入输出变量、回归模型类型、原始残差与滑动统计窗口、精度档与定点缩放参数；同时给出两代预测器快照 v1 单文件 JSON 与 v2 分片 JSON 加 SQLite 元数据库，用于互操作与代际切换验证。系统不是离线训练，而是围绕两组不同变量之间的“协同-漂移”判定以及滑动残差驱动的重训练闭包展开，最终交付数据处理管线与结果验证工具。

任务环境与准备：
安装 Python 3.10 或更高版本，并安装 NumPy 1.24 以上版本：pip install numpy
提供一个本地固定种子脚本，生成变量观测流、预测器配置及两代快照文件，所有输入位于项目 data/ 目录

业务要求：
1. 实现确定性的双边变量对齐与残差回溯窗口构造：按逻辑毫秒和采样率把两组变量观测对齐到公共时间索引，缺失值依据配置做前向填充或最小变化插补，并对每个滑动窗口做残差回溯；同一输入、同一配置与固定种子下必须逐字节产出相同的对齐序列与窗口残差摘要。
2. 实现残差滑动统计量与预测器漂移分数计算：除均值和方差外，按配置的滑动衰减系数计算连续窗口残差的偏度和趋势统计量，并把协变量反传的上游异常贡献计入漂移分数；每个窗口的漂移分数必须可由原始残差和窗口参数独立复算，不能依赖全局预测器状态的隐式截断。
3. 实现预测器增量重训练闭包：对超过漂移阈值的窗口标记漂移事件，计算其影响相邻窗口的最小闭包，同分时按窗口起始逻辑毫秒升序合并，闭包内只对该闭包涉及的样本做增量重训练并替换旧预测，未进入闭包的窗口预测必须复用旧结果且不得改变。
4. 实现两代预测器快照的读取与互迁：v1 单文件 JSON 记录相对秒与扁平参数，v2 分片 JSON 加 SQLite 元数据库记录绝对毫秒、配置代数与失效墓碑；读取按版本头分派，升级时补全元数据并记录补全来源，降级时对无法表达的增量重训练代数按显式丢弃并输出丢弃记录，未知版本返回 E_VERSION_UNSUPPORTED。
5. 实现双端输入的数值漂移与预测器漂移的联合门槛裁决：为输入残差幅度和预测器漂移分数分别提供严格比较与容差带比较两种策略及次正规数保护，漂移判定必须在 float64、float32 与定点缩放整数三档下保持一致，门限附近样本的判决不得被舍入翻转。
6. 实现基于内容寻址的缓存与按依赖闭包的定向失效传播：缓存键纳入输入变量内容哈希、预测器快照版本、残差窗口范围、回收率阀值和重训练配置摘要，键相同必须复用；当某变量修订、预测器参数变化或残差窗口尺寸改变时算出受影响预测器闭包和受影响窗口集合，仅重算闭包内产物并输出重算与复用清单。
7. 实现阶段状态机与持久化检查点，可处理信号进入退出报告后由显式保存点恢复，对强制终止只承诺恢复最近已提交阶段；阶段快照携带单调递增版本号、已完成记录集合与内容校验和，只有整个阶段完成才以临时文件原子替换提交，提交顺序与阶段状态不存在交错可见的半完成状态。
8. 实现并发提交控制与多窗口交叉诊断的校验账本，并给出结果验证入口：同一时刻只允许一个阶段或预测器快照提交生效，冲突后到者返回 E_STAGE_BUSY 且不阻塞；校验账本记录每个重训练闭包覆盖的窗口集合、重算范围、预测器漂移分数和涉及的业务码，并能独立重放出相同结果。
