某安全团队需要在离线 Windows 工作站上构建一个身份认证与会话隔离的增量失效检测与诊断工作台。输入是一份本地确定性 JSON 策略声明文件（会话策略、令牌规则、角色绑定及其版本与依赖声明）和一批会话事件流（登录、续期、角色变更、登出、令牌撤销）。工具须在策略增量更新时识别哪些已签发令牌与活跃会话因依赖失效而被波及，把失效传播链可视化，并输出可复现的 JSON 诊断报告与人工可读的依赖图。核心难点是：策略条目之间存在角色继承与令牌模板引用，一次增量更新可能只改一条规则却沿依赖链波及大量会话；失效判定必须与更新的到达顺序无关，且检查点恢复时不得把旧版本策略的失效结论混入新版本。工作区为空，从零开发，不依赖网络、真实账号或外部服务。

任务环境与准备：
确认 Windows 本地 Python 3.10 及以上可用，创建空白工作目录作为项目根。
安装 pytest 与 NumPy 到本地虚拟环境，不连接外部网络服务。
无需外部数据或账号，样本生成器与测试均在本地确定性生成与运行。

业务要求：
1. 实现策略声明与事件流的解析规范化层：逐项校验策略条目版本号格式、角色继承引用是否存在、令牌规则引用的策略标识是否存在、事件中的会话标识与令牌标识格式，对非法条目输出含条目序号与业务错误码的拒绝记录并继续处理后续内容，不得因单条非法而整体中止。
2. 构建策略依赖图并实现增量更新后的失效传播：以角色继承边与令牌模板引用边计算从被修改条目可达的受影响条目集合，再映射到依赖这些条目的已签发令牌与活跃会话，输出失效传播链；传播必须支持传递闭包且对环状依赖返回 E_CYCLE 并列出环中条目序号。
3. 保证失效判定与更新到达顺序无关：对同一组增量更新，任意合法到达顺序下最终受影响的令牌集合、会话集合与传播链必须完全一致；时间戳相同或缺失时须以版本号与稳定键排序作为次序依据，不得依赖到达顺序或字典遍历顺序。
4. 实现增量日志与检查点：按已应用更新水位与策略版本持久化检查点，恢复时只从最后一个完整检查点继续；检测到检查点结构版本或策略版本与当前不一致时须整体重建而非增量续接，不得把旧策略版本的失效结论与新策略混合。
5. 实现原子快照与强制终止边界：检查点与诊断快照均先写临时文件再整体替换，替换前校验内容完整性；同一工作目录并发写入须用文件锁串行化，锁冲突返回 E_LOCK；进程被强制终止后只允许恢复到最后一个完整检查点，不承诺生成退出报告，且不得残留半写文件。
6. 实现诊断工作台输出：生成可解析的 JSON 诊断报告（含失效令牌、活跃会话、传播链、错误码与偏移/序号）以及一份依赖图数据文件（节点、边、受影响标记）；单份事件流处理失败不得中断同批其他文件，退出码区分全部成功、部分失败与参数错误三种情形。
7. 实现基于同步标记的真值对照：样本内显式记录每条策略更新前后的版本同步标记与预期受影响集合的观测条目，验证只依据这些标记与依赖图计算比较，不得以生成器的中间计算结果作为真值；报告须给出观测一致与不一致的明细。
8. 提供确定性本地样本生成器与 pytest 测试集：覆盖顺序无关、传播链环状依赖、非法条目、版本变化重建、锁冲突与强制终止恢复、半写文件残留等情形，测试须断言业务错误码、受影响集合一致性与恢复后状态正确性。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证增量失效传播、顺序无关一致性与检查点恢复，并核对诊断报告中的错误码与退出码。
