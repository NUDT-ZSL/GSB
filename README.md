在空白工作区从零实现一个本地变更批次灰度放量与回滚窗口编排引擎，用于在确定性样本上复现同一服务多批次变更在灰度放量过程中的批间依赖、放量节奏与回滚窗口裁决，并兼容两代批次节奏描述格式。本地样本给出两代节奏描述：v1 为单文件 JSON 的批次节奏表，以批次号为主键给出灰度档位比例序列、批次间最小间隔相对秒数、观察点标记；v2 为分片 JSON 加 SQLite 元数据库，以服务规范名加批次号为主键给出绝对放量时刻毫秒戳、批次代数、观察点合格判据、与同服务其它批次的依赖关系及回滚窗口起止毫秒。另给出观测事件流，按可注入逻辑时钟记录每批次的观察指标快照与人工中止信号。引擎需合并两代节奏为一个统一放量视图，在注入逻辑时钟下推演每档放量、观察点判定、批间推进与回滚窗口开闭，识别格式冲突与版本不兼容，并在进程被强制终止后依据持久化状态恢复未完成的回滚窗口收尾。

任务环境与准备：
安装 Python 3.11 或以上版本，确认标准库 sqlite3、hashlib、json、multiprocessing 可用。
安装 NumPy（建议 1.26 及以上）用于档位比例与观察指标快照的向量化计算。
在空工作区用本地固定脚本生成样本：v1 批次节奏单文件 JSON、v2 分片 JSON 与 SQLite 元数据库、节奏包清单、观测事件流、兼容降级默认语义声明，全部离线可复现。
确认工作目录可读写，SQLite 数据库文件与分片目录均在工作区内，无需任何容器或容器编排环境。

业务要求：
1. 实现两代批次节奏描述的解析与校验：v1 校验批次号在服务内唯一、灰度档位比例严格递增且以 1.0 收尾、批次间最小间隔为非负整秒、观察点标记位于档位序列内；v2 校验分片文件哈希、批次代数单调、绝对时刻为毫秒非负整数、依赖批次必须已声明、回滚窗口起止为合法区间；非法输入必须返回明确业务错误码如 E_BAD_RHYTHM、E_BAD_SHARD 且不写入任何持久化状态。
2. 实现跨版本合并与统一放量视图：同一服务同一批次在两代描述中同时存在时，依据描述声明的逻辑时钟与批次代数裁决最新节奏，逻辑时钟相同按来源格式优先级；合并后每批次须保留来源版本、原始节奏表示与裁决依据，两代档位比例序列不一致且无法裁决时必须输出冲突双方完整证据并进入待人工裁决态，不得静默取任一版本继续放量。
3. 实现档位节奏的模式迁移与等价性保证：把 v1 的批次间最小间隔相对秒数在注入逻辑时钟下换算为绝对最早放量时刻并记录换算标度与舍入方向，v2 绝对时刻保持原值；v1 缺失的观察点合格判据与回滚窗口迁移为 v2 声明的默认语义并记录迁移映射；迁移后同一逻辑时钟下放量档位顺序与批次推进先后必须与迁移前等价，不得因换算导致批间次序颠倒。
4. 实现灰度放量与观察点判定的推进链：每批次按档位序列逐档提升流量比例，每档到达观察点后依据观测事件流中的指标快照与合格判据裁决通过、继续观察或中止；批次推进须同时满足前一批次达成稳定结论与批次间最早放量时刻，未满足时下游批次必须等待并记录阻塞来源，不得凭内存残留决定批次是否可推进。
5. 实现回滚窗口的开闭与中止回滚裁决：人工中止信号或观察点判据不满足时在回滚窗口内执行回滚，回滚须按档位倒序逐档降低流量比例并在最后恢复至零放量，每档回滚记录生效时刻与依据；超出回滚窗口仍未完成时必须标记为超窗失败并输出已完成档位、未完成档位与首个失败原因，不得承诺超窗后仍能自动恢复到零放量。
6. 实现基于注入逻辑时钟的版本兼容判定与格式互操作：所有档位时刻、观察点间隔与回滚窗口边界只依赖注入逻辑时钟毫秒值，不读取系统墙钟；v2 新增字段在 v1 路径读取时必须按声明默认语义降级处理并记录兼容降级决策；同一逻辑时钟序列重放必须得到逐位一致的放量与回滚序列，逻辑时钟回拨超过容差时返回业务错误码并保持视图不变。
7. 实现节奏包整体替换的版本变化识别与回退拒绝：收到新节奏包时比较清单版本号、批次代数下限、各分片哈希与档位序列摘要，判定完整替换、增量追加还是无需操作；整体替换须以临时表加版本号切换当前节奏指针而非逐条覆盖，版本回退必须被拒绝并留证据；进行中的放量必须绑定其开始时节奏版本直至该批次结束，读者不得看到新旧节奏混合的档位。
8. 实现强制终止后的恢复与多进程幂等演示：把批次阶段、已完成档位、观察点结论、回滚窗口状态、迁移决策与逻辑时钟水位以事务原子写入 SQLite；进程在放量或回滚中途被强制终止后，恢复路径识别已提交档位与半提交档位，只重做未提交档位且不得重复提升或重复降低流量比例；提供 load、merge、ramp、observe、rollback、resume、status、verify 子命令，status 以稳定排序 JSON 输出节奏版本、各批次已完成档位与回滚窗口状态，固定样本运行两次输出逐字节一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本运行两次，验证两代节奏合并、灰度放量与观察点推进、回滚窗口收尾及强制终止后恢复结果逐字节一致。
