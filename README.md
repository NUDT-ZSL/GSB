交付从新建的代码库开始，需要实现一个本地弹性容器实例冷启动的配额账本与抢占回收裁决引擎，核心业务问题是：在可注入逻辑时钟下，把容器实例冷启动所需的本地镜像层读取配额、临时存储写入配额与启动时限预算统一记账，并在配额逼近上限时依据实例优先级与启动阶段裁决抢占回收哪些在途冷启动。本地 JSON 样本给出：容器实例清单（实例 ID、服务名、优先级、请求的临时存储字节、所需镜像层摘要集合、启动截止逻辑时钟毫秒）、本地镜像层托管清单（层摘要、层字节、所在节点、引用计数）、节点本地存储快照（节点名、可用临时存储字节、镜像层已占用字节、单节点并发冷启动上限），以及账本配置（临时存储配额上限、镜像层读取带宽字节每秒、单轮冷启动逻辑时间预算、定点标度、误差上界预算、逻辑时钟步进毫秒）。引擎需在同一事务内联动冷启动准入、镜像层读取配额扣减与临时存储写入额度登记，使配额账目、启动阶段与中断恢复后的重放结果逐位一致。

任务环境与准备：
安装 Python 3.11 或更高版本，并在虚拟环境中执行 pip install pytest。
确认 SQLite 3 由 Python 标准库自带且可正常打开本地数据库文件，无需安装额外数据库服务。
准备本地样本目录，包含容器实例清单、本地镜像层托管清单、节点存储快照与账本配置四份 JSON 文件，均置于同一工作区根目录下。
运行平台为 Windows，所有路径使用本地文件系统，不依赖网络、真实集群或外部存储服务。

业务要求：
1. 实现容器实例清单、本地镜像层托管清单、节点存储快照与账本配置的解析校验：实例 ID 与层摘要唯一、所需镜像层均存在于托管清单、请求临时存储字节与层字节为正整数、节点可用存储与并发上限为正整数、定点标度与误差上界预算为正；非法输入返回明确业务错误码且不写入任何持久状态。
2. 实现基于注入逻辑时钟的冷启动准入与启动阶段演进：实例在待准入、读层中、写临时存储中、已就绪、已撤回之间按规则迁移，准入判定只依据注入逻辑时钟毫秒值、启动截止时刻与节点并发上限，不读取系统墙钟；过了启动截止的实例不得进入读层阶段而须进入撤回，撤回与读层失败须使用不同结局码。
3. 实现镜像层读取配额与临时存储写入额度的受控定点换算与余量保留：把层读取字节按带宽换算为预计读层逻辑毫秒、把临时存储写入按声明标度换算为定点字节额度，登记每次换算的标度、舍入方向与被舍弃余量；未满一个定点单位的余量须逐实例与逐节点分别保留并在后续换算中参与，同一输入重复换算逐位一致。
4. 实现配额账本的原子扣减与守恒校验：每次准入必须在同一事务内扣减节点可用临时存储额度、登记镜像层读取配额与实例写入额度，任意时刻账本不得出现负余量、重复扣减或层字节与实例所需层集合不一致；盘点时须校验已扣减总量等于各实例登记额度之和，层字节变化须使引用该层的在途实例进入撤回。
5. 实现配额逼近上限时的抢占回收推演：当节点可用临时存储不足以准入高优先级实例时，按优先级、启动阶段与已消耗额度推演可被抢占回收的在途实例集合，输出完整回收链、回收依据与回收后能否准入的判定；被抢占实例须记录已消耗层读取额度与写入额度的退还未结记录，回收不得使节点账本短暂为负。
6. 实现单轮冷启动逻辑时间预算与节点并发上限双重约束下的并行调度：同一轮次内按节点分组并发推进冷启动，同时受单轮逻辑时间预算与节点并发上限约束；预算耗尽须放弃剩余未启动实例并记录放弃原因，严格区分预算内未启动、启动后失败与主动放弃三类结局，已启动实例不得以线程超时描述为已终止。
7. 实现定点与 decimal 双通路误差账本及精度敏感标记：对每实例的预计读层耗时、写入额度与调度得分同时计算受控定点通路值与基于 decimal 的高精度通路值，记录两通路数值、绝对偏差与累计误差上界；当两个候选实例或两条回收链的得分差小于比对容差且准入或回收裁决依赖该差值时标记为精度敏感，输出误差来源链（实例、层摘要、换算登记序号、余量）。
8. 实现强制终止后的恢复一致性与多进程幂等：把冷启动轮次水位、实例阶段、已提交层读取摘要、节点可用存储与并发占用、余量保留表、退还未结记录与逻辑时钟水位以事务原子写入 SQLite，每轮提交识别版本变化并整体替换当前账本指针；多实例并行时保证同一实例同一轮次同一来源只提交一次、节点存储与并发不被并发超扣，重复提交相同结果幂等；层摘要不匹配、层缺失、逻辑时钟回拨超阈值分别映射到不同业务错误码。
