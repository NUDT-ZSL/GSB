在空白工作区从零实现一个本地数据库主从复制延迟诊断组件，核心是让两代复制元数据格式在同一套延迟计算链路中互操作，并在弱一致性延迟观测下给出可复现的延迟结论。本地样本给出两代复制位点记录：v1 为单文件 JSON 行，记录事务号、写入相对延迟毫秒、事务字节量与提交标记；v2 为分片 JSON 加 SQLite 元数据库，记录事务号的规范形式、绝对提交时间戳毫秒、回放时间戳毫秒、主从节点标识、回放代数与是否已应用墓碑。从库回放进度由本地样本日志目录中的有序事务流模拟，不依赖真实主从服务。组件需加载并合并两代位点记录，按注入逻辑时钟计算每事务的回放延迟、滑动窗口延迟分位数与从库落后量，并识别版本回退、位点不连续与精度换算差异。

任务环境与准备：
安装 Python 3.10 及以上版本，仅使用标准库与 NumPy、SQLite3 模块，不引入其他第三方依赖。
在空白工作区准备本地样本目录：放置 v1 单文件 JSON 行位点样本、v2 分片 JSON 与 SQLite 元数据库样本、有序事务流日志目录、以及新位点包样本（含完整替换与回退两种情形）。
准备注入清单样本，用于向解析、合并、延迟计算注入非法事务号、断链、摘要不匹配与逻辑时钟回拨等异常。
确保工作区可写以创建 SQLite 状态库与临时对象目录，运行环境为 Windows 本地文件系统。

业务要求：
1. 实现 v1 与 v2 两代复制位点记录的解析与校验：v1 校验事务号严格递增、相对延迟毫秒为非负整数、事务字节量为正、提交标记与行序一致；v2 校验分片文件哈希、SQLite 元数据中的回放代数单调、绝对提交与回放时间戳为毫秒整数且回放不早于提交、墓碑标记与回放代数对应；非法记录必须返回明确的 E_xxx 业务码并不写入任何持久化状态。
2. 实现跨版本位点合并与统一位点索引：同一事务号在两代记录中同时出现时，依据记录声明的逻辑时钟与回放代数裁决最新版本，逻辑时钟相同则按来源格式优先级；合并后每个事务须保留来源版本、原始时间表示与原始延迟表示，供误差溯源读取；合并结果按事务号稳定排序，不得因输入文件加载顺序不同而改变裁决结果。
3. 实现延迟语义的模式迁移：v1 的相对延迟毫秒在注入逻辑时钟下换算为绝对回放时刻并记录换算标度与舍入方向，v2 的绝对时间戳保持原值；v1 无回放代数的事务迁移为 v2 的统一代数语义并记录迁移映射；迁移不得改变事务在延迟计算上的先后关系，也不得把精度换算误差隐式丢弃。
4. 实现主从复制延迟计算：按事务序计算每事务的回放延迟、从库落后量（未回放日志字节数与未回放事务数）及滑动窗口延迟分位数，分位数按固定排序与插值规则计算，所有运算顺序固定使同一输入在任意运行次数下逐位一致；每个窗口摘要必须记录所依赖的已提交水位与参与计算的事务区间。
5. 实现精度与延迟观测诊断：对每条延迟记录换算与累计过程记录误差上界，当两个事务或两个窗口的延迟差小于给定容差且结论依赖该差值时标记为精度敏感，并输出误差来源链；延迟结论必须说明依赖的观测（提交与回放时间戳或相对延迟）与真值来源（按事务号排序的全量重算），不得从缺失时间信息推断延迟。
6. 实现位点整体替换的版本变化识别与回退拒绝：收到新位点包时比较清单版本号、逻辑时钟下限、事务号区间与各分片哈希，判定完整替换、增量追加或无需操作；完整替换必须整体替换当前位点快照指针而非逐条覆盖，位点回退（事务号上界低于当前水位）必须被拒绝并返回业务错误码。
7. 实现强制终止后的恢复与多进程幂等：把当前位点快照指针、迁移决策、窗口摘要、误差记录与已提交事务水位以事务原子写入 SQLite，位点替换采用临时表加版本号整体替换；进程被强制终止后依据持久化状态识别未提交的合并或替换步骤并只重放未完成步骤，不承诺一定生成退出报告；多个实例并发处理同一事务号时通过事务与文件锁保证同一版本只被提交一次，读取方只能看到完整已提交的位点快照。
8. 提供可重复命令行接口与结果验证工具：支持 load、merge、lag、resume、status、verify 子命令，lag 以稳定排序 JSON 输出每事务延迟、窗口分位数、精度敏感标记与误差上界，status 输出当前位点版本、迁移决策数量与墓碑事务数，verify 校验持久化状态与输出一致；使用固定本地样本连续运行两次必须产生逐字节相同的 JSON 输出。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地两代位点样本验证合并裁决、延迟计算、精度标记、恢复与并发幂等，连续两次运行输出逐字节一致并覆盖各业务错误码。
