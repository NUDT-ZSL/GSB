当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向 LLM 多轮对话状态管理的本地诊断应用，核心业务问题是对话槽位状态在轮次回滚与增量追加下的失效传播与因果追溯。业务对象是本地确定性生成的多轮会话：每段会话由固定种子拼装若干轮用户与助手消息，每轮用户消息携带若干槽位候选（键、值、来源轮次、置信度、抽取器版本），助手轮次携带触发的澄清请求。状态推进被建模为有向无环计算图：轮次解析→槽位候选打分→槽位合并（含覆盖与冲突裁决）→待澄清集合生成→状态摘要。应用需支持把某轮标记为“撤回”并按剩余轮次重算状态，也支持在尾部追加新轮次；两者都要计算受影响的图节点与槽位集合，复用未受影响上游产物，并让每个最终槽位值可追溯到产生它的轮次、候选与缓存键。

任务环境与准备：
确认使用 Windows 本地环境与 Python 3.10 及以上版本，安装 NumPy 与标准库自带组件。
在工作区创建从零开始的本地目录结构，会话样本由固定随机种子在本地确定性生成，不下载任何外部数据。
本地运行验证使用自带测试脚本或命令行入口，不依赖真实账号、线上站点或容器环境。

业务要求：
1. 实现确定性的轮次解析与槽位候选打分节点：按帧内轮序解析用户消息中的槽位候选，按置信度与抽取器版本加权打分，同分按来源轮次升序、再按槽位键字典序裁决；同一会话、同一抽取器版本与同一配置下必须逐字节产出相同的候选集合与分数。
2. 实现槽位合并节点：同一槽位键在新轮次出现时按来源轮次覆盖，来源轮次相同时取高分候选，仍相同按候选值字典序裁决并标记冲突；合并结果须记录获胜候选与全部被覆盖候选，且被覆盖候选不得在最终状态中继续可见。
3. 实现待澄清集合生成节点：由合并后的槽位状态与助手澄清请求推导待澄清槽位集合，须校验待澄清槽位均存在于槽位状态中且其获胜候选置信度低于澄清门限，违反分别返回 E_PENDING_SLOT_MISSING 与 E_THRESHOLD_CONFLICT 并指明槽位键。
4. 实现按内容寻址的节点产物缓存与缓存键构造：候选打分、槽位合并、待澄清集合与状态摘要各自以内容哈希落盘，缓存键须纳入该节点输入摘要、抽取器版本、澄清门限与上游节点哈希；键相同必须复用快照，键不同必须重算，且每个条目须可按键取出并核对哈希。
5. 实现轮次撤回的定向失效传播：把某轮标记撤回时，计算受影响槽位集合与该轮之后受其覆盖关系影响的槽位，复用未受影响上游产物，仅重算受影响后缀；须输出本次重算节点清单、重算槽位清单与复用集合，并保证撤回后的状态与“从不含该轮的会话直接重算”的结果逐字节一致。
6. 实现尾部追加轮次的增量推进：追加一轮时仅对新增轮次及其影响的槽位重算，已提交轮次不得重算；须保证增量推进结果与整体重算一致，且当追加轮次与撤回同时发生时按显式声明的处理顺序执行并输出顺序记录，顺序非法返回 E_OPERATION_ORDER。
7. 实现槽位值的因果追溯重放：对任一最终槽位值，可按其记录的缓存键、来源轮次、获胜候选与抽取器版本重放出同一值与同一被覆盖候选集合；当追溯链中断、键无法复现或版本已变化而记录未更新时返回 E_LINEAGE_BROKEN 或 E_LINEAGE_STALE 并指出槽位键与断点节点。
8. 实现缓存与配置快照的版本化整体替换、并发写控制及本地可交互诊断应用：快照携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换而非增量修补，回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符返回 E_CACHE_CORRUPT；多个任务并发写同一条目时须保证只有一个写入生效，冲突方立即获得 E_STAGE_BUSY 而不阻塞等待；应用展示计算图拓扑、撤回与追加的失效覆盖范围、逐槽位获胜候选与追溯路径、快照版本与最近业务错误码，并允许触发一次撤回与一次追加的演示。
