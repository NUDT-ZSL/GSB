为多模态协同推理团队构建一个本地可运行的推理会话服务，核心问题是多模态证据融合下的状态演进与恢复一致性。输入是本地场景目录：一份查询样本 JSONL（每条含 query id、文本提示与图像描述向量）与一份证据清单 JSONL（每条含证据 id、所属查询、模态类型 text 或 image、固定维度嵌入向量与置信度）。工作区为空，需从零创建项目：一个 FastAPI 服务，支持创建推理会话、按阶段执行多模态证据融合与协同打分、查询会话状态、导出快照。会话必须经历 evidence_loaded、fused、scored、committed 四个阶段，每个阶段完成后状态可追溯；进程中可能被强制终止，重启后必须仅依据 SQLite 已提交状态恢复，且每个阶段的输出在恢复后与无中断执行一致。多模态融合涉及数值累积误差传播，阶段推进涉及版本化快照与失效检测，多个查询可并发执行又共享全局融合预算。

任务环境与准备：
安装 Python 3.11 与 pip，创建虚拟环境。
安装 fastapi、uvicorn、numpy、pytest，版本固定写入 requirements.txt。
在本地生成固定随机种子的查询样本与证据文件，每类文件同时准备一份含非法字段的样本用于异常验证。
以本地端口启动服务并用 uvicorn 单进程运行，确认 SQLite 文件与结果目录位于工作区内。
准备强制终止测试脚本：在指定阶段后对服务进程发送 terminate 信号，再重启服务执行恢复。

业务要求：
1. 服务须提供会话创建接口，接收场景目录、证据文件、融合权重与全局并发预算，校验文件存在、嵌入维度一致、权重非负且和为 1、预算为正整数；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不得写入任何会话状态或产生临时文件。
2. 须实现确定性的多模态证据融合：对每条查询的文本与图像证据分别按模态分组，组内按置信度降序、同分按证据 id 字典序累加，用 log-sum-exp 在 float64 下做加权融合；相同输入与权重下融合向量须逐位一致，不得依赖浮点求和顺序或全局随机状态。
3. 会话须按 evidence_loaded、fused、scored、committed 四个阶段推进，阶段顺序不可跳步，乱序推进返回 E_STAGE 并给出当前阶段；重复调用已完成阶段须幂等返回已有结果与快照版本，同一会话的最终得分在重复调用间须逐位一致。
4. 证据校验须在 evidence_loaded 阶段完成：模态类型非法、证据 id 重复、置信度不在闭区间 [0,1] 或查询引用的证据缺失时分别返回 E_MODAL、E_DUP、E_CONF、E_EVID 业务码并定位证据 id 与查询 id，校验失败不得进入下一阶段。
5. 会话状态须以会话、阶段、查询三级记录在 SQLite 中提交，单个查询的融合结果与阶段进度在同一事务中写入；某查询融合或打分失败时整个阶段事务回滚，不得留下部分查询结果或与快照版本不一致的记录。
6. 每次阶段完成须生成整体替换的版本化快照，含会话版本号、各查询阶段结果摘要与结果文件内容哈希；读取快照时若检测到数据库版本与磁盘结果文件哈希不一致、版本变化或残留旧结果文件，须返回 E_STALE 并定位到查询，禁止返回旧数据。
7. 服务须支持多查询并发执行且共享创建时给定的全局融合预算，预算按查询实际消耗的融合单元计数并原子扣减；预算耗尽时排队查询须返回 E_BUDGET 而非阻塞或超额执行，并发场景下预算扣减总数不得超过给定值。
8. 进程被强制终止后重启，服务须从 SQLite 已提交进度继续，核对每个会话的阶段标记、查询结果文件哈希与快照版本，重算未提交查询且不重复消费已提交证据；恢复后的阶段结果、逐查询得分与无中断执行须完全一致，并提供确定性演示入口输出阶段推进序列、逐查询得分与预算消耗的可重复结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本与权重验证四阶段推进、并发预算扣减、快照失效检测及强制终止后恢复结果与无中断执行逐位一致。
