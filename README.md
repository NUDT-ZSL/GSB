数字出版平台的值班工程师在章节更新高峰期，面对渲染、转码、索引重建与预热预取四类后台作业同时争抢有限节点资源池的局面。每类作业带有业务截止时刻与可让步标记，节点按 CPU 份额、内存与 IO 带宽三个维度声明容量上界。当前缺乏统一的优先级语义与降级裁决口径，低频索引重建可能挤占高优先级章节渲染，而降级预案释放的资源量又常与准入决策脱节，导致截止时刻失守且难以追溯责任。平台需要在本地可重复演示中复盘每一次争用决策，保留完整的容量账本变更与业务影响说明。

任务环境与准备：
准备 Linux（WSL Ubuntu）上的 Python 3 运行环境，仅使用标准库（json、unittest、argparse 等），无需安装第三方包。
在空目录中创建项目文件，入口为命令行脚本，运行前无需任何外部服务、数据库或网络访问。
提供示例种子与一键运行命令，通过 python3 -m unittest 执行单元测试。

业务要求：
1. 实现一个确定性样本生成器，接收固定整数种子，产出作业工程、节点声明与按逻辑时刻排序的提交/取消事件流；作业工程须包含作业标识、业务类别（章节渲染、音视频转码、索引重建、预热预取）、优先级等级（1-5）、可让步标记、三维资源需求刻度与业务截止时刻；节点声明须包含节点标识、三维容量上界与可接纳类别列表；同一份工程须可被独立参考裁决器以相同种子重建。
2. 按逻辑时刻推进多维资源容量核算：维护每个节点在 CPU 份额、内存与 IO 带宽三个维度上的已占用与可用余量账本，处理作业提交、完成与取消事件，所有容量以整数刻度表示，并在任何决策后保证账本数值守恒，输出每个采样时刻各节点的余量快照。
3. 为每个待决策作业计算紧迫度权重，综合优先级等级与剩余业务时间（截止时刻减当前逻辑时刻）形成可复核的排序键；剩余时间越短、优先级越高则权重越大，当剩余时间小于等于零时紧迫度须有明确的降级语义，不得与其他状态混淆；输出排序依据表供逐条核对。
4. 在节点容量不足以接纳新作业时，按紧迫度从低到高选择可让步的已接纳作业执行抢占或降级：对声明了降级预案的作业按预案切换形态并释放指定资源量，对无可降级形态的作业执行迁移或拒绝；同一组互斥作业不得在同一节点同时被接纳，每次决策须输出准入、抢占、降级或拒绝的类型与理由。
5. 将降级释放的资源量实时回写对应节点的容量账本，并立即以更新后的账本重新评估同一逻辑时刻后续待决策作业的准入结果；输出决策序列与容量变更序列，保证每一步容量变更都能追溯到触发它的决策条目，且序列按逻辑时刻与决策序号严格有序。
6. 按业务类别统计资源满足率（实际分配资源与需求资源之比）与业务截止时刻达成情况，对失守作业输出其从提交到截止期间涉及的争用决策链（包括被抢占、被降级、被拒绝及竞争作业），使值班工程师能定位是哪次决策导致失守。
7. 实现决策检查点：在指定逻辑时刻将当前节点容量账本、已接纳作业集合与事件流位置持久化为 JSON 文件，并支持从检查点恢复后继续推进事件流，恢复后的后续决策须与不中断运行完全一致，检查点须识别版本标识并在加载时校验内容摘要。
8. 提供命令行演示入口，加载或生成作业工程后逐逻辑时刻输出各节点准入决策清单与资源满足率汇总，并附加单元测试验证：容量恰好等于作业需求时的准入判定确定性、降级触发阈值恰好相等时的行为、账本守恒不变量以及检查点恢复后决策序列与全量运行的一致性。

验收：
以独立参考裁决器逐时刻复算为准，比对容量账本守恒、同组互斥、降级回写后准入重算以及检查点恢复后的决策序列完全一致。
