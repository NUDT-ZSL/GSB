消防指挥中心的调度席上，调度员习惯把接警记录、救援站车辆状态与市政水源信息拼成几条固定组合查询，但底层接警事件来自三个年代不同的接入工程：字段名、时间单位（秒与毫秒）、事件等级表达（数字或文本）以及地址结构（扁平表或嵌套树）各成一派。同一班次里调度员会反复发出几十次仅过滤条件或时间窗略有差异的查询，其中大量过滤、连接与聚合被重复计算，导致联动方案出得慢，运维工程师也说不清哪些中间结果可以安全复用、数据追加或查询改写后又该重算哪一块。为此需要在本地从零建立一套接警查询复用内核：把三个 schema 版本归一为统一事件模型，将每条查询解析成逻辑计划树并提取公共子表达式，按整数权重裁决是否物化，执行后给出逐查询结果与复用账目，并在事件批次追加或查询编辑时用版本向量仅重算受影响部分。

任务环境与准备：
准备 Linux（WSL Ubuntu）下的 Python 3 运行环境，仅使用标准库 sqlite3 处理持久化，不安装第三方包。
在空工作区创建项目入口，并在仓库内实现固定种子的确定性接警事件、查询请求与更新序列生成器。
运行前无须外部数据库服务或网络访问，SQLite 数据库文件由程序在本地工作目录内创建并复用。

业务要求：
1. 读取确定性生成器按固定种子产出的三 schema 版本接警事件记录，归一为统一事件模型（接警编号、发生时刻统一为毫秒、事件类型、地址路径、涉及人员、关联救援站与车辆），并输出每个统一字段的来源路径及所依据的版本号。
2. 将每条查询解析为包含过滤、连接、聚合与投影节点的逻辑计划树，对可交换过滤、连接键排序等做规范化，提取结构相同的子树作为公共子表达式候选，输出候选清单及其在多个查询中的引用位置。
3. 对每个候选公共子表达式，结合其在查询集中的引用次数、静态结果行数估计和单次计算代价给出整数权重，裁决是否物化复用并记录裁决理由；遇到同一候选的重复引用次数与计算代价冲突时，按声明的权重规则给出唯一取舍。
4. 按复用计划执行所有查询，输出每个查询的最终结果集，并生成执行账目，逐候选记录复用次数、物化行数以及因复用而未重复执行的代价节省量。
5. 为每个物化公共子表达式维护版本向量（事件数据块版本与查询定义版本），在事件批次追加序列或查询编辑序列到来时，通过版本向量比较找出受影响的公共子表达式清单。
6. 仅重算受影响的公共子表达式并更新其物化结果与版本向量，未受影响的物化结果须逐字节保持不变，且重算过程能从中断的批次边界恢复。
7. 在部分公共子表达式失效重算后，自底向上重组所有引用它的查询结果，并与全量单查询重算结果逐查询比对，输出一致性报告，指出任何结果差异及所涉公共子表达式。
8. 将归一后的统一事件模型、物化结果与版本向量持久化到本地 SQLite 数据库，使进程重启后能依据版本向量继续增量推进，并支持调度席按接警编号或时间范围回查复用账目。

验收：
给定三版本接警工程与查询集，候选清单、复用裁决和节省账目与独立参考实现一致，追加或编辑后仅重算受影响部分且各查询结果与全量重算逐条相同。
