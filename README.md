当前是空白工作区，需要从零实现一个本地慢查询诊断引擎，用于在确定性样本上复现从慢查询原始采样到按归一化模板聚合的执行计划画像，以及统计信息刷新后画像增量失效与中断恢复的完整链路。样本以本地 JSON 与 SQLite 给出：本地样本库（表结构、索引与固定数据，可由脚本确定性重建）、慢查询采样流（采样序号、采集逻辑时钟毫秒戳、SQL 文本、归一化模板 ID、执行耗时毫秒、扫描行数、返回行数、命中索引描述、会话标识）、统计信息快照（表行数、列 NDV、索引前缀选择性、快照版本号与生效逻辑时钟）。引擎需按模板聚合采样、在样本库上构建候选访问路径画像，并在统计补丁提交时沿统计项到索引到模板到画像的依赖链精确判定失效范围。核心矛盾在于：统计快照以整体替换方式推进，而画像与聚合结论必须跨快照保持可复用与可追溯，且进程被强制终止后恢复必须与不中断运行逐字段一致。

任务环境与准备：
安装 Python 3.11 及以上版本，确认 python 与 pip 可在命令行调用。
安装 sqlite3 命令行工具与 Python 依赖 NumPy，执行 pip install numpy 完成安装。
创建空白工作目录，将样本库重建脚本、采样流 JSON、统计快照 JSON 与统计补丁样本放入固定路径，不依赖任何外部数据库或网络服务。
确认运行用户对工作目录具备读写权限，SQLite 数据库文件位于工作目录内，运行前后可用 python --version 与 sqlite3 --version 核对环境。

业务要求：
1. 实现样本库、慢查询采样流与统计快照的解析校验：样本库可确定性重建且表名与索引名唯一，采样序号严格递增，采集逻辑时钟为非负整数，SQL 文本可被归一化器解析且模板 ID 与归一化结果一致，耗时为非负整数；非法输入必须返回明确业务错误码且不产生任何持久化写入。
2. 实现 SQL 到查询模板的确定性归一化与分组聚合：去除字面量与 IN 列表长度差异后得到稳定模板结构，模板 ID 由结构确定性计算，同一 SQL 任意次数归一化必须得到相同模板与 ID；按模板聚合采样数、耗时与扫描行数分位数，分位数按固定排序与插值规则计算。
3. 实现慢查询采样窗口切分与聚合水位推进：窗口边界只依赖注入的逻辑时钟毫秒值，不得读取系统墙钟，每个采样唯一归属一个窗口；窗口只有在完整提交后才计入模板聚合，跨越边界的采样不得同时计入两个窗口，同一采样序列在任意运行次数下聚合结果逐位一致。
4. 实现执行计划画像构建：对每个模板在样本库上枚举候选访问路径，按当前统计快照估算行数与选择性，与实际采样扫描行数对比得出偏差比与偏差方向；画像结论须记录所依赖的统计快照版本号、候选路径与首个偏差来源，使结论可追溯到具体观测。
5. 实现统计项驱动的依赖追踪与增量失效闭包：建立统计项到索引、索引到查询模板、模板到画像结论的依赖边；提交统计快照刷新补丁时沿依赖边计算受影响闭包，精确标记哪些模板聚合与画像需重算、哪些可安全复用，未受影响模板的结论与追溯信息必须逐字保持不变，失效决策须输出触发来源与被保留项清单。
6. 实现统计快照整体替换与版本变化识别：每次统计补丁提交产生新快照版本并整体替换当前快照指针而非逐条覆盖；收到新快照时比较版本号、生效逻辑时钟、统计项摘要与覆盖表集合，判定完整替换、增量追加或无需操作，版本回退必须被拒绝并返回业务错误码。
7. 实现画像与聚合结论的持久化及强制终止后的恢复：把快照指针、采样水位、模板聚合摘要、依赖图版本、失效事件与画像结论以事务原子写入 SQLite；进程在窗口提交或补丁提交中途被强制终止后，恢复路径识别已提交与半提交步骤，只重放未完成步骤，恢复后结论须与不中断运行逐字段一致。
8. 实现多进程并发一致性与异常链路隔离：允许多个采样处理实例与统计补丁实例并行，通过 SQLite 事务与文件锁保证同一快照版本只提交一次、同一采样序号只被计入一次、同一模板同一快照版本的画像只提交一次，重复提交必须幂等；统计项引用不存在列、采样 SQL 无法归一化、逻辑时钟回拨超容差须映射到不同业务错误码且单个异常不得污染其他模板已提交结论。
