当前是空白工作区，需要从零构建一个面向视频目标跟踪（多目标跟踪）的本地领域数据编辑与操作应用，核心业务问题是跟踪状态的演进与中断后的恢复一致性。业务对象是本地确定性生成的视频跟踪样本：每段序列由固定种子在固定尺寸画布上驱动若干目标做可复现运动，逐帧生成检测框清单（JSONL，字段含 seq_id、frame_index、track_id_true、x1、y1、x2、y2、score、class_id、occluded），并在指定帧区间内人为制造遮挡、目标交叉与短暂消失。系统需完成检测框预处理、相邻帧匹配指派（IoU 与外观确定性特征结合的代价）、轨迹状态机推进（新建、保持、丢失、终结）、轨迹片段补全与指标统计（MOTA、IDF1 类），并输出逐帧轨迹状态与轨迹片段表。核心矛盾在于轨迹状态机跨帧演进必须可持久化，进程被强制终止后重启只能从已提交的检查点继续；而遮挡与交叉导致的状态回退、轨迹片段合并必须在版本演进下保持与不间断完整运行完全一致，不能出现重复轨迹编号或状态跳变。

任务环境与准备：
Windows 本地环境，Python 3.10 及以上，安装 NumPy；不依赖任何外部数据集、账号或网络服务。
准备本地确定性样本生成脚本所需参数：序列数量、帧数、每帧目标数、画布尺寸、随机种子与遮挡帧区间，全部写入本地配置文件。
创建持久化目录用于阶段检查点与按序列的中间产物，确保进程重启后可读取；不预置任何业务代码或数据文件。
准备演示用异常输入：重复 seq_id、跳帧、非法检测框坐标与非法 occluded 取值，作为命令行参数或输入文件注入。

业务要求：
1. 实现确定性的检测框预处理与相邻帧匹配指派：按 seq_id 与帧序推进，用 IoU 与外观确定性特征加权构造代价并做贪心指派，同分时按 track_id_true 升序、再按检测框分数降序打破平局；同一序列同一配置下必须逐字节产出相同指派与代价明细。
2. 实现轨迹状态机推进与状态回退：为每条轨迹维护新建、保持、丢失、终结四态并按命中与未命中帧数迁移，丢失轨迹在重新命中时须走复活路径而非新建；须禁止同一预测轨迹编号在终结后复活，违反时返回 E_TRACK_ILLEGAL 并指明 seq_id 与帧号。
3. 实现逐帧轨迹状态的可持久化检查点：检查点携带单调递增版本号、已完成帧号与内容校验和，只有该帧全部检测框处理与状态迁移结束后才提交；提交顺序与轨迹状态视图必须在持久化存储中原子可见，部分完成的帧不得提交。
4. 实现强制终止后的恢复逻辑：重启时读取最后一次已提交检查点，从下一帧继续推进，已提交帧的轨迹状态与编号分配不得重算或重复；未提交的中间匹配结果必须丢弃并从该帧起点重建，恢复后的逐帧状态与最终轨迹片段表须与不间断完整运行逐字节一致。
5. 实现轨迹片段补全与遮挡处理：对因遮挡造成的丢帧区间按配置的最大补全帧数与速度外推规则做片段补全，补全帧不得覆盖已有真实检测命中的帧；须输出补全区间明细并在评分中把补全帧与真实命中帧区分统计，补全越权或区间重叠返回 E_GAP_INVALID。
6. 实现检测框与跟踪结果标识的版本一致性校验：真值 track_id_true 与预测轨迹编号分离管理，检测框被修正、occluded 标记变化或序列以更高 revision 到达时计算受影响帧与轨迹集合，复用未受影响检查点，仅重算受影响后缀，并禁止复用跨 revision 的编号映射。
7. 实现指标统计与集合一致性自检：由逐帧指派与轨迹片段表计算 MOTA、IDF1 类指标与轨迹切换次数，指标须可由逐帧明细独立重算一致；同时校验每条预测轨迹至少关联一个真值轨迹、终结轨迹不参与后续帧匹配、编号映射无多对多冲突，违反时返回 E_INCONSISTENT 并指出不一致类别。
8. 实现资源上限与异常链路归因，并提供本地可交互应用：为同时驻留的检测框数、外观特征缓存条目与并行补全轨迹数设可配置上限，超限时返回 E_RESOURCE_LIMIT 或按明确策略降级并标记降级类别；对重复 seq_id、帧号不连续、检测框坐标非法、occluded 取值非法分别返回对应业务码并归因到具体序列与帧，应用展示当前帧、轨迹状态分布、检查点版本、恢复报告与最近业务错误码，并允许触发一次演示运行。
