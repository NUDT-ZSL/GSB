为图像修复与风格迁移团队从零构建一个本地可运行的格式互操作与版本兼容工作台。工作区为空，需自行初始化项目。输入是本地样本目录：一份图像清单 JSONL，每条含 image id、宽高、像素格式描述（通道顺序 RGB/BGR、位深 8 或 16、是否含 alpha）、修复区域掩码（行段区间编码）与文件相对路径；一份风格预设文件 JSON，含若干风格预设 id、色调曲线控制点、色彩空间标记 sRGB 或 linear 与版本号；一组本地生成的 PNG 与 NPZ 像素文件作为图像字节来源。团队需要在该工作台中完成修复区域的确定性伪修复、风格预设套用、色彩空间转换与格式导出，并保证不同位深、通道顺序与色彩空间之间迁移的可逆性与可追溯性。核心难点在于：旧版本清单与风格预设需要按版本兼容规则迁移，格式字段必须逐字段比较而不是整体覆盖；修复与风格迁移结果须可逐字节复现，缓存与快照在任何参数或版本变化时整体替换并可定位过期数据。

任务环境与准备：
安装 Python 3.11，并用 pip 安装 fastapi、uvicorn、numpy 与 pytest，均在 Windows 本地虚拟环境中执行。
从未含附件的空白工作区创建项目目录，按题面自行生成图像清单、风格预设、PNG 与 NPZ 样本文件，所有样本均为本地合成数据。
确认 SQLite 使用 Python 标准库 sqlite3，无需外部数据库服务；HTTP 演示使用 127.0.0.1 上的本地端口。
准备固定演示参数与预设版本升级序列，确保可在 Windows 命令行重复执行并比对结果。

业务要求：
1. 清单与预设导入接口须校验每条记录的像素格式描述：通道顺序只能是 RGB 或 BGR，位深只能是 8 或 16，alpha 标记与通道数一致，修复掩码行段不越出宽高；任一项非法返回 E_FORMAT 业务码并指出 image id 与字段名，且不创建输出目录或临时文件。
2. 须实现确定性伪修复渲染器：由 image id、修复掩码与风格预设 id 派生低频噪声并逐像素回填掩码区域，掩码外像素保持原值；同一位深与通道顺序下重复运行结果逐字节一致，渲染器不得依赖系统时间、全局随机状态或字典遍历顺序。
3. 须实现色彩空间转换与位深迁移：sRGB 与 linear 之间按可配置伽马做浮点转换，8 位到 16 位与反向迁移须声明量化与截断策略；迁移前后像素摘要、量化误差与削波样本数须写入结果统计，可无损与有损映射须在清单中显式标记。
4. 风格预设须支持版本兼容判定：按版本号逐字段比较当前预设与旧版预设，只有色调曲线控制点单调性保持、色彩空间标记与位深通道组合可映射时才允许迁移；不可映射字段须返回 E_COMPAT 并列出不兼容字段名与两侧取值，禁止静默丢弃字段。
5. 修复与风格迁移结果须以版本化快照整体替换：快照含配置指纹、逐图像像素摘要与结果文件内容哈希；读取快照时若检测到磁盘文件哈希与数据库记录不一致、配置指纹变化或残留旧版本结果文件，须返回 E_STALE 并定位到 image id 与版本，禁止汇入旧数据。
6. 处理进度须在 SQLite 中以图像粒度事务提交，像素结果文件先写临时文件再原子替换并登记内容哈希；进程被强制终止后重启须核对已提交图像的内容哈希与结果文件，重算未提交图像且不重复处理已提交图像，恢复后像素摘要集合须与无中断执行一致。
7. 须提供交互式 HTTP 接口：创建工程、触发批量修复与风格迁移、查询逐图像处理状态与量化统计、导出快照与兼容判定报告；作业未完成时读取快照返回 E_PENDING，参数非法返回 E_PARAM，错误响应须与正常响应共用同一 JSON 结构并可定位到 image id。
8. 须提供确定性本地演示入口：固定一组覆盖 8 位与 16 位、RGB 与 BGR、含与不含 alpha、sRGB 与 linear 的样本及预设版本升级序列，跑出各图像迁移前后格式、量化误差与削波数、兼容判定结论、实际重算与失效未变计数、快照版本序列的可重复结果，并给出可用等价参数复现的命令示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
本地样本验证格式迁移、版本兼容判定、快照一致性与中断恢复，结果可重复。
