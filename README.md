在空白工作区构建一个面向本地确定性语料的索引构建与倒排压缩工作台，用于小规模搜索场景的索引压缩、检索与交互式验证。输入为本地合成的 JSONL 文档流（每条含文档 ID、标题、正文与来源标签，词项由固定种子程序按可控词表分布生成），一份索引配置（词表路径、文档分片大小、倒排表分块大小、压缩档位、位置信息保留开关、查询并发数与交互延迟预算毫秒）以及一份查询集 JSON（查询词项列表、期望结果数量）。工作台需要完成词项归一化与统计、倒排表构建与分块压缩、文档分片写盘、查询执行与交互延迟观测，并输出可复现的索引产物与检索结果。核心挑战在于：压缩档位与位置信息保留开关会同时改变倒排表的编码格式与查询时的解码路径，而交互查询要求在延迟预算内返回结果，压缩档位切换后已建索引必须被识别为版本失效，增量构建与全量重建的检索结果仍需逐项一致。

任务环境与准备：
确认 Windows 上可用 Python 3.10 及以上版本，安装 NumPy，无需其他外部服务。
准备本地样本生成脚本说明：按固定种子生成 JSONL 文档流与查询集，词表与分布参数写入配置，样本目录与输出目录均为工作区内路径。
运行前清空输出目录与快照目录，确保从空白状态开始；交互延迟预算与并发数取自配置，测量方式为进程内单调时钟。

业务要求：
1. 实现词项归一化与文档解析层：读取 JSONL 文档流，做大小写折叠、全半角折叠与空白合并后切分为词项，统计每文档词频与位置列表；空正文、非法 JSON、文档 ID 重复分别输出 E_EMPTY_DOC、E_PARSE_INVALID、E_DUP_DOC_ID 并进入失败清单，其余文档继续处理。
2. 实现倒排表构建与分块压缩：按配置的分块大小将倒排表切块，压缩档位一为变长整数差值编码，档位二为差值编码叠加低频词过滤，两档位对同一倒排内容必须能逐项无损还原；位置信息保留开关决定是否编码位置列表，关闭时文档 ID 之外的位置相关查询须返回 E_POSITION_UNAVAILABLE。
3. 实现文档分片写盘与索引产物指纹：按分片大小将文档原文与倒排块写入独立分片文件，以临时文件加原子替换方式提交；为整个索引计算由词表指纹、配置指纹、压缩档位、位置开关与全部分片摘要派生的索引版本指纹，产物清单文件记录分片清单与版本指纹。
4. 实现压缩档位切换后的版本失效识别：交互会话中允许切换压缩档位或位置开关，切换后旧索引版本指纹与新配置不符，构建器必须识别失效并仅重建受影响的倒排块与分片，不得静默复用旧格式块；复用与重建的块清单须在结果中逐块列出。
5. 实现交互查询执行与延迟预算观测：接收查询词项列表，按当前压缩档位解码倒排块并做合取检索，返回按文档 ID 升序的结果与命中词项位置摘要（位置开关开启时）；每次查询记录解码块数、解码词项数与耗时，超预算时仍返回已完整解码结果并以 E_BUDGET_EXHAUSTED 标注并附中间状态，不得以线程超时视为终止。
6. 保证增量构建与全量重建的检索一致性：对同一份最终文档流与同一配置，先小批增量构建再查询所得结果，必须与一次性全量重建后查询的结果在文档 ID 顺序、命中词项与位置摘要上逐项一致；比较须在两种压缩档位与两种位置开关组合下分别执行并输出比对摘要。
7. 实现并发查询与串行结果一致性：使用线程池并发执行查询集中的多条查询，最大并发数取自配置；每条查询任务携带由查询序号派生的稳定排序键，无论线程完成顺序如何，最终查询结果顺序、失败清单顺序与延迟统计汇总必须与单线程按序执行逐字段一致。
8. 实现异常链路、可处理退出与验证报告输出：单个文档或查询在解析、构建、压缩、解码任一阶段抛异常时记录标识、阶段名、业务码与异常类型并继续其余项；收到可处理的退出信号时完成当前索引产物原子提交与进度记录后以整数退出码 0 退出，强制终止后仅依据已提交产物与进度记录恢复；最终输出 JSON 报告含索引版本指纹、复用与重建块清单、各查询耗时与预算标注、一致性比对摘要与失败清单。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
