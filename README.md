在空白工作区从零实现一个本地限流熔断与降级裁决组件，用于在确定性样本上复现流量治理决策随数据规模变化而自适应切换算法取舍的过程。样本以本地 JSON 给出：服务拓扑清单（服务名、依赖边、实例列表、优先级）、调用事件流（事件序号、服务名、逻辑时钟毫秒戳、结果标记、耗时毫秒、成本权重）以及治理策略配置（每秒请求上限、令牌桶容量、滑动窗口长度与步长、熔断错误率阈值与半开探测参数、降级级别与降级后允许的请求比例、容差参数）。组件需在可注入逻辑时钟下对事件流做限流裁决、窗口统计、熔断状态机演进与降级决策，并在单窗口事件数超过保留上限时于精确统计与分层摘要之间按明确规则切换，输出每次裁决的决定链与所用算法模式。所有状态需持久化到本地 SQLite，支持强制终止后的恢复。

任务环境与准备：
安装 Python 3.11 及以上版本，确保 sqlite3 与 json 标准库可用。
通过 pip 安装 NumPy 1.26 及以上版本与 pytest，用于数组统计与测试。
准备本地固定 JSON 样本：服务拓扑、事件流、治理策略配置各一份，事件规模覆盖精确统计与分层摘要两种模式。
在空白工作区创建项目目录与 SQLite 数据库文件路径配置，确认所有路径均为本地相对路径。
运行前确认无需外部网络、真实账号或容器环境。

业务要求：
1. 实现拓扑、事件流与治理策略的解析校验：服务名唯一、依赖边两端闭合、事件序号严格递增、逻辑时钟毫秒戳非负、结果标记与耗时字段类型合法、每秒上限与令牌桶容量为正整数、滑动窗口步长不大于窗口长度、降级比例在合法区间；非法输入返回不同业务错误码且不写入任何状态。
2. 实现基于可注入逻辑时钟的令牌桶限流与滑动窗口统计：限流裁决与窗口边界只依赖注入的逻辑时钟，不读取系统墙钟；同一事件序列在任意运行次数下得到逐位一致的裁决序列与窗口归属，逻辑时钟回拨超过容差时返回业务错误码并保持状态不变。
3. 实现熔断状态机演进：依据窗口内错误率与连续失败裁决实例在闭合、打开、半开之间迁移，打开态到期时间与半开允许探测数由策略配置决定；迁移必须依据持久化窗口结论与逻辑时钟裁决，重启后不得凭内存残留决定状态，半开探测结果需精确计入下一轮错误率。
4. 实现数据规模变化下的窗口统计算法取舍：当单窗口原始事件数超过配置保留上限时，在精确统计与分层摘要统计之间按明确规则切换，分层摘要须保留错误率估计与分位数误差上界；每次裁决输出实际使用的统计模式、切换触发依据与误差上界，规模回落后切回精确模式并保证结论不倒退。
5. 实现降级决策与恢复裁决：熔断打开或错误率超阈时按降级级别与允许比例裁决降级放行或全拒，记录决定链中的触发服务、窗口证据与熔断状态；降级解除须依据半开探测成功序列与持久化状态裁决，不得因瞬时窗口波动反复切换，恢复后限流预算需按规则重新计算。
6. 实现持久化状态与强制终止后的恢复：把熔断状态、窗口摘要、统计模式决策、令牌余额、降级状态与事件水位以事务原子写入 SQLite，窗口推进识别版本变化并整体替换当前结果指针；进程被强制终止后恢复路径识别未提交窗口与半提交状态，只补算未完成窗口，不承诺一定生成完整退出报告。
7. 实现多进程并发一致性与幂等裁决：多个裁决实例并行处理同一服务时通过 SQLite 事务与文件锁保证同一窗口同一版本摘要只提交一次、同一事件序号只被计入一次，重复提交相同窗口结果必须幂等；读取方只能看到完整已提交窗口结论而非中间态，统计模式切换不得使同一事件被重复计数。
8. 实现异常链路与可重复命令行诊断：事件结果标记非法、耗时负值、窗口内合法请求数为零、样本摘要不匹配、统计模式切换失败分别映射到不同业务错误码并保留可诊断字段，单条异常事件不得中断其他服务的裁决；提供 load、run、resume、status、explain、verify 子命令，explain 以稳定排序 JSON 输出指定事件的完整决定链与所用模式。
