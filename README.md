在空白工作区从零实现一个本地数据库日志与崩溃恢复组件，用于在确定性样本上复现 WAL 增量回放、检查点链演进与中断恢复。本地样本以目录形式给出：一组按序列号递增的 WAL 段（JSON 行格式，每行含逻辑事务号、表名、行键、操作类型、变更前后镜像、依赖的检查点代数与内容摘要哈希），以及两代检查点文件——v1 为单文件 JSON，记录检查点代数、已应用事务水位与各表行数摘要；v2 为分片 JSON 加 SQLite 元数据库，记录回放代数、绝对提交时刻毫秒戳、各表行版本摘要与脏页映射。此外提供一批待回放的增量事务与回放策略配置（每轮回放并发事务上限、单轮逻辑时间预算、检查点生成间隔与逻辑时钟步进）。组件需加载检查点与增量日志，按事务序验证日志链连续性，把增量应用到本地 SQLite 表上，维护每行版本号与来源事务号，并在检查点整体替换时识别版本变化。核心难点是日志链依赖、并发回放预算与中断恢复三者耦合：任何一处裁决不同都会使回放结果与检查点指针偏离。

任务环境与准备：
Windows 上安装 Python 3.11 及以上版本，并在虚拟环境中安装 numpy 与 pytest（sqlite3 为标准库自带）。
确认工作区为空，创建样本目录，按题目描述手工或脚本生成 WAL 段文件、v1 与 v2 两代检查点文件及回放策略配置 JSON。
确认本地 SQLite 可创建文件数据库，样本目录与 SQLite 文件路径均为可写本地路径。
准备两套样本：一套正常链用于结果一致性验证，一套含断链、摘要不匹配与版本回退用于异常链路验证。

业务要求：
1. 实现 WAL 段与两代检查点的解析校验：逻辑事务号严格递增、操作类型枚举闭合、变更前后镜像与操作类型匹配、依赖的检查点代数存在、内容摘要哈希与行内容一致、v2 分片哈希与回放代数单调；非法行、断链、摘要不匹配与代数缺失分别返回不同业务错误码（如 E_BAD_WAL、E_CHAIN_BREAK、E_SUMMARY_MISMATCH）且不写入任何持久化状态。
2. 实现桩式增量应用语义：按事务序把插入、更新、删除增量真实应用到本地 SQLite 表，维护每行版本号、来源事务号与删除墓碑，使应用结果与从空库全量重放同一 WAL 链得到的结果逐行逐值一致；该一致性必须能通过在样本中注入差异行来验证，而非仅打印比对通过。
3. 实现回放过程的并行调度：在每轮回放并发事务上限与单轮逻辑时间预算双重约束下决定事务组启动顺序；预算耗尽必须放弃剩余未启动事务并记录放弃原因，区分预算内未启动、启动后失败与主动放弃三类结局，已启动事务不得被简单截断为超时。
4. 实现基于可注入逻辑时钟的回放延迟与检查点节奏：所有回放完成时刻、检查点生成间隔与预算判定只依赖注入的逻辑时钟毫秒值，不得读取系统墙钟；v1 相对表示换算为绝对时刻时须记录换算标度与舍入方向，同一逻辑时钟序列下重放须得到逐位一致的结果，逻辑时钟回拨超过容差返回业务错误码并保持状态不变。
5. 实现检查点创建与整体替换的版本变化识别：按当前已应用水位生成新检查点并转换为 v2 格式登记，提交时以临时表加版本号整体替换当前检查点指针而非逐条覆盖；收到新检查点包时比较清单版本号、回放代数下限与各表行版本摘要，判定完整替换、增量追加或无需操作，版本回退必须被拒绝（E_VERSION_ROLLBACK）且旧版本检查点不得被覆盖。
6. 实现强制终止后的恢复裁决：把已应用水位、已提交事务集合、检查点指针、在途事务登记与逻辑时钟水位以事务原子写入 SQLite；进程在回放或检查点提交中途被强制终止后，恢复路径依据持久化状态识别已提交但未更新水位的事务与半应用事务，只重放未完成部分且不得重复应用已提交事务；不承诺强制终止后一定生成退出报告。
7. 实现多进程并发一致性与幂等应用：允许多个回放或恢复实例并行处理同一 WAL 链，通过 SQLite 事务与文件锁保证同一事务号同一版本只被应用一次、同一检查点代数只被提交一次，重复应用同一 WAL 段必须幂等且不改变行版本号与检查点指针；读取方只能看到完整已提交事务的可见结果。
8. 提供可重复命令行接口与证据输出：支持 load、apply、checkpoint、resume、status、verify 子命令，status 以稳定排序 JSON 输出当前水位、检查点代数、已应用事务数与在途事务；verify 校验持久化状态与已应用结果摘要一致并报告不一致处的事务号；使用固定本地样本两次运行输出完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证跨版本回放结果一致性、预算放弃裁决、强制终止后恢复与重复提交幂等，并核对稳定 JSON 输出。
