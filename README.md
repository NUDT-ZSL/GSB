某身份认证团队需要在 Windows 本地空工作区为自研授权服务器落地一个离线裁决组件，业务对象是带设备绑定的多因子登录过程：固定种子脚本在本地生成用户凭据声明（用户标识、盐、口令摘要档位与迭代参数）、设备指纹声明（设备标识、平台、指纹分量的整数定点值时序）、已绑定因子清单（TOTP、WEBAUTHN、PUSH 三类因子的标识与共享密钥占位摘要）以及按注入逻辑时钟到达的登录尝试流与两份口径不同的策略快照——v1 为单文件 JSON，记录相对过期秒、扁平因子要求与无绑定声明；v2 为分片 JSON 加 SQLite 元数据库，记录绝对毫秒时间戳、设备绑定的规范指纹键、策略代数与墓碑标记。组件须把两代策略与设备声明合并为统一授权视图，对每次登录尝试做出裁决并写入可追溯账本，还要在凭据档位迁移与设备绑定吊销后正确传播失效。全部输入输出与时刻判定都以本地样本内声明的观测时钟为唯一真值来源，不依赖真实账号、外部 IdP 或网络。

任务环境与准备：
安装 Python 3.11 或更高版本，确认 python 与 pip 在 PATH 中可用。
执行 pip install pytest 安装测试依赖，SQLite 使用 Python 标准库 sqlite3，无需额外安装。
在空工作区创建项目目录，将固定种子样本生成脚本与样本生成参数一并纳入工作区，运行生成脚本产出本地样本与真值文件。
确认工作目录可写，并在运行前清空或新建状态目录，避免旧检查点影响恢复验证。

业务要求：
1. 实现用户凭据、设备指纹、因子清单与两代策略快照的严格解析规范化层：校验用户与因子标识唯一性、平台取值白名单、指纹分量为非负整数、口令摘要档位与迭代参数为正整数且档位在白名单内、v1 相对过期秒为非负整数、v2 绝对毫秒与策略代数为非负整数；非法记录须输出含来源声明类别与记录序号及稳定业务码的拒绝记录并继续处理其余记录。
2. 把两代策略与设备声明合并为统一授权视图：v1 的相对过期秒须以样本声明的观测时钟为唯一基准换算为绝对毫秒，禁止使用系统当前时间；同一规范策略键按策略代数与生效时刻裁决权威来源，墓碑标记必须覆盖较早的非墓碑记录；两代对同一策略的因子要求、绑定要求或过期时刻给出不一致结论时须单列 E_POLICY_CONFLICT 并保留两侧依据。
3. 实现设备指纹的定点可比化与绑定校验：按各平台声明的小数位数把指纹分量对齐到统一规范指纹空间，输出规范指纹键与对齐引入的误差界；对齐后误差界跨越同一比较阈值时不得判定为同一设备，须单列 E_FINGERPRINT_AMBIGUOUS；绑定不符返回 E_DEVICE_MISMATCH 并给出两侧规范指纹键与依据代数。
4. 实现多因子登录裁决：一次尝试须同时通过绑定设备校验、因子清单命中与口令摘要档位满足当前生效策略三项条件；因子按 TOTP、WEBAUTHN、PUSH 分派校验逻辑，缺因子、因子类型与策略要求不匹配、摘要档位低于策略下限分别给出独立业务码；全部时刻比较只依据观测时钟。
5. 实现凭据档位迁移与设备绑定吊销后的失效传播：策略代数升级使摘要档位或迭代下限提高、设备绑定被墓碑化、因子被解绑时，须沿用户到设备到因子到会话的依赖边计算传递失效闭包，遇到因子依赖环或设备绑定链环返回 E_BIND_CYCLE 并列出环中规范键；失效闭包结论必须与声明到达顺序无关且重判结果与从零全量重判逐条一致。
6. 在 SQLite 中维护裁决账本并支持增量策略批次：以用户标识与尝试序号为主键记录裁决结论、依据策略代数、规范指纹键与判定水位，每轮裁决在单事务内推进，前置校验失败不得改动账本任何状态；账本格局版本（因子类型白名单或绑定口径版本）变化时须整体重建而非增量续接，并识别快照版本变化以拒绝混用旧结论。
7. 实现检查点演进与强制终止后的恢复边界：按已处理批次水位与账本摘要把检查点持久化到 SQLite 与本地快照文件，恢复时只从最后一个完整检查点继续并重放比对账本一致性以识别半写残留；进程被强制终止后不承诺生成退出报告；检查点与裁决报告均先写临时文件，校验内容可解析后整体重命名替换。
8. 交付可交互命令行与基于同步标记的确定性验证：提供导入、登录裁决、吊销传播、导出诊断报告、校验检查点五类子命令，报告为可解析 JSON 并含尝试级结论、业务码、规范指纹键、误差界与失效闭包；单份声明解析失败不得中断同批其他声明，并发度变化下结论与串行完全一致，退出码区分全部成功、部分失败与参数错误。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
