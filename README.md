当前是空白工作区，需要从零构建一个面向本地搜索与推荐前链路的倒排索引数据处理管线与结果验证工具。业务对象是本地确定性生成的文档集合与查询集合：文档为 JSONL，字段含 doc_id、terms 列表（含 term 与词频）、doc_len；查询为 JSONL，字段含 query_id、terms 列表与 top_k。管线需要把文档集合构建为倒排索引，对每个 term 的倒排表（posting 列表，含 doc_id 与词频）实施分块与压缩存储，并在压缩索引上完成 BM25 类打分与 top-k 检索。核心业务矛盾是交互延迟与计算结果一致性：分块大小、压缩编码与是否预先解码单个分块的取舍，会同时影响查询延迟和打分结果是否与未压缩基线逐值一致。索引构建还须支持可持久化快照、并发查询与构建之间的版本切换、资源预算准入以及异常输入的归因。所有样本在本地生成，不依赖外部服务与网络。

任务环境与准备：
安装 Python 3.11 或以上版本，使用其标准库 json、hashlib、struct 与 pathlib 完成序列化与校验和计算。
安装 NumPy（建议 1.26 及以上）用于本地确定性样本生成与基线分数计算。
在空工作区创建项目目录，运行前用固定种子生成文档与查询样本 JSONL 以及读取配置，样本全部本地生成，不下载外部数据集。
确认本地进程池与文件写入权限可用，准备临时缓存目录用于分块压缩与快照存放。

业务要求：
1. 实现确定性的倒排索引构建：从文档 JSONL 按 doc_id 升序、term 字典序排出每个 term 的倒排表，记录词频与文档长度统计，生成词项字典与文档总数、平均文档长度等打分统计量；同一输入与配置下必须产出逐字节一致的倒排表与统计量，并校验 doc_id 唯一、词频为正、doc_len 与词频求和自洽，违反时返回 E_DOC_INVALID 并归因到具体 doc_id。
2. 实现倒排表分块与压缩编码：按可配置的每块 posting 数量把每个倒排表切成分块，采用差分编码加变长整数编码压缩 doc_id 与词频，块头记录块内条数、首 doc_id 与压缩字节长度；须保证任意倒排表解压后与构建阶段的原始 posting 序列逐项相等，否则返回 E_DECODE_MISMATCH 并指出 term 与块编号。
3. 实现压缩索引上的打分与 top-k 检索：查询时按查询词项定位倒排表，逐块解码参与 BM25 类打分，输出含 doc_id、分数、命中词项的 top-k；分数必须与在未压缩原始倒排表上计算的基线分数在给定数值容差内一致，同分按 doc_id 升序打破平局，禁止用近似打分或跳块剪枝改变结果集合。
4. 实现查询延迟预算与分块策略的取舍控制：为单次查询设置可配置的延迟预算，在预算内选择块大小与是否缓存解码后分块；超预算时按明确策略返回 E_LATENCY_BUDGET 并附带已完成阶段与已解码块数，禁止用人为延时或未完成的近似结果冒充完成；预算内的策略选择必须在查询报告里落盘成可复现依据。
5. 实现索引快照的版本化与整体替换：索引快照携带单调递增版本号与内容校验和，构建提交时整体替换旧快照而非增量修补；检测到版本号或校验和变化时查询侧必须切换到新快照，损坏或校验和不符的快照在加载时返回 E_SNAPSHOT_CORRUPT 并指出 term 或块编号，禁止使用部分可解析的损坏数据继续服务。
6. 实现并发查询与构建的原子切换：多个查询可并发执行，构建提交与快照切换须原子生效，查询侧不得读到半构建的倒排表或新旧混合的统计量；同一时刻只允许一个构建提交生效，并发提交冲突时后到者立即获得 E_BUILD_BUSY 而不阻塞等待，已完成快照不能被旧版本回退覆盖。
7. 实现资源预算准入与异常链路归因：为倒排表总 posting 数、解码后驻留内存与缓存分块条目数设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或降级到流式逐块解码并标记降级类别；查询词项不在字典、压缩字节截断、块头与块内条数不符等异常须沿链路归因到构建或查询阶段并返回对应业务码。
8. 实现结果验证工具与一致性自检：独立复核每个 term 的分块解压结果、任意查询的基线分数与压缩索引分数可重算一致、top-k 集合与分数顺序合法、快照中统计量与逐表明细可核对；检测到偏差返回 E_VERIFY_FAIL 并输出首个偏差位置，另提供命令行演示加载本地生成样本并注入一次超预算与一次损坏快照场景。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证分块压缩后检索结果与基线逐值一致，并覆盖预算拒绝、快照损坏与并发构建冲突。
