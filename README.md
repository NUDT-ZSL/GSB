需要为一个面向 LLM 预训练的数据工程团队构建本地可运行的数据配比与去重流水线原型。输入是多个本地 JSONL 数据分片，每个分片包含若干条样本，样本字段至少有 id、source、text、token_count，text 在分片内可能存在近似重复。团队需要按来源配额完成采样与近重复去除，并记录整个处理过程的状态，以便在多阶段任务中断后能从持久化检查点继续，且不重复消费已提交的数据。工作区为空，需要从零创建项目：一个可交互的 FastAPI 服务，提供作业创建、分阶段执行、快照查询与恢复的 HTTP 接口；一个核心流水线模块，负责分片解析、去重、配额采样与快照生成；一个状态存储模块，使用 SQLite 记录作业、阶段和分片提交进度。所有行为必须在 Windows 本机通过确定性本地样本验证，不依赖外部模型、网络或真实数据集。

任务环境与准备：
安装 Python 3.11 及以上版本，创建虚拟环境并使用 pip 安装 fastapi、uvicorn、numpy、pytest 与 httpx。
在工作区准备固定本地 JSONL 分片样本，包含多个来源、可构造近重复文本和 token_count 字段，样本内容需确定且可重复。
确认 SQLite 由 Python 标准库提供，运行时无需外部数据库、网络或模型下载。
在 Windows 下准备可直接调用的 curl 示例或 pytest 用例，用于重复演示与恢复验证。

业务要求：
1. 作业创建接口接收分片列表、按来源的目标 token 配额和一个去重相似度阈值，校验分片存在与字段完整，非法参数返回 E_PARAM 或 E_INPUT 业务码且不写入任何阶段状态。
2. 核心去重阶段必须对每条样本的文本做规范化后计算指纹，相似度达到阈值的样本进入同一去重簇，每簇保留 token_count 最大者，并列时按 id 字典序稳定选择，输出结果需可重复。
3. 配额采样必须按来源分别消费已去重样本，在不超过目标 token 配额的前提下尽量贴近，若某来源去重后不足配额则记录短缺并继续其他来源，不得因单来源短缺整体失败。
4. 状态存储须以作业、阶段、分片三级记录提交进度，分片内样本处理与分片进度提交必须在同一 SQLite 事务中完成，中途失败的分片不得留下部分提交。
5. 服务须支持分阶段执行；重复调用已完成的阶段返回幂等结果并给出当前快照版本，阶段执行顺序不可跳步，乱序请求返回 E_STAGE 业务码。
6. 每次阶段完成生成整体替换的版本化快照，快照包含作业版本号和样本摘要；读取快照时若检测到版本与状态库不一致必须返回 E_STALE 而非返回旧数据。
7. 恢复接口须在进程被强制终止后从 SQLite 已提交进度继续，核对每个分片的处理标记与快照版本，重新执行未提交分片且不重复消费已提交样本，恢复结果须与无中断执行一致。
8. 提供确定性本地演示入口，使用固定输入与阈值跑出包含去重簇数量、各来源采样量与短缺量、快照版本序列的可重复结果，并给出可用 curl 复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证去重、配额采样、版本快照、乱序与非法输入返回约定业务码，并验证强制终止后恢复结果与无中断执行一致。
