当前是空白工作区，需要从零构建一个面向依存句法分析前链路的本地应用。输入为本地确定性生成的分词句子集（JSONL，字段含 sent_id、tokens 列表，每个 token 含 id、word、pos、head_gold、deprel_gold），以及随附的 head 候选生成配置与评分权重表；系统需为每个 token 生成候选 head 弧（含虚拟根 ROOT），按 token 对之间的方向与距离特征打分，再在预算约束下并行完成句子的弧候选评分与最优弧选择，输出每个 token 的预测 head、deprel 与分数，并用 head_gold 做无环与单根约束下的准确率统计。业务关注点是并行调度与资源预算：弧候选数随句长平方增长，必须按预算裁决准入、按 worker 并行分批、在总比较次数与内存上限内归并出确定性结果，同时保证同一输入同一配置下逐字节可复现，并给出预算触发与降级报告。

任务环境与准备：
安装 Python 3.11 与 NumPy，确认可在本地创建多进程进程池；无需外部服务、账号或网络资源。
在工作区准备本地确定性样本生成脚本，产出 JSONL 句子集与评分权重表，生成参数与随机种子固定。
确认工作区可写本地调度报告与快照文件，并预留运行演示所需的临时目录。

业务要求：
1. 实现确定性的 head 候选生成与弧打分：对每个 token 生成其左侧与右侧的候选 head 及 ROOT 候选，按词性与距离特征表计算弧分数，同分时按候选 head 的 id 升序打破平局；同一输入同一配置下必须产出逐字节一致的候选集与分数，句子含非法 token id 引用时返回 E_TOKEN_REF 并指明 sent_id 与 token id。
2. 实现单根与无环约束下的最优弧选择：基于打分结果做整句最优指派，保证每个 token 恰有一个 head、整句恰好一个根、不产生环，输出预测 head、deprel 与确认分数；检测到预测结果违反约束时返回 E_TREE_INVALID 并指出 sent_id 与 token id。
3. 实现并行调度层：按可配置的 worker 数与每批句子数将句子分块交给本地进程池执行弧评分，分块边界与归并顺序必须确定性可复现；worker 内异常须以结构化业务码与阶段名回传主进程并归因到具体 sent_id，禁止因单个句子失败而静默丢弃结果。
4. 实现弧比较次数与内存双预算准入：按句长估算每句候选弧数与比较代价，在总比较预算与剩余驻留内存内做准入裁决；超预算时按明确策略拒绝返回 E_BUDGET_EXCEEDED 或降级到仅保留距离不超过阈值的受限候选模式，降级必须在结果中标记降级类别与被裁剪的候选规模。
5. 实现预算冲突裁决：当并行度提高可缩短整体耗时但会放大驻留内存、裁剪候选可满足内存但会降低候选召回时，须按显式优先级规则在精度、内存、进度之间裁决，并在调度报告中记录裁决依据与各句子所走的路径，裁决结果必须可复现。
6. 实现准确率统计与集合一致性自检：由预测 head 与 head_gold 计算整体与按 deprel 的准确率，并校验任一 token 的预测 head 与确认分数可核对、受限模式句子的准确率单独标记；检测到预测集与输入句集不一致或重复句返回 E_INCONSISTENT 并指出不一致类别。
7. 实现配置与输入校验链路：重复 sent_id、token id 非连续、pos 标签不在受控集合内、权重表缺特征项、worker 数与预算参数非法分别返回 E_CONFIG_INVALID 或对应样本级业务码并指明字段与位置，非法输入不得进入并行调度阶段。
8. 提供一个本地可交互应用：展示句子列表、候选弧分数、预测 head 与 deprel、准确率统计、当前调度批次、预算消耗与最近业务错误码，并允许触发一次演示运行；演示用本地生成样本并注入一次超预算与一次非法输入，不依赖外部服务或在线模型。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
