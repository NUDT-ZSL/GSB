当前是空白工作区，需要从零实现一个本地基础设施配置的派生量误差账本引擎，用于在确定性样本上复现多层数值参数沿依赖链合成时的舍入账本登记、派生量真值对照与失效重算过程。本地 JSON 样本给出：服务拓扑清单（服务名、依赖上游服务名、参数来源层）、每层数值参数（超时毫秒、重试倍率、采样率、容量上限、权重），以及账本配置（每项参数的定点标度、误差上界预算、比对容差、逻辑时钟步进、并发诊断上限）。引擎不以判定配置是否一致为主目标，而是为每个派生量维护一份逐项舍入账本：每次定点换算与乘加都要登记被舍弃的余量、舍入方向与累计误差，再把账本合成结果与以高精度小数逐项全量重算得到的一份真值逐项对照，凡是两者在容差内无法区分的派生量都必须标为账本敏感并给出可追溯的登记条目链，进程被强制终止后依据持久化账本恢复未完成的登记与对照。

任务环境与准备：
安装 Python 3.10 及以上版本，确认 numpy 与 sqlite3（标准库）、decimal（标准库）可用，无需外部服务或网络。
在工作区创建固定本地样本：拓扑与分层参数 JSON、账本配置 JSON、若干参数补丁 JSON，样本内容与随机种子固化为文件。
确认样本目录与 SQLite 账本文件路径在诊断运行前按约定准备，运行脚本仅依赖上述本地文件。
准备两次运行的对照输出目录，用于比对各子命令 JSON 输出是否逐位一致。

业务要求：
1. 实现拓扑与参数的解析校验：读取本地 JSON 拓扑与每层数值参数，校验服务名唯一、依赖上游存在且无自环、超时与容量为正整数、采样率在开区间内、权重有限非负、定点标度与误差上界预算合法，构建依赖有向图并检测环；非法输入必须返回明确业务错误码（如 E_BAD_TOPOLOGY、E_CYCLE、E_BAD_SCALE）且不写入任何持久化状态。
2. 实现定点换算的舍入账本登记：把超时毫秒、重试倍率、采样率、容量与权重各自按声明标度换算为定点整数，每次换算须登记被舍弃的余量、舍入方向与本次登记的序号，未满一个定点单位的余量必须逐参数保留并在下次换算时并入，不得丢弃，使同一参数重复换算得到逐位相同的定点值与完全相同的登记序列。
3. 实现沿依赖边的派生量合成与真值对照：按拓扑序计算最坏链路超时、有效容量与加权采样率，定点合成路径与基于 decimal 高精度全量重算的真值路径同时运行，每个派生量输出两条路径的数值、绝对偏差与相对偏差；定点路径的运算顺序与余量并入位置固定，真值路径的精度与舍入模式显式声明，使同一输入重复运行两路径结果均逐位可复现。
4. 实现舍入账本到派生量的误差归因：对每个派生量累计其换算与乘加登记的误差上界，输出误差来源链，链中须含参与参数名、登记序号、该登记的余量与舍入方向、以及在合成中的权重位置；当某派生量的绝对偏差超过其误差上界时须判定账本记录存在缺陷并给出首个无法解释偏差的登记条目。
5. 实现账本敏感标记与结论可复现：当两个服务或两个派生量的差值小于比对容差且二者大小关系依赖该差值时标记为账本敏感，输出参与比较的派生量、各自偏差、误差上界与若改用更高标度是否会翻转大小关系；该标记必须能由持久化账本与真值对照记录重新推导出逐字段相同的结论。
6. 实现参数补丁的失效账本登记与复用裁决：某层参数被修改或删除时以补丁提交，沿依赖边计算受影响闭包，精确标记哪些派生量、误差来源链与账本敏感标记需要重算、哪些可安全复用；未受影响服务的派生量、偏差与来源链必须逐字段保持不变，失效决策须记录触发来源参数与被复用条目的登记序号。
7. 实现持久化账本与强制终止后的恢复：把诊断轮次、舍入登记序列、派生量、偏差、误差来源链、敏感标记与逻辑时钟水位以事务原子写入 SQLite，每轮提交识别版本变化并整体替换当前结果指针；进程在登记或对照中途被强制终止后，恢复路径依据持久化账本识别已提交服务与半提交登记，只补算缺失登记且不得重复登记同一换算或回退已提交结论。
8. 实现多进程并发一致性与可重复命令行：多个诊断实例并行处理同一批服务时，通过 SQLite 事务与文件锁保证同一服务同一轮次同一版本只提交一次、同一参数登记的序号不被并发重复分配，重复提交相同补丁或相同对照结论必须幂等；提供 load、diagnose、resume、status、verify 子命令，status 以稳定排序 JSON 输出各服务派生量、偏差、误差上界与敏感标记，verify 校验账本与真值对照记录一致，使用固定本地样本两次运行结果完全一致。
