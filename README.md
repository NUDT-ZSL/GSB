某安全团队需要在离线 Windows 工作站上评估自研二进制报文解析器在数值精度与误差传播方面的安全风险。目标格式 NBP（Numeric Binary Protocol）报文由 16 字节头与若干定长/变长字段组成：头部含魔数 b'NBP1'、版本 uint16 小端、字段数量 uint32 小端、头部声明的浮点精度模式 uint8（0 为 float32、1 为 float64、2 为十进制定点）、定点小数位数 uint8、保留区 6 字节；随后每个字段记录字段标识 uint16、类型 uint8（0 为整型、1 为浮点、2 为定点、3 为嵌套 NBP）、声明长度 uint32 与载荷。报文在发送端与接收端之间可能经历多次精度转换与序列化往返，攻击者可构造极端指数、非规格化数、超出定点位数、累积舍入偏差与精度模式声明不一致的报文，诱导下游系统产生越界、溢出或结论偏差。工作区为空，无现成代码、样本与依赖，全部解析、生成与验证在本地完成，不依赖网络、账号或外部数据。

任务环境与准备：
在空白工作区初始化项目目录，创建 Python 虚拟环境并安装 Python 3.11 及以上版本解释器。
通过本地包索引或离线 wheel 安装 numpy 与 pytest，确认安装版本可导入，不访问网络资源。
准备本地确定性样本生成脚本入口与 pytest 配置文件，确保样本目录、报告目录位于工作区内且可写。
确认 Windows 环境具备文件重命名与临时文件写入权限，用于验证报告与快照的原子替换行为。

业务要求：
1. 实现 NBP 报文的严格头部与字段解析，校验魔数、版本白名单（仅 1 与 2）、精度模式取值 0 至 2、定点小数位数上限 18、字段数量与头部长度自洽，并对每个字段的偏移加声明长度是否溢出 64 位整型、是否落在文件实际范围内做边界校验，违规时返回一致命名的 E_HEADER 或 E_BOUNDS 业务码并携带出错偏移。
2. 实现浮点与定点数值的规范化解码层，将 float32、float64 与十进制定点统一表示为可精确比较的观测向量（原始位型、规范值、相对误差界），对 NaN、正负无穷、非规格化数与负零分别给出明确分类标记而不得静默折算，未知类型编号须返回 E_TYPE 作为可报告错误。
3. 在规范化层上实现精度误差传播估计，对每个字段给出由解码到目标精度模式转换的舍入误差上界与累计误差界，误差界需依据 IEEE 754 舍入规则与定点小数位数推导，必须以报文内声明的精度模式为观测依据，跨多个嵌套 NBP 层级时按层级合成误差界，不得从缺失字段推断误差。
4. 检测精度模式声明与实际载荷位型不一致的报文，例如声明 float32 但载荷使用 float64 位宽、声明定点但小数位数与载荷比例因子冲突、头部精度模式与嵌套子报文精度模式不匹配，分别返回 E_PRECISION、E_SCALE、E_MISMATCH 业务码并给出字段路径与冲突依据。
5. 实现嵌套 NBP 的递归解析并限制最大递归深度为 6 层，超过返回 E_DEPTH；检测嵌套载荷对父报文字段区段的自引用与环状引用并返回 E_CYCLE。递归过程中累计展开字节数须受可配置配额约束，超限返回 E_QUOTA，且配额按实际解出的字节计量而非声明长度。
6. 实现基于观测与同步标记的真值校验机制：提供本地确定性样本生成器，样本内显式记录每个数值字段的发送端原始位型与同步标记，验证端只依据这些标记与规范化向量比较，不得使用样本生成器的中间计算结果作为真值；误差判定阈值须以误差界为唯一依据并允许配置宽严档位。
7. 实现结构化检测报告的原子写出与拒绝处理：报告为可解析 JSON，含文件级结论、每字段状态、业务错误码、出错偏移与累计误差界；报告先写临时文件再整体替换；单文件解析失败不得中断同批目录处理，退出码区分全部通过、部分失败、参数错误三种情形，业务错误码同时写入 JSON 与 stderr。
8. 提供覆盖极端指数、非规格化数、负零、精度声明冲突、定点越界、深层嵌套、环状引用与配额超限的确定性畸形样本与 pytest 测试集，测试须断言业务错误码、出错偏移、误差界方向与退出码，并验证输入样本在检测前后未被修改；异常场景通过注入参数触发，不得改动解析源码制造失败。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
