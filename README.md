交付负责人把首版目标定为一个可运行的容量评估诊断引擎，当前 WSL Ubuntu 工作区里没有任何历史代码或样本，需要从零搭建算法实现与可复现实验环境。全部输入由随工程交付的固定种子脚本确定性生成：容量评估场景声明服务清单（服务名、实例 ID、服务等级、期望请求速率）、请求轨迹流（每条记录含请求序号、服务名、实例 ID、注入逻辑时钟毫秒戳、耗时毫秒、成功标记、丢弃标记）、容量指标定义（CPU 利用率、内存占用率、请求延迟 P95、吞吐达标率的换算参数与定点标度）以及两代容量阈值快照（v1 为单文件 JSON，记录相对生效秒数与扁平阈值映射；v2 为分片 JSON 加 SQLite 元数据库，记录绝对生效毫秒、阈值代数与失效墓碑）。引擎需在注入逻辑时钟下按滑动窗口聚合请求轨迹，把各容量指标换算为受控定点值，沿计算链记录每次换算与乘加运算的误差上界，并与高精度全量重算的真值对照；当两代阈值快照并存时，须按逻辑时钟与阈值代数合并为统一视图，识别阈值变化导致的评估结论失效并重算；核心矛盾是：容量预估依赖的定点余量保留与误差传播必须在多次窗口推进和阈值快照替换后仍然可追溯、可恢复，且任何精度敏感判定都不得因舍入而翻转。

任务环境与准备：
在 Linux（WSL Ubuntu）安装 Python 3.10 及以上版本，命令：sudo apt update && sudo apt install python3 python3-pip。
安装 Python 依赖：pip install numpy。
确保可用磁盘空间至少 500MB，用于本地样本生成、SQLite 状态与日志输出。
准备一个空工作区目录，所有样本由随题交付的固定种子脚本生成，无需外部网络或真实服务。

业务要求：
1. 实现容量场景、请求轨迹流、容量指标定义与两代阈值快照的解析校验：服务名与实例 ID 唯一，请求序号在实例内严格递增且逻辑时钟毫秒戳非负，耗时与吞吐相关字段为正整数或非负小数，指标定义的定点标度为正整数且阈值快照引用的指标名称闭合，v1 相对生效秒数为非负整数，v2 分片哈希与阈值代数单调，非法条目须返回明确业务错误码且不污染其他实例的聚合状态。
2. 在注入逻辑时钟下实现滑动窗口切分与请求归属：窗口长度与步长取自容量指标定义，每个请求必须唯一归属一个窗口且不得重复计入，窗口边界只依据注入的逻辑时钟毫秒值推进，不读取系统墙钟；同一轨迹在任意运行次数下得到逐位一致的窗口划分与请求计数，窗口推进时把已提交窗口摘要与逻辑时钟水位以事务原子写入 SQLite。
3. 实现容量指标的受控定点换算与余量保留：把 CPU 利用率、内存占用率、请求延迟 P95 与吞吐达标率按各自定点标度换算为整数，每次除法与乘法换算登记被舍弃余量、舍入方向与登记序号，未满一个定点单位的余量须按指标分别保留并参与后续窗口聚合，使相同输入重复计算得到相同定点值，并以 SQLite 表保存每窗口的余量账本。
4. 为每个容量指标的派生值累计误差上界并输出来源链：沿换算登记序号与乘加顺序累计误差上界，输出包含窗口号、参与请求区间、换算标度与余量的误差来源链；当两个服务或两个实例的同一指标差值小于给定容差且容量评估结论依赖该差值时标记为精度敏感，并记录若改用更高标度是否会翻转结论。
5. 实现基于高精度全量重算的真值对照：以 decimal 高精度按同一窗口与同一运算顺序重新计算各容量指标，与定点通路逐一逐值比对，输出两通路数值、绝对偏差与相对偏差；偏差超过误差上界预算的窗口须返回 E_PRECISION_BUDGET 并保留影响该窗口的换算登记序号列表。
6. 实现两代阈值快照的跨版本合并与统一阈值视图构建：同一服务同一指标在 v1 与 v2 同时存在时依据声明的逻辑时钟与阈值代数裁决最新版本，逻辑时钟相同按来源格式优先级裁决；v1 相对秒数换算为绝对毫秒时记录换算标度与舍入方向，合并后每个阈值条目保留来源版本、原始时间表示与裁决依据，并拒绝版本回退。
7. 在阈值快照变更或指标参数调整时沿依赖边计算失效闭包并重算受影响的评估结论：被修改阈值、指标换算参数或窗口划分规则改动时，精确标记哪些窗口容量值、误差账本与精度敏感标记需要重算、哪些可安全复用；未受影响的窗口结论必须保持与全量重算一致，重算动作以事务提交并识别版本变化。
8. 实现强制终止后的恢复一致性与多进程并发控制：进程在窗口聚合、定点换算或阈值替换中途被 SIGKILL 后，恢复路径依据 SQLite 持久化状态识别已提交窗口与半提交账本，只重放缺失窗口并保证余量账本与误差来源链不重复累计；允许多个评估实例并行处理不同服务，通过事务与文件锁保证同一窗口同一版本只提交一次、同一阈值快照只被整体替换一次，并提供可重复命令行接口。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
