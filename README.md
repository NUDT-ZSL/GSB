存储团队准备在本地空目录落地一个冷热分层存储的迁移裁决组件，代码与样本均未动工。所有输入由随题交付的固定种子脚本确定性生成：对象清单记录对象键、字节大小、最近访问逻辑时钟、访问计数、热度权重、声明层与内容摘要；分层配置记录热层与冷层容量上限、每轮迁移字节预算、迁移并发上限、冷热阈值与退避参数；迁移策略以两代格式并存，v1 为单文件 JSON 记录相对生效秒数与扁平映射，v2 为分片 JSON 加 SQLite 元数据库记录绝对生效毫秒、策略代数与失效墓碑。组件需在可注入逻辑时钟下判定对象目标层级，计算迁移代价的定点账本，在容量与预算约束下调度迁移批次，并保证策略版本切换、强制终止恢复与多进程并发下的裁决一致。

任务环境与准备：
在本地工作区创建项目目录，Python 3.10 及以上环境，安装 numpy 与标准库 sqlite3、hashlib、json。
编写并运行固定种子样本生成脚本，生成对象清单、分层配置、两代迁移策略与迁移事件的本地 JSON 文件及 SQLite 元数据库。

业务要求：
1. 实现对象清单、分层配置与迁移事件的解析校验：对象键唯一且内容摘要与字节数一致，访问计数与逻辑时钟非负，分层配置中热层与冷层容量上限、迁移字节预算和并发上限为正整数，冷热阈值在合法区间，迁移事件序号单调，引用对象存在。
2. 跨版本合并两代迁移策略：同一策略键在 v1 与 v2 同时存在时，依据声明的逻辑时钟与策略代数裁决最新版本，逻辑时钟相同则按来源格式优先级，合并后保留来源版本、原始时间表示与裁决依据，v1 相对秒数在注入逻辑时钟下换算为绝对毫秒并记录舍入方向与余量。
3. 在可注入逻辑时钟下计算对象热度得分与目标层级：热度得分按固定顺序结合最近访问逻辑时钟、访问计数与权重，目标层级根据冷热阈值判定，相同输入在任意运行次数得到逐位一致结果，逻辑时钟回拨超过容差须返回独立业务错误码。
4. 为每个迁移候选维护定点迁移代价账本：将对象字节数按声明定点标度换算为迁移耗时或带宽消耗，记录标度、舍入方向与换算前原始值，每次加法与乘法累计误差上界，当两个候选的代价差小于容差且调度裁决依赖该差值时标记为精度敏感并输出误差来源链。
5. 在热层与冷层容量上限、每轮迁移字节预算与迁移并发上限三重约束下调度迁移批次：并发执行迁移任务，预算或容量不足时放弃剩余候选并区分预算内未启动、启动后失败与主动放弃三类结局，迁移成功须原子更新对象层级与两层容量账目。
6. 将迁移策略版本快照以临时表加版本号整体替换当前指针：收到新策略包时比较清单版本号、策略代数下限、分片哈希与对象集合摘要，判定完整替换、增量追加或无需操作，版本回退必须拒绝并返回业务错误码，进行中的迁移任务绑定开始时的策略版本直至结束。
7. 实现强制终止后的恢复一致性：把已提交迁移水位、对象层级、容量账目、迁移代价账本与逻辑时钟水位以事务原子写入 SQLite，进程在调度或迁移中途被强制终止后，恢复路径识别半提交或未提交迁移并重放，不重复扣减容量或推进水位。
8. 实现多进程并发一致性与可重复诊断命令：多个迁移实例并行处理不同对象时，通过 SQLite 事务与文件锁保证同一对象同一轮次同一版本只被迁移一次、两层容量账本不被并发超扣、重复提交幂等；提供 load、merge、judge、migrate、resume、status、verify 子命令。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
