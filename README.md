当前是空白工作区，需要从零实现一个本地对象存储分片与元数据管理组件，交付可集成的领域库与完整示例。样本由本地 JSON 给出：对象清单（对象键、分片序号、分片字节内容、分片大小、内容版本号）、桶与元数据声明（桶名、一致性级别、元数据键值对、逻辑时钟毫秒戳），以及存储配置（分片大小上限、元数据缓存条目上限、单次读取延迟预算毫秒、定点标度、比对容差、误差上界预算、逻辑时钟步进）。组件需把对象按分片写入本地内容寻址的分片目录并原子落盘，在 SQLite 中登记元数据与分片清单，支持整读与范围读，并在读取路径中给出延迟计量。本题的核心业务问题不是分片读写本身，而是：分片大小、缓存占用与读取延迟均为换算得到的数值，必须在受控定点表示下参与装配、逐出与预算比较，诊断出换算舍入与累计误差如何翻转“是否满足延迟预算”“缓存条目该淘汰谁”这类边界结论。

任务环境与准备：
确认 Windows 上 Python 3.11 及以上可用，并预先安装 numpy 本地依赖
准备本地 JSON 样本目录：对象清单、桶与元数据声明、存储配置，不含真实对象存储账号或网络资源
在空白工作区创建项目目录与 SQLite 数据库文件占位，运行前无需启动任何外部服务
执行测试时使用本地临时目录作为分片目录与缓存目录，验证前清空该目录以保证可重复

业务要求：
1. 实现对象清单、桶与元数据声明及存储配置的解析校验：校验对象键与桶名格式合法、分片序号从零开始且连续、分片字节内容与其摘要一致、分片大小为正整数且不超过配置上限、元数据键值类型合法、定点标度与容差为正；非法输入必须返回明确业务错误码 E_BAD_SAMPLE 且不写入任何持久化状态。
2. 实现内容寻址的分片原子落盘：每分片按 SHA-256 计算摘要写入本地分片目录，采用临时文件加重命名保证原子性，相同内容重复写入必须复用同一摘要文件且不产生重复副本；分片清单记录顺序、摘要、字节大小与内容版本号，并作为后续读取与延迟装配的唯一依据。
3. 实现分片大小、元数据缓存占用与读取延迟的受控定点换算：三者各自按声明标度换算为定点整数，登记每次换算的舍入余量、舍入方向与原始浮点值，未满一个定点单位的余量须逐项保留并在后续累加中参与；同一输入重复换算必须逐位一致，并保留原始值用于误差溯源。
4. 实现整读与范围读的延迟装配与误差上界累计：每次读取的耗时由分片摘要校验、拼接与缓存查找各环节的定点量累加得到，累计每步加法与换算的误差上界；当单次读取的实际耗时与延迟预算之差小于比对容差、结论依赖该差值时，必须标记为精度敏感并输出误差来源链（环节名、舍入余量、累加位置）。
5. 实现元数据缓存逐出在定点占用下的裁决与真值对照：缓存条目数受上限约束，按确定性的最近使用逻辑时钟与占用次序淘汰；同时在受控定点与基于 decimal 的高精度通路下计算各条目的占用量与淘汰候选序列，两条通路逐条比对，若因舍入导致候选序列不同须标记并输出首个分歧条目、两条通路中间值与参与换算步骤。
6. 实现读取延迟预算与缓存占用的规模自适应模式取舍：当单对象分片数或缓存候选条目数超过配置阈值时，在逐条精确装配与按分片摘要分桶的批量装配之间切换，切换须输出实际模式、触发条件、被否决模式原因与批量装配备注的误差界；两种模式对同一对象集合的整读结果逐字节一致，否则标记为一致性异常。
7. 实现强制终止后的恢复与半写入清理：把已提交对象水位、分片提交状态、元数据版本、缓存条目版本与逻辑时钟水位以事务原子写入 SQLite；进程在分片落盘与元数据提交之间被强制终止后，恢复路径识别无引用孤片与半提交元数据并只清理或补齐未完成部分；恢复后整读结果与不中断运行逐字节一致，各轮提交须识别版本变化。
8. 实现多进程并发一致性与异常链路隔离：多个写入与读取进程并行操作同一桶时，通过 SQLite 事务与文件锁保证同一对象同一内容版本只被提交一次、同一分片摘要只被物化一次、延迟预算不被并发超用，重复提交相同分片或元数据必须幂等；分片缺失、摘要不匹配、对象未提交即读取、缓存容量为零或非法、逻辑时钟回拨超阈值分别映射到不同业务错误码并保留可诊断字段。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
