当前是空白工作区，需要从零实现一个本地 HTTP/2 多路复用连接的状态演进与恢复一致性诊断工作台，全部在 Windows 上以确定性样本运行，不依赖任何真实网络对端、证书或外部站点。连接行为由本地 JSON 场景脚本以帧级事件描述：脚本按可注入逻辑时钟给出 HEADERS、CONTINUATION、DATA、RST_STREAM、WINDOW_UPDATE、SETTINGS 及其 ACK、PING、GOAWAY 等帧事件序列，每条流声明流 ID、初始发送与接收窗口、请求权重与期望最终状态；工作台需在同一连接上并发推进多条流，维护连接级与流级两层窗口账目、流状态机、头部块跨帧重组与加权调度。核心矛盾在于增量更新与依赖失效：场景以增量补丁形式持续下发新帧事件与窗口更新，补丁可能修改流权重、SETTINGS 初始窗口或流结束标记，而进行中的流已按旧配置推进，必须精确判定哪些窗口账目、调度顺序与头部重组结论需要失效重算、哪些可安全复用，且任一帧提交、补丁整体替换或进程被强制终止后，恢复结果必须与不中断运行逐字段一致。

任务环境与准备：
安装 Python 3.11 及以上版本，并在工作区创建虚拟环境后安装 fastapi、uvicorn、numpy 与 pytest（版本以本地可获得的稳定版本为准）。
确认 SQLite 由 Python 标准库 sqlite3 提供且支持临时表与 WAL 模式，无需额外安装数据库服务。
在本地样本目录放置由题目自带的确定性生成脚本产出的场景脚本、增量补丁与帧事件样本；样本生成与校验脚本需在无网络环境下可重复执行并输出内容摘要。
不启动任何真实网络监听以外的外部依赖；FastAPI 仅绑定回环地址用于本地诊断查询，不接入真实 HTTP/2 对端。

业务要求：
1. 实现场景脚本与增量补丁的解析校验：流 ID 单调且奇偶性符合发起方角色、初始窗口为正整数、权重在合法区间、事件逻辑时钟非降序、CONTINUATION 必须紧随未完成的 HEADERS 块、WINDOW_UPDATE 增量非负且不得使对应层级额度超过上限、GOAWAY 最后一流 ID 不越界、补丁引用的流必须已声明且补丁内容摘要与声明一致；非法脚本或补丁须返回不同业务错误码且不写入任何持久化状态。
2. 实现连接级与流级双层流量控制账目以及流状态机演进：任一时刻已发送未确认字节不得超过 min(流发送窗口, 连接发送窗口)，WINDOW_UPDATE 只能增加对应层级额度，RST_STREAM 后该流在途额度须按规则回收至连接级且不得被该流再次占用；依据 HEADERS 与 END_STREAM、RST_STREAM、GOAWAY 驱动每条流在 idle、open、half-closed-local、half-closed-remote、closed 之间迁移，每帧处理必须同时更新两层窗口余额与对应流状态且两者保持一致。
3. 实现 HEADERS 与 CONTINUATION 分片重组以及优先级权重调度：跨帧重组头部块并校验 END_HEADERS 标记，缺失或顺序错乱须映射到独立业务错误码；在连接发送额度受限时必须按流权重与稳定次序决定可发送流顺序，权重变更只影响此后调度，不得使已发送未确认的数据被重新排序或丢弃；重组后的头部摘要须可复现且与逐帧直接拼接结果一致。
4. 实现增量补丁驱动的依赖失效闭包裁决：补丁修改流权重、SETTINGS 初始窗口或流结束标记时，须沿“SETTINGS—连接窗口—各流窗口—调度顺序—头部重组结论”的关系计算受影响闭包，精确标记哪些窗口账目、调度名次与已缓存的头部重组结果需失效重算、哪些可安全复用；进行中的帧处理必须绑定其开始时的补丁版本直到该帧提交，未受影响流的账目与结论须逐字段保持不变。
5. 实现基于注入逻辑时钟的帧级原子提交与持久化：所有窗口推进、状态迁移与调度名次只依赖注入的逻辑时钟毫秒值，不读取系统墙钟；每处理一帧须把连接状态、全部流状态、两层窗口余额、逻辑时钟水位与帧摘要以单事务写入 SQLite，每轮补丁提交以临时表加版本号整体替换当前场景指针而非逐条覆盖，并识别完整替换、增量追加与无需操作并拒绝版本回退。
6. 实现强制终止后的恢复一致性：进程在任意帧处理或补丁替换中途被强制终止后，恢复路径依据持久化状态识别已提交帧水位与半提交帧，只重放水位之后的帧且不重复计入任何窗口额度或状态迁移；恢复后必须重新构造出与未中断运行逐字段一致的连接状态、每流状态、两层窗口余额与调度名次，不得承诺强制终止一定能生成退出报告，恢复只依赖已持久化状态。
7. 实现多进程并发一致性与幂等提交：允许多个处理实例并行处理同一连接的不同流，通过 SQLite 事务与文件锁保证同一流同一帧序号同一补丁版本只被提交一次、连接级窗口不被并发超扣、调度名次不被两个实例同时改写，重复提交相同帧或相同补丁请求必须幂等；查询方只能看到完整已提交的帧水位对应状态，不得观察到新旧补丁混合的窗口或状态。
8. 提供服务化诊断接口与可重复一致性验证工具：以 FastAPI 暴露 run、patch、resume、status、verify 端点或等价命令行子命令，status 以稳定排序 JSON 输出连接窗口、每流状态、窗口余额、调度名次与逻辑时钟水位；verify 校验持久化状态与逐帧重算结果、补丁失效清单与实际重算范围是否一致，不一致须输出首个分歧帧号、两条路径的中间值与所依赖的观测。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
