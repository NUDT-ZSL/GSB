为空工作区从零构建一个面向零样本目标检测（ZSL）离线评估的数据处理管线与结果验证工具。输入是本地样本目录：若干图像元数据 JSON（含图像 id、宽高、按像素坐标给出的真实框与类别名）、一份类别词表（含已见与未见类别的文本嵌入向量，固定维度），以及一份候选框文件（每张图若干候选框含坐标、类别无关置信度与匹配阶段使用的嵌入向量）。管线需要完成候选框与真实框的匹配、按已见/未见类别划分的预测汇总，并支持在多进程并行调度下按图像预算分批处理。核心难点在于：候选匹配的贪心顺序必须与串行结果完全一致，而并行分片与内存预算又要求受限批次处理；类别划分、匹配统计与指标计算分散在不同模块，任何一处计数偏差都会在最终指标中放大。所有资源判断必须基于本地真实可观测的样本与内存量，不依赖 GPU、外部下载或真实数据集。

任务环境与准备：
安装 Python 3.10 及以上，并安装 numpy 与 torch CPU 版（pip install numpy torch），不要求 GPU；Windows 下确认多进程使用 spawn 启动方式。
准备本地确定性样本目录：若干图像元数据 JSON、一份固定维度的类别词表与嵌入向量文件、一份候选框文件，全部随题目自造且不依赖外部下载。
确认工作区为空，运行任务前不存在输出目录与进度数据库；准备一个可直接复现的启动命令用于演示入口。
验证 Windows 进程退出码为整数，业务错误以 E_xxx 形式出现在 JSON 或 stderr 中，便于脚本区分强制终止与可处理退出。

业务要求：
1. 管线入口接收样本目录、类别词表文件、候选框文件、并行 worker 数与单批内存预算字节数，校验文件存在、嵌入维度一致性与预算为正整数，任一非法返回 E_PARAM 业务码且不得创建任何输出文件或临时进度记录。
2. 候选框与真实框的匹配须采用确定性贪心：按类别无关置信度降序、置信度相同时按候选框 id 字典序处理，每个候选框匹配当前 IoU 最大且尚未被占用的真实框，IoU 计算须使用样本元数据中的像素坐标且在同一图像内完成，结果与串行单进程执行逐条一致。
3. 并行调度须将图像划分为可分片单元交给多进程处理，但每个进程只允许同时驻留不超过内存预算的候选记录数；驻留量须由真实样本的候选框数量与记录字节量估算得出，超预算时先落盘再继续读取，禁止以固定 sleep 或线程超时冒充资源控制。
4. 每个分片完成后须把匹配结果以原子方式写入不可分割的结果分片文件，并在 SQLite 中以图像粒度提交完成标记；进程被强制终止后重跑仅处理未提交图像，结果分片与数据库标记在同一恢复流程中核对，不得出现重复或缺失图像。
5. 匹配统计须按真实框类别名映射到类别词表中的已见或未见集合，分别汇总命中数、假正例数与漏检数；词表中不存在的类别名返回 E_CLASS 并指出图像 id 与类别名，已见未见划分错误不得被最终指标掩盖。
6. 结果验证工具须从各结果分片重建整体统计，并在读取时检测分片文件版本与 SQLite 记录的版本是否一致；检测到版本变化或残留旧分片时返回 E_STALE 而不是汇入旧数据，重建统计须与单进程全量处理结果逐字段相同。
7. 最终须输出按已见与未见类别分别计算的检测指标与混淆计数量表，指标所需的匹配计数必须只来自已提交结果，任何分片缺失或重复计数时须给出可定位到图像与分片的诊断信息，而不是给出看似正常的数值。
8. 提供确定性本地演示入口：固定并行 worker 数、预算与样本，跑出分片数、逐类匹配计数、已见未见指标、恢复前后一致性结论的可重复结果，并给出可用等价参数复现的命令示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证匹配与串行一致、预算受限并行、中断恢复及版本失配报错。
