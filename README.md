当前是空白工作区，需要从零实现一个本地数据库连接池管理引擎，用于在确定性样本上复现连接申请、租约发放、空闲回收与池水位演进过程，并处理数据规模变化时的调度算法取舍。本地 JSON 样本给出：上游端点清单（端点名、回环地址、最大物理连接数、每连接建链逻辑耗时、健康状态）、连接申请轨迹（申请序号、租户、期望池标签、申请逻辑时钟毫秒、持有逻辑时长、释放事件）、以及池配置（总物理连接上限、每租户配额、空闲超时逻辑毫秒、最小空闲数、单轮逻辑时间预算、容差参数、逻辑时钟步进）。连接目标由本地回环回显测试服务模拟，不依赖真实数据库。引擎需在注入逻辑时钟推进下维护空闲队列与在途租约，按成本估计在精确队列与分层桶队列间切换调度算法，并在强制终止后依据持久化状态恢复租约与配额账目。

任务环境与准备：
Windows 上安装 Python 3.11 及以上，并安装 numpy 与 pytest（pip install numpy pytest）。
在空白工作区创建项目目录与本地样本目录，准备端点清单、申请轨迹与池配置 JSON 样本，以及本地回环回显测试服务的启动说明。
确认标准库 sqlite3 可用，样本与测试服务均使用本地回环地址与本地文件，不依赖外部数据库或网络。

业务要求：
1. 实现端点清单、申请轨迹与池配置的解析校验：端点名与申请序号唯一、地址为合法回环地址、最大物理连接数与每租户配额为正整数、持有逻辑时长为非负整数、空闲超时与最小空闲数满足边界关系、逻辑时钟步进为正整数，构建租户到池标签的映射模型；非法条目必须返回明确业务错误码且不写入任何持久化状态。
2. 实现连接申请的租约发放与配额账目：在总物理连接上限与每租户配额双重约束下决定复用空闲连接、新建物理连接或排队，租约须记录申请序号、租户、池标签、发放逻辑时钟与建链耗时；租约与配额账目必须同一事务提交，任何中途失败不得出现连接已建而配额未扣或配额已扣而无连接的中间态。
3. 实现空闲队列与分层桶队列两种调度算法并保证等价性：精确模式按空闲时长严格排序复用，分层模式按配置的时长桶分级复用；两种模式对同一申请轨迹在相同逻辑时钟序列下必须给出逐位一致的租约发放序列，并提供切换判据与开销估计输出。
4. 实现数据规模变化下的调度算法自适应切换：依据空闲连接数、池标签跨度与队列深度估算两种模式的开销，超过阈值时按明确规则切换模式；切换过程中在途租约不得丢失或重复发放，切换事件须记录触发条件、切换点逻辑时钟与被否决模式原因。
5. 实现空闲回收与最小空闲数维持：按注入逻辑时钟判定空闲超时并真实关闭超出最小空闲数的空闲连接，回收须释放对应配额且不得回收在途租约连接；区分超时回收、配额收缩回收与主动关闭三类原因，回收顺序与选择必须确定可复现。
6. 实现强制终止后的恢复一致性：把已提交申请水位、在途租约、空闲队列内容摘要、配额账目与逻辑时钟水位以事务原子写入 SQLite；进程在发放或回收中途被强制终止后，恢复路径识别已提交租约与半提交连接，只重建未提交部分且不得重复扣减配额或重复计数连接。
7. 实现多进程并发一致性与幂等提交：允许多个池实例并行处理同一租户申请，通过 SQLite 事务与文件锁保证同一申请序号同一版本只被发放一次、总连接数不被并发超建，重复提交相同申请或相同释放必须幂等；读取方只能看到完整已提交池状态而非发放中间态。
8. 实现异常链路与可重复命令行演示：端点拒绝连接、建链超出单次逻辑预算、连接探测返回畸形响应、池配置版本回退、样本摘要不匹配分别映射到不同业务错误码并保留可诊断字段，单次异常不得污染其他租户租约；提供 load、acquire、release、resume、status、verify 子命令，status 以稳定排序 JSON 输出租约、空闲队列分级与配额账目。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
