当前是空白工作区，需要从零实现一个本地告警降噪与根因关联组件，并以可交互 Web 应用与可重复演示交付。业务场景为 SRE 值班台：同一批告警事件需要经过聚合降噪、依赖链根因候选排序与拓扑规则增量更新三个环节。本地 JSON 样本给出两代告警规则条目：v1 为单文件 JSON，按告警规则名记录服务名、实例 ID 列表、严重度、相对生效秒数与扁平的服务到规则映射；v2 为分片 JSON 加 SQLite 元数据库，记录规则规范名、绝对生效毫秒戳、规则代数、依赖上游服务列表、静默标签与失效墓碑。另提供服务拓扑清单（服务名、实例 ID、上游依赖、故障域、实例权重）与告警事件流（事件序号、实例 ID、规则名、严重度、注入逻辑时钟毫秒戳、指标值）。组件需加载并合并两代规则条目为统一降噪视图，在可注入逻辑时钟下完成告警聚合与根因候选排序，并支持规则条目补丁的增量更新与失效闭包计算。核心矛盾在于：两代条目在时间表示与代数语义上不一致，而增量更新必须精确判定哪些已提交的降噪结论与根因候选需要重算，未受影响部分必须逐字保持不变。

任务环境与准备：
安装 Python 3.10 及以上版本，创建虚拟环境并安装 Flask 与 pytest（仅本地开发依赖，版本以 requirements.txt 固定）。
在工作区根目录准备 samples/ 子目录，放置两代规则快照（v1 单文件 JSON、v2 分片 JSON 与 SQLite 元数据库）、服务拓扑 JSON 与告警事件流 JSON，事件流须包含乱序与迟到事件样本。
确保 SQLite 可由 Python 标准库 sqlite3 直接打开，样本数据库与工作数据库分目录存放，工作目录可写。
启动前确认本地回环端口未被占用，Flask 仅绑定回环地址，不依赖任何外部服务、真实账号或线上站点。

业务要求：
1. 实现两代告警规则条目的解析与校验：v1 校验规则名唯一、服务名与实例 ID 存在于拓扑清单、严重度为合法枚举、相对生效秒数为非负整数、扁平映射条目与规则声明一致；v2 校验分片文件哈希、SQLite 元数据中规则代数单调、绝对生效毫秒戳为整数、依赖上游服务可解析、墓碑标记为布尔；非法条目须返回不同业务错误码且不写入任何持久化状态。
2. 实现跨版本规则合并与统一降噪视图构建：同一规则名在两代快照中同时存在时，依据快照声明的逻辑时钟与规则代数裁决最新条目，逻辑时钟相同则按来源格式优先级；合并后每条规则须保留来源版本、原始时间表示与裁决依据；整体替换快照时须以临时表加版本号切换视图指针并识别版本回退。
3. 实现时间语义的模式迁移与精度记录：把 v1 相对生效秒数在注入逻辑时钟下换算为绝对生效时刻，记录换算标度、舍入方向与换算前原始值；v2 绝对毫秒时戳保持原值；迁移决策须持久化，同一逻辑时钟下重复判定逐位一致，墓碑规则不得进入生效降噪视图但须保留审计记录。
4. 实现基于注入逻辑时钟的告警聚合降噪：按服务与规则名把时间邻近的告警归并为事件簇，依据规则严重度、实例权重与静默标签计算代表事件与抑制计数；簇窗口边界只依赖注入逻辑时钟毫秒值，不读取系统墙钟；相同事件流重复运行必须得到逐位一致的簇划分与代表事件，迟到事件不得改动已关闭簇。
5. 实现沿拓扑上游闭包的根因候选排序与证据链：对每个事件簇计算受影响实例集合，按告警时间先后、实例权重与依赖距离给出根因候选排序，并输出每条候选的判定依据（参与实例、依赖路径、时间差与权重）；排序所用运算顺序固定，相同输入重复运行逐位一致。
6. 实现规则补丁的增量失效闭包与结论复用：以补丁提交依赖关系、静默标签与生效时刻的修改，沿“规则—实例—事件簇—根因候选”的关系计算受影响闭包，精确标记哪些簇与候选需重算、哪些可安全复用；未受影响的簇与候选必须逐字段保持不变，失效清单须给出触发来源与被影响对象路径。
7. 实现持久化状态与强制终止后的恢复：把规则视图版本指针、事件水位、簇划分摘要、根因候选记录、失效事件与逻辑时钟水位以事务原子写入 SQLite；进程在簇提交或补丁提交中途被强制终止后，恢复路径须识别已提交簇与半提交状态，只重放未提交部分且不得重复累加抑制计数或改变已提交代表事件。
8. 实现多进程并发一致性与可重复 Web 演示：允许多个降噪实例与规则更新实例并行，通过 SQLite 事务与文件锁保证同一规则版本只提交一次、同一事件簇同一版本只提交一次，重复提交相同补丁或相同簇结果幂等；以 Flask 提供 load、patch、status、verify 等可交互端点，status 以稳定排序 JSON 输出当前规则版本、各簇代表事件与根因候选排序。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地两代规则样本与告警流验证合并裁决、降噪聚合、根因排序及补丁失效闭包，并检查中断恢复后结论一致。
