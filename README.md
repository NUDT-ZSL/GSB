当前是空白工作区，没有现存项目、代码或数据附件，需要从零构建一个面向命名实体识别（NER）标注数据治理的本地可集成领域组件与完整示例，核心业务问题是多标注者标注在受控实体类型集合版本演进下的格式互操作与冲突裁决。业务对象是本地确定性生成的 NER 标注样本：标注文件为 JSONL，每行含 doc_id、tokens 列表、ner_tags 列表、annotator_id、annotation_version、label_set_version；同时提供三套并存的实体类型集合书写形式（v1 为竖线分列行式、v2 为键值行式、v3 为结构化声明，各含类型名、BIO 前缀要求与启用标记）以及一份标注配置，声明合并策略、类型别名映射、最大 token 数与资源上限。系统需把三套类型集合规范化后合并同一文档的多标注者标注，并保证合并结论可追溯。

任务环境与准备：
安装 Python 3.10 及以上版本，并确保 numpy 可导入用于本地确定性样本生成，无需联网。
创建工作区目录，准备本地确定性样本生成脚本，按固定随机种子生成 NER 标注 JSONL、三套实体类型集合与标注配置，规模满足背景描述的业务语义。
确认运行环境为 Windows，工作区与持久化快照目录可写。
无需任何外部账号、线上站点、付费资源或 GPU。

业务要求：
1. 实现 v1、v2、v3 三种实体类型集合书写形式的读取器，按格式头或字段集分派解析路径；未知版本返回 E_VERSION_UNSUPPORTED，格式头截断、竖线字段数不符、必填字段缺失或启用标记不可解析返回 E_TYPE_SET_CORRUPT 并指出字段与行号，禁止部分解析后继续使用。
2. 实现三套类型集合的双向迁移器：v1 升级到 v2 或 v3 时补全 BIO 前缀要求与启用标记默认值并逐项记录补全来源；v3 降级到 v1 时对 v1 无法表达的嵌套别名与启用标记按显式声明的丢弃或展平规则处理并输出丢弃明细；迁移结果须可重放，补全与丢弃项须能与源行逐条对应。
3. 实现确定性的多标注者标注合并：按 doc_id 分组，对每个 token 位置按配置合并策略（多数投票或 annotator_id 优先级）选出最终标签，同票按 annotator_id 字典序升序打破平局；同一输入、同一类型集合版本与同一配置下逐字节产出相同合并标注与投票明细，禁止依赖字典遍历顺序或系统时间。
4. 实现受控类型集合与 BIO 合法性校验：合并后每个实体类型须属于当前启用类型集合，别名须先经别名映射归一后再校验，且 I- 标签前须存在同类型 B- 或 I- 标签；违反分别返回 E_TYPE_NOT_ALLOWED、E_ALIAS_UNRESOLVED、E_BIO_INVALID 并指明 doc_id、token 位置与标签值。
5. 实现类型集合版本收缩的裁决链路：当类型集合版本提升导致某类型被停用时，命中该类型的标注须按配置的替代映射改归、显式拒绝或整文档退回，分别返回 E_TYPE_RETIRED、以替代类型结果代替或 E_DOC_REJECTED，并在结果中标记处理类别与回退原因，不得静默接受越权类型。
6. 实现跨格式语义等价裁决与可追溯重放：同一类型集合以 v1、v2、v3 三种形式书写时，读取与迁移后必须产出相同启用集合、相同别名映射与相同合并标注，不等返回 E_SEMANTIC_DRIFT；对任一合并后 token 标签可按投票记录、标注者集合与类型集合版本重放出相同标签，追溯缺失或重放不符返回 E_TRACE_BROKEN 并指出 doc_id 与位置。
7. 实现类型集合与合并结果快照的版本化及整体替换，并实现资源上限：快照各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT；为单文档 token 数、类型总数与驻留投票中间结果设上限，超限返回 E_RESOURCE_LIMIT 或降级并标记降级类别。
8. 提供可集成的领域组件接口与完整示例，并实现跨模块一致性自检：暴露类型集合加载、双向迁移、合并、追溯与自检入口；自检校验各标注者 doc_id 集合一致、每个 token 位置恰有一个最终标签、投票统计可由原始 ner_tags 独立重算、三种格式视图下启用集合与合并结论可互相核对，不一致返回 E_INCONSISTENT 并指出 doc_id；示例读取本地样本输出含合并标注、迁移补全与丢弃明细、处理类别、业务码与自检结论的 JSON。
