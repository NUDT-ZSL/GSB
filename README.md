校园计算中心的值班中间件运维工程师需要为选课、实验台预约、文件共享与身份认证等院系实验平台依赖的校园服务建立可复核的熔断链路。每个被保护依赖由服务目录声明服务标识、所属院系平台、下游依赖与权重，每实例声明并发上限与探测配额；调用结果事件流按逻辑时刻交错给出成功、超时、业务错误与连接失败及耗时；熔断策略声明滑动窗口长度、失败率与连续失败阈值、冷却期以及半开状态的探测并发与探针数。问题在于高峰失败常由下游实验平台过载引起：一律整块打开会误伤正常调用，过于保守又让故障扩散；半开阶段的探测并发与探针数量如何配合冷却期缺少统一口径，失败率与连续失败两类判据在窗口边界裁决不一致，恢复结论很难复核。工作台需输出逐时刻状态序列、切换原因、探针放行拦截明细与按院系平台的可用性摘要，并支持状态切换时间线诊断。

任务环境与准备：
准备 Python 3 运行环境并在空工作区创建项目目录；本题只使用 Python 标准库，无需安装第三方包或配置外部服务。
准备本地样本入口：由实现提供的确定性生成器按固定种子生成服务目录、实例配额、调用结果事件流与熔断策略，无需访问真实校园服务或网络。
准备持久化目录用于状态快照与半开探针记录，直接使用本地文件系统；提供命令行或本地交互入口以运行状态推进和诊断视图。

业务要求：
1. 实现确定性样本生成器，按固定种子产出服务目录（服务标识、院系平台、下游依赖与权重）、实例并发上限与探测配额、交错的调用结果事件流（成功、超时、业务错误、连接失败，带耗时与逻辑时刻）以及熔断策略声明（滑动窗口长度、失败率阈值、连续失败阈值、冷却期、半开探测并发与探针数），同一种子两次生成结果须逐字段一致，并输出归一后的被保护依赖清单与策略摘要。
2. 为每个被保护依赖维护按逻辑时刻推进的滑动窗口，分别累计成功、超时、业务错误与连接失败的分类计数并计算窗口失败率与连续失败数；窗口关闭边界上的事件归属必须遵循统一的左开右闭规则，使同一事件不会同时计入两个窗口。
3. 依据失败率阈值与连续失败阈值两条判据裁决关闭到打开的切换，输出打开时刻、实际触发判据以及冷却期计时起点；当两条判据在同一时刻同时成立时须给出确定且可复述的优先级裁定，不得依赖遍历顺序。
4. 冷却期结束时刻与下一条事件时刻相同的情况下，须先完成状态迁移再做事件归属处理，并按探测配额与并发上限逐探针输出放行或拦截判定及占用计数，探针数耗尽后剩余事件一律拦截且不影响窗口计数。
5. 依据半开阶段探针的成功比例与连续成功数裁决恢复关闭或重新打开；重新打开时须重置冷却计时，恢复关闭时须清空审计中过期的滑动窗口并按窗口规则重新开始计数。
6. 在相同逻辑时刻存在多条事件时，须按稳定顺序处理并保证窗口滑动与冷却推进都使用事件时刻而非处理序号，从而在乱序提交同一批事件后得到与逐条顺序推进一致的失败率、连续失败计数与状态序列。
7. 当策略中的失败率阈值、连续失败阈值、冷却期或依赖权重被局部修改后，仅重算受影响依赖自修改时刻起的状态序列与恢复结论，未受影响的依赖其状态序列与统计须逐字段保持不变，并保证局部重算结果与全量重算一致。
8. 提供可交互的状态切换时间线诊断视图，展示被保护依赖的状态变化、切换原因、半开探针明细及按院系平台的可用性摘要，并支持恢复到本地持久化的状态快照后继续推进，快照版本变化须被识别并拒绝加载不兼容快照。

验收：
以独立参考熔断器复算的状态序列、失败率、连续失败数与半开探针明细为准核对每次切换时刻与触发判据；局部修改策略后的重算须与全量重算一致，且未受影响依赖逐字段相同。
