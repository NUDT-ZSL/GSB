当前是空白工作区，没有现存项目、代码或数据附件。需要从零构建一个面向本地 Windows 环境的 ML 推理网关诊断工作台，聚焦“后端版本指纹如何决定路由命中归属”。用户在本地 JSON 文件中声明一组推理后端（模型标识、回环端口、模型参数向量、整数并发上限）与一组路由规则（规则标识、按请求特征匹配的条件、目标后端、批大小参数）。网关在回环 TCP 端口上以 JSON 行协议接收推理请求，按规则选择后端并按批大小确定性分批，调用本地 NumPy 模拟推理服务对样本输入做轻量前向计算，返回输出摘要与整数耗时。核心业务不是维护规则间依赖图，而是：每个后端在每次加载时生成由模型参数向量与配置推导的版本指纹，路由命中必须绑定当时生效的后端指纹，形成逐请求命中账本；当后端被重新加载或参数变更导致指纹变化时，网关须识别哪些已记录的命中归属失效、哪些在途批次必须作废重派、哪些历史聚合统计需要重算，并把该过程做成可诊断、可重放的账本演进。整个会话状态持久化到本地 SQLite，恢复时按指纹集合差异整体替换状态，不得与旧状态增量合并。

任务环境与准备：
安装 Python 3.11，并确保 numpy 与内置 tkinter、sqlite3 可用；无需容器或外部服务。
准备本地确定性样本：后端与规则声明 JSON、请求序列 NDJSON、模型参数向量文件，均为工作区内新创建的文件。
确保本地回环高位端口未被占用，运行演示脚本前关闭占用同端口的其他进程。

业务要求：
1. 实现后端与路由规则的加载和强校验：从本地 JSON 读取后端与规则，校验模型标识与规则标识唯一、端口为 1 至 65535 的回环端口、并发上限与批大小为受区间约束的正整数、模型参数向量为定长有限浮点数组、规则条件字段与目标后端存在；任一不合法须以 E_RULE 业务码整体拒绝加载并输出出错条目路径。
2. 实现后端版本指纹的确定性推导与加载态建模：指纹由模型参数向量的规范化逐位表示、参数长度、后端配置摘要与加载序号共同推导，采用可复现的哈希组合规则；相同声明在不同加载顺序、不同并发加载下必须得到相同指纹，参数向量末位变化必须导致不同指纹，指纹量化口径须在报告中显式声明。
3. 实现路由命中与分批执行：按规则优先级与匹配条件把请求路由到后端，并按该规则批大小确定性分批，调用本地 NumPy 模拟推理服务取得输出摘要与整数耗时；每个批次须记录所用规则、后端标识与批次开始时的后端指纹，相同请求序列与相同指纹集合多次执行须得到逐字节一致的输出摘要与稳定分批记录，后端不可达须以 E_UPSTREAM 记入该批次并触发指纹归属复核。
4. 实现逐请求命中账本与指纹绑定判定：账本按请求记录路由规则、后端标识、批次序号、绑定指纹与输出摘要；判定某条命中是否仍有效须比较其绑定指纹与后端当前生效指纹，不一致即标记为失效归属并列入失效归属集合，判定只能基于指纹比较与加载序号，不得依赖时间推断或推断缺失信息。
5. 实现在途批次作废与重派规则：当后端指纹在批次执行期间变化时，该批次结果不得计入有效统计，须标记作废并按显式规则决定是否用新指纹重派；作废、重派与已完成批次须在账本中分列可核验，重派批次不得复用旧批次的输出摘要，且同一请求在账本中任一时刻至多存在一条有效归属记录。
6. 实现指纹演进后的统计重算与整体替换：后端集合指纹发生变化时，须识别受影响的规则、历史聚合统计与缓存条目，受影响统计基于现行有效归属重算，未受影响的聚合结果须保持不变且可校验；当前视图须整体替换而非逐条修补，替换时须稳定列出受影响后端、失效归属条数、作废批次与被重算统计项，旧统计保留为只读版本并可辨识差异。
7. 实现会话快照的版本识别与恢复后重放校验：快照持久化到本地 SQLite，含后端指纹集合、加载序号、规则版本、命中账本、作废与重派记录及统计版本；重新打开快照时须比较快照指纹集合与当前声明推导出的指纹集合，不一致须整体替换当前账本与统计状态而非增量合并；恢复后按快照记录的请求序列重放并逐条比较绑定指纹、路由规则、作废标记与输出摘要，差异须定位到首个不一致的请求序号与字段并输出 E_REPLAY。
8. 提供 Tkinter 诊断工作台与可重复演示脚本：界面展示后端列表与当前指纹、加载序号、每条规则命中分布、逐请求账本的指纹绑定与失效归属、作废重派批次以及统计版本与快照列表，渲染顺序稳定；附带本地确定性样本声明与请求序列及演示脚本，顺序执行首次加载并路由、变更后端参数触发指纹演进后重跑、快照恢复后重放三个场景，每个场景输出稳定顺序的诊断总结，并以命令行参数注入声明损坏、参数向量长度不合法、快照指纹集合冲突三类异常，分别以 E_RULE、E_VECTOR、E_SNAP 报告并写入结构化日志。
