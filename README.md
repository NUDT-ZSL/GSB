在空白工作区从零实现一个本地多租户压测批次容量评估引擎及其结果验证工具，用于在确定性样本上复现从压测观测到容量结论链路中的数值精度问题与误差传播。本地 JSON 场景给出：目标服务清单（服务名、回环 HTTP 测试服务地址、每租户的成功率下限与 P95 延迟上限）、压测批次计划（批次号、租户、并发梯度序列、每梯度持续逻辑毫秒、请求节奏、是否允许提前终止）、逻辑时钟步进表与精度配置（延迟定点标度、百分比标度、比对容差、误差上界预算）。目标服务由本地 Python 回环 HTTP 测试服务模拟，可按租户路径返回可配置状态码分布、慢响应与连接拒绝。引擎需按注入逻辑时钟驱动请求、按窗口统计成功率与延迟分位数、判定容量拐点，并全程为每个比率与分位数维护换算标度、舍入来源与误差上界，使结论可追溯、可复现。

任务环境与准备：
安装 Python 3.11 及以上版本，并确保 numpy 与标准库 sqlite3 可用；numpy 建议 1.26 及以上。
准备本地回环 HTTP 测试服务脚本与固定 JSON 场景样本（服务清单、批次计划、逻辑时钟步进表、精度配置），全部随任务提供，不依赖外部网络。
在 Windows 上创建空白工作目录，确认可写本地 SQLite 文件与结果目录，准备运行命令的终端。

业务要求：
1. 实现场景文件、压测批次计划与精度配置的解析校验：服务名与租户名唯一、地址为合法回环地址、并发梯度序列严格递增且元素为正整数、持续逻辑毫秒与请求节奏为正整数、SLO 阈值区间有效、定点标度与容差为正；非法输入须返回明确业务错误码且不写入任何持久化状态。
2. 实现基于可注入逻辑时钟的压测单元驱动与观测窗口切分：请求节奏、梯度持续时长与窗口边界只依据注入的逻辑时钟毫秒值推进，不得读取系统墙钟；每个请求必须唯一归属一个观测窗口且不得同时计入两个窗口，相同计划与相同响应序列在任意运行次数下得到逐位一致的窗口归属。
3. 实现成功率与延迟分位数的定点换算与误差账本：每个比率与分位数在声明标度下换算时须登记被舍弃余量、舍入方向与登记序号，P95 按固定排序与插值规则计算；累计每次加法与除法的误差上界，使相同输入重复计算逐位一致并可按登记序号回溯。
4. 实现精度敏感标记与误差来源链输出：当两个租户或两个并发梯度的成功率差、P95 延迟差小于比对容差而容量拐点裁决依赖该差值时标记为精度敏感，输出参与窗口号、换算登记序号、误差上界与若改用更高标度是否翻转结论；标记与来源链必须可复现。
5. 实现窗口摘要、梯度结论与容量拐点的状态演进：依据成功率、P95 与 SLO 阈值裁决梯度通过、降级通过或中止，并据此决定是否推进下一梯度与是否提前终止；迁移只能依据已提交窗口摘要裁决，重启后不得凭内存残留决定梯度是否已通过。
6. 实现强制终止后的恢复与预算约束下的调度：把单元水位、已提交窗口摘要、误差账本登记序列、梯度结论与逻辑时钟水位以事务原子写入 SQLite；每租户并发上限与全局逻辑时间预算耗尽时须放弃剩余单元并记录放弃原因，恢复路径只重放未提交窗口且不得重复计入已提交请求。
7. 实现多进程并发一致性与幂等提交：多个评估实例并行处理不同租户或同一租户不同梯度时，通过 SQLite 事务与文件锁保证同一窗口同一版本只提交一次、全局预算不被并发超用，重复提交相同窗口结果必须幂等，读取方只能看到完整已提交窗口而非中间态。
8. 实现异常链路隔离与可重复命令行验证：连接拒绝、响应超出单请求逻辑预算、状态码不符、畸形响应、目标服务中断、窗口摘要不匹配分别映射到不同业务错误码并保留可诊断字段，单个异常不得中断其他租户窗口；提供 run、resume、status、report、verify 子命令，report 稳定排序输出容量结论、窗口摘要与精度敏感标记。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地回环测试服务与固定样本验证窗口口径、容量拐点、精度敏感标记、中断恢复与错误码一致性，并附运行结果。
