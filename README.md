构建平台的网络策略管理员要为分布在多个区域的构建节点核对出口流量路径：各节点经由不同上游接入点对外访问软件制品仓库，前缀路由表给出候选下一跳的 AS 路径、本地优先级与社区标记，策略声明则按社区偏好与过滤规则决定哪些候选会被保留。线路中断、恢复与策略调整按逻辑时刻交错发生，管理员难以判断某次切换究竟源自社区过滤排除，还是本地优先级刻度表达差异。同一份策略工程还会以两版 schema 交付，社区标记有字符串标签与位图整数两种写法，本地优先级有绝对整数与相对百分比两种刻度。为此需要从零实现一个可集成的 Python 领域组件与本地诊断工作台，用固定种子生成器产出双版本工程与事件序列，支撑逐事件复盘。

任务环境与准备：
准备 Linux（WSL Ubuntu）系统及 Python 3 运行环境，仅使用标准库 sqlite3 与 http.server 等模块。
从空目录创建项目，运行确定性生成器（固定种子）产出双版本策略工程样本与交错事件序列。
启动本地 HTTP 诊断工作台前初始化 SQLite 数据库文件，确保工作目录可写。

业务要求：
1. 实现双 schema 版本策略工程归一器，将两版本的前缀路由表、社区标记表示（字符串标签与位图整数）及本地优先级刻度（绝对整数与相对百分比）转换为统一内部模型，并校验前缀与下一跳引用合法性，对悬空引用输出带业务码 E_REFERENCE 的差异报告。
2. 按社区过滤规则筛除前缀的候选下一跳，对剩余候选依 AS 路径长度升序、本地优先级降序、社区偏好权重降序的确定性次序确定最优路径与备选路径，输出每条路径的择优依据说明。
3. 按逻辑时刻推进线路中断、恢复与策略变更事件，更新候选下一跳与过滤结果，沿受影响前缀重算至所有前缀选路稳定，输出每个前缀的切换序列与全局收敛时刻。
4. 对同一前缀在两版本归一后的最优路径与备选路径逐字段比对，输出差异前缀清单并归因到社区标记表达差异或本地优先级刻度差异，归因结果须与生成器注入的已知差异逐项吻合。
5. 在策略声明局部修改后，仅重算受影响前缀的候选过滤与择优结果，未受影响前缀的最优路径、备选路径及切换序列逐字段保持不变，且重算结果与全量重算一致。
6. 汇总每个构建节点出口路径的可达性与回退覆盖统计，标记无可用候选或无备选路径的前缀，区分装载错误、全部候选被社区过滤、单一候选三类原因，按节点与区域两级输出。
7. 将前缀选路结果与事件切换序列持久化到 SQLite，支持从最近已提交事件时刻续算，续算后最终状态与从头重放一致，已提交前缀的切换序列不重复写入。
8. 提供本地 HTTP 诊断工作台，按构建节点与前缀展示当前最优/备选路径、择优依据、切换历史与收敛时刻，并支持以查询参数指定逻辑时刻回看历史选路快照，快照须读取持久化序列而非重新计算。

验收：
独立参考选路器逐事件比对最优/备选路径与收敛时刻一致，两版本差异归因与已知差异吻合，局部修改重算与全量重算一致且未受影响前缀不变。
