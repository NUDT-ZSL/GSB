当前是空白工作区，需要从零构建一个面向卷积与插值算子的本地领域数据编辑与操作应用，核心业务问题是状态演进与恢复一致性。输入为本地确定性生成的算子任务清单（JSONL，字段含 job_id、op_kind、input_shape、kernel 或 scale 参数、stride、padding、模式标识、seed、权重种子）以及由 seed 生成的特征图与卷积权重数组；算子覆盖二维卷积与多种插值（最近邻、双线性、双三次）两类。应用把一次批量算子执行建模为多阶段流程：输入校验→权重与特征准备→分块卷积或插值计算→结果聚合。每个阶段完成后才能提交带单调递增版本号与内容校验和的阶段快照，进程被强制终止后重启需从最后已提交阶段继续，进行中未提交的中间工作必须丢弃。卷积与插值同时存在时需要统一的分块与边界处理口径，且恢复后结果必须与不间断运行逐元素一致。

任务环境与准备：
安装 Python 3.10 及以上与 NumPy（pip install numpy），无需 GPU 或外部服务。
在空白工作区创建工作目录，准备本地确定性样本生成脚本，按固定种子生成特征图、卷积权重与算子任务清单 JSONL。
准备本地持久化目录用于阶段快照与恢复演示，确认进程可被强制终止以验证恢复流程。
确认可在 Windows 下运行命令行入口与本地交互应用。

业务要求：
1. 实现二维卷积与最近邻、双线性、双三次四类算子的统一入口，按任务清单解析形状、stride、padding、scale 与模式标识，对非法形状、stride 非正、padding 越界、未知模式分别返回 E_SHAPE_INVALID、E_PARAM_INVALID、E_MODE_UNSUPPORTED 并指明 job_id。
2. 实现统一的分块与边界处理口径：卷积与插值共用同一套块划分与越界索引规则，边缘块按显式声明的边界策略处理；同一输入与配置下逐元素结果必须与针对每类算子独立实现的参考结果在给定 float64 容差内一致，且分块结果不得依赖块执行顺序。
3. 实现输入校验、准备、计算、聚合四个阶段的状态机，每阶段产生带单调递增版本号与内容校验和的阶段快照，只有阶段完整结束才提交；提交顺序、阶段状态与版本号必须在持久化存储中原子可见，部分完成的阶段不得提交。
4. 实现强制终止后的恢复逻辑：重启时读取已提交快照，识别版本号与校验和变化并整体替换旧快照，从最后一次已提交阶段继续；未提交的中间分块结果必须丢弃并从该阶段起点重建，恢复后的最终结果须与不间断完整运行逐元素一致并输出恢复报告。
5. 实现快照损坏与版本回退防护：损坏或校验和不符的快照返回 E_SNAPSHOT_CORRUPT 并指明阶段名与版本号，禁止使用部分可解析的损坏数据；旧版本快照不得覆盖新版本已提交阶段，回退尝试返回 E_STAGE_STALE 而不改变已提交状态。
6. 实现并发提交控制与资源上限：同一时刻只允许一个阶段提交生效，并发冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待；为单阶段任务数、块数量与中间结果驻留内存设可配置上限，超限时按明确策略返回 E_RESOURCE_LIMIT 或降级到更小块并标记降级类别，降级不得改变结果的数值容差口径。
7. 实现输入与异常校验链路：重复 job_id、input_shape 维度不符、scale 非正、seed 缺失分别返回 E_DUP_JOB、E_SHAPE_INVALID、E_PARAM_INVALID、E_SEED_MISSING；解析失败与磁盘写入失败须沿异常链路归因到具体阶段与 job_id，未归因异常汇总到结果报告中。
8. 提供本地可交互应用展示当前阶段、快照版本、各算子完成计数、最近业务错误码与恢复报告，并允许触发一次演示：执行批量任务、强制终止后从已提交快照恢复并对比恢复结果与完整运行结果，演示仅使用本地确定性样本与注入的异常输入。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证四类算子结果、阶段快照恢复一致性与异常码。
