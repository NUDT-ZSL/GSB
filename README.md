交付从新建的代码库开始，需要实现一个本地可观测性告警关联引擎，用于在确定性样本上复现从原始告警事件流到降噪聚合、依赖失效传导与根因候选排序的完整链路，并处理数据规模变化时精确关联与近似关联之间的算法取舍。本地 JSON 样本给出：服务拓扑清单（服务名、实例 ID、上游依赖服务名列表、所属故障域、实例权重）与告警事件流（事件序号、实例 ID、告警规则名、严重度、可注入逻辑时钟毫秒戳、指标值、静默与维护窗口标记）。引擎需维护告警聚合器与拓扑依赖图，支持拓扑与静默规则的增量更新：当某服务的依赖关系或实例权重被修改时，精确计算受影响闭包并使既有降噪结论与根因候选按需失效重算，同时保证未受影响结论逐字不变。样本规模可在单机任意放大，故需在单流精确嵌套与基于依赖距离的分桶近似之间做取舍，并给出可复现的比较结果。

任务环境与准备：
安装 Python 3.11 或更高版本，并使用 pip 安装 numpy 与 pytest（版本以本地可用稳定版为准）。
仅使用 Python 标准库 sqlite3、json、hashlib、threading 与 multiprocessing，不需要任何外部网络、容器或数据库服务。
在新建工作区中准备本地样本目录：拓扑 JSON、告警事件流 JSON、静默与维护窗口补丁 JSON，以及用于验证恢复的强制终止复现脚本。
确认工作区可写并允许创建 SQLite 数据库文件与临时目录，用于持久化与整体替换时的临时表。
运行任务前先执行一次样本校验脚本，确保样本中事件序号递增、逻辑时钟非负且依赖图无环，避免把样本缺陷混入实现问题。

业务要求：
1. 实现拓扑与告警事件流的解析校验：服务名与实例 ID 唯一、上游依赖两端闭合且无自环、实例必须归属已声明服务、事件序号严格递增、逻辑时钟毫秒戳非负、严重度与静默维护标记枚举合法、指标值有限，构建依赖有向图并检测环；非法输入须返回明确业务错误码且不写入任何持久化状态。
2. 实现基于注入逻辑时钟的告警降噪：按（服务, 告警规则名）将时间邻近的告警归并为事件簇，抑制被静默或维护窗口完整覆盖的告警，并依据严重度与实例权重计算簇的代表事件与抑制计数；聚类窗口边界只依赖注入逻辑时钟毫秒值，不读取系统墙钟，相同事件流在任意运行次数下须得到逐位一致的簇划分与代表事件。
3. 实现沿依赖图的根因候选关联与稳定排序：对每个事件簇按上游依赖闭包计算受影响实例集合，结合告警发生先后、实例权重与因果距离给出根因候选排序与判定依据；排序须说明所依赖的观测项与聚合顺序，同分时按稳定次序裁决，输出每条候选的参与实例、依赖路径与时间差。
4. 实现数据规模变化下的关联算法取舍：当单故障域事件数或依赖闭包规模超过配置阈值时，在单流精确嵌套与按依赖距离分桶的近似关联之间切换，切换须输出实际模式、切换触发条件、被否决模式原因以及近似模式的召回率估计与误差上界；切换前后对已确定的明显胜负不得翻转，仅在容差带内的候选允许顺序变化并须标记。
5. 实现规则增量更新与依赖失效闭包：以补丁形式提交依赖关系、静默窗口与实例权重的修改，沿依赖图计算受影响闭包，精确标记哪些事件簇与根因候选需重算、哪些可安全复用；未受影响的簇与候选不得被重算且其结论与依据链须逐字保持不变，失效清单须给出触发来源与被波及层级。
6. 实现静默窗口与事件簇状态的演进：新增静默或维护窗口可抑制既存簇中部分告警并改变代表事件，窗口撤销后不得让已抑制告警直接提升为代表事件，而须按逻辑时钟重新裁决；状态迁移只能依据已提交簇结论与持久化状态裁决，重启后不得凭内存残留决定状态。
7. 实现持久化状态与强制终止后的恢复：把拓扑版本、事件水位、簇划分摘要、失效事件与根因候选记录以事务原子写入 SQLite，每次规则提交与簇推进采用临时表加版本号识别版本变化并整体替换当前结果指针；进程被强制终止后，恢复路径依据持久化状态识别已提交簇与半提交结果，只重放未完成部分且不重复计入抑制数。
8. 实现多进程并发一致性与异常链路隔离：允许降噪实例与规则更新实例并行，通过 SQLite 事务与文件锁保证同一规则版本只提交一次、同一事件簇同一版本只提交一次，重复提交相同补丁或相同簇结果必须幂等；依赖成环、补丁引用不存在的服务、事件引用未声明实例、静默窗口区间非法、拓扑版本回退分别映射到不同业务错误码并保留可诊断字段，单个异常不得中断其他服务的降噪。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证降噪聚类、规模切换、增量失效与中断恢复结果一致且幂等，并给出取舍比较。
