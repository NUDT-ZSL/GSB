在游戏引擎的光照探针烘焙流程中，需要从零开发一个本地多频段辐照度烘焙数据处理管线与结果验证工具。场景由程序按确定性规则生成本地样本：一组探针点阵（稀疏三维坐标）、若干带自发光的面片光源、以及用于散射的环境四面体几何。每个探针需要把可见方向半球内的直接光照与单次散射间接光照投影到低阶球谐基（至少二阶），生成可持久化的辐照度系数文件。编辑器侧要求：设计者调整光源亮度或散射强度后，仅重烘受影响的探针子集，且交互预览读取的辐照度必须与全量重烘逐系数一致；烘焙过程中可中断，再次启动须从持久化快照恢复且最终结果与连续烘焙完全一致。真实难点在于分区烘焙的局部结果与全局一致性之间的冲突：探针之间的可见性由几何决定，扰动一个光源可能影响远处探针，增量与延迟预览不得让设计者看到与全量结果不符的辐照度。

任务环境与准备：
Windows 10 或更高版本，已安装 Python 3.10 及以上并确保 python 与 pip 在 PATH 中。
在空工作区创建项目目录，通过 pip 安装 numpy（任意稳定版本）作为唯一第三方依赖，不依赖 GPU、渲染库或外部资源。
准备本地确定性样本生成脚本的输入参数：场景种子、探针点阵规格、面片光源清单、散射四面体几何与编辑脚本，样本由程序按规则生成本地文件。
准备一个用于持久化分区状态与最终输出的本地目录，并确保测试进程对其有读写权限。

业务要求：
1. 实现场景描述解析与输入校验：读取 JSON 场景，校验探针坐标与四面体顶点均为有限数、探针互不重合、面片光源法线为单位向量且辐亮度为有限正数、球谐阶数属于允许集合且与每探针系数数量匹配、分区规格能覆盖全部探针，非法输入返回带 E_xxx 业务码的 JSON 错误且不产生任何输出文件。
2. 实现确定性的球谐投影：对每个探针在可见半球内按固定方向采样集（由场景种子派生的确定性伪随机序列）采集直接光照与散射贡献，用与采样方向对应的球谐基逐系数累加积分权重，投影结果只依赖场景参数与探针坐标而不依赖遍历与调度顺序，同一输入重复烘焙须得到逐系数相同的辐照度系数。
3. 实现探针可见性与分区判定：对每个探针对每个面片光源与散射四面体做可见性测试（遮挡判定基于本地几何），按场景给出的空间分区把探针归入分区并记录每个探针实际受影响的光源与几何集合；一个探针若被分区规则判定为不受某光源影响，须给出判定依据的可复核记录。
4. 实现分区级持久化与版本标识：每个分区烘焙完成后把该分区探针的球谐系数、受影响集合摘要与由场景几何、光源参数、采样集与球谐阶数规范化摘要构成的版本标识原子写入状态目录，先写同目录临时文件再整体替换，替换前比对已有分区的版本标识，标识变化时不得直接覆盖而须归档旧版本。
5. 实现增量重烘与全量一致性：当编辑脚本仅修改部分光源亮度或散射强度后，按受影响集合只把相关分区标记为失效并重烘，未失效分区复用持久化系数；增量结果与同输入从头全量烘焙在球谐系数上逐探针逐系数差不超过数值容差，受影响集合判定错误导致漏烘时必须能被一致性检查发现并返回 E_INCONSIST。
6. 实现交互预览与计算结果的一致性：提供本地命令行预览查询接口，按探针标识与方向返回由球谐系数重建的辐照度；预览只读取已持久化且摘要有效的分区系数，未完成分区以确定占位状态返回带业务码 E_PENDING 的响应而不阻塞后续查询，后台重烘完成后不得改变已返回历史查询的数值语义。
7. 处理中断信号、强制终止与并发资源上限：可处理终止信号只在分区边界生效，写入中断标记并以约定整数退出码退出，未完成分区不得留下可被误认为完成的结果；强制终止后重启仅依据已持久化且摘要有效的分区状态恢复，不承诺生成退出报告；使用有界线程池按并发上限调度分区烘焙，同时在处理的探针采样缓冲与球谐累加缓冲总量受内存预算限制，任一分区失败时取消其余待处理分区并返回首个错误。
8. 实现分区摘要校验与结果原子导出：全部完成后逐分区比对内容摘要，摘要不匹配、缺失或声明探针数与实际不符时判定该分区失效并返回 E_DIGEST 且回退重烘，不得静默使用失效分区；校验通过后按探针稳定标识拼装全部系数并导出为最终文件，导出读取已有文件的版本摘要，版本不同才整体替换，同时输出 JSON 报告含分区数、每分区探针数、增量与全量比对结果及业务码汇总。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
