在空白工作区从零实现一个本地告警降噪与根因关联组件，用于在确定性样本上复现告警事件从原始记录到降噪聚合、依赖失效传导与根因候选排序的完整链路。本地 JSON 样本给出：服务拓扑清单（服务名、实例 ID、上游依赖服务名列表、所属故障域、实例权重）与告警事件流（事件序号、实例 ID、告警规则名、严重度、可注入逻辑时钟毫秒戳、指标值、静默与维护窗口标记）。组件需维护告警聚合器与拓扑依赖图，支持规则的增量更新：当某服务的依赖关系、静默窗口或实例权重被修改时，精确计算受影响闭包并使既有降噪结论与根因候选按需失效重建，未受影响部分必须复用且结论保持不变。降噪结论与根因候选需在可注入逻辑时钟下可重复，全部状态持久化到 SQLite 并支持强制终止后的恢复。

任务环境与准备：
安装 Python 3.11 及以上版本，确认可用标准库 json、sqlite3、hashlib、multiprocessing 与 argparse。
安装 NumPy 1.26 及以上版本，仅用于数值聚合运算，不依赖 GPU。
准备本地固定样本目录：拓扑清单 JSON、告警事件流 JSON 与增量补丁 JSON，全部为确定性数据。
确认工作区为空白，可写入 SQLite 文件与本地演示输出目录，不需要网络与外部账号。
运行前无需启动任何服务，全部组件在本地文件与 SQLite 上执行。

业务要求：
1. 实现拓扑与告警事件流的解析校验：服务名与实例 ID 唯一、上游依赖两端闭合且无自环、实例必须归属已声明服务、事件序号严格递增、逻辑时钟毫秒戳非负、严重度与静默维护标记枚举合法、指标值有限，构建依赖有向图并检测环；非法输入返回明确业务错误码且不得写入任何持久化状态。
2. 实现基于注入逻辑时钟的告警降噪：按（服务, 告警规则名）将时间邻近的告警归并为事件簇，抑制被静默或维护窗口覆盖的告警，并依据严重度与实例权重计算簇的代表事件与抑制计数；聚类窗口边界只依赖注入逻辑时钟毫秒值，同一事件序列在任意运行次数下必须得到逐位一致的簇划分与代表事件。
3. 实现沿依赖图的根因候选关联与排序：对每个事件簇，按上游依赖闭包计算受影响实例集合，结合告警时间先后、实例权重与因果距离给出根因候选排序与判定依据；排序结果须说明依赖的观测项与聚合顺序，相同输入必须得到完全一致的候选序列与依据文本。
4. 实现规则增量更新与依赖失效闭包：以补丁形式提交依赖关系、静默窗口与实例权重的修改，沿依赖图计算受影响闭包，精确标记哪些事件簇与根因候选需重算、哪些可安全复用；未受影响的簇与候选不得被重算且其结论与依据必须保持不变，失效决策须可追溯。
5. 实现静默窗口与事件簇状态的演进：新增静默或维护窗口可抑制既存簇中部分告警并改变代表事件，窗口撤销后不得让已抑制告警重新成为代表事件而须按逻辑时钟重新裁决；状态迁移只能依据持久化状态裁决，重启后不得凭内存残留决定抑制关系。
6. 实现持久化状态与强制终止后的恢复：把拓扑版本、事件水位、簇划分摘要、失效事件与根因候选记录以事务原子写入 SQLite，每次规则提交与簇推进采用临时表加版本号识别版本变化并整体替换当前结果指针；进程被强制终止后恢复只重放未提交步骤，不得重复计入事件或回退簇状态。
7. 实现多进程并发一致性与幂等提交：允许降噪实例与规则更新实例并行，通过 SQLite 事务与文件锁保证同一规则版本只提交一次、同一事件簇同一版本只提交一次，重复提交相同补丁或相同簇结果必须幂等；读取方只能看到完整已提交的拓扑版本与簇结论而非更新中间态。
8. 实现异常链路与可重复命令行演示：依赖成环、补丁引用不存在的服务、事件引用未声明实例、静默窗口区间非法、拓扑版本回退分别映射到不同业务错误码并保留可诊断字段，单个异常不得中断其他服务的降噪；提供 load、ingest、patch、resume、status、verify 子命令，status 以稳定排序 JSON 输出拓扑版本、簇数量、失效计数与根因候选摘要，演示脚本使用固定本地样本两次运行输出完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定样本验证增量补丁后的失效闭包、根因排序、恢复与并发幂等，两次运行输出一致并附结果。
