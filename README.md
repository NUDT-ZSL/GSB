需要在新工作区从零构建一个面向“网页结构变化”的本地采集管线，用于多源商品目录页的字段抽取。目标站点是本地启动的确定性站点服务，同一商品目录在多个来源下呈现不同的页面结构版本，由每个页面内显式声明的 schema 版本号区分，来源之间的字段命名和嵌套路径存在差异。列表页含分页与前端脚本二次渲染后的条目容器，详情页有模拟 503、会话过期与慢响应的可控开关。采集器需按可配置并发度并行抓取列表与详情，依据结构声明选择对应来源的提取规则，把原始响应与规范化字段写入 SQLite，并在中断后从持久化检查点恢复。最终交付包括管线本体、可交互的字段对齐验证控制台以及确定性演示脚本，用于观察跨来源字段对齐、并发预算遵循、恢复前后已确认条目计数一致。

任务环境与准备：
Windows 环境，安装 Python 3.11 及以上并创建虚拟环境。
pip 安装 fastapi、uvicorn、httpx、selectolax、pytest 等依赖，版本在 requirements 中固定。
在项目内准备本地确定性站点样本：列表页、两个来源各两版详情页、503 与会话过期模拟开关均由配置文件控制。
运行前确认本地端口可用，站点服务与采集器均绑定 127.0.0.1。
准备演示脚本入口与 pytest 用例目录，样本数据由脚本生成，不依赖外部下载。

业务要求：
1. 实现列表页就绪判定与分页游标推进：必须以条目容器出现且条目计数在连续两次观测中稳定作为渲染完成标记，不得用固定等待替代；分页游标以页面声明的总页数与下一页标识共同推进，超时返回 E_RENDER_TIMEOUT 并保存当次观测快照。
2. 实现多来源版本化提取规则：按详情页内声明的来源标识与 schema 版本号共同选择字段映射，至少覆盖两个来源各两个版本；遇到未声明或未知版本时保留原始字段并标记为 unresolved，不得静默丢弃或按默认规则猜测，未解析条目数须在汇总中单独计数。
3. 设计跨来源规范字段与幂等键：以来源业务标识与来源内 schema 版本号构成唯一键去重入库；各来源字段需映射到统一的规范字段集合，冲突写回记录来源标识，重复插入被数据库约束拒绝时返回 E_DUPLICATE，恢复重跑与并行重复抓取均不得产生重复行。
4. 实现并行调度与资源预算：并发度可配置且有硬上限，需对在途请求数与重试等待队列分别设预算，任一预算耗尽时新请求排队而非无限开连接；慢响应与 503 触发有界指数退避，重试耗尽记为条目级失败而非任务级失败，失败分类须在汇总中区分。
5. 实现会话过期识别与重放：检测到会话过期响应时重新获取会话并重放当前请求，重放次数有上限；超过上限返回 E_SESSION 并保持任务可恢复，过期响应体不得作为正常数据入库，重放期间须遵守同一并发预算。
6. 实现断点恢复一致性：以持久化检查点记录已完成条目键集合与当前分页游标，恢复时跳过已确认条目、重抓未确认条目；强制终止进程后仅依赖库中状态续跑，不承诺补写退出报告，恢复前后已确认条目计数须一致。
7. 提供跨来源字段对齐验证工具：对同一业务标识在不同来源与版本下的规范化结果给出字段差异报告（新增、缺失、类型变化），并按统一规范字段集合检查必填字段完整性；差异报告须基于解析结果中的统一版本证据，不得与入库唯一键的版本判定冲突。
8. 交付本地站点服务与管线的一体化运行入口：站点服务与采集器通过配置中的本地地址与端口协作，控制台可创建任务、查看进度、失败明细与恢复操作，并能通过配置参数注入版本切换与异常；演示脚本重复执行须得到相同的条目计数、失败分类与最终任务状态汇总。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
