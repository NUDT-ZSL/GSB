当前是空白工作区，需要从零实现一个本地服务网格流量治理的配置下发对账与漂移裁决引擎，业务目标不是调度下发本身，而是把“声明期望配置”与“实例实际生效配置”之间的差异做成可解释、可裁决、可恢复的漂移账本。样本以本地 JSON 给出：期望配置快照（服务名、实例 ID、路由规则、版本标签与权重拆分）、实例上报快照（每个实例周期性上报当前实际生效的规则版本号、规则内容摘要、生效逻辑时钟与自行声明的健康标记），以及裁决配置（漂移容忍窗口逻辑毫秒、版本摘要严格比对开关、每轮对账并发上限与每轮对账逻辑时间预算、压制重复漂移的去重冷却）。实例上报由本地回环 HTTP 测试服务模拟，可返回与期望一致、陈旧版本、摘要被篡改、字段缺失或畸形响应，不依赖真实集群。要求把每条漂移登记为带来源、证据链与裁决结论的账本条目，并保证中断后可继续裁决且已提交账本不被重算。

任务环境与准备：
安装 Python 3.11，并在项目虚拟环境中安装 pytest 与 requests，确认可正常导入。
准备本地回环 HTTP 上报模拟服务脚本，可按实例返回与期望一致、旧版本、摘要被篡改、字段缺失或畸形响应，并监听多个空闲回环端口。
准备确定性样本 JSON：期望配置快照、实例上报配置、裁决配置与异常注入清单，全部使用回环地址与固定随机种子。
确认 SQLite 3 可用，工作区可创建数据库与锁文件，测试中可在同机并发启动多个对账实例。

业务要求：
1. 实现期望配置快照、实例上报快照与裁决配置的解析校验：服务名与实例 ID 唯一、实例归属已声明服务、版本号为非负整数、权重拆分和与版本标签闭合、上报生效逻辑时钟为非负整数、漂移容忍窗口与并发上限为正整数；非法条目须返回 E_BAD_EXPECTED、E_BAD_REPORT 等不同业务错误码且不写入任何持久化状态。
2. 实现期望与实际的结构化差异计算与漂移分类：按实例逐字段比对版本号、规则内容摘要与关键路由权重，输出漂移类型至少区分版本落后、摘要不一致、实例多出未声明规则、实例缺少声明规则与上报元数据缺失，每条差异携带字段路径、期望值、实际值与判定依据，结果以稳定排序 JSON 输出且相同输入多次运行逐字一致。
3. 实现漂移的裁决语义与容忍窗口判定：依据漂移容忍窗口逻辑毫秒、版本摘要严格比对开关与实例自声明健康标记，裁决每条漂移为自动收敛、需人工介入或暂时容忍，并记录裁决所依赖的观测；同一实例同时命中多种漂移时须给出聚合裁决与优先级依据，不得只保留首个差异。
4. 实现对账账本的去重冷却与演进：同一实例同一漂移类型在去重冷却窗口内重复出现时不得新增账本条目而须累加出现次数并更新时间戳，冷却窗口过后再次出现须作为新条目登记并关联前序条目；账本条目的打开、容忍、关闭、重新打开状态迁移只能依据持久化账本与逻辑时钟裁决，重启后不得凭内存残留决定状态。
5. 实现对账轮次的并发执行与预算约束：在每轮对账并发上限与每轮对账逻辑时间预算双重约束下并发拉取实例上报，预算耗尽须放弃剩余未启动实例并记录放弃原因，且放弃不得被记为漂移或提升实例异常计数；已启动拉取不得被截断为漂移，须给出真实结局分类。
6. 实现账本与实例视图的原子持久化推进：每轮对账须在同一事务内提交账本变更、实例最新上报视图与轮次摘要，读取方只能看到完整已提交轮次；轮次摘要须记录本轮输入快照摘要、参与实例集合与裁决统计，使任一轮次可被独立复算校验。
7. 实现强制终止后的恢复裁决：把轮次水位、账本条目版本、去重冷却计时、实例视图摘要与逻辑时钟水位以事务原子写入 SQLite；进程在拉取上报或账本提交中途被强制终止后，恢复路径须识别已提交轮次与半提交账本，只重做未完成部分且不得重复累加漂移出现次数，恢复结果须与不中断运行得到的账本逐字段一致。
8. 实现多进程并发一致性与异常链路隔离：允许多个对账实例并行处理不同服务，通过 SQLite 事务与文件锁保证同一实例同一轮次同一账本版本只被提交一次且重复提交幂等；上报连接拒绝、响应超出单实例预算、响应畸形、上报版本回退分别映射到不同业务错误码并保留可诊断字段，单个实例异常不得影响其他实例账本与轮次提交。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地回环上报服务验证漂移分类、容忍裁决、去重冷却与强杀后账本续算，verify 复算一致。
