在空白工作区从零实现一个本地服务注册中心的健康探测调度管线，用于验证注册实例的存活状态并控制探测开销。注册表以本地 JSON 文件给出初始实例清单，每个实例声明服务名、实例 ID、地址、权重、探测端点描述（协议、路径、期望状态码、超时预算）与心跳租约。探测目标由本地 HTTP 测试服务模拟，该服务根据请求路径返回可配置的状态码与延迟，并可注入慢响应与拒绝连接。管线需按并行调度模型对同一轮次内的实例分组探测，在每轮总探测时间预算与每服务并发上限双重约束下决定启动顺序与放弃策略；探测结果需驱动实例状态在健康、可疑、失联之间的演进，并把状态变更持久化到 SQLite，以便进程被强制终止后依据持久化状态重建租约与退避计时。所有输入输出、错误码与状态查询均可离线复现。

任务环境与准备：
Windows 本地环境，安装 Python 3.11 或以上，并确保 sqlite3 标准库可用。
安装 Python 依赖 asyncio 无需额外安装，确保标准库 http.server 可用于启动本地 HTTP 测试服务。
准备空白工作区，生成题目所述的本地注册清单 JSON 样本与可配置状态码、延迟、拒绝连接的测试服务脚本。
确认无外部网络、无真实服务注册中心依赖，所有探测目标均为本机回环地址上的测试服务。

业务要求：
1. 实现注册清单解析与探测任务建模：从本地 JSON 读取实例清单，校验服务名、实例 ID 唯一性、地址格式、期望状态码区间与超时预算合法性，构建每个实例的探测任务描述；非法条目必须以明确业务错误码报告并隔离，不得使整批加载失败。
2. 实现并行探测调度器：在同一轮次内按服务分组并发发起探测，同时受每服务并发上限与每轮总时间预算约束；预算耗尽时必须放弃剩余未启动任务并记录放弃原因，已启动任务不得被简单截断为超时。区分预算内未启动、启动后真实超时与连接拒绝三类结果。
3. 实现实例状态机与租约演进：探测成功、连续失败、心跳租约到期分别驱动实例在健康、可疑、失联间迁移，并维护连续失败计数与下一次探测时间；状态迁移必须依据本轮完整结果与持久化租约计算，重启后不得凭内存残留决定状态。
4. 实现退避与再探测计划：可疑与失联实例按连续失败次数计算指数退避间隔（带确定性的上限与抖动规则），健康实例按基础间隔探测；再探测时间必须与每服务并发上限和总预算共同裁决，预算不足以覆盖全部到期任务时按优先级与到期顺序取舍。
5. 实现持久化状态与强制终止后的恢复：把实例状态、连续失败计数、租约到期时间、退避截止时间与最近一轮调度摘要原子写入 SQLite；进程被强制终止后，恢复路径依据持久化状态重建调度计划，识别未完成轮次并补算，不得承诺强制终止时生成退出报告。
6. 实现并发一致性与幂等：同一注册表允许多个调度进程并行运行，通过 SQLite 事务与文件锁保证同一实例同一轮次只被一个进程推进状态，重复提交相同轮次结果必须幂等，不得出现状态被回退或连续失败计数被重复累加。
7. 实现错误码与异常链路：探测中出现连接拒绝、响应超出单任务超时、响应状态码不符合期望、目标返回畸形响应时分别映射到不同业务错误码并在结果中保留可诊断字段；单个探测异常不得污染同轮其他实例结果或中断调度主循环。
8. 提供命令行接口与结果验证工具：支持 load、run、status、verify 子命令，status 以稳定排序输出 JSON 状态快照，verify 校验持久化状态与调度摘要的一致性；使用固定本地样本与测试服务执行两次运行，输出结果与摘要必须完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本与测试服务验证并行调度的预算取舍、状态演进与强制终止后恢复的一致性。
