团队准备新建一个项目，从零实现一个面向本地数据库检查点与 WAL 回放领域的领域数据编辑与操作应用，用于在确定性样本上复现 WAL 增量应用、检查点链演进与崩溃后恢复裁决的完整链路，并支持两代检查点格式互操作。本地样本目录给出：一组按序列号递增的 WAL 段（JSON 行格式，每行含事务号、表名、行键、操作类型、变更前后镜像、依赖的检查点代数与内容摘要哈希），以及两代检查点文件——v1 为单文件 JSON，记录检查点代数、已应用事务水位、各表行数摘要与相对保存秒数；v2 为分片 JSON 加 SQLite 元数据库，记录回放代数、绝对保存毫秒戳、各表行版本摘要与失效墓碑。应用还需支持用户对 WAL 行与检查点元数据的编辑操作，编辑后须精确判定哪些回放结论与行版本需要失效重算。所有时间判定只依赖可注入逻辑时钟毫秒值，运行环境为 Windows，不依赖任何真实数据库服务。

任务环境与准备：
Windows 10/11，安装 Python 3.11 或 3.12，并确认 python --version 可执行
执行 python -m pip install --upgrade pip 后安装依赖：python -m pip install numpy
确认标准库 sqlite3 可用（Python 内置），执行 python -c "import sqlite3, numpy; print(sqlite3.sqlite_version, numpy.__version__)" 查看版本
在空工作区根目录准备 samples 目录，放入由本地脚本确定性生成的 WAL 段样本、v1 检查点 JSON 与 v2 分片 JSON 加 SQLite 元数据样本
确认工作区磁盘可写，用于生成临时文件与 SQLite 数据库文件

业务要求：
1. 实现 WAL 段与两代检查点的解析校验：事务号在段内严格递增且跨段连续、操作类型枚举闭合、变更前后镜像与操作类型匹配、依赖的检查点代数在当前链中存在、内容摘要与行内容一致、v2 分片哈希与回放代数单调；非法行、断链与摘要不符须分别映射到不同业务错误码且不写入任何持久化状态。
2. 实现两代检查点的跨版本合并与统一回放基线构建：同一检查点代数在两代文件中同时存在时，依据声明的逻辑时钟与回放代数裁决最新版本，逻辑时钟相同则按来源格式优先级；v1 相对保存秒数在注入逻辑时钟下换算为绝对保存时刻并记录换算标度、舍入方向与换算前原始值，合并结果须逐项保留来源版本与裁决依据。
3. 实现从检查点出发的增量回放与行版本维护：按事务序把插入、更新、删除增量真实应用到 SQLite 表，维护每行版本号、来源事务号与删除墓碑；回放结果必须与从空库全量重放同一 WAL 链得到的结果逐行逐值一致，出现不一致时输出首个差异行的行键、两条路径的值与来源事务号。
4. 实现基于注入逻辑时钟的回放延迟计算与精度记录：每个事务的回放延迟由其提交时刻与注入逻辑时钟的回放时刻换算得到，所有回放完成时刻与检查点生成间隔只依赖注入逻辑时钟毫秒值；同一逻辑时钟序列下重放必须得到逐位一致的延迟序列，逻辑时钟回拨超过容差时返回独立业务错误码。
5. 实现用户对 WAL 行的编辑操作与依赖失效闭包裁决：编辑可修改或删除某 WAL 行，沿“WAL 行—事务—检查点代数—回放行版本—延迟记录”的引用关系计算受影响闭包，精确标记哪些行版本、检查点引用与延迟记录需重算、哪些可安全复用；未受影响事务的回放结果与延迟记录必须逐字保持不变，失效清单须给出触发来源与被否决的复用依据。
6. 实现检查点创建与整体替换的版本变化识别：按当前已应用水位生成新检查点并转换为 v2 格式登记，提交时以临时表加版本号整体替换当前检查点指针而非逐条覆盖；收到新检查点包时比较清单版本号、回放代数下限与各分片哈希判定完整替换、增量追加或无需操作，版本回退必须被拒绝。
7. 实现强制终止后的恢复裁决：把已应用水位、已提交事务标记、检查点指针、回放延迟记录与未完成事务登记以事务原子写入 SQLite；进程在回放、编辑失效或检查点提交中途被强制终止后，恢复路径依据持久化状态识别已提交与半提交状态，只重放缺失事务且不得重复计入已完成延迟记录，恢复后结果与不中断运行逐行一致。
8. 实现多进程并发一致性与可重复命令行验证：允许多个回放或恢复实例并行处理同一 WAL 链，通过 SQLite 事务与文件锁保证同一事务号同一检查点版本只被应用一次、同一检查点代数只被提交一次，重复应用同一 WAL 段必须幂等；提供 load、apply、edit、checkpoint、resume、status、verify 子命令，status 以稳定排序 JSON 输出当前水位、检查点代数、已应用事务数与延迟摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

使用本地 WAL 与两代检查点样本验证增量回放一致性、编辑失效闭包、版本替换与中断恢复，并校验幂等与错误码。
