项目从空白的工作目录启动，需要为多级目录配额管理场景实现一个可集成的诊断组件，并通过完整示例验证配额回滚扣减、规则增量失效与中断恢复的一致性。所有输入由随工程交付的固定种子脚本在 Linux（WSL Ubuntu）本地确定性生成：目录清单记录目录 ID、父目录 ID 与基础配额；文件写入流按注入逻辑时钟逐条描述写入事件（事件序号、目录 ID、文件键、字节数、内容摘要）；配额规则以两代快照并存，v1 为单文件 JSON 使用相对生效秒数，v2 为分片 JSON 加 SQLite 元数据库使用绝对毫秒偏移与规则代数。组件需要把两代规则合并为统一视图，在父子目录链上回滚扣减配额，并根据规则变化计算受影响子树的失效闭包。

任务环境与准备：
Linux（WSL Ubuntu）环境，安装 Python 3.10 或更高版本。
使用 pip 安装依赖：SQLite 为标准库；Flask 可选，安装命令为 pip install Flask。
使用随题交付的固定种子脚本在本地生成样本文件到指定目录，不依赖外部网络或服务。

业务要求：
1. 实现目录清单、文件写入流与两代配额规则快照的解析校验：校验目录 ID 唯一且父目录引用存在并无链路回环、基础配额为正整数或按文件键声明扩展配额、写入事件序号严格递增、注入逻辑时钟为非负整数且单调不降、内容摘要与字节数一致，违规输入映射到不同业务错误码并保留可诊断字段。
2. 实现两代规则的跨版本合并与统一配额视图构建：同一规则键在 v1 与 v2 同时存在时依据声明的规则代数与逻辑时钟裁决最新版本，逻辑时钟相同则按来源格式优先级，并记录每个规则节点的来源版本与裁决依据，使合并后的配额窗口边界在任意加载顺序下保持一致。
3. 实现基于父子目录回滚的配额账本扣减与审计：每次文件写入按写入内容摘要与字节数从目标目录开始沿父链回滚扣减各层级剩余配额，剩余配额不足时记录扣减失败原因并停在首个失败目录节点，扣减与审计记录在同一 SQLite 事务内原子提交，确保账本总消耗与写入事件流逐项对账一致。
4. 实现规则增量更新引发的子树失效闭包与重算裁决：以补丁形式提交规则变更、目录重命名或失效墓碑，沿目录依赖边计算受影响子树闭包，精确标记哪些目录的配额账本与审计结论需重算、哪些可安全复用，未受影响的目录不得重算，重算结果必须与全量单次计算逐步一致。
5. 实现符合注入逻辑时钟的配额窗口切换与规则代际推进：系统所有窗口判定与规则生效时刻只依据注入的逻辑时钟毫秒值，不读取系统墙钟，v1 相对生效秒数在注入逻辑时钟下换算为绝对毫秒并记录换算标度、舍入方向与余量，使同一逻辑时钟序列下重复运行得到逐位一致的裁决序列。
6. 实现规则快照整体替换的版本变化识别与并发隔离：收到新规则包时比较清单版本号、规则代数下限、分片哈希与规则键集合摘要，判定完整替换、增量追加或无需操作，整体替换采用临时表加版本号切换当前指针而非逐条覆盖，版本回退必须拒绝，正在执行的写入块必须绑定其开始时的规则版本。
7. 实现强制终止后的恢复一致性：将配额账本指针、每个目录剩余配额、规则合并裁决、失效闭包标记、审计记录水位与逻辑时钟水位以单事务原子写入 SQLite，进程在解析、合并或扣减中途被强制终止后，恢复路径依据持久化状态只重放未提交部分，不重复扣减或改变已确认审计结果。
8. 实现多进程并发一致性与可重复命令行接口：允许多个写入处理和规则更新进程并行操作不同目录，通过 SQLite 事务与文件锁保证同一写入事件序号同一版本只被处理一次、同一规则快照只被整体替换一次，并支持 load、merge、write、patch、resume、status、verify 子命令。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定种子生成的目录、写入流与两代规则快照验证合并、回滚扣减、失效闭包及恢复一致性，输出账本与审计结果。
