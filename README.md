为句法与依存分析团队从零构建一个本地可运行的领域数据编辑与操作应用，核心问题是多句依存分析任务在多进程并行调度下的资源预算控制与结果一致性。输入是本地样本目录：一份待分析句子清单 JSONL，每条含 sentence id、原始 UTF-8 文本与若干候选依存弧候选文件引用；每个候选文件含该句的候选弧集合，每条候选弧给出 head 词下标、dependent 词下标、依存标签、对数概率与产生该候选的模型阶段名。另有一份标签表 JSON，声明合法依存标签集合与是否允许该标签出现在根节点。工作区为空，需从零创建项目：读取清单与候选文件，按字符下标重建词序列，对每句做依存弧解码得到一棵合法依存树，并支持在多进程并行调度下按句批次处理，同时遵守创建时给定的内存预算与并发 worker 上限。难点在于：解码的贪心或动态规划顺序必须与并行切分无关，分片结果在进程被强制终止后必须可核对与续算，且预算不足时的排队、拒绝与落盘必须有确定行为，最终统计只能来自已提交结果。

任务环境与准备：
安装 Python 3.11 并在工作区创建虚拟环境
安装 FastAPI、uvicorn、NumPy 与 pytest 的兼容版本，版本号写入 requirements.txt
准备本地样本目录：句子清单 JSONL、若干候选依存弧文件、标签表 JSON 与覆盖越界及中断场景的测试输入
确认可在 Windows 本机以多进程方式启动服务并执行确定性演示入口，验收前不预置任何结果文件或数据库

业务要求：
1. 入口接收句子清单、候选文件目录、标签表、并行 worker 数与单批内存预算字节数，校验文件存在、候选弧的 head 与 dependent 下标均为非负整数且不相等、对数概率为有限实数、标签表可解析、worker 与预算为正整数；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不创建任何结果文件、临时目录或数据库。
2. 须按原始文本重建词序列并以 Unicode 字符下标定位词，句子清单与候选文件中对同一 sentence id 的词数、词形与下标必须一致；不一致时返回 E_SEG 业务码并定位 sentence id 与首个不一致下标，禁止用候选文件的下标覆盖原始文本的切分结果。
3. 依存解码须保证输出是恰好一棵合法的依存树：除根外每个词恰有一个 head、无自环、无环、根节点唯一且其标签在标签表中被声明允许出现在根；解码按候选弧对数概率累加最大化的确定性动态规划进行，同分时按 dependent 下标升序与 head 下标升序稳定选择，禁止在解码中引入随机性或并行归约顺序依赖。
4. 并行调度须将句子划分为可分片单元交给多进程处理，每个进程同时驻留的候选弧记录数受内存预算约束；驻留量须由候选文件实际记录的字段数与数值得到，超预算时先把已完成句子结果原子落盘再继续读取下一批，禁止用固定 sleep 或与真实记录量无关的常量冒充预算控制，worker 数超出上限时返回 E_PARAM。
5. 每个分片完成后须将解码结果以原子替换方式写入不可分割的分片文件，并在 SQLite 中以句子粒度提交完成标记与结果内容哈希；进程被强制终止后重启须核对分片文件哈希与数据库标记，重算未提交句子且不重复消费已提交句子，恢复后的树结构、得分与快照版本序列须与无中断执行完全一致。
6. 标签表兼容性须在解码与提交中同时生效：候选弧标签不在标签表中时返回 E_TAG 并定位标签与弧；根节点候选弧使用不允许做根的标签时须被排除出根选择而不是使整句失败，且被排除的候选弧数量须计入每句统计，任何输出树的标签都不得越过标签表约束。
7. 每次完整分析须以整体替换方式生成版本化快照，含配置指纹、句子数与分片哈希、逐句树根与得分摘要；读取快照时若检测到数据库版本与磁盘分片哈希不一致、版本变化或残留旧分片，须返回 E_STALE 并定位到句子与分片，禁止把旧分片汇入统计。
8. 须提供确定性本地演示入口：固定 worker 数、预算与样本及一组覆盖合法、越界与分片中断的输入，跑出各句依存树、解码得分、被排除根候选数、分片数、恢复前后一致性与快照版本序列的可重复结果，并给出可用等价参数复现的命令与请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证并行解码结果、预算控制与中断恢复后的树结构和统计一致。
