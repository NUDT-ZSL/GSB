当前是空白工作区，需要从零实现一个本地列式聚合计算引擎及其可复现实验环境，核心业务目标是在固定内存预算下执行分组聚合与滑动窗口计算，并在内存溢出、批次损坏与进程强制终止等异常注入下仍能给出可复现、可追溯的裁决。本地 JSON 样本给出列式批次文件（每批含批次序号、行数、按列存储的整数/浮点/布尔数组、批次内容摘要）、查询描述（分组键、求和均值方差计数等聚合表达式、窗口行长与步长）、执行配置（引擎常驻内存预算 MiB、单批次最大行数、溢出落盘目录、定点标度、浮点容差、逻辑时钟步进）以及本地注入清单（在读取、聚合、窗口与写出阶段注入受控异常）。引擎需流式处理批次，在内存预算内维持算子状态，预算不足时把部分状态真实溢出到本地磁盘并在后续批次按需回读，中途被强制终止后依据持久化状态恢复，不得凭内存残留推断进度。所有耗时与窗口边界均基于可注入逻辑时钟，不读取系统墙钟。

任务环境与准备：
安装 Python 3.11 或以上，并在虚拟环境中安装 NumPy 与 pytest，版本以 requirements.txt 固定。
创建空工作区目录结构，包含 samples 样本目录、workspace 持久化目录与 spill 溢出目录，全部位于工作区根内。
准备固定随机种子生成的列式批次 JSON 样本、查询描述与注入清单，样本内容在同一提交内保持字节级一致。
确保 Windows 本地文件系统支持原子重命名与文件锁，无需任何容器、外部服务、GPU 或网络依赖。

业务要求：
1. 实现批次文件、查询描述与注入清单的解析校验：列名唯一、各列数组长度与批次行数一致、批次序号严格递增、批次内容摘要与列内容一致、分组键与聚合表达式引用的列存在且类型可比、窗口行长与步长为正整数且步长不大于行长、内存预算为正整数 MiB；非法输入必须返回明确业务错误码（如 E_BAD_BATCH、E_BAD_QUERY），且不写入任何持久化状态。
2. 实现双通路数值聚合：同一输入可按配置走 float64 通路或定点整数通路，定点通路记录每项换算的标度与舍入方向并保留换算前原始浮点值；两条通路对同一输入重复运行必须逐位一致，NaN 与无穷输入须按统一规则处理并记录，不得静默丢弃。
3. 实现受控内存预算下的分组聚合状态演进：每个分组维护计数、求和、平方和与均值，引擎常驻内存不得超过配置预算；超出预算时须把最久未更新的分组状态真实序列化溢出到本地磁盘文件，后续批次按需回读后再继续更新，溢出不得改变聚合结果。
4. 实现滑动窗口计算的中间缓冲与跨批次补齐：按分组维护按行序的窗口缓冲，窗口行长与步长决定窗口归属，跨批次的部分窗口在后续批次补齐后才产出最终结果；窗口结果须与对同一序列执行全量重算得到的唯一真值逐位一致，否则输出首个分歧窗口与中间值。
5. 实现内存溢出的真实资源机制与可诊断记录：溢出落盘须使用真实文件写入并以原子重命名落盘，回读须校验文件摘要；统计每轮溢出与回读的分组数、字节数与耗时（以注入逻辑时钟计量），当预算极小导致单分组状态无法容纳时须进入明确失败态并返回独立业务错误码，而不是以延迟或线程超时冒充内存隔离。
6. 实现注入清单驱动的受控异常与异常链路隔离：在读取、聚合、窗口与写出四个阶段分别注入畸形列数组、摘要不匹配、定点溢出、溢出文件被篡改、回读摘要失败等异常，每种异常映射到不同业务错误码并保留可诊断字段（批次序号、列名、分组键）；单个异常批次与受影响分组进入失败态，其他分组的已提交结果不得被回滚或污染。
7. 实现持久化状态与强制终止后的恢复一致性：把算子水位、已提交批次摘要、每分组状态版本、溢出文件清单与逻辑时钟水位以事务原子写入 SQLite；进程在聚合或溢写中途被强制终止后，恢复路径须识别已提交批次与半提交状态，只重放缺失批次、只清理无引用溢出文件，不得重复累加已提交分组状态，并承认强制终止可能留下需据此清理的半写产物而非承诺一定生成退出报告。
8. 实现多进程并发一致性与可重复命令行验证工具：多个执行实例并行处理同一计划的不同批次时，通过 SQLite 事务与文件锁保证同一批次同一分组状态版本只提交一次、同一溢出文件只被物化一次，重复提交相同批次结果必须幂等，读取方只能看到完整已提交结果；提供 load、execute、resume、status、verify 子命令，status 以稳定排序 JSON 输出每分组状态版本、溢出与回读统计、失败态，verify 校验持久化状态与结果摘要的一致性，使用固定样本执行两次的输出完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地样本验证定点与浮点聚合结果、真实内存溢出落盘回读、注入异常的失败隔离及强制终止后的恢复一致性，两次运行输出完全一致。
