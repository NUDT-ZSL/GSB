当前是空白工作区，需要从零实现一个本地网络接口中断合并（interrupt coalescing）参数核算与吞吐偏差账本引擎，交付数据处理管线与结果验证工具。本地 JSON 样本给出：网卡与队列清单（网卡名、队列序号、队列权重、最大中断速率上限、当前合并参数），合并参数集（每队列的 rx-usecs 微秒、rx-frames 帧数、tx-usecs、tx-frames），流量轨迹（记录序号、队列序号、注入逻辑时钟微秒、到达帧数、帧字节数），以及核算配置（微秒与帧数换算的定点标度、浮点容差、每队列中断预算、误差上界预算、逻辑时钟步进）。核心业务问题是：中断合并的生效中断次数由微秒窗口与帧数阈值共同决定，二者换算到统一时间尺度后产生的舍入误差会沿队列累计，进而使吞吐核算、中断预算判定与参数调优结论发生偏差；必须让每次换算与累计可追溯，并在强制终止后从持久化账本续算。

任务环境与准备：
安装 Python 3.11 及以上版本，并安装 numpy 与 pytest（以本地 wheel 可离线安装为准）
确认工作区可创建本地目录与 SQLite 文件，样本 JSON、核算配置与崩溃注入描述均由本地确定性生成脚本产出
在 Windows 终端设置 UTF-8 输出，运行前确认无残留的 SQLite 锁文件与临时落盘目录

业务要求：
1. 实现网卡队列清单、合并参数集与流量轨迹的解析校验：网卡名与队列序号组合唯一、队列权重为正整数、最大中断速率上限为正整数、rx-usecs 与 tx-usecs 为非负整数微秒、rx-frames 与 tx-frames 为非负整数、记录序号严格递增、到达帧数非负、帧字节数为正整数；非法输入必须返回明确业务错误码并保证不写入任何持久化状态。
2. 实现微秒窗口与帧数阈值到统一中断判定尺度的定点换算：把每队列的微秒参数按声明标度换算为定点时间单位，把帧数阈值换算为在给定平均帧到达间隔下的等效时间单位，每次换算登记标度、舍入方向与被舍弃的余量，未满一个定点单位的余量须逐队列保留并在后续累计中参与，相同输入重复换算必须逐位一致。
3. 实现合并生效的中断次数推演与吞吐核算：按注入逻辑时钟逐记录推进，微秒窗口到期或帧数阈值达成即计一次生效中断并重置对应队列的窗口与帧计数，两种触发同时命中须去重只计一次并记录触发来源；据生效中断次数与到达字节数核算每队列吞吐与有效中断速率，结果按固定聚合顺序与整数运算规则计算。
4. 实现定点通路与 float64 通路的偏差账本对照：对每队列的有效中断速率、吞吐与窗口占用同时计算定点通路值与 float64 通路值，记录两通路数值、绝对偏差与相对偏差，并累计每次换算与乘加的误差上界；当两通路偏差超过给定容差时必须输出首个分歧记录、分歧队列、被舍弃余量与其双通路中间值，不得仅报告最终不一致。
5. 实现中断预算判定与偏差归因：按每队列中断预算与误差上界判定是否在预算内，当某队列有效中断速率超出预算时须判定该超出是由真实流量超限还是由累计换算余量造成，输出余量累积占总超出的比例、参与累计的记录区间与首个使偏差越过阈值的记录；归因结论必须基于当时已提交的账本，不得在重算后倒推。
6. 实现队列权重与合并参数变更后的账本失效闭包：当某队列权重或合并参数被修改时，沿该队列的账本记录计算受影响闭包，精确标记哪些中断计数、吞吐结论与归因条目需要重算、哪些可安全复用；未受影响队列的账本与结论必须逐字段保持不变，失效决策须输出触发来源、受影响的记录区间与被复用的账本条目。
7. 实现强制终止后的恢复与参数版本整体替换：把队列参数版本指针、已提交记录水位、每队列窗口与帧计数、余量保留表、误差上界与逻辑时钟水位以事务原子写入 SQLite，参数提交以临时表加版本号整体替换指针并识别版本回退；进程在记录推进或参数替换中途被强制终止后，恢复路径须识别已提交记录与半提交状态，只重放未完成部分且不得重复计入中断次数或重复累计余量。
8. 实现多进程并发一致性、幂等提交与可重复命令行：多个核算实例并行推进同一网卡不同队列时，通过 SQLite 事务与文件锁保证同一队列同一记录同一版本只提交一次、余量保留表不被并发重复累加，重复提交相同记录结果必须幂等；提供 load、run、diagnose、resume、status、verify 子命令，status 以稳定排序 JSON 输出记录水位、每队列中断计数、余量累计与偏差标记。
