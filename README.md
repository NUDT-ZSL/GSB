当前为空白工作区，需要从零构建一个面向 Windows 本地环境的分库分表路由领域组件，用于教学与排障演示。用户以本地 JSON 配置文件描述逻辑表的分片规则：分片键（单列或多列组合）、分片算法（取模、范围、一致性哈希环）、物理库数量与每库物理表数量，以及若干路由规则之间的依赖关系（如某逻辑查询的路由结果由其他路由单元派生）。组件须把逻辑 SQL 谓词编译为分片路由计划，定位目标物理库表，并在分片规则版本演进时准确推导哪些路由缓存条目失效。同时须支持异常注入与可复现验证：同一输入在多次运行中必须得到逐字节一致的路由计划，注入分片规则损坏、哈希环冲突与元数据版本不一致三类异常时须以明确业务码报告。

任务环境与准备：
安装 Python 3.11 或以上，确保标准库包含 sqlite3 与 tkinter；无需联网或第三方索引服务。
创建空白工作目录，准备本地确定性样本分片配置 JSON、样本表结构与演示脚本入口文件，均由本任务随附内容生成。
确认本地回环端口未被占用以便未来扩展，当前版本不依赖任何网络服务；Tkinter 界面在无显示环境下可跳过并以命令行验证。
准备异常注入参数样本（损坏配置、冲突哈希环参数、版本不一致元数据）作为输入文件或启动参数，不改动源码。

业务要求：
1. 实现分片配置加载与强校验：从本地 JSON 读取逻辑表、分片键列、分片算法参数、物理库表数量与路由单元依赖关系；校验表名唯一、分片键列存在于表结构、库数为正整数且表数为正整数、取模基数大于零、范围边界单调递增、一致性哈希环上虚拟节点权重为正整数、依赖引用存在且无环；任一不合法须以 E_CONFIG 整体拒绝加载并输出出错字段路径，不得部分生效。
2. 实现逻辑谓词的规范化与分片键提取：支持等值、IN 列表、范围与 AND 组合谓词，识别谓词中是否包含完整分片键；同一语义谓词（空白、大小写、IN 顺序差异）须得到相同规范化文本与稳定路由标识；不含完整分片键的谓词须判定为广播查询并在计划中显式标注，无法解析的语法返回 E_SQL 并指明位置。
3. 实现三种分片算法的确定性路由：取模算法按分片键整数化的稳定哈希取模定位库表，范围算法按单调边界定位并处理边界值归属，一致性哈希按虚拟节点环查找顺时针首个节点；三种算法须输出目标库表集合、算法名、所用参数版本与路由理由；相同分片键多次路由必须得到同一目标集合，算法内部不得依赖字典或哈希表遍历顺序。
4. 实现路由缓存与分片规则版本识别：路由缓存以表名、规范化谓词、分片规则版本与哈希环版本为键，规则或环参数变更后版本号单调递增，旧缓存条目须整体失效而非逐条修补；缓存命中须校验条目记录版本与当前版本一致，不一致返回 E_CACHE 并触发重算，缓存容量超限时按确定性规则逐出。
5. 实现路由单元依赖图与失效传播：在路由单元引用关系上维护依赖图，当某逻辑表分片规则或某路由单元结果变化时，沿依赖图推导全部直接与间接下游单元并按拓扑序使其缓存失效；删除仍被引用的分片规则须拒绝并返回 E_DEPEND 列出引用者，失效集合与传播顺序须写入路由报告且重复计算得到相同集合。
6. 实现异常注入与可复现验证：支持以命令行参数注入分片规则文件损坏、哈希环上同权重节点冲突、元数据版本不一致三类异常，分别以 E_CONFIG、E_RING、E_VERSION 业务码报告并写入结构化日志；注入仅改变输入文件或参数，不修改源码；同一正常输入在两次独立运行中须产出逐字节一致的路由计划与报告。
7. 实现路由会话快照与整体替换恢复：快照持久化分片配置版本、哈希环版本、依赖图版本、缓存条目与路由历史摘要；重新打开快照时须先比较快照中的配置版本与依赖图版本同当前会话是否一致，不一致须整体替换当前配置、依赖图与缓存状态而非增量合并，并稳定列出差异项。
8. 提供 Tkinter 界面与可集成的组件 API 及完整示例：界面展示分片规则、目标库表映射、路由理由、依赖边、本轮失效集合与业务码，渲染顺序稳定；以 Python 包暴露配置加载、谓词规范化、路由、缓存、依赖失效、快照保存恢复与验证接口，附带本地确定性样本配置与演示脚本，顺序执行正常路由、规则变更后增量路由、快照恢复后重放三个场景并输出结构化总结。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证三种分片算法路由、依赖失效传播、快照整体替换恢复及三类异常业务码，输出稳定计划与报告。
