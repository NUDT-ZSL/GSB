当前是空白工作区，需要从零实现一个本地 DNS 解析缓存系统及其误差诊断能力，Windows 上以确定性样本运行，不依赖真实域名或线上解析器。本地还提供一个可编程 DNS 测试服务器（Python 实现，监听回环地址，按查询名与类型返回预设应答、分片 TTL 秒数、NXDOMAIN/NODATA、畸形报文与延迟），由样本脚本启动。核心业务问题是：缓存 TTL 既有 v1 快照里的剩余秒数，也有 v2 快照里的绝对毫秒过期时间戳，还有上游应答携带的 TTL 秒数需要按可注入逻辑时钟换算成绝对过期时刻；同一域名的多级缓存（权威段、递归段、本地段）在换算、取最小值与剩余时长比较中会累积舍入与截断误差，使“是否过期”“是否该回源”的边界判定出现翻转，进而让解析结果与命中率统计不一致。系统需在全链路记录每个 TTL 的换算标度、舍入方向与误差上界，并给出可追溯的误差来源链与结论翻转追溯。

任务环境与准备：
Windows 上安装 Python 3.11 或以上，并创建独立虚拟环境。
在虚拟环境中安装 dnslib 与 pytest，用于构建回环 DNS 测试服务器与运行本地样本测试。
确认 SQLite3 可用（Python 标准库自带），工作目录具备可写权限以创建快照目录、对象目录与账本数据库。
准备本地确定性样本：两代缓存快照文件、查询模板与逻辑时钟步进表，以及启动回环 DNS 测试服务器的脚本与预设应答清单。

业务要求：
1. 实现 v1（单文件 JSON，域名、类型、TTL 剩余秒数、应答记录、权威标记）与 v2（分片 JSON 加 SQLite 元数据，规范域名、按类型记录集、绝对毫秒过期时间戳、否定缓存标记、缓存代数）两代快照的解析与校验：域名规范化后唯一，TTL 剩余秒数为非负整数，v2 分片哈希与缓存代数单调性须校验；非法条目返回明确业务错误码且不写入任何持久化状态。
2. 实现跨版本快照合并与统一多级缓存索引：同一域名同一类型在两代快照中同时存在时，依据快照声明的逻辑时钟与缓存代数裁决最新条目，逻辑时钟相同则按来源格式优先级；合并后每条目须保留来源版本、原始时间表示、原始 TTL 值，并记录裁决依据供后续误差溯源引用。
3. 实现 TTL 换算与精度记账：v1 剩余秒数与上游应答 TTL 秒数在注入逻辑时钟下换算为绝对过期毫秒时刻，每次换算登记标度、舍入方向与丢弃的亚毫秒余量；权威段、递归段、本地段多级同域名条目的过期时刻须按固定次序取最小值，每次比较记录参与条目与比较结果，不得把取最小值写成无序归并。
4. 实现误差上界累计与精度敏感标记：对每条目与每个域名的最终过期时刻累计换算与比较的误差上界；当两条目剩余时长之差小于给定容差且“是否过期”或“是否回源”的判定依赖该差值时标记为精度敏感，输出误差来源链（含域名、记录类型、换算与比较步骤、余量）以及若改用毫秒级精确表示是否会翻转判定的结论。
5. 实现多级缓存查询与回源链路：按精确键与记录类型命中缓存，支持 CNAME 链逐跳解析并缓存每一跳；未命中或已过期时通过本地 DNS 测试服务器回源，回源应答的 TTL 须按逻辑时钟换算入缓存；命中、过期回源与否定缓存（NXDOMAIN/NODATA）须在结果中以不同判据区分，CNAME 解析不得跳过中间跳。
6. 实现快照整体替换的版本变化识别：收到新快照包时比较清单版本号、缓存代数下限、各分片哈希与条目摘要，判定完整替换、增量追加或无需操作；整体替换须整体切换当前缓存快照指针而非逐条覆盖，版本回退须被拒绝并返回业务错误码，替换后未受影响条目的过期时刻与精度标记必须逐项保持不变。
7. 实现持久化状态与强制终止后的恢复：把缓存快照指针、迁移决策、换算与比较的精度账本、替换审计与逻辑时钟水位以事务原子写入 SQLite；进程在合并、替换或查询回源中途被强制终止后，恢复路径须识别未提交步骤并只重放未完成部分，重放后精度账本登记序号与误差上界必须与未中断运行逐项一致。
8. 实现多进程并发一致性与诊断命令行：允许多个查询进程与快照替换进程并行，通过 SQLite 事务与文件锁保证同一快照版本只提交一次、同一替换请求幂等、查询方只看到完整版本快照；提供 load、resolve、warmup、diagnose、replace、resume、status、verify 子命令，diagnose 以稳定排序 JSON 输出精度敏感条目、误差来源链与结论翻转追溯。
