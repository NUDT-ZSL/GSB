语言学期刊编辑部在初审阶段需要同时阅读每篇投稿的中英文摘要：术语表规定“注意力机制”只能写作“注意力机制（attention mechanism）”首次全称后统一用“注意力机制”，英文摘要必须使用“attention mechanism”，而作者经常在中文摘要中混用“注意力模型”“注意力机制”，英文中混用“attention model”“attention mechanism”；摘要句子动辄五六个定语套叠，编辑很难判断哪一句已经超过可读性上限，更难判断中文的“对……进行研究”与英文“conduct a study on ...”是否承担同样的句法角色。审校人员希望有一个可集成的分析组件，一次输入中英文摘要与术语表，输出每个词的依存树、术语在树中的角色、术语不一致告警、双语句法差异列表与句子复杂度标记，所有结论都要附上可复核的依存路径证据，便于在退修意见中直接引用。

任务环境与准备：
在 Linux（WSL Ubuntu）工作区从零创建项目目录与程序入口，准备 Python 运行环境，并安装 NumPy 用于句法距离与树深度等数值计算。
把期刊术语表与本地摘要样本（含人工标注的依存关系、术语边界与一致性判断）放入仓库数据目录，运行示例只读取这些本地文件，不访问外部服务。

业务要求：
1. 组件接收一篇稿件的中英文摘要文本与期刊术语表，对中文摘要按标点与句末切句后完成分词与依存句法分析，为每个词输出词形、词性、中心词索引与依存关系标签，中心词索引必须在句内自洽（根词指向自身或统一哨兵值），并按句输出可供打印的树形结构。
2. 对英文摘要完成词性标注与依存句法分析，输出与中文摘要完全相同的字段结构与索引约定，保证同一份分析结果可以按语言无关的方式被下游消费，两段摘要的句子编号从 1 开始独立计数且不得串号。
3. 从中文与英文摘要中识别术语表中登记的专业术语（含全称、缩写与推荐译法），标注每个命中术语在依存树中的句法角色，角色判定必须依据该术语中心词的依存关系与父节点关系推导，而不是按字符位置直接指定，并给出从术语中心词到根的依存路径。
4. 在同一篇摘要内检测同一术语的不同表述：中文全称与缩写的首次出现顺序、同一语义下不同译法并存、英文大小写与单复数变体，均需给出告警级别与发生句子号；术语表未登记但形似术语的字符串不得直接判为不一致，需附上判定理由。
5. 对中英文摘要的依存结构做对齐比较：以术语及其依存角色为锚点，比较中文动词宾语结构与英文介词短语结构、中文定语前置与英文关系从句后置等对应关系，输出差异列表，每条差异指明中文句号、英文句号、两侧依存路径与差异类型，无法建立锚点的句子单独标注为不可对齐而非静默丢弃。
6. 依据依存距离与句法树深度计算每句复杂度指标，标记超过阈值的句子，阈值可配置；当中文句子被标为高复杂度而对应英文句未超标（或反之）时，需在报告中单独列出这种跨语言复杂度不一致，并说明两侧的距离与深度数值。
7. 生成审校报告：汇总术语使用统计（每术语出现次数、首次出现句子与形式）、不一致告警、跨语言句法差异与高复杂度句子，每条问题附所在句子原文与依存路径证据，报告需可按稿件独立输出且同一输入重复运行结果完全一致。
8. 当摘要为空段、中英文句子数量悬殊、术语表条目缺少推荐译法、文本含术语表外的中英混排片段时，组件必须给出明确的降级结论与业务码，不得因单段解析失败而丢弃整篇稿件的其余分析结果，降级项需在报告中可见。

验收：
用人工标注样本核对依存关系、术语角色与不一致告警，并验证跨语言差异列表与重复运行一致性。
