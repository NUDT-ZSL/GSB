当前是空白工作区，需要从零构建一个面向关系与事件抽取标注数据的本地领域数据编辑与操作应用。业务对象是本地确定性生成的抽取样本集合：文本句由固定种子生成（含实体提及与触发词），标注数据以多个版本格式并存——v1 为扁平 JSON（实体提及列表、关系三元组列表、触发词与论元列表，偏移均为字符码点整数），v2 在 v1 基础上引入实体规范化标识、论元角色受控集合、跨句共指引用与逐条置信区间字段，并把关系和事件合并为统一事件图（节点为实体与触发词，边为关系或论元角色）；外部交换格式为行式标注格式（每行一个标注，含类型前缀、起止码点偏移、文本与可选属性）。应用需要在这些格式之间双向迁移、支持对标注的编辑操作（新增与删除实体与论元、修改论元角色、拆分合并事件），并保证迁移与编辑后的事件图语义不变或按显式规则变更且可审计。

任务环境与准备：
确认 Windows 本地具备 Python 3.10 及以上与 pip，安装 NumPy（如 1.26 系列）与标准库即可，无需外部服务或网络账号。
新建空白工作区目录，规划源码、样本、快照与缓存子目录；样本由固定种子本地生成，不依赖任何外部数据集或附件。
准备运行命令的 PowerShell 或命令提示符入口，确认进程可被强制终止以验证恢复与错误阻断场景。

业务要求：
1. 实现 v1 与 v2 内部规范格式的读取器，按版本头分派解析路径并分别校验必填字段、偏移类型（码点整数）与字段类型；对缺失必填字段、偏移非整数、start 大于等于 end、实体或触发词 id 重复分别返回 E_SCHEMA_MISSING、E_OFFSET_TYPE、E_SPAN_INVALID、E_DUP_ID，且错误须指出字段路径。
2. 实现 v1 与 v2 的双向版本迁移器：v1 升级到 v2 时按配置策略补全实体规范化标识与论元角色受控集合校验，并把关系与事件统一为事件图；v2 降级回 v1 时按显式声明的冲突合并规则处理跨句共指与置信区间不可表达的情形并输出丢弃明细；往返后事件图的实体、关系、事件与论元集合必须一致或差异全部登记在明细中。
3. 实现规范格式与行式交换格式的双向映射：导出时按声明的类型前缀、转义与换行规则序列化，导入时按类型前缀重建实体与论元并挂接到正确的事件或关系；任一规范样本导出再导入后，在码点偏移与角色受控集合上必须与导出前一致，不一致返回 E_ROUNDTRIP_MISMATCH 并给出首个差异位置。
4. 实现标注编辑操作与事件图不变式维护：支持新增删除实体提及、修改论元角色、拆分与合并事件；编辑后须保证关系两端实体存在、论元角色属于受控集合、事件触发词恰被一个事件拥有、跨句共指引用可解析，违反分别返回 E_DANGLING_REF、E_ROLE_INVALID、E_TRIGGER_CONFLICT、E_COREF_UNRESOLVED，并附带可审计的编辑日志。
5. 实现受控集合与配置的版本化管理：实体类型、论元角色与关系类型的受控集合连同迁移策略各携带单调递增版本号与内容校验和，加载时识别版本变化并整体替换旧快照而非增量修补；受控集合收缩导致已有标注不再合法时，须输出受影响的标注清单并按配置的宽松或严格模式处理，严格模式返回 E_ONTOLOGY_CONTRACT。
6. 实现跨模块一致性自检与审计：校验迁移、导出导入与编辑三条路径产出的事件图可互相核对、审计日志可重放出编辑后的同一状态、每个论元可追溯到其所属事件与触发词；检测到不一致返回 E_INCONSISTENT 并指出不一致类别与首个定位，禁止用部分可解析的数据继续后续操作。
7. 实现资源上限与异常链路归因：为单样本实体与论元总数、导入文件大小、事件图节点数设可配置阈值，超限时返回 E_RESOURCE_LIMIT 或按明确策略降级为仅保留实体层并标记降级类别；解析错误、迁移错误与编辑错误须沿链路归因到具体版本、格式与标注位置，未被归因的异常须汇总到结果报告的未归因段。
8. 提供本地可交互的编辑与操作应用：展示当前格式版本、受控集合版本、事件图节点与边、迁移往返报告、编辑日志与最近业务错误码，允许在 v1、v2 与行式视图之间切换，并触发一次演示：加载本地确定性样本，执行一次迁移往返、一次编辑与一次受控集合收缩，输出可重复的审计报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
