团队第一版推理引擎已支持自回归生成，但遇到长上下文场景的显存碎片与容量账本问题，当前工作目录没有任何实现或样本，需要从零交付一个 KV 缓存分层换出的定点账本与中断恢复裁决引擎。业务对象由固定种子脚本确定性生成：请求轨迹逐条给出 seq_id、max_len、当前已生成 token 数、层级列表、每层 KV 条目字节大小；显存配置声明可用显存总字节、分层容量比例、每轮换出字节预算与并发换出上限；换出策略以两代格式并存，v1 为单文件 JSON 记录相对生效秒与扁平阈值，v2 为分片 JSON 加 SQLite 元数据记录绝对逻辑毫秒、策略代数与失效墓碑。引擎需在注入逻辑时钟下把超限 KV 条目按策略从 HBM 逐层换出到本地 NVMe 模拟文件，并登记每笔换出的定点字节账本与误差上界，进程被强制终止后恢复不得重复计账。

任务环境与准备：
Linux（WSL Ubuntu）环境，Python 3.10+，安装 numpy 和标准库 sqlite3，工作区从空目录开始。
固定种子脚本确定性生成输入 JSON 与样例，所有文件保存在本地当前目录。

业务要求：
1. 实现请求轨迹、显存配置与两代换出策略快照的解析校验：seq_id 唯一，max_len 与已生成 token 数为正整数且已生成不超过 max_len，层级列表非空且层标识合法，KV 条目字节大小为正整数，显存总字节大于各层容量之和，v1 相对生效秒为非负整数且换出阈值为有限正数，v2 分片哈希与 SQLite 元数据中策略代数单调；任何输入畸变或分片摘要不匹配必须返回独立业务错误码且不产生换出动作。
2. 跨版本合并两代换出策略并构建统一分层视图：同一策略键在 v1 与 v2 同时存在时依据声明的逻辑时钟与策略代数裁决最新版本，逻辑时钟相同按来源格式优先级裁决且记录被否决来源；合并后每条策略保留来源版本、原始时间表示、换出阈值与误差传播所依赖的代数，v1 相对秒在注入逻辑时钟下换算为绝对逻辑毫秒并登记舍入方向。
3. 在注入逻辑时钟下按请求逐 token 累积 KV 缓存占用并把超限条目分层换出：请求每新增一个 token 先生成该层 KV 字节增量，再比较当前显存总占用与分层容量，超限时按合并后策略从最冷层级选出条目并写入本地 NVMe 模拟文件，换出后实时扣减对应显存字节并物化文件偏移与条目摘要，所有容量与时间判定只使用注入逻辑时钟，不读取系统墙钟。
4. 维护定点字节账本与误差上界累计：把每条 KV 条目字节数、分层容量与换出字节预算按声明定点标度换算为整数，登记每次换算的标度、舍入方向与被舍弃余量，未满一个定点单位的余量按请求分层保留并在后续累加中参与；同一请求轨迹在任意运行次数下账本数值逐位一致，并明确输出每条换出记录的实际字节、定点值与误差项。
5. 在每轮逻辑时间预算与并发换出上限双重约束下调度批量换出：同一轮次内按请求优先级与稳定次序并发执行多笔换出，每个候选换出前先比较剩余显存、剩余字节预算与并发槽位，任一不足即放弃剩余候选并记录放弃原因，严格区分预算内未启动、启动后失败与主动放弃三类结局，已启动换出必须真实完成文件写入与显存扣减，不得以线程超时充当逻辑预算耗尽。
6. 实现换出策略快照的整体替换与进行中请求的版本绑定：收到新快照包时比较清单版本号、策略代数下限、各分片哈希与策略键摘要，判定完整替换、增量追加或无需操作，版本回退必须拒绝并返回业务错误码；整体替换以临时表加版本号原子切换当前策略指针，进行中的请求必须绑定开始时的策略版本直到其下一轮换出，读方不得观察到新旧策略混合的阈值。
7. 实现强制终止后的恢复一致性：把请求水位、已提交换出记录、分层显存占用、换出文件偏移、定点账本、策略版本指针与逻辑时钟水位以单事务原子写入 SQLite，进程在批量换出或策略替换中途被 SIGKILL 后，恢复路径依据持久化状态识别已提交与半提交换出，只重放未完成部分并确保文件位移与显存账本不重不漏，显存总账与各层容量保持守恒。
8. 实现多进程并发一致性与可重复命令行验证：允许多个请求处理进程并行、多个换出调度进程并行，通过 SQLite 事务与文件锁保证同一请求同一代数的换出只入账一次、同一策略指针只被整体替换一次、并发换出文件偏移不重叠且重复提交相同账本幂等；提供 load、merge、evict、resume、status、verify 子命令，status 以稳定排序 JSON 输出每请求显存占用、策略版本、误差上界与恢复裁决。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
