在空白工作区从零构建一个面向 MVCC 可见性语义的领域数据编辑与操作应用，用于编辑多用户共享的记录集合并给出版本可见性判定。本地场景由确定性样本给出：表描述（表名、列与类型）、若干并发编辑会话（每个会话声明事务开始逻辑时钟、隔离级别与有序操作：插入、更新、删除、范围读），以及引擎配置（快照保留上限、逻辑时钟步进、可见性判定容差、GC 水位）。引擎需为每个事务分配读视图（活跃事务集合与快照水位），按行版本链维护创建事务号、删除事务号与提交状态，在编辑会话交替时裁决每行对某事务是否可见，并保证交互式查询与异步 GC 并行时的结果一致。

任务环境与准备：
安装 Python 3.11 及以上，并在项目虚拟环境中安装 SQLite 绑定的标准库与 numpy（用于摘要与批量比对）。
准备本地确定性样本目录：表描述 JSON、并发编辑会话脚本 JSON 与引擎配置 JSON，均随题自造且不含任何外部数据依赖。
确认工作区无既存项目文件；SQLite 数据库文件与版本存储目录由首次运行自动创建。
运行环境为 Windows，不使用容器；所有路径使用本地相对路径，逻辑时钟由测试注入而非系统时钟。

业务要求：
1. 实现场景样本与并发会话脚本的解析校验：表名列名唯一、列类型枚举合法、事务号与逻辑时钟毫秒为正整数且事务开始时钟非降序、操作序列仅含插入更新删除与范围读、隔离级别枚举闭合，非法输入须返回明确业务错误码且不写入任何持久化状态。
2. 实现行版本链与事务提交表：每行版本记录创建事务号、删除事务号、版本逻辑时钟与内容摘要，提交表记录事务号的提交状态与提交时钟；同一事务内对同一行的多次更新须合并为单版本，回滚事务留下的版本必须标记为不可见而非物理删除。
3. 实现快照与读视图构造：为每个事务依据其开始逻辑时钟、活跃事务集合与隔离级别生成读视图，可重复读与读已提交必须得到不同的快照重建规则；同一逻辑时钟下重建读视图必须逐字段一致，活跃事务集合的顺序不得影响判定结果。
4. 实现 MVCC 可见性判定与范围读：按版本链裁决每行对指定事务是否可见，需正确处理删除后重建、更新丢失与回滚版本，范围读返回稳定排序 JSON 并附可见性与判定依据的事务号链；应全部基于持久化版本数据算出，不得读取系统墙钟。
5. 实现基于注入逻辑时钟的交互式编辑与延迟观测：每次编辑操作与查询的延迟以注入逻辑时钟计量，查询须在配置的单次查询逻辑时延预算内完成；同一操作序列在任意运行次数下必须得到逐位一致的版本链与查询结果，逻辑时钟回拨超阈值须返回业务错误码。
6. 实现异步 GC 与快照保留的并发一致性：GC 只能回收不被任何保留读视图引用且事务号低于 GC 水位的版本，回收期间并发查询不得看到版本链断裂或读到被回收版本；GC 数量与保留原因须可查，且回收与查询不得互相阻塞到超出逻辑时延预算。
7. 实现强制终止后的恢复与多进程幂等：把事务提交状态、行版本链水位、读视图注册表与 GC 水位以事务原子写入 SQLite，并采用临时表加版本号整体替换当前快照指针；进程被强制终止后恢复路径须识别未提交事务与半写入版本，只重放缺失步骤且不得重复提交，多实例并发提交须幂等。
8. 提供命令行编辑应用与可重复验证：支持 edit、read、gc、resume、status、verify 子命令，read 以稳定排序 JSON 输出可见行、判定依据与快照水位，status 输出版本链长度、读视图注册数与 GC 回收数；异常链路覆盖引用不存在的事务号、过期快照与版本摘要不匹配。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
