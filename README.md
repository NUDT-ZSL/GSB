当前为空白工作区，需要从零构建一个面向 Windows 本地环境的日志结构存储引擎组件，用于教学与排障演示。引擎以追加式日志段文件持久化键值记录，每条记录包含格式版本号、操作类型、键、值、毫秒级逻辑时间戳与校验和；引擎支持基于逻辑时钟的快照点，允许从任意快照点增量重放日志以恢复状态。业务核心是：当键的写入导致派生视图（如按前缀的键计数、二级索引条目）失效时，须沿依赖图准确推导出受影响视图并使其缓存失效，同时将一次完整恢复会话（日志段集合、快照点、依赖图与失效轨迹）持久化。用户通过命令行交互执行写入、快照、恢复与诊断，须在段文件尾部截断、校验和损坏、依赖成环与快照版本缺失等异常下给出确定业务码。全部输入为本地文件与本地确定性脚本生成的样本，不依赖网络、数据库或外部服务。

任务环境与准备：
安装 Rust 稳定工具链（rustc 与 cargo，建议 1.75 及以上）并可在命令行调用 cargo build 与 cargo test。
在空白工作区执行 cargo init 创建库与二进制目标，在 Cargo.toml 中添加 serde 与 serde_json 依赖（版本自定），全程离线可用本地 cargo 缓存。
准备本地确定性样本：由示例脚本生成若干日志段文件、一份依赖图定义 JSON 与一份会话快照 JSON，作为演示与异常注入的输入。
确认 Windows 命令行可运行生成的可执行文件并读取 stdin 命令，无需网络、数据库或外部服务。

业务要求：
1. 实现追加式日志段的记录编码与严格解码：每条记录采用长度前缀，头部含整数格式版本号、操作类型、键长度、值长度、毫秒逻辑时间戳与校验和；解码时校验长度字段自洽、校验和匹配、版本号属于受支持集合，非法记录须以 E_LOG 业务码报告并给出段文件路径与字节偏移，解码结果的顺序仅由段文件字节顺序决定。
2. 实现基于逻辑时钟与快照点的增量重放恢复：引擎维护单调递增的逻辑时间戳，用户可显式创建快照点记录当前重放位置与状态摘要；恢复时只重放快照点之后的记录，快照点之前的段文件内容视为已持久化，若快照点引用的段文件缺失或逻辑时间戳不连续须返回 E_SNAPSHOT 并拒绝恢复，禁止静默回退到更早位置。
3. 实现派生视图依赖图与增量失效传播：用户可声明派生视图（如按前缀的键计数、二级索引条目）及其依赖的基键或前缀；当基键被写入、删除或过期时，沿依赖图推导直接与间接受影响视图，按确定的拓扑顺序使其缓存条目失效并递增视图版本号，传播轨迹须记录每一步触发源与受影响视图标识，依赖图成环须在加载时以 E_DEPEND 整体拒绝。
4. 实现崩溃恢复后的段文件尾部截断与校验和损坏处理：恢复时若最后一个段文件尾部存在不完整记录，须依据记录长度前缀与校验和判定截断位置并保留已完整前缀，截断信息须写入恢复报告；若中间段出现校验和损坏，须以 E_CORRUPT 报告并列出首个损坏记录偏移，恢复流程不得跳过损坏记录继续重放后续段。
5. 实现依赖失效后的视图重建与一致性校验：视图缓存失效后，用户可触发重建，重建须仅依据当前已恢复的基键状态与视图定义计算，不得复用失效前缓存；提供校验命令，对每个视图比较重建前后内容摘要与版本号，若版本号未变化但摘要变化或反之须以 E_VIEW 报告，并稳定列出首个差异视图标识与差异键。
6. 实现恢复会话快照的版本识别与整体替换：会话快照持久化段文件集合摘要、快照点逻辑时间戳、依赖图版本与视图版本；重新打开快照时须比较快照中的段集合摘要与当前磁盘段集合摘要，若不一致须整体替换当前内存状态而非增量合并，替换过程须保证快照点引用的段文件均存在，版本差异须在诊断输出中稳定列出。
7. 实现异常注入下的业务码链路与结构化日志：支持以启动参数分别注入段文件尾部截断、中间记录校验和损坏、依赖图成环、快照点段文件缺失四类异常，分别以 E_LOG、E_CORRUPT、E_DEPEND、E_SNAPSHOT 业务码报告并写入结构化日志，日志含时间戳、业务码、段文件与偏移；注入仅改变输入文件或参数，不得修改引擎源码制造失败。
8. 提供可集成的库 API 与完整命令行示例：以 Rust 库形式暴露打开存储、写入记录、创建快照点、声明视图、恢复、重建视图、保存与打开会话快照、校验的接口，附带本地确定性样本日志段与演示脚本，顺序执行首次恢复、增量写入后创建快照点、注入截断后恢复三个场景，每个场景输出含业务码、段文件摘要、视图版本与失效轨迹的稳定顺序报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本段文件验证增量恢复、依赖失效传播与异常业务码，输出稳定顺序报告。
