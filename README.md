当前是空白工作区，需要从零构建一个面向本地 Windows 环境的跨组件基础设施配置一致性审计组件。系统读取若干本地 JSON 配置档案，每份档案描述一个组件节点的一组数值型配置项（如超时毫秒、重试次数、并发连接上限、采样率、刷新间隔）及其取值来源（人工录入或上游派生）。审计的核心业务是：对同一配置键在不同节点与不同档案间比较数值，按预定义的比较容差与统一精度口径判定一致或偏差，并把各配置项的偏差沿派生关系（某配置项由其他配置项按线性系数组合派生）进行误差传播，给出每个配置项的一致性结论、偏差量与误差上界。背景中给定的是数值精度与误差传播这一核心技术问题，不是通用配置管理：判定必须明确精度固定格度、量化误差来源与传播规则，且同一输入在多次审计中必须产出逐位相同的结论。组件以 Python 包形式交付，附带本地确定性样本配置与可复现实验脚本。

任务环境与准备：
安装 Python 3.11 及以上版本与 NumPy，确认在 Windows 命令行可直接运行 python 与 pip。
准备本地确定性样本配置档案、数值越界样本与派生成环样本，均为随项目生成的 JSON 文件，不依赖网络或外部账号。
确认项目目录可写，用于保存审计会话快照文件与结构化日志。
运行前通过命令行参数指定精度格度与容差参数，不修改源码。

业务要求：
1. 实现配置档案的加载与强校验：从本地 JSON 文件读取多份档案，每份含节点标识、档案版本与该节点的配置项集合；每个配置项含键名、数值、单位与来源标记。校验键名合法、数值类型与单位受支持、同一档案内键唯一、派生项引用的上游键必须存在，非法档案须以 E_CONFIG 业务码整体拒绝并输出错误位置，不允许部分加载。
2. 实现统一的精度口径与定点量化：以整数表示的固定格度（小数位数与缩放因子均可由会话参数指定）把每项数值量化为定点整数，并明确记录量化产生的向下与向上误差界；派生项的系数与常量同样量化，量化误差须以整数格为单位逐项记录并在最终报告中可追溯，量化规则不得随运行次序或数据读取顺序变化。
3. 实现一致性与偏差判定：对同一配置键在不同节点之间的取值按相对容差与绝对容差同时比较，容差以定点整数方式参与计算，输出每个键的偏差量、是否一致与触发的是哪一条容差；当两值之差落在容差边界上时必须按显式定义的边界包含规则判定，且判定结论与偏差量在同一精度口径下自洽。
4. 实现派生配置项的误差传播：对由线性系数组合派生的配置项，按系数绝对值加权把上游各项的量化误差界合成为该派生项的误差界，并给出传播路径；当派生链存在多级时须逐级合成并记录每级贡献，若某上游项缺失或其误差界无法确定，须以 E_PROPAGATE 业务码报告并指出断点键。
5. 实现容差判定受误差界约束的取舍：当两个值的偏差小于派生误差上界时，判定须与偏差大于误差上界时的语义不同，并输出该判定是否被误差界主导；用户可调整精度格度并观察判定翻转，翻转结果须能被解释为格度与误差界变化所致，且旧格度下的结论必须标记为陈旧而不得与当前结论混用。
6. 实现审计会话快照的版本识别与整体替换恢复：快照持久化档案版本、精度格度参数、量化后的定点值、偏差与误差传播结论；恢复时先比较快照档案版本与当前档案版本，不一致须整体替换当前审计状态而非增量合并，恢复后对同一输入重新审计须得到与快照逐位相同的结论，否则以 E_REPLAY 业务码报告差异键。
7. 实现异常注入与结构化日志：支持以命令行参数分别注入数值越界、派生系数成环、快照精度格度缺失三类异常，分别以 E_RANGE、E_CYCLE、E_GRID 业务码报告并写入结构化日志；注入只改变输入文件或参数，不得通过修改源码制造失败，异常路径下的日志须包含触发键与所用精度格度。
8. 提供可集成的包 API 与可复现实验环境：以 Python 包形式暴露档案加载、定点量化、一致性判定、误差传播、快照保存与恢复、重放校验的接口，附带本地确定性样本档案、数值越界与成环样本以及演示脚本，脚本顺序执行首次审计、调整精度格度后审计与快照恢复后重放，输出稳定顺序的审计报告与误差界总结。
