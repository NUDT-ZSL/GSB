当前为空白工作区，需要从零构建一个面向本地 Windows 环境的云原生流水线制品缓存与复用工作台。用户在本地 JSON 清单中声明一条构建流水线：若干阶段，每个阶段产出若干制品，制品以本地文件形式存放并带整数格式版本号；制品之间存在引用关系（下游制品引用上游制品的摘要与版本）。系统须把制品登记到本地缓存库，缓存库存在多个格式版本（v1 仅摘要，v2 增加制品大小与阶段标识，v3 再增加引用列表与压缩标记），并要求跨版本读取与写入互操作：旧版本库可被升级读取，新写入始终以当前版本落盘。核心业务是：给定相同输入，缓存命中判定与制品摘要必须字节级一致；当某上游制品变更时，须沿引用关系准确推导依赖它的下游制品并使其缓存条目失效；一次会话的缓存库、引用图、失效轨迹与命中历史须可快照持久化，恢复时识别版本差异并整体替换。系统须提供可交互的本地命令行应用与可重复演示脚本。

任务环境与准备：
安装 Go 1.21 或以上版本，并确认 go 命令在 Windows 系统 PATH 中可用；交互全部通过 stdin/stdout 命令循环完成，不依赖图形界面库。
在工作区创建项目目录并初始化 Go 模块，确保无需访问外网下载依赖，仅使用标准库与 encoding/json、net/http。
准备本地确定性样本流水线清单 JSON、制品文件与 v1、v2、v3 三个格式版本的样本缓存库目录，均以工作区内文件形式提供并在清单中写明内容摘要。
准备演示脚本与本地命令脚本，覆盖冷缓存构建、上游变更失效传播、缓存库降版升级三个场景，并确认脚本可在 Windows 命令行直接运行。
确认工作目录路径不含特殊字符，检查点文件、快照文件与缓存库目录均位于工作区内，便于验证中断后重启与整体替换行为。

业务要求：
1. 实现流水线清单与制品的加载及强校验：从本地 JSON 读取阶段、制品声明与引用关系，校验阶段标识唯一、制品键合法、格式版本号属于受支持集合、引用目标存在且版本可比较、制品文件路径位于工作区内；任一不合法须以 E_MANIFEST 业务码整体拒绝加载并输出出错字段位置，不得部分载入。
2. 实现缓存库多版本格式的编解码与互操作：缓存库以本地文件目录存放，每个条目带整数格式版本号；须能逐条解码 v1、v2、v3 条目（v1 仅内容摘要，v2 增加字节数与阶段标识，v3 增加引用列表与压缩标记），对未知版本以 E_FORMAT 拒绝该条目但不影响其余条目可用，写入始终以当前版本落盘。
3. 实现缓存命中的确定性判定与摘要一致性：以制品键、内容摘要与引用列表共同决定命中，内容摘要须由制品文件内容以确定性规则计算；相同输入在不同执行顺序与不同并发度下必须得到相同摘要与相同命中结论，摘要不一致时须以 E_HIT 报告期望与实际的摘要差异。
4. 实现引用依赖图与增量失效传播：当某制品内容或版本变化时，沿引用关系推导全部直接与间接下游制品，按稳定顺序使其缓存条目失效并记录传播轨迹；删除仍被引用的制品须拒绝并返回 E_REF 列出引用者，失效集合须与重新计算结果一致。
5. 实现缓存库打开时的自动升级与中断恢复：打开缓存库时检测全部条目的格式版本，低于当前版本的条目须逐个在内存中升级并以当前版本重写，每完成一个条目即更新检查点文件；强制终止后重启只能依据检查点恢复已升级条目，重写中断不得留下被误认为完整的条目。
6. 实现制品缓存会话快照与版本识别的整体替换恢复：快照持久化清单版本、缓存库条目、引用图版本、失效轨迹与命中历史；重新打开快照时须先比较快照清单版本与缓存库条目摘要集合同当前是否一致，不一致须整体替换当前缓存库、引用图与命中历史而非增量合并，旧快照保留为只读并稳定列出差异条目。
7. 实现恢复后的缓存一致性重放校验：从快照恢复后按快照记录的清单版本与制品内容摘要重新计算命中结论与失效集合，与快照保存结果逐项比较；因清单版本、格式版本或制品内容变化导致不可复现时须以 E_REPLAY 报告不可复现的具体依据与首个差异制品键。
8. 提供可交互命令行应用与可重复演示：以 stdin/stdout 命令循环支持 load、build、hit、invalidate、upgrade、snapshot、restore、replay 等命令，输出稳定有序；附带本地确定性样本清单与演示脚本，顺序执行冷缓存构建、上游制品变更后的失效传播、缓存库降版升级三个场景，每个场景输出命中数、失效制品集合与业务码。
