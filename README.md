当前是空白工作区，需要从零实现一个本地 GitOps 回滚与收敛控制器。控制器以本地 JSON 文件模拟 Git 仓库中的多环境（dev/staging/prod）声明式清单，清单存在两代格式：v1 为单文件 JSON 的扁平应用清单，按应用记录镜像版本、副本数、相对生效秒数与扁平应用到参数映射；v2 为分片 JSON 加 SQLite 元数据库的分层清单，按应用与环境记录规范应用名、副本数、镜像版本、资源需求、依赖上游应用、绝对生效时刻毫秒、清单代数与失效墓碑。另有一个本地集群状态文件描述各环境实际运行的应用镜像版本与副本数。控制器需把期望清单与集群实际状态对比，计算回滚计划并驱动收敛，同时兼容两代清单格式的读取与合并。核心矛盾在于：回滚必须精确识别清单版本变化并拒绝版本回退，收敛过程中需处理并发更新、强制终止后的恢复以及两代格式在时间表示与代数语义上的差异。

任务环境与准备：
安装 Python 3.10 及以上版本，使用标准库 sqlite3 与 json，无需第三方依赖。
在空白工作区创建项目目录，准备本地样本文件：v1 单文件 JSON 清单、v2 分片 JSON 与 SQLite 元数据库、集群实际状态 JSON 文件，所有样本由固定种子生成并放入本地目录。
确保 Windows 路径分隔符与文件权限不影响 SQLite 文件锁行为，运行前关闭可能占用样本文件的编辑器。
提供运行演示脚本的入口说明，演示脚本只依赖本地样本与标准库，不访问网络或外部服务。

业务要求：
1. 实现 v1 扁平清单与 v2 分层清单的解析校验：v1 校验应用名唯一、副本数为正整数、镜像版本格式合法、相对生效秒数为非负整数；v2 校验分片文件哈希、SQLite 元数据中的清单代数单调、绝对生效时刻为整数毫秒；两代均校验依赖上游应用存在且无环，非法输入返回明确业务错误码（如 E_BAD_MANIFEST、E_BAD_VERSION、E_DEP_CYCLE）。
2. 实现跨版本清单合并与统一期望状态构建：同一应用在两代清单中同时存在时，依据清单声明的逻辑时钟与清单代数裁决最新版本，逻辑时钟相同则按来源格式优先级；合并后每个应用条目须保留来源版本、原始时间表示与裁决依据，不得丢失任何应用，且相同输入重复合并逐字段一致。
3. 实现回滚计划的生成与版本回退拒绝：对比期望状态与集群实际状态，按依赖拓扑逆序生成回滚操作序列并给出每条操作的触发来源；当目标版本号低于当前已提交版本号时拒绝并返回 E_VERSION_ROLLBACK，计划以稳定排序 JSON 输出且附带上游回滚完成条件。
4. 实现回滚执行的收敛推进与逻辑时间预算：按拓扑序逐应用执行回滚操作，每个操作用注入逻辑时钟计量并受超时预算约束；预算耗尽时放弃剩余操作并记录放弃原因，区分预算内未启动、启动后失败与主动放弃三类结局，已启动操作不得被截断为超时。
5. 实现强制终止后的恢复一致性：把回滚轮次水位、已提交操作摘要、应用阶段与逻辑时钟水位以事务原子写入 SQLite；进程在回滚中途被强制终止后，恢复路径依据持久化状态识别已提交与半提交操作，只重放未完成操作且不得重复回滚已完成应用，恢复后收敛状态与未中断运行逐字段一致。
6. 实现多进程并发一致性与幂等提交：允许多个控制器实例并行处理不同环境，通过 SQLite 事务与文件锁保证同一应用同一回滚版本只被提交一次、同一清单版本只被合并一次，重复提交相同回滚结果必须幂等；读取方只能看到完整已提交状态而非中间态。
7. 实现两代清单时间语义的模式迁移与精度记录：把 v1 相对生效秒数在注入逻辑时钟下换算为绝对时刻并记录换算标度与舍入方向，v2 绝对毫秒时间戳保持原值；迁移决策须持久化，同一逻辑时钟下重复判定逐位一致，逻辑时钟回拨超过容差返回 E_CLOCK_ROLLBACK 且不改变状态。
8. 提供命令行接口与可重复演示：支持 load、plan、rollback、resume、status、verify 子命令，plan 以稳定排序 JSON 输出回滚操作序列与版本裁决依据，status 输出各环境收敛状态与逻辑时钟水位，verify 校验持久化状态与集群实际状态的一致性；使用固定本地样本两次运行产生完全一致的输出。
