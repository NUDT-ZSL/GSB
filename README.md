当前是空白工作区，没有现存项目、代码或数据附件。需要从零构建一个面向 LLM 检索增强与工具调用链路的本地诊断工作台，核心业务问题是工具结果在格式版本演进下的一致性重组与其增量失效回溯。业务对象是本地确定性生成的多轮请求清单（JSONL，字段含 request_id、turn_no、query_text、tool_calls 列表，每次调用含 tool_id、arg_digest、result_ref、result_format_version）以及一份工具结果仓库：结果仓库中的每个结果以三种版本格式并存，v1 为无字段名的竖线分列行式（tool_id|payload|status 三段，无结构信息与来源标记），v2 为带字段名的行式（含 payload、status、result_schema_version、置信区间），v3 为带嵌套结构声明的结构化格式（含分片引用、多结果聚合声明与来源链）。系统把一次回答组装建模为有向无环计算图：结果加载与版本迁移→结果解析与校验→调用对齐→片段合并→答案组装。核心矛盾在于：v1 表达能力不足以承载 v3 的分片引用与来源链，降级会丢失信息，而升级必须补全并记录来源；同时结果仓库版本提升后，已组装答案中引用了旧结果的片段必须被识别并可追溯到具体结果版本，未受影响的结果必须复用缓存而不被无谓重算。题目要求围绕格式互操作、来源追溯、增量失效与快照整体替换实现真实机制，并给出本地可视化诊断视图。

任务环境与准备：
安装 Python 3.10 以上版本，确认标准库 pathlib、hashlib、json 可正常使用。
安装 NumPy（1.24 以上）用于本地确定性样本生成与哈希摘要计算，不依赖任何容器环境。
在工作区内准备样本生成脚本所需的固定随机种子常量，以及结果仓库、缓存目录与快照目录。
确认工作区可写，用于存放内容寻址缓存、持久化快照与诊断报告产物。
不连接任何外部网络、真实账号或线上站点，全部请求清单、工具结果与文档片段均在本地确定性生成。

业务要求：
1. 实现 v1、v2、v3 三种工具结果格式的读取器：v1 按竖线分列解析、v2 按键值对解析、v3 按结构化格式解析，按格式头或字段集分派解析路径；未知版本返回 E_FORMAT_VERSION_UNSUPPORTED，行字段数不符、必填字段缺失、payload 不可解析、状态码不在受控集合分别返回 E_FORMAT_CORRUPT 并给出字段偏移与所在行号。
2. 实现三套格式的双向迁移器，把任意格式规范化为统一的内部结果表示（结果节点、分片引用节点、来源链节点）：v1 升级到 v2 或 v3 时补全 result_schema_version、置信区间与来源链并逐项记录补全来源；v3 降级到 v1 时对分片引用与多结果聚合声明按显式声明的展平或丢弃规则处理并输出丢弃明细，丢弃项不得静默消失。
3. 实现基于结果版本的片段合并与答案组装：按调用计划顺序把结果解析为答案片段并合并，每条片段记录来源 tool_id、result_ref、result_format_version、合并位置与所用缓存键；须校验任一结果不得同时计入答案与失败集、片段来源必须存在于调用集合、同一结果同一区间重复合并须被拒绝并返回 E_MERGE_CONFLICT，答案须可由逐片段明细独立重算一致，同分片段按 tool_id 字典序打破平局。
4. 实现内容寻址结果缓存与增量失效联动：每个解析产物与片段产物以内容哈希落盘，缓存键须纳入结果原始内容哈希、格式版本、结构声明摘要、调用参数摘要与上游产物哈希；结果仓库某条目以更高版本到达或被替换时计算受影响结果与受影响片段集合（内容哈希与格式版本均未变的条目不得判为受影响），复用未受影响缓存，仅重算受影响后缀，并输出重算与复用集合。
5. 实现过期结果拒绝与来源追溯重放：当答案片段所引用的结果版本已被新版本取代且其缓存键失效时，禁止继续使用旧片段并返回 E_RESULT_STALE 并指出 result_ref 与来源版本；对任一在册答案片段，可按其记录的缓存键、结果版本与节点路径重放出相同片段与相同合并位置，追溯链缺失或重放不符返回 E_LINEAGE_BROKEN 并指出断点节点。
6. 实现跨格式语义等价裁决与往返校验：同一结果以 v1、v2、v3 三种形式书写时，读取与迁移后必须产出相同结果节点、相同分片归属与相同状态；当 v1 表达能力不足导致语义无法完全还原时返回 E_SEMANTIC_DRIFT 并列出不可还原字段；任一格式样本完整往返后，在 payload、状态与分片归属上必须逐项相同，v2 与 v3 往返还须校验置信区间与来源链在声明精度内一致。
7. 实现结果仓库、格式定义与答案快照的版本化整体替换及并发写控制：三者各携带单调递增版本号与内容校验和，检测到任一版本号或校验和变化时必须整体替换旧快照而非增量修补，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明部件与版本号；同一时刻只允许一次提交生效，并发提交冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待。
8. 提供本地可交互诊断工作台并实现跨模块一致性自检与资源上限：展示计算图拓扑、各节点命中或重算状态、失效传播覆盖的结果与片段、迁移补全与丢弃明细、逐片段来源路径与当前格式视图、快照版本与最近业务错误码，支持在 v1、v2、v3 视图间切换；自检校验图拓扑无环、缓存键与产物哈希可互相核对、重算与复用集合无交集且并集覆盖全部受影响集合；为同时驻留结果数、缓存条目总量与单结果分片数设可配置上限，超限返回 E_RESOURCE_LIMIT 或降级并标记降级类别。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
