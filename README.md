当前为空白工作区，需要从零构建一个面向表格数据的交互式特征编码与选择专业应用，并附可重复演示。输入是本地确定性生成的表格样本（字段含 row_id、若干数值列与类别列、label），以及一份特征配置：每个类别列的编码方式（one-hot 或目标编码）、每个数值列的标准化方式、选择器类型（方差过滤或互信息）与目标特征数。应用需完成编码、标准化、选择、训练一个简单分类器并输出指标，同时对外提供一个交互式查询接口：用户按 row_id 查询该行的编码后特征向量与模型预测。核心业务难点是交互延迟预算与计算结果一致性：交互查询必须在给定的延迟预算内返回，而编码与选择结果又与训练批次、统计量估计顺序、缓存版本紧密耦合，任一环节的口径不一致都会让交互结果与训练结果出现偏差。

任务环境与准备：
安装 Python 3.10 及以上版本，并安装 numpy、scikit-learn 到本地环境，安装说明参阅各自官方文档。
在当前空白工作区创建项目目录，不放置任何既有源码或数据附件；样本由程序按固定随机种子在本地生成表格数据。
确认可本地运行交互式演示所需的最简界面依赖（如标准库 http.server 或已安装的本地桌面库），不连接任何外部服务。
为演示准备一组固定配置与种子，以及一组用于注入的异常配置（非法编码方式、超目标特征数、超延迟预算），均由本地参数提供。

业务要求：
1. 实现确定性的特征编码与标准化管线：类别列按配置做 one-hot 或目标编码（目标编码的平滑系数与折数由配置给出且固定随机种子），数值列按配置做 z-score 或 min-max；同一输入与配置下编码矩阵必须逐元素一致，并明确目标编码的平滑与防泄漏策略，即折外均值只使用非本折样本计算。
2. 实现特征选择阶段：按配置的方差阈值或互信息分数选出恰好目标特征数（或按阈值切分），输出保留特征名有序清单与逐特征分数；选择结果必须记录所依据的编码矩阵版本与统计量口径，同一版本重跑得到同一清单，且清单顺序确定。
3. 实现交互式查询接口的延迟预算控制：按 row_id 查询单行编码后特征与预测结果，须在配置的单次延迟预算内返回；超预算时按明确策略返回 E_LATENCY_BUDGET 并附带已完成阶段标记，禁止用无界等待或无限重试掩盖超时，且超时判定依据真实的高精度单调时钟耗时而非人为延迟。
4. 实现训练侧与交互侧的结果一致性保证：单行查询得到的编码特征与保留特征必须与批量训练矩阵中同一 row_id 的行在配置精度内一致，预测也必须一致；检测到偏差时返回 E_INCONSISTENT 并给出偏差特征名、偏差量级与所比对的两侧版本号。
5. 实现统计量与产物的版本化快照：目标编码统计量、标准化均值方差、选择器分数各带单调递增版本号与内容校验和，训练提交时整体替换旧快照；重启加载时识别版本变化并整体替换，校验和不符返回 E_SNAPSHOT_CORRUPT，禁止增量合并导致新旧统计量混用。
6. 实现缓存与失效联动：交互查询可缓存单行结果或编码器状态，当快照版本变化、特征配置变更或样本追加时必须使受影响缓存失效并重算；需保证缓存命中率不影响正确性，失效后首次查询结果与新版本训练矩阵一致。
7. 实现并发查询与资源上限：多个交互查询可并发执行，同一时刻统计量快照切换须原子生效，查询侧不得读到半更新的编码器；为编码矩阵内存与缓存条目数设可配置上限，超限返回 E_RESOURCE_LIMIT，并发冲突按明确策略返回 E_BUSY 而不阻塞占用延迟预算。
8. 实现配置与输入校验及跨阶段自检入口：编码方式未知、目标特征数超过可用特征数、延迟预算或阈值非法分别返回 E_CONFIG_INVALID 并指明字段；并校验保留特征清单与编码矩阵列可核对、单行查询特征名与训练侧一致，违反返回 E_INCONSISTENT 并指明类别，同时提供可交互应用展示延迟分布与一致性报告并支持一次演示。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地生成样本验证编码与选择结果一致、查询在延迟预算内与训练矩阵一致及快照版本整体替换。
