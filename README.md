当前是空白工作区，需要从零构建一个面向本地 Windows 环境的 TCP 连接状态与拥塞控制诊断工作台。系统以本地回环 TCP 端口启动一个确定性模拟对端服务（可按脚本注入丢包、乱序与延迟），并在客户端侧实现一个教学用的拥塞控制状态机，把已发送未确认、拥塞窗口、慢启动阈值、重复确认计数与 RTT 估计量与 TCP 状态（CLOSED、SYN_SENT、ESTABLISHED、FIN_WAIT 等）绑定推进。核心业务是：在一次完整连接会话中，依据本地模拟对端返回的确认与重复确认推进拥塞状态与 RTT 估计，所有观测（发送时刻、确认时刻）必须写明时钟基准与真值来源，界面须以稳定顺序展示当前状态与估计值，并支持把会话快照持久化与恢复后重放校验。

任务环境与准备：
安装 Python 3.11 或以上版本，确认 tkinter 可用（Windows 官方安装包默认包含）。
仅使用标准库（socket、threading、json、tkinter、unittest），无需第三方依赖。
在工作区创建项目目录，准备本地 JSON 对端行为脚本与演示脚本，所有通信绑定 127.0.0.1 高位端口。
以命令行方式运行演示与校验脚本，确保不访问外网、不依赖真实账号或线上服务。

业务要求：
1. 实现客户端 TCP 状态机：在本地回环连接上按 CLOSED、SYN_SENT、ESTABLISHED、FIN_WAIT、CLOSE_WAIT、CLOSED 推进状态，每个迁移记录触发报文类型、序号与单调时钟毫秒时间戳；非法迁移须以 E_STATE 业务码拒绝并保持原状态。
2. 实现拥塞窗口与慢启动阈值推进：按已确认字节推进拥塞窗口，慢启动阶段每确认一字节窗口增一，拥塞避免阶段按每往返窗口增一的整数规则推进；重复确认达到三次数须进入快速重传并调整阈值，超时须回到慢启动，所有窗口与阈值须为整数并写入轨迹。
3. 实现 RTT 估计与超时定时器：以发送与确认的单调时钟差为样本，按整数定点方式维护平滑 RTT 与偏差估计并推导重传超时值，公式与缩放因子须在报告中明确；对 Karn 规则下的重传样本须排除，样本不足或时钟回拨须以显式规则处理，不得静默采用可疑样本。
4. 实现模拟对端的确定性行为脚本：以本地 JSON 描述对端对每个报文的应答（确认、重复确认、丢包、延迟毫秒、乱序），对端按脚本顺序应答，脚本耗尽后按默认确认策略应答；两端时钟基准须一致声明，真值来源为对端脚本记录的预期事件序列。
5. 实现 RTO 重传与累计确认处理：超时触发重传最早已发送未确认段并重置定时器，累计确认须确认所有小于等于该序号的段并更新窗口与 RTT 样本；同一段被重传后其后续确认须正确更新状态，重复确认不得推进确认点，异常序号须以 E_SEQ 报告。
6. 实现会话快照的版本识别与整体替换恢复：快照持久化状态机当前状态、窗口、阈值、RTT 估计量、序号空间与事件轨迹；重新打开快照时须比较快照版本与当前会话配置版本，不一致须整体替换当前状态而非增量合并，恢复后须能继续推进新的报文交互。
7. 实现恢复后的一致性重放校验：从快照恢复后按快照记录的对端脚本与初始参数重新执行同一交互序列，逐步比较状态迁移、拥塞窗口、阈值与 RTT 估计值与快照记录，差异须定位到首个不一致的报文序号与字段并输出 E_REPLAY。
8. 提供 Tkinter 交互界面与可重复演示：界面展示当前状态、拥塞窗口、慢启动阈值、平滑 RTT、RTO、已发送未确认数量与事件轨迹，渲染顺序稳定；附带确定性对端脚本与演示脚本，顺序执行正常三次握手与传输、注入丢包与重复确认、快照恢复后重放三个场景并输出稳定总结。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
