当前是空白工作区，需要从零实现一个本地列式存储的压缩分块扫描组件，作为可集成库与完整示例交付。样本以本地 JSON 描述一张列式表的布局：列名与类型、行组划分、每列每行组的分块边界、分块编码方式（整数游程编码、字典编码、浮点原始编码）、每分块的字节大小估计与校验摘要，另有一组扫描任务声明谓词（等值、范围、合取）与目标投影列。扫描需在每轮并行任务数上限与总内存预算双重约束下决定分块启动顺序，按编码解码分块、按谓词过滤并按行序输出结果，未被谓词引用的列必须跳过解码。组件须把扫描进度、分块提交状态与结果摘要持久化到 SQLite，并支持进程被强制终止后按持久化状态续算；并发实例须通过事务与文件锁保证同一分块只被解码提交一次。

任务环境与准备：
Windows 本地 Python 3.10 或以上，创建虚拟环境并安装 numpy 与 pytest（版本自定，安装方式以 pip 为准）。
准备固定本地样本：列式表布局 JSON、每列每行组的分块二进制或 JSON 编码文件与校验摘要，样本随项目一同生成并保证确定性。
确保 SQLite 由标准库 sqlite3 提供，无需额外服务；准备一组扫描任务声明与并发实测所需的多进程入口脚本。

业务要求：
1. 实现列式表布局与扫描任务的解析校验：列名唯一、每行组行数为正整数、分块边界不越界且连续覆盖行组、编码方式与列类型匹配、分块校验摘要与声明内容一致、谓词引用列存在且类型可比；非法布局或任务须返回明确业务错误码且不写入任何持久化状态。
2. 实现分块编码的确定性编解码：整数游程编码与字典编码需可逆且对相同输入逐字节可复现，浮点原始编码按固定字节序读写；解码结果须与布局声明的行数与类型逐行一致，相同分块重复解码须得到相同摘要，作为后续结果一致性校验的依据。
3. 实现列裁剪与谓词下推的扫描计划生成：只对谓词引用列与投影列解码，未被任何谓词或投影引用的列必须整列跳过解码并在统计中记录跳过数；等值、范围与多列合取谓词须下推到分块级以整块跳过明显不命中的分块，跳过的分块不得消耗解码预算。
4. 实现并行扫描调度器：在每轮并行任务数上限与总内存预算双重约束下决定分块启动顺序，估算每个候选分块的解码内存占用并与剩余预算比较；预算不足时显式放弃剩余分块并记录放弃原因，区分预算内未启动、启动后失败与主动放弃三类结局，已启动分块必须执行完成。
5. 实现扫描结果的行序一致性与真值对照：合并各分块结果时须按全局行序输出，不得因并行完成顺序改变结果顺序；同时以单线程逐分块顺序扫描计算唯一真值，两者逐行比对，任何不一致须输出首个差异行、来源分块与该分块的解码摘要。
6. 实现扫描状态与分块水位的持久化推进：把扫描轮次、已提交分块结果摘要、解码内存占用、跳过计数与结果行数水位以事务原子写入 SQLite，推进前校验分块内容摘要，摘要不匹配须拒绝推进并保持状态不变；状态只能依据已提交分块的完整结果推进。
7. 实现强制终止后的恢复与幂等续算：进程在调度或解码中途被强制终止后，恢复路径依据持久化状态识别已提交分块与半提交状态，只重放未完成分块且不得重复计入已完成分块的结果或内存占用；恢复后结果与不中断运行逐行一致，无法完成的分块须给出明确失败结论。
8. 实现多进程并发一致性与可重复命令行演示：多个扫描实例并行处理同一表时通过 SQLite 事务与文件锁保证同一分块同一版本只被解码提交一次、内存预算不被并发超卖，重复提交相同分块结果必须幂等；提供 scan、resume、status、verify 子命令，status 以稳定排序 JSON 输出每分块状态、跳过列数、已用内存与放弃原因。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
