当前是空白工作区，需要从零构建一个面向本地 Windows 环境的云原生声明式配置漂移收敛诊断工作台，用于教学与排障演示。用户的期望状态以若干本地 JSON 声明文件描述：每个声明文件对应一个逻辑资源组，包含版本号、资源键、资源期望属性（整数或字符串）、对其他资源的引用、收敛策略与依赖的其他声明文件版本。实际状态由本地模拟的一组资源快照文件表示，可人为注入漂移。工作台核心业务是：把当前期望状态与实际状态比对得出漂移集合，按声明版本增量更新，仅重新编译并收敛受影响的资源，准确推导引用失效并处理依赖失效传播；把一次收敛会话（声明版本、漂移集合、依赖图、收敛轨迹）持久化为本地快照，恢复时识别版本差异整体替换。交付为领域可视化与诊断工作台，以 Tkinter 展示漂移热力、依赖边、失效范围与收敛结论，并支持可重复演示。

任务环境与准备：
安装 Python 3.11 或以上，确认标准库 tkinter 可用；无需第三方包与网络访问。
在空白工作区创建项目目录，准备本地 JSON 声明文件与实际状态快照样本，全部位于项目内。
确认 Windows 回环文件读写与子目录创建权限正常，演示脚本可由 python 命令直接运行。

业务要求：
1. 实现声明文件与实际状态快照的加载与强校验：从本地 JSON 读取声明组与实际资源快照，校验版本号单调递增且唯一、资源键唯一、引用目标存在、期望属性为受支持的整数或字符串类型、收敛策略字段完整；任一不合法须以 E_DECL 业务码整体拒绝该声明组加载并输出具体文件与字段位置，不得部分加载。
2. 实现声明版本增量更新与资源级不可变编译产物：当用户提交新声明版本时，仅对属性或引用发生变化的资源重新生成编译产物并递增其产物版本，未变化资源的产物版本必须保持不变且可校验；版本号变化后当前视图须整体替换而非逐条合并，旧版本视图保留供对比。
3. 实现引用依赖图与失效传播推导：在资源引用关系上维护依赖图，当某资源被修改或删除时准确推导全部直接与间接下游资源并标记其编译产物失效；删除仍被其他资源引用的资源须拒绝并返回 E_REF 业务码列出引用者，依赖成环须以 E_CYCLE 报告。
4. 实现漂移比对与收敛计划生成：逐资源按属性粒度比对期望与实际状态得出漂移集合，区分缺失、多余、值不符三类漂移；仅对存在漂移或产物失效的资源生成收敛动作，动作须含资源键、漂移类型、期望值与当前值，并按稳定的拓扑序与资源键输出。
5. 实现依赖失效链路上的连锁收敛顺序与失败隔离：收敛须按依赖图拓扑序执行，某资源收敛失败须按其收敛策略决定下游跳过或继续，被跳过的下游须记录触发上游与业务码 E_CONVERGE；收敛顺序与跳过集合须可复现，失败不得导致已成功资源被回滚，除非声明策略显式要求。
6. 实现收敛会话快照与版本识别的整体替换恢复：快照持久化声明组版本、依赖图版本、各资源产物版本、漂移集合与收敛轨迹；重新打开快照时须比较快照声明版本与当前声明版本，不一致须整体替换当前声明、依赖图与漂移状态而非增量合并，恢复后须能继续提交新的增量版本。
7. 实现恢复后的一致性重放校验：从快照恢复后按快照记录的声明版本与资源产物版本重新计算漂移集合与收敛计划，与快照保存结果逐项比较；若因声明版本缺失、引用目标消失或产物版本不一致导致不可复现，须以 E_REPLAY 业务码报告并列出首个不可复现的资源键与原因。
8. 提供 Tkinter 诊断工作台与可重复演示：界面展示漂移热力、资源依赖边、本轮失效传播到的资源集合、收敛执行顺序与业务码，渲染顺序稳定；附带确定性样本声明文件与演示脚本，顺序执行首次全量收敛、增量修改一条被引用资源、删除一条无引用资源三个场景并输出稳定顺序的诊断总结。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证增量收敛、失效传播、快照整体替换与重放校验，并输出稳定诊断总结。
