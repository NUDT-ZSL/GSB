产品原型评审已通过，当前工作区为空目录，需要在 Linux（WSL Ubuntu）本地从零交付一个用于资源编排依赖图谱的跨版本配置失效与拓扑恢复诊断组件。业务对象由随工程交付的固定种子脚本确定性生成：服务模板清单记录模板名、资源需求、依赖上游模板列表、版本号、标签集合与生效逻辑时钟；实例化请求流按可注入逻辑时钟给出请求序号、模板名、目标拓扑命名空间、实例 ID 与期望状态；编排策略快照存在两代格式，v1 为单文件 JSON，记录相对生效秒数、扁平模板依赖映射与无拓扑约束声明，v2 为分片 JSON 加 SQLite 元数据库，记录绝对生效毫秒时刻、策略代数、依赖闭包墓碑与拓扑失效标记。组件需解析并合并两代策略快照，沿模板依赖边传播配置失效，在实例化请求到达时判定拓扑闭合、资源可满足性以及策略版本切换是否造成实例化回退，全部输入均在本地生成，不依赖真实云平台或外部网络。

任务环境与准备：
在 Linux（WSL Ubuntu）部署 Python 3.10+，安装 SQLite3 模块（Python 标准库自带）。
工作区为空目录，从零创建项目文件，不依赖任何外部网络或真实云平台。
所有输入样本由随工程交付的固定种子脚本在本地确定性生成，输出 JSON、SQLite 数据库与日志文件。

业务要求：
1. 实现服务模板清单、实例化请求流与两代编排策略快照的解析校验：模板名与请求序号唯一、依赖上游模板均存在且依赖图无环、资源需求为正整数、版本号单调、标签集合格式合法、注入逻辑时钟为非负整数、v1 相对生效秒数为非负整数、v2 分片文件哈希与 SQLite 元数据中策略代数单调；引用不存在的模板依赖、分片哈希不匹配或逻辑时钟回拨超过容差须返回明确业务错误码并保留可诊断字段（模板名、版本号、分片序号、请求序号）。
2. 实现跨版本编排策略的合并与统一依赖视图构建：同一模板在同一策略键下同时出现在 v1 与 v2 时，依据策略声明的逻辑时钟与策略代数裁决最新版本，逻辑时钟相同则按来源格式优先级裁决；合并后每个依赖边须保留来源版本、原始时间表示、裁决依据与生效时刻，v1 相对生效秒数在注入逻辑时钟下换算为绝对毫秒时刻并记录换算标度、舍入方向与舍入前原始值，迁移决策必须持久化使同一逻辑时钟下重复判定逐位一致。
3. 实现依赖闭包计算与配置失效传播：沿模板依赖边计算每个模板的传递依赖闭包，当上游模板版本更新、标签变更或策略墓碑标记出现时，精确计算受影响下游模板集合；只重算受影响闭包内模板的依赖摘要与配置指纹，未受影响模板的闭包与指纹必须保持不变，失效传播不得跨越完全不同分支，并输出每条失效传播链的触发来源（模板名、版本号、策略代数、逻辑时钟）与受影响模板的持久化版本变化。
4. 实现实例化请求拓扑闭合与资源满足裁决：每个实例化请求沿模板依赖闭包构建完整拓扑图，校验所有依赖上游均存在对应模板且版本兼容，任一依赖缺失或版本冲突即拒绝实例化并给出首个拓扑断点；在每节点总资源预算与每模板并发实例上限双重约束下计算资源可满足性，任一约束不足即拒绝并给出首个触发约束，预算裁决必须记录所依赖的资源观测项与扣减前的数值。
5. 实现并行实例化调度与资源账本守恒：同一轮次内按目标拓扑命名空间分组并发处理实例化请求，同时受每轮总逻辑时间预算与每模板并发实例上限双重约束；预算耗尽必须放弃剩余未启动请求并记录放弃原因，严格区分预算内未启动、启动后失败与主动放弃三类结局，已启动实例化不得被事后截断；每次成功实例化在同一事务内原子地扣减节点资源账本并登记实例状态，任意时刻对账不得出现负余量或重复扣减。
6. 实现策略版本切换的原子性与进行中实例化的版本绑定：收到新策略快照包时比较清单版本号、策略代数下限、各分片哈希与依赖摘要集合，判定完整替换、增量追加或无需操作，版本回退必须被拒绝并返回独立业务错误码；完整替换以临时表加版本号整体切换当前策略指针而非逐条覆盖，进行中的实例化请求必须绑定其开始时的策略版本与依赖视图直至完成，读取方只能看到完整已提交版本，不得出现新旧混合的依赖快照。
7. 实现强制终止后的恢复统一：把策略视图指针、已提交实例化水位、依赖闭包指纹、资源账本、进行中请求登记与逻辑时钟水位以事务原子写入 SQLite；进程在依赖解析、资源扣减或策略替换中途被强制终止后，恢复路径依据持久化状态识别已提交实例化、半提交账本与未完成拓扑，只重放缺失部分且不得重复扣减资源或重复注册实例，恢复后的拓扑结果必须与未中断运行的全量重放结果逐项一致。
8. 实现多进程并发一致性与可重复命令行验证：允许多个实例化处理进程与策略更新进程并行，通过 SQLite 事务与文件锁保证同一请求同一策略版本只被实例化一次、同一资源账本条目不被并发超扣、同一策略快照版本只被整体替换一次，重复提交相同请求或相同补丁必须幂等；提供 load、build、schedule、recover、status、verify 子命令，status 以稳定排序 JSON 输出依赖闭包摘要、资源余量、实例化水位与当前策略版本指针。
