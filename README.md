项目启动时工作区没有任何已有实现，团队需要在 Linux（WSL Ubuntu）本地从零交付一个推理批处理队列的定点精度账本与中断续算裁决引擎，以可交互的专业应用与可重复演示形式验证批处理调度链路中的数值误差传播与恢复一致性。业务对象由本地固定种子脚本确定性生成：模型描述（层名与每层参数量、每请求输入与输出 token 数）、副本清单（副本 ID、可用算力、显存上限 MiB、批处理窗口逻辑毫秒、最大批大小、支持序列长度上限）、请求轨迹（请求序号、到达逻辑时钟毫秒、优先级、输入 token 数、最大输出 token 数、期望截止逻辑时钟）、精度配置（算力占用与延迟估算的定点标度、浮点容差、误差上界预算）以及可选的强制终止注入清单。引擎需按可注入逻辑时钟推进批处理窗口切分与请求归属，在算力与显存双重预算下裁决批组成，对每批估算量进行定点换算并记录逐项舍入误差与累计误差上界，在进程被强制终止后依据 SQLite 持久化状态续算并保证与一次性执行逐位一致。

任务环境与准备：
在本地 Linux（WSL Ubuntu）工作区安装 Python 3.10 及以上版本，并确保 SQLite3 模块可用。
随项目交付固定种子样本生成脚本，用于生成模型描述、副本清单、请求轨迹、精度配置与注入清单，所有样本均不依赖网络或外部服务。
确认工作目录为空，运行环境仅包含 Python 标准库，不安装任何第三方包。

业务要求：
1. 实现模型描述、副本清单、请求轨迹、精度配置与注入清单的解析校验：校验副本 ID 唯一、算力与显存上限为正有限数、批处理窗口与最大批大小为正整数、支持序列长度上限不小于任一请求的输入输出 token 数、请求序号唯一且到达与截止逻辑时钟为非负整数、定点标度与容差为正数；任何非法输入须返回明确业务错误码且不写任何持久化状态。
2. 实现基于注入逻辑时钟的批处理窗口切分与请求唯一归属：窗口边界由副本批处理窗口逻辑毫秒与注入逻辑时钟共同决定，绝不读取系统墙钟；每个请求必须唯一归属一个副本的一个窗口且不得同时计入两个窗口，窗口期满未满批也要关闭并进入裁决，同一轨迹在任意运行次数下产生逐位一致的窗口划分与归属结果。
3. 实现算力与显存双重预算下的批组成裁决：在最大批大小、副本可用算力、显存上限与期望截止逻辑时钟约束下决定每批容纳的请求集合；优先级插队必须显式记录被跳过请求与首个触发约束，并记录裁决所依赖的观测项（各请求 token 数、算力估算量与显存占用估算量），使相同输入条件下裁决结果可复现。
4. 实现批估算量的定点换算与误差谱记录：把每批的算力占用、显存占用与预计排队时长按声明定点标度换算，记录每项换算的标度、舍入方向与换算前原始浮点值，并对每次加法与乘法累计误差上界；当两个候选批或两个副本的换算结果差小于浮点容差且裁决依赖该差值时标记为精度敏感并输出误差来源链。
5. 实现请求生命周期状态机与持久化裁决：请求在待入批、已入批、执行中、已完成、已超期之间迁移，迁移必须依据已提交窗口结论与 SQLite 持久化状态裁决，重启后不得凭内存残留决定请求状态；已超期请求必须与执行失败使用不同状态标记，且不得因进程重启被错误重纳入批。
6. 实现强制终止注入驱动的中断恢复与续算一致性：允许在窗口提交或批组成裁决中途注入 SIGKILL 强制终止进程，恢复时依据 SQLite 持久化状态识别已提交批次与半提交窗口，只重放未完成部分；续算后产生的批次清单、请求状态与误差谱必须与一次性完整执行得到的对应部分逐位一致。
7. 实现多进程并发一致性与幂等提交：允许多个调度进程并行推进同一副本，通过 SQLite 事务与文件锁保证同一窗口同一版本只被提交一次、同一请求序号同一版本只被入批一次、算力与显存预算不被并发超卖；重复提交相同窗口结果必须幂等，且并发结果与单进程结果逐位一致。
8. 提供可交互的专业应用与可重复演示：支持 load、run、inject、resume、status、verify 子命令；status 以稳定排序 JSON 输出每窗口的批组成决策、误差谱条目、精度敏感标记与请求状态，verify 能重放请求轨迹并逐字段比对断续执行与一次性执行的结果。
