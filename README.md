需要在空白工作区中实现一个面向本地多进程模拟训练的“梯度同步通信调度服务”，复现数据并行训练中 all-reduce 的核心机制。每个训练 worker 进程持有一份本地梯度向量，按轮次向协调器提交梯度分片，协调器按配置的同步策略（全量同步、分桶流水线、参数服务器式分片聚合）完成跨 worker 聚合，再把平均梯度回发给各 worker 用于下一轮。系统须支持 worker 数量变化、worker 中途退出、通信超时与重传，并在多轮之间保证同一参数位置上各 worker 看到的聚合结果完全一致。协调器通过本地回环 TCP 与 worker 通信，全部状态持久化到 SQLite，服务重启后从已完成轮次的检查点继续，不得重算已提交轮次。难度来自交互延迟预算与计算结果一致性之间的耦合：桶越小延迟越低但聚合次数增多，超时重传与迟到分片必须在不破坏轮次一致性的前提下被吸收。

任务环境与准备：
确认 Windows 环境安装 Python 3.11 及以上，并安装 numpy 与 pytest 的可离线版本；不需要 GPU、外网或真实训练框架。
在工作区创建项目目录结构，预留样本梯度文件生成脚本的输出位置，样本由固定随机种子在本地生成，不依赖外部数据集。
确认本机允许本地回环 TCP 监听，用于协调器与 worker 桩交互；测试全部离线运行。
运行 pytest 前先执行一次本地样本生成，确保协调器数据目录为空或处于已知初始状态。

业务要求：
1. 实现 worker 注册与轮次提交协议：worker 注册时上报唯一标识、参数量与分片能力，协调器在每轮开始时广播轮次号与分片任务分配，worker 只提交本轮被分配的分片；重复提交同一分片必须是幂等的，迟到分片来自已结束轮次时返回业务码 E_STALE_ROUND 且不进入聚合。
2. 实现三种同步策略的聚合计算：全量同步在全部 worker 分片到齐后按参数位置求算术平均；分桶流水线把参数按桶大小切分，各桶独立成轮聚合以减少等待；参数服务器式按分片归属聚合后广播。三种策略在同一输入下必须产出逐元素误差不超过 1e-9 的相同平均梯度，不得因浮点累加顺序不同产生可见偏差。
3. 实现交互延迟预算与桶大小自适应：协调器为每轮设定等待预算，超预算未到的分片按配置策略处理（本轮降级为已到集合聚合或标记轮次失败）；协调器需在连续若干轮观测到平均到达延迟后调整桶大小，调整必须记录到事件流。降级聚合后必须显式标记参与 worker 集合，禁止静默丢弃 worker。
4. 实现 worker 异常退出的容错处理：worker 在提交分片前退出时，其分片必须由协调器按补齐策略处理（从聚合中排除并重算权重，或使用上一轮该 worker 的梯度），两种策略须可通过配置选择且行为可复现；全部 worker 退出时必须将当前轮标记为 aborted 并返回 E_NO_WORKERS。强制终止后的恢复只能依赖已持久化的分片与轮次状态。
5. 实现超时重传与去重：协调器对超时分片发起重传请求，worker 回复相同分片内容；重传到达时若原分片已入库，不得重复计入聚合，也不得改变聚合结果；同一分片的重传次数超过上限时该分片按未到达处理并记录失败原因。真实超时必须由 asyncio 超时取消实现，不得以固定 sleep 代替。
6. 实现持久化与轮次恢复的一致性：每轮的分片提交记录、参与集合、策略选择与聚合结果摘要写入 SQLite，事务提交后才对 worker 回发结果；进程重启后从最后完成的轮次继续，未完成轮次的分片按已持久化内容重建，不得要求 worker 重算已完成轮次。检查点写入与轮次推进之间不得出现部分可见的中间状态。
7. 实现聚合结果的一致性校验与异常链路：每轮聚合完成后由协调器计算聚合结果的校验摘要并随结果广播，worker 校验不一致时上报并返回业务码 E_DIGEST_MISMATCH；所有业务错误以固定错误码集合在 JSON 中返回，包括 E_STALE_ROUND、E_DUPLICATE_SHARD、E_TIMEOUT、E_NO_WORKERS、E_DIGEST_MISMATCH 与 E_INVALID_STATE。
8. 提供本地多进程演示与可重复测试：用本机多进程 worker 桩驱动至少 4 个 worker、2 种桶大小与三类故障注入（退出、超时、迟到分片），演示脚本输出每轮的参与集合、聚合摘要与决策事件；pytest 用例须在 Windows 离线运行，覆盖三种策略结果一致、超时重传去重、退出容错、重启续跑与非法状态拒绝，并在固定随机种子下可重复。
