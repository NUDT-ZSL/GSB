当前是空白工作区，没有现存项目、代码或数据附件。需要从零构建一个面向本地 Windows 环境的云原生可观测性告警关联与诊断工作台，交付形式为领域可视化与诊断工作台。用户在本地 JSON 文件中声明一组服务拓扑（有向依赖边，边带整数权重）与一组告警规则（规则标识、目标服务、指标名、比较条件、阈值与严重级）；观测样本以 NDJSON 录入，每行包含毫秒时间戳、服务标识、指标名与数值。工作台须把原始观测按规则判定为告警事件，再按固定毫秒时间窗口与服务拓扑可达关系把告警事件关联成告警簇，为每个簇推导根因候选并给出判定理由，识别被传播掩盖的衍生告警。核心要求是可复现：同一拓扑版本与同一观测输入，在不同告警到达顺序与不同处理并发度下必须得到逐字节一致的簇划分、根因候选与诊断报告；同时必须支持可复现的异常注入并验证注入确实生效。工作台以 Tkinter 呈现拓扑、簇、根因与注入轨迹，全部状态持久化到本地 SQLite。

任务环境与准备：
确认 Windows 本地已安装 Python 3.10 及以上版本，并可在命令行调用 python；Tkinter 随官方 Python 安装包提供，无外部网络依赖。
在工作区新建项目目录，规划源码、样本数据与演示脚本子目录，不预置任何已有代码或数据。
准备本地确定性样本：服务拓扑与告警规则 JSON 文件、观测 NDJSON 文件，以及拓扑演进后的第二版变更集样本。
运行前确认本地 SQLite 可通过 Python 标准库 sqlite3 使用，界面演示需在可交互桌面会话中启动 Tkinter。
演示脚本按只读方式使用源码与样本，异常注入仅通过命令行参数或输入文件完成。

业务要求：
1. 实现拓扑、告警规则与观测样本的加载及强校验：从本地 JSON 读取服务与依赖边，从 NDJSON 读取观测行；校验服务名唯一、依赖边两端服务存在、边权重为正整数、规则标识唯一、阈值与严重级合法、观测时间戳为整数毫秒且指标名属于受支持集合；任一不合法须以 E_INPUT 整体拒绝加载，并输出首个出错记录的行号、字段路径与期望约束。
2. 实现规则判定与告警事件生成：对每条观测按所属规则的条件与阈值以显式比较规则（含整数与浮点阈值的一致处理方式）判定是否产生告警事件，事件记录规则标识、服务、毫秒时间戳、观测值与严重级；同一观测不得重复生成事件，事件序列的排序须由稳定键决定而非输入顺序，告警事件摘要须可逐字节复现。
3. 实现按固定时间窗口与拓扑可达关系的告警簇关联：把时间邻域内且处于同一依赖链上的告警事件合并为簇，窗口重叠时须传递合并；聚类结果必须与观测行的输入顺序无关，并提供规范化簇标识（由簇内成员稳定排序后推导），跨服务的上下游告警关联须记录所用的拓扑路径，簇划分与拓扑版本绑定。
4. 实现簇内根因候选推导与衍生告警折叠：按拓扑入度、严重级与时间先后以确定性规则评定根因候选并排序，输出候选服务、支撑告警集合与判定理由；被判定为传播性告警的成员须折叠并标注触发的根因候选，同一簇重复推导必须得到相同候选顺序与相同折叠集合，不允许依赖字典或哈希遍历顺序。
5. 实现异常注入接口与注入生效的可复现验证：支持以命令行参数或界面操作注入至少三类异常（观测时间戳乱序、某服务依赖边被替换为新版本、观测样本缺失），分别以 E_ORDER、E_TOPO、E_GAP 业务码记录；每类注入须产出注入标识、影响范围与预期受影响簇集合，运行结束后由验证步骤确认受影响簇集合与预期一致，注入仅改变输入文件或参数，禁止修改源码制造失败。
6. 实现拓扑或规则版本演进后的增量失效与整体替换：规则或依赖边以变更集更新后版本号单调递增，须准确推导受影响簇集合并标记失效，未受影响簇结论保持不变且可校验；当前视图须整体替换而非增量合并，替换时须稳定列出失效簇、保留簇与版本差异，跨版本结论不得混用。
7. 实现诊断会话快照与强制终止后的恢复：会话状态持久化到本地 SQLite，含拓扑版本、规则版本、观测游标、簇与根因结论、注入轨迹与失效链路；进程被强制终止后重启只能依据已持久化的完整记录恢复，未完成处理须标记为未知并要求重跑，恢复报告须列出恢复的簇数、游标位置与版本差异，不得声称能生成退出报告。
8. 提供 Tkinter 可视化工作台与可重复演示脚本：界面展示服务拓扑与依赖边、告警簇成员、根因候选及理由、折叠的衍生告警、注入轨迹与当前版本，渲染顺序稳定；附带确定性样本拓扑、规则与观测及演示脚本，顺序执行首次全量关联、注入乱序后重算、拓扑演进后增量重算三个场景，每个场景输出含版本号、簇数、根因与业务码的诊断总结，供逐次比对复现。
