当前是空白工作区，需要从零实现一个本地分布式训练梯度同步的数据处理管线与结果验证工具，重点解决多工作进程通信格式在版本演进中的互操作问题。本地 JSON 训练计划给出：模型层清单（层名、参数量、参数分片方式）、同步策略（环形 AllReduce 分片数、桶大小、累积步）、通信信封版本（v1 为紧凑字段数组、v2 为带校验和与逻辑时钟的具名字段信封）、随机种子与超参。样本目录还提供两代历史同步进度快照：v1 为单文件 JSON 记录分片阈值与相对完成秒数，v2 为分片 JSON 加 SQLite 元数据记录绝对完成毫秒戳、同步代数与失效墓碑。管线需启动多个本地工作进程生成确定性梯度分片，按环形或树形拓扑完成收发并做跨版本信封编解码互操作，用串行单进程聚合结果作为唯一真值逐元素比对，并支持断点续算与结果验证。

任务环境与准备：
确认 Windows 上可用 Python 3.10 及以上解释器，并安装 NumPy（pip install numpy）与标准库 sqlite3（随 Python 自带，无需额外安装）。
在空白工作区创建项目目录，任务开始时仅存在本地样本 JSON 与快照目录，不预置任何代码文件。
准备固定本地样本：训练计划 JSON、两代通信信封样例文件、两代进度快照目录，全部由本地生成，不依赖网络或真实账号。
通信使用本地管道或回环 socket，不需要外部服务；SQLite 数据库文件路径由命令行参数指定，位于工作区内。
运行时通过命令行注入逻辑时钟与随机种子，验证过程不读取系统墙钟以保持可复现。

业务要求：
1. 实现训练计划、两代通信信封与两代同步进度快照的解析校验：层名唯一、参数量与分片数整除关系合法、桶大小为正整数、v1 紧凑字段数组的元素个数与分片声明一致、v2 具名字段信封的校验和与逻辑时钟字段类型合法、v1 相对完成秒数为非负整数、v2 同步代数单调；非法输入必须返回明确业务错误码且不写入任何持久化状态。
2. 实现通信信封的跨版本编解码互操作：同一分片消息在 v1 与 v2 信封之间必须无损转换，字段、校验和、轮次号与分片号在往返转换后逐字段保持等价，v2 新增字段在 v1 路径读取时按声明默认语义降级并记录兼容降级清单；编解码结果必须为稳定排序的确定性字节序列，相同消息重复编码逐字节一致。
3. 实现多工作进程的确定性梯度产生与分片：每个进程按全局种子与进程号生成固定梯度向量，按计划的分片方式与桶边界切分，相同种子与计划必须逐位复现；以串行单进程聚合结果作为唯一真值来源，分布式同步结果须与真值逐元素比对并输出首个差异元素、所属层与所属分片。
4. 实现环形与树形 AllReduce 通信协议以及跨版本信封的收发：基于本地管道实现 reduce-scatter 与 all-gather 阶段的轮次收发，消息带轮次号、分片号、校验和与信封版本标签；接收方须依据信封版本选择对应解码路径并在校验和与轮次号不符时触发该分片重传，重传次数受预算约束，超预算须返回业务错误码。
5. 实现跨版本进度快照的合并与续算裁决：同一工作进程同一分片在两代快照中同时存在时，依据逻辑时钟与同步代数裁决最新进度，逻辑时钟相同则按来源版本优先级；v1 相对完成秒数在注入逻辑时钟下换算为绝对完成时刻并记录换算标度与舍入方向；续算时只重发未确认分片，不得重复累加已提交梯度累积计数。
6. 实现强制终止后的恢复：把轮次号、累积步计数、每层梯度摘要哈希、分片提交状态、信封版本绑定、快照合并裁决与逻辑时钟水位以事务原子写入 SQLite；任一工作进程被强制终止后，恢复路径依据持久化状态识别未完成轮次与已提交分片，只重发未确认分片，不得承诺一定生成完整退出报告，也不得回退已提交状态。
7. 实现多进程并发一致性与幂等提交：多个工作进程及重复启动的恢复实例共享同一 SQLite 状态，通过事务与文件锁保证同一轮次同一分片只被提交一次、总同步结果只被整体替换一次，重复提交相同分片结果必须幂等；读取方只能看到完整已提交轮次的同步结果，不得观察到混用两代信封的中间态。
8. 提供命令行接口与结果验证工具：支持 plan、run、inject、resume、status、verify 子命令，status 以稳定排序 JSON 输出每轮次、每层梯度摘要、信封版本与换算精度记录，verify 校验持久化状态与输出结果一致并报告与串行真值的逐元素比对结论；使用固定本地样本产生两次运行完全一致的输出。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证跨版本信封互操作、分布式与串行真值逐元素一致、断点续算及异常错误码，附运行结果。
