校园计算与实验设施的共享对象存储池里，多个课题组持续写入实验数据与课程资料，值班管理员面对的是高频的对象键读查询：绝大多数查询针对根本不存在或已被删除的键，如果每次都落到后端分片索引，读放大与索引压力会迅速堆高。管理员希望先做一层布隆过滤器前置拦截，命中不存在即直接返回，其余再放行到后端分片索引核对；但写入、删除会不断改变键集合，过滤器容量也会逼近上限，需要换代重建与切换，同时历史工程以三个 schema 版本登记，字段命名、哈希种子表达与键编码方式各不相同。本题要求从零交付这套负查询加速内核，做到逐查询可核对、逐代可追踪。

任务环境与准备：
准备 Python 3 运行环境，仅使用语言标准库实现生成器、过滤器内核、参考实现与交互式命令行演示，不安装第三方包。
在工作区新建项目目录与可执行入口脚本，样本由题内确定性生成器按固定种子产出，不依赖真实对象存储、网络服务或外部账号。
在 Linux（WSL Ubuntu）终端运行演示命令，检查输出报告与整数退出码，确认无外部依赖即可复现全部裁决与统计。

业务要求：
1. 将三个 schema 版本的对象键、哈希种子与过滤器参数（位数组规模、哈希函数个数、每代最大插入量）归一为统一的字节键与位数组口径，键编码在原始字节与十六进制串之间转换后必须一致，同一键在各版本下映射到相同位位置。
2. 按声明参数构建逐代布隆过滤器，对每个插入键用全部哈希函数置位，输出每代位数组占用率、已插入键数与位数组中置位计数，占用率按置位计数除以位数组规模计算。
3. 对按逻辑时刻排列的读查询序列逐条执行过滤器判定，输出拦截或放行的裁决；放行的查询再落到后端分片索引核对存在性，并记录放行后核对为不存在的条目作为实测误判。
4. 处理对象删除：以计数布隆的逐位计数或代际标记消解删除键的残留误判，保证删除后再次查询该键时不再被判定为存在，并输出仍可能被误判为存在的键清单及其残留计数依据。
5. 当某代插入量逼近或超出声明上限时，以当前存活键集重建后继代并原子切换，记录触发时刻、迁移键数与旧代停用时刻，旧代停用后不再参与新的判定。
6. 按查询序列统计每代实测误判率与拦截率，并分别汇总两个课题组前缀下的负查询加速效果，统计口径与逐查询裁决结果可逐条复算。
7. 对同一工程在三个 schema 版本归一后产出相同的逐查询裁决、每代统计与误判率，并输出跨版本差异清单，标明字段命名、哈希种子表达与键编码的对应关系。
8. 提供不复用主实现位计算路径的独立位数组参考实现，逐查询核对过滤器判定结果与位占用是否一致，发现不一致时报告首个不一致查询、其键、计算出的位位置与参考实现的位状态。

验收：
用题内确定性样本逐查询核对拦截裁决、放行核对与误判率，并检查删除残留清理、超限重建切换与三版本归一结果的一致性。
