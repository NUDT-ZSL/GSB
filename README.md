当前是空白工作区，需要从零构建一个面向本地 Windows 环境的列式数据处理管线，聚焦算子下推与列裁剪，并在并行调度与资源预算约束下执行。用户在本地 JSON 文件中声明若干列式数据表（列名、类型、空值位图与确定性样本值）与一条处理查询：查询由扫描、逐表过滤、投影、两表连接与最终聚合组成。管线须先把查询编译为逻辑计划，再把过滤条件下推到扫描算子、把上游未引用的列从扫描与中间结果中裁剪掉，随后在受全局并行度预算与内存预算约束下把可并行的扫描与过滤任务分配到工作线程池执行。业务核心是：下推与裁剪必须与代价估算联动（下推的选择度估计决定并行任务切分粒度），并行执行的资源占用不得超出声明的预算，并且下推优化后的结果与未优化基线结果必须逐字节一致。另需一个结果验证工具独立核对执行轨迹与产出。

任务环境与准备：
安装 Python 3.11 或以上，并确认标准库 tkinter 可用，NumPy 通过本地已安装版本使用。
无需外部网络；样本列式数据与查询文件由演示脚本在本地工作区生成。
在 Windows 命令行下运行界面与演示脚本，验证工具与执行轨迹输出到本地文件。

业务要求：
1. 实现列式数据表与查询定义的加载与强校验：从本地 JSON 读取表结构与列式行数据，校验表名唯一、列名合法、列类型属于受支持集合、空值位图长度与行数一致、聚合与连接引用的列存在；任一不合法以 E_DATA 业务码整体拒绝加载并输出出错字段路径，且不得留下部分加载状态。
2. 实现查询解析与逻辑计划生成：支持扫描、逐表等值/范围/IN/AND 组合过滤、投影、两表内连接与分组聚合，生成稳定结构的逻辑计划树并给出规范化计划摘要；同一语义查询在空白与括号差异下须得到相同摘要，不支持语法以 E_PARSE 拒绝并说明原因。
3. 实现过滤下推与列裁剪：把可下推的过滤条件移动到对应扫描算子，并从扫描、连接中间结果与投影中有序裁掉未被后续算子引用的列；下推与裁剪后的计划须输出被下推条件集合、被裁剪列集合及其推导依据，且裁剪不得改变列类型与空值语义。
4. 实现下推选择度估计与并行任务切分粒度联动：依据下推后的过滤条件估算扫描输出行数与选择度，以整数定点输出估算值与量化误差上界；切分粒度须按估算行数与全局并行度预算确定，粒度决定任务数与每任务行区间，相同输入必须得到相同切分方案。
5. 实现受资源预算约束的并行执行调度：在全局并行度上限与内存预算（按每任务峰值列缓冲区字节数估算）下调度扫描与过滤任务，预算不足时任务排队且不得绕过预算；调度须输出每任务的开始与结束单调时钟毫秒、完成行数与峰值内存估算，任一时刻内存占用合计不得超过预算。
6. 实现优化结果与基线结果的逐字节一致性校验：提供命令分别以下推裁剪后的计划和未优化的基线计划执行同一查询，逐字节比较最终聚合输出与列序，不一致须以 E_DIVERGE 报告首个差异分组键与字段，并校验两条路径的收集统计与实际任务轨迹口径一致。
7. 实现会话快照的版本识别与整体替换恢复：快照持久化表结构版本、数据摘要、索引集合、统计快照、计划历史与执行轨迹；恢复时须比较快照版本与当前数据版本，不一致须整体替换当前表与统计状态而非增量合并，版本无法对应时以 E_VERSION 拒绝，并列出可辨识的差异项。
8. 提供 Tkinter 界面、结果验证工具与可重复演示脚本：界面展示逻辑计划树、下推条件、裁剪列、切分方案、各任务资源占用时间线与业务码，渲染顺序稳定；验证工具独立读取快照与产出校验计划与结果；附带样本数据与脚本顺序执行全量、下推裁剪后与恢复重放三个场景并输出结构化结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
