团队正在为即将替换的旧事务隔离诊断工具做一个独立原型，当前工作目录没有任何代码与样本，需要在 Linux（WSL Ubuntu）本地从零实现一个事务锁等待的定点时长账本与回滚裁决引擎，覆盖自研数据库连接池与事务管理模块。业务输入全部由随工程交付的固定种子脚本在本地确定性生成，包括 SQLite 样本库描述（表、列、索引及固定数据）、并发事务脚本流（每个事务含有序读写操作、隔离级别、锁声明与重试上限），以及两代锁等待策略快照：v1 为单文件 JSON，记录相对等待预算、重试倍率与扁平映射；v2 为分片 JSON 加 SQLite 元数据库，记录绝对生效毫秒、策略代数与失效墓碑。引擎以可注入逻辑时钟推进事务执行，通过自建锁表与等待队列收集每次锁等待的入队与出队时刻，按定点标度换算等待时长并累计误差账本；在等待预算耗尽或死锁环形成时裁决放弃或牺牲回滚。所有裁决须在逻辑时钟步进与持久化约束下完成，并在强制终止后恢复到同一账本状态。

任务环境与准备：
确保已安装 Python 3.10 或更高版本，执行 python3 --version 检查。
确保已安装 sqlite3 模块（Python 标准库自带），无需额外安装。
在 WSL Ubuntu 终端中创建工作目录，例如 mkdir -p ~/lock_wait_lab && cd ~/lock_wait_lab。
使用随工程交付的固定种子脚本生成样本：包括样本库描述 JSON、事务脚本 JSONL、两代策略快照文件及逻辑时钟注入配置，放置在工作目录的 samples/ 下。
安装项目依赖（若使用任何第三方库），建议在虚拟环境中执行 pip install -r requirements.txt（如无 requirements 则不需要）。
运行 python main.py load --samples samples/ 验证样本加载，再执行 run 子命令进行首次执行。

业务要求：
1. 解析并校验样本库描述、事务脚本流与两代锁等待策略快照，确保表名与列名唯一、索引与主外键引用合法、事务操作序列在固定隔离级别下可执行、相对等待预算为非负整数且 v2 绝对毫秒与策略代数单调，非法输入映射到独立业务错误码并保留首个违规字段。
2. 以可注入逻辑时钟的分层处理控制面推进每个事务的读写操作，该控制面按操作序列将事务拆分为可独立调度的执行单元，确保同一时刻对同一行的锁申请按稳定顺序进入等待队列，且读写冲突时排他锁与共享锁的互斥判定不依赖系统墙钟。
3. 把入队与出队逻辑时刻按声明定点标度换算为固定精度等待时长，登记每次换算的标度、舍入方向与被舍弃余量，并沿锁资源、持有事务与保持时长的依赖链累计误差上界，使同一事务脚本在任意进程内重复执行得到逐位一致的账本条目。
4. 在等待时长接近边界时触发精度敏感标记：当某事务等待时长与预算之差小于容差、或两个候选牺牲区的误差上界相交且牺牲裁决依赖等待时长差值时，必须输出参与比较的事务、锁资源、误差上界与精度提升一级后是否翻转裁决。
5. 在每轮逻辑时间预算与并行度上限下实现等待放弃与死锁牺牲回滚，预算耗尽须区分预算内未启动、入队后等待超时放弃与主动回滚，等待图按周期识别环并选择确定性牺牲事务回滚，同一批事务的放弃与牺牲顺序在恢复后保持稳定。
6. 以两代策略快照的版本递增为触发，对锁等待账本执行整体替换而非逐条覆盖：比较版本号、绝对毫秒与策略摘要，拒绝版本回退，并让进行中的事务绑定开始时的策略代数直到提交；快照提交记录必须与账本指针原子关联。
7. 将每轮待处理事务、已提交等待账本、锁持有表、等待队列与精度敏感记录全部持久化到 SQLite，进程在任何一步被 SIGKILL 后恢复时依据已提交水位与未完成事务登记重放缺失部分，不重复计数、不改变已提交裁决。
8. 提供命令行接口与可重复验证子命令，load、run、snapshot、resume、status、verify 均以稳定排序 JSON 输出待处理事务、账本摘要、实际使用的策略版本、误差上界与恢复后裁决。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
加载本地确定性样本，验证锁等待账本与回滚裁决的正确性及中断恢复一致性，并输出结构化结果。
