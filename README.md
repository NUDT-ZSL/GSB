团队准备新建一个项目，做本地消息顺序投递网关的控制面与数据面，用于在确定性样本上复现同一分区内严格顺序语义下的投递事务账本与积压追平裁决。本地 JSON 样本给出：主题与分区清单（主题名、分区数、分区键规则、每分区积压上限与乱序容忍窗口）、生产者事件流（事件序号、分区键、载荷摘要、注入逻辑时钟毫秒戳、期望投递代数）、消费者订阅声明（订阅者 ID、主题、每次拉取条数、消费速率上限、处理失败率声明、重试预算）以及网关配置（每分区顺序锁粒度、单轮追平逻辑时间预算、全局并发投递上限、重试退避基数与上限、定点标度与容差）。网关需要把事件按分区键稳定路由到分区并分配单调偏移，投递必须以事务提交偏移、投递代数与消费位点，积压追平要在预算约束下按分区并发推进，且任一环节被强制终止后偏移不得跳号或重复投递。核心冲突是顺序锁粒度决定并发度，而追平预算又要求提高并发，两者与偏移单调性、失败重试退避形成直接矛盾。

任务环境与准备：
Windows 10 及以上，安装 Python 3.11 并确保 pip 可用
执行 pip install fastapi==0.110.0 uvicorn==0.27.1 numpy==1.26.4 pytest==8.0.0
在空工作区创建项目目录与 SQLite 数据库文件路径，无需外部服务或网络访问
准备本地 JSON 样本：主题分区清单、生产者事件流、订阅声明与网关配置各一份，含少量非法条目用于异常链路验证
提供独立进程强制终止的验证脚本入口，仅用于恢复流程演示，不修改被测源码

业务要求：
1. 实现主题分区清单、生产者事件流、订阅声明与网关配置的解析校验：主题名与订阅者 ID 唯一、分区数为正整数、分区键可规范化为稳定分区、积压上限与拉取条数为正整数、注入逻辑时钟为非负整数、重试基数为正整数且退避上限不小于基数、定点标度与容差为正；非法输入必须返回 E_BAD_SAMPLE 且不写入任何持久化状态。
2. 实现分区键到分区的确定性路由与单调偏移分配：同一分区键在任意运行次数下必须落到同一分区，事件偏移按分区内追加顺序单调递增且不跳号，每次追加在同一事务内写入偏移、载荷摘要、投递代数与逻辑时钟戳，并输出分区日志摘要作为后续追平裁决的唯一真值来源。
3. 实现顺序锁粒度可配的多分区并发追平调度：按分区并发推进拉取与投递，同时受全局并发投递上限与单轮追平逻辑时间预算双重约束；预算耗尽必须放弃剩余未启动分区并记录放弃原因，严格区分预算内未启动、启动后失败与主动放弃三类结局，已启动分区必须完成本轮投递而不得以事后标注超时替代真实预算判定。
4. 实现投递重试与退避的代数演进：投递失败按退避基数与当前投递代数计算下一次可投递逻辑时刻并施加确定性抖动与上限，代数超限进入死信并记录耗尽原因；重复确认、迟到确认与跨订阅者确认必须幂等且不得使投递代数回退或使已确认偏移重新进入待投递队列。
5. 实现追平过程中的顺序与幂等一致性裁决：同一分区任一时刻最多一个投递在途，后偏移事件不得越过前偏移未确认事件，同一事件重复投递必须由订阅者幂等键去重并在账本中只记一次实际投递；须输出追平完成时的可投递偏移、已确认偏移、死信偏移与三者之间的空隙清单，空隙必须可解释。
6. 实现账本与追平状态的持久化及强制终止后的恢复：把分区已提交偏移水位、投递代数、在途投递登记、确认标记、死信墓碑与逻辑时钟水位以事务原子写入 SQLite，每轮提交以版本号整体替换当前账本指针；进程在追加、投递或确认中途被强制终止后，恢复路径只重放未提交部分且不得重复累计代数或重复投递已确认事件，恢复结果与不中断运行逐字段一致。
7. 实现多进程并发一致性与业务错误码隔离：多个网关实例并行处理不同分区时，通过 SQLite 事务与文件锁保证同一分区同一偏移只被追加一次、同一事件同一代数只被投递一次、全局并发额度不被并发超卖，重复提交相同轮次结果幂等；分区积压超限、订阅者不存在、投递引用不存在事件、确认引用不存在的在途投递、逻辑时钟回拨超容差分别映射到不同业务错误码并保留可诊断字段。
8. 实现基于注入逻辑时钟的自适应锁粒度取舍与可重复命令行演示：当分区积压深度或并发投递数超过阈值时在分区级顺序锁与分段顺序锁之间切换，并输出实际模式、切换触发条件、被否决模式原因与切换前后一致性结论；提供 load、produce、deliver、resume、status、verify 子命令，status 以稳定排序 JSON 输出每分区偏移水位、在途投递、死信与逻辑时钟水位。
