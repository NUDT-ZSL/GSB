房产交易与租赁办理平台的消息中间件运维工程师要在正式接入消息总线之前，先把消费者重平衡这段最容易出错的逻辑做成本地可复核的独立内核。平台中成交确认、合同签署、资金监管、过户预约等办理事件按主题分区消费，事件以房源编号或办理单号作为分区键；当消费者实例上线、离线或处理能力变化时，分区归属必须重新分配，且同一房源或同一办理单的事件始终由同一消费者顺序处理。同一份消费组工程会以三个 schema 版本流入：字段命名不同，分区编号有的从 0 起有的从 1 起，会话超时与心跳有的用毫秒有的用秒，分区清单有的写成扁平表有的写成按主题分组的嵌套树。旧成员尚未确认的事件在重平衡时必须回收再投递，既不能丢也不能重复越界。运维工程师需要一个本地确定性可复现的内核，逐轮算出归属方案、再投递清单与积压摘要，并给出跨版本归一差异报告。

任务环境与准备：
准备 Python 3 运行环境，本题只使用标准库，无需安装第三方包。
在空工作区建立项目入口与本地确定性生成器，按固定种子产出三版本消费组工程、成员事件序列与分区键事件流。
本地运行入口输出各轮归属方案、再投递清单、消费位点摘要与归一差异报告，供逐轮核对。

业务要求：
1. 实现消费组工程装载器，把三个 schema 版本的成员、订阅与分区描述归一为统一内部模型，记录每个归一字段的来源路径与原始版本，使同一内容在三版本下装载后得到相同的统一模型。
2. 按逻辑时刻依次处理成员加入、主动退出、处理速率变更与心跳事件，依据各版本声明的会话超时裁定成员存活，为每轮重平衡输出触发原因、参与成员与判定存活或失效的依据。
3. 在有存活成员的前提下生成分区归属方案：以分区键稳定哈希给出亲和候选，再按成员声明处理速率做加权分配，输出每轮归属并核对每个分区键只落在一个成员名下。
4. 重平衡时回收即将失去分区的成员上未确认事件的位点，按新归属生成再投递清单，保证每个未确认事件恰好被再投递一次且位点区间连续、不越界。
5. 输出重平衡前后各成员持有的分区变化清单，以及按成员与主题统计的已确认位点与积压条数摘要，并标出分配后负载偏差超过阈值的成员。
6. 成员处理速率变更后只对受影响主题做局部归属重算，并与同时刻全量重平衡的结果逐分区比对，输出一致性结论与差异分区。
7. 处理分区数少于成员数、同一时刻多成员加入与退出、心跳恰在会话超时边界、分区键集中度极高等边界输入，给出确定的归属与存活判定结果。
8. 提供固定种子的确定性生成器产出消费组工程、成员事件序列与分区键事件流，并输出跨版本归一差异报告作为归属计算的追溯凭证。

验收：
核对三版本归一结果一致、逐轮分区键单归属、再投递不丢不重、局部重算与全量重平衡逐分区一致。
