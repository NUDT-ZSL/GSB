从无到有搭建时，需要构建一个面向 Transformer 前向链路的本地可集成算子组件与完整示例，核心业务问题是激活算子与转置重排算子在同一算子链中连续调用时，如何把二者融合为单一分块内核从而避免中间张量落盘，并在融合口径下保证数值与逐算子分别执行的参考结果逐元素一致。业务对象是本地确定性生成的算子任务清单（JSONL，字段含 case_id、op_chain、input_shape、axis_order、activation_kind、block_size、eps、dtype、seed、policy），以及由固定种子驱动 NumPy 生成的输入张量；不依赖任何外部服务或真实数据集。组件需要为每个 case 识别可融合的相邻激活与转置重排算子对，建立融合内核与独立执行之间的等价性证据，并在融合不可行时按显式规则退回逐算子执行。

任务环境与准备：
安装 Python 3.10 或 3.11，并执行 python -m pip install numpy==1.26.4 与 pytest==8.2.0。
在 Windows 工作区创建项目目录，用固定种子与脚本生成算子任务清单 JSONL 与输入张量 npz 样本，样本写入本地 data 子目录。
运行前确认本地缓存目录与快照目录可写且未被其他进程占用；示例命令以 python -m 方式从项目根目录执行。

业务要求：
1. 实现算子链解析与可融合性判定入口，按任务清单解析 op_chain、input_shape、axis_order、activation_kind、block_size、eps、dtype 与 seed，逐 case 识别 op_chain 中相邻的激活与转置重排对是否可融合（融合可行性由激活是否逐元素、转置是否为纯轴重排、两算子间是否存在归约依赖等显式规则判定）；不可融合对须记录理由并退回逐算子执行，算子名未知或轴序不是输入维度合法排列分别返回 E_OP_UNKNOWN 与 E_AXIS_INVALID 并指明 case_id。
2. 实现两阶段融合分块内核：融合对在单一内核内先对输入块按 block_size 分块计算激活、再按语义轴序在块内直接重排写出，不产生中间激活张量；块边界以显式声明的元素索引确定，重排输出位置须由轴序唯一推导；同一 case_id、同一 seed 与同一配置下融合路径与逐算子路径必须逐字节产出相同的中间张量摘要与最终输出，禁止依赖系统时间或未声明的全局状态。
3. 实现融合内核与逐算子参考执行的逐元素一致性裁决：以逐算子分别执行在 float64 下的结果为参考真值，记录最大绝对偏差、最大相对偏差与超出容差的元素位置；超出容差返回 E_TOLERANCE_EXCEEDED 并输出越界位置与偏差谱，使偏差可定位到激活计算口径、轴序重排映射或块边界写出位置中的一级。
4. 实现四类由输入或参数触发的异常注入：在算子链解析、融合可行性判定、融合内核数值计算、一致性裁决四个环节分别提供注入点（如 op_chain 含未知算子、转置轴序重复、激活输入含非有限值、容差配置非正），注入不得通过修改源码制造；每次注入须产生带环节名与业务码的记录，且不得使未被注入的 case 结果或复用判定发生变化。
5. 实现融合内核产物的内容寻址缓存与部分失效联动：缓存键须纳入输入张量内容哈希、算子链摘要、轴序、block_size、eps 与精度档，键相同必须复用、键不同必须重算；当轴序变化时应使该融合对的产物及下游失效，而仅 eps 变化时只使激活相关产物失效，须输出受影响 case 与受影响节点集合并仅重算受影响后缀。
6. 实现融合与逐算子两种执行路径的取舍裁决：当融合减少一次中间张量写出与一次完整遍历但使块内重排布局更不规整、降低缓存局部性，且融合后单块驻留内存高于逐算子时，须按显式优先级规则在内存、局部性与遍历次数之间裁决是否融合并在执行计划中记录依据；同时执行计划、缓存条目与结果快照各携带单调递增版本号与内容校验和，检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明 case_id。
7. 实现资源上限与退回策略：为单次调用估计驻留内存、块数量与并行重算 case 数设可配置上限，超限时返回 E_RESOURCE_LIMIT 或退回逐算子执行、缩小分块或降低精度档；退回须在结果中标记退回类别与触发它的上游业务码，退回不得改变已提交结果，且退回后仍须覆盖全部受影响 case 并给出与逐算子参考一致的裁决结论。
8. 提供可集成的领域组件接口与完整示例，并实现跨模块一致性自检：暴露 execute、inject_diagnose、cache_diagnose 与 equivalence_report 入口；自检校验各环节处理的 case_id 集合一致、缓存键与产物哈希互相可核对、失效节点与复用节点无交集且并集覆盖全部受影响节点、融合输出可由逐算子参考与轴序映射独立复算一致，不一致返回 E_INCONSISTENT 并指明 case_id 与环节。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证融合内核与逐算子执行的一致性裁决、异常注入归因及部分失效联动，并附运行结果。
