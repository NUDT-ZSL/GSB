在全新工作区中，需要从零构建一个面向搜索推荐前链路多路召回融合的本地数据处理管线与结果验证工具。业务对象是本地确定性生成的文档集合与查询集合：文档 JSONL 每行含 doc_id、terms（term 与词频）、doc_len、category、quality_score；查询 JSONL 每行含 query_id、terms、top_k 与可选过滤条件；另有一份融合配置声明四路召回（词项倒排、词项前缀、类别热门、向量近似）的启用状态、各路候选数、融合权重、归一化口径、并行 worker 数与总候选、融合比较、驻留内存三类预算。管线把一次融合检索建模为多阶段流水：查询分块摄入与校验→四路召回→跨路候选对齐去重→归一化与加权融合→并行调度与预算准入→结果聚合与指标统计。核心业务问题是并行调度与资源预算，需要在总候选预算、融合比较预算与驻留内存上限下决定准入与降批，并使调度结果可复现、执行摘要可回溯、被拒查询可核对。

任务环境与准备：
安装 Python 3.11 或更高版本，并在项目虚拟环境中执行 pip install numpy
在全新工作区创建项目目录与本地样本生成入口，样本与配置均由固定种子确定性生成，不依赖网络或真实数据
确认本地进程池可在 Windows 下启动，且子进程入口使用 if __name__ == '__main__' 保护

业务要求：
1. 实现四路确定性召回：词项倒排按查询词项与文档词频打分，词项前缀按 term 前缀匹配，类别热门按 category 与 quality_score 排序，向量近似按固定种子生成的文档向量与查询向量做余弦相似度排序；每路输出候选 doc_id、路名与原始分，各路候选数由配置给出且截断后按原始分降序、同分按 doc_id 升序排列，同一查询与同一配置下四路候选逐字节可复现。
2. 实现跨路候选对齐与去重：按 doc_id 归并各路候选，同一 doc_id 在多路命中时保留每路原始分与路名，去重口径由配置在“保留最高归一化分”与“保留首路命中”之间选择；须保证最终候选集中无重复 doc_id，且被合并记录的路名数量与原始分明细可核对，配置去重口径非法时返回 E_MERGE_POLICY 并指明查询与字段。
3. 实现可配置的分数归一化与融合层：提供分数缩放归一化与排名倒数归一化两种口径，按融合权重加权求和；须逐候选记录每路原始分、归一化分与加权贡献，使最终分数可由明细独立重算一致，归一化口径非法或权重含负值分别返回 E_NORM_INVALID 与 E_WEIGHT_INVALID 并指明查询。
4. 实现并行调度层：按可配置 worker 数与每批查询数把查询分块分配给本地进程池执行四路召回与融合，分块边界、任务派发顺序与归并顺序必须确定性可复现；worker 内异常须以结构化业务码与阶段名回传主进程并归因到具体批次与 query_id，单个查询失败不得静默丢弃或影响其他查询的最终结果。
5. 实现总候选预算与融合比较预算的双重准入裁决：按文档数、各路候选数与过滤条件估算每查询代价，在总候选预算与融合比较预算内决定准入集合与各路候选规模；超限时按显式优先级返回 E_RECALL_BUDGET 或 E_FUSION_BUDGET 并附带剩余预算与被拒查询清单，被拒查询不得出现在执行摘要的已完成集合中。
6. 实现驻留内存上限与淘汰策略：为同时驻留的候选数组与融合中间表设可配置内存上限，超限时按明确的分片淘汰策略释放已归并查询的数据或返回 E_RESOURCE_LIMIT；淘汰策略不得丢失最终统计所需的计数与明细，须在调度报告中记录淘汰触发点、释放量与保留量，且淘汰后完成的查询结果与无淘汰运行一致。
7. 实现精度、内存与延迟之间的显式冲突裁决：当扩大候选数提升召回但逼近内存上限、切换到两段式先粗排后精排提升融合质量但突破融合比较预算、降低并行度节省内存但放大整体延迟时，须按配置声明的优先级顺序裁决，并在调度报告中记录每次裁决的依据、被牺牲的指标与所选批规模，裁决结果须在同一观测下逐字节一致。
8. 实现召回统计与融合权重的版本化快照及整体替换：每路召回统计量、归一化参数与融合权重各携带单调递增版本号与内容校验和，提交时整体替换旧快照而非增量修补；加载时检测版本号或校验和变化并整体替换，旧版本不得覆盖新版本且回退尝试返回 E_SNAPSHOT_ROLLBACK，损坏或校验和不符返回 E_SNAPSHOT_CORRUPT 并指明快照种类与版本号。
