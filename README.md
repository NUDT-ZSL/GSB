在空白工作区构建一个本地确定性的图像修复与风格迁移领域编辑器，核心解决任务产物在多种交换格式之间的互操作与版本兼容问题。系统输入为程序生成的 PNG 图像样本（含待修复的矩形缺损区域）、风格参考图、修复与风格迁移配置 JSON，以及两份不同版本的工程交换文件：v1 工程为二进制掩码编码（掩码以 1 位行程压缩存储，风格参数为单个整型强度档位），v2 工程为文本 JSON 编码（掩码以 base64 编码的逐像素 0/255 数组存储，风格参数为分通道浮点权重对象并带命名调色板）。两类工程在掩码精度、参数表达粒度与元数据上不等价；编辑器需支持在两种版本间互转、编辑掩码与风格参数、执行确定性的修复填充与风格迁移渲染，并在版本降级或升级时明确信息保留与降级损失记录。所有渲染算法必须为本地确定性实现（邻域加权填充与查表式颜色映射），不依赖任何预训练权重或外部服务。

任务环境与准备：
安装 Python 3.10 及以上版本，并安装 NumPy 与 Pillow，版本以本地已可用为准。
在工作区创建 samples 目录，使用脚本按固定种子生成若干 PNG 待修复图与风格参考图，并生成对应的 v1 二进制工程与 v2 JSON 工程样本。
准备修复与风格迁移配置 JSON、版本映射表、量化规则与回放编辑序列文件，均放在本地配置目录中。
准备异常注入样本：非法行程、长度不符 base64、未知版本号、缺失通道权重等畸变工程文件。
确认命令行交互与回放演示可在 Windows 终端本地运行，无需网络与外部服务。

业务要求：
1. 实现双版本工程文件解析器：分别读取 v1 二进制行程压缩掩码与整型风格强度、v2 JSON 掩码 base64 与分通道浮点权重及命名调色板，解析为统一的掩码位图、风格参数结构与来源版本元数据；遇到非法行程、base64 长度不符、通道权重缺失或版本号未知时输出 E_FORMAT_INVALID 或 E_VERSION_UNSUPPORTED 业务码并进入失败清单。
2. 实现工程版本双向转换器：v1 升 v2 时将整型强度按可配置映射表展开为分通道权重并生成调色板元数据，v2 降 v1 时将分通道权重按可配置量化规则折叠为单一强度档位并把浮点精度损失、调色板条目与掩码位宽差异写入降级损失清单；转换后生成的工程必须能被原版本解析器重新读入且掩码位图逐像素一致。
3. 实现确定性修复填充渲染：对缺损区域按由外向内逐层推进的邻域加权均值填充，权重为距离平方反比，平票和边界外像素按固定规则处理，全部计算使用整数或定点数以避免平台差异；同一输入与配置在任意运行中输出的修复图像必须逐像素一致，并输出每层填充的像素数与来源像素统计。
4. 实现确定性风格迁移渲染：以查表方式将修复后图像颜色按分通道权重与调色板映射到目标风格，映射表由风格参数与参考图统计量确定性构建，采用固定量化档位；禁止随机采样，同一工程与参考图必须得到逐像素一致的风格结果，并输出映射表规模的构建耗时与命中统计。
5. 实现跨版本渲染一致性校验与诊断报告：对同一内容分别以 v1 与 v2 工程渲染，对比两份输出的逐像素差值、掩码覆盖范围差异与风格参数折算偏差，输出 JSON 报告包含最大通道差、差异像素数、降级损失清单条目、业务码与统一结构指纹；当折算偏差超过可配置阈值时标注为版本兼容告警但不中断渲染。
6. 实现版本化快照与恢复一致性：每次成功编辑或转换后以临时文件加原子替换方式写盘快照，快照含全局版本号、统一工程结构指纹、降级损失清单哈希与编辑操作日志摘要；读取时以快照版本号与当前工程内容指纹判定是命中复用或拒绝恢复，指纹不符时输出 E_SNAPSHOT_STALE 且不得静默读取旧快照。
7. 实现异常链路隔离与可处理退出语义：解析、转换、修复、风格迁移、恢复五个阶段分别捕获异常，记录阶段名、源工程路径、像素坐标或参数键与异常类型到失败清单并继续处理其余工程；收到可处理的退出信号时完成当前工程的快照原子替换与进度记录后以整数退出码 0 退出，进度记录含最后完成的操作序号与快照版本号，恢复从该操作之后继续。
8. 实现可交互的专业应用与可重复演示：提供命令行交互会话支持加载工程、切换版本、编辑掩码矩形区域、调整风格参数、执行渲染、查看诊断报告与回放整段编辑序列；回放时按相同编辑序列从空白工作区重放得到的最终渲染像素与报告内容必须与交互过程一致，交互与演示的全部业务码与字段名须与前述要求一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证双版本互转、修复与风格渲染的确定性、诊断报告及异常码。
