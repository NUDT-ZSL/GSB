技术方案确定后开始工程实现，当前工作目录尚未创建任何代码或样本，需要从零交付一个面向表格二分类线性模型正则化训练与推理链路的诊断引擎。业务对象由本地固定种子脚本确定性生成：样本清单为 JSONL，每行含 sample_id、若干数值列与类别列、label；训练配置声明正则化类型、强度路径、迭代上限与收敛容差、精度档、定点缩放因子及分块口径；另有两代配置快照并存，v1 为单文件 JSON 记录相对秒与参数，v2 为分片 JSON 加 SQLite 元数据库记录绝对毫秒、配置代数与内容摘要。系统需完成特征标准化、逐档正则化求解、分块计算、结果校验与诊断报告输出，并支持异常注入。

任务环境与准备：
Python 3.10 及以上版本
NumPy 1.24 及以上版本
SQLite3（标准库自带）
创建本地虚拟环境并安装上述依赖
使用随题附带的固定种子脚本生成样本与配置快照，放置在 ./data 目录下

业务要求：
1. 实现确定性的特征标准化与正则化路径求解层：数值列按配置做 z-score 或 min-max，类别列按固定规则编码；从强度最大的档开始逐档用确定性求解器求解，每档输出系数向量、截距、目标函数值与收敛标记，同分或同收敛点时按档位顺序严格推进。
2. 实现可切换的精度档执行层：float64、float32 与定点缩放整数三档共用同一算子语义，定点档的缩放因子与舍入模式由配置显式给出；同一输入在不同精度档下结果差异必须仅来自数值精度损失本身，禁止切换精度档时改变特征处理顺序、分块划分或收敛判定结果。
3. 实现基于输入规模的分块策略决策器：按样本数、特征数与当前剩余预算选择分块尺寸、归约顺序与是否走小分块降级路径，输出含决策依据的代价估计记录；同一观测与同一配置下决策必须逐字节一致，所选分块必须覆盖全部样本行，且分块路径与整块路径的目标函数值在声明容差内一致。
4. 实现四阶段异常注入框架：在特征标准化、逐档求解、分块归约、结果校验四个阶段分别提供由输入或参数触发的注入点（如类别列取值越界、正则化强度非正、分块尺寸为零、收敛容差非正），注入不得通过修改源码制造；每次注入必须产生带阶段名与业务码的结构化记录，下游按显式策略降级并携带降级类别。
5. 实现两代配置快照的解析、互迁与整体替换：v1 单文件 JSON 扁平参数与 v2 分片 JSON 加 SQLite 元数据库均需解析为统一内部配置；升级时补全元数据字段并记录补全来源，降级时按显式丢弃规则处理；检测到版本号或校验和变化时必须整体替换旧快照而非增量修补，回退尝试返回 E_SNAPSHOT_ROLLBACK。
6. 实现定点误差传播计算与主导来源归因：以同一输入上 float64 整块路径为参考真值，输出特征缩放、分块累加、定点量化、正则化梯度更新各级的绝对偏差、相对偏差、误差区间与误差放大比，并定位主导误差级别；偏差谱必须与分块决策及精度档配置可重放一致。
7. 实现结果校验与跨档一致性自检：校验各精度档下系数向量、目标函数值与收敛标记可由标准化统计量及路径参数独立重算一致，分块路径与整块路径结果一致，且异常注入后的降级结果仍满足同一快照内口径一致；不一致返回 E_INCONSISTENT 并输出首个偏差位置。
8. 实现强制终止后的恢复逻辑与并发提交控制：在路径档位或阶段边界持久化带单调递增版本号与内容校验和的检查点，重启时从最近已提交检查点继续，已提交档位不得重算；同一时刻只允许一个配置快照提交生效，并发冲突时后到者立即获得 E_STAGE_BUSY 而不阻塞等待。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
