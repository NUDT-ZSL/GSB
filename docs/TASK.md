当前是空白工作区，需要从零构建一个面向本地 Windows 环境的 HTTP/2 多路复用诊断工作台，作为领域可视化与诊断工作台交付。用户在本地 JSON 文件中声明一次连接的初始条件：客户端与服务端的初始流控窗口大小、最大并发流数、每个流的权重与依赖（形成优先级树）、帧大小上限与一组确定性请求序列；工作台在本地回环 TCP 端口上运行一个最小可用的 HTTP/2 对端服务（基于本地依赖库完成帧编解码与 HPACK，不访问真实站点），客户端侧按声明并发发出多个流并完成多路复用收发。核心业务是：在不同流数量、帧大小与窗口规模下，工作台须在若干个调度策略之间做算法取舍（如按权重轮转、按流剩余窗口优先、按到达顺序），并通过可视化展示 HEADERS/DATA/WINDOW_UPDATE 帧的时序列、各流的发送进度与窗口余量，同时对“计算正确的发送配额”与“观测到的进度一致性”做诊断，识别窗口耗尽、优先级饥饿与流状态机违规。环境准备：Python 3.11 与本地安装的 h2、hyperframe、hpack 依赖（离线 wheel 或 pip 内网源），Tkinter 随 Python 标准发行版提供；样本清单与请求序列均为本地确定性文件，不依赖真实网络站点、账号或外部服务。

任务环境与准备：
安装 Python 3.11 并确认 Tkinter 可导入；准备 h2、hyperframe、hpack 的本地离线 wheel 或可用内网源，执行安装并记录版本。
在空白工作区创建项目目录，准备本地确定性样本声明清单、请求序列与对端脚本，全部文件位于工作区内。
确认本地回环高位端口可监听；准备演示脚本入口与运行说明，样本与依赖均不依赖真实站点、账号或外部服务。

业务要求：
1. 实现连接声明清单的加载与强校验：从本地 JSON 文件读取初始窗口大小、最大并发流数、帧大小上限、流的权重与依赖关系以及请求序列；须校验窗口大小与帧大小在协议允许的整数范围内、权重为 1 至 256 的整数、依赖关系构成无环优先级树、并发流数不超过本地约束，任一不合法须以 E_DECL 业务码整体拒绝加载并输出出错字段路径。
2. 实现本地回环 HTTP/2 对端服务与客户端帧收发：在回环端口上完成连接前言、SETTINGS 交换与 HPACK 编解码，客户端按声明并发发出多个流并完整完成 HEADERS 与 DATA 序列；对端须按确定性规则回应 WINDOW_UPDATE，若帧序列违反连接或流状态机须以 E_PROTO 报告违规帧类型与流标识，且不得依赖真实站点或外部服务。
3. 实现至少三种多路复用发送调度策略：按权重轮转、按流剩余窗口优先与按到达顺序，每种策略须在给定帧大小上限与窗口余量下计算每一帧应分配的字节数与目标流，分配须满足单帧不超过帧大小上限且不超过该流可用窗口；同一策略在相同输入下多次运行必须产出逐字节一致的发送计划。
4. 实现调度策略的规模自适应取舍：依据并发流数量、流权重分布与窗口规模按确定性规则选择一个默认策略并输出选择理由与关键规模参数；当候选策略的预估空等代价之差小于显式阈值时须按稳定决胜规则选择，不得依赖字典或哈希遍历顺序，且取舍结论须与发送计划一并写入诊断报告。
5. 实现流控窗口账本与窗口耗尽诊断：逐流与连接级维护已发送字节、窗口余量与 WINDOW_UPDATE 增量，窗口余量不得因并发发送变为负数；须识别窗口耗尽导致的空等区段并记录起止单调时钟毫秒与受影响流标识，窗口账本须与对端回写增量逐项对账，不一致须以 E_WINDOW 列出首个偏差流与字节数。
6. 实现优先级公平性诊断：统计各流实际获得字节数与按权重应得配额，计算饥饿指标并识别连续若干轮未获配额的流；权重为零或依赖权重失效时须按显式回退规则处理并标注，诊断输出须包含每流的应得、实得与偏差量，且排序稳定以便逐次比对。
7. 实现会话快照的版本识别与整体替换恢复：快照持久化声明清单版本、策略选择与阈值、逐流窗口账本、发送计划与诊断结论；重新打开快照时须先比较快照声明版本与当前会话版本，不一致须整体替换当前窗口账本与发送计划状态而非增量合并，恢复后须能继续对同一批次发送重放校验并以 E_REPLAY 报告不可复现的具体依据。
8. 实现 Tkinter 可视化与可重复演示脚本：界面展示帧时序列、各流窗口余量曲线、策略当前选择、公平性诊断与快照列表，渲染顺序稳定；附带本地确定性样本清单与对端脚本，顺序执行单策略小规模发送、切换策略并放大流数三组场景，每组输出包含策略、帧数、空等区段与公平性指标的诊断总结。
