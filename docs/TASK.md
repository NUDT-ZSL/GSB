当前是空白工作区，需要从零构建一个面向本地 Windows 环境的 Kubernetes 调度与亲和性仿真诊断工作台，用于分析调度打分中的数值精度与误差传播。用户以本地 JSON 文件声明若干 Node（带标签、可分配 CPU/内存值与污点）与若干 Pod（带资源请求、节点亲和性硬/软约束、节点反亲和性硬/软约束、污点容忍），工作台按 Kubernetes 调度框架的语义模拟过滤（Filter）与打分（Score）两个阶段：过滤阶段判定硬约束与资源是否满足，打分阶段把节点亲和、节点反亲和、资源均衡、镜像本地性等多个打分插件的结果加权求和，选出得分最高的节点。核心业务是：在同一条调度流水线上，每个打分插件输出定点整数分，加权求和时需以整数定点方式处理权重比例，并在最终分数并列、插件输入统计量缺失或节点受限时才可用时给出稳定可解释的决胜规则；同时要求诊断工作台能追溯每个 Pod 的得分沿插件的传播路径、量化定点归一化引入的误差上界，并把一次完整调度会话（节点集合版本、Pod 队列、插件权重参数、全部得分明细与最终绑定结果）持久化为快照；用户可修改权重参数或节点状态后继续仿真，也可回退到历史快照继续，快照整体替换且必须识别版本变化。整个工作台须在 Windows 本地以确定性样本运行，不依赖真实集群。

任务环境与准备：
安装 Python 3.11 及以上版本并确认 tkinter 可用，安装 NumPy 与 PyYAML 用于样本清单解析与定点数值辅助。
准备确定性样本：节点清单与 Pod 队列 JSON，覆盖污点、硬软亲和性、资源受限节点与统计缺失节点，保证多次运行输入逐字节一致。
准备本地演示脚本与异常注入参数说明，验证过程不依赖网络、真实集群或任何外部账号。

业务要求：
1. 实现节点与 Pod 清单的加载与强校验：从本地 JSON 文件读取 Node 集合与 Pod 队列，校验节点名唯一、标签键值合法、可分配 CPU 与内存为正整数、污点 effect 属于预定义集合、Pod 资源请求为正整数、亲和性规则引用合法标签键；任一非法记录须以 E_MANIFEST 业务码整体拒绝加载并指出出错条目与字段路径，不允许部分加载。
2. 实现 Filter 阶段的硬约束判定：按节点亲和硬约束（requiredDuringScheduling）、节点反亲和硬约束、污点容忍与可分配资源是否满足依次过滤节点，输出每个被过滤节点的具体拒绝原因与所处过滤项；同一 Pod 对同一节点集合重复过滤必须得到相同的被拒原因序列，且资源判定须使用整数比较避免浮点误差。
3. 实现多插件 Score 阶段的整数定点打分：每个打分插件（节点亲和软约束、节点反亲和软约束、资源均衡、镜像本地性）输出 0 至 100 的定点整数分，权重以整数比例给出，加权求和须以整数定点方式完成并输出每插件的原始分、权重与加权贡献，禁止用浮点累加决定最终名次。
4. 实现定点归一化的误差上界推导与报告：对权重比例与加权求和过程给出量化误差上界（以分数单位与整数格表示），在评分报告中列出每个 Pod 的误差上界、所用定点格度与插件贡献明细；当两个节点最终分数之差小于误差上界时，必须标记为不可区分并列，不得凭误差范围内的差值直接判定胜者。
5. 实现并列与统计缺失下的决胜规则：当多个节点得分不可区分并列时，按节点名稳定排序或按明确记录的决胜策略选择，且决胜依据须写入诊断输出；当某打分插件所需统计量缺失或节点受限（如可分配资源为零）时，插件须输出明确的不可用标记而非默认零分，不可用插件的权重须按明确规则从归一化中剔除。
6. 实现得分传播路径的可视化与诊断：Tkinter 界面展示每个 Pod 的候选节点、每个节点的插件原始分与加权贡献、误差上界、最终选择与决胜依据，界面渲染顺序稳定；提供按 Pod 追溯的得分传播链，能够从最终得分下钻到每个插件输入，且当节点状态或权重改变后视图须整体刷新而非增量叠加旧分数。
7. 实现调度会话快照与版本识别的整体替换恢复：快照持久化节点集合版本、Pod 队列版本、插件权重参数、全部得分明细与绑定结果；重新打开快照时须先比较快照版本与当前会话版本，若不一致须整体替换当前状态而非增量合并，恢复后对历史 Pod 重新打分须得到逐位相同的得分与绑定结果，版本不一致导致不可复现时以 E_REPLAY 业务码报告。
8. 提供可重复本地演示与异常注入验证：附带确定性样本节点与 Pod 清单及演示脚本，顺序执行首次调度、修改权重参数后重调度、快照恢复后重放三个场景，输出稳定顺序的诊断总结；支持以命令参数注入清单损坏、亲和性规则成环引用、统计量缺失三类异常，分别以 E_MANIFEST、E_AFFINITY、E_STATS 业务码报告并写入结构化日志，异常注入仅改变输入与参数。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
