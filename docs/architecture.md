# 架构与确定性说明

## 1. 处理流水线

`render_task()` 的执行顺序是：

1. 读取并校验任务 JSON。
2. 读取点云二进制，逐项校验所有点、世界尺度、坐标原点偏移。
3. 若存在编辑清单，校验基线与替换点云、区域范围、重叠关系和区域摘要。
4. 校验相机、视场角、宽高比、超采样、分块覆盖和内存预算。
5. 创建状态目录，逐相机规划复用、版本迁移或整幅重做。
6. 以确定性波次调度需要补渲的块，块完成后原子持久化。
7. 逐块重新加载并核对版本、像素数、依赖摘要和内容摘要；坏块只补渲自身。
8. 所有相机通过校验后，才在输出目录生成 PNG/PFM/诊断 JSON/HTML。
9. 成功提交相机状态并清除中断标记。

任何第 1 至 4 步失败都不会创建输出目录。处理中断或未修复的 `E_DIGEST` 也不会发布最终图像。

## 2. 世界坐标与相机

点云文件保存局部坐标，任务提供：

```text
p_world = p_raw * world_scale + origin_offset
r_world = r_raw * world_scale
```

相机由位置、目标、上方向、垂直视场角和宽高比确定。视线为 `target - position`；上方向与视线平行或反平行时返回 `E_CAMERA`。

设超采样网格宽高为 `Wss/Hss`：

```text
fy = Hss / (2 * tan(vertical_fov / 2))
fx = Wss / (2 * tan(vertical_fov / 2) * aspect_ratio)
```

因此宽高比是独立输入，不会仅由图像宽高隐式替代。点半径在屏幕上形成轴向半径分别为 `fx*r/z` 与 `fy*r/z` 的椭圆覆盖区，并至少覆盖一个超采样中心，避免极小世界半径的点完全漏掉。

每个超采样像素维护 `(最近世界深度, 点索引)`。深度更小者获胜；深度完全相等时索引更小者获胜。每个超采样像素最终只由最近点贡献，更远点不再叠加：

```text
shade = 0.35 + 0.65 * max(0, normal · direction_to_camera)
attenuation = 1 / (1 + 0.25 * depth / camera_target_distance)
gray = clip(point_gray * shade * attenuation, 0, 1)
```

深度衰减使用相机目标距离作归一化，因此在点云、半径和完整相机整体同比缩放时保持可见性以及灰度关系。深度比较本身始终使用世界单位。

## 3. 超采样与分块

分块规格定义在输出像素坐标。超采样倍率可为任意有限正数：

```text
Wss = max(width, ceil(width * supersample))
Hss = max(height, ceil(height * supersample))
```

输出像素与超采样边界通过全局四舍五入边界映射。因此每个块都使用整幅画面的统一坐标，不依赖块在网格中的局部原点。超采样平均降采样时，灰度对全部超采样样本求均值；深度只对有限深度样本求均值，无有限深度则为 `inf`。

块独立分配：

- `winner`：`int64`，每样本 8 字节
- `depth`：`float64`，每样本 8 字节

即每个在途块采样缓冲为 `超采样像素数 * 16` 字节。块之间没有可写缓冲共享，也不依赖完成顺序。

## 4. 确定性调度与双预算

调度器按分块索引建立有序队列，以“准入波次”执行。单波满足：

1. 不超过 `max_workers`。
2. 所有在途块采样缓冲之和不超内存预算。
3. 下一个候选块始终是队列头；若放不下，则整波等待完成后从头重试，不跳过索引，不降低超采样倍率。

每波全部完成后才检查停止事件，因此终止信号只在块边界生效。波次全部结束后，逻辑时钟按波内最大逻辑成本前进；一个轮次累计达到 `round_budget_units` 时调用 `yield_round()` 并开始下一轮。逻辑成本只由块超采样像素数和点数计算，不读取线程完成墙钟时间，因此相同输入、并发上限、内存预算和轮次预算会得到相同准入序列。

任一 worker 异常后，不再提交待处理块；已准入波次完成并保留有效的原子块，然后返回按块索引最小的首个错误。调度器不会取消已运行的分块，以免留下无摘要的部分文件。

## 5. 版本、缓存与编辑谱系

每个块文件是同一目录临时文件原子替换后的 NPZ，包含：

- 8 位灰度块
- 32 位世界深度块
- `int64` 投影依赖点索引
- 规范化元数据 JSON

块版本为点云数据集摘要、相机摘要和像素相关渲染参数摘要三者的规范 JSON SHA-256。像素参数包括分辨率、超采样和分块网格；线程数、内存预算和逻辑轮次预算只影响调度，不进入版本，因此调整执行预算不会无故丢弃像素缓存。内容摘要覆盖块几何、版本、依赖数组、灰度与深度；依赖摘要单独覆盖依赖点集。

启动规划分三种模式：

- **resume**：没有提交记录时，或已提交数据集/相机/渲染与目标一致。版本和摘要有效的块直接复用，缺失或损坏块补渲。
- **edit_migration**：编辑清单声明的基线等于已提交数据集，并且相机、渲染未变。此时按依赖闭包只补渲受影响块，其余块在原像素不变的前提下原子改写为新版本元数据。
- **full_reset**：没有已声明的编辑谱系而版本不一致，或编辑谱系不匹配。所有块整幅重做。

这个区分把业务要求中的“局部替换复用”与“未登记版本变化整幅重做”分开：只有编辑清单的基线/目标摘要和区域摘要全部通过验证，才被承认为可安全迁移的谱系。

## 6. 失效闭包与复用证明

渲染块时，依赖集包含所有在该块超采样区域内有覆盖样本的点，即使它最终被更近点遮挡。局部替换后，一个块失效当且仅当：

1. 旧依赖集与替换索引集合相交；或
2. 替换后的新点投影覆盖该块。

第二项必不可少：一个索引在旧点云中可能没有投影到该块，但替换后可能新进入该块。

未失效块可安全复用，因为：

- 相机和渲染参数摘要一致；
- 所有替换索引均不在旧依赖集中；
- 所有替换后的新点均不覆盖该块；
- 该块内容摘要有效。

因此块内未变点的索引、坐标、法线、灰度、半径、相机和深度裁决输入都没有变化。

## 7. 中断、摘要和输出

原子写使用同目录 `.tmp-*` 文件、`fsync`、`os.replace`，因此进程被强杀时不会把半成品误认为完成块。每个完成的块立即持久化；恢复时只信任能通过摘要和像素数校验的块。

最终发布前逐块重新加载。缺失、损坏、像素数不符、依赖摘要或内容摘要不符时，只把该块重新提交给调度器，并在报告中以 `digest_repairs[].business_code = E_DIGEST` 记录检测与定向修复事实。若一轮定向补渲后仍不一致，进程返回 `E_DIGEST` 和失败块明细。所有相机块通过后，灰度 PNG、PFM 深度图、深度预览、块诊断 JSON、总报告和 HTML 视图均使用同目录临时文件整体替换。

## 8. 诊断工作台

`workbench.html` 是单文件静态视图，图片以 data URI 内嵌，数据来自已持久化块清单，不发起网络请求。Tk 视图同样只读取：

- `render_report.json`
- 每相机 `blocks.json`
- 已发布灰度 PNG 与深度预览 PNG

视图不会调用渲染器，也不会修改缓存。
