# 设计说明

## 分层

| 模块 | 职责 |
| --- | --- |
| `models.py` | 严格解析与验证服务、节点、轨迹；生成规范样本摘要 |
| `demand.py` | 使用 `Decimal` 将观测窗口换算为目标副本数并记录推导过程 |
| `packing.py` | 单卡显存、节点并发、拓扑和算力约束下的全有或全无装箱 |
| `engine.py` | 轮次规划、优先级排序、预算预留、并发动作执行、生命周期裁决 |
| `store.py` | SQLite 事务、文件锁、动作幂等、快照指针和恢复状态 |
| `launcher.py` | 回环 HTTP 生命周期客户端及稳定业务错误映射 |
| `test_server.py` | 本地确定性拉起/排空服务与故障注入 |
| `cli.py` | 校验、单轮、全轨迹、快照和状态导出命令 |

## 关键不变量

1. 输入验证发生在任何持久化初始化之前。
2. 同一副本的所有资源只由一条 `occupancies` 记录持有。
3. 资源预留、动作记录、预算记账和决策记录在同一个 `BEGIN IMMEDIATE` 事务内完成。
4. 动作在外部调用前先提交为 `in_flight`；每个动作有跨轮次唯一的幂等键。
5. 只有完整成功/失败结果提交后，副本阶段才发生迁移。
6. `draining` 副本持续占用节点资源，但不计入 `ready` 服务容量。
7. 轮次最终提交与快照指针替换属于同一事务。
8. 恢复只读取 SQLite，不依赖进程内缓存。

## 崩溃矩阵

| 崩溃位置 | 持久化状态 | 恢复行为 |
| --- | --- | --- |
| 输入校验后、规划前 | 无轮次 | 重新规划 |
| 规划事务中 | 事务回滚 | 重新规划，无部分占用 |
| 规划提交后、HTTP 前 | `planned`，动作 `in_flight` | 使用原幂等键执行 |
| HTTP 已成功、结果提交前 | 动作仍 `in_flight` | 远端幂等缓存返回，提交成功结果 |
| 拉起结果提交后、轮次提交前 | 动作 `succeeded`/`failed` | 跳过动作，直接完成轮次 |
| 快照事务中 | 事务回滚 | 保留动作状态，重新构建快照 |
| 快照提交后 | `committed` | 返回已提交结果 |

## 并发协议

- 文件锁按作用域命名：`round:<id>` 和 `service:<name>`。
- 锁按排序后的作用域依次获取，避免死锁。
- 不同服务可在不同进程中并行；相同服务/轮次被文件锁串行化。
- 即使不同服务同时规划，SQLite 写事务也会串行化容量读取与预留，避免跨服务显存超卖。
- `actions.idempotency_key`、`actions(round_id, replica_id, action)` 和主键共同提供数据库级幂等防线。

## 预算模型

每轮维护 `budget_limit_ticks` 和 `budget_used_ticks`。拉起动作按服务冷启动逻辑耗时计费，排空动作不计费。候选先按以下稳定键排序：

```text
(是否低于最小副本, 是否重试, 服务名, 原有稳定序号)
```

预算在规划事务中一次性预留。若当前候选无法覆盖，所有后续候选标记为 `budget_not_started`，不执行低优先级插队。已启动动作使用独立 socket 超时，不受轮次总预算截断。

## 输出确定性

- 所有 JSON 使用规范键排序和稳定列表排序。
- 决策不使用墙钟时间。
- 浮点观测只在固定精度 `Decimal` 中参与决策。
- 退避抖动来自稳定 SHA-256，不使用随机数。
- 错误详情不写入随机分配的回环端口。
- 重复运行同一轮次直接返回持久化结果。
