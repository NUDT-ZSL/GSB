# 设计说明

## 模块边界

- `loading.py`：严格 JSON/NDJSON 校验与整体拒绝。
- `topology.py`：稳定邻接表、方向可达性、连通分量和入度。
- `clustering.py`：时间邻域 + 拓扑可比关系 + 并查集。
- `rootcause.py`：候选排序、根因选择、传播折叠。
- `changes.py` / `session.py`：原子变更、失效集合、局部重算、全量等价校验。
- `snapshot.py`：SQLite 不可变快照、整体状态替换、重放校验。
- `diagnostics.py`：纯展示投影；`tkinter_ui.py` 只消费该投影。

## 关键不变量

1. 规则标识唯一，拓扑服务声明唯一，规则与拓扑服务集合完全一致。
2. 事件只有在校验通过后才进入会话；失败不会出现部分状态。
3. 事件分析前始终按 `(timestamp, event_id)` 排序。
4. 簇 ID 是成员 `(event_id, timestamp)` 的规范 SHA-256 前缀。
5. 规则版本、拓扑版本和所有摘要都由规范 JSON 的 SHA-256 产生。
6. 任何字典驱动的输出都先排序，不依赖 Python 哈希随机化。
7. 增量变更先作用于临时副本；只有局部结果通过全量等价校验后才提交会话状态。
8. 快照载荷不可覆盖；恢复只改变“当前快照”元数据，并整体重建会话。

## 时间窗口解释

时间窗口是整数毫秒 `W`。两个事件的时间戳差 `abs(t1 - t2) <= W` 时被视为处于同一时间邻域。相同服务可直接连接；不同服务还必须在新/旧拓扑中具有方向可达关系。传递桥接允许由多个连续邻域形成更长覆盖区间。

## 根因排序与决胜

排序键为：

```text
(-global_in_degree, -severity_rank, earliest_timestamp, service_name)
```

其中严重级秩为 `INFO < WARNING < ERROR < CRITICAL`，最终服务名升序保证完全同分时也有唯一结果。候选还携带簇内入度 `cluster_in_degree`，便于解释为什么某下游服务可能是本地传播终点，但排序本身使用全局拓扑入度。

## 增量范围为什么正确

- 规则只改变某服务的事件严重级或规则映射，根因影响不会越过包含该服务的簇，因此按服务定位旧簇。
- 边新增/删除会改变新旧拓扑的可达性和连通分量。任何跨越变化分量的旧簇都可能拆分或与他簇合并，因此新旧两侧分量内所有簇都必须失效。
- 边权重当前不参与聚类或根因排序，因此仅定位端点相关簇。
- 局部收集“失效旧簇成员 + 受影响服务的全部活动事件”，避免遗漏规则删除后重新激活或失效的事件。
- 提交前对当前事件集执行一次只读全量 oracle 比较；该计算不写回状态，不改变实际局部重算范围。

## 规则删除语义

已进入事件流的原始事件被保留。若其规则被删除，该事件在后续聚类中视为非活动事件；若规则以相同标识重新加入且服务一致，历史事件会重新参与分析。目标服务变更若已有保留事件则拒绝，避免事件中的服务与规则目标产生歧义。删除服务最后一条规则时，若仍有入边依赖者或出边依赖关系，返回 `E_DEPEND`。

## SQLite 快照

`snapshots` 表保存版本、游标、规范载荷、载荷摘要和只读/当前标记。载荷本身从不更新。保存新快照会把旧快照设为非当前并保持只读；恢复会把目标快照标记为当前，但两个快照的版本和载荷仍可辨识、可重放。

## 异常码

| 业务码 | 含义 |
| --- | --- |
| `E_SPEC` | 输入规格、服务一致性或变更结构非法 |
| `E_TIME` | 事件时间戳回退 |
| `E_DEPEND` | 删除仍参与依赖关系的服务 |
| `E_INCR` | 增量结果与全量重算不一致或计数不闭合 |
| `E_REPLAY` | 快照不可复现、版本依据缺失或游标超前 |
| `E_SNAP` | 快照库/快照元数据不可用，含注入的版本缺失 |
| `E_UI` | 当前环境无法启动 Tkinter 诊断视图 |
