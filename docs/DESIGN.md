# 技术设计说明

## 1. 总体结构

`xrel` 是一个纯本地、确定性、无外部网络依赖的跨语言检索相关性建模应用。数据链路为：

```
确定性样本 -> 桥接展开 -> 分区倒排统计 -> 置信度加权 BM25 -> 分区归约
          -> top-k / 相关性分档 -> 误差传播谱 -> 版本化快照与血缘
```

模块职责：

- `xrel/data_gen.py`：固定种子（默认 `20261124`）生成多语言文档、查询与桥接资源。
- `xrel/expansion.py`：桥接展开与确定性候选排序。
- `xrel/index.py`：按语言分区的倒排表与 BM25 集合统计。
- `xrel/numerics.py`：float64 / float32 / 定点缩放整数三档统一算子语义。
- `xrel/scoring.py`：置信度加权 BM25、合并规则、逐候选明细与资源预算。
- `xrel/error_spectrum.py`：以 float64 为真值的四级误差谱与定点重算校验。
- `xrel/topk.py`：top-k、严格/容差带门限与次正规数保护。
- `xrel/snapshot.py`：单调版本号、内容校验和与原子整体替换。
- `xrel/concurrency.py`：非阻塞提交闸门与增量失效规划。
- `xrel/lineage.py`：缓存键、血缘记录、过期拒绝与重放校验。
- `xrel/pipeline.py`：串联全部模块的门面与查询/批量一致性自检。

## 2. 三精度统一算子语义

三个后端实现同一套算子：`quantize/add/sub/mul/div/log/sqrt/maximum/
absolute/sum_sorted`。打分图只面向该抽象编写一次，因此切换精度只改变数值，
不改变候选集合与命中文档集合（二者由词项身份决定）。

- float64：参考真值。
- float32：每次运算回舍到 binary32，并将次正规数冲洗为零。
- 定点：所有实数存为缩放整数 `Q = round(x * scale)`，缩放因子与舍入模式由
  `FixedConfig` 显式声明；`scale <= 0` 或未知舍入模式返回 `E_CONFIG_INVALID`。

定点关键不变量：整数统计量（tf、df、doc_len、doc_count）也必须经过同一
`quantize` 放大到 Q 域；乘除分别通过一次缩放校正避免双重缩放。

## 3. 确定性与可复现

- 候选排序键：置信度降序 -> 目标词项字典序 -> 目标语言 -> 源词项。
- 文档/分区/贡献均按稳定键排序后累加，累加顺序不依赖集合迭代或系统时间。
- 所有快照与结果使用 `canonical.py` 的排序键紧凑 JSON 编码并计算 SHA-256，
  作为“逐字节一致”的比较基础。

## 4. 误差传播谱

以 float64 为参考，对每个命中文档输出四级：
置信度加权、分区统计归约、定点/低精度量化、top-k 门限比较。每级给出绝对偏差、
相对偏差、对称误差区间与相对上一级的放大比，并按总绝对偏差定位主导级别。

定点档额外执行“量子值重算”：从量化后的原始分与权重经定点乘法重建每个贡献，
再按确定顺序求和；任一贡献或总分无法由 `scale` 与舍入模式复现时返回
`E_ERR_SPECTRUM_INVALID`，且不会通过放大容差掩盖超差。区间下界大于上界同样
触发该错误。

## 5. top-k 数值稳定性

- `strict`：严格比较，门限判定不做任何平移。
- `tolerance_band`：落在门限下方 `tolerance` 带内的文档上调等级并记录保护日志。
- 次正规数：float32 次正规值冲洗为零并记录 `subnormal_flush_to_zero`。
- 跳过（超出 top-k）与被保护文档分别落盘，保证记录与实际执行一致。

## 6. 快照与增量失效

桥接表、方向表、分区索引各自带单调版本号与校验和，发布通过同目录临时文件
`fsync` 后 `os.replace` 原子整体替换；新版本号不大于当前版本即返回
`E_VERSION_ROLLBACK`。

增量变更分三类：

- 桥接条目修正：受影响源词项对应的查询重算，目标语言分区标记受影响。
- 方向表增删：该源语言的全部查询重算。
- 文档批次追加：对应语言分区统计变更，所有展开可达该分区的查询重算。

未受影响查询的上游产物从内存缓存恢复复用；增量结果与一次完全绕过缓存的全量
重算按内容指纹逐字节比对，并校验重算集合与复用集合无交集、并集覆盖全部查询。

## 7. 查询接口、血缘与并发

- 缓存键由 query_id、精度、桥接/索引版本与校验和、配置指纹共同决定。
- 结果记录包含缓存键、桥接版本、精度、节点路径与结果校验和。
- 依赖版本变化后读取旧键结果返回 `E_STALE_RESULT`；校验和不符或节点路径缺失
  返回 `E_LINEAGE_BROKEN`，并支持按记录重放出相同分数与分档。
- `StageLock` 为 try-only 闸门，并发冲突立即返回 `E_STAGE_BUSY`，不阻塞等待。
- posting 读取量、候选比较次数、驻留明细内存均有预算；不可降级时超限返回
  `E_RESOURCE_LIMIT`，允许降级时切换流式打分并记录降级类别。

## 8. 运行环境说明

任务要求 Python 3.11+；当前验证容器仅提供 Python 3.10.12。代码刻意避免 3.11
专有语法（如 `X | Y` 仅用于注解并配合 `from __future__ import annotations`），
因此在 3.10 与 3.11+ 均可运行。Windows 本地运行时使用 `python` 替换下文的
`python3` 即可，路径均由 `pathlib` 处理。
