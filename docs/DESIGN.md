# 设计说明：locklease 分布式锁与租约中间件（本地实验）

## 1. 总体架构

```
lockctl 子进程 (JSON Lines over 127.0.0.1 TCP)
        |  acquire / renew / release / query / table / snapshot / restore
        v
lockd 服务端 (internal/server)
        |  每条连接一个 goroutine；所有状态变更进入同一把互斥锁串行化
        v
store.Store (internal/store)
   |-- graph.Graph   依赖图（邻接表，DAG 校验 + 确定性 BFS 闭包）
   |-- locks         活动锁表 key -> Lock
   |-- keyVersions   每把锁的服务端可信租约版本基线（含已删除锁）
   |-- traces        失效传播轨迹（事件号 + 序号 + 触发源 + 受影响键 + 版本）
   |-- reclaims      服务端回收记录（原因 + 租约版本）
        |  每次变更后原子写盘（tmp + rename）
        v
data/lock-state.json        增量锁状态（每次变更覆盖写）
data/session-snapshot.json  完整会话快照（锁表/图/版本/轨迹/回收）
logs/lockd.log              服务端回收等运行日志
```

## 2. 时间与过期精度

- 所有时间均为 Unix 毫秒整数（int64），不使用浮点。
- 判定源唯一：请求带 `now_ms` 时以注入时间为准（确定性演示/测试），否则使用服务端墙钟毫秒。
- 过期判定为包含边界：`expires_at_ms <= now_ms` 即视为到期。续租与到期回收在同一把互斥锁内
  串行，到期锁会先进入确定性回收路径，因此不可能出现“续租成功且回收成功”的双写。
- 后台回收器每 100ms 用墙钟扫描；任何读写请求也会惰性回收，两条路径共用同一函数。

## 3. 依赖图与传播顺序

- 边方向：`A -> B` 表示 B 依赖 A；A 失效时 B 是下游。
- 加载校验：依赖引用必须存在；DFS 白/灰/黑染色检测环，非法图以 `E_DEPEND` 整体拒绝并输出
  具体环路（沿依赖边方向）。
- 传播顺序：从触发源做 BFS，同层按键名字典序排序，保证输出稳定可复现。
- 去重：单次事件用 visited 集合；互斥锁保证并发触发被串行化，同一锁不会在一个事件里传播两次。
- 仅对“事件发生时实际持有租约”的下游锁产生轨迹步骤并递增其租约版本；未持有的键不伪造版本。

## 4. 租约版本与抢占

- 加锁成功版本从 1 开始；续租需同时匹配 holder 与 lease_version，否则 `E_VERSION`。
- 重复 acquire 返回 `E_LOCKED`，detail 携带当前 holder、到期毫秒与版本。
- `force=true` 的 acquire 构成抢占：替换持有者、版本 +1，并对下游闭包触发 cause=preempt 传播。

## 5. 客户端崩溃回收

- 演示以本地子进程方式启动多个 lockctl，强杀进程（不发送任何退出消息）。
- 锁的回收完全由服务端依据到期时间驱动；回收记录包含 key、holder、reason=expired、
  回收时的 lease_version 与时间戳，并写入 `logs/lockd.log` 与快照 reclaims。

## 6. 快照、整体替换与重放校验

- 快照包含：图定义、图版本、锁表、每键可信版本 `key_versions`、全部传播轨迹、回收记录、表版本。
- 恢复时比较 table/graph 版本；不一致即 `Replaced=true`，先清空全部内存 map 再整体装入快照，
  杜绝与旧锁表做增量合并（任何只存在于旧表的键都不会残留）。
- 重放校验（E_REPLAY）不修改状态：
  1. 用恢复后的图重新推导每个事件源的下游闭包，校验轨迹中的键都在闭包内且顺序符合 BFS；
  2. 轨迹版本必须为正数、不超过服务端维护的可信版本基线；
  3. 每个键最后一次失效记录必须与其可信基线精确相等，篡改版本会稳定列入 diffs。
- 图或租约版本缺失、不可复现时，以 `E_REPLAY` 返回稳定排序的差异项列表。

## 7. 业务码

| 代码 | 触发条件 |
| --- | --- |
| E_DEPEND | 依赖引用缺失或依赖图成环（含具体环路） |
| E_LOCKED | 重复获取已被持有的锁（携带 holder/到期/版本） |
| E_VERSION | holder/租约版本不匹配，或锁已到期被回收 |
| E_NOT_FOUND | 锁键不在图定义中或无活动锁 |
| E_SNAPSHOT | 快照文件缺失、损坏或格式无法识别 |
| E_REPLAY | 恢复后传播轨迹/租约版本重放不一致 |
| E_PORT | 回环端口无法绑定（如端口已被占用） |
| E_BAD_REQUEST | 请求 JSON 非法或参数缺失 |

## 8. 持久化与崩溃一致性

- 所有写盘采用“写临时文件 + rename”，在 Windows/Linux 上均为原子替换。
- 锁状态在每次成功变更后立即落盘；进程重启后从状态文件与图定义重建，再按需恢复快照。
