# JoinLab 技术设计

## 分层

| 模块 | 职责 |
| --- | --- |
| `catalog.py` | 目录/数据文件的原子强校验，计算 NDV、倾斜比率，构造不可变目录与行元组 |
| `query.py` | 无依赖的小型 SQL 词法/语法解析器、别名消解、类型检查、规范化与查询 ID |
| `cost.py` | 定点代价参数、计划枚举、基数估算、量化与稳定决胜 |
| `executor.py` | 哈希/嵌套循环真实执行、LEFT 语义、统一排序、逐算子统计、跨路径字节比较 |
| `session.py` | 模式/数据/参数版本、不可变执行快照、陈旧结果拒绝、查询历史 |
| `snapshot.py` | 全会话快照、全量替换、历史回放与差异报告 |
| `injection.py` | 仅通过派生输入文件制造三类异常 |
| `report.py` / `acceptance.py` | 稳定结构化报告与端到端验收 |
| `gui.py` | Tkinter 参数编辑、防抖刷新、后台执行、最新请求发布 |
| `cli.py` | 从任意工作目录可启动的 JSON CLI |

## 数据契约

目录根包含 `schema_version`、`data_version`、`tables`。每张表包含 `name`、`row_count`、`skew`、`columns` 和 `data_file` 或快照内嵌 `rows`。列支持 `integer`、`real`、`text`、`boolean`、`date`。可选的 `ndv` 用于代价估算；未提供时由样本去重数计算。可选的 `skew_column` 与 `skew_limit` 会触发实际频率校验。

加载器先在局部变量中完成所有表和行验证，只有全部通过才返回 `Catalog`。任何失败都不会暴露部分目录。

## 查询语言

支持：

```sql
SELECT <列或 *> FROM <表> [别名]
  [INNER] JOIN <表> [别名] ON <谓词> [AND <谓词> ...]
  [LEFT [OUTER] JOIN <表> [别名] ON ...]
  [WHERE <谓词> [AND <谓词> ...]]
```

谓词为列与列或列与字面量的 `= <> != < <= > >=` 组合。不支持 OR、括号、子查询、聚合、RIGHT/FULL/CROSS、GROUP/ORDER/LIMIT、UNION 和四表连接。

规范化规则：

1. 标识符大小写归一；别名只在解析期存在，规范 SQL 全部使用真实表名。
2. INNER 关系按“最小表名优先且保持连接图连通”的规则稳定生成规范顺序；LEFT 查询保留原左右语义序列。
3. ON/WHERE 中的谓词排序、恒等方向与 `!=` 写法归一。
4. `SELECT *` 按规范表序展开。
5. `query_id = sha256(canonical_sql)` 的稳定截断值。

因此空白、大小写、别名和同语义 INNER 连接书写顺序不会改变规范化文本或标识。

## 代价模型

默认参数（单位化后以 1000 微单位定点存储）：

- 扫描、过滤、哈希构建/探测、嵌套循环对、输出行成本。
- 倾斜放大因子与每表连接顺序偏置。
- `cost_quantum` 为可视化/决胜量化格。

本地基数估算使用声明行数 × 样本比例、本地谓词选择率、连接等值 `1 / max(NDV)`、范围 `0.3`；LEFT 输出至少保留左侧行数。候选覆盖所有合法 INNER 排列以及每一步的哈希/嵌套循环组合；哈希仅在有可用等值键时出现。LEFT 查询只在语义允许的固定左右序列上枚举算子。

每个候选保存扫描明细与逐步中间基数、算子成本、偏置成本、累计成本。候选按 `(quantized_cost, plan_signature)` 全序排列。量化格内相同代价由计划签名字典序决胜，规则字段 `decision_rule` 随计划集输出。

## 执行一致性

- 数据行是不可变元组；执行器只读取当前版本数据视图。
- JOIN 谓词使用显式类型比较；NULL 比较不匹配。
- LEFT JOIN 对无匹配左行补右侧 NULL，WHERE 在外连接后统一求值，避免错误下推。
- 所有计划执行完成后，以全部输出列为键排序；NULL 排最后。最终行编码为逐行紧凑 JSON 数组，带尾换行。
- 结果集摘要为编码字节的 SHA-256。跨路径比较的是完整字节，而不是仅行数或摘要。
- 差异报告包含首个差异行索引、两侧行键、两侧行文本和 `canonical_sort` 算子，CLI 以 `E_PLAN` 返回。
- 稳定 `stats` 不含实际耗时；逐算子耗时放在独立 `timings.per_operator_ms` 中。稳定统计指纹只哈希确定字段，计划排序、计划选择、快照判定都不读取耗时。

## 版本与刷新

`SessionVersions = (schema_version, data_version, param_version)`。代价参数修改推进参数版本；样本规模修改同时推进数据与参数版本。执行开始捕获不可变版本，结束时重新核对；变化则抛 `E_STALE`，不写历史、不参与选优。

GUI 对参数输入做 260 ms 防抖，后台线程执行时携带请求序号和版本。结果仅在请求序号仍最新且版本仍等于当前会话时发布。参数变化后旧展示立即标记 `STALE`，快照恢复后重新刷新当前查询。

## 快照与异常

快照包含目录（含内嵌全部行）、代价参数、版本、样本比例、查询历史、候选计划、选中计划、结果/对照摘要。恢复流程：

1. 校验快照格式与 `schema/data/param` 三版本。
2. 从快照构造全新目录和新会话，不向当前会话做增量合并。
3. 逐个解析 `source_sql`，重新估算和执行。
4. 比较选中计划 ID、计划签名、结果摘要、行数、统计指纹、回退计划与跨路径结论。
5. 全部一致才返回恢复会话；否则 `E_SNAP` 列出首个/全部差异字段。

三类注入均由 CLI 生成派生文件并实际触发加载/解析/恢复路径：

- 放大受监控列频率：`E_SKEW`。
- 构造数字列与非数字列的 ON 等值连接：`E_TYPE`。
- 删除 `versions.param_version`：`E_SNAP`。

## 业务错误码

| 代码 | 含义 |
| --- | --- |
| `E_SCHEMA` | 目录、类型、行数或查询引用不合法 |
| `E_QUERY` | 语法或查询特性不受支持 |
| `E_TYPE` | 连接/谓词类型不可比较 |
| `E_PLAN` | 跨计划结果不一致或无合法计划 |
| `E_SKEW` | 倾斜放大超过限制 |
| `E_SNAP` | 快照缺失字段、回放差异或版本不一致 |
| `E_STALE` | 结果落后于当前参数/数据版本 |
| `E_GUI` | 当前解释器无法启动 Tkinter |

CLI 错误同时写到 `artifacts/logs/business.jsonl`（可用 `--log` 覆盖）。
