# 设计说明

## 1. 处理链路

```
JSON 清单/配置 -> 参数校验(E_xxx) -> 多倍频噪声场 -> 通道映射
              -> 分块切片(含重叠边距) -> 接缝归一化权重 -> 整幅拼接裁决
              -> 分块原子持久化 -> 原子导出/旧版本归档
```

对应模块：

| 模块 | 职责 |
| --- | --- |
| `matgen/model.py` | 数据模型、JSON 解析、逐条校验与业务码 |
| `matgen/noise.py` | 种子驱动的确定性梯度噪声与多倍频叠加 |
| `matgen/channels.py` | 粗糙度、颜色、切线空间法线通道映射 |
| `matgen/tiling.py` | 分块规划、接缝权重、拼接与一致性裁决 |
| `matgen/persistence.py` | 原子写、版本标识、块摘要、恢复与重做 |
| `matgen/engine.py` | 有界线程池、内存预算、中断语义、编排 |
| `matgen/exporting.py` | 原子导出与旧版本归档 |
| `matgen/injection.py` | 仅基于输入数据/状态文件的异常注入 |
| `matgen/cli.py` | 命令行入口 |

## 2. 确定性与“同口径”如何保证

### 2.1 噪声是全局坐标的纯函数

`fbm_field(width, height, seed, frequencies, amplitudes, x0, y0)` 只由种子、频率、
振幅、倍频数与全局像素坐标决定。种子通过固定常量的晶格平移注入，哈希使用固定 64 位
位宽整数，不依赖全局随机状态、调用顺序或线程。分块只是在同一函数上取不同坐标窗口，
因此整幅与分块在同一格点逐格相等（见 `tests/test_noise.py`）。

多倍频结果按振幅和归一化：`sum(a_i * perlin(f_i * x)) / sum(a_i)`，归一化常量只由
材质参数决定，不随分块尺寸或边界变化。

### 2.2 通道映射使用统一常量与全局坐标

* 粗糙度：`clip(roughness + 0.25 * field, 0, 1)`，常量固定。
* 颜色：基础色叠加固定系数的同噪声场扰动。
* 法线：由高度场差分得到。关键设计是**邻居按整幅全局坐标周期环绕定位**：
  当差分邻居落在当前分块窗口之外时，按全局坐标用同一噪声纯函数向量化补算，
  从而分块边界内侧像素与整幅使用完全相同的邻居，避免单侧/中心差分不一致。

### 2.3 接缝归一化权重

分块采用“核心区 + 重叠边距”。单轴重叠区两侧权重严格互补（和为 1），二维权重为两轴
乘积；拼接时再对覆盖同像素的所有块按权重和归一化，因此
`拼接值 = Σ wᵢvᵢ / Σ wᵢ`。由于各块在重叠像素上的 `vᵢ` 本就来自同一纯函数（数值相同），
拼接在数学上等于整幅直接生成，实测各通道最大误差约 1e-16，远严于规格容差 1e-6。

## 3. 持久化、版本与恢复

* 版本标识 `version_id`：对“材质规范化参数 + 影响结果的配置项 + 文件格式版本”做
  SHA-256。输出路径、并发、内存预算、容差不参与，因为它们不改变像素结果。
* 块摘要 `digest`：覆盖版本标识、块几何参数、权重与全部通道字节，恢复时重算比对。
* 原子写：一律“同目录 `.tmp` 临时文件 + flush/fsync + `os.replace` 整体替换”。
  数据文件先替换、摘要文件后替换；摘要存在即代表该块完整提交。
* 恢复：版本一致且摘要有效才复用；任一持久化块版本不符或摘要损坏，则该材质
  **整体清空重做**，杜绝新旧版本切片混拼。

## 4. 终止语义

* 可处理终止：`StopController` 同时支持进程信号（SIGINT/SIGBREAK/SIGTERM）与轮询
  标记文件（Windows 友好）。停止信号只阻止提交“下一个”块，已在途块跑完并持久化，
  随后在分块边界写 `interrupted.json` 并以退出码 10 退出，不会留下被误认为完成的块。
* 强制终止：`--force-crash-after N` 在原子持久化 N 块后调用 `os._exit(137)`，
  不写标记、不写报告。重启后只依据已落盘且摘要有效的块恢复，`.tmp` 残留被清理忽略。

## 5. 并发与资源上限

* `ThreadPoolExecutor(max_workers=concurrency)` 提供有界线程池。
* `MemoryBudget` 用票据锁实现 FIFO：超出内存预算时，按材质标识与分块索引序让后续块
  等待，绝不降低倍频数或精度。主线程按索引序提交，保证确定性的调度顺序。
* 最终整幅纹理、切片预览与所有报告均先写临时文件再 `os.replace`；导出前读取已有
  `version.json`，版本变化时把旧输出整体移动到 `archive` 而不是直接覆盖。

## 6. 业务码

| 业务码 | 触发条件 |
| --- | --- |
| `E_BASE_COLOR_RANGE` | 基础色分量不在 [0,1] 或非有限数 |
| `E_ROUGHNESS_INVALID` | 粗糙度非有限正数 |
| `E_NORMAL_STRENGTH_INVALID` | 法线强度非有限正数 |
| `E_OCTAVES_INVALID` | 倍频数非正整数 |
| `E_FREQUENCY_ORDER` | 频率长度不符或未严格递增 |
| `E_AMPLITUDE_INVALID` | 振幅长度不符或非正 |
| `E_GRID_DIVISIBILITY` | 分块行列非正或不能整除纹理宽高 |
| `E_DIMENSION_INVALID` | 整幅宽高非正整数 |
| `E_CHANNEL_MISSING` | 缺少 color/roughness/normal 声明 |
| `E_CONFIG_INVALID` | 材质/配置结构或 seed 等字段非法 |
| `E_CHUNK_DIGEST_MISMATCH` | 持久化块版本不符或摘要损坏 |
| `E_CHUNK_DATA_MISSING` | 持久化块数据/摘要缺失 |
| `E_INTERRUPTED` | 可处理终止 |
| `E_UNKNOWN` | 未归类异常（含一致性裁决失败） |

非法条目按 `material_id` 记录后继续处理其余合法材质，异常注入清单与受影响材质、
业务码、产出切片数统一汇总到 `run_report.json` 与逐材质 `report.json`。
