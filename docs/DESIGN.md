# 设计与实现说明

## 1. 模块划分

| 模块 | 责任 |
|---|---|
| `schema.py` | JSON 结构、骨架拓扑、轨道、参数、转移、编辑顺序校验；规范化版本摘要 |
| `math3d.py` | 四元数、slerp、TRS 父链组合 |
| `sampler.py` | 通道插值、参数采样、片段局部时间、片段姿态缓存 |
| `concurrency.py` | 有界线程池、优先级内存租约、批次化片段采样 |
| `engine.py` | 状态机推进、事件与姿态同源生成、分块依赖聚合、全量对比 |
| `incremental.py` | 编辑失效闭包、连续脏块重算、保留块复用 |
| `snapshots.py` | v1/v2 读取、摘要校验、墓碑/代数裁决、冲突定位、回退 |
| `persistence.py` | 原子块写入、版本保护、有效前缀恢复、边界终止 |
| `reconnect.py` | 断线缺口补帧、事件续播、`E_REPLAY` 定位 |
| `samplegen.py` | 固定种子确定性样本与两代快照 |
| `cli.py` | 统一命令行、JSON 错误、退出码 |

## 2. 确定性姿态求值

时间轴固定为整数毫秒，帧时间为 `0, step, 2*step, ..., duration`。片段姿态只取决于片段局部毫秒，而局部毫秒只取决于 `t - enter_ms` 和片段时长。因此每个片段的局部姿态序列可独立预计算。

通道求值：

- `translation`、`scale`：分量线性插值。
- `rotation`：四元数归一化后最短弧 slerp；点积为负时翻转目标符号。
- 超出首/尾关键帧时钳制到端点。
- 局部姿态按通道覆盖 rest，再沿拓扑父链累乘：
  - 平移：`parent_t + rotate(parent_q, parent_s * local_t)`
  - 旋转：`parent_q * local_q`
  - 缩放：`parent_s * local_s`

框架有意不使用 BLAS 或并行归约来聚合浮点值。线程只并行“互不依赖的片段局部姿态批次”，最终按片段 id 和批次序号合并。因而并发度与分块切分不会改变加法顺序或输出位模式。

## 3. 状态机同源事件

每个逻辑帧按以下顺序执行：

1. 采样参数轨道；
2. 判断当前片段是否完成目标循环次数；
3. 按来源、条件、`min_hold_ms`、`interrupt`/`on_finish` 过滤候选；
4. 按 `(priority, id)` 选择唯一转移；
5. 若转移，则写入事件并切换到目标片段的局部 0 ms 状态；
6. 用同一个状态求当前帧姿态并写入帧序列。

事件不是由姿态差分反推，而是与姿态在同一循环内产生。目标片段进入时刻采用明确规格：硬切换到局部 0 ms，不做隐式 crossfade。有限循环完成后，若没有可用转移，姿态固定在片段末帧。

## 4. 依赖图与失效闭包

每个块保存：

- 块内每帧的片段和局部时间范围；
- 每个 `(clip, bone, channel)` 轨道被采样的关键帧区间 `[lo, hi]`；
- 参与的骨骼与通道；
- 块的片段时间范围和状态快照；
- 当前片段可用转移规则及实际选中规则。

编辑失效：

- 关键帧增删改/移动：计算受影响相邻插值区间，只标记采样到这些区间且片段匹配的块；受影响输出骨骼为编辑骨骼及其全部后代。额外记录原因、受影响帧和局部区间。
- 片段时长/循环次数：从该片段首次活跃的块开始，后续状态时间线都可能移位，全部标记。
- 转移条件增删改：从规则来源片段首次活跃的块开始，后续状态都可能分叉，全部标记。
- 无操作编辑不产生失效。

重算按脏块连续段进行。每个连续段从基线边界状态开始；仅关键帧编辑不会改变状态机边界，因而可逐段独立重算。复用块保留原始帧、事件和依赖对象，报告会比较 payload 摘要，确保没有“看似复用但内容被改写”。

`incremental` 命令为生成“首个超容差位置”会额外执行一次独立的全量参考回放作为审计，不参与增量输出生成。库调用方可传入或不传入 `reference`。

## 5. 两代快照

v1 在合并时即时换算为绝对逻辑毫秒。v2 分片与 SQLite 元数据分别校验摘要和帧数；某一代任一分片失败时整代排除，并回退到最近完整有效代。

合并键按时间桶对齐，避免 v1 秒换算的微小舍入造成“同一状态不在一组”。排序优先级明确为状态代数、墓碑、时刻、版本来源、快照代。冲突按通道展开，附带双方分片路径和记录索引，便于定位。

## 6. 持久化与恢复

块文件先写入同目录临时文件，`fsync` 后 `os.replace` 原子替换。替换前读取已有块，若版本标识不同则抛出 `E_VERSION`，绝不混写。

恢复只扫描从块 0 开始的连续前缀。每个块验证：

- 格式与版本标识；
- 内容摘要；
- 块索引、帧数；
- 状态边界连续性。

遇到摘要无效块即停止恢复；后续即使存在看似有效块也不使用。缺失的下一块不属于坏块，正常从该块继续。

信号处理只设置标志，不抛异常。推进循环在块开始前和块提交后检查标志；若信号在块计算中到达，当前块仍会完整落盘后才以 130/143 退出。强制终止可能留下临时文件，恢复时忽略。

## 7. 并发与内存预算

片段局部姿态采样被切成批次，提交到最多 `max_workers` 个任务的 `ThreadPoolExecutor`。每个任务在计算前申请内存租约，租约量包括：

- 该批次姿态快照的保守对象估算；
- 该片段关键帧插值缓冲；
- 固定工作开销。

内存不足时，等待队列按 `(clip_id, batch_index)` 确定优先级，只允许最小键的租约在空间足够时获得预算。系统通过等待而不是减少采样帧、跳过关键帧或降低插值精度来适配预算。若单个最小批次仍大于预算，返回 `E_BUDGET`。

预算统计的是“在途”批次；已完成并成为权威输出缓存的姿态不计入在途租约，但报告会单独列出 `retained_pose_bytes`。

## 8. 断线追平

重连先检查客户端版本、帧时间唯一性、重叠姿态和已应用事件前缀。任何偏差都在补帧前返回 `E_REPLAY`，并定位最早逻辑毫秒、片段、骨骼通道与分量。

无偏差时：

1. 计算权威帧时间与客户端帧时间的差集；
2. 按逻辑毫秒升序生成 `fill_pose`；
3. 所有补帧完成后再按事件序号生成 `replay_event`。

报告显式给出 `order_contract`，防止调用方把补帧和事件回放交错执行。

## 9. Windows 注意事项

- 临时文件与目标文件始终位于同一目录，确保 `os.replace` 在同卷原子替换。
- 路径比较和样本清单使用 `/` 规范化的相对路径；文件写入使用 `pathlib`。
- `SIGTERM` 在支持它的平台安装处理器；不支持时仅 `SIGINT` 处理器生效，`--stop-after-chunks` 可用于 Windows 上确定性复现边界停止。
- SQLite 以标准库连接并在读取后执行 `PRAGMA query_only=ON`，不依赖 URI 路径格式。
- 不依赖 shell 管道、Docker、网络或 Unix 专有命令。
