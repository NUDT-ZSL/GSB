# 设计说明

## 1. 分层与数据流

```text
固定种子 SpeakerSpec
        │
        ├── 混合会议 PCM ──► 帧特征（能量/ZCR/频带）
        │                              │
        └── 逐帧真值/注册片段          ├── 双门限滞回 VAD
                                       ├── 注册声纹相似度 → 掩码
                                       └── 段重建 → 重识别/置信区间
                                                    │
规范 MeetingConfig ◄── v1/v2/v3 Reader/Migrator    │
        │                                           │
        └── 三项版本化快照 ──► 结果摘要/失效防护 ───┘
                                 │
                                 └── 跨模块一致性自检
```

处理链的输入只有规范配置与会话数据；真值用于交付核对和身份评估，不参与掩码生成。

## 2. 确定性合成

- 采样率 16 kHz，单声道，int16 PCM；默认时长 4 s。
- 每位说话人由固定种子产生独立 F0 抖动、共振峰、相位和能量包络。
- 语音由 1..18 次谐波叠加，谐波幅度受三个共振峰响应塑形，并加入确定性平滑呼吸噪声。
- 说话人按固定时间轴轮流活动，区间之间保留间隙；按配置的逐说话人增益叠加到背景噪声。
- PCM 转换使用固定 `np.rint` 与 int16 夹取，测试验证两次运行 `bytes` 相同。
- v3 的 `precision` 声明控制注册嵌入与逐帧嵌入的 `float32`/`float64` 计算精度。

真值帧严格为 20 ms。若 `hop_ms < 20`，分析帧重叠；`is_speech` 按真值帧的样本窗口与说话人活动样本区间是否相交确定，因此帧真值、特征帧和段帧始终一一对应。

## 3. 唯一时间基准

权威表示是半开区间：

```text
frame:  [start_frame, end_frame)
sample: [start_frame * hop, (end_frame - 1) * hop + frame_samples)
```

对外毫秒值由样本整数运算得到，采用 `half_up` 取整到 0.001 ms：

```text
micro_ms = round_half_up(sample * 1_000_000 / sample_rate)
ms = micro_ms / 1000
```

反算使用 `Decimal` 和 `ROUND_HALF_UP`。验证器同时检查：

1. 段跨度至少一帧；
2. 样本起止等于帧区间推导值；
3. 毫秒起止反算样本完全相等；
4. 样本反算帧区间完全相等。

任一失败返回 `E_TIME_BASE_MISMATCH`，附 `segment_id`、`frame_interval` 和反算值。

## 4. 分段、掩码与段重建

1. 以第 10 百分位能量估计噪声底，以第 95 百分位作为峰值。
2. 根据 `threshold_multiplier` 计算高/低门限，高门限触发，低门限释放，形成滞回候选段。
3. 对每帧计算 80 Hz–4 kHz 的 8 个对数频带能量，经 `log1p` 与 L2 归一化形成嵌入。
4. 注册片段活动帧嵌入的均值构成每个声明说话人的规范声纹。
5. 候选帧与所有声纹做余弦相似度，取得分最高者；差值不超过 `1e-12` 时选较小说话人编号。
6. `binary` 掩码写 1，`weighted` 掩码按高于阈值的规整相似度写权重。
7. 每个说话人的连续活跃帧重建为段；最终按说话人编号升序、起始样本升序输出。
8. 候选外帧掩码强制为 0，确保“候选帧集合 = 掩码活跃帧集合”。

## 5. 重识别与置信区间

对每个分离段，计算逐帧嵌入对每个注册声纹的余弦相似度；取段内均值作为确定性得分。排序键为 `(-score, speaker_id)`，所以同分必选更小说话人编号。

置信区间：

```text
mean ± 1.96 * std / sqrt(n)
```

并夹取到 `[0, 1]`。输出同时包含：

- 指派身份与所有候选得分；
- 是否达到配置重识别阈值；
- 段内逐帧真值说话人集合；
- `matches_truth` 是否全部一致。

身份标签必须属于会话声明集合，否则返回 `E_SPEAKER_UNKNOWN`。

## 6. 配置规范语义

所有版本解析为 `MeetingConfig`。规范摘要覆盖：

```text
sample_rate, duration_ms, max_speakers, threshold_multiplier,
frame_ms, hop_ms, normalization, variant, reid_threshold,
speaker_gains, mask_mode, precision
```

版本只影响书写形式，不改变上述语义。v1/v2 隐式字段会记录在 `provenance` 中：

- v1 补全帧长、帧移、归一化、变体、重识别阈值、单位增益、二值掩码、float64；
- v2 补全单位增益、二值掩码、float64；
- 迁移审计逐项记录 `field`、补全值和 `source`。

严格降级时，目标不能表达且源值不等于目标隐式值的字段进入 `E_SEMANTIC_LOSS`。有损降级执行明确规则：

- 逐说话人增益：`flatten_to_unit_gain`；
- 掩码/精度/其他缺失字段：`discard_use_target_default`。

审计同时输出 `drops` 与可保留的 `implicit` 项。

## 7. 快照与结果失效

三个独立项：

| 项 | 载荷 |
|---|---|
| `segmentation` | 采样率、时长、门限、帧长/帧移、归一化、变体 |
| `separation` | 上限、逐说话人增益、掩码模式、精度 |
| `reid` | 重识别阈值、平局规则 |

每项文件是完整 envelope：

```json
{"item":"reid","version":2,"checksum":"sha256:...","payload":{...}}
```

- 新版本必须大于当前版本；
- 同版本同内容为幂等；
- 同版本不同内容视为 `E_SNAPSHOT_CORRUPT`；
- 新版本整包写临时文件后 `os.replace`，不做字段级补丁；
- 读取时重新计算载荷校验和。

加工前验证三个快照载荷与配置逐项匹配；加工后再次验证快照摘要未变化。任何版本或校验和变化都会使旧结果返回 `E_RESULT_STALE`，应用层必须清空并重算。

## 8. 自检不变量

`run_self_check` 检查：

1. 候选段帧集合与掩码活跃帧集合互相覆盖；
2. 身份指派与分离段 ID 一一对应且唯一；
3. 每个段的毫秒/样本/帧双向反算一致；
4. 段位于音频时长内且互不重叠；
5. 每个身份均属于会话声明集合；
6. 每个分离段的身份与逐帧真值一致。

失败可返回结构化报告；严格模式抛 `E_INCONSISTENT` 并附问题列表。
