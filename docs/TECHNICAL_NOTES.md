# 注入类漏洞静态检测工作台 — 技术说明

## 1. 目录与模块

| 模块 | 职责 |
| --- | --- |
| `config.py` | 检查点结构版本、方言白名单版本、规模阈值与资源预算 |
| `transforms.py` | 变换名注册表：变换名 →（编码族, 编码/解码方向） |
| `normalizer.py` | 连续同类合并 + 同族反向抵消，输出规范链与抵消记录 |
| `parser.py` | 清单记录级校验，非法记录产生带序号与错误码的拒绝记录 |
| `analyzer.py` | 路径三缺陷判定、汇点聚合去重、规模模式与等价类剪枝 |
| `resources.py` | 真实墙钟截止时间、路径数预算、非阻塞文件锁、原子写 |
| `checkpoints.py` | 检查点持久化、版本变化整体重建 |
| `runner.py` | 线程池并发、单清单异常隔离、报告汇总 |
| `samples.py` | 确定性样本生成器（无随机源） |
| `cli.py` / `webapp.py` | 命令行入口与 Flask 本地工作台 |

## 2. 规范链归一

单次栈扫描同时完成两件事：

1. 栈顶与新变换同族且同方向 → 合并，保留所有原始序号；
2. 栈顶与新变换同族但反方向 → 成对抵消出栈，`CancelRecord` 同时保留
   编码侧与解码侧原始序号。`is_encode_then_decode()` 用于顺序颠倒判定。

## 3. 三类缺陷与互不叠报

每条路径至多一个缺陷，优先级固定，保证“互不叠报”：

1. `E_ORDER`：所需编码族出现“先编码后解码”的抵消（原始解码序号可定位）；
2. `E_MISSING_ENC`：规范链无任何存活编码，或所需族部分缺失且无多余族；
3. `E_MISMATCH`：施加了汇点上下文不需要的编码族，或编码族集合一致但顺序不符。

## 4. 规模模式与一致性

- `path_count` 或 `sink_count` 超过阈值即从 `exact_per_path` 切到 `batch_grouped`；
- 两模式调用同一份 `classify_path`，缺陷集合与汇点判定天然一致；
- 批处理仅额外按 `(规范链签名, 抵消记录, 所需族)` 做记忆化剪枝。
  抵消记录必须入键，否则“空链（被还原）”与“空链（本就无变换）”会碰撞，
  把 `E_ORDER` 错误复用到 `E_MISSING_ENC` 路径；
- 报告显式给出 `mode`、`memo_hits` 与 `prune_ratio`。

## 5. 资源预算

- 耗时以 `time.perf_counter()` 单调墙钟在路径循环中协作式检查，无任何人工延迟；
- 路径数在分析前与 `max_paths_per_manifest` 比较，超限 `E_BUDGET`；
- 超时 `E_TIMEOUT`、超限 `E_BUDGET` 都在工作线程内被捕获隔离，不影响同批清单；
- 检查点/报告写入走 `mkstemp + os.replace` 原子替换，并以 `fcntl.flock(LOCK_NB)`
  串行化，抢锁失败立即返回 `E_LOCK`。

## 6. 检查点

- 仅当 `complete=true`、结构版本与方言白名单版本都匹配时才增量续接；
- 任何不匹配都返回空状态并标记 `rebuilt`，整体重建；
- 检查点内容为已完成 `file_id` 与汇点聚合结论的精简形态。

## 7. 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 全部清单处理成功（记录级拒绝属业务结果，不算失败） |
| 1 | 部分清单失败（`E_TIMEOUT`/`E_BUDGET`/`E_LOCK`/致命 JSON 等） |
| 2 | 参数错误（文件不存在、非法模式、参数解析失败） |
