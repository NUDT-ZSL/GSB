# 技术说明：程序化网格地形分块离屏渲染引擎

本引擎仅依赖 `numpy` 与 Python 标准库（`json`、`sqlite3` 可用但本实现以
文件清单持久化，无需外部数据库或渲染库），全部计算在 CPU 上以确定性
NumPy 内核完成。相同输入在任意分块划分、线程数或调用顺序下产生逐字节
一致的结果。

## 1. 模块划分

| 模块 | 职责 |
| --- | --- |
| `errors.py` | 稳定业务码 `E_xxx` 与统一异常、JSON 错误信封 |
| `digest.py` | 规范化 JSON、SHA-256 高度/分块/参数摘要 |
| `model.py` | 地形、相机、灯光、分块、任务、编辑的数据类 |
| `validate.py` | 任务与地形样本的严格解析校验（先校验后落盘） |
| `geometry.py` | 整幅坐标系梯度/法线、双线性高度与法线采样 |
| `render.py` | 相机基、超采样光线、毫米步进求交、兰伯特着色 |
| `scheduler.py` | 逻辑时钟、双预算准入裁决、有界线程池执行 |
| `storage.py` | 分块原子持久化、版本识别、归档、PGM/深度写出 |
| `edits.py` | 编辑批次、矩形校验、失效闭包 |
| `engine.py` | 编排：缓存复用、注入链路、增量、中断、合成 |
| `cli.py` | `render` / `append` / `preview` / `verify` 入口 |

## 2. 坐标系与法线口径（业务要求 2）

格点 `(i, j)` 的世界坐标为 `x = i*sx`、`y = j*sy`，整数高度 `h` 映射为
`z = h*sz`，单位均为毫米。梯度由**整幅**高度场的全局格索引差分得到：

* 内部格点使用中心差分 `dh/di = (h[i+1]-h[i-1])/2`；
* 边界行/列使用确定的单侧前向/后向差分；
* 换算 `dz/dx = (dh/di)*sz/sx`，法线归一化为
  `(-dz/dx, -dz/dy, 1)`。

所有分块共享同一全局高度场并调用同一函数，因此任一格点的法线逐分量
相同，不会因分块边界退化为块内差分，也不随调用顺序变化。单行/单列
退化网格的对应方向梯度按 0 处理。

## 3. 逐超采样求交与着色（业务要求 3）

* 正交相机由位置、目标、上方向构造严格正交归一基（右、上、前向）。
* 每像素的超采样偏移用确定性 Halton(2,3) 低差异序列，无随机数。
* 每条视线沿前向以固定毫米步长从 `near` 到 `far` 步进，首次出现
  “光线点低于地表”即记录跨越，再做 6 次二分细化定位交点。
* 交点换算回全局格索引，双线性插值取高度与法线；两盏方向光分别计算
  兰伯特项（负值截断为 0），加环境光后裁剪到 `[0,1]`，对超采样取均值，
  四舍五入为 8 位灰度；深度为命中超采样沿视线的世界单位毫米均值，
  完全无命中时为 `-1.0`。

## 4. 双预算联合裁决（业务要求 4）

裁决与执行解耦：

1. `plan_rounds` 是单线程离散事件模拟，只依据分块顺序、声明的缓冲字节
   数与可注入逻辑时钟，决定每轮准入/延后序列；
2. 轮次仅由**逻辑时间预算**与**在途内存预算**决定，`max_concurrency`
   只约束真实线程池，因此任意并发度下轮次与准入顺序完全一致；
3. 内存采用字节级 `_MemoryLimiter`，单块缓冲超预算直接 `E_BUDGET`；
4. 执行阶段用有界 `ThreadPoolExecutor`，按准入顺序提交，单块异常被捕获
   为结构化 `TileResult`，不影响其余合法分块。

## 5. 依赖闭包与增量（业务要求 5）

每块的依赖范围由其视锥四角在 `near/far` 全程的 x/y 极值换算为全局格
索引，并向四周各扩 1 格以覆盖法线/双线性模板。编辑矩形（半开区间）与
该依赖范围求交，相交才失效。未失效块通过 `carry_forward` 以新版本标识
重新发布，像素内容不变；失效块重渲。报告逐条给出失效理由、重渲数与
复用数。

跨进程追加（CLI `append`）在状态目录维护：

* `edit_cursor.json`：已应用批次高水位；
* `terrain_snapshot.npy`：编辑后的高度场快照。

重启先恢复快照再只应用新批次，避免旧批次被重复应用（`smooth` 为非线性
操作，重复应用会改变结果），从而保证追加结果与从零全量逐像素一致。

## 6. 持久化、版本与摘要（业务要求 6、8）

每块写 `<id>.npz`（灰度、深度、依赖）与 `<id>.manifest.json`（版本、
声明像素数、数组摘要、依赖摘要）。所有写操作先写同目录 `.tmp` 再
`os.replace` 原子替换。版本标识由地形高度摘要与相机/光照/采样规范化
摘要构成。版本变化时旧结果先移动到 `state/archive/<旧版本>/`，杜绝
新旧分块混用。恢复时逐块校验版本、形状、声明像素数、数组与依赖摘要，
任一不符返回 `E_DIGEST` 并回退补渲。

## 7. 终止语义（业务要求 7）

* 可处理终止（SIGINT/SIGTERM，Windows 上为 SIGINT）只在分块边界生效，
  写 `interrupted.json`（含完成/延后清单）并以退出码 `130` 退出，
  未完成块不会留下 manifest，因此不可能被误认为已完成；
* 强制终止不承诺退出报告，重启仅依据已持久化且摘要有效的块恢复。

## 8. 错误码

| 码 | 触发场景 |
| --- | --- |
| `E_PARSE` | JSON 语法错误、文件缺失 |
| `E_SCHEMA` | 字段类型/结构非法、未知分块、游标倒退 |
| `E_GRID_DIMS` / `E_SCALE` | 行列数非正、尺度非有限正 |
| `E_HEIGHT_COUNT` | 高度数量不符、非整数、注入高度数异常 |
| `E_TILE_COVERAGE` / `E_TILE_DIVISIBILITY` | 分块覆盖/整除问题 |
| `E_SAMPLES` | 超采样数非正 |
| `E_CAMERA_AXIS` | 上方向与视线平行、相机参数非法 |
| `E_LIGHT` | 灯光数量/方向/环境光非法 |
| `E_DIGEST` | 版本、形状、像素数、数组或依赖摘要不符 |
| `E_BOUNDS` | 编辑矩形越界或为空 |
| `E_BUDGET` | 单块超内存、零进展等双预算问题 |
| `E_STATE` / `E_IO` | 状态/快照缺失、图像写出问题 |
