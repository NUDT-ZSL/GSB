# Architecture

## Invariants

1. SQLite is the committed source of truth. In-memory group objects never define progress.
2. One batch is committed in one `BEGIN IMMEDIATE` transaction.
3. A spill file is an immutable, checksummed side artifact. A missing or modified file fails readback explicitly.
4. A batch-level read fault commits only a failed batch marker. A group-level fault commits only that group's failure marker and leaves prior group state/results in place.
5. All reported durations and batch/window logical positions use the injected logical clock.

## Tables

`plan` stores the canonical query/config/manifest and `plan_digest`. `batches` stores canonical payloads and per-batch commit state. `group_states` stores either canonical state JSON or a spill reference. `group_commits` is the idempotency ledger. `spill_files` records immutable spill manifests. `spill_events` records each logical spill/readback round. `results` stores aggregate and window outputs. `failures` and `group_failures` store diagnostics. `conversion_audit` stores every fixed/float conversion.

## Batch commit ordering

```text
BEGIN IMMEDIATE
  read batch + apply read injection
  load/update group states with LRU spill/readback
  write spill files atomically (outside SQLite, before references commit)
  upsert group_states + group_commits + results + failures + spill manifest
  update logical clock and global state_digest
  mark batch committed/failed
COMMIT
```

A process death before `COMMIT` rolls back all database references and progress. Any spill files already renamed into place are unreferenced and cleaned by `resume`. A process death after `COMMIT` leaves only referenced files, so no replay is needed.

## Memory accounting

The deterministic logical estimate is:

```text
4096 group base
+ group-key UTF-8 bytes
+ 512 per measure column
+ 512 window base
+ 64 per buffered window row
```

This estimate is intentionally conservative for Python object overhead. It is checked after each row and each cache insertion. LRU victims are spilled until the resident estimate fits. If the active single group alone exceeds the budget, the group enters `E_STATE_TOO_LARGE`.

## Determinism

- Inputs are canonical JSON with sorted keys and stable float tokenization.
- Batch files are generated by a fixed seed.
- Group processing follows batch sequence and row order.
- LRU ties are broken by group hash.
- Spill filenames and IDs are content-derived.
- SQLite result/status queries use explicit ordering.
- No business code reads the wall clock.
- Fixed output contains exact rational values; float output contains `float.hex()` representations.
