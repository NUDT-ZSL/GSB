# 技术设计说明

## 1. 模块边界

- `loader.py`：单遍文件解析、字段/顺序/类型校验、SHA-256 数据指纹。
- `aggregation.py`：全量前缀和路径与固定环形缓冲流式路径；共享窗口构造和预算公式。
- `fixed.py`：`Fraction` 量化、整数 ticks、确定性舍入和误差上界。
- `alerts.py`：不依赖哈希遍历的长/短双窗口组合状态机。
- `engine.py`：单次文件扫描内的自适应路径切换、资源报告和会话组装。
- `snapshot.py`：严格快照解析、原子写入、整体替换恢复。
- `replay.py`：重新计算并逐字段比较，失败转换为 `E_REPLAY`。

核心数值路径不依赖 NumPy。Python 任意精度整数避免不同平台/NumPy dtype 的溢出和
舍入差异；NumPy 只用于百万行基准样本生成。这样重放结果与 CPU、操作系统和
NumPy 版本解耦。

## 2. 时间与窗口

时间统一归一化为 UTC 分钟起点（Unix 秒）。输入 ISO 时间必须带时区且秒/微秒为
零；整数时间必须是 60 的倍数。窗口采用左闭右开区间：

```text
start_k = first_minute + k * step_minutes
end_k   = start_k + window_minutes
```

只要 `start_k <= last_minute` 就输出该窗口。`partial` 由时间覆盖而非行数决定：
`coverage_minutes < window_minutes`。`observed_minutes` 单独记录实际数据行数，
因此可区分“窗口时间不完整”和“窗口内存在缺失分钟”两种情况。

## 3. 数值取舍

浮点被排除在业务计算之外。SLI、错误率、预算比例、预算量和燃烧率先以
`Fraction` 精确计算，再分别量化：

| 输出 | 默认 scale | 单值误差上界 |
| --- | ---: | ---: |
| SLI / error rate / budget fraction | `1e9` | `1e-9` |
| burn rate | `1e6` | `1e-6` |
| request budget | `1e6` | `1e-6` request |

舍入规则是 round-half-even。公开对象同时输出 ticks、scale、十进制字符串和整数
误差上界。量化误差不进入后续计算；预算和燃烧率始终从窗口整数计数重新精确推导，
避免误差传播。

## 4. 两条聚合路径

**全量路径**：保留全部事件，构建时间戳与总/失败请求前缀和；每个窗口用两次二分
定位，区间和相减。复杂度 `O(N + W log N)`，内存 `O(N + W)`。

**流式路径**：单遍读取事件，使用容量为 `max(long, short) + 2` 的环形缓冲。每个
槽保存时间戳和全局累计总量/失败量，区间查询通过环形逻辑索引二分完成。窗口在事件
到达时完成，流结束时补齐尾部 partial 窗口。输入事件内存固定为
`O(max_window_minutes)`；窗口元数据为 `O(W)`，因为快照必须保存全部结果。

自动模式在超过阈值时只把内存中的缓冲转入流式聚合器，文件本身仍只读一次。两条路径
共享 `_make_window`，单元测试同时覆盖连续数据、空洞、重叠窗口、步长大于窗口和随机
窗口形状。

## 5. 状态机确定性

评估步骤按 `range()` 和显式长/短窗口对顺序处理。状态只依赖当前两个窗口的精确
`Fraction` 燃烧率、配置阈值和前一状态；没有集合或字典遍历。每条告警记录保存全部
证据，状态变化另存迁移，迁移包含触发窗口、两个 fixed-point 燃烧率和 SLO 版本。

## 6. 快照与重放

快照是纯整数/字符串 JSON，使用 `sort_keys=True` 和原子 `os.replace` 写入。加载
时验证固定点渲染值、窗口/步骤数量、步骤引用、告警状态链和资源行数。恢复永远不
把快照窗口与活动会话窗口合并。

重放不信任快照结果：它从同一配置重新解析并聚合数据，再比较：

1. 数据版本、内容 SHA-256、行数和首末分钟；
2. 每个长/短窗口的所有公开字段和定点误差界；
3. 每个评估步骤的燃烧率与状态；
4. 完整告警历史、迁移链和最终状态。

参数或数据不一致会在重算前/后转为 `E_REPLAY`；首个差异采用稳定的字典键排序和列表
索引定位。

## 7. 内存观测口径

`tracemalloc` 在文件解析前启动并重置峰值，覆盖解析、聚合、告警和报告对象构建。
它测量 Python 堆分配峰值，不包含解释器基线、已加载模块和操作系统 RSS 开销。
确定性估算只计算核心保留结构，因此小于观测值属于预期现象；字段
`memory_accounting` 和 `estimator` 被写入每次结果与快照以便审计。
