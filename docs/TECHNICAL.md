# 技术说明

## 1. 规范化与权威规则视图

解析器逐行读取 JSONL，因此可保留 1 基物理行号和 0 基记录号。每条拒绝只影响当前记录：

- 连接标识必须为非空字符串且无控制字符；
- 方向先做大小写/别名规范化，再限制到 `C2S`/`S2C`；
- `seq`、`logical_ms` 拒绝布尔值，要求非负整数；
- 十六进制先去除空白，再检查偶数长度，最后 `bytes.fromhex`；
- v1 相对秒使用 `Decimal` 与 `ROUND_HALF_UP` 换算，基准仅为 `observed_clock_ms`。

v2 由 SQLite 元数据与 JSON 分片按 `(canonical_name, generation, effective_from_ms)` 配对。匹配到的分片补充迁移约束；未被数据库引用的分片仍可作为诊断记录加载。加载过程不依赖文件行顺序。

规范规则名使用 NFKC、去首尾、casefold 和内部空白折叠。按规范名分组后，在评估时刻筛出窗口内记录，再以以下键选权威记录：

```text
(generation, effective_from_ms, source_priority, canonical_name, source_file, record_index)
```

权威记录若为墓碑或禁用，则该规范名没有活动规则。因此新墓碑覆盖所有较早记录，包括上一代活动规则。

## 2. 连接重组

输入先按 `(connection_id, direction)` 分组。每个方向内：

1. 按到达顺序扫描，相同 `seq` 只保留首次记录；
2. 重复项记录次数、首次位置、重复位置和载荷是否冲突；
3. 按 `seq` 数值排序后拼接载荷；
4. 保留每个序号到字节区间的映射；
5. 计算最小/最大序号间的缺口与连续区间。

缺口连接不会跨缺口猜测拼接，直接产生 `E_MSG_GAP`。混连可由作用域参数、`payload_connection_id` 提示或同一调用中的多个连接标识检测。

## 3. HTTP 状态机

状态与代表性事件：

| 状态 | 事件 |
| --- | --- |
| `START_LINE` | `START_LINE_DONE` |
| `HEADERS` | `HEADER_FIELD`, `HEADERS_DONE` |
| `BODY` | `BODY_COMPLETE` |
| `CHUNK_SIZE` | `CHUNK_SIZE`, `CHUNK_SIZE_INVALID` |
| `CHUNK_DATA` | `CHUNK_DATA_COMPLETE` |
| `TRAILERS` | `TRAILER_FIELD`, `MESSAGE_END` |
| `MESSAGE_END` | `MESSAGE_END` |

定长实体使用 `Content-Length`；存在最终 `chunked` 的 `Transfer-Encoding` 时按块解析；CL/TE 并存时在解释结构中同时标记两个候选帧。块行解析严格到十六进制数字和可选扩展，块后 CRLF、零块、Trailer 区和结束空行都会形成显式迁移。

每个请求保存：

- 原始字节与首尾偏移；
- 状态迁移序列；
- 头字段多重性与 Trailer；
- 帧模式、候选帧、实体和块元数据；
- 下一请求边界；
- 异常集合与完整性。

完成请求后继续从下一偏移解析，因此支持 HTTP 流水线。只有实际字节满足下一状态前置条件时才迁移。

## 4. 迁移约束

约束对象包含：

```json
{
  "states": ["HEADERS"],
  "on": "HEADERS_DONE",
  "when": {
    "header_names_all": ["content-length", "transfer-encoding"],
    "framing_pattern": "AMBIGUOUS"
  },
  "action": "REJECT",
  "code": "D_TE_CL"
}
```

条件按语义求值，支持同名头存在/全存在、重复头、帧模式、异常、块模式、Trailer、TE token、方法和目标。未知条件不会退化为字节子串匹配，而是按不满足处理。

事件点实时求值可保证命中偏移属于触发事件，而不是报文解析完成后的近似位置。

多个活动规则同时命中时：

1. 过滤状态和事件；
2. 过滤语义条件；
3. 以代数降序、生效时刻降序、规范名升序、迁移序号升序排序；
4. 动作一致则全部保留；
5. 动作冲突则第一条为裁决者，其余进入 `suppressed_hits`。

候选规则求值保留全代记录，以便补丁把墓碑恢复为活动规则时仍能正确建立失效闭包。

## 5. 变异与真实回显

变异先解析请求头/实体边界，再做结构化字节编辑。所有结果只由基线请求、清单参数和种子决定。

回显服务是独立 TCP HTTP 对端：

- 客户端完成发送后关闭写方向，服务端按实际线上字节解析；
- 服务端返回原始回显十六进制、SHA-256 和自身解释 JSON；
- 客户端校验回显摘要与提交摘要一致；
- 延迟在服务端实际睡眠后发送响应，客户端用单调时钟测量完整往返。

服务端解释策略可配置，默认模拟一个常见的宽松中间件。状态机保持严格 RFC 风格，因此策略差异会表现为可解释的稳定分歧。

## 6. 判定与推翻

本地预判：

- 命中 `REJECT` 为 `BLOCKED`；
- 其他命中或解析异常为 `SUSPECTED`；
- 否则为 `CLEAN`。

最终判定在真实回显可见后形成：

- 有分歧为 `SMUGGLED`；
- 无分歧且本地阻断为 `BLOCKED`；
- 无分歧且无阻断为 `CLEAN`；
- 链路异常为 `ERROR`。

风险类别从 `RISK` 变为 `CLEAN`，或从 `CLEAN` 变为 `RISK`，记一次推翻。最终结论始终取最后可见回显。

## 7. 并发一致性与延迟口径

同一连接的所有变异由同一个工作线程串行执行，避免同连接竞态。不同连接组最多按 `concurrency` 并发。在途字节使用带条件变量的全局字节配额。

完成后所有结果按 `(stable_key, mutation_id)` 排序，再生成报告。稳定键由变异规范内容摘要产生。因此以下字段在并发/串行、不同线程完成顺序下一致：

- 判定与分歧集合；
- 规则命中与压制；
- 异常码；
- 推翻计数；
- 延迟档位、测量时钟和观测状态。

`latency_ms` 保存每次执行真实测得的数值。物理上，真实网络和调度不会在不同并发度下产生相同浮点数；工作台明确区分“稳定可比较的观测结构”与“真实测量值”，不做固定常量归一化。

## 8. 增量失效闭包

补丁比较每个规范名最新记录的以下签名：

- 代数与生效窗口；
- 启用和墓碑；
- 迁移约束；
- 规则依赖。

差异规则进入依赖传递闭包，再映射到基线变异/连接的候选规则集合。若补丁引入基线中从未出现的新规范规则，则边界未知，保守重判全部变异，避免漏判。

受影响部分只重算本地规则命中和最终语义；真实回显解释按变异摘要复用，因为规则补丁不改变线上请求。随后对同一新规则视图执行一次全量本地重演，仅用于逐字节验证。任何差异产生 `E_RECOMPUTE_DIVERGE`。

依赖图使用稳定排序 DFS；发现环时统一成最小旋转表示并列出规范名。

## 9. 检查点提交协议

快照内容包含：

```text
schema_version, rules_basis, completed_connections,
connection_results, mutation_results, aggregate, generation, complete
```

每次提交：

1. 计算规范 JSON 和 SHA-256；
2. 写 `snapshots/checkpoint-XXXXXXXX.json` 临时文件；
3. 读取临时文件验证 JSON；
4. `fsync` 后 `os.replace`；
5. SQLite 事务插入同代行；
6. 原子替换 `checkpoint.json` 指针。

恢复从最高代向下扫描，要求数据库校验和、快照校验和、规范状态、结构版本和规则口径全部匹配，并重放已完成连接。若较新代只完成一半，旧完整代仍可恢复；孤儿分代和临时文件报告为残留。

文件锁在 POSIX 用 `flock`，Windows 用 `msvcrt.locking`，均非阻塞。工作台在整次运行期间持锁，竞争方得到 `E_LOCK`。

## 10. 限制

- 当前首版聚焦 HTTP/1.x 请求方向；`S2C` 流参与重组、重复与缺口校验，但不用于走私请求边界。
- 回显服务为验收用本地模型，不实现完整 HTTP/2、TLS 或业务路由。
- 分块解析在畸形块上停止当前请求并保留异常证据，不尝试启发式恢复后续请求。
- 检查点保留历史分代用于崩溃恢复；首版不做自动垃圾回收。
